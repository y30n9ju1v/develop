카메라와 LiDAR가 자율주행 인식의 주역처럼 보이지만, 고속도로 자율주행과 ACC(어댑티브 크루즈 컨트롤)에서 **가장 믿을 수 있는 센서는 Radar**입니다. 폭우, 짙은 안개, 직사광선 — 카메라와 LiDAR가 무력화되는 상황에서도 Radar는 동작합니다. 그리고 Radar만이 물체의 **속도를 직접** 측정합니다.

이 글은 Radar가 어떤 원리로 거리와 속도를 동시에 얻는지, 그 결과물이 어떤 형태인지, 카메라·LiDAR와 어떻게 함께 쓰이는지를 설명합니다.

---

## 1. Radar가 카메라·LiDAR와 다른 점

세 센서를 한 줄로 비교하면:

| 센서 | 거리 측정 | 속도 측정 | 각도 해상도 | 날씨 저항성 |
|------|---------|---------|-----------|-----------|
| 카메라 | ✗ (단안 불가) | ✗ (추정만) | ◎ 매우 높음 | △ 비·눈에 약함 |
| LiDAR | ◎ 정밀 | ✗ (프레임 간 추정) | ◎ 높음 | △ 안개·폭우에 약함 |
| Radar | ◎ 정밀 | ◎ **직접 측정** | △ 낮음 | ◎ 매우 강함 |

Radar의 약점은 **각도 해상도**입니다. 안테나 수와 크기가 해상도를 결정하는데, 차량에 장착할 수 있는 크기에는 물리적 한계가 있습니다. 카메라가 "저 물체가 사람인지 표지판인지" 구별하는 동안, Radar는 "저 방향 15m에 시속 40km로 움직이는 무언가가 있다"고 말합니다.

이 상호 보완 관계가 센서 융합의 출발점입니다.

## 2. FMCW: Radar가 거리와 속도를 동시에 재는 방법

자율주행에 쓰이는 Radar는 거의 모두 **FMCW(Frequency-Modulated Continuous Wave, 주파수 변조 연속파)** 방식입니다.

### 2.1 기본 원리

펄스를 쏘고 돌아오는 시간을 재는 LiDAR와 달리, FMCW Radar는 **주파수가 시간에 따라 선형으로 변하는 신호(chirp)**를 연속으로 송신합니다.

```
주파수
  ↑
  │     /|    /|    /|
  │    / |   / |   / |
  │   /  |  /  |  /  |
  │  /   | /   | /   |
  │ /    |/    |/    |
  └──────────────────→ 시간
      chirp   chirp
```

이 신호가 물체에 반사되어 돌아오면, **송신 신호와 수신 신호 사이에 주파수 차이(beat frequency)**가 생깁니다.

**거리 계산**: 신호가 왕복하는 시간 $\tau$ 동안 주파수가 얼마나 변했는지로 거리를 계산합니다.

$$d = \frac{c \cdot \tau}{2} = \frac{c}{2} \cdot \frac{f_{beat}}{S}$$

- $c$: 빛의 속도 (전파도 빛의 속도로 진행)
- $f_{beat}$: 송수신 주파수 차이
- $S$: chirp의 주파수 변화 기울기 (sweep rate)

**속도 계산 (도플러 효과)**: 물체가 움직이면 반사 신호의 위상이 변합니다. 여러 chirp 사이의 위상 변화로 속도를 측정합니다.

$$v = \frac{\lambda \cdot f_d}{2}$$

- $\lambda$: 신호 파장
- $f_d$: 도플러 주파수 편이

FMCW의 핵심은 **거리와 속도를 분리하여 독립적으로** 측정할 수 있다는 것입니다. LiDAR는 속도를 직접 측정하지 못해 두 프레임의 위치 차이로 추정합니다. Radar는 단 한 번의 측정으로 둘을 동시에 얻습니다.

### 2.2 각도 측정: MIMO 안테나

거리와 속도만으로는 물체가 **어느 방향**에 있는지 모릅니다. 방위각(azimuth)과 앙각(elevation)을 측정하려면 여러 안테나가 필요합니다.

**MIMO(Multiple Input Multiple Output)** 구성에서는 송신 안테나와 수신 안테나를 여러 개 배열합니다. 각 안테나 쌍에서 받은 신호의 위상 차이로 신호가 들어온 방향을 계산합니다.

```
수신 안테나 배열:  [A1] [A2] [A3] [A4]
                         ←d→
신호 입사 방향: θ
위상 차이: Δφ = 2π·d·sin(θ)/λ
```

안테나 수가 많을수록 각도 해상도가 높아지지만, 그만큼 칩 크기와 연산량이 늘어납니다. 77GHz 4D Radar(방위각+앙각+거리+속도)는 이 기술의 최신 버전입니다.

## 3. Range-Doppler 맵

FMCW 신호를 수신한 후 2D FFT를 적용하면 **Range-Doppler 맵**이 만들어집니다.

```
속도(m/s)
  ↑  +30│         *          ← 접근하는 차량
     +20│
     +10│    *               ← 보행자
      0 │──────────────────
     -10│
     -20│      *             ← 멀어지는 차량
     -30│
       └───────────────────→ 거리(m)
         0   20   40   60
```

- **가로축**: 물체까지의 거리
- **세로축**: 물체의 반경 방향 속도 (+ = 접근, - = 멀어짐)
- **밝기**: 반사 신호 강도 (RCS, Radar Cross Section)

맵에서 밝은 점 하나가 "특정 거리, 특정 속도에서 강한 반사가 있음"을 의미합니다. 여기에 각도 정보를 합치면 3D 공간의 한 점으로 확정됩니다.

이 처리 과정을 거쳐 최종 출력되는 것이 **Radar 포인트 클라우드**입니다.

## 4. Radar 포인트 클라우드

LiDAR 포인트 클라우드가 x/y/z/intensity 4열이라면, Radar 포인트 클라우드에는 속도 열이 추가됩니다.

| 필드 | 의미 |
|------|------|
| **x, y, z** | 포인트의 3D 좌표 |
| **rcs** | Radar Cross Section — 반사 강도. 물체 크기·재질 반영 |
| **vr** | 반경 방향 속도 (radial velocity). Radar 기준 가까워지는 속도 |
| **vr_compensated** | 자차 속도를 보정한 상대 속도 |

**vr(반경 방향 속도)**은 Radar와 물체를 잇는 직선 방향의 속도 성분만 측정합니다. 물체가 Radar를 향해 정면으로 달려오면 실제 속도와 같지만, 옆으로 지나가면 0에 가깝습니다. 이 한계를 **도플러 모호성(Doppler ambiguity)**이라 합니다.

nuScenes 데이터셋의 Radar 포인트 클라우드에는 위 필드들이 포함되어 있고, [py123d](/docs/autonomous/data-infra/py123d-for-beginners/)도 이 형식을 지원합니다.

### Radar 포인트 클라우드의 특징

LiDAR와 비교하면 훨씬 **희소(sparse)**합니다.

```
LiDAR 스캔 1회: ~130,000 포인트
Radar 스캔 1회: ~100~500 포인트
```

하지만 각 포인트가 속도 정보를 갖기 때문에, 적은 수로도 움직이는 물체와 정지 물체를 즉시 구별할 수 있습니다.

## 5. 자율주행에서 Radar의 역할

### 5.1 ACC와 AEB

**ACC(어댑티브 크루즈 컨트롤)**과 **AEB(자동 긴급 제동)**은 Radar가 주 센서입니다. 전방 차량까지의 거리와 상대 속도를 정확히 알아야 하는데, 이 두 값을 가장 빠르고 안정적으로 주는 것이 Radar입니다.

Tesla FSD 이전 세대 Autopilot은 카메라+Radar 조합이었고, 전방 추돌 회피는 Radar가 거의 전담했습니다.

### 5.2 정지 물체 vs 움직이는 물체 구분

Radar의 도플러 측정 덕분에 **자차 기준으로 속도가 0인 포인트**를 바로 걸러낼 수 있습니다. 도로 위 정지 물체(낙하물, 정차 차량)와 움직이는 물체(보행자, 달리는 차량)를 단 한 프레임에서 구별합니다.

LiDAR는 같은 일을 하려면 최소 두 프레임을 비교해야 하고, 그 사이 레이턴시가 생깁니다.

### 5.3 날씨 저항성

77GHz 전파는 빗방울이나 안개 입자를 대부분 통과합니다. 폭우에서 LiDAR 포인트 클라우드는 빗방울 반사로 가득 차고, 카메라는 뿌연 영상을 얻습니다. 이 상황에서 Radar는 전방 차량을 여전히 정확히 잡습니다.

## 6. 카메라 + LiDAR + Radar 융합

세 센서의 장단점이 상호 보완적이기 때문에, 고수준 자율주행에는 세 가지를 함께 씁니다.

### 6.1 초기 융합 (Early Fusion)

Raw 데이터 레벨에서 합칩니다. Radar 포인트를 카메라 이미지 위에 투영하거나, LiDAR 포인트에 Radar 속도 정보를 덧붙입니다.

**Radar 포인트 → 카메라 이미지 투영**은 LiDAR-카메라 투영과 동일한 변환을 씁니다:

```
P_image = K · [R|t]_radar_to_cam · P_radar
```

단, Radar 포인트가 LiDAR보다 훨씬 희소하기 때문에 카메라 이미지 위에 찍히는 점이 몇십 개에 불과합니다. 이 점들이 "여기 속도가 있는 물체가 있다"는 힌트를 딥러닝 모델에 줍니다.

### 6.2 후기 융합 (Late Fusion)

각 센서가 독립적으로 물체 감지를 수행한 후, 결과(바운딩 박스)를 합칩니다.

```
카메라 → 2D detection → 바운딩 박스 + 클래스
LiDAR  → 3D detection → 3D 바운딩 박스 + 크기
Radar  → 포인트 클러스터 → 위치 + 속도

                    ↓
              [Fusion Module]
                    ↓
         통합 물체 목록 (위치 + 크기 + 클래스 + 속도)
```

**칼만 필터**나 **Hungarian Algorithm** 기반의 트래킹이 이 단계에서 각 센서의 감지 결과를 동일 물체로 연결(association)합니다.

### 6.3 역할 분담 예시

실제 시스템에서 세 센서는 다음처럼 역할을 나눕니다:

| 상황 | 주 담당 |
|------|---------|
| 물체 클래스 판별 (사람인지 차인지) | 카메라 |
| 물체까지 정밀 거리 측정 | LiDAR |
| 물체 속도 직접 측정 | Radar |
| 악천후 전방 추돌 감지 | Radar |
| HD Map 정합 (차선, 도로 경계) | 카메라 + LiDAR |
| 가려진 물체 예측 | Radar (투과성 일부 있음) |

## 7. 4D Radar: 기존 Radar의 한계를 넘는 방향

기존 자동차용 Radar의 가장 큰 약점은 **앙각(elevation) 해상도 부족**입니다. 고가도로 아래를 지나는 상황에서 고가도로 구조물을 전방 장애물로 오인하는 문제가 대표적입니다.

**4D Radar**는 MIMO 안테나를 대폭 늘려 방위각+앙각+거리+속도 4차원 정보를 제공합니다. 포인트 수도 수천 개로 늘어나 LiDAR와의 격차가 줄어듭니다.

Arbe Robotics, Oculii, Continental의 4D Radar 칩이 차세대 자율주행에 탑재되고 있습니다. nuScenes v2.0은 4D Radar 데이터를 포함하도록 업데이트됐습니다.

## 정리

| 개념 | 핵심 |
|------|------|
| **FMCW** | 주파수가 선형으로 변하는 chirp 신호로 거리·속도를 동시 측정 |
| **Range-Doppler 맵** | 2D FFT로 거리-속도 2D 공간에 신호 강도를 시각화 |
| **Radar 포인트 클라우드** | x/y/z + rcs + vr — LiDAR보다 희소하지만 속도 포함 |
| **도플러 모호성** | 반경 방향 속도만 측정 — 옆으로 지나가는 물체는 속도 0으로 보임 |
| **4D Radar** | 앙각 해상도 추가 + 포인트 수 증가 — LiDAR 대체 가능성 |
