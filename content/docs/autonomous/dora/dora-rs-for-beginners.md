## 1. DORA가 뭔가요?

**DORA**는 **Dataflow-Oriented Robotic Architecture**의 약자로, Rust로 만들어진 실시간 로보틱스 및 AI 애플리케이션 개발 프레임워크입니다.

로봇을 만들 때 가장 많이 쓰는 표준이 ROS2(Robot Operating System 2)인데, DORA는 ROS2의 개발 경험을 유지하면서 성능과 편의성을 크게 끌어올리는 것을 목표로 만들어졌습니다.

> 한 줄 요약: **"ROS2보다 10~17배 빠르고, 쓰기 더 편한 로보틱스 프레임워크"**

---

## 2. 왜 만들어졌나요?

### 2.1 성능 문제

ROS2는 Python 노드를 많이 사용하는데, 실시간성이 중요한 로봇 시스템에서 Python의 속도는 한계가 있습니다. DORA는 내부를 Rust로 구현하고, **4KB 이상의 메시지는 제로카피(zero-copy) 공유 메모리**로 전달해 직렬화/역직렬화 오버헤드를 없앴습니다.

결과적으로 ROS2 Python 대비 **10~17배 빠른 지연시간(latency)**을 달성했고, 페이로드 크기가 커져도 지연시간이 안정적으로 유지됩니다.

### 2.2 도구 파편화 문제

로봇 소프트웨어를 개발하다 보면 로컬 실행, 배포, 모니터링 각각에 서로 다른 도구를 써야 하는 경우가 많습니다. DORA는 **하나의 CLI**로 전체 개발 라이프사이클을 관리합니다.

```bash
# 로컬 개발
dora run my_pipeline.yml

# 분산 프로덕션 배포
dora up
dora start my_pipeline.yml
```

---

## 3. 어떤 구조로 동작하나요?

DORA는 **데이터플로우(Dataflow)** 방식으로 동작합니다. 로봇 애플리케이션을 여러 **노드(Node)**의 **방향 그래프(Directed Graph)**로 표현하고, 노드 사이의 데이터 흐름을 YAML로 선언합니다.

```yaml
# 예시: 카메라 → 인식 → 제어기 파이프라인
nodes:
  - id: camera
    path: nodes/camera.py
    outputs:
      - image

  - id: detector
    path: nodes/detector.py
    inputs:
      image: camera/image
    outputs:
      - detections

  - id: controller
    path: nodes/controller.py
    inputs:
      detections: detector/detections
```

이 선언만으로 DORA가 노드 간 데이터 라우팅, 스케줄링, 재시작 정책 등을 자동으로 처리합니다.

---

## 4. 핵심 기술 스택

### 4.1 Apache Arrow

노드 간 메시지 포맷으로 **Apache Arrow**의 컬럼 메모리 포맷을 사용합니다. Arrow는 언어에 상관없이 같은 메모리 레이아웃을 공유하므로, Rust/Python/C/C++ 노드 사이에서 데이터를 복사 없이 주고받을 수 있습니다.

### 4.2 Zenoh 공유 메모리

데이터 전송 레이어로 **Zenoh**를 사용합니다. 같은 머신 안에서는 공유 메모리로 제로카피 전송을 하고, 네트워크가 필요하면 자동으로 전환합니다. 개발자는 전송 방식을 신경 쓸 필요가 없습니다.

### 4.3 멀티언어 지원

노드를 Rust, Python, C, C++ 중 원하는 언어로 작성할 수 있습니다. 래퍼(wrapper)가 아닌 **각 언어의 네이티브 API**를 제공하기 때문에, 언어별 생태계를 그대로 활용할 수 있습니다.

---

## 5. 프로덕션 기능

로봇 시스템은 24시간 돌아야 하는 경우가 많습니다. DORA는 이를 위한 프로덕션 기능을 내장하고 있습니다.

| 기능 | 설명 |
|------|------|
| **노드 재시작 정책** | 노드가 죽으면 지수 백오프(exponential backoff)로 자동 재시작 |
| **동적 토폴로지 변경** | 파이프라인을 재시작하지 않고 실행 중 구조 변경 가능 |
| **분산 상태 저장** | 영속적 상태 저장으로 분산 환경에서도 복구 가능 |
| **큐 정책 설정** | 노드별로 메시지 큐 동작 방식을 커스터마이즈 |

---

## 6. 관찰 가능성(Observability)

로봇 소프트웨어 디버깅은 재현이 어렵습니다. DORA는 이를 위한 도구도 제공합니다.

- **Record/Replay**: 데이터 흐름을 기록하고 그대로 재생해 버그를 재현
- **라이브 토픽 검사**: 실행 중인 파이프라인의 데이터를 실시간으로 확인
- **리소스 모니터링 대시보드**: CPU, 메모리 등 리소스 사용량 시각화
- **분산 트레이싱**: 어느 노드에서 지연이 생기는지 추적

---

## 7. ROS2와 비교

| | ROS2 | DORA |
|-|------|------|
| **구현 언어** | C++, Python | Rust |
| **통신 방식** | DDS | Zenoh + 공유 메모리 |
| **메시지 포맷** | IDL (직렬화 필요) | Apache Arrow (제로카피) |
| **성능** | 기준 | ~10~17× 빠름 |
| **멀티언어** | 래퍼 방식 | 네이티브 API |
| **파이프라인 정의** | launch 파일 (Python/XML) | YAML 선언형 |
| **생태계 성숙도** | 매우 성숙 | 빠르게 성장 중 |

ROS2는 수십 년간 쌓인 패키지 생태계가 강점이고, DORA는 성능과 개발자 경험이 강점입니다. 신규 프로젝트라면 DORA를 검토할 가치가 있고, 기존 ROS2 프로젝트라면 병행 사용도 가능합니다.

---

## 8. 정리

DORA는 로보틱스 소프트웨어 개발의 세 가지 문제를 동시에 해결하려 합니다.

1. **성능**: Rust + 제로카피 공유 메모리로 ROS2 대비 10~17× 빠른 지연시간
2. **개발 편의성**: 선언형 YAML 파이프라인 + 단일 CLI
3. **프로덕션 안정성**: 자동 재시작, 동적 토폴로지, 분산 트레이싱

아직 ROS2만큼 생태계가 크진 않지만, 성능이 중요한 실시간 로봇/AI 애플리케이션을 새로 시작한다면 DORA는 충분히 고려할 만한 선택지입니다.
