> 이 글은 [ISO 8855 좌표계](../iso-8855-coordinate-systems/)와 함께 읽으면 좋습니다. 좌표계가 어떻게 정의되는지 알았다면, 이 글에서는 한 좌표계에서 다른 좌표계로 **어떻게 변환하는지**를 다룹니다.

py123d 파서 코드에는 `PoseSE3`, `cam_to_imu_se3`, `ego_to_global_se3`, `rel_to_abs_se3`, `get_rotation_matrix_from_quaternion` 같은 표현이 곳곳에 나옵니다. 이 글은 그 표현들이 실제로 무슨 계산을 하는지를 직관부터 쌓아 설명합니다.

---

## 1. 변환이 왜 필요한가

자율주행 차량 위에는 여러 센서가 달려 있습니다. 각 센서는 자기 자신을 원점으로 한 좌표계에서 데이터를 만듭니다. 전방 카메라는 카메라 렌즈를 원점으로 한 좌표계에서 물체를 봅니다. LiDAR는 LiDAR 스캐너를 원점으로 한 좌표계에서 포인트 클라우드를 만듭니다.

그런데 "보행자가 차량 기준으로 전방 15m, 좌측 2m에 있다"고 말하려면 모든 센서의 측정값을 **공통 좌표계(차량 프레임 또는 글로벌 프레임)**로 변환해야 합니다. 이 변환이 SE3입니다.

---

## 2. 회전을 표현하는 세 가지 방법

변환에는 **이동(translation)**과 **회전(rotation)** 두 가지 성분이 있습니다. 이동은 벡터 하나(tx, ty, tz)로 간단하게 표현됩니다. 회전이 복잡합니다.

### 오일러 각 (Euler Angles)

가장 직관적입니다. "X축 기준으로 30도, Y축 기준으로 0도, Z축 기준으로 90도 회전"처럼 표현합니다. Roll, Pitch, Yaw가 오일러 각입니다.

문제는 **짐벌 락(Gimbal Lock)**입니다. 특정 자세에서 두 축이 겹쳐 자유도를 잃는 현상입니다. 또한 오일러 각의 순서(XYZ인지 ZYX인지)에 따라 결과가 달라지므로, 라이브러리마다 순서가 다르면 틀린 변환이 나옵니다.

### 회전 행렬 (Rotation Matrix)

3×3 행렬로 회전을 표현합니다. 짐벌 락이 없고, 행렬 곱으로 회전 합성이 간단합니다.

```
     ⎡ r00  r01  r02 ⎤
R =  ⎢ r10  r11  r12 ⎥
     ⎣ r20  r21  r22 ⎦
```

유효한 회전 행렬은 두 조건을 만족합니다. **정규직교(Orthonormal)**: 각 열(또는 행)이 단위벡터이고 서로 수직입니다. **행렬식 = +1**: 좌표계를 뒤집지 않고 순수하게 회전합니다.

단점은 9개의 수로 회전을 표현하지만 실제 자유도는 3개뿐이라는 것입니다. 수치 계산에서 오차가 누적되면 직교성이 깨질 수 있고, 두 회전 사이를 보간하기 어렵습니다.

### 쿼터니언 (Quaternion)

**4개의 수 [w, x, y, z]**로 회전을 표현합니다. 짐벌 락이 없고, 두 자세 사이 보간(SLERP)이 부드럽고, 수치 안정성이 높습니다. 자율주행과 로보틱스에서 회전 표현의 사실상 표준입니다.

쿼터니언은 복소수의 확장입니다. 단위 쿼터니언(크기가 1인 쿼터니언)이 3D 회전 하나를 표현합니다.

**직관**: 회전축 방향의 단위벡터 **n** = (nx, ny, nz)와 회전각 θ가 주어지면:

```
w = cos(θ/2)
x = nx · sin(θ/2)
y = ny · sin(θ/2)
z = nz · sin(θ/2)
```

Z축(위)을 기준으로 90도 회전하면 **n** = (0, 0, 1), θ = 90°:
```
w = cos(45°) ≈ 0.707
x = 0
y = 0
z = sin(45°) ≈ 0.707
```

**주의**: `q`와 `-q`는 같은 회전을 나타냅니다. 부호가 달라도 동일한 변환입니다.

**규약 주의**: [w, x, y, z] 순서와 [x, y, z, w] 순서 두 가지가 쓰입니다. py123d는 `[qw, qx, qy, qz]` 순서를 씁니다. scipy는 `[qx, qy, qz, qw]`를 씁니다. 항상 확인해야 합니다.

## 3. SE3: 회전 + 이동

**SE3(Special Euclidean Group, 3D)**는 회전과 이동을 묶은 강체 변환(Rigid Body Transform)입니다. 물체의 모양은 바꾸지 않고 위치와 방향만 바꾸는 변환입니다.

4×4 동차 행렬(Homogeneous Matrix)로 표현합니다:

```
T = ⎡ R  t ⎤  =  ⎡ r00 r01 r02 tx ⎤
    ⎣ 0  1 ⎦     ⎢ r10 r11 r12 ty ⎥
                  ⎢ r20 r21 r22 tz ⎥
                  ⎣  0   0   0   1 ⎦
```

왼쪽 위 3×3이 회전 행렬 R, 오른쪽 위 열이 이동 벡터 t입니다. 아래 행 [0, 0, 0, 1]은 동차 좌표계의 관례입니다.

### 점 변환

점 p = (px, py, pz)를 변환하면:

```
p_new = R · p + t
```

4×4 행렬로 쓰면:

```
⎡ px_new ⎤       ⎡ r00 r01 r02 tx ⎤   ⎡ px ⎤
⎢ py_new ⎥   =   ⎢ r10 r11 r12 ty ⎥ · ⎢ py ⎥
⎢ pz_new ⎥       ⎢ r20 r21 r22 tz ⎥   ⎢ pz ⎥
⎣   1    ⎦       ⎣  0   0   0   1 ⎦   ⎣  1 ⎦
```

### 역변환 (Inverse)

"카메라에서 차량으로" 변환의 역은 "차량에서 카메라로"입니다.

```
T^{-1} = ⎡ R^T  -R^T · t ⎤
          ⎣  0       1    ⎦
```

회전 행렬의 역행렬은 전치 행렬(R^T = R^{-1})입니다. 이동의 역은 단순히 -t가 아니라 -R^T · t입니다.

py123d에서 `ego_to_global.inverse()`가 이 계산을 합니다.

### 합성 (Compose)

두 변환을 연속으로 적용할 때 행렬 곱으로 합성합니다.

```
T_cam_to_global = T_ego_to_global · T_cam_to_ego
```

"카메라에서 글로벌로"는 "카메라에서 차량(IMU)으로" 먼저, "차량에서 글로벌로" 다음의 합성입니다.

**주의**: 행렬 곱은 순서가 중요합니다. `A · B ≠ B · A`. 오른쪽 행렬이 먼저 적용됩니다.

py123d에서:
```python
cam_to_global = rel_to_abs_se3(origin=ego_to_global, pose_se3=cam_to_ego)
# = ego_to_global · cam_to_ego
```

## 4. py123d에서 SE3가 등장하는 곳

### ego_to_global_se3

차량 IMU 프레임에서 글로벌 프레임으로의 변환입니다. 매 타임스탬프마다 달라집니다. 차량이 이동하고 회전하면서 글로벌 맵 위의 위치가 바뀝니다.

`EgoStateSE3.ego_to_global_se3`로 접근합니다.

### camera_to_imu_se3

카메라 센서 프레임에서 IMU(차량 기준) 프레임으로의 변환입니다. **정적 캘리브레이션 값**입니다. 카메라를 차량에 물리적으로 고정했다면 이 값은 바뀌지 않습니다. 캘리브레이션으로 한 번 측정하면 됩니다.

`PinholeCameraMetadata.camera_to_imu_se3`로 접근합니다.

### 파서 코드에서의 활용

```python
# cam_to_ego: 정적 캘리브레이션 (카메라 → 차량)
# ego_to_global: 동적 포즈 (차량 → 글로벌)
# 합성: 카메라 → 글로벌
cam_to_global = rel_to_abs_se3(origin=ego_to_global, pose_se3=cam_to_ego)
```

이 값이 있으면 카메라가 찍은 물체의 픽셀 좌표를 글로벌 3D 좌표로 역투영할 수 있습니다.

### NCore 변환에서의 활용

NCore는 IMU 중심이 아닌 후축(rear axle)을 원점으로 씁니다. py123d → NCore 변환 시:

```python
rig_to_world = ego_to_global.compose(center_offset.inverse())
# center_to_imu_se3의 역으로 IMU 중심 → rear axle 중심으로 변환
```

## 5. SLERP: 쿼터니언 보간

두 자세 사이를 부드럽게 보간해야 할 때 SLERP(Spherical Linear Interpolation)을 씁니다.

nuScenes는 2Hz(키프레임)로만 라벨이 있고, LiDAR는 20Hz로 찍힙니다. 중간 스윕의 박스 위치를 얻으려면 두 키프레임 사이를 보간해야 합니다.

오일러 각을 선형 보간하면 회전이 부자연스럽게 꺾입니다. 쿼터니언을 SLERP로 보간하면 구면 위를 일정 속도로 이동하는 것처럼 부드럽게 보간됩니다.

```
q(t) = SLERP(q0, q1, t)  (t: 0~1)
     = q0 · (q0^{-1} · q1)^t
```

py123d nuScenes 파서의 10Hz 보간 모드가 이 방식으로 키프레임 사이 박스를 보간합니다.

## 6. 오차 누적과 주의사항

### 수치 드리프트

회전 행렬을 반복적으로 곱하면 수치 오차가 누적되어 직교성이 깨집니다. 장시간 운행 궤적을 처리할 때 `R^T · R ≠ I` 문제가 생깁니다. 쿼터니언은 크기를 주기적으로 1로 정규화하는 것이 좋습니다.

### 쿼터니언 부호

`q`와 `-q`가 같은 회전이므로, 두 쿼터니언의 내적이 음수라면 둘 중 하나에 부호를 반전하고 SLERP해야 최단 경로를 보간합니다. 내적이 음수인 경우 보간 경로가 "돌아서" 갑니다.

### 규약 혼재

라이브러리마다 쿼터니언 순서, 행렬 표현(행 우선/열 우선), 회전 적용 방향(active/passive)이 다릅니다. py123d → NCore 변환처럼 두 라이브러리를 연결할 때는 반드시 각각의 규약을 확인하고 변환해야 합니다.

## 7. 정리

| 표현 | 파라미터 수 | 특징 | 쓰임새 |
|------|-----------|------|--------|
| 오일러 각 | 3 | 직관적, 짐벌 락 위험 | 사람이 읽는 UI |
| 회전 행렬 | 9 (자유도 3) | 행렬 연산 직접, 수치 드리프트 | 연산 중간 단계 |
| 쿼터니언 | 4 (단위 구속) | 짐벌 락 없음, SLERP 가능 | 저장, 보간, 합성 |
| SE3 (4×4) | 12 (자유도 6) | 회전+이동 통합, 합성이 행렬 곱 | 파이프라인 전체 |

py123d 파이프라인에서 좌표 변환이 일어나는 모든 지점 — 파서의 `cam_to_global` 계산, nuScenes 보간, NCore 원점 변환, CARLA Y축 반전 — 이 결국 SE3 합성, 역변환, 쿼터니언 변환으로 귀결됩니다.
