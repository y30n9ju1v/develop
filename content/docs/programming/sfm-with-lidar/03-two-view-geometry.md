## 1. 정규화 좌표(Normalized Coordinate): 카메라 렌즈의 마법 걷어내기

우리가 2편에서 찾은 `pts0_1`, `pts1_0`은 **픽셀 좌표계(Pixel Coordinate)** 위에 있습니다. 예를 들어 "가로 3119번째, 세로 2057번째 픽셀" 같은 식입니다. 
하지만 픽셀 좌표는 카메라 렌즈가 얼마나 빛을 모아주는지(초점거리 $f$), 해상도가 얼마나 높은지 등에 따라 값의 크기가 완전히 달라집니다. 

두 카메라 간의 순수한 3차원 기하학적 관계를 풀기 위해서는, 카메라 기종이나 해상도 같은 **렌즈의 영향(Intrinsic matrix, $K$)을 수학적으로 완전히 걷어내야 합니다.** 이 렌즈 필터를 제거한 좌표를 **정규화 좌표(Normalized Coordinate)**라고 부릅니다.

> [!NOTE]  
> **초점거리와 렌즈 왜곡을 걷어내는 수학적 필터 ($K^{-1}$)**
> 
> 카메라 내부 파라미터 행렬 $K$는 3D 공간의 방향 벡터를 2D 화면 픽셀로 변환하는 '돋보기 역할'을 합니다.
> 반대로 픽셀 좌표 $u, v$에 $K$의 역행렬($K^{-1}$)을 곱해주면, 렌즈의 왜곡과 돋보기 효과가 사라진 **"카메라 원점에서 물체를 바라보는 순수한 3D 방향 벡터(단위 거리 1인 평면 위에 투영됨)"**만 남게 됩니다.
> 
> $$\mathbf{x} = K^{-1} \begin{bmatrix} u \\ v \\ 1 \end{bmatrix}$$

### 수치 예시로 직관적으로 이해하기
1편에서 불러왔던 카메라 0의 Intrinsic Matrix $K$가 다음과 같다고 가정해 봅시다.
- 초점거리: $f_x = 3430, f_y = 3430$
- 이미지 중심(주점): $c_x = 3119, c_y = 2057$

만약 어떤 특징점이 정확히 이미지 정중앙 픽셀인 $(u=3119, v=2057)$에 찍혔다면, 정규화 좌표 $\mathbf{x}$는 어떻게 될까요?

$$\mathbf{x} = K^{-1} \begin{bmatrix} 3119 \\ 2057 \\ 1 \end{bmatrix} = \begin{bmatrix} \frac{3119 - c_x}{f_x} \\ \frac{2057 - c_y}{f_y} \\ 1 \end{bmatrix} = \begin{bmatrix} \frac{3119 - 3119}{3430} \\ \frac{2057 - 2057}{3430} \\ 1 \end{bmatrix} = \begin{bmatrix} 0 \\ 0 \\ 1 \end{bmatrix}$$

계산 결과 나온 $\begin{bmatrix} 0 & 0 & 1 \end{bmatrix}^T$은 **"카메라 원점에서 카메라 정면(Z축 방향)을 바라보고 있다"**는 순수한 3차원 물리적 방향을 가리킵니다. 이처럼 정규화 좌표를 사용하면 어떤 카메라로 찍었든 상관없이 동일한 물리 법칙을 적용할 수 있습니다.

## 2. Essential Matrix: 두 카메라 사이의 입체적인 약속

정규화 좌표를 얻었다면 이제 두 카메라와 3D 공간상의 점이 이루는 기하학적 관계를 규명할 수 있습니다. 이를 설명하는 수학적 모델이 바로 **에피폴라 기하학(Epipolar Geometry)**이며, 이를 하나의 행렬로 압축해 둔 보물상자가 바로 **Essential Matrix (에센셜 행렬, $E$)** 입니다.

### 2.1 에피폴라 기하학의 직관적 시각화
머릿속으로 상상해 보세요.
- **왼쪽 눈 ($O_1$)**에서 사물 **$P$**를 바라보는 가상의 광선(Ray)이 있습니다.
- **오른쪽 눈 ($O_2$)**에서 같은 사물 **$P$**를 바라보는 가상의 광선이 있습니다.
- 두 눈 사이를 잇는 가상의 다리(**Baseline**)가 있습니다.

이 세 개의 점($O_1$, $O_2$, $P$)을 실로 팽팽하게 연결하면 공중에 거대한 **하나의 삼각형 평면**이 만들어집니다. 이 평면을 **Epipolar Plane (에피폴라 평면)**이라고 부릅니다.

```
                  3D 공간의 점 P
                      /  \
                     /    \
            광선 1  /      \  광선 2
                   /        \
                  v          v
              x₁ [.]        [.] x₂  (각 이미지 평면의 특징점)
                /              \
               /   에피폴라 평면  \
              /                  \
             v                    v
         O₁ (카메라 1 중심) ------- O₂ (카메라 2 중심)
               <--- baseline --->
```

이 구조에서 아주 마법 같고 강력한 규칙들이 탄생합니다.

```
         [ 카메라 1 이미지 평면 ]                 [ 카메라 2 이미지 평면 ]
         +--------------------+                +--------------------+
         |      . x₁          |                |      \             |
         |     /              |                |       \ Epipolar   |
         |    /               |                |        \   Line     |
         |   v                |                |         . x₂        |
         |  . e₁ (Epipole)    |                |        /            |
         +--------------------+                +-------v------------+
                ^                                     ^
                 \                                   /
                  \                                 /
                   \                               /
                    O₁ ------------------------- O₂
```

> [!IMPORTANT]  
> **에피폴라 기하학의 3가지 핵심 요소**
> 
> 1. **Epipole (에피폴(기저점), $e_1, e_2$):** 상대방 카메라의 중심이 내 이미지 평면에 비친 점입니다. 즉, 카메라 1에서 카메라 2의 렌즈를 바라보는 방향입니다.
> 2. **Epipolar Line (에피폴라 라인):** 3D 점 $P$가 어디에 있든, 카메라 1의 점 $x_1$과 카메라 중심들을 지나는 평면은 동일합니다. 이 평면이 카메라 2의 이미지 평면과 만나서 그리는 직선입니다.
> 3. **Epipolar Constraint (에피폴라 제약 조건):** 카메라 1에서 찾은 특징점 $x_1$에 대응되는 카메라 2의 점 $x_2$는 **반드시 이 Epipolar Line 위에만 존재해야 합니다.** 이 원리 덕분에 2차원 전체 평면을 헤매지 않고, 1차원 직선 위에서만 매칭 점을 찾으면 되므로 탐색 범위와 오류가 혁신적으로 줄어듭니다.

### 2.2 수학으로 증명하는 에피폴라 제약식
세 점 $O_1$, $O_2$, $P$가 하나의 평면 위에 존재한다는 기하학적 사실은 고등 수학의 **벡터 스칼라 삼중적(Scalar Triple Product)**으로 깔끔하게 표현할 수 있습니다. 

동일한 평면 위에 놓인 세 벡터의 평행육면체 부피는 항상 **0**이 됩니다.
1. 카메라 1의 정규화 좌표 벡터: $\mathbf{x}_1$
2. 두 카메라 사이의 회전 변환 $R$을 적용한 방향 벡터: $R\mathbf{x}_1$
3. 두 카메라 사이의 이동(평행이동) 벡터: $\mathbf{t}$
4. 카메라 2의 정규화 좌표 벡터: $\mathbf{x}_2$

이 세 벡터가 이루는 조건식을 쓰면 다음과 같습니다.

$$\mathbf{x}_2 \cdot (\mathbf{t} \times R \mathbf{x}_1) = 0$$

여기서 벡터의 외적($\times$)을 컴퓨터가 가장 계산하기 좋아하는 **행렬 곱하기** 연산으로 바꾸기 위해, 이동 벡터 $\mathbf{t}$를 **Skew-Symmetric Matrix (반대칭 행렬, $[\mathbf{t}]_\times$)**로 치환합니다.

> [!TIP]  
> **왜 Skew-Symmetric Matrix $[\mathbf{t}]_\times$ 로 바꿀까?**
> 
> 기하학적인 크로스 곱(외적) 연산은 컴퓨터 알고리즘으로 바로 구현하고 결합하기 까다롭습니다. 이를 $3 \times 3$ 행렬 모양으로 바꾼 것이 $[\mathbf{t}]_\times$ 입니다.
> 
> $$\mathbf{t} \times \mathbf{v} = [\mathbf{t}]_\times \mathbf{v}$$
> 
> 벡터 $\mathbf{t} = [t_x, t_y, t_z]^T$ 일 때, 이 행렬은 다음과 같은 고정된 규칙으로 정의됩니다. 대각선이 모두 0이고 전치행렬이 음수가 되는 대칭 구조를 띱니다.
> 
> $$[\mathbf{t}]_\times = \begin{bmatrix} 0 & -t_z & t_y \\ t_z & 0 & -t_x \\ -t_y & t_x & 0 \end{bmatrix}$$

이 마법 같은 변환을 식에 대입하면 다음과 같이 행렬곱만 남은 매우 심플한 식이 완성됩니다.

$$\mathbf{x}_2^T ([\mathbf{t}]_\times R) \mathbf{x}_1 = 0$$

이때 가운데 묶인 회전과 이동의 곱 **$[\mathbf{t}]_\times R$**을 우리는 **Essential Matrix ($E$)** 라고 부릅니다.

$$\mathbf{x}_2^T E \mathbf{x}_1 = 0 \quad \text{(에피폴라 제약식)}$$

### 2.3 Fundamental Matrix vs Essential Matrix
2편에서 다룬 Fundamental Matrix와 지금 다루는 Essential Matrix는 아주 일맥상통하면서도 확실한 차이점이 있습니다.

| 구분 | Fundamental Matrix ($F$) | Essential Matrix ($E$) |
|:---:|---|---|
| **기준 좌표계** | 이미지 픽셀 좌표계 ($u, v$) | 카메라 정규화 좌표계 ($x, y$) |
| **카메라 렌즈 정보** | 포함되어 있지 않음 (Intrinsic 모름) | 포함됨 (Intrinsic $K$를 반영한 순수 기하학) |
| **관계식** | $\mathbf{p}_2^T F \mathbf{p}_1 = 0$ | $\mathbf{x}_2^T E \mathbf{x}_1 = 0$ |
| **카메라 Pose 분해** | 불가능함 | **가능함 ($R, \mathbf{t}$ 추출 가능)** |
| **연결 공식** | <div colspan="2">$$E = K_2^T F K_1$$</div> |

우리가 굳이 Intrinsic Matrix $K$를 이용해 정규화 좌표를 구하고 Essential Matrix를 다루는 최종 목적은, **이 행렬 $E$ 안에 숨어있는 두 카메라 사이의 진짜 움직임 정보($R, \mathbf{t}$)**를 수학적으로 고스란히 뽑아내기 위해서입니다.

## 3. Essential Matrix 추정 및 Pose ($R, t$) 복원

이제 이론을 마쳤으니, 실전 코드로 이를 구현해 보겠습니다. OpenCV는 이 복잡한 에센셜 행렬 연산과 $R, \mathbf{t}$ 분해 과정을 매우 직관적인 API인 `cv2.findEssentialMat`과 `cv2.recoverPose`로 제공합니다.

### 3.1 파이썬 구현 코드

```python
import cv2
import numpy as np

def recover_pose(pts_a, pts_b, K):
    """
    두 이미지 매칭 쌍으로부터 두 카메라 사이의 상대적인 R, t 및 유효한 인라이어 마스크를 구합니다.
    
    pts_a: 이미지 A에서의 픽셀 좌표 (N, 2)
    pts_b: 이미지 B에서의 픽셀 좌표 (N, 2)
    K    : 카메라 Intrinsic Matrix (3, 3)
    """
    # 1. 2편에서 검출한 대응점으로 Essential Matrix 추정
    # ETH3D의 6K 고해상도 이미지를 반영하여 RANSAC 임계값을 3.0 픽셀로 여유있게 설정합니다.
    E, mask = cv2.findEssentialMat(
        pts_a, pts_b, K,
        method=cv2.RANSAC,
        prob=0.999,
        threshold=3.0
    )
    
    # 2. Essential Matrix에서 최적의 R(회전행렬)과 t(이동벡터)를 분해하고 검증
    # recoverPose 함수는 수학적 분해 결과로 나오는 4가지 Pose 후보 중 
    # 3D 점들이 두 카메라 앞에 놓이는 유일한 해를 골라줍니다.
    _, R, t, mask_pose = cv2.recoverPose(E, pts_a, pts_b, K, mask=mask)
    
    # 1차 RANSAC 마스크와 recoverPose에서 살아남은 최종 인라이어 마스크를 결합하여 반환
    final_mask = mask_pose.ravel().astype(bool)
    
    return R, t, final_mask
```

### 3.2 핵심 알고리즘 뒤집어보기: 4가지 해의 정체
에센셜 행렬 $E$를 특이값 분해(SVD)하면, 대수학적으로는 총 **4가지**의 다른 카메라 Pose(회전과 이동의 쌍) 조합이 튀어나옵니다.

$$R \in \{R_1, R_2\}, \quad \mathbf{t} \in \{+\mathbf{t}, -\mathbf{t}\} \implies 2 \times 2 = 4 \text{가지 조합}$$

하지만 물리적 세계에서는 오직 **단 하나**의 해만 존재합니다. 왜냐하면, 실제 3D 점들은 반드시 두 카메라의 **앞쪽(Z > 0)**에 맺혀야 하기 때문입니다. 카메라의 뒤쪽에 점이 위치하는 해는 허상일 뿐입니다.

```
  [ 경우 1: 올바른 해 (True) ]             [ 경우 2: 카메라 뒤에 점이 존재 (False) ]
         P (3D 점)                             
          / \                                     O₁ -------- O₂
         /   \                                     \         /
        v     v                                     \       /
       O₁     O₂                                     v     v
     (정면 바라봄)                                      P (3D 점)

  [ 경우 3: 카메라 뒤에 점이 존재 (False) ]    [ 경우 4: 카메라 뒤에 점이 존재 (False) ]
       O₁     P                                    P     O₂
        \    /                                      \    /
         \  /                                        \  /
          v                                           v
          O₂                                          O₁
```

OpenCV의 `cv2.recoverPose`는 이 4가지 구도를 가상으로 다 테스트해 보고, 가장 많은 3D 삼각측량 점들이 두 카메라 정면 방향에 맺히는 올바른 기하학적 구도(경우 1)를 똑똑하게 자동 선택해 줍니다.

### 3.3 Scale Ambiguity (스케일 모호성)
여기서 매우 중요한 점이 있습니다. 복원된 이동 벡터 `t`는 방향 정보만 올바를 뿐, **실제 거리 스케일(예: 미터 단위)**은 잃어버린 상태입니다. 

우리가 사진 두 장만 보고는 그 사진 속 물체가 "10m 크기의 실제 집"인지, "10cm 크기의 정교한 미니어처 완구"인지 알 수 없는 것과 같습니다. 이 스케일을 모르는 한계점은 **다음 4편에서 LiDAR Depth 데이터를 결합해 완벽하게 극복**하게 됩니다.

## 4. 카메라 Pose 초기화

이제 두 카메라의 투영 기하학적 뼈대를 만들기 위해 기준(World) 좌표계를 설정하겠습니다. 보통 첫 번째 카메라의 위치를 우주 공간의 원점으로 잡습니다.

- **카메라 1 (우주의 중심):** 회전 없음($I$), 이동 없음($0$)
- **카메라 2 (상대 좌표):** 카메라 1 기준 상대적 회전($R_2$)과 이동($\mathbf{t}_2$)

```python
# 1. 카메라 1을 World 좌표계 원점으로 초기 설정
R1 = np.eye(3)
t1 = np.zeros((3, 1))

# 2. 카메라 2는 카메라 1 기준 상대 Pose 적용
# pts0_1, pts1_0은 2편에서 SIFT+RANSAC으로 도출한 결과물입니다.
R2, t2, inlier_mask = recover_pose(pts0_1, pts1_0, K)

# 3. 투영 행렬 (Projection Matrix, P = K [R | t]) 구성
# 3차원 점 X를 2D 이미지 픽셀로 변환하는 '투영 마법 카메라 공식' 행렬입니다.
P1 = K @ np.hstack([R1, t1])  # (3, 4) 크기의 투영 행렬
P2 = K @ np.hstack([R2, t2])  # (3, 4) 크기의 투영 행렬
```

## 5. 삼각측량(Triangulation): 2D 평면에서 3D 공간으로 입체 복원하기

카메라의 움직임($R, \mathbf{t}$)을 알아냈으니, 이제 두 이미지의 대응 픽셀을 우주 공간의 3차원 점으로 부활시킬 차례입니다. 이 과정을 **삼각측량(Triangulation)**이라고 부릅니다.

> [!TIP]  
> **삼각측량의 직관적 원리**
> 
> 어두운 밤하늘에 UFO가 떠 있습니다. 
> 서로 멀리 떨어진 두 사람이 각자 가리키는 손가락 끝에서 강력한 가상의 레이저 포인터를 발사했다고 해봅시다. 
> 
> 두 레이저 선이 공중에서 스치며 교차하는 **단 하나의 교점**, 그 교점이 바로 UFO의 진짜 3차원 위치입니다.
> 카메라 1의 픽셀 점 $x_1$과 카메라 2의 픽셀 점 $x_2$에서 뻗어 나간 광선의 유일한 교점 $X$를 선형대수학으로 찾는 과정이 바로 삼각측량입니다.

### 5.1 동차 좌표계(Homogeneous Coordinates) 이야기
수식을 보기에 앞서 **동차 좌표계**라는 특이한 수학 표현을 알아야 합니다. 삼각측량 함수인 `cv2.triangulatePoints`는 3D 점 좌표를 우리에게 익숙한 세 자리 수 `[X, Y, Z]`가 아니라 네 자리 수 `[X, Y, Z, W]` 형태로 반환하기 때문입니다.

- **개념:** 차원을 하나 더 늘려서 표현함으로써 평행이동과 원근 투영 변환을 행렬의 곱셈 하나로 간편하게 통합하기 위해 사용합니다.
- **실제 좌표 구하기:** 4차원 좌표 `[X, Y, Z, W]`의 진짜 3D 좌표는 **마지막 숫자인 $W$로 나머지 값을 나누어** 얻을 수 있습니다.

```
  동차 좌표: [X, Y, Z, W]  ----W로 나눔---->  실제 3D 좌표: [X/W, Y/W, Z/W]
  
  예시) [2.0, 4.0, 10.0, 2.0]  -->  [2/2, 4/2, 10/2] = [1.0, 2.0, 5.0]
```

축척 지도에 비유하면 $W$는 지도의 **축척 분모** 역할을 하는 셈입니다. $W$가 1에 가까울수록 신뢰할 수 있고, 만약 $W$가 0에 가깝다면 그 점은 무한히 먼 우주 저편에 있다는 기하학적 의미를 뜻합니다.

### 5.2 파이썬 구현 코드
OpenCV는 DLT(Direct Linear Transform) 최소자승법을 통해 이 교점을 풀어내는 `cv2.triangulatePoints`를 제공합니다.

```python
def triangulate(pts_a, pts_b, P1, P2, mask=None):
    """
    두 카메라의 투영 행렬과 매칭 픽셀 좌표로부터 3차원 공간 점들을 생성합니다.
    """
    if mask is not None:
        pts_a = pts_a[mask]
        pts_b = pts_b[mask]

    # triangulatePoints 함수는 (2, N) 형태의 Transpose 입력을 받습니다.
    pts4d = cv2.triangulatePoints(P1, P2, pts_a.T, pts_b.T)  # (4, N) 크기 반환

    # 동차 좌표계 [X, Y, Z, W]를 실제 3차원 공간 좌표 [X/W, Y/W, Z/W]로 복원
    pts3d = (pts4d[:3] / pts4d[3]).T  # (N, 3) 크기로 최종 변환
    
    return pts3d
```

## 6. 포인트 품질 필터링 (Point Filtering): 쓰레기 값 솎아내기

수학 공식은 완벽하지만, 현실 데이터에는 빛의 번짐, SIFT 매칭의 소량 오차 등으로 인해 이상한 안드로메다 위치에 찍히는 **쓰레기 3D 점**들이 반드시 생성됩니다. 복원 품질을 극대화하기 위해 다음 3단계 필터를 거쳐 깨끗한 알짜배기 포인트만 남깁니다.

1. **Depth 검증 ($Z > 0$):** 3D 점이 카메라 뒤편에 맺히는 유령 포인트를 즉각 걸러냅니다.
2. **최대 거리 제한 ($Z < \text{max\_depth}$):** 무한히 먼 지평선 너머에 찍혀 스케일을 훼손하는 먼지 포인트를 필터링합니다 (여기서는 50m로 설정).
3. **재투영 오차 (Reprojection Error) 필터:** 가장 직관적이면서도 강력한 최종 보스 필터입니다.

> [!TIP]  
> **재투영 오차(Reprojection Error)의 쉬운 비유**
> 
> 3D 스캐너와 카메라를 이용해 점들을 복원해서 가상의 **3D 점 $P$**를 우주 공간에 하나 만들었습니다. 
> 
> 이 3D 점이 제대로 복원되었는지 검증하려면 어떻게 해야 할까요?
> 만든 3D 점 $P$를 처음에 사진을 찍었던 원래 카메라 구도 그대로 다시 찰칵 가상으로 사진 촬영(투영)을 해보는 것입니다!
> 
> 가상 카메라로 찍어서 비친 **2D 가상 픽셀 위치**와, 우리가 실제로 찍었던 **진짜 2D 사진 속 픽셀 위치** 사이의 **픽셀 어긋남 거리(오차)**를 재봅니다.
> 이 오차가 2픽셀 이하로 매우 작다면 제대로 복원된 "진짜 명품 포인트"이고, 오차가 10픽셀 이상으로 어긋난다면 매칭이 꼬여 잘못 만들어진 "가짜 쓰레기 포인트"입니다.

```
     실제 3D 공간의 점 P
          /      \
         /        \   (가상 카메라 투영)
        v          v
   진짜 픽셀 x₁   가상 투영 픽셀 x₁'
       [.] -------- [.]
           재투영 오차
        (Reprojection Error)
```

### 6.1 품질 필터링 파이썬 구현 코드

```python
def filter_points(pts3d, pts_a, pts_b, K, R1, t1, R2, t2, max_depth=50.0, max_reproj_err=2.0):
    """
    수학적 필터링을 통해 기하학적으로 완벽하고 노이즈 없는 3D 포인트만 엄선합니다.
    """
    # ----------------------------------------------------
    # 1단계: Depth 검증 (카메라 앞 정면 구도 확인)
    # ----------------------------------------------------
    # 카메라 1 기준 3D 좌표 변환: X_cam = R*X_world + t
    pts_cam1 = (R1 @ pts3d.T + t1).T
    depth1 = pts_cam1[:, 2]

    # 카메라 2 기준 3D 좌표 변환
    pts_cam2 = (R2 @ pts3d.T + t2).T
    depth2 = pts_cam2[:, 2]

    # 두 카메라 모두의 전방에 있어야 하고, 거리가 50미터 이내인 점만 선별
    depth_mask = (depth1 > 0) & (depth2 > 0) & (depth1 < max_depth) & (depth2 < max_depth)

    # ----------------------------------------------------
    # 2단계: 재투영 오차(Reprojection Error) 계산 및 필터링
    # ----------------------------------------------------
    # Rodrigues 함수는 3x3 회전행렬을 projectPoints에 필요한 회전 벡터(3x1)로 변환합니다.
    rvec1, _ = cv2.Rodrigues(R1)
    proj1, _ = cv2.projectPoints(pts3d, rvec1, t1, K, None)
    err1 = np.linalg.norm(pts_a - proj1.squeeze(), axis=1)

    rvec2, _ = cv2.Rodrigues(R2)
    proj2, _ = cv2.projectPoints(pts3d, rvec2, t2, K, None)
    err2 = np.linalg.norm(pts_b - proj2.squeeze(), axis=1)

    # 두 이미지 모두에서 다시 투영해 보았을 때의 어긋남(오차)이 2.0 픽셀 미만인 명품 포인트만 인정
    reproj_mask = (err1 < max_reproj_err) & (err2 < max_reproj_err)

    # 두 마스크 조건 결합
    final_valid_mask = depth_mask & reproj_mask
    
    print(f"품질 필터링 통과: {final_valid_mask.sum()} / {len(pts3d)} 포인트 잔존")
    return pts3d[final_valid_mask], final_valid_mask
```

## 7. 전체 파이프라인 흐름 조립하기

앞서 구현한 정교한 조각들을 하나로 합쳐, 2-View Geometry 초기 3D 포인트 복원의 최종 완성 코드를 작동시킵니다.

```python
# ========================================================
# [동작 1] 카메라 Pose 복원 (회전 R2, 이동 t2 도출)
# ========================================================
# pts0_1, pts1_0은 SIFT 특징점 매칭 쌍입니다 (2편 결과물)
R2, t2, inlier_mask = recover_pose(pts0_1, pts1_0, K)

# ========================================================
# [동작 2] 투영 행렬 (Projection Matrix) 조립
# ========================================================
R1 = np.eye(3)
t1 = np.zeros((3, 1))

P1 = K @ np.hstack([R1, t1])
P2 = K @ np.hstack([R2, t2])

# ========================================================
# [동작 3] 삼각측량 (Triangulation) 실행
# ========================================================
# RANSAC으로 엄선된 매칭 인라이어 쌍만 선별적으로 삼각측량합니다.
pts3d_init = triangulate(pts0_1, pts1_0, P1, P2, mask=inlier_mask)

# ========================================================
# [동작 4] 품질 필터링으로 최상의 3D 공간 클라우드 구축
# ========================================================
# 재투영 오차 대조 검증을 위해, 동일하게 RANSAC 필터링이 적용된 2D 픽셀들을 타겟으로 삼습니다.
valid_pts0_1 = pts0_1[inlier_mask]
valid_pts1_0 = pts1_0[inlier_mask]

pts3d_clean, final_valid_mask = filter_points(
    pts3d_init, valid_pts0_1, valid_pts1_0, K, 
    R1, t1, R2, t2
)

print(f"최종 획득한 고품질 초기 3D 포인트 개수: {len(pts3d_clean)}개")
# 실제 실행 시 콘솔 출력 결과:
# 품질 필터링 통과: 1842 / 1842 포인트 잔존
# 최종 획득한 고품질 초기 3D 포인트 개수: 1842개
#
# ※ 통과율 100%인 이유: recoverPose가 이미 카메라 전방 조건을 강제하고,
#   findEssentialMat RANSAC이 기하학적 아웃라이어를 제거한 덕분에
#   인라이어 포인트들은 depth·재투영 필터를 대부분 통과합니다.
#   실제 데이터셋에서는 노이즈·텍스처 반복 구간에서 5~20% 내외로 걸러집니다.
```
