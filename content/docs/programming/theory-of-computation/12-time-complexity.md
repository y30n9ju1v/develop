지난 11편에서는 프로그램이 자기 자신의 코드를 획득하는 **재귀 정리(Recursion Theorem)**와 이를 활용해 수학의 불완전함을 입증한 괴델의 제1불완전성 정리를 공부했습니다.

지금까지는 "이 문제가 컴퓨터로 풀 수 있는가 없는가(판정 가능성)"의 근본적인 경계를 다루었다면, 이제부터는 **"이 문제를 컴퓨터로 현실적인 시간과 자원 내에 효율적으로 풀 수 있는가"**를 다루는 **계산 복잡도 이론(Complexity Theory)**의 세계로 진입합니다.

이번 12번째 강의와 강의 슬라이드에서는 복잡도 분석의 기초인 시간 복잡도와 클래스 P(Class P)에 대해 알아보겠습니다.

## 1. 계산 복잡도 이론의 서막과 Worst-case Complexity

1930년대부터 1950년대까지의 계산 이론은 **"판정 가능한가?"**에 집중했습니다. 반면, 1960년대부터 현재까지의 복잡도 이론은 **"한정된 자원(시간, 메모리)을 가지고 판정 가능한가?"**를 질문합니다.

어떤 알고리즘의 동작 속도는 입력의 크기 $n$에 비례하여 결정됩니다. 복잡도 이론에서는 입력의 종류에 상관없이 최악의 입력을 만났을 때도 보장할 수 있는 상한선인 **최악의 경우 시간 복잡도(Worst-case Time Complexity)**를 기준으로 계산 자원을 측정합니다.

이를 표기하기 위해 점근적 표기법인 **Big-O ($O$)** 기호를 사용합니다.
- $f(n) = O(g(n))$: 큰 $n$에 대해 $f(n)$이 $g(n)$의 상수 배를 넘지 않는다. (상한선)
- $f(n) = o(g(n))$: $n$이 무한히 커질 때 $f(n)$이 $g(n)$에 비해 무시할 수 있을 만큼 느리게 자란다(즉, $f(n)/g(n) \to 0$). (초과 상한선)

## 2. 컴퓨터 모델에 따라 시간이 다르다? 모델 의존성 (Model Dependence)

계산 가능성 이론에서는 어떤 하드웨어 모델(단일 테이프, 다중 테이프, RAM 등)을 쓰든 풀 수 있는 문제의 종류가 같았습니다(처치-튜링 명제). 

하지만 **복잡도 이론에서는 하드웨어 모델에 따라 걸리는 시간 복잡도가 달라집니다.** 문자열 $A = \{a^k b^k \mid k \ge 0\}$의 판별 속도를 비교해 봅시다.

### A. 1-테이프 튜링 머신 (DFA 시뮬레이션)
- **일반적인 방법**: 매번 테이프 왼쪽 끝에서 오른쪽 끝을 왕복하며 $a$ 하나와 $b$ 하나를 지워나갑니다. 지우는 데 $O(n)$ 단계가 걸리고, 총 $n$번 왕복하므로 **$O(n^2)$ 시간**이 소요됩니다.
- **개선된 방법 (Parity Check)**: 스캔할 때 매번 지워지지 않은 문자들 중 한 칸씩 건너뛰며(짝수/홀수 번째 문자를) 절반씩 지워나갑니다. 이렇게 하면 루프 횟수가 $\log n$번으로 줄어들어 **$O(n \log n)$ 시간**에 해결할 수 있습니다.
  - *수학적 정리: 1-테이프 튜링 머신에서 $a^k b^k$ 언어를 $o(n \log n)$ 시간 내에 해결하는 것은 불가능함이 증명되어 있습니다.*

### B. 다중 테이프 튜링 머신 (Multi-tape TM)
- **알고리즘**: 첫 번째 테이프에서 $a$들을 스캔해 두 번째 테이프에 카피합니다. 이어서 첫 번째 테이프의 $b$들과 두 번째 테이프의 $a$들을 일대일로 대조하며 앞으로 나아갑니다. 테이프를 뒤로 되돌릴 필요가 없으므로 **단 $O(n)$ 시간(선형 시간)**만에 해결됩니다.

### 다항식적 관계 (Polynomially Related)
비록 모델에 따라 시간 복잡도가 $O(n \log n)$과 $O(n)$으로 다르지만, 수학자들은 이 차이가 합리적인 한계 내에 있음을 발견했습니다.

> **정리: 다중 테이프 튜링 머신에서 $t(n)$ 시간에 해결되는 문제 $B$는, 1-테이프 튜링 머신에서 $O(t^2(n))$ 시간(제곱 관계) 내에 해결할 수 있다.**

1-테이프 머신, 다중 테이프 머신, RAM, 셀룰러 오토마타 등 모든 합리적인 결정적 계산 모델들은 서로를 시뮬레이션할 때 걸리는 시간이 최대 **다항식 배(Polynomial overhead)**만큼만 차이 납니다. 이를 **다항식적 관계**라고 합니다.

## 3. 시간 복잡도 클래스 TIME(t(n))과 클래스 P

시간 복잡도의 한계를 기준으로 문제들을 분류하기 위해 복잡도 클래스를 정의합니다.

### $\text{TIME}(t(n))$ 클래스
$$\text{TIME}(t(n)) = \{ L \mid L\text{은 } O(t(n)) \text{ 시간의 결정적 1-테이프 TM으로 판정 가능하다} \}$$
예를 들어, $\{a^k b^k\} \in \text{TIME}(n \log n)$ 입니다.

### 클래스 P (The Class P)
현대 컴퓨터 과학에서 가장 중대한 복잡도 클래스인 **P**는 **다항 시간(Polynomial Time)** 내에 해결할 수 있는 모든 판정 문제들의 집합입니다.

$$\text{P} = \bigcup_{k \ge 1} \text{TIME}(n^k)$$

클래스 P가 중요한 이유는 두 가지입니다:
1. **모델 독립성 (Model Invariance)**: 합리적인 결정적 모델들이 모두 다항식적 관계로 묶여 있기 때문에, 어떤 컴퓨터 기종을 쓰든 **P에 속하는 문제는 어떤 컴퓨터에서도 항상 다항 시간 내에 풀립니다.**
2. **현실적인 해결 가능성 (Realistic Solvability)**: 입력 $n$이 커질 때 $2^n$ 같은 지수 시간 알고리즘은 우주 나이만큼 돌려도 답이 나오지 않는 반면, $n^2$이나 $n^3$ 같은 다항 시간 알고리즘은 실생활에서 유의미한 속도로 작동합니다. 따라서 클래스 P는 **실제로 해결 가능한(Tractable) 문제**의 바운더리가 됩니다.

---

## 4. P 클래스의 대표 문제: PATH vs HAMPATH

두 유사한 문제의 시간 복잡도 분석을 통해 P 클래스의 특징을 이해해 봅시다.

### A. PATH 문제 (P 클래스)
$$\text{PATH} = \{ \langle G, s, t \rangle \mid G\text{는 } s\text{에서 } t\text{로 가는 경로가 존재하는 유향 그래프이다} \}$$
- **알고리즘**: 너비 우선 탐색(BFS)을 사용해 $s$부터 이웃 노드들을 하나씩 마킹해 나갑니다.
- **복잡도**: 노드의 총 개수를 $n$이라 할 때, 최대 $n$번의 탐색 루프 $\times$ 각 루프당 $n$개의 노드 스캔 $\times$ $O(n^2)$의 간선 검사가 이루어지므로 총 **$O(n^4)$ 단계**가 걸립니다.
- $n^4$은 다항식이므로 **$\text{PATH} \in \text{P}$**가 성립합니다.

### B. HAMPATH 문제 (해밀턴 경로 문제)
$$\text{HAMPATH} = \{ \langle G, s, t \rangle \mid G\text{는 } s\text{에서 } t\text{로 가되, 모든 노드를 정확히 한 번씩만 방문하는 경로가 존재한다} \}$$
- **문제점**: 이 문제는 방문 여부만 마킹하며 나아갈 수 없습니다. 모든 경우의 수(순열)를 조사해야 하므로 가능한 경로가 $m! \ge 2^m$개 이상 존재할 수 있습니다.
- **복잡도**: 브루트 포스로 탐색할 경우 **지수 시간(Exponential Time)**이 걸립니다.
- 아직 전 세계 수학자 중 그 누구도 이 HAMPATH를 다항 시간 내에 풀 수 있는 알고리즘을 찾아내지 못했습니다. 그렇다고 다항 시간에 풀 수 없다는 증명조차 하지 못했습니다.

이 HAMPATH처럼 "다항 시간 알고리즘은 없지만, 답이 주어졌을 때 맞는지 검사하는 것은 다항 시간에 가능한" 문제들의 범주가 바로 다음 시간에 만나게 될 복잡도 이론의 핵심, **NP 클래스**입니다.

## 요약 및 마치며

- **계산 복잡도 이론**은 한정된 자원 하에서의 문제 해결 능력을 평가합니다.
- **시간 복잡도**는 하드웨어 모델에 따라 다르지만, 합리적인 결정적 하드웨어 기계들은 서로 **다항식적 관계(Polynomial overhead)**로 묶여 있습니다.
- **클래스 P**는 모델 독립적인 다항 시간 판정 가능 문제들의 집합으로, **현실적으로 컴퓨터가 해결할 수 있는 한계선**입니다.
- 경로 존재 문제인 **$\text{PATH}$**는 $O(n^4)$ 알고리즘이 존재해 P에 속하지만, 모든 점을 방문하는 **$\text{HAMPATH}$**는 지수 시간이 걸려 P에 속하는지 여부가 베일에 싸여 있습니다.

계산 복잡도 이론의 기초 체력을 다졌습니다. 다음 13번째 강의 요약에서는 전산학 최고의 미해결 난제인 **P vs NP 문제**의 실체와, 답을 검증하는 시간 복잡도를 정의하는 **NP 클래스**에 대해 자세히 알아보겠습니다!
