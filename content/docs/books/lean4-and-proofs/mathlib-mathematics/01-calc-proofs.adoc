== 손으로 쓰는 증명과 Lean4 증명 사이의 간극

수학 증명을 손으로 쓸 때는 보통 이런 식입니다 — "`a = b + 2`이고 `b = 3`이니, `a = 3 + 2 = 5`다." 이 계단식 논증을 `by rw [h1]; rw [h2]; norm_num`처럼 전술을 이어 붙여 표현할 수도 있지만, 그러면 **중간에 어떤 값을 거쳐 가는지가 코드에서 안 보입니다**. `calc`는 이 문제를 풉니다 — 손으로 쓰는 증명의 "계단"을 코드에 그대로 남겨둡니다.

[source,lean]
----
example (a b : ℝ) (h1 : a = b + 2) (h2 : b = 3) : a = 5 := by
  calc a = b + 2 := h1
    _ = 3 + 2 := by rw [h2]
    _ = 5 := by norm_num
----

`calc`는 `a = 5`라는 목표를 `a = b + 2`, `b + 2 = 3 + 2`, `3 + 2 = 5`라는 세 개의 작은 등식으로 쪼갭니다. 각 줄이 "왼쪽이 오른쪽과 같다"는 걸 각자 증명하고, `calc`가 이 등식들을 자동으로 이어 붙여(등식의 추이성을 이용해) 전체 목표를 완성합니다. `_`는 "바로 앞 줄의 오른쪽 값"을 가리키는 자리표시자입니다 — 매번 값을 반복해서 안 써도 됩니다.

== 부등식도 섞어 쓸 수 있다

[source,lean]
----
example (x y : ℝ) (h1 : x ≤ y + 1) (h2 : y < 4) : x < 6 := by
  calc x ≤ y + 1 := h1
    _ < 4 + 1 := by linarith
    _ = 5 := by norm_num
    _ < 6 := by norm_num
----

`calc`의 강력한 점은 **등식과 부등식을 자유롭게 섞을 수 있다**는 것입니다 — `≤`로 시작해서 `<`를 거쳐 다시 `=`, `<`로 이어져도, `calc`가 "전체적으로 `x < 6`이다"라는 결론을 자동으로 조합해줍니다(`≤`와 `<`를 섞으면 최종 결론은 더 강한 쪽인 `<`가 됩니다 — 이 관계 조합 규칙도 Mathlib이 미리 갖추고 있습니다). `linarith`(선형 산술 자동 증명 전술로, 여러 부등식·등식 가정을 조합해 목표를 증명합니다)가 `h2 : y < 4`로부터 `y + 1 < 4 + 1`을 자동으로 이끌어냅니다.

== 대칭적인 증명에서 진가를 발휘한다

[source,lean]
----
example (a b c : ℝ) (h1 : a = b) (h2 : b = c) : a + a = c + c := by
  calc a + a = b + b := by rw [h1]
    _ = c + c := by rw [h2]
----

`a = b`와 `b = c`가 주어졌을 때 `a + a = c + c`를 증명하는 것도, `calc`로 쓰면 "`a`를 `b`로 바꾸고, `b`를 다시 `c`로 바꾼다"는 두 단계가 코드에 그대로 드러납니다. `rw [h1]`이 `a`를 `b`로 다시 쓰는 전술(3장 이전에도 이미 익숙할 수 있는 도구입니다)이라는 걸 떠올리면, `calc`가 하는 일은 "여러 개의 `rw`/증명 단계를, 중간값을 명시하면서 이어 붙이는 것"이라고 정리할 수 있습니다.

== 왜 굳이 calc를 쓰는가

`by rw [h1, h2]; norm_num`처럼 짧게 써도 되는 증명을 왜 `calc`로 풀어쓸까요 — 두 가지 이유가 있습니다.

* *가독성*: 증명이 길어질수록, 중간에 어떤 값을 거치는지가 코드에 남아있으면 나중에 이 증명을 읽는 사람(미래의 자신 포함)이 논증을 따라가기 훨씬 쉽습니다.
* *디버깅*: 증명이 막히면, `calc`의 각 줄을 개별적으로 확인할 수 있습니다 — 어느 단계에서 막혔는지가 명확합니다. 반면 `by rw [h1, h2]; norm_num`처럼 전술을 뭉쳐 쓰면, 실패했을 때 정확히 어느 지점이 문제인지 파악하기가 상대적으로 어렵습니다.

이 책 전체에서 증명이 두세 단계를 넘어가면 `calc`를 적극적으로 씁니다 — 나머지 장들에서 계속 다시 보게 될 패턴입니다.

== 직접 해보기

* `(x : ℝ) (h1 : x = 2) (h2 : x * x = y) : y = 4`를 `calc`로 증명해보세요.

.해답 보기
[%collapsible]
====
[source,lean]
----
example (x y : ℝ) (h1 : x = 2) (h2 : x * x = y) : y = 4 := by
  calc y = x * x := h2.symm
    _ = 2 * 2 := by rw [h1]
    _ = 4 := by norm_num
----

`h2 : x * x = y`는 방향이 반대라, `h2.symm`(등식의 방향을 뒤집는 Mathlib의 기본 도구)으로 뒤집어서 `calc` 첫 줄에 씁니다.
====

== 요약

* `calc`는 손으로 쓰는 계단식 증명을 코드에 그대로 옮기게 해주는 문법입니다 — 각 단계의 중간값이 코드에 남아 가독성과 디버깅에 유리합니다.
* `_`는 바로 앞 줄의 오른쪽 값을 가리키는 자리표시자입니다.
* `calc`는 등식과 부등식을 섞어 쓸 수 있고, Mathlib이 그 관계들을 자동으로 조합해 최종 결론을 만들어줍니다.
