14장에서 벡터공간을 공리화했다면, 이 장에서는 벡터공간 **사이**의 구조를 보존하는 함수 — 선형사상 — 을 다룹니다. 12장의 군 준동형사상과 정확히 같은 발상이 벡터공간에서 다시 등장합니다.

== 선형사상: 덧셈과 스칼라 곱을 보존하는 함수

[source,lean]
----
example {V W : Type*} [AddCommGroup V] [Module ℝ V] [AddCommGroup W] [Module ℝ W]
    (f : V →ₗ[ℝ] W) (u v : V) : f (u + v) = f u + f v := f.map_add u v

example {V W : Type*} [AddCommGroup V] [Module ℝ V] [AddCommGroup W] [Module ℝ W]
    (f : V →ₗ[ℝ] W) (c : ℝ) (v : V) : f (c • v) = c • f v := f.map_smul c v
----

`V →ₗ[ℝ] W`(선형사상)는 12장의 `G →* H`(군 준동형사상)와 같은 패턴입니다 — 함수이면서, 그 함수가 구조(이번엔 덧셈과 스칼라 곱)를 보존한다는 증거까지 함께 담고 있는 값입니다. `f (u+v) = f u + f v`(덧셈 보존)와 `f (c•v) = c•(f v)`(스칼라 곱 보존)가 정의의 핵심입니다.

== 직접 선형사상 만들어보기

[source,lean]
----
def proj1 : (Fin 2 → ℝ) →ₗ[ℝ] ℝ where
  toFun v := v 0
  map_add' u v := by simp
  map_smul' c v := by simp

example : proj1 (fun i => if i = 0 then 3 else 5) = 3 := by norm_num [proj1]
----

`proj1`은 "2차원 벡터에서 첫 번째 좌표만 뽑아내는" 선형사상입니다. `V →ₗ[ℝ] W`라는 타입의 값을 만들려면 `toFun`(실제로 무엇을 계산하는지)과 함께, 그게 정말 덧셈·스칼라 곱을 보존한다는 **증거**(`map_add'`, `map_smul'`)를 같이 지어줘야 합니다 — "좌표 하나를 뽑는 것"이 왜 선형적인지는 직관적으로 당연해 보이지만, Lean4는 그 당연함도 실제로 증명하라고 요구합니다(`by simp`가 두 증거 모두 자동으로 처리해줍니다). `(3, 5)`라는 벡터에 `proj1`을 적용하면 정확히 `3`이 나옵니다.

== 선형사상의 합성도 선형사상이다

[source,lean]
----
example {U V W : Type*} [AddCommGroup U] [Module ℝ U] [AddCommGroup V] [Module ℝ V]
    [AddCommGroup W] [Module ℝ W] (f : U →ₗ[ℝ] V) (g : V →ₗ[ℝ] W) (u1 u2 : U) :
    (g.comp f) (u1 + u2) = (g.comp f) u1 + (g.comp f) u2 := (g.comp f).map_add u1 u2
----

`g.comp f`(먼저 `f`, 그다음 `g`)도 다시 선형사상입니다 — 이 사실 자체는 Mathlib이 `LinearMap.comp`를 정의할 때 이미 증명해뒀고, 우리는 그냥 결과로 나온 `g.comp f`가 여전히 `.map_add`를 가진 선형사상이라는 걸 확인만 하면 됩니다. "구조를 보존하는 함수들의 합성은 다시 구조를 보존한다"는 원리가 12장의 군 준동형사상에서도 성립했던 것과 같은 패턴입니다.

== 행렬: 선형사상을 구체적인 수로 표현하기

[source,lean]
----
example : (!![1, 2; 3, 4] : Matrix (Fin 2) (Fin 2) ℝ) 0 1 = 2 := by norm_num

example : (!![1, 2; 3, 4] : Matrix (Fin 2) (Fin 2) ℝ) * !![1, 0; 0, 1] = !![1, 2; 3, 4] := by
  norm_num [Matrix.mul_fin_two]
----

`!![1, 2; 3, 4]`는 `2×2` 행렬을 손으로 쓴 것과 똑같은 모양으로 적는 표기법입니다 — `[0][1]` 위치(0번째 행, 1번째 열)를 조회하면 `2`가 나옵니다. 항등행렬(`!![1,0;0,1]`)을 곱해도 원래 행렬이 그대로 나온다는 것도 확인했습니다 — **행렬은 선형사상을 구체적인 수의 배열로 옮겨 적은 것**입니다. 추상적인 선형사상(`V →ₗ[ℝ] W`)과 구체적인 행렬(`Matrix`)은 벡터공간에 좌표(기저)를 정하는 순간 서로 대응됩니다 — 이 대응 자체는 이 책의 범위를 넘어서지만, 왜 "선형대수 문제를 행렬 계산으로 바꿔 푼다"는 게 정당한지의 근거가 여기 있습니다.

== 행렬 곱셈이 결합적인 이유

[source,lean]
----
example (A B C : Matrix (Fin 2) (Fin 2) ℝ) : A * B * C = A * (B * C) := mul_assoc A B C
----

행렬 곱셈이 결합법칙을 만족한다는 건 손으로 확인하려면 성분 하나하나를 전개해야 하는 지루한 계산이지만, Mathlib은 이미 `mul_assoc`(11장에서 본, 사실 곱셈이 있는 어떤 구조든 만족하길 기대하는 그 결합법칙과 이름이 같습니다!)으로 증명해뒀습니다. 행렬 곱셈이 결합적인 진짜 이유는 **함수 합성이 결합적이기 때문**입니다 — 행렬 곱셈은 결국 선형사상의 합성을 좌표로 표현한 것이고, "먼저 F, 그다음 G, 그다음 H"를 어떻게 묶어 계산하든 결과가 같다는 게 합성의 결합성입니다.

== 5부를 마무리하며

14~15장에서 본 벡터공간·부분공간·선형사상·행렬은 서로 독립된 개념이 아니라 하나의 그림입니다 — 벡터공간이 대상이라면, 선형사상은 그 대상들 사이를 잇는 화살표이고, 행렬은 그 화살표를 손으로 계산할 수 있게 좌표로 옮긴 것입니다. 12장의 군·준동형사상·핵이 여기서 벡터공간·선형사상·핵(선형사상 버전의 커널, 이 책에서는 다루지 않았지만 `LinearMap.ker`로 존재합니다)으로 그대로 되풀이된다는 걸 눈치챘다면, 이 책이 4부와 5부를 나란히 배치한 이유를 알아챈 것입니다.

== 직접 해보기

* `proj2 : (Fin 2 → ℝ) →ₗ[ℝ] ℝ`를 "두 번째 좌표를 뽑는" 선형사상으로 직접 정의해보고, `proj1`과 `proj2`를 더한 새 선형사상(`proj1 + proj2`, Mathlib이 선형사상의 덧셈도 이미 정의해뒀습니다)이 "두 좌표의 합을 계산하는" 사상이라는 걸 확인해보세요.

.해답 보기
[%collapsible]
====
[source,lean]
----
def proj2 : (Fin 2 → ℝ) →ₗ[ℝ] ℝ where
  toFun v := v 1
  map_add' u v := by simp
  map_smul' c v := by simp

example : (proj1 + proj2) (fun i => if i = 0 then 3 else 5) = 8 := by
  norm_num [proj1, proj2]
----
====

== 요약

* 선형사상(`V →ₗ[ℝ] W`)은 덧셈과 스칼라 곱을 보존하는 함수이고, 새로 정의할 땐 그 보존 증거까지 함께 지어야 합니다.
* 선형사상의 합성은 다시 선형사상입니다.
* 행렬은 선형사상을 구체적인 수의 배열로 옮긴 것이고, 행렬 곱셈의 결합법칙은 함수 합성의 결합성에서 옵니다.

5부가 여기서 끝났습니다. 6부에서는 해석학 — 수열의 극한과 연속함수 — 을 맛봅니다.
