== 이 책이 하려는 것

이 사이트에는 범주론 책(`category-theory-for-programmers`)과 타입론을 다루는 책이 여럿(`type-driven-design`의 대수적 데이터 타입과 모나드, `lean4-program-semantics`의 명제-타입 대응) 있습니다. 이 책들은 모두 **순수 함수형 프로그램의 합성**을 타입으로 다스리는 법을 다뤘습니다 — 효과를 값으로 만들고(Monad), 구조를 사상으로 다루고(Functor), 상태 기계를 순수 함수로 표현하는 식입니다.

이 책은 다른 질문을 던집니다 — **자원을 두 번 쓰거나, 아예 안 쓰는 실수를 타입 시스템이 미리 잡아줄 수 있을까?** 파일 핸들을 닫은 뒤에 또 쓰거나, 뮤텍스를 두 번 푸는 것 같은 버그는 함수형이든 명령형이든 상관없이 일어납니다. Rust가 유명해진 이유 중 하나가 바로 이겁니다 — 소유권(ownership)과 빌림 검사기(borrow checker)로 "이 값은 정확히 한 곳에서만 유효하다"를 컴파일 타임에 강제해서, 가비지 컬렉터 없이도 메모리 안전성과 데이터 경쟁(data race) 없음을 보장합니다.

이 책은 Rust의 소유권 시스템을 떠받치는 이론적 뿌리인 **선형 타입(linear type)** 을 처음부터 설계·구현·증명하고, 그 선형성을 "값 하나"가 아니라 "두 프로세스 사이의 통신 프로토콜 전체"로 확장한 **세션 타입(session type)** 까지 이어갑니다. 세션 타입은 "이 소켓에서 다음에 뭘 보내고 뭘 받아야 하는가"를 타입으로 명세하고, 그 명세를 지키는 프로그램은 **교착 상태(deadlock)에 빠지지 않는다**는 것을 증명할 수 있게 해줍니다 — 이게 이 책이 말하는 "병렬 프로그램을 안전하게 만드는 이론"입니다.

이 책의 모든 정리(선형 타입의 Progress, 세션 타입의 교착 없음)는 Lean4로 실제로 증명하고 검증했습니다 — 이 사이트의 다른 Lean4 책들과 같은 원칙입니다.

== 왜 이 책을 쓰는가

이 시리즈의 다른 두 책이 이미 이 방향을 가리키고 있었습니다. `fp-backbone-of-async` 12장은 "Ownership과 Linear Types"를 미래 발전 방향으로 딱 한 문단 언급하고 파이썬의 한계상 다루지 않았다고 인정했습니다. `nand2npu-cpu` 11장과 13장은 힙 할당자를 더 현실적으로(블록을 쪼개고 병합하도록) 만들려면 "이 포인터가 유일하게 소유되다가 정확히 한 번 해제된다"는 성질을 강제하는 선형 타입이 필요하다고 명시하면서도 "이 방향을 시리즈에서 끝까지 밀어붙이지는 않았다"고 회고했습니다. 이 책은 그 두 복선을 회수합니다 — 이번엔 미루지 않고, 선형성이 실제로 무엇을 막아주는지 타입 시스템을 지어서 증명까지 갑니다.

== 누구를 위한 책인가

이 책은 **독립적으로 완결된 책**입니다 — Lean4를 한 번도 안 써봤어도 상관없지만, 귀납적 명제와 귀납법으로 증명을 쓰는 경험이 있으면 훨씬 수월합니다(`lean4-getting-started`나 `lean4-program-semantics`를 먼저 읽었다면 이상적입니다). 타입 이론이나 프로그래밍 언어 이론을 처음 접해도 괜찮습니다 — 1장부터 "왜 이게 문제인가"를 구체적인 버그로 시작합니다.

== 읽는 순서

이 책은 4부 9개 장과 맺음말로 나뉩니다.

*1부(1~2장)* 는 동기를 다집니다 — 자원을 두 번 쓰거나 안 쓰는 버그가 실제로 무엇인지, 그리고 그걸 막는 선형 람다계산법의 문법과 타이핑 규칙을 설계합니다.

*2부(3~4장)* 는 이 타입 시스템이 약속을 지킨다는 것을 증명합니다 — "잘 타입된 프로그램은 절대 막다른 골목에 빠지지 않는다"는 Progress 정리를 완전히 증명하고, "실행해도 타입이 안 변한다"는 Preservation을 구체적인 프로그램으로 검증하면서, 선형 시스템에서 이 증명이 왜 일반적인 람다계산법보다 더 까다로운지(컨텍스트를 쪼개는 대입 보조정리) 짚습니다.

*3부(5~7장)* 는 이 책의 정점입니다 — 선형성을 "값 하나"에서 "통신 프로토콜 전체"로 확장한 세션 타입을 설계하고, 타입 지정 프로세스 계산으로 두 프로세스가 실제로 통신하는 것을 모델링하고, 그렇게 만든 시스템이 **교착 상태에 빠지지 않는다**는 것을 Progress 정리로 증명합니다.

*4부(8~9장)* 는 종합과 확장입니다 — 이 책에서 지은 것과 Rust의 소유권 시스템, 실전 세션 타입 라이브러리들을 비교하고, 이 사이트의 `nand2npu-gpu`가 조작적 의미론으로 직접 증명했던 워프 동기화를 세션 타입의 눈으로 다시 읽어봅니다.

*맺음말(10장)* 은 이 책이 다루지 않은 것과 다음으로 어디를 볼지 안내합니다.

각 장은 이전 장에서 지은 타입 시스템과 증명을 당연하게 재사용합니다 — 순서대로 읽는 걸 권합니다.
