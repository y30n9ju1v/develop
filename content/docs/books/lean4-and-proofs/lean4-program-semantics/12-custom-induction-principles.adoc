11장에서 `induction`이 결국 `Nat.rec` 호출을 자동으로 조립해주는 것뿐이라는 걸 봤습니다. 이 장에서는 한 걸음 더 나아가, **`Nat.rec`가 아닌 다른 귀납 원리를 직접 만들어 쓰는 법**을 다룹니다.

== 기본 귀납법의 한계: "바로 앞 경우"만 가정할 수 있다

2장에서 쓴 귀납법은 항상 같은 모양이었습니다 — `n`에서 성립한다고 가정하고 `n+1`에서도 성립함을 보이는 것입니다. 그런데 어떤 증명은 "`n`에서 성립한다"만으로는 부족하고, **"`n`보다 작은 모든 수에서 성립한다"**는 훨씬 강한 가정이 필요합니다. 예를 들어 "숫자를 계속 반으로 나누다 보면 언젠가 0에 도달한다"는 성질을 생각해봅시다 — `n`에서 한 번 반으로 나누면 `n/2`인데, `n/2`는 `n-1`이 아니라 훨씬 작은 값입니다. 기본 귀납법은 "`n-1`에서 성립한다"만 가정하게 해주니, 이 증명에는 안 맞습니다.

== 강한 귀납법을 직접 증명하기

[source,lean]
----
theorem strongInduction {motive : Nat → Prop}
    (step : ∀ n, (∀ m, m < n → motive m) → motive n) : ∀ n, motive n := by
  have aux : ∀ n, ∀ m, m ≤ n → motive m := by
    intro n
    induction n with
    | zero =>
      intro m hm
      have hm0 : m = 0 := by omega
      subst hm0
      exact step 0 (by omega)
    | succ n ih =>
      intro m hm
      rcases Nat.lt_or_ge m (n + 1) with h | h
      · exact ih m (by omega)
      · have hmeq : m = n + 1 := by omega
        subst hmeq
        exact step (n + 1) (fun k hk => ih k (by omega))
  intro n
  exact aux n n (Nat.le_refl n)
----

`strongInduction`은 "**`n`보다 작은 모든 `m`에서 성질이 성립한다고 가정하면, `n`에서도 성립함을 보여라**"(`step`)는 조건 하나만으로 "모든 `n`에서 성립한다"를 이끌어냅니다. 흥미로운 건 이 증명 **자체는 기본 귀납법(`induction n with ...`)으로 이뤄진다**는 것입니다 — 다만 증명하는 대상이 "`n`에서 성립한다"가 아니라 **"`n` 이하의 모든 `m`에서 성립한다"**(`aux`)라는, 한 단계 더 강한 명제입니다. 이렇게 "증명하려는 것보다 더 강한 명제를 증명해서, 그걸로 원하는 걸 이끌어낸다"는 전략을 **귀납 강화(induction strengthening)**라고 부릅니다 — 2장에서 본 "보조 정리를 먼저 증명한다"는 전략의 사촌입니다.

== 강한 귀납법으로 증명하기: 반씩 줄어드는 재귀는 끝난다

[source,lean]
----
def halve (n : Nat) : Nat := n / 2

def iterate (f : Nat → Nat) : Nat → Nat → Nat
  | 0, n => n
  | k + 1, n => iterate f k (f n)

theorem halve_terminates (n : Nat) : ∃ k, iterate halve k n = 0 := by
  induction n using strongInduction with
  | step n ih =>
    rcases Nat.eq_zero_or_pos n with h0 | h0
    · exact ⟨0, h0⟩
    · have hlt : halve n < n := by unfold halve; omega
      obtain ⟨k, hk⟩ := ih (halve n) hlt
      exact ⟨k + 1, by unfold iterate; exact hk⟩

#eval iterate halve 5 20  -- 20 -> 10 -> 5 -> 2 -> 1 -> 0
----

`iterate f k n`은 "함수 `f`를 `n`에 `k`번 반복 적용한 결과"입니다. `halve_terminates`는 "0이 아닌 어떤 자연수든, `halve`를 몇 번 반복하면 결국 `0`에 도달한다"는 걸 증명합니다. `induction n using strongInduction with`이 핵심입니다 — `step n ih`에서 `ih`는 **"`n`보다 작은 모든 `m`에 대해, `halve`를 반복하면 결국 `0`에 도달한다"**는 훨씬 강한 가정입니다. `n`이 `0`보다 크면 `halve n = n / 2`는 반드시 `n`보다 작으니(`hlt`), 이 강한 가정을 `halve n`이라는 구체적인 값에 적용해서(`ih (halve n) hlt`) "`halve n`에서 시작해도 결국 `0`에 도달한다"는 걸 얻고, 거기에 한 스텝(`k + 1`)을 더 얹어 `n`에서 시작하는 경우까지 증명합니다.

만약 기본 `induction`을 썼다면, `n`에 대한 가정은 "`n-1`에서 성립한다"였을 텐데, 우리에게 필요한 건 "`halve n`(대략 `n/2`)에서 성립한다"는 가정입니다 — `n/2`가 `n-1`과 같은 경우는 `n`이 아주 작을 때뿐이라, 기본 귀납법으로는 이 증명이 애초에 안 풀립니다.

== 왜 이게 3부와 이어지는가

3부에서 반복문의 `BigStep` 의미론을 다룰 때, "반복문이 결국 끝난다"는 성질(정지성, termination)은 다루지 않았습니다 — `BigStep`은 "만약 끝난다면 어떤 상태에 도달하는가"만 정의했지, "정말 끝나는가"는 별개의 질문이기 때문입니다. `halve_terminates`가 정확히 그 "정말 끝나는가"라는 질문의 축소판입니다 — 실전 프로그램 검증에서 "이 반복문은 매번 값이 줄어드니 언젠가 끝난다"는 논증이 바로 이 장에서 쓴 강한 귀납법(또는 그 사촌인 정초 귀납법, well-founded induction)으로 이뤄집니다.

== 직접 해보기

* `strongInduction`을 이용해, "`n ≥ 1`이면 `n`을 소수들의 곱으로 표현하는 목록이 존재한다"까지는 아니어도, 훨씬 단순한 성질 — **"모든 자연수 `n`에 대해, `n`을 2로 나눈 몫을 계속 따라가면 반드시 유한 번 만에 `n` 자신보다 항상 작아지는 사슬을 만들 수 있다"**는 것과 비슷한 감각으로, `iterate halve k n ≤ n`(반복 적용한 결과는 항상 원래 값 이하)을 **기본** `induction`(강한 귀납법 없이)으로 증명해보세요 — 이번엔 강한 귀납법이 굳이 필요 없다는 것도 함께 확인하는 것입니다.

.해답 보기

====
[source,lean]
----
theorem iterate_halve_le (k n : Nat) : iterate halve k n ≤ n := by
  induction k generalizing n with
  | zero => simp [iterate]
  | succ k ih =>
    unfold iterate
    have h1 : halve n ≤ n := by unfold halve; omega
    exact Nat.le_trans (ih (halve n)) h1
----

이 성질은 "한 스텝 줄어들거나 같다"는 것만 알면 되니, 기본 `induction`(귀납 가설이 "`k`번 반복했을 때"만 있으면 됨)으로 충분합니다 — 강한 귀납법이 필요했던 `halve_terminates`와 비교해보면, **"몇 번 반복하는지"에 대한 귀납이냐 "값 자체"에 대한 귀납이냐**에 따라 필요한 도구가 달라진다는 걸 알 수 있습니다.

== 요약

* 기본 `induction`은 "바로 하나 작은 경우"만 가정하게 해줍니다 — 재귀가 한 단계씩 줄어들지 않는 증명(예: 절반으로 줄어드는 경우)에는 부족합니다.
* 강한 귀납법(`strongInduction`)은 "더 작은 모든 경우"를 가정하게 해주고, 그 증명 자체는 "`n` 이하 전부에 대해 성립한다"는 강화된 명제를 기본 귀납법으로 증명하는 방식으로 만들 수 있습니다.
* `induction ... using 이름` 문법으로, `Nat.rec`가 아닌 우리가 만든 귀납 원리를 그대로 전술처럼 쓸 수 있습니다.
* 어떤 대상에 대해 귀납하느냐(값 자체 vs 반복 횟수)에 따라 기본 귀납법으로 충분한지, 강한 귀납법이 필요한지가 갈립니다.

다음 장에서는 4부의 마지막 주제, "이 프로그램은 이 명세를 만족한다"는 걸 증명하는 호어 논리를 맛봅니다 — 8~10장에서 다진 `BigStep`과 이 책 전체의 증명 기술이 총동원됩니다.
