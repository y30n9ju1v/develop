== 1.3.1. 인자로서의 절차

정수를 더하는 절차, 그 세제곱을 더하는 절차, stem:[\pi/8]로 수렴하는 역수곱 급수를 더하는 절차 — 이 셋을 자세히 보면 똑같은 뼈대를 공유합니다. 기저 사례에서는 ``0``이고, 그렇지 않으면 "현재 인덱스에서 항을 계산하고, 나머지의 합에 더한다"는 것입니다. 다른 것은 오직 _어떤_ 항 함수를 쓰는지와 인덱스가 _어떻게_ 전진하는지뿐입니다. 수학자들은 수백 년 전에 이미 같은 패턴을 발견하고, 합산 자체를 개별 급수와 무관하게 추론할 수 있도록 이름과 표기법(stem:[\sum])을 붙였습니다.

우리도 절차적으로 똑같이 할 수 있습니다 — 공유된 뼈대에서 달라지는 부분을 형식 매개변수로 바꾸면 됩니다. ``term``과 ``next``가 다른 숫자 인자와 마찬가지로 평범한 인자가 됩니다.

[source,text]
----
                       [sum 고차 함수 파이프라인]

      시작점 a ───(term a 계산)───► [항 값] ──┐
         │                                    │ (+)
         ▼ (next a 전진)                      ▼
       next a ───(term (next a))─► [항 값] ──► 누적합 (결과)
         │                                    ▲
        ...                                   │
         │                                    │
       끝점 b ───(term b 계산)───► [항 값] ──┘
         │
         ▼ (a > b 이면 0 반환 후 재귀 종료)
----

[source,lean]
----
partial def sum (term : Float → Float) (a : Float) (next : Float → Float) (b : Float) : Float :=
  if a > b then 0
  else term a + sum term (next a) next b

def cube (x : Float) : Float := x * x * x
def inc (x : Float) : Float := x + 1
def identity (x : Float) : Float := x

def sumCubes (a b : Float) : Float := sum cube a inc b
def sumIntegers (a b : Float) : Float := sum identity a inc b

def piTerm (x : Float) : Float := 1.0 / (x * (x + 2))
def piNext (x : Float) : Float := x + 4
def piSum (a b : Float) : Float := sum piTerm a piNext b

#eval sumCubes 1 10
-- 3025.000000

#eval sumIntegers 1 10
-- 55.000000

#eval 8 * piSum 1 1000
-- 3.139593
----

Lean 고유의 주름이 하나 있습니다 — Scheme의 숫자 타워는 하나의 ``sum``을 어떤 곳에서는 정수 범위로, 다른 곳에서는 부동소수점 범위로, 누구도 타입을 선언하지 않고도 호출할 수 있게 해줍니다. Lean의 ``sum``은 하나의 구체적인 매개변수 타입에 확정해야 하므로, 여기서는 전체를 ``Float``로 통일했습니다 — 그 대가로, 개념적으로는 자연수를 "다루는" ``sumIntegers``가 ``piSum``의 연속적인 범위와 호환되기 위해서만 ``Float`` 시그니처를 갖게 됩니다. 완전히 일반적인 버전이라면 ``sum``을 숫자 타입클래스에 대해 매개변수화하겠지만, SICP 코드와의 직접적인 대응을 유지하기 위해 여기서는 그 일반화를 미뤄둡니다.

[NOTE]
.완전히 일반적인 버전으로 가는 방향
====
``α``에 대해 사칙연산과 순서 비교가 모두 필요하므로, ``sum``을 진짜로 일반화한다면 ``Add α``·``LT α`` 같은 제약을 하나씩 나열하기보다 Mathlib의 ``LinearOrderedField``처럼 필요한 연산을 한 번에 묶어주는 기존 타입클래스 하나로 매개변수화하는 편이 낫습니다. 이 글에서는 SICP 코드와의 직접적인 대응을 유지하기 위해 그 일반화를 하지 않습니다.
====

``sum``이 생기고 나면 더 많은 추상화를 위한 재료가 됩니다 — 예를 들어 수치 적분은 ``dx`` 간격으로 떨어진 표본들의 합을 스케일링한 것일 뿐입니다.

[source,lean]
----
def integral (f : Float → Float) (a b dx : Float) : Float :=
  sum f (a + dx / 2.0) (fun x => x + dx) b * dx

#eval integral cube 0 1 0.01
-- 0.249988

#eval integral cube 0 1 0.001
-- 0.250000
----

*연습문제 1.30 (Lean 버전)*: 위의 ``sum``은 선형 재귀 프로세스를 만듭니다. 상태를 ``iter``로 감싸 반복 프로세스로 다시 쓰면 다음과 같습니다 — ``a``가 매 호출마다 ``next a``로 구조적으로 전진하는 것이 아니라 임의의 ``next`` 함수를 거치므로, 여전히 ``partial``이 필요합니다.

[source,lean]
----
partial def sumIter (term : Float → Float) (a : Float) (next : Float → Float) (b : Float) : Float :=
  let rec iter (a result : Float) : Float :=
    if a > b then result else iter (next a) (result + term a)
  iter a 0
----

'''

== 1.3.2. ``lambda``로 절차 만들기 — Lean의 ``fun``과 ``let``

``piTerm``처럼 ``sum``에 딱 한 번 넘기려고 자잘한 일회용 절차를 정의하는 건 과하게 느껴집니다. Scheme의 답은 ``lambda``입니다 — 이름에 전혀 묶지 않고 절차를 만드는 특수 형식입니다. Lean에서 이에 정확히 대응하는 것이 ``fun``입니다.

[source,lean]
----
def piSum' (a b : Float) : Float :=
  sum (fun x => 1.0 / (x * (x + 2))) a (fun x => x + 4) b

def integral' (f : Float → Float) (a b dx : Float) : Float :=
  sum f (a + dx / 2.0) (fun x => x + dx) b * dx
----

``(define (plus4 x) (+ x 4))``가 ``(define plus4 (lambda (x) (+ x 4)))``의 설탕일 뿐이듯, Lean의 ``def plus4 (x : Float) : Float := x + 4``도 ``def plus4 : Float → Float := fun x => x + 4``의 설탕입니다 — 절차에 이름을 붙이는 것은 사실 익명 절차에 ``def``를 적용하는 것뿐입니다.

``fun`` 표현식은 이름을 붙이지 않고도 곧바로 적용할 수 있습니다.

[source,lean]
----
#eval (fun (x y z : Float) => x + y + z * z) 1 2 3
-- 12.000000
----

Scheme에서 ``lambda``는 두 번째 역할도 합니다 — ``let``을 통해 지역 변수를 도입하는 것입니다. SICP의 예제는 stem:[f(x,y) = xa^2 + yb + ab]를 계산하는데, 여기서 stem:[a = 1+xy]와 stem:[b = 1-y]는 표현식을 반복하지 않기 위해 이름 붙일 만한 중간값입니다.

[source,lean]
----
def f (x y : Float) : Float :=
  let a := 1 + x * y
  let b := 1 - y
  x * a * a + y * b + a * b

#eval f 2 3
----

SICP는 ``let``이 전혀 새로운 메커니즘이 아니라, ``lambda``를 즉시 적용하는 것에 대한 구문적 설탕일 뿐이라고 꼼꼼히 설명합니다. Lean의 ``let``도 겉보기엔 비슷해 보이지만, 순수하게 함수 적용에 대한 매크로는 아닙니다 — ``let``은 Lean 자체 핵심 언어의 원시 항 생성자입니다(일반 적용을 처리하는 베타 축약과는 별개로, 자기만의 축약 규칙인 제타 축약을 가지고 있습니다). 겉으로 관찰되는 동작 — 이름이 뒤따르는 본문에 국한된다는 것 — 은 결국 어느 쪽이든 동일하지만, Lean은 SICP의 Scheme처럼 ``let``을 ``fun`` 적용으로 완전히 없애버리는 대신 커널의 일급 시민으로 만들었다는 점은 눈여겨볼 만합니다.

SICP가 ``let``에 대해 짚는 스코프 관련 미묘함은 그대로 옮겨집니다. ``let``으로 묶인 이름은 오직 ``let``의 본문 안에서만 같은 철자의 바깥 이름을 가립니다. 그리고 각 바인딩의 우변 표현식은 ``let`` 자신의 이름들이 생기기 _전에_, 바깥 스코프에서 평가됩니다.

[source,lean]
----
def xOuter : Float := 5

#eval (let x := (3 : Float); x + x * 10) + xOuter
-- 38.000000

def yOuter : Float := 2

#eval let x := (3 : Float)
      let y := yOuter + 2
      x * y
-- 12.000000
----

*연습문제 1.34 (Lean 버전)*: ``def g (f : Float → Float) : Float := f 2``를 정의했다고 합시다. Scheme에서는 ``(g g)``를 평가하면 인터프리터가 실행 중에야 "2를 절차로 적용하려 했다"는 오류를 냅니다. Lean에서는 이 문제가 아예 컴파일조차 되지 않습니다 — ``g``의 타입은 ``(Float → Float) → Float``인데, ``g g``는 ``g``의 인자 자리에 ``Float → Float`` 타입이 아니라 ``g`` 자신(타입이 ``(Float → Float) → Float``)을 넣으려는 것이므로 타입 검사기가 즉시 타입 불일치로 거부합니다. 같은 실수가 Scheme에서는 런타임 오류로, Lean에서는 컴파일 시점 오류로 나타난다는 점이 이 시리즈 전체를 관통하는 정적/동적 타입의 핵심 차이입니다.

'''

== 1.3.3. 일반적인 방법으로서의 절차

고차 절차는 특정 계산뿐 아니라 _일반적인 방법(general method)_ — 어떤 구체적인 함수에 적용되든 상관없는 기법 — 을 표현하게 해줍니다. SICP는 이를 두 가지 고전적인 예로 보여줍니다 — 근을 찾는 이분법과 고정점 탐색입니다.

=== 이분법

연속 함수 stem:[f]에 대해 stem:[f(a) < 0 < f(b)]라면, stem:[a]와 stem:[b] 사이 어딘가에 근이 있어야 합니다. 중점에서 stem:[f]의 부호를 확인하면 어느 절반으로 재귀할지 알 수 있고, 각 단계마다 불확실한 구간이 절반으로 줄어듭니다.

[source,lean]
----
def average (x y : Float) : Float := (x + y) / 2

def closeEnough (x y : Float) : Bool := Float.abs (x - y) < 0.001

partial def search (f : Float → Float) (negPoint posPoint : Float) : Float :=
  let midpoint := average negPoint posPoint
  if closeEnough negPoint posPoint then midpoint
  else
    let testValue := f midpoint
    if testValue > 0 then search f negPoint midpoint
    else if testValue < 0 then search f midpoint posPoint
    else midpoint
----

Scheme의 ``half-interval-method``는 stem:[f]가 실제로 부호를 바꾸지 않는 두 점이 주어졌을 때 ``error``를 호출해 전체 계산을 메시지와 함께 중단시켜 방어합니다. Lean은 "답이 나오지 않을 수도 있다"는 것을 주변 런타임 중단이 아니라 _타입_에 드러내는 쪽을 선호하는 경향이 있습니다 — 이전 글에서 페르마 테스트에 ``IO``를 썼을 때와 같은 본능입니다. 여기서는 ``Option Float``가 자연스럽게 들어맞습니다 — ``none``은 "이 두 점이 근을 감싸지 않는다"는 뜻이고, 타입 시스템이 호출하는 쪽에서 이 경우를 잊지 못하고 반드시 처리하도록 강제합니다.

[source,lean]
----
def halfIntervalMethod (f : Float → Float) (a b : Float) : Option Float :=
  let aValue := f a
  let bValue := f b
  if aValue < 0 && bValue > 0 then some (search f a b)
  else if bValue < 0 && aValue > 0 then some (search f b a)
  else none

#eval halfIntervalMethod Float.sin 2.0 4.0
-- some 3.141113

#eval halfIntervalMethod (fun x => x ^ 3 - 2 * x - 3) 1.0 2.0
-- some 1.893066
----

=== 고정점 탐색

stem:[f(x) = x]를 만족하면 stem:[x]는 stem:[f]의 _고정점(fixed point)_입니다. 많은 함수에 대해, 시작 추측값에 stem:[f]를 반복 적용하면 그런 점으로 수렴합니다. 이는 고정점을 찾을 함수와 시작 추측값으로 매개변수화된 두 번째 범용 탐색 절차를 줍니다.

[source,text]
----
  [고정점 수렴 궤적: x_{n+1} = f(x_n)]

   y = f(x)
       ▲             / (y = x 대각선)
       │            /
       │           /     ┌─── (x₂, f(x₂))
       │          /  ┌───┘
       │         /┌──┘       <-- 수렴점 (고정점 x*)
       │        ┌─┘
       │       ┌┘
       │      ┌┘
       │     (x₀, f(x₀))
       └────────────────────────► x
----

[source,lean]
----
def tolerance : Float := 0.00001

partial def fixedPoint (f : Float → Float) (firstGuess : Float) : Float :=
  let closeEnoughFP (v1 v2 : Float) : Bool := Float.abs (v1 - v2) < tolerance
  let rec try_ (guess : Float) : Float :=
    let next := f guess
    if closeEnoughFP guess next then next else try_ next
  try_ firstGuess

#eval fixedPoint Float.cos 1.0
-- 0.739082

#eval fixedPoint (fun y => Float.sin y + Float.cos y) 1.0
-- 1.258732
----

제곱근은 stem:[y \mapsto x/y]의 고정점임이 드러납니다 — 하지만 이 고정점을 곧바로 찾으려 하면 각 추측값이 그저 이전 값으로 되돌아가면서 영원히 진동하며 수렴하지 않습니다. stem:[x/y]로 곧장 뛰는 대신 추측값과 stem:[x/y]의 평균을 내면 진동이 감쇠되는데, 이 _평균 감쇠(average damping)_ 기법은 이 시리즈 첫 글의 뉴턴법 제곱근과 정확히 같은 근사 수열을 재현합니다.

[source,lean]
----
def sqrtFP (x : Float) : Float :=
  fixedPoint (fun y => average y (x / y)) 1.0

#eval sqrtFP 2
-- 1.414214
----

'''

== 1.3.4. 값으로 반환되는 절차

절차를 인자로 넘기는 것만으로도 이미 강력했지만, 절차가 _다른 절차를 반환하게_ 하면 한 층이 더 열립니다. 평균 감쇠 자체가 재사용 가능한 변환입니다 — 어떤 stem:[f]가 주어지든, stem:[x]에서의 값이 stem:[x]와 stem:[f(x)]의 평균인 새 함수를 만들어냅니다.

[source,lean]
----
def averageDamp (f : Float → Float) : Float → Float :=
  fun x => average x (f x)

#eval (averageDamp (fun x => x * x)) 10
-- 55.000000
----

``averageDamp``의 타입 — ``(Float → Float) → (Float → Float)`` — 은 SICP의 산문이 말하는 것을 그대로 소리 내어 말해줍니다. 함수를 먹고 함수를 돌려주는 절차라는 것입니다. 이걸 쓰면, 앞 절의 제곱근 고정점 탐색을 세 가지 아이디어 — 고정점 탐색, 평균 감쇠, 함수 stem:[y \mapsto x/y] — 가 뒤엉키지 않고 각각 이름 붙은 채로 다시 표현할 수 있습니다.

[source,lean]
----
def sqrtFP' (x : Float) : Float :=
  fixedPoint (averageDamp (fun y => x / y)) 1.0

def cubeRoot (x : Float) : Float :=
  fixedPoint (averageDamp (fun y => x / (y * y))) 1.0
----

=== 뉴턴법

첫 글에서 비공식적으로 소개했던 뉴턴법은 사실 특정 변환에 적용된 고정점 탐색입니다 — stem:[g]의 근은 stem:[x \mapsto x - g(x)/Dg(x)]의 고정점이고, 여기서 stem:[Dg]는 stem:[g]의 도함수입니다. "도함수"는 평균 감쇠와 마찬가지로 함수를 함수로 바꾸는 변환 자체이며, 극한 정의로부터 직접 근사할 수 있습니다.

[source,lean]
----
def dx : Float := 0.00001

def deriv (g : Float → Float) : Float → Float :=
  fun x => (g (x + dx) - g x) / dx

#eval (deriv cube) 5
-- 75.000150

def newtonTransform (g : Float → Float) : Float → Float :=
  fun x => x - g x / (deriv g x)

def newtonsMethod (g : Float → Float) (guess : Float) : Float :=
  fixedPoint (newtonTransform g) guess

def sqrtNewton (x : Float) : Float :=
  newtonsMethod (fun y => y * y - x) 1.0

#eval sqrtNewton 2
-- 1.414214
----

=== 추상화와 일급 절차

두 제곱근 유도 모두 훨씬 더 일반적인 모양을 공유합니다 — 함수 ``g``에서 시작해, 어떤 ``transform``을 적용하고, 그 결과의 고정점을 찾습니다.

[source,lean]
----
def fixedPointOfTransform
    (g : Float → Float) (transform : (Float → Float) → (Float → Float)) (guess : Float) : Float :=
  fixedPoint (transform g) guess

def sqrtA (x : Float) : Float :=
  fixedPointOfTransform (fun y => x / y) averageDamp 1.0

def sqrtB (x : Float) : Float :=
  fixedPointOfTransform (fun y => y * y - x) newtonTransform 1.0
----

``fixedPointOfTransform``의 두 번째 매개변수 타입은 ``(Float → Float) → (Float → Float)``입니다 — 함수를 받아 함수를 돌려주는 함수이고, 그 자체가 다른 함수에 평범한 인자로 전달됩니다. 이런 타입을 기꺼이 쓸 수 있다는 것이야말로 SICP가 말하는 _일급(first-class)_ 지위의 의미입니다 — 절차는 이름 붙일 수 있고, 인자로 넘길 수 있고, 결과로 반환할 수 있고, 데이터 구조에 담을 수 있으며, 그중 어느 것도 이등 시민이 아닙니다. Lean의 타입 시스템은 이를 허용하는 데서 그치지 않고, 중첩의 매 층마다 정확히 어떤 종류의 함수가 어디로 흐르는지를 명시하도록 요구합니다 — 고차 절차를 이렇게까지 명시적으로 만드는 데 따르는 대가(이자 안전장치)입니다.

*연습문제 1.42 (Lean 버전)*: 두 함수 stem:[f]와 stem:[g]의 합성 stem:[f \circ g]는 stem:[x \mapsto f(g(x))]입니다.

[source,lean]
----
def compose (f g : Float → Float) : Float → Float :=
  fun x => f (g x)

#eval (compose (fun x => x * x) (fun x => x + 1)) 6
-- 49.000000
----

*연습문제 1.43 (Lean 버전)*: 함수 stem:[f]를 stem:[n]번 반복 적용한 함수를 만듭니다. ``compose``를 재사용해 정의할 수 있습니다.

[source,lean]
----
def repeated (f : Float → Float) : Nat → (Float → Float)
  | 0 => id
  | n + 1 => compose f (repeated f n)

#eval (repeated (fun x => x * x) 2) 5
-- 625.000000
----

``repeated``가 ``Nat``의 successor 패턴으로 구조적 재귀를 타므로, 여기서는 ``partial``이 필요 없습니다 — 인자로 받은 함수 ``f`` 자체가 종료하는지와 무관하게, ``repeated``가 몇 번 합성할지를 세는 재귀는 항상 유한합니다.
