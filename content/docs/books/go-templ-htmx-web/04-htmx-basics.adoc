지금까지는 브라우저가 페이지를 요청할 때마다 전체 HTML을 새로 받았습니다. htmx는 HTML 속성만으로 "이 버튼을 클릭하면 서버에 요청을 보내고, 응답으로 받은 HTML을 페이지의 특정 부분에 끼워 넣어라"는 동작을 만듭니다. 이 장에서는 증가 버튼 하나로 이 흐름 전체를 실습합니다.

== htmx 불러오기

htmx는 별도의 빌드 도구 없이 스크립트 태그 하나로 불러올 수 있습니다.

[source,html]
----
<script src="https://unpkg.com/htmx.org@2.0.3"></script>
----

이 스크립트가 로드되면, `hx-`로 시작하는 HTML 속성들을 htmx가 감시하기 시작합니다.

== 카운터 컴포넌트: hx-post, hx-target, hx-swap

3장의 templ 컴포넌트에 htmx 속성을 붙여, 클릭할 때마다 서버에서 증가된 숫자를 받아오는 버튼을 만듭니다.

[source,templ]
----
package main

import "fmt"

templ Page() {
	<html>
	<head>
		<script src="https://unpkg.com/htmx.org@2.0.3"></script>
	</head>
	<body>
		@Counter(0)
	</body>
	</html>
}

templ Counter(count int) {
	<div id="counter">
		<span>{ fmt.Sprint(count) }</span>
		<button
			hx-post={ fmt.Sprintf("/increment?count=%d", count) }
			hx-target="#counter"
			hx-swap="outerHTML"
		>+1</button>
	</div>
}
----

세 속성의 역할입니다.

* `hx-post="/increment?count=0"`: 버튼을 클릭하면 이 경로로 `POST` 요청을 보냅니다.
* `hx-target="#counter"`: 응답으로 받은 HTML을 어디에 반영할지 지정합니다(`id="counter"`인 요소).
* `hx-swap="outerHTML"`: 그 대상 요소 자체를 응답 HTML로 통째로 바꿔치기합니다(`innerHTML`이면 내부 내용만 바뀝니다 — 5장에서 차이를 다룹니다).

== 서버 핸들러: 다음 숫자를 담은 조각을 돌려준다

[source,go]
----
package main

import (
	"context"
	"net/http"
	"strconv"
)

func pageHandler(w http.ResponseWriter, r *http.Request) {
	Page().Render(context.Background(), w)
}

func incrementHandler(w http.ResponseWriter, r *http.Request) {
	count, _ := strconv.Atoi(r.URL.Query().Get("count"))
	count++
	Counter(count).Render(context.Background(), w)
}

func main() {
	mux := http.NewServeMux()
	mux.HandleFunc("GET /", pageHandler)
	mux.HandleFunc("POST /increment", incrementHandler)
	http.ListenAndServe(":8080", mux)
}
----

`incrementHandler`는 전체 페이지가 아니라 `Counter` 컴포넌트 하나만 렌더링해서 돌려줍니다 — 이 "조각만 응답한다"는 게 하이퍼미디어 방식의 핵심입니다(1장에서 개념으로 소개했던 것을 이제 실제로 구현했습니다).

== 브라우저 없이 확인하기: curl로 htmx 요청 흉내 내기

htmx가 보내는 요청은 사실 평범한 `fetch`/XHR 요청에 `HX-Request: true` 같은 커스텀 헤더가 추가된 것뿐입니다. 브라우저를 열지 않고도 `curl`로 같은 흐름을 재현할 수 있습니다.

[source,bash]
----
echo "-- 최초 페이지 --"
curl -s "http://localhost:8080/"

echo "-- 버튼 클릭 (htmx가 보낼 요청을 흉내) --"
curl -s -X POST "http://localhost:8080/increment?count=0" -H "HX-Request: true"

echo "-- 다시 클릭 --"
curl -s -X POST "http://localhost:8080/increment?count=1" -H "HX-Request: true"
----

[source]
----
-- 최초 페이지 --
<html><head><script src="https://unpkg.com/htmx.org@2.0.3"></script></head><body><div id="counter"><span>0</span> <button hx-post="/increment?count=0" hx-target="#counter" hx-swap="outerHTML">+1</button></div></body></html>
-- 버튼 클릭 (htmx가 보낼 요청을 흉내) --
<div id="counter"><span>1</span> <button hx-post="/increment?count=1" hx-target="#counter" hx-swap="outerHTML">+1</button></div>
-- 다시 클릭 --
<div id="counter"><span>2</span> <button hx-post="/increment?count=2" hx-target="#counter" hx-swap="outerHTML">+1</button></div>
----

최초 페이지는 전체 `<html>` 문서를, 이후 요청들은 `<div id="counter">...</div>` **조각만** 돌려받습니다. 실제 브라우저에서는 htmx가 이 조각을 받아서 `id="counter"` 요소를 통째로 교체하고, 그 안의 새 버튼에는 다음 숫자(`count=2`)가 이미 박혀 있으니 클릭할 때마다 이 흐름이 그대로 반복됩니다 — 클라이언트 자바스크립트 코드를 단 한 줄도 쓰지 않았다는 것에 주목하세요.

== 서버가 상태를 어디에 두고 있는가

이 예제에서 흥미로운 점은, 서버가 "현재 카운트가 몇인지" 어디에도 저장하지 않는다는 것입니다 — 매 요청마다 `count` 값을 쿼리 파라미터로 받아서 `+1`한 결과만 응답합니다. **다음 상태는 지금 응답한 HTML 안(다음 버튼의 `hx-post` URL)에 이미 인코딩되어 있습니다.** 이게 하이퍼미디어 방식의 또 다른 특징입니다 — 서버가 세션이나 데이터베이스에 매번 접근하지 않고도, 응답 자체가 "다음에 무엇을 요청해야 하는지"를 담고 있습니다. 물론 실전에서는 여러 사용자가 공유하는 진짜 데이터(예: 좋아요 수)라면 서버 측에 저장해야 하는데, 이는 8장(데이터베이스 연동)에서 다룹니다.

== 직접 해보기

* 버튼을 두 개로 늘려 `+1`과 `-1`을 각각 만들고, `-1` 버튼을 눌렀을 때 카운트가 `0` 밑으로 내려가지 않도록(`count`가 `0`이면 `-1` 요청이 와도 그대로 `0`을 유지하도록) 서버 핸들러를 고쳐보세요.

.해답 보기
[%collapsible]
====
[source,templ]
----
templ Counter(count int) {
	<div id="counter">
		<span>{ fmt.Sprint(count) }</span>
		<button hx-post={ fmt.Sprintf("/increment?count=%d", count) } hx-target="#counter" hx-swap="outerHTML">+1</button>
		<button hx-post={ fmt.Sprintf("/decrement?count=%d", count) } hx-target="#counter" hx-swap="outerHTML">-1</button>
	</div>
}
----

[source,go]
----
func decrementHandler(w http.ResponseWriter, r *http.Request) {
	count, _ := strconv.Atoi(r.URL.Query().Get("count"))
	if count > 0 {
		count--
	}
	Counter(count).Render(context.Background(), w)
}
----

`count > 0`일 때만 감소시키는 조건 하나로, 클라이언트가 아무리 빠르게 `-1`을 눌러도 서버가 항상 `0` 이상만 응답한다는 걸 보장합니다 — 이 검증이 클라이언트가 아니라 서버에 있다는 게 중요합니다(클라이언트 자바스크립트로 버튼을 비활성화하는 것과 별개로, 서버가 최종 방어선이어야 합니다).

== 요약

* `hx-post`(요청을 보낼 경로), `hx-target`(응답을 반영할 위치), `hx-swap`(어떻게 교체할지)이라는 세 속성만으로 클릭 → 서버 요청 → 부분 갱신이라는 흐름을 자바스크립트 코드 없이 만들었습니다.
* htmx가 보내는 요청은 `HX-Request` 같은 헤더가 붙은 평범한 HTTP 요청이므로, 브라우저 없이 `curl`로도 서버의 동작을 그대로 검증할 수 있습니다.
* 서버는 전체 페이지가 아니라 갱신이 필요한 HTML 조각만 응답하며, "다음에 무엇을 요청해야 하는가"는 그 응답 HTML 안에 이미 인코딩되어 있습니다.
* 다음 장에서는 `hx-target`과 `hx-swap`이 지원하는 더 다양한 옵션(다른 요소를 갱신하기, 요소를 추가/삭제하기, OOB 스왑으로 한 응답에서 여러 곳을 동시에 갱신하기)을 다룹니다.
