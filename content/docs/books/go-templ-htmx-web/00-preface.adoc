== 이 책이 하려는 것

오늘날 웹 서비스를 만든다고 하면 흔히 React/Vue 같은 프런트엔드 프레임워크와 REST/GraphQL API 서버를 나누고, 그 사이를 JSON으로 잇는 구조를 떠올립니다. 이 구조는 강력하지만 비용이 있습니다 — 프런트엔드 빌드 도구 체인, 클라이언트 상태 관리, API 스키마를 두 번(서버·클라이언트) 유지하는 부담이 따라옵니다. 이 책은 그 대안 — **서버가 HTML을 직접 내려주고, 자바스크립트는 최소한만 쓰는 방식** — 을 Go, templ, htmx라는 세 도구로 실습합니다.

* **Go**: 표준 라이브러리 `net/http`만으로도 충분히 튼튼한 웹 서버를 만들 수 있는 언어입니다. 별도의 프레임워크 없이 라우팅, 미들웨어, 핸들러를 직접 다룹니다.
* **templ**: Go 코드로 HTML 템플릿을 작성하면 컴파일 타임에 타입 검사를 받는 라이브러리입니다. 템플릿에 오타를 내거나 잘못된 타입을 넘기면 런타임이 아니라 `go build` 시점에 걸러집니다.
* **htmx**: HTML 속성(`hx-get`, `hx-post`, `hx-target` 등)만으로 서버에 요청을 보내고, 응답으로 받은 HTML 조각을 페이지 일부에 갈아 끼우는 라이브러리입니다. 클라이언트 상태를 따로 관리할 필요 없이, "지금 화면에 보이는 HTML"이 곧 상태입니다.

이 세 도구를 합치면, 자바스크립트 프레임워크 없이도 검색창에 입력할 때마다 목록이 갱신되고, 폼을 제출하면 페이지 전체가 아니라 필요한 부분만 바뀌는 상호작용하는 웹 페이지를 만들 수 있습니다 — 이 접근을 흔히 **하이퍼미디어 지향 애플리케이션(Hypermedia-Driven Application, HDA)**이라고 부릅니다.

== 이 책의 방식: 실제로 서버를 띄우고, 실제로 요청을 보내고

이 시리즈의 다른 책들과 마찬가지로, 이 책의 모든 코드는 실제로 `go build`/`go run`으로 실행하고 검증합니다. templ 컴포넌트는 실제로 `templ generate`로 컴파일해 타입 오류가 어떻게 잡히는지 직접 확인하고, htmx 상호작용은 실제 HTTP 요청과 응답 HTML을 `curl`로 찍어보며 "무슨 일이 일어났는지" 눈으로 봅니다. 1부(기초)에서 각 도구를 따로 다진 뒤, 2부(htmx 상호작용)와 3부(실전 패턴)에서 점점 더 복잡한 화면을 조립하고, 4부(완성과 배포)에서 데이터베이스·인증·테스트까지 갖춘 작은 TODO 앱을 처음부터 끝까지 완성합니다.

== 누구를 위한 책인가

Go 문법(변수, 함수, 구조체, 인터페이스)에는 익숙하지만 웹 서버를 처음 만들어보는 독자를 대상으로 합니다. 프런트엔드 프레임워크 경험이 있다면 htmx의 "서버가 상태를 갖고, HTML이 곧 뷰"라는 접근이 처음엔 낯설 수 있는데, 이 책 전체가 그 낯섦을 하나씩 코드로 풀어가는 과정입니다.
