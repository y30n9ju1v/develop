4장에서는 `hx-swap="outerHTML"`(대상 요소 자체를 통째로 바꾸기)만 썼습니다. 이 장에서는 리스트에 항목을 **추가**하는 것처럼 "통째로 바꾸기"가 아닌 다른 방식이 필요한 경우와, 하나의 응답으로 화면의 서로 다른 두 위치를 동시에 갱신하는 **OOB(Out of Band) 스왑**을 다룹니다.

== hx-swap의 여러 값

`hx-swap`은 응답 HTML을 타겟 요소에 대해 정확히 어떻게 배치할지 결정합니다.

[cols="1,3"]
|===
| 값 | 의미

| `innerHTML` (기본값)
| 타겟 요소의 내부 내용을 응답으로 교체

| `outerHTML`
| 타겟 요소 자체를 응답으로 교체(4장에서 사용)

| `beforeend`
| 타겟 요소의 자식 목록 맨 끝에 응답을 추가(리스트에 항목 추가할 때 씀)

| `afterbegin`
| 타겟 요소의 자식 목록 맨 앞에 응답을 추가

| `delete`
| 응답 내용과 무관하게 타겟 요소를 제거
|===

== 목록에 항목 추가하기: beforeend

할 일을 입력하면 목록 끝에 새 항목이 추가되는 폼을 만듭니다.

[source,templ]
----
package main

import "fmt"

templ Page() {
	<html>
	<head><script src="https://unpkg.com/htmx.org@2.0.3"></script></head>
	<body>
		<p>총 <span id="item-count">0</span>개</p>
		<ul id="item-list"></ul>
		<form hx-post="/items" hx-target="#item-list" hx-swap="beforeend">
			<input type="text" name="text"/>
			<button type="submit">추가</button>
		</form>
	</body>
	</html>
}
----

`hx-target="#item-list"`(추가될 자리)와 `hx-swap="beforeend"`(그 목록의 끝에 덧붙이기)의 조합입니다. `hx-post`가 붙은 요소가 `<form>`이면, htmx는 그 폼의 입력값들을 자동으로 요청 본문에 담아 보냅니다(6장에서 폼을 더 깊게 다룹니다).

== 한 응답으로 두 곳을 동시에 갱신하기: hx-swap-oob

새 항목을 추가할 때, 목록 끝에 항목을 붙이는 것과 **동시에** 상단의 "총 N개"라는 카운터도 갱신하고 싶다고 합시다. `hx-target`은 한 곳만 가리킬 수 있는데, 이럴 때 응답 HTML 안에 `hx-swap-oob="true"`가 붙은 요소를 추가로 넣으면, htmx가 `hx-target`과 무관하게 그 요소를 **자신과 같은 `id`를 가진 화면의 다른 위치**에 별도로 반영합니다.

[source,templ]
----
templ ItemFragment(text string, count int) {
	<li>{ text }</li>
	<span id="item-count" hx-swap-oob="true">{ fmt.Sprint(count) }</span>
}
----

[source,go]
----
package main

import (
	"context"
	"net/http"
)

var items []string

func addItemHandler(w http.ResponseWriter, r *http.Request) {
	r.ParseForm()
	text := r.FormValue("text")
	items = append(items, text)
	ItemFragment(text, len(items)).Render(context.Background(), w)
}
----

=== 실제 요청으로 두 위치가 함께 갱신되는지 확인

[source,bash]
----
curl -s -X POST "http://localhost:8080/items" -H "HX-Request: true" \
  --data-urlencode "text=우유 사기"

curl -s -X POST "http://localhost:8080/items" -H "HX-Request: true" \
  --data-urlencode "text=책 읽기"
----

[source]
----
<li>우유 사기</li><span id="item-count" hx-swap-oob="true">1</span>
<li>책 읽기</li><span id="item-count" hx-swap-oob="true">2</span>
----

응답 하나에 `<li>`(목록에 추가될 항목)와 `<span id="item-count" hx-swap-oob="true">`(카운터, OOB로 표시됨)가 함께 들어 있습니다. 브라우저에서 htmx가 이 응답을 받으면 — `<li>` 부분은 `hx-target="#item-list"`와 `hx-swap="beforeend"` 규칙대로 목록 끝에 추가하고, `<span id="item-count" hx-swap-oob="true">` 부분은 `hx-target`을 무시하고 화면에서 같은 `id="item-count"`를 가진 요소를 찾아 그 자리에서 바로 교체합니다. **한 번의 서버 요청·응답으로 화면의 서로 다른 두 위치를 동시에 갱신**한 것입니다.

== 왜 OOB 스왑이 필요한가

OOB 스왑이 없다면, "항목 추가"와 "카운터 갱신"을 별도의 두 요청으로 나누거나(비효율적이고, 두 요청 사이에 다른 사용자의 변경이 끼어들 여지가 생김), 아니면 페이지의 훨씬 큰 영역(목록과 카운터를 모두 포함하는 공통 부모)을 통째로 `outerHTML`로 갈아 끼워야 합니다(불필요하게 많은 HTML을 다시 그리게 됨). OOB 스왑은 "이 요청의 주된 목적(목록에 항목 추가)"과 "그 김에 갱신해야 하는 부수적인 위치(카운터)"를 하나의 응답 안에서 정확히 필요한 만큼만 갱신하게 해줍니다. 9장(목록·검색·페이지네이션)과 13장(종합 실전)에서 이 패턴을 다시 씁니다.

== 직접 해보기

* 항목을 삭제하는 버튼을 각 `<li>`에 추가하고(`hx-swap="delete"`), 삭제할 때도 OOB 스왑으로 카운터가 함께 줄어들도록 만들어보세요.

.해답 보기
[%collapsible]
====
[source,templ]
----
templ ItemFragment(id int, text string, count int) {
	<li id={ fmt.Sprintf("item-%d", id) }>
		{ text }
		<button hx-delete={ fmt.Sprintf("/items/%d", id) } hx-target={ fmt.Sprintf("#item-%d", id) } hx-swap="delete">삭제</button>
	</li>
	<span id="item-count" hx-swap-oob="true">{ fmt.Sprint(count) }</span>
}
----

[source,go]
----
func deleteItemHandler(w http.ResponseWriter, r *http.Request) {
	// items 슬라이스에서 해당 id를 제거하는 로직(생략)
	remainingCount := len(items)
	fmt.Fprintf(w, `<span id="item-count" hx-swap-oob="true">%d</span>`, remainingCount)
}
----

`hx-swap="delete"`가 붙은 버튼을 누르면, 응답 내용과 무관하게 `hx-target`으로 지정한 요소(`<li>` 자신)가 화면에서 제거됩니다. 응답 본문에는 삭제될 항목 자체에 대한 내용은 필요 없고, OOB 스왑으로 카운터만 갱신하면 됩니다 — 이렇게 `hx-swap` 값이 `delete`일 때는 응답 본문이 사실상 "부수 효과(카운터 갱신)"만 담아도 된다는 걸 보여주는 예시입니다.
====

== 요약

* `hx-swap`은 `innerHTML`, `outerHTML` 외에도 `beforeend`, `afterbegin`, `delete` 같은 값으로 응답 HTML을 타겟 요소에 정확히 어떻게 배치할지 세밀하게 제어합니다.
* `hx-swap-oob="true"`가 붙은 요소는 `hx-target`과 무관하게, 같은 `id`를 가진 화면의 다른 위치에 별도로 반영됩니다 — 하나의 응답으로 화면의 여러 곳을 동시에 갱신할 수 있습니다.
* OOB 스왑은 "이 요청의 주된 결과"와 "그에 따라 함께 갱신해야 하는 부수적인 위치"를 하나의 요청·응답 안에서 정확히 필요한 만큼만 갱신하게 해줍니다.
