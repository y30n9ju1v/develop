== 명제도 타입이다

[source,lean]
----
def IsPositive (n : Nat) : Prop := n > 0

theorem three_is_positive : IsPositive 3 := by unfold IsPositive; omega
----

`IsPositive : Nat → Prop`은 "자연수 하나를 받아 명제 하나를 만드는 함수"입니다. `Prop`은 Lean4에서 "참일 수도 거짓일 수도 있는 문장들의 타입"입니다 — `Nat`이 "자연수들의 타입"이듯, `Prop`은 "명제들의 타입"입니다. `three_is_positive`라는 이름의 값이 `IsPositive 3`이라는 **타입**을 갖는다는 게 이 장의 핵심입니다 — **증명은 그 명제라는 타입에 속하는 하나의 값**입니다. `omega`(자연수·정수의 선형 산술을 자동으로 증명해주는 전술)가 그 값을 실제로 만들어낸 것이고, `theorem` 키워드는 사실 `def`와 다르지 않습니다(둘 다 "이름에 값을 묶는다"는 같은 일을 합니다) — 다만 결과 타입이 `Prop`일 때 관례적으로 `theorem`이라고 씁니다.

== 함의는 함수 타입이다

[source,lean]
----
theorem positive_add (a b : Nat) (ha : IsPositive a) : IsPositive (a + b) := by
  unfold IsPositive at *
  omega
----

`positive_add`의 타입을 풀어보면 "`a`, `b`, 그리고 `IsPositive a`의 증명을 받아서 `IsPositive (a + b)`의 증명을 내놓는 함수"입니다. **"P이면 Q이다"라는 함의(`P → Q`)가 바로 "P의 증명을 받아 Q의 증명을 내놓는 함수"라는 것**이 Curry-Howard 대응의 핵심 대응 관계입니다 — 논리의 "함의"와 프로그래밍의 "함수"가 같은 것의 두 이름입니다. `ha : IsPositive a`라는 매개변수 이름 자체가 "증명도 그냥 함수의 인자"라는 걸 보여줍니다.

== 논리곱은 곱 타입, 논리합은 합 타입

[source,lean]
----
example (a b : Nat) (ha : IsPositive a) (hb : IsPositive b) : IsPositive a ∧ IsPositive b :=
  ⟨ha, hb⟩

example (a : Nat) (h : IsPositive a) : IsPositive a ∨ a = 100 :=
  Or.inl h
----

`P ∧ Q`(논리곱, "P이고 Q")의 증명은 **P의 증명과 Q의 증명을 한 쌍으로 묶은 것**입니다 — `⟨ha, hb⟩`라는 익명 생성자가 정확히 구조체(product)를 만드는 문법과 같습니다. `P ∨ Q`(논리합, "P이거나 Q")의 증명은 **P의 증명이거나 Q의 증명, 둘 중 하나**입니다 — `Or.inl h`는 "왼쪽(P)이 증명됐다"는 뜻이고, 이건 sum 타입의 생성자와 똑같은 모양입니다. 논리곱·논리합이라는 논리 연산자가 곱 타입·합 타입이라는 데이터 연산자와 **정확히 같은 구조**를 가진다는 게 이 대응의 또 다른 축입니다.

== 증명 항을 전술 없이 손으로 짓기

지금까지는 `by ...`(전술 모드)로 증명을 "만들어달라고 요청"했습니다. 그런데 방금 본 대응이 말 그대로라면, 증명을 **함수를 짜듯이 직접 손으로 지을 수도** 있어야 합니다.

[source,lean]
----
theorem andComm {P Q : Prop} (h : P ∧ Q) : Q ∧ P :=
  ⟨h.2, h.1⟩

theorem modusPonens {P Q : Prop} (hpq : P → Q) (hp : P) : Q := hpq hp
----

`andComm`은 "`P ∧ Q`의 증명 `h`가 있으면 `Q ∧ P`의 증명을 만들어라"는 정리입니다 — `h.1`(첫 번째 성분, `P`의 증명)과 `h.2`(두 번째 성분, `Q`의 증명)를 순서만 바꿔 다시 묶었습니다. `modusPonens`는 더 극적입니다 — `hpq : P → Q`가 함수이므로, `hp : P`라는 값에 **그냥 함수를 적용하기만 하면**(`hpq hp`) `Q`의 증명이 나옵니다. 논리학에서 "전건 긍정"(modus ponens)이라고 부르는 추론 규칙이, 여기서는 그냥 **함수 호출**입니다.

== 전칭과 존재 양화사

[source,lean]
----
example : ∀ n : Nat, n + 0 = n := by intro n; omega
example : ∃ n : Nat, n * n = 9 := ⟨3, by decide⟩
----

`∀ n : Nat, P n`(모든 자연수 `n`에 대해 `P n`)의 증명은 **임의의 `n`을 받아 `P n`의 증명을 내놓는 함수**입니다 — `intro n`이 바로 그 함수의 매개변수를 받는 동작입니다. `∃ n : Nat, P n`(어떤 자연수 `n`이 존재해서 `P n`)의 증명은 **구체적인 `n`과 그 `n`에 대한 `P n`의 증명을 짝지은 것**입니다 — `⟨3, by decide⟩`가 "그 `n`은 `3`이고, `3 * 3 = 9`라는 증거는 이렇다"는 뜻입니다. `∀`는 함수 타입의 일반화(어떤 인자를 받든 같은 방식으로 결과를 내놓는), `∃`는 곱 타입의 일반화(값과 그 값에 대한 증거를 짝짓는)입니다.

== 왜 이 대응이 이 책 전체의 기반인가

이 책의 3부에서 프로그래밍 언어의 의미론을 "관계"로 정의할 텐데, 그 관계 자체가 결국 `Prop`을 반환하는 함수이고, "이 프로그램이 이 결과로 평가된다"는 주장의 증명도 결국 이 장에서 본 것과 똑같은 재료(함수, 곱, 합, 전칭, 존재)로 지어집니다. Curry-Howard 대응을 제대로 다져두면, 나중에 훨씬 복잡해 보이는 증명도 사실은 "함수를 짜고, 값을 짝짓고, 어느 쪽 생성자를 고를지 결정하는" 익숙한 작업의 연장이라는 걸 알아볼 수 있습니다.

== 직접 해보기

* `IsEven (n : Nat) : Prop := n % 2 = 0`을 정의하고, `IsEven a → IsEven b → IsEven (a + b)`를 증명해보세요.
* `P → Q → P`(어떤 명제 `P`, `Q`에 대해서도 성립하는 규칙)를 전술 없이 증명 항으로 직접 지어보세요.

.해답 보기
[%collapsible]
====
[source,lean]
----
def IsEven (n : Nat) : Prop := n % 2 = 0

theorem even_add (a b : Nat) (ha : IsEven a) (hb : IsEven b) : IsEven (a + b) := by
  unfold IsEven at *
  omega

theorem constK {P Q : Prop} (hp : P) (_hq : Q) : P := hp
----
====

== 요약

* `Prop`은 명제들의 타입이고, 증명은 그 명제 타입에 속하는 하나의 값입니다.
* 함의(`P → Q`)는 함수 타입, 논리곱(`∧`)은 곱 타입, 논리합(`∨`)은 합 타입과 정확히 같은 구조를 가집니다 — 이걸 Curry-Howard 대응이라고 부릅니다.
* `∀`는 함수 타입의 일반화, `∃`는 곱 타입의 일반화입니다.
* 증명은 `by ...`(전술)로 만들어달라고 요청할 수도 있고, 함수를 짜듯 값을 직접 지을 수도 있습니다 — 이 둘은 같은 것의 다른 표현일 뿐입니다.
