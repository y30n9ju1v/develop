== "당연한" 성질도 증명이 필요하다

`BigStep`을 **함수**가 아니라 **관계**로 정의했다는 게 8장의 핵심이었습니다. 그런데 관계로 정의하면 걱정거리가 하나 생깁니다 — 함수는 정의상 "하나의 입력에 하나의 출력"이 자동으로 보장되지만, 관계는 원칙적으로 "같은 입력이 여러 출력과 이어져 있다"고 정의될 수도 있습니다. `c / s ⇓ s1`과 `c / s ⇓ s2`가 둘 다 성립하는데 `s1 ≠ s2`인 경우가 있다면, 우리 언어는 "같은 프로그램을 같은 곳에서 실행했는데 실행할 때마다 결과가 달라지는" 이상한 언어가 됩니다. 이런 일이 **없다**는 걸 증명하는 게 이 장의 목표입니다 — 이 성질을 **결정성(determinism)**이라고 부릅니다.

== 결정성 정리 세우기

[source,lean]
----
theorem bigstep_deterministic (c : Com) (s s1 s2 : State)
    (h1 : c / s ⇓ s1) (h2 : c / s ⇓ s2) : s1 = s2 := by
  induction h1 generalizing s2 with
  ...
----

정리 자체는 단순합니다 — "같은 명령문 `c`를 같은 시작 상태 `s`에서 실행해 각각 `s1`, `s2`에 도달했다면(`h1`, `h2`), 사실 `s1 = s2`다." 증명은 `h1`(첫 번째 실행 증거)에 대한 귀납법입니다. `generalizing s2`가 중요합니다 — `s2`(그리고 `h2`)를 귀납법을 걸기 전에 고정해버리면, 귀납 가설이 "지금 이 특정한 `s2`에 대해서만" 성립하는 것으로 너무 좁아져서 증명이 안 풀립니다. "**어떤** `s2`가 오든" 성립한다고 일반화해야, `seq`나 `whileTrue`처럼 중간 상태를 거치는 갈래에서 귀납 가설을 자유롭게 적용할 수 있습니다 — 2장의 `induction ... generalizing`이 다시 등장한 것입니다.

== 갈래별로 확인하기

[source,lean]
----
  | skip s => cases h2 with
    | skip => rfl
  | assign s x a => cases h2 with
    | assign => rfl
----

`skip`과 `assign`은 간단합니다 — `h1`이 `skip`(또는 `assign`)으로 지어졌다면, `h2`도 **같은 명령문**에 대한 증거이니 `cases h2`로 열어보면 `h2`도 반드시 `skip`(또는 `assign`)일 수밖에 없고, 그 결과 상태는 정의상 하나로 정해져 있어 `rfl`로 끝납니다.

[source,lean]
----
  | seq c1 c2 s1 s2' s3 h1 h2' ih1 ih2 =>
    cases h2 with
    | seq _ _ _ s2'' _ h1' h2'' =>
      have heq := ih1 s2'' h1'
      subst heq
      exact ih2 s2 h2''
----

`seq`가 조금 더 흥미롭습니다 — `c1 ; c2`를 실행한 두 증거(`h1`이 지어진 쪽과 `h2`)가 각자 **다른 중간 상태**(`s2'`과 `s2''`)를 거쳤을 수 있습니다. 먼저 귀납 가설 `ih1`(c1에 대한 결정성)로 "그 중간 상태들이 사실 같다"(`heq : s2' = s2''`)는 걸 확립하고(`subst heq`로 둘을 하나로 합친 뒤), 그다음 `ih2`(c2에 대한 결정성)로 최종 상태가 같다는 걸 마무리합니다 — **부분 문제(c1의 결정성, c2의 결정성)를 각자 증명해서 전체(c1;c2의 결정성)를 조립**하는 방식입니다.

[source,lean]
----
  | ifTrue b c1 c2 s s' hb h1 ih =>
    cases h2 with
    | ifTrue _ _ _ _ _ _ h1' => exact ih s2 h1'
    | ifFalse _ _ _ _ _ hb' _ => simp_all
----

`ifTrue` 갈래에서는 `h2`가 `ifTrue`일 수도 `ifFalse`일 수도 있어 보입니다 — 하지만 `h1`이 이미 `evalB s b = true`(`hb`)라는 증거를 갖고 있으니, `h2`가 `ifFalse`(`evalB s b = false`라는 증거를 요구)일 수는 **없습니다**. `simp_all`이 이 모순(`true = false`)을 확인해서 그 갈래를 자동으로 없애줍니다 — `evalB`가 **함수**라서 같은 입력에 항상 같은 `Bool`을 내놓는다는 사실이, 여기서 조건문의 결정성을 뒷받침하는 재료로 쓰입니다. `whileFalse`/`whileTrue` 갈래도 같은 논리로, "조건이 참인지 거짓인지"는 `evalB`가 하나로 정하니 두 증거가 서로 다른 갈래로 지어질 수 없다는 걸 확인합니다.

== 이 증명이 보여주는 것

`bigstep_deterministic`을 증명할 수 있었다는 것 자체가 의미 있습니다 — **관계로 정의했다고 해서 "여러 값과 동시에 이어질 수 있다"는 걱정이 실제로 실현되지는 않는다**는 걸 확인해준 것입니다. 이 증명이 기대는 두 기둥은 `evalA`/`evalB`가 함수라는 것(산술식·불식은 항상 하나의 값으로 정해짐, 7장)과, `BigStep`의 생성자들이 서로 겹치지 않는 조건(`ifTrue`는 조건이 참일 때만, `ifFalse`는 거짓일 때만)으로 나뉘어 있다는 것(8장의 설계)입니다 — **언어를 어떻게 설계하느냐가 그 언어의 성질을 결정한다**는 걸 보여주는 사례입니다.

== 왜 이게 다음 장의 기반인가

10장에서 "두 프로그램이 같은 일을 한다"는 걸 정의할 때, "**모든** 시작 상태에 대해, 첫 번째 프로그램이 도달하는 상태와 두 번째 프로그램이 도달하는 상태가 같다"는 식으로 정의합니다. 이 정의가 말이 되려면 애초에 "프로그램이 도달하는 상태"가 하나로 정해져 있어야 하는데, 그게 바로 이 장에서 증명한 결정성입니다.

== 직접 해보기

* `bigstep_deterministic`의 증명에서 `whileTrue` 갈래를 직접 채워보세요(본문에 보인 `seq` 갈래와 거의 같은 구조입니다).

.해답 보기
[%collapsible]
====
[source,lean]
----
  | whileTrue b c s s' s'' hb h1 h2' ih1 ih2 =>
    cases h2 with
    | whileFalse _ _ _ hb' => simp_all
    | whileTrue _ _ _ s2'' _ _ h1' h2'' =>
      have heq := ih1 s2'' h1'
      subst heq
      exact ih2 s2 h2''
----

`seq` 갈래와 정확히 같은 패턴입니다 — 반복문 본문을 한 번 실행한 뒤의 중간 상태가 같다는 걸 먼저 확립하고(`ih1`), 그다음 "남은 반복문"(재귀적으로 같은 `whileLoop`)에 대한 결정성(`ih2`)으로 마무리합니다. `whileLoop`이 `seq`처럼 "한 스텝 + 나머지"의 모양이라는 걸 이 대칭성이 보여줍니다.
====

== 요약

* 관계로 정의한 의미론은 "같은 입력이 여러 출력과 이어질 수도 있다"는 원칙적인 위험을 갖는데, 그게 실제로는 일어나지 않는다는 걸 결정성 정리로 증명해야 합니다.
* 증명은 `BigStep` 증거에 대한 귀납법이고, `generalizing`으로 비교 대상을 일반화해야 `seq`·`whileTrue`처럼 중간 상태를 거치는 갈래가 풀립니다.
* 결정성은 `evalA`/`evalB`가 함수라는 사실(7장)과 `BigStep` 생성자들의 조건이 서로 겹치지 않는다는 설계(8장)에 기대고 있습니다 — 언어 설계와 그 성질은 서로 맞물려 있습니다.

다음 장에서는 이 결정성 위에서, "다르게 생긴 두 프로그램이 사실은 같은 일을 한다"는 프로그램 동치를 정의하고 증명합니다.
