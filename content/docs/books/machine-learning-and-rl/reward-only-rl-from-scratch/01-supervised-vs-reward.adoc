== 지도학습: 정답이 주어진다

지도학습의 기본 구조는 단순합니다 — 입력 `x`와 정답 `y` 쌍이 데이터셋으로 이미 주어져 있고, 모델은 `x`를 보고 `y`를 예측하도록 오차를 줄여나갑니다. 아주 작은 로지스틱 회귀로 이걸 직접 확인합니다. 입력 `x`가 양수면 레이블 1, 음수면 레이블 0이라는 정답이 이미 데이터에 박혀 있습니다.

[source,python]
----
import numpy as np
rng = np.random.default_rng(0)

X_sup = rng.uniform(-3, 3, size=200)
y_sup = (X_sup > 0).astype(int)  # 정답 레이블이 이미 주어져 있다

def supervised_train(X, y, epochs=200, lr=0.5):
    w, b = 0.0, 0.0
    for _ in range(epochs):
        z = w * X + b
        p = 1 / (1 + np.exp(-z))
        grad_w = np.mean((p - y) * X)   # 정답 y와 예측 p의 오차로 그래디언트 계산
        grad_b = np.mean(p - y)
        w -= lr * grad_w
        b -= lr * grad_b
    return w, b
----

`(p - y)`라는 항이 핵심입니다 — 모델이 무엇을 예측하든, 그 예측이 정답 `y`와 얼마나 다른지를 매 스텝 즉시 알 수 있습니다. 이 오차 신호가 지도학습을 지도학습답게 만듭니다.

== 강화학습: 정답이 없다, 보상만 있다

이제 정답 레이블이 아예 없는 문제를 만듭니다 — 2개의 슬롯머신 팔(2-armed bandit) 중 하나를 골라 당기면, "이 팔이 정답이다"라는 말은 안 알려주고 그냥 보상(0 또는 1)만 하나 돌아옵니다. 어느 쪽이 더 좋은 팔인지는 직접 당겨보며 통계로 추정하는 수밖에 없습니다.

[source,python]
----
true_means = np.array([0.3, 0.7])  # 에이전트는 이 값을 모른다

def pull(arm):
    return rng.binomial(1, true_means[arm])

def epsilon_greedy_bandit(n_steps=1000, epsilon=0.1):
    counts = np.zeros(2)
    values = np.zeros(2)
    rewards = []
    for t in range(n_steps):
        if rng.uniform() < epsilon:
            arm = rng.integers(0, 2)      # 탐험: 무작위로 팔을 골라본다
        else:
            arm = np.argmax(values)       # 활용: 지금까지 가장 좋아 보이는 팔을 고른다
        r = pull(arm)
        counts[arm] += 1
        values[arm] += (r - values[arm]) / counts[arm]  # 받은 보상으로 가치 추정을 갱신
        rewards.append(r)
    return values, counts, np.array(rewards)
----

정답 레이블은 어디에도 없습니다. `values[arm]`이라는 추정치도 "정답"이 아니라 "지금까지 당겨본 결과의 평균"일 뿐이고, 그마저도 매 스텝 갱신됩니다. 게다가 지도학습에는 없던 문제가 하나 생깁니다 — 팔을 하나 당길 때마다 그 팔의 가치를 더 정확히 알게 되지만(활용), 아직 안 당겨본(또는 적게 당겨본) 팔이 사실 더 좋을 수도 있다는 가능성은 계속 남습니다(탐험). `epsilon`이 그 둘 사이의 저울입니다.

== 실행 결과

[source,python]
----
w, b = supervised_train(X_sup, y_sup)
pred = (1 / (1 + np.exp(-(w * X_sup + b))) > 0.5).astype(int)
acc_sup = np.mean(pred == y_sup)
print(f"[지도학습] w={w:.3f}, b={b:.3f}, 학습 정확도={acc_sup:.3f}")

values, counts, rewards = epsilon_greedy_bandit()
print(f"[강화학습] 추정 가치: 팔1={values[0]:.3f}, 팔2={values[1]:.3f}")
print(f"[강화학습] 팔 선택 횟수: 팔1={int(counts[0])}, 팔2={int(counts[1])}")
print(f"[강화학습] 초반 100스텝 평균 보상={rewards[:100].mean():.3f}, "
      f"마지막 100스텝 평균 보상={rewards[-100:].mean():.3f}")
----

실제로 실행하면:

----
[지도학습] w=4.287, b=0.100, 학습 정확도=0.990
[강화학습] 추정 가치: 팔1=0.333, 팔2=0.714
[강화학습] 팔 선택 횟수: 팔1=57, 팔2=943
[강화학습] 초반 100스텝 평균 보상=0.580, 마지막 100스텝 평균 보상=0.730
----

지도학습은 200 에폭 만에 정답 레이블에 99% 들어맞는 결정 경계를 찾습니다 — 매 스텝 정답과의 오차를 정확히 알기 때문에 수렴이 빠르고 확실합니다. 강화학습 쪽은 1000번 팔을 당긴 뒤에도 추정 가치(0.333, 0.714)가 참값(0.3, 0.7)에 가깝긴 하지만 정확히 일치하지는 않고, 팔1(진짜로 나쁜 팔)도 57번이나 당겼습니다 — 탐험 비용입니다. 대신 뒷부분 100스텝의 평균 보상(0.730)이 앞부분(0.580)보다 뚜렷이 높아진 걸 보면, "정답을 모른 채로도" 경험만으로 점점 더 좋은 팔을 더 자주 고르게 됐다는 걸 확인할 수 있습니다 — 이게 강화학습이 학습이라고 부를 수 있는 이유입니다.

== 이 대조가 이 책 전체의 축이다

앞으로 이 책에서 다룰 모든 알고리즘(Q-learning, DQN, PPO, 그리고 최종적으로 마리오 정책망)은 전부 이 2-armed bandit과 같은 구조를 갖습니다 — "정답이 뭔지 알려주는 사람은 없고, 행동을 하고 나서 보상이라는 스칼라 하나만 돌아온다"는 것. 다음 장에서는 이 구조를 하나의 스텝이 아니라 여러 스텝에 걸친 연쇄된 의사결정(순차적 의사결정)으로 일반화하는 수학적 틀 — 마르코프 결정 과정(MDP) — 을 세웁니다.
