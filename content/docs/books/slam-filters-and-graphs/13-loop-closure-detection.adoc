'''

1권 12장에서 루프 클로저의 효과(루프를 닫는 간선 하나가 궤적 전체의 오차를 재분배한다)를 맛봤지만, "로봇이 지금 예전에 왔던 곳을 다시 지나고 있다"는 사실 자체는 이미 안다고 가정했습니다. 실전에서는 그렇지 않습니다 — 로봇은 자기 위치 추정(드리프트로 인해 부정확할 수 있는)만으로는 "여기 와본 곳인가?"를 알 수 없습니다. 이 장에서는 이 재방문을 센서 데이터만으로 **탐지**하는 방법과, 탐지된 재방문을 정확한 그래프 제약으로 바꾸는 방법을 다룹니다.

== 문제: 위치 추정이 이미 틀렸는데, 어떻게 "여기 와봤다"를 아는가

11장에서 봤듯 오도메트리만으로 추정한 로봇 위치는 드리프트가 쌓입니다. 그러니 "지금 위치 추정치가 예전의 어느 위치 추정치와 가까운가"로 재방문을 판단하면, 애초에 드리프트 때문에 틀린 그 위치 추정치를 기준으로 판단하는 셈이라 신뢰할 수 없습니다. 대신 **로봇이 지금 무엇을 보고 있는지**(센서 데이터 자체)로 판단해야 합니다 — 위치 추정과 무관하게, "지금 보이는 풍경이 예전에 봤던 풍경과 닮았다"는 것만으로 재방문을 알아챌 수 있습니다.

== 방향에 무관한 서술자(descriptor)

로봇이 같은 장소를 다시 지나가더라도, 그때와 지금 로봇이 향하고 있는 방향(heading)은 다를 수 있습니다. 그러니 서술자는 로봇의 방향에 영향받지 않아야 합니다 — 가장 단순한 방법은, 지금 보이는 랜드마크들까지의 **거리만** 모아서 정렬한 목록을 쓰는 것입니다(방위각은 방향에 따라 바뀌지만 거리는 안 바뀝니다).

[source,python]
----
def range_descriptor(pose):
    scan = local_scan(pose)                       # 보이는 랜드마크들의 로컬 좌표
    ranges = np.sort(np.linalg.norm(scan, axis=1))  # 거리만 뽑아서 정렬
    return ranges

def descriptor_distance(d1, d2):
    n = min(len(d1), len(d2))
    if n == 0: return np.inf
    return np.linalg.norm(d1[:n] - d2[:n]) + abs(len(d1)-len(d2)) * 2.0
----

== 검증: 재방문한 장소는 정말로 서술자가 가깝게 나오는가

로봇이 팔각형 경로를 두 바퀴 돕니다(`x0~x7`이 첫 바퀴, `x8~x15`가 같은 물리적 위치를 도는 두 번째 바퀴) — `x_i`와 `x_{i+8}`은 실제로 정확히 같은 장소입니다.

[source,python]
----
same_place_dists = [descriptor_distance(descriptors[f"x{i}"], descriptors[f"x{i+8}"]) for i in range(8)]
diff_place_dists = [descriptor_distance(descriptors[f"x{i}"], descriptors[f"x{j}"]) for i,j in 서로_다른_위치_쌍들]
print(np.max(same_place_dists), np.min(diff_place_dists))
----

[source]
----
same-place descriptor distance: mean=0.0  max=0.0
diff-place descriptor distance: mean=3.09  min=0.36
----

같은 장소를 재방문한 쌍은 서술자 거리가 정확히 `0`(방향이 달라도 거리 목록 자체는 완전히 동일)인 반면, 서로 다른 장소 쌍은 아무리 가까워도 `0.36` 이상입니다 — 두 그룹이 완벽하게 분리되어, 서술자만으로 "여기 와봤다"를 확실하게 판단할 수 있습니다.

== 검증: ICP로 정확한 상대 포즈까지 복원하는가

서술자로 "아마 같은 장소"라는 **후보**를 찾았다면, 다음 단계는 9장에서 배운 ICP로 두 스캔을 실제로 정렬해서 **정확한 상대 회전·이동**까지 구하는 것입니다.

[source,python]
----
scan_x0 = local_scan(true_poses["x0"]) + noise
scan_x8 = local_scan(true_poses["x8"]) + noise
R_icp, t_icp = icp_2d(scan_x8, scan_x0)   # x8의 스캔을 x0의 스캔에 맞추는 변환
theta_icp = np.arctan2(R_icp[1,0], R_icp[0,0])
print(theta_icp)   # 0.0009 (실제로 두 포즈의 방향이 같으므로 참값 0에 근접)
----

서술자는 "가능성이 있다"는 후보만 알려줄 뿐, 정확한 상대 포즈는 알려주지 않습니다 — ICP가 그 정확한 상대 포즈(그래프에 새 제약으로 추가할 수치)를 만들어내는 두 번째 단계입니다. 서술자(빠르지만 대략적인 후보 탐지)와 ICP(느리지만 정밀한 정합)를 조합하는 이 2단계 구조가, 실전 SLAM의 루프 클로저 탐지가 거의 항상 따르는 패턴입니다.

== 실험: 체계적 편향으로 실제 드리프트 만들기

지금까지 여러 장에서 오도메트리에 무작위 노이즈만 섞었습니다. 이번엔 실전에서 흔한 문제 — 바퀴 반경이 설계값과 미세하게 다른 것 같은, 매 스텝 같은 방향으로 쌓이는 **체계적** 편향 — 을 추가합니다.

[source,python]
----
bias = np.array([0.0, 0.0, 0.02])   # 매 스텝 회전이 실제보다 항상 살짝 더 크게 측정됨
delta_meas = delta_true + bias + rng.normal(0, [0.04,0.04,0.02])
----

무작위 노이즈는 평균적으로 상쇄되는 경향이 있지만, 이런 체계적 편향은 스텝을 거듭할수록 한 방향으로 계속 쌓입니다 — 3장·11장에서 이미 봤던 드리프트를 더 뚜렷하게 만드는 현실적인 원인입니다.

== 검증: 루프 클로저 엣지가 이 드리프트를 실제로 고치는가

서술자로 찾은 재방문 후보 `4`곳(`x0-x8`, `x2-x10`, `x4-x12`, `x6-x14`)에 대해 ICP로 정확한 상대 포즈를 구하고, 그 결과를 새로운 그래프 제약(엣지)으로 추가합니다.

[source,python]
----
for i in [0, 2, 4, 6]:
    pa, pb = pose_ids[i], pose_ids[i+8]
    R_rel, t_rel = icp_2d(local_scan(pb)+noise, local_scan(pa)+noise)
    delta_loop = [t_rel[0], t_rel[1], np.arctan2(R_rel[1,0], R_rel[0,0])]
    graph.add_factor(OdometryFactor(pa, pb, delta_loop, info_loop))   # 10장의 팩터를 그대로 재사용
----

[source]
----
mean pose error WITHOUT loop closure: 0.784
mean pose error WITH loop closure:    0.233   (70% 감소)
----

루프 클로저 엣지 `4`개를 추가하고 11장의 최적화를 다시 돌리자, 평균 포즈 오차가 `0.784`에서 `0.233`으로 `70%` 줄었습니다 — 체계적 편향으로 누적된 드리프트가, "이 지점들은 사실 같은 곳이어야 한다"는 정보 몇 개만으로 궤적 전체에 걸쳐 크게 교정된 것입니다.

== 시행착오: 엣지를 너무 많이 넣으면 오히려 나빠질 수 있다

이 실험을 준비하며 겪은 흥미로운 함정이 있습니다 — 처음에는 재방문한 `8`쌍(`x0-x8`부터 `x7-x15`까지) **전부**를 루프 클로저 엣지로 추가했는데, 결과가 오히려 **더 나빠졌습니다**. 원인은 이렇습니다 — 무작위 노이즈만 있던 (편향 없는) 초기 실험에서는, `8`개의 엣지 각각이 (자체적인 노이즈가 섞인) 살짝씩 다른 "정답"을 주장하는 셈이 되어, 이미 우연히 낮았던 드리프트를 오히려 노이즈가 섞인 여러 제약들의 절충안으로 밀어내며 참값에서 더 멀어지게 만들었습니다. 소수(`4`개)의, 궤적 전체에 고르게 퍼진 엣지만 쓰는 게 — 특히 편향처럼 실제로 교정할 가치가 있는 오차가 있을 때 — 더 안정적인 결과를 냈습니다. 이건 5장에서 데이터 연관을 다룰 때도 나왔던 교훈과 비슷합니다 — 제약은 많다고 무조건 좋은 게 아니라, **정확하고 서로 일관된** 제약이어야 도움이 됩니다.

== 왜 이게 SLAM에서 중요한가

루프 클로저는 SLAM에서 "공짜로 얻는 정보"가 아니라, 지도 전체의 신뢰도를 검증하는 사건입니다 — 로봇이 실제로 같은 곳을 다시 왔다는 것 자체가, 그 사이에 쌓인 모든 오차에 대한 강력한 제약을 제공합니다. 반대로 루프 클로저를 잘못 탐지하면(실제로는 다른 곳인데 같은 곳이라고 오판하면), 5장의 데이터 연관 오류처럼 지도 전체를 심각하게 오염시킬 수 있습니다 — 서술자 단계의 오탐(false positive)을 ICP 단계에서 최종 정합 오차로 한 번 더 거르는 이유가 여기 있습니다.

체계적 편향이 없으면, 무작위 노이즈만으로 쌓이는 드리프트는 이 정도 스텝 수(`15`)에서는 크지 않을 수 있고(무작위 노이즈는 서로 상쇄되는 경향이 있으므로), 특정 난수 시드에 따라 "루프 클로저 없이도 우연히 이미 꽤 정확한" 경우가 생길 수 있습니다 — 본문에서 겪은 시행착오가 바로 이 현상이었습니다. 루프 클로저의 진짜 가치는 이런 우연에 기댈 게 아니라, 체계적 편향처럼 **반드시, 그리고 계속 쌓이는** 오차가 있는 상황에서 뚜렷하게 드러납니다. 실전 로봇의 오도메트리는 거의 항상 이런 체계적 편향(바퀴 지름 오차, 센서 정렬 오차 등)을 갖고 있으므로, 루프 클로저는 이론적 사치가 아니라 실질적으로 거의 항상 필요한 교정 수단입니다.

== 요약

* 위치 추정 자체가 드리프트로 부정확할 수 있으므로, 재방문 탐지는 위치가 아니라 센서 데이터(방향에 무관한 서술자)를 기준으로 해야 합니다.
* 거리만 모아 정렬한 서술자로 재방문 후보를 완벽하게 분리해낼 수 있었고(같은 장소 거리 `0` vs 다른 장소 거리 `0.36` 이상), ICP로 그 후보의 정확한 상대 포즈까지 복원했습니다.
* 바퀴 반경 오차 같은 체계적 편향으로 실제 드리프트를 만들고, 소수의 정확한 루프 클로저 엣지가 이 드리프트를 `70%` 줄이는 걸 확인했습니다.
* 루프 클로저 엣지를 무분별하게 많이 추가하면, 특히 편향이 없는 상황에서는 오히려 결과가 나빠질 수 있다는 실전적인 함정도 겪었습니다 — 제약은 정확하고 일관될 때만 도움이 됩니다.
