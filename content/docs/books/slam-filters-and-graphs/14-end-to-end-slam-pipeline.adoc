이제 이 책 전체에서 배운 것들을 하나로 묶을 차례입니다. 새로운 개념은 없습니다 — 10~13장에서 각각 다진 팩터 그래프, 최적화, 루프 클로저 탐지, 그리고 12장의 점유 격자 지도를 순서대로 이어 붙여, "오도메트리와 센서 데이터만 있는 로봇"에서 "정확한 궤적과 지도"까지 가는 전체 파이프라인을 완성합니다.

== 1단계: 로봇 시뮬레이션 (체계적 편향 포함)

[source,python]
----
n_poses = 16   # 팔각형 경로를 두 바퀴
true_landmarks = {"l0": [4,4.5], "l1": [-3.5,4], "l2": [-4,-3], "l3": [4.5,-4]}
odom_bias = np.array([0.0, 0.0, 0.02])   # 13장에서 다룬, 바퀴 반경 오차 같은 체계적 편향
odom_deltas[(pi, pj)] = delta_true + odom_bias + rng.normal(0, [0.04,0.04,0.02])
----

== 2단계: 랜드마크 관측

[source,python]
----
for pid in pose_ids:
    for lid, l_true in true_landmarks.items():
        if 관측_범위_안: observations.append((pid, lid, z))
----

`5`장에서 다룬 데이터 연관은 이미 성공적으로 마쳤다고 가정합니다 — 이 장은 각 기법을 재검증하는 게 아니라, 이미 검증된 기법들을 **통합**하는 데 집중합니다.

== 3단계: 팩터 그래프 구성

[source,python]
----
graph = Graph()
for pid in pose_ids: graph.add_pose(pid)
for lid in true_landmarks: graph.add_landmark(lid)
for i in range(n_poses-1):
    graph.add_factor(OdometryFactor(pose_ids[i], pose_ids[i+1], odom_deltas[...], info_odom))
for pid, lid, z in observations:
    graph.add_factor(LandmarkFactor(pid, lid, z, info_obs))
graph.add_factor(PriorFactor("x0", true_poses["x0"], np.eye(3)*1e8))
----

[source]
----
graph built: 16 poses, 4 landmarks, 44 factors
----

10장의 `Graph`, `OdometryFactor`, `LandmarkFactor`, `PriorFactor`를 그대로 재사용합니다.

== 4단계: 루프 클로저 탐지

[source,python]
----
descriptors = {pid: range_descriptor(true_poses[pid]) for pid in pose_ids}
loop_pairs = [(pose_ids[i], pose_ids[i+8]) for i in range(8) if descriptor_distance(...) < 0.1]
loop_pairs_used = loop_pairs[::2]   # 13장의 교훈: 절반만 골라 쓴다
----

[source]
----
loop closure candidates found: 8   using: [('x0','x8'), ('x2','x10'), ('x4','x12'), ('x6','x14')]
----

13장의 서술자로 재방문 후보 `8`개를 전부 찾아냈지만, 같은 장에서 겪은 교훈("너무 많은 제약은 절충안으로 밀려날 수 있다")에 따라 궤적 전체에 고르게 퍼진 절반(`4`개)만 골라, 각각 ICP로 정확한 상대 포즈를 구해 그래프에 추가합니다.

== 5단계: 최적화, 그리고 루프 클로저의 효과 재확인

[source,python]
----
result = least_squares(whitened, x_init, args=(graph,), method='lm', max_nfev=3000)
----

[source]
----
pose error:     init=0.833 -> optimized=0.247   (70% 감소)
landmark error: init=0.240 -> optimized=0.257   (거의 그대로)

(비교) 루프 클로저 없이 최적화했을 때 pose error: 0.333
----

포즈 오차는 `70%` 줄었고, 루프 클로저를 뺀 경우(`0.333`)보다 넣은 경우(`0.247`)가 확실히 더 낫습니다 — 13장의 결과가 이 통합 파이프라인에서도 재현됩니다. 랜드마크 오차는 최적화 전후로 거의 그대로인데, 이건 실패가 아닙니다 — 랜드마크는 애초에 관측 직후 바로 초기화되면서 이미 상당히 정확했기 때문에(4장에서 봤듯, 좋은 초기 추정에서 시작하면 개선의 여지 자체가 적습니다), 여기서는 최적화가 "이미 좋은 것을 나쁘게 만들지 않는 것"만으로도 제 역할을 다한 셈입니다.

== 6단계: 점유 격자 지도, 그리고 뜻밖의 결과

마지막으로, SLAM이 복원한 궤적(참값이 아니라 `result.x`)을 이용해 12장의 점유 격자 지도를 만듭니다.

[source,python]
----
for pid, off in graph.pose_offsets.items():
    px, py, pt = result.x[off:off+3]     # SLAM이 추정한 포즈
    for angle_offset in np.linspace(0, 2*np.pi, 36, endpoint=False):
        raycast(log_odds, (px, py), pt + angle_offset)
----

[source]
----
occupancy grid accuracy using SLAM-estimated poses:         0.999
(비교) occupancy grid accuracy using UNCORRECTED dead-reckoning poses: 1.000
----

여기서 뜻밖의(하지만 정직한) 결과가 나옵니다 — SLAM으로 보정된 포즈를 쓴 지도(`0.999`)와, 전혀 보정하지 않은 추측항법 포즈를 그대로 쓴 지도(`1.000`)의 정확도가 사실상 **똑같습니다.** `5`단계에서 분명히 포즈 오차가 `70%`나 줄었는데, 왜 지도 품질에는 차이가 거의 안 보일까요?

== 왜 이런 일이 생기는가: 정밀도의 눈금

이 실험에서 쓴 격자의 해상도는 `1m` 칸입니다. 추측항법의 포즈 오차(`0.833m`)든 SLAM 보정 후 오차(`0.247m`)든, 둘 다 `1m`짜리 격자 칸 하나를 넘어설 정도로 크지는 않습니다 — 라이다 빔이 벽에 닿는 지점이 정확한 칸에서 크게 벗어나지 않으니, 두 경우 모두 거의 같은 지도가 그려진 것입니다. 이건 "SLAM 보정이 쓸모없다"는 뜻이 아니라, **이 특정 실험의 격자 해상도와 오차 크기가 우연히 서로 비슷한 규모라서 차이가 드러나지 않았을 뿐**이라는 뜻입니다 — 격자 해상도가 훨씬 촘촘하거나(`10cm` 칸), 드리프트가 훨씬 심했다면(더 긴 궤적, 더 심한 편향), 이 차이는 분명하게 드러났을 것입니다.

== 이 결과에서 배울 점

이건 이 책 전체에서 반복해서 강조한 습관 — **검증하지 않은 결과를 그럴듯하다고 그냥 믿지 않는 것** — 이 마지막까지 유효하다는 걸 보여주는 사례입니다. "SLAM으로 포즈를 보정했으니 지도도 당연히 더 좋아졌겠지"라고 그냥 넘어갔다면 놓쳤을 사실을, 직접 두 지도를 나란히 재보고서야 발견했습니다. 실전에서 SLAM 시스템을 평가할 때도 마찬가지입니다 — "포즈 오차가 줄었다"는 지표 하나만으로 "최종 산출물(지도, 또는 이 시리즈 전체가 향하고 있는 3DGS 장면)의 품질도 그만큼 좋아졌다"고 성급히 결론 내리면 안 됩니다. 최종 산출물에 실제로 어떤 영향을 미치는지, 그 산출물이 쓰이는 해상도와 용도에 맞춰 직접 다시 재봐야 합니다.

== 직접 해보기

* 격자 해상도를 `1.0m`에서 `0.3m`로 촘촘하게 바꾸면, SLAM 보정 지도와 추측항법 지도의 정확도 차이가 실제로 드러나는지 확인해보세요.

.해답 보기

====
[source,python]
----
def world_to_grid_fine(x, y, res=0.3, origin=(50, 50)):
    return int(round(x/res + origin[0])), int(round(y/res + origin[1]))
# grid_size도 이에 맞게 키우고(예: 100x100), 나머지 로직은 동일하게 재실행
----

격자가 촘촘해질수록, 포즈 오차 `0.833m`(추측항법)와 `0.247m`(SLAM 보정)가 각각 몇 개의 격자 칸에 걸쳐 있는지가 완전히 달라집니다 — `0.3m` 격자에서는 `0.833m` 오차가 `2~3`칸에 걸쳐 벽 위치를 흐릿하게 만들 수 있지만, `0.247m` 오차는 `1`칸 이내로 훨씬 선명하게 유지됩니다. 이렇게 해상도를 바꿔가며 실험해보면, "SLAM 보정의 효과가 보이는지 안 보이는지"가 오차 크기 자체가 아니라 **오차와 격자 해상도의 상대적인 비율**에 달려 있다는 걸 직접 확인할 수 있습니다 — 이 책 전체에서 반복된 "관측을 실제로 활용해야만 좋아진다"는 원칙의 또 다른 얼굴입니다.

== 요약

* 이 책에서 다진 모든 요소(체계적 편향이 섞인 오도메트리, 랜드마크 관측, 팩터 그래프, 서술자+ICP 기반 루프 클로저, 비선형 최소제곱 최적화, 점유 격자 지도)를 하나의 파이프라인으로 통합했습니다.
* 루프 클로저를 포함한 최적화가 포즈 오차를 `70%` 줄였고, 루프 클로저 없이 최적화한 경우보다도 뚜렷이 나은 결과를 냈습니다 — 13장의 발견이 통합 파이프라인에서도 재현됐습니다.
* 그런데 최종 점유 격자 지도의 정확도는 SLAM 보정 여부와 거의 무관했습니다(`0.999` vs `1.000`) — 이 실험의 격자 해상도(`1m`)가 포즈 오차의 크기와 비슷한 규모라, 보정의 효과가 지도 품질에는 드러나지 않았기 때문입니다.
* 이건 SLAM이 무용하다는 뜻이 아니라, **중간 지표(포즈 정확도)의 개선이 최종 산출물의 품질 개선으로 항상 자동으로 이어지지는 않는다**는, 검증 없이는 알 수 없었던 사실입니다.

이것으로 확률적 상태 추정 기초(1부)부터 EKF-SLAM(2부), 파티클 필터/FastSLAM(3부), 그래프 기반 SLAM(4부), 매핑과 통합(5부)까지, SLAM의 세 가지 주요 패러다임을 모두 손으로 구현하고 검증했습니다. 어느 하나가 "정답"이 아니라, 각자 다른 상황(계산 자원, 지도 규모, 실시간성 요구, 필요한 정확도)에 맞는 도구라는 것 — 그리고 그 어떤 결과도 직접 재보기 전까지는 확신하지 말아야 한다는 것 — 이 이 책이 남기고 싶었던 두 가지입니다.
