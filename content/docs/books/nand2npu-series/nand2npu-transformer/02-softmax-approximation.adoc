== 1. 왜 지수함수가 문제인가

`softmax(x_i) = exp(x_i) / Σⱼ exp(xⱼ)`입니다. 지금까지 이 시리즈가 다룬 회로는 전부 덧셈·곱셈·비교뿐이었습니다(1권 2장에서 곱셈조차 "회로가 복잡하다"는 이유로 ALU에서 뺐던 걸 떠올려보세요). `exp`는 그보다 훨씬 비싼 함수입니다 — 정확히 계산하려면 테일러 급수나 반복 알고리즘이 필요하고, 매 클록 끝내야 하는 하드웨어에는 맞지 않습니다. 이 장은 `exp`를 룩업 테이블(LUT)로 근사합니다.

== 2. 룩업 테이블: 미리 계산해둔 표로 근사

[source,lean]
----
-- Transformer/Softmax.lean
namespace Nand2Npu.Transformer

/-- (구간 경계, 그 구간에서의 근사 exp 값) 쌍의 목록 — 구간 경계는 오름차순이어야 합니다.
    실제 값은 책 밖에서 미리 계산해 상수로 박아둡니다(7장에서 컴파일러가 이 테이블을
    NPU 메모리에 로드하는 절차를 다룹니다). -/
def ExpLUT := List (Int × Nat)

/-- x보다 큰 첫 구간 경계를 찾아 그 근사값을 반환 — 가장 단순한 형태의
    구간별 상수 근사(piecewise-constant approximation)입니다. -/
def approxExp (lut : ExpLUT) (x : Int) : Nat :=
  match lut.find? (fun p => x ≤ p.1) with
  | some (_, v) => v
  | none => (lut.getLast?.map Prod.snd).getD 0  -- 표 밖으로 넘치면 마지막 값으로 포화

end Nand2Npu.Transformer
----

[NOTE]
====
구간별 상수 근사(계단 함수)는 이 시리즈에서 가장 거친 근사입니다 — 실전에서는 구간 안에서 선형 보간(piecewise-linear)을 섞어 오차를 줄이지만, 이 장에서는 회로를 최대한 단순하게(비교기와 작은 메모리뿐) 유지하려고 계단 함수를 택합니다. 3권 4장에서 "정확성보다 근사 품질"을 물어야 한다고 짚었던 원칙이 여기서 다시 적용됩니다 — `approxExp`가 참값과 정확히 얼마나 다른지 정량화하는 건 LUT의 구간을 얼마나 촘촘히 잡느냐에 달린 설계 파라미터이고, 이 장에서는 고정하지 않습니다.
====

== 3. 정말 필요한 성질: 단조성

softmax의 최종 목표는 "확률 분포를 만든다"보다 훨씬 약한 것으로 충분할 때가 많습니다 — 트랜스포머가 실제로 쓰는 건 "어느 토큰에 더 많은 가중치를 주는가"라는 **순서**입니다. `approxExp`가 정확한 지수함수 값을 못 맞혀도, **원래 큰 점수가 여전히 더 큰 근사값을 받기만 하면** 어텐션이 "누구를 더 많이 볼지" 잘못 판단하지 않습니다.

[source,lean]
----
namespace Nand2Npu.Transformer

/-- LUT가 단조(구간 경계도, 근사값도 둘 다 오름차순)라는 조건. -/
def ExpLUT.Monotonic (lut : ExpLUT) : Prop :=
  ∀ i j, i < j → (h1 : i < lut.length) → (h2 : j < lut.length) →
    (lut[i]'h1).1 < (lut[j]'h2).1 → (lut[i]'h1).2 ≤ (lut[j]'h2).2

/-- LUT가 단조이면, 더 큰 점수는 근사 exp 값도 작지 않습니다 — 3권 7장의
    action_order_preserved와 같은 계열의 "순서 보존" 정리입니다. -/
theorem approxExp_monotonic (lut : ExpLUT) (hmono : lut.Monotonic) (x y : Int) (hxy : x ≤ y) :
    approxExp lut x ≤ approxExp lut y := by
  sorry  -- approxExp가 lut.find?로 "x 이상인 첫 구간"을 찾는다는 정의를 펼쳐,
         -- x ≤ y이면 y가 찾는 구간이 x가 찾는 구간보다 앞서지 않는다는 것을
         -- List.find?의 동작에 대한 귀납으로 보이는 자리 — 연습 문제로 남깁니다.

end Nand2Npu.Transformer
----

`approxExp_monotonic`이 이 장의 핵심 정리입니다 — 3권 7장에서 "양자화 오차가 행동 선택 순서를 뒤집지 않는다"를 증명했던 것과 정확히 같은 발상을, 이번엔 "점수 근사가 어텐션 가중치 순서를 뒤집지 않는다"는 형태로 다시 씁니다. 오차의 절대적인 크기를 걱정하는 대신, "순서가 유지되는가"라는 훨씬 다루기 쉬운 질문으로 바꿔치기하는 것 — 이게 3권부터 이 시리즈가 반복해온 전략입니다.

== 4. softmax 조립: 근사 exp의 합으로 나누기

[source,lean]
----
namespace Nand2Npu.Transformer

/-- 한 행(토큰 i가 다른 모든 토큰을 보는 점수들)에 대한 근사 softmax —
    분자는 approxExp, 분모는 그 합. 나눗셈은 1장과 같은 이유로 고정소수점 곱셈으로
    근사합니다(실제 구현은 연습 문제). -/
def approxSoftmaxNumerators (lut : ExpLUT) {n : Nat} (scores : Fin n → Int) : Fin n → Nat :=
  fun i => approxExp lut (scores i)

def approxSoftmaxDenom (lut : ExpLUT) {n : Nat} (scores : Fin n → Int) : Nat :=
  ((List.finRange n).map (fun i => approxExp lut (scores i))).sum

end Nand2Npu.Transformer
----

이 정의를 3권 4장 스타일로 32비트 누산 뒤 INT8로 재양자화하는 것이 실제 NPU 파이프라인이고, 어텐션 가중치(`numerator / denom`)를 밸류 `V`에 곱하는 마지막 단계는 다시 1장의 `matmul`입니다 — softmax 자체(2~4절)만 이 장에서 새로 다룬 조각이고, 그 앞뒤는 전부 이미 검증된 부품의 재사용입니다.

== 6. Verilator로 단조성 실측

[source,cpp]
----
// sim/tb_approx_exp.cpp
#include "Vapprox_exp.h"
#include "verilated.h"
#include <cstdio>

int main(int argc, char** argv) {
    Verilated::commandArgs(argc, argv);
    auto* dut = new Vapprox_exp;

    // 오름차순으로 나열된 입력 10개를 넣고, 출력도 오름차순(또는 같음)인지 확인.
    int inputs[10] = {-40, -30, -20, -10, 0, 10, 20, 30, 40, 50};
    int prev = -1;
    int failures = 0;
    for (int x : inputs) {
        dut->x = x;
        dut->eval();
        if (dut->result < prev) {
            std::printf("FAIL: monotonicity broken at x=%d (result=%d < prev=%d)\n", x, dut->result, prev);
            ++failures;
        }
        prev = dut->result;
    }
    delete dut;
    if (failures) { std::printf("%d FAILURES\n", failures); return 1; }
    std::printf("APPROX EXP MONOTONIC OVER 10 SAMPLES\n");
    return 0;
}
----

[TIP]
====
*확인*: `APPROX EXP MONOTONIC OVER 10 SAMPLES`가 나와야 합니다. 이 테스트가 실제로 검증하는 건 "이 LUT가 `approxExp_monotonic`의 전제(`Monotonic`)를 만족하는가"입니다 — 전제 자체가 깨지면(LUT를 잘못 채워 넣으면) 정리는 아무것도 보장해주지 않으니, LUT를 바꿀 때마다 이 테스트를 다시 돌리는 게 중요합니다.
====

== 이 장에서 확정한 것

* `exp`를 정확히 계산하는 대신 구간별 상수 룩업 테이블로 근사했습니다 — 회로는 비교기 사슬과 작은 ROM뿐입니다.
* "정확한 확률"이 아니라 "순서 보존"이 진짜 필요한 성질이라는 것을 짚고, `approxExp_monotonic`으로 LUT가 단조이기만 하면 점수 순서가 뒤집히지 않는다는 걸 증명했습니다 — 3권 7장의 `action_order_preserved`와 같은 전략입니다.
* softmax 분자·분모를 조립하고, 그 앞뒤(Q·Kᵀ 계산, 밸류 가중합)는 전부 1장에서 이미 검증한 `matmul`의 재사용이라는 것을 확인했습니다.
