== 1. 왜 마리오로 바로 가지 않는가

5장에서 `matmul` 하나가 게이트부터 양자화된 행렬 곱셈까지 끊기지 않고 이어지는 것을 확인했습니다. 그런데 마리오 정책망(7장)은 게임 화면(이미지)을 입력으로 받는 CNN(합성곱 신경망)입니다 — `matmul`만으로는 안 되고, *컨볼루션*(가중치를 이미지 위에서 슬라이딩하며 곱하고 더하는 연산)과 *풀링*(이미지를 축소하는 연산)이 추가로 필요합니다. 이 둘을 처음부터 정책망 위에서 디버깅하면 "이미지 처리 자체의 버그"와 "정책 결정의 버그"가 뒤섞여 원인을 찾기 어렵습니다. 그래서 이 장에서는 훨씬 작고 검증하기 쉬운 문제 — `8×8` 흑백 이미지가 "X"인지 "O"인지 분류하는 최소 CNN — 으로 컨볼루션·풀링·NPU 파이프라인 전체를 먼저 다집니다.

== 2. 컨볼루션을 matmul로 재사용하기: im2col

새 하드웨어를 만들지 않고 2장의 시스톨릭 어레이를 그대로 재사용하는 표준적인 방법이 *im2col*(image-to-column)입니다 — 컨볼루션 윈도우가 지나가는 각 위치의 이미지 패치를 행렬의 한 열로 펼쳐놓으면, 컨볼루션 전체가 "펼쳐진 이미지 행렬"과 "펼쳐진 커널 행렬"의 `matmul` 하나로 바뀝니다.

[source,lean]
----
-- Npu/Im2col.lean
import Npu.Quant

namespace Nand2Npu.Npu

/-- k×k 커널이 stride 1로 슬라이딩할 때, (h,w) 이미지에서 나오는 패치 개수. -/
def outDim (imgDim kernelDim : Nat) : Nat := imgDim - kernelDim + 1

/-- 이미지의 (row, col)에서 시작하는 k×k 패치를 한 줄로 펼칩니다. -/
def extractPatch (img : Fin h → Fin w → Int8) (k : Nat) (row col : Nat)
    (hrow : row + k ≤ h) (hcol : col + k ≤ w) : List Int8 :=
  (List.range k).flatMap (fun dr =>
    (List.range k).map (fun dc =>
      img ⟨row + dr, by omega⟩ ⟨col + dc, by omega⟩))

/-- 이미지 전체를 im2col 행렬로 펼칩니다 — 각 행이 패치 하나. -/
def im2col (img : Fin h → Fin w → Int8) (k : Nat) : List (List Int8) :=
  (List.range (outDim h k)).flatMap (fun row =>
    (List.range (outDim w k)).map (fun col =>
      if hr : row + k ≤ h then
        if hc : col + k ≤ w then extractPatch img k row col hr hc
        else []
      else []))

end Nand2Npu.Npu
----

`im2col`이 하는 일은 순수하게 데이터 재배열입니다 — 새 곱셈이나 덧셈이 없으므로, 이 함수의 "정확성"은 "컨볼루션의 수학적 정의와 펼친 뒤의 `matmul` 결과가 같다"는 정리로 표현됩니다.

[source,lean]
----
namespace Nand2Npu.Npu

/-- 컨볼루션의 수학적 정의: 커널을 이미지 위에서 슬라이딩하며 원소별 곱의 합. -/
def convSpec (img : Fin h → Fin w → Int) (kernel : Fin k → Fin k → Int)
    (row col : Nat) (hrow : row + k ≤ h) (hcol : col + k ≤ w) : Int :=
  ((List.finRange k).flatMap (fun dr =>
    (List.finRange k).map (fun dc =>
      img ⟨row + dr.val, by omega⟩ ⟨col + dc.val, by omega⟩ * kernel dr dc))).sum

/-- im2col로 펼친 패치와 커널을 각각 벡터로 보고 내적한 것이 convSpec과 같습니다.
    (증명은 extractPatch와 convSpec이 같은 순서로 원소를 나열한다는 것을 확인하는
    List.flatMap/List.sum 재정렬이라 연습 문제로 남깁니다.) -/
theorem im2col_matches_conv (img : Fin h → Fin w → Int8) (kernel : Fin k → Fin k → Int8)
    (row col : Nat) (hrow : row + k ≤ h) (hcol : col + k ≤ w) :
    (List.zip (extractPatch img k row col hrow hcol)
              ((List.finRange k).flatMap (fun dr => (List.finRange k).map (fun dc => kernel dr dc))))
      |>.map (fun (p, w) => p.toInt * w.toInt) |>.sum
    = convSpec (fun i j => (img i j).toInt) (fun i j => (kernel i j).toInt) row col hrow hcol := by
  sorry  -- extractPatch/convSpec이 같은 (dr, dc) 순서로 원소를 나열함을 보이는 재정렬 — 연습 문제

end Nand2Npu.Npu
----

[NOTE]
====
`im2col_matches_conv`를 `sorry`로 남긴 이유 — 이 정리는 새로운 산술적 통찰이 없는, 순수하게 "두 개의 서로 다른 순회 순서가 같은 다중집합을 만든다"는 조합적 사실입니다. 3장(1권)에서 반복했던 리스트 귀납 기법을 `List.flatMap`의 결합 법칙에 적용하는 정도의 작업이라, 지면에서는 결론만 밝히고 연습 문제로 남깁니다.
====

== 3. 맥스 풀링: 비교와 선택의 조합

풀링은 `2×2` 블록에서 최댓값 하나만 남겨 이미지를 절반으로 줄입니다. 4장에서 만든 `Int8` 비교 연산자만 있으면 됩니다.

[source,lean]
----
-- Npu/Pool.lean
import Npu.Quant

namespace Nand2Npu.Npu

def Int8.max (a b : Int8) : Int8 := if a.toInt ≥ b.toInt then a else b

/-- 2×2 맥스 풀링: 네 값 중 최댓값. -/
def maxPool2x2 (a b c d : Int8) : Int8 := Int8.max (Int8.max a b) (Int8.max c d)

theorem maxPool2x2_ge_all (a b c d : Int8) :
    (maxPool2x2 a b c d).toInt ≥ a.toInt ∧ (maxPool2x2 a b c d).toInt ≥ b.toInt ∧
    (maxPool2x2 a b c d).toInt ≥ c.toInt ∧ (maxPool2x2 a b c d).toInt ≥ d.toInt := by
  unfold maxPool2x2 Int8.max
  split_ifs <;> omega

end Nand2Npu.Npu
----

`maxPool2x2_ge_all`은 "풀링 결과가 네 입력 모두보다 작지 않다"는, 맥스 풀링이 이름값을 한다는 것에 대한 가장 기본적인 확인입니다 — 증명 자체는 `split_ifs`(조건 분기를 전부 펼침) 다음 `omega`로 끝나는, 3장에서 반복한 비교-분기 패턴의 재사용입니다.

== 4. depthwise separable convolution: 왜 컨볼루션을 쪼개는가

지금까지의 `conv2d`는 입력 채널 `Cin`개와 출력 채널 `Cout`개 사이를 *전부* 연결하는 "표준 컨볼루션"입니다 — 출력 채널 하나마다 입력 채널 `Cin`개 전부를 각각 `k×k` 커널로 훑어야 하므로, 출력 위치 하나당 MAC 연산이 `k²·Cin·Cout`번 필요합니다. 7장의 마리오 정책망처럼 채널 수가 늘어나기 시작하면(첫 컨볼루션이 16채널을 출력하고, 다음 컨볼루션이 그 16채널을 받아 32채널을 출력하는 식) 이 `Cin·Cout` 곱이 빠르게 커집니다. MobileNet이 대중화한 *depthwise separable convolution*은 이 하나의 컨볼루션을 두 단계로 쪼개 이 곱을 합으로 바꿉니다.

1. *depthwise 컨볼루션*: 채널마다 **독립적으로** `k×k` 커널 하나씩 적용합니다 — 채널을 섞지 않으므로 출력도 `Cin`채널이고, MAC 수는 `k²·Cin`(채널마다 한 번씩, `Cout` 곱이 없음)입니다.
2. *pointwise 컨볼루션*: `1×1` 커널로 채널만 섞어 `Cin`채널을 `Cout`채널로 바꿉니다 — 공간 방향으로는 아무것도 훑지 않으므로 사실상 5장의 `matmul`이고, MAC 수는 `Cin·Cout`(`k²`이 없음)입니다.

[source,lean]
----
-- Npu/Depthwise.lean
import Npu.Im2col

namespace Nand2Npu.Npu

/-- 표준 컨볼루션 한 출력 위치당 MAC 수: 채널마다, 커널 안의 모든 위치마다,
    출력 채널마다 한 번씩. -/
def standardConvMacs (k Cin Cout : Nat) : Nat := k * k * Cin * Cout

/-- depthwise(채널별 독립 k×k) + pointwise(1×1로 채널만 섞음) MAC 수의 합. -/
def depthwiseSeparableMacs (k Cin Cout : Nat) : Nat := k * k * Cin + Cin * Cout

/-- depthwise separable 방식은 표준 컨볼루션보다 MAC 수가 많지 않습니다 —
    커널이 2×2보다 크고(k ≥ 2) 출력 채널이 2개 이상(Cout ≥ 2)이면 항상 성립합니다.
    (이 두 조건이 실전에서 항상 성립하는 흔한 설정이라는 것 자체가, 이 기법이
    널리 쓰이는 이유입니다.) -/
theorem depthwise_separable_reduces_macs (k Cin Cout : Nat) (hk : k ≥ 2) (hCout : Cout ≥ 2) :
    depthwiseSeparableMacs k Cin Cout ≤ standardConvMacs k Cin Cout := by
  unfold depthwiseSeparableMacs standardConvMacs
  have hkk : k * k ≥ 4 := by nlinarith
  have key : k * k + Cout ≤ k * k * Cout := by nlinarith
  calc k * k * Cin + Cin * Cout
      = Cin * (k * k + Cout) := by ring
    _ ≤ Cin * (k * k * Cout) := by exact Nat.mul_le_mul_left Cin key
    _ = k * k * Cin * Cout := by ring

end Nand2Npu.Npu
----

`depthwise_separable_reduces_macs`의 증명은 결국 초등 부등식 하나(`a + b ≤ a * b`, `a, b ≥ 2`일 때)로 환원됩니다 — `key`가 바로 그 부등식이고, `nlinarith`(비선형 산술을 다루는 자동화 전술)가 `(a-1)(b-1) ≥ 1`이라는 관찰을 자동으로 찾아 닫아줍니다. 구체적인 수치로 감을 잡아보면, `k=5`(5×5 커널), `Cin=16`, `Cout=32`일 때 표준 컨볼루션은 `5²·16·32 = 12800`MAC, depthwise separable은 `5²·16 + 16·32 = 400 + 512 = 912`MAC — 약 14배 적습니다. 이 차이가 정확히 MobileNet이 실전에서 값어치를 하는 지점입니다.

[source,lean]
----
-- Compiler/Ast.lean에 추가 (위 2~3절의 conv2d/maxPool과 같은 자리)
namespace Nand2Npu.Compiler

inductive Expr where
  | intLit (n : Nat)
  | varRef (name : String)
  | binOp (op : BinOp) (l r : Expr)
  | call (name : String) (args : List Expr)
  | matrixLit (rows : List (List Expr))
  | matmul (a b : Expr)
  | conv2d (img kernel : Expr)
  | maxPool (m : Expr)
  | depthwiseConv2d (img kernel : Expr)   -- 새로 추가: 채널별 독립 k×k (im2col을 채널마다 따로 적용)
  | pointwiseConv (img weights : Expr)     -- 새로 추가: 1×1 컨볼루션 — 사실상 matmul과 동일
  deriving Repr

end Nand2Npu.Compiler
----

[NOTE]
====
`depthwiseConv2d`의 코드 생성은 2절의 `im2col`을 채널마다 독립적으로(채널을 섞지 않고) 반복 호출하는 것이고, `pointwiseConv`는 커널 크기가 `1×1`인 특수 케이스라 사실상 5장의 `matmul` 호출 시퀀스를 그대로 재사용합니다 — 새로운 회로나 새로운 NPU 명령어가 필요 없다는 것 자체가 이 기법의 또 다른 장점입니다(2장의 시스톨릭 어레이와 3장의 `Npu.setA`/`start`/`getC`만으로 충분합니다). 두 코드 생성 갈래 모두 위 `conv2d`(2절)와 5장의 `matmul` 패턴을 채널 루프 하나로 감싸는 정도의 반복 작업이라, 지면에서는 생략하고 연습 문제로 남깁니다.
====

== 6. 8×8 X/O 분류기 전체 조립

`8×8` 흑백 이미지(X 또는 O 모양), `3×3` 커널 하나로 컨볼루션(출력 `6×6`), `2×2` 맥스 풀링(출력 `3×3`), 마지막으로 `3×3=9`개 값을 1×2 출력(X 점수, O 점수)으로 낮추는 `matmul` 하나 — 이게 이 장의 최소 CNN입니다.

[source,text]
----
입력(8×8, Int8) → im2col + matmul(커널 3×3) → 컨볼루션 결과(6×6)
  → 2×2 맥스 풀링 → 풀링 결과(3×3)
  → flatten(9개 값) → matmul(9×2 가중치) → 출력(X 점수, O 점수)
----

[source,lean]
----
-- Compiler/Ast.lean에 추가 (5장의 matmul 확장과 같은 자리)
namespace Nand2Npu.Compiler

inductive Expr where
  | intLit (n : Nat)
  | varRef (name : String)
  | binOp (op : BinOp) (l r : Expr)
  | call (name : String) (args : List Expr)
  | matrixLit (rows : List (List Expr))
  | matmul (a b : Expr)
  | conv2d (img kernel : Expr)     -- 새로 추가: im2col + matmul로 낮춤
  | maxPool (m : Expr)              -- 새로 추가: 2×2 블록마다 maxPool2x2 호출로 낮춤
  deriving Repr

end Nand2Npu.Compiler
----

`conv2d`와 `maxPool`을 코드 생성기(`compileExpr`)에 추가하는 방식은 5장의 `matmul` 갈래와 동일한 패턴입니다 — `conv2d`는 `im2col`로 펼친 뒤 5장의 `matmul` 호출 시퀀스를 그대로 재사용하고, `maxPool`은 `Npu.setA`/`Npu.getC` 대신 새 명령어 `Npu.maxPool4`(4개 값을 받아 `maxPool2x2` 회로를 트리거) 하나만 추가하면 됩니다. 반복적인 코드 생성 로직이라 지면에서는 생략하고 연습 문제로 남깁니다.

[NOTE]
====
가중치(3×3 커널, 9×2 최종 레이어)는 이 장에서 훈련하지 않습니다 — X/O 각각 4~5개씩의 손으로 만든 예시로 미리 계산해둔 고정 가중치를 그대로 사용합니다. 이 장의 목표는 "이 특정 가중치로 정확히 추론하는가"이지 "가중치를 어떻게 찾는가"가 아니고, 이 경계는 서문에서 이미 밝힌 이 2권 전체의 원칙과 같습니다.
====

====
*확인*: `X_IMAGE`에서는 X 점수가, `O_IMAGE`에서는 O 점수가 더 높게 나와야 합니다. 테스트벤치의 실행·점수 추출 부분을 5장 4절의 `tb_cpu_npu.cpp` 절차를 참고해 직접 채우는 것이 이 장의 마지막 연습 문제입니다 — `im2col`이 만드는 패치 순서와 커널을 펼친 순서가 어긋나면(2절에서 `sorry`로 남긴 지점과 정확히 같은 위험) 컨볼루션 결과 전체가 조용히 틀어지니, 먼저 손으로 계산한 `6×6` 컨볼루션 결과와 시뮬레이션 중간값을 대조하는 것이 가장 빠른 디버깅 경로입니다.
====

== 이 장에서 확정한 것

* im2col로 컨볼루션을 `matmul`(2장의 시스톨릭 어레이)로 환원하는 표준 기법을 구현하고, "펼친 뒤의 내적이 컨볼루션 정의와 같다"는 정리(`im2col_matches_conv`, 재정렬 증명은 연습 문제)로 그 환원이 옳음을 명시했습니다.
* 맥스 풀링을 4장의 비교-멀티플렉서 패턴으로 구현하고, `maxPool2x2_ge_all`로 "결과가 입력 모두보다 작지 않다"는 최소한의 정당성을 증명했습니다.
* Mini 언어에 `conv2d`/`maxPool` 표현식을 추가해, `8×8` 이미지를 분류하는 최소 CNN 전체를 컴파일러→NPU 명령어 경로로 연결했습니다.
* 고정된(훈련되지 않은, 손으로 만든) 가중치로 X/O 두 이미지를 정확히 구분하는 것을 시뮬레이션 절차의 뼈대로 확인했습니다 — 실행·점수 추출 세부는 연습 문제로 남겼습니다.
* depthwise separable convolution(채널별 독립 `k×k` + 채널을 섞는 `1×1`)을 도입하고, 새 회로 없이 기존 시스톨릭 어레이·`matmul` 경로만으로 구현 가능함을 확인했습니다. `depthwise_separable_reduces_macs`로 MAC 수가 표준 컨볼루션보다 항상 적음(`k≥2, Cout≥2`일 때)을 증명했습니다.

다음 장에서는 이 파이프라인을 훨씬 큰 입력(게임 화면)과 훈련된(책 밖에서 미리 학습된) 가중치로 확장해, 실제 마리오 정책망의 추론을 다룹니다 — 특히 depthwise separable convolution을 실제 다채널 정책망 구조에 적용해봅니다.
