== 문제: 같은 State+Effect 조합이 여러 컴포넌트에 반복된다

"창 너비가 얼마인지"를 알아야 하는 컴포넌트가 여러 개 있다고 해봅시다.

[source,tsx]
----
function Header() {
  const [width, setWidth] = useState(window.innerWidth);

  useEffect(() => {
    const handleResize = () => setWidth(window.innerWidth);
    window.addEventListener("resize", handleResize);
    return () => window.removeEventListener("resize", handleResize);
  }, []);

  return <p>창 너비: {width}px</p>;
}

function Sidebar() {
  const [width, setWidth] = useState(window.innerWidth); // 완전히 같은 로직 반복

  useEffect(() => {
    const handleResize = () => setWidth(window.innerWidth);
    window.addEventListener("resize", handleResize);
    return () => window.removeEventListener("resize", handleResize);
  }, []);

  return <p>사이드바 (너비: {width})</p>;
}
----

`useState`와 `useEffect` 조합이 토씨 하나 안 틀리고 반복됩니다. 7장에서 배운 대로라면 "반복되는 로직은 함수로 뽑아낸다"가 상식적인 해법인데, 여기서는 그게 그렇게 간단하지 않습니다 — **이 로직 안에 `useState`, `useEffect`라는 훅이 들어있기 때문**입니다.

== 왜 이름이 `use`로 시작해야 하는가

[source,tsx]
----
function getWindowWidth() {
  const [width, setWidth] = useState(window.innerWidth);
  useEffect(() => {
    const handleResize = () => setWidth(window.innerWidth);
    window.addEventListener("resize", handleResize);
    return () => window.removeEventListener("resize", handleResize);
  }, []);
  return width;
}
----

이 함수 자체는 사실 지금 당장 컴포넌트 안에서 평범하게 호출하면 별문제 없이 동작합니다 — 이름이 `use`로 시작하지 않는다고 React가 실행을 막는 건 아닙니다. 문제는 **당장이 아니라 나중**에 생깁니다. 8장에서 `useState`가 렌더링 사이에도 값을 기억한다고 했는데, 그 기억이 정확히 "몇 번째 훅 호출인가"라는 **순서**로 관리됩니다. 이 함수를 나중에 실수로 조건문 안에서(`if (조건) { getWindowWidth(); }`)나 반복문 안에서 부르면, 렌더링마다 훅이 호출되는 횟수나 순서가 달라져 `Invalid hook call` 같은 런타임 에러로 이어집니다 — **당장 눈에 보이는 버그가 아니라, 나중에 코드를 조금만 바꿔도 터질 수 있는 잠재적 위험**이라는 게 핵심입니다.

React 자신은 함수 이름을 실행 시점에 검사하지 않습니다 — 대신 Vite 템플릿에 이미 포함된 ESLint 플러그인(`eslint-plugin-react-hooks`)이 **`use`로 시작하는 함수만** "이 안에서 조건문·반복문 안에 훅을 두면 안 된다"는 규칙으로 검사해줍니다. 즉 `getWindowWidth`라는 이름 그대로 두면, 나중에 이 함수를 조건문 안에서 잘못 불러도 아무도 경고해주지 않습니다 — `useWindowWidth`로 이름을 바꾸는 순간부터, 린트 도구가 이 함수를 훅 규칙 검사 대상으로 인식하고 실수를 미리 잡아줍니다. `use` 접두사는 실행을 바꾸는 문법이 아니라, **도구에게 "이 함수는 훅 규칙을 지켜야 한다"고 알려주는 신호**입니다.

== 커스텀 훅: 이름이 `use`로 시작하는, 규칙을 지키는 함수

[source,tsx]
----
function useWindowWidth() {
  const [width, setWidth] = useState(window.innerWidth);

  useEffect(() => {
    const handleResize = () => setWidth(window.innerWidth);
    window.addEventListener("resize", handleResize);
    return () => window.removeEventListener("resize", handleResize);
  }, []);

  return width;
}

function Header() {
  const width = useWindowWidth();
  return <p>창 너비: {width}px</p>;
}

function Sidebar() {
  const width = useWindowWidth();
  return <p>사이드바 (너비: {width})</p>;
}
----

`useWindowWidth`가 하는 일은 방금 "안 되는 예제"와 코드상 거의 똑같습니다 — 차이는 딱 하나, **이름이 `use`로 시작한다는 것**입니다. 이게 장난처럼 보이지만 실제로 의미가 있습니다 — React의 훅 규칙 검사 도구(Vite 템플릿에 이미 포함된 ESLint 플러그인)가 "`use`로 시작하는 함수는 그 안에서 다른 훅을 불러도 되고, 그 규칙(항상 같은 순서로, 컴포넌트나 다른 커스텀 훅의 최상위에서만 호출)을 지키는지 검사해준다"는 뜻입니다. 즉 `use` 접두사는 사람에게 주는 이름표이면서 동시에, 도구가 "이 함수는 훅 규칙을 지켜야 하는 특별한 함수다"라고 알아보는 신호이기도 합니다.

== 커스텀 훅이 진짜로 하는 일: State+Effect 조합의 재사용

커스텀 훅은 새로운 종류의 기능이 아닙니다 — **`useState`, `useEffect` 같은 기본 훅들을 조합해서, 그 조합에 이름을 붙인 것**뿐입니다. `useWindowWidth`를 부르는 두 컴포넌트는 각자 독립된 `width` State를 갖습니다(8장에서 State가 컴포넌트마다 독립적이라고 했던 것과 같은 원리로, 커스텀 훅을 부를 때마다 그 안의 `useState`도 각자 새로 만들어집니다) — `Header`의 창 너비와 `Sidebar`의 창 너비가 서로 영향을 주지 않는다는 뜻입니다. 재사용되는 건 **값이 아니라 로직**입니다.

== 직접 해보기

* `useToggle(initial: boolean)`을 만들어, `[value, toggle]`을 반환하고(`toggle`을 부르면 `value`가 반전됨) 두 컴포넌트에서 각각 독립적으로 써보세요.
* `useLocalStorage(key: string, initialValue: string)`을 만들어, `localStorage`에서 값을 읽어와 초기값으로 쓰고 값이 바뀔 때마다(`useEffect`로) 다시 저장하는 훅을 작성해보세요.

.해답 보기
[%collapsible]
====
[source,tsx]
----
function useToggle(initial: boolean): [boolean, () => void] {
  const [value, setValue] = useState(initial);
  const toggle = () => setValue((v) => !v);
  return [value, toggle];
}

function useLocalStorage(key: string, initialValue: string) {
  const [value, setValue] = useState(() => localStorage.getItem(key) ?? initialValue);

  useEffect(() => {
    localStorage.setItem(key, value);
  }, [key, value]);

  return [value, setValue] as const;
}
----
====

2부는 여기서 마칩니다. React의 핵심(컴포넌트, Props, State, 렌더링, 부수효과, 리스트, 로직 재사용)을 다뤘습니다. 3부에서는 1부(TypeScript)와 2부(React)를 실제로 합쳐, 지금까지 느슨하게 써온 타입들을 제대로 갖춥니다.

== 요약

* State+Effect 조합을 평범한 함수로 뽑아내면, 그 함수가 컴포넌트 밖에서 호출될 수 있어 "훅은 항상 같은 순서로 호출된다"는 React의 전제가 깨집니다.
* 이름을 `use`로 시작하면 이 함수가 "훅 규칙을 지켜야 하는 특별한 함수"라는 걸 사람과 린트 도구 양쪽에 알릴 수 있습니다.
* 커스텀 훅은 새 기능이 아니라 기본 훅들의 조합에 이름을 붙인 것이고, 그 훅을 쓰는 컴포넌트마다 독립된 State를 갖습니다 — 재사용되는 건 값이 아니라 로직입니다.
