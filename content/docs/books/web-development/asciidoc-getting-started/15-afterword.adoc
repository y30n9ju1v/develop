== 지나온 길

1부에서는 AsciiDoc의 가장 기본이 되는 문법 — 제목의 레벨, 문단이 나뉘는 규칙, 굵게·기울임 같은 인라인 강조, 순서 있는/없는/설명 목록 — 을 다졌습니다. Markdown과 닮았지만 굵게가 별표 하나라는 것, 그리고 constrained/unconstrained라는 두 가지 강조 형식이 있다는 것이 눈여겨볼 차이였습니다.

2부에서는 문서를 구조화하는 법을 봤습니다. 문서 속성으로 목차와 섹션 번호를 자동 생성하는 법, 예제·사이드바·열린 블록으로 여러 요소를 하나의 단위로 묶는 법, 표 안에 서식과 다른 블록을 넣는 법, 이미지와 다양한 형태의 링크, 그리고 다섯 가지 admonition과 인용문까지 — AsciiDoc이 Markdown보다 "긴 문서"에 유리한 이유가 이 부에서 하나씩 드러났습니다.

3부는 이 책에서 가장 중요한 부였습니다. 소스 코드의 일부만 태그로 뽑아 쓰는 법, 그리고 그 태그 문법을 AsciiDoc 문서 자체에 적용해 여러 장을 하나의 전체 목차로 조립하는 include 패턴 — 이게 바로 이 사이트의 모든 책이 실제로 쓰고 있는 방식이라는 걸 확인했습니다. 속성과 변수, 조건부 포함(`ifdef`/`ifndef`/`ifeval`)까지 더해지면, 하나의 소스로 여러 버전의 문서를 관리하는 것도 가능해집니다.

4부에서는 실제로 `asciidoctor`와 `asciidoctor-pdf`로 문서를 HTML과 PDF로 변환해봤고, Hugo 같은 정적 사이트 생성기가 `.adoc` 파일을 어떻게 자동으로 처리하는지 확인한 뒤, 배운 모든 문법을 종합해 작은 문서 하나를 처음부터 끝까지 직접 설계·조립했습니다.

== 이 책이 다루지 않은 것

이 책은 "AsciiDoc으로 문서를 쓰고 조립하는 법"에 집중했고, 의도적으로 남겨둔 것들이 있습니다 — 수식을 표현하는 STEM(LaTeX 수식) 지원, PlantUML/Mermaid 같은 다이어그램 확장, 각주와 참고문헌 관리, 커스텀 Asciidoctor 확장 작성(자신만의 매크로나 블록 처리기를 Ruby로 짜는 것), 그리고 DocBook 같은 다른 출력 포맷입니다. 이들은 대부분 Asciidoctor 공식 문서에 잘 정리돼 있고, 이 책에서 다진 include·태그·속성 개념 위에서 자연스럽게 확장해서 배울 수 있는 것들입니다.

== 다음으로

가장 좋은 다음 단계는 짧은 문서 하나(회의록, 프로젝트 README, 개인 노트 모음)를 AsciiDoc으로 직접 써보는 것입니다 — 이 책에서 배운 제목·목록·표·admonition·코드 블록·태그와 include 패턴을 실제 글에 적용해보면서 손에 익히는 것이 가장 빠른 길입니다.

문법을 안다는 것과, 그 문법으로 실제로 읽기 좋은 문서를 설계할 수 있다는 것은 다른 종류의 능력입니다. 이 책이 전자를 다졌다면, 후자는 여러분이 직접 써나가면서 쌓는 몫입니다.
