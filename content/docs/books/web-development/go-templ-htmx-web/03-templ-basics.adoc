1~2장에서는 `fmt.Fprintf`로 HTML 문자열을 직접 조립했습니다. 이 방식은 태그 두 개짜리 예제에서는 괜찮지만, 화면이 복잡해지면 두 가지 문제가 생깁니다 — 태그를 닫는 걸 깜빡하기 쉽고, 사용자 입력을 이스케이프하지 않으면 XSS(크로스사이트 스크립팅) 취약점이 생깁니다. **templ**은 HTML과 비슷한 문법으로 컴포넌트를 작성하면, 이를 진짜 Go 함수로 컴파일해주는 도구입니다.

== templ 설치하고 첫 컴포넌트 만들기

templ CLI를 설치하고, `.templ` 확장자의 파일에 컴포넌트를 작성합니다.

[source,bash]
----
go install github.com/a-h/templ/cmd/templ@latest
----

[source,templ]
----
package main

templ Hello(name string) {
	<h1>Hello, { name }!</h1>
}
----

`templ`이라는 키워드로 시작하는 블록이 컴포넌트입니다 — `Hello(name string)`처럼 일반 Go 함수처럼 매개변수를 받고, `{ name }` 구문으로 Go 표현식을 HTML 안에 끼워 넣습니다.

== templ generate: .templ을 진짜 Go 코드로

`templ generate` 명령이 `.templ` 파일을 읽어 `_templ.go`로 끝나는 진짜 Go 소스 파일을 만듭니다.

[source,bash]
----
templ generate
----

[source]
----
(✓) Complete [ updates=1 duration=1.6ms ]
----

생성된 `hello_templ.go`를 열어보면 `Hello`가 `templ.Component`를 돌려주는 평범한 Go 함수라는 걸 확인할 수 있습니다 — templ은 런타임에 템플릿을 해석하는 게 아니라, **빌드 시점에 Go 코드로 미리 변환**합니다. 이게 이 장 전체의 핵심입니다.

== 핸들러에서 컴포넌트 렌더링하기

생성된 `Hello` 함수는 `.Render(ctx, writer)` 메서드로 `http.ResponseWriter`에 직접 씁니다.

[source,go]
----
package main

import (
	"context"
	"net/http"
)

func helloHandler(w http.ResponseWriter, r *http.Request) {
	name := r.URL.Query().Get("name")
	if name == "" {
		name = "손님"
	}
	Hello(name).Render(context.Background(), w)
}

func main() {
	mux := http.NewServeMux()
	mux.HandleFunc("GET /hello", helloHandler)
	http.ListenAndServe(":8080", mux)
}
----

[source,bash]
----
curl "http://localhost:8080/hello?name=World"
----

[source]
----
<h1>Hello, World!</h1>
----

1장의 결과와 똑같아 보이지만, 이번엔 문자열을 직접 조립하지 않고 타입이 있는 `Hello(name string)` 함수를 호출했습니다.

== 자동 이스케이프: XSS를 기본으로 막는다

`{ name }`처럼 중괄호로 끼워 넣은 값은 templ이 자동으로 HTML 이스케이프를 합니다. 악의적인 입력을 그대로 넣어봅니다.

[source,bash]
----
curl "http://localhost:8080/hello?name=%3Cscript%3Ealert(1)%3C%2Fscript%3E"
----

[source]
----
<h1>Hello, &lt;script&gt;alert(1)&lt;/script&gt;!</h1>
----

`<script>alert(1)</script>`라는 입력이 `&lt;script&gt;alert(1)&lt;/script&gt;`로 이스케이프되어, 브라우저가 이걸 실행 가능한 스크립트가 아니라 그냥 텍스트로 표시합니다. 1~2장에서 `fmt.Fprintf`로 문자열을 직접 조립했다면 이 이스케이프를 매번 직접 챙겨야 했을 것이고, 깜빡하면 그대로 XSS 취약점이 됩니다 — templ에서는 `{ }` 구문을 쓰는 한 이 방어가 기본값입니다.

== 컴파일 타임 타입 검사: 잘못된 타입은 빌드가 막는다

`Hello`는 `string`을 받는 평범한 Go 함수로 컴파일됐으니, 잘못된 타입을 넘기면 `go build` 자체가 실패합니다.

[source,go]
----
func badCallExample() {
	_ = Hello(42)   // string이 아니라 int를 넘겼다
}
----

[source,bash]
----
go build ./...
----

[source]
----
./badcall.go:4:12: cannot use 42 (untyped int constant) as string value in argument to Hello
----

서버를 띄우고 요청을 보내본 뒤에야 오류를 발견하는 게 아니라, 빌드 시점에 바로 걸립니다. 화면이 수십 개의 컴포넌트로 늘어나고 여러 사람이 함께 작업할수록, 이 "틀린 인자를 넘기면 빌드가 막힌다"는 성질이 실전에서 버그를 크게 줄여줍니다 — 이 책 전체에서 컴포넌트가 점점 복잡해질 텐데, 그때마다 이 안전망이 계속 작동합니다.

== 왜 별도의 템플릿 언어가 아니라 Go 코드로 컴파일하는가

Jinja(Python)나 EJS(Node.js) 같은 전통적인 템플릿 엔진은 템플릿을 별도의 텍스트 파일로 다루고, 런타임에 해석합니다 — 템플릿 안에서 변수 이름을 잘못 쓰거나 타입을 잘못 넘겨도, 그 코드 경로가 실제로 실행되기 전까지는 알 수 없습니다. templ은 템플릿을 진짜 Go 함수로 미리 컴파일해버림으로써, Go 컴파일러가 이미 갖고 있는 타입 검사·미사용 변수 검사 같은 도구를 템플릿에도 그대로 적용받습니다. 이 장에서 확인한 두 가지(자동 이스케이프, 컴파일 타임 타입 검사)가 바로 그 이점의 핵심입니다.

== 직접 해보기

* `Hello` 컴포넌트에 두 번째 매개변수 `age int`를 추가해(`templ Hello(name string, age int) { <h1>Hello, { name }! You are { fmt.Sprint(age) } years old.</h1> }`), `templ generate`를 다시 실행한 뒤 핸들러에서 이 새 매개변수를 빠뜨리고 호출하면 어떤 컴파일 오류가 나는지 확인해보세요.

.해답 보기
[%collapsible]
====
[source,templ]
----
package main

import "fmt"

templ HelloWithAge(name string, age int) {
	<h1>Hello, { name }! You are { fmt.Sprint(age) } years old.</h1>
}
----

[source,go]
----
func helloHandler(w http.ResponseWriter, r *http.Request) {
	HelloWithAge("World").Render(context.Background(), w)   // age 인자를 빠뜨림
}
----

[source]
----
./main.go:12:2: not enough arguments in call to HelloWithAge
	have (string)
	want (string, int)
----

컴포넌트의 매개변수를 빠뜨리면(또는 개수가 안 맞으면) 일반 Go 함수 호출과 똑같은 방식으로 `go build`가 즉시 오류를 냅니다 — 템플릿 파일 안에서 매개변수를 하나 추가하는 게, 그 템플릿을 쓰는 모든 곳에서 누락된 인자를 컴파일 타임에 강제로 찾아준다는 뜻입니다.
====

== 요약

* templ은 `.templ` 파일에 HTML과 비슷한 문법으로 컴포넌트를 작성하면, `templ generate`가 이를 `templ.Component`를 돌려주는 진짜 Go 함수로 컴파일합니다.
* `{ }`로 끼워 넣은 값은 자동으로 HTML 이스케이프되어, 사용자 입력을 통한 XSS를 기본으로 방어합니다.
* 컴포넌트가 진짜 Go 함수이므로, 잘못된 타입이나 개수의 인자를 넘기면 런타임이 아니라 `go build` 시점에 오류가 발생합니다.
* 다음 장부터는 이 templ 컴포넌트를 htmx와 결합해, 페이지 전체가 아니라 화면 일부만 서버에서 다시 받아 갈아 끼우는 상호작용을 만듭니다.
