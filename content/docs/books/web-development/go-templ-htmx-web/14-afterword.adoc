== 지나온 길

1장에서는 SPA + API 구조와 하이퍼미디어 지향 구조(HDA)의 차이를, "서버가 데이터를 주는가, 화면을 주는가"라는 질문으로 나눴습니다. 2장에서 Go 1.22의 메서드/경로 라우팅과 미들웨어로 프레임워크 없이도 튼튼한 서버 기초를 다졌고, 3장에서 templ이 자동 이스케이프(XSS 방어)와 컴파일 타임 타입 검사(잘못된 인자를 `go build`가 즉시 잡아냄)라는 두 가지를 공짜로 준다는 것을 실제 코드로 확인했습니다.

4~6장에서는 htmx의 핵심을 다졌습니다 — `hx-post`/`hx-target`/`hx-swap` 세 속성만으로 자바스크립트 없이 부분 갱신을 만들었고, `hx-swap-oob`로 한 응답에서 화면의 여러 위치를 동시에 갱신했으며, `hx-target="this"`로 검증에 실패한 폼이 입력값과 에러 메시지를 채운 채로 스스로를 갱신하는 패턴을 만들었습니다.

7~9장에서는 이 조각들을 실전 규모로 키웠습니다 — `children`과 컴포넌트 합성으로 화면을 재사용 가능한 단위로 나눴고, SQLite로 데이터를 영속화했으며, `hx-trigger="keyup changed delay:300ms"`로 자바스크립트 없는 실시간 검색과 SQL `LIMIT`/`OFFSET`으로 페이지네이션을 구현했습니다.

10~12장에서는 실전 서비스에 필요한 나머지를 갖췄습니다 — `bcrypt`와 쿠키 기반 세션으로 로그인을, SSE로 서버가 주도하는 실시간 갱신을, `httptest`로 서버를 띄우지 않는 자동화된 테스트를 각각 만들었습니다. 마지막 13장에서는 이 모든 조각(레이아웃, htmx CRUD, SQLite, 세션 인증, OOB 스왑)이 하나의 TODO 앱 안에서 실제로 맞물려 동작하는 것을, 로그인부터 삭제까지 `curl`로 전체 흐름을 직접 확인하며 마무리했습니다.

== 이 책을 관통한 하나의 습관

이 책 곳곳에서 반복된 장면이 있습니다 — htmx가 브라우저에 보내는 요청이 실제로 무엇인지, 서버가 정확히 무슨 HTML을 돌려주는지를 짐작하지 않고 `curl`로 직접 찍어봤습니다(4장의 카운터, 5장의 OOB 스왑, 9장의 실시간 검색). "브라우저를 열어야만 확인할 수 있다"는 생각을 버리고, HTTP 요청과 응답이라는 가장 근본적인 층위에서 무슨 일이 일어나는지 검증하는 습관이, 이 책 전체에서 htmx의 동작을 마법처럼 느끼지 않고 정확히 이해하게 해준 도구였습니다. 실전에서 htmx 상호작용이 예상과 다르게 동작할 때도, 이 습관(네트워크 탭이나 `curl`로 실제 요청·응답을 먼저 확인하는 것)이 자바스크립트 디버거보다 먼저 손이 가야 할 곳입니다.

== 이 책이 다루지 않은 것

이 책은 Go + templ + htmx의 핵심 패턴에 집중했습니다. 의도적으로 남겨둔 것들이 많습니다 — 웹소켓(양방향 실시간 통신, SSE로 부족할 때), 파일 업로드와 이미지 처리, CSRF 토큰 같은 추가적인 보안 계층(이 책의 세션 인증은 가장 기본적인 형태입니다), 여러 서버 인스턴스가 세션을 공유해야 하는 경우의 Redis 같은 외부 세션 저장소, 실제 프로덕션 배포(리버스 프록시, TLS, 프로세스 관리, 컨테이너화), 그리고 htmx의 더 많은 확장(`hx-ext="ws"`, `hx-boost`, 히스토리 관리)입니다. 이들은 이 책에서 다진 net/http·templ·htmx의 기본 패턴 위에서 자연스럽게 확장해서 배울 수 있는 것들입니다.

== 다음으로

가장 좋은 다음 단계는 이 책의 13장 TODO 앱을 자신만의 기능으로 확장해보는 것입니다 — 할 일에 마감일과 우선순위를 추가하고, 9장의 검색을 마감일 기준 정렬과 결합하고, 11장의 SSE로 다른 기기에서 로그인한 같은 사용자에게 실시간으로 변경사항을 반영해보세요. 각 확장이 이 책의 어느 장에서 배운 패턴을 조합해야 하는지 스스로 판단하게 될 텐데, 그 판단 과정 자체가 "책의 예제를 따라 쳤다"와 "이 도구들로 실제로 무언가를 만들 수 있다"의 차이를 만듭니다.

Go로 웹 서비스를 만든다는 것이 반드시 프런트엔드 프레임워크와 API 서버를 나누는 것을 뜻하지 않는다는 것을, 그리고 자바스크립트 없이도 충분히 상호작용하는 웹을 만들 수 있다는 것을 이 책이 보여줬다면, 그것으로 충분합니다.
