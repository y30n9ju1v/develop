지금까지는 페이지마다 `<html>`, `<head>`, `<body>`를 매번 새로 썼습니다. 실제 서비스는 여러 페이지가 같은 헤더·푸터·내비게이션을 공유합니다. 이 장에서는 templ의 두 가지 조립 도구 — **`children`으로 감싸는 레이아웃**과 **컴포넌트를 인자로 받는 컴포넌트** — 로 화면을 재사용 가능한 조각으로 나눕니다.

== 레이아웃: children으로 공통 뼈대 감싸기

`{ children... }`은 "이 컴포넌트를 호출할 때 중괄호 블록 안에 쓴 내용이 여기에 들어간다"는 자리표시자입니다.

[source,templ]
----
package main

templ Layout(title string) {
	<html>
	<head>
		<title>{ title }</title>
		<script src="https://unpkg.com/htmx.org@2.0.3"></script>
	</head>
	<body>
		<header><h1>내 사이트</h1></header>
		<main>
			{ children... }
		</main>
		<footer><p>&copy; 2026</p></footer>
	</body>
	</html>
}
----

이제 각 페이지는 `Layout`을 호출하면서 `{ }` 블록 안에 그 페이지만의 내용을 씁니다.

[source,templ]
----
templ HomePage() {
	@Layout("홈") {
		<p>환영합니다!</p>
	}
}

templ AboutPage() {
	@Layout("소개") {
		<p>이 사이트는 예제입니다.</p>
	}
}
----

`@Layout("홈") { <p>환영합니다!</p> }`에서 `<p>환영합니다!</p>`가 `Layout`의 `{ children... }` 자리에 그대로 들어갑니다.

=== 실제 렌더링 결과 확인

[source,bash]
----
curl -s "http://localhost:8080/"
curl -s "http://localhost:8080/about"
----

[source]
----
<html><head><title>홈</title>...</head><body><header><h1>내 사이트</h1></header>
<main><p>환영합니다!</p></main><footer>...</footer></body></html>

<html><head><title>소개</title>...</head><body><header><h1>내 사이트</h1></header>
<main><p>이 사이트는 예제입니다.</p></main><footer>...</footer></body></html>
----

`<header>`, `<footer>`, `<script>` 태그는 완전히 똑같이 유지되면서, `<title>`과 `<main>` 안의 내용만 페이지마다 다릅니다 — 헤더나 푸터에 링크를 하나 추가하고 싶으면 `Layout` 한 곳만 고치면 모든 페이지에 반영됩니다.

== 컴포넌트를 인자로 받는 컴포넌트

templ 컴포넌트는 `templ.Component` 타입의 값이므로, 다른 컴포넌트의 **인자로 넘길 수 있습니다** — React의 `children` prop이나 Vue의 슬롯과 비슷한 역할입니다.

[source,templ]
----
templ Card(title string, body templ.Component) {
	<div class="card">
		<h2>{ title }</h2>
		<div class="card-body">
			@body
		</div>
	</div>
}

templ Tag(label string) {
	<span class="tag">{ label }</span>
}

templ TagList(labels []string) {
	<div class="tags">
		for _, label := range labels {
			@Tag(label)
		}
	</div>
}
----

`Card`는 "제목"과 "내용물"을 받는 범용 카드입니다 — 내용물이 무엇인지는 전혀 몰라도 됩니다. `TagList`처럼 이미 정의된 다른 컴포넌트를 그대로 `Card`의 `body` 인자로 넘길 수 있습니다.

[source,go]
----
Card("공지사항", TagList([]string{"중요", "새소식"})).Render(ctx, w)
----

[source]
----
<div class="card">
  <h2>공지사항</h2>
  <div class="card-body">
    <div class="tags">
      <span class="tag">중요</span><span class="tag">새소식</span>
    </div>
  </div>
</div>
----

`Card`의 결과 안에 `TagList`의 결과가, 그 안에 다시 `Tag` 두 개의 결과가 정확히 중첩되어 렌더링됐습니다 — 컴포넌트를 값처럼 조합해서 새 화면을 만드는 게 일반 Go 함수를 조합하는 것과 다르지 않습니다.

== 이 설계가 실전에서 중요한 이유

지금까지 나온 화면들(4장의 카운터, 5장의 할 일 목록, 6장의 회원가입 폼)은 각각 독립적인 예제였지만, 실제 서비스에서는 이 조각들이 같은 헤더·내비게이션 아래 여러 페이지에 걸쳐 나타납니다. `Layout`으로 공통 뼈대를 한 곳에 모으고, `Card`처럼 "내용은 몰라도 되는" 범용 컴포넌트를 만들어두면, 8장부터 데이터베이스·인증·실시간 갱신을 추가할 때도 화면 구조 자체는 거의 손대지 않고 내용물만 바꿔 끼울 수 있습니다. 13장의 종합 실전에서 만들 TODO 앱도 이 장의 `Layout`/`Card` 패턴을 그대로 확장한 구조 위에 세워집니다.

== 직접 해보기

* `Layout`에 `children`뿐 아니라, 페이지마다 다른 내비게이션 활성 항목을 표시할 수 있도록 `activeNav string` 매개변수를 추가하고, 현재 페이지에 해당하는 내비게이션 링크에만 `class="active"`가 붙도록 만들어보세요.

.해답 보기
[%collapsible]
====
[source,templ]
----
templ Layout(title string, activeNav string) {
	<html>
	<head><title>{ title }</title></head>
	<body>
		<nav>
			<a href="/" class={ templ.KV("active", activeNav == "home") }>홈</a>
			<a href="/about" class={ templ.KV("active", activeNav == "about") }>소개</a>
		</nav>
		<main>{ children... }</main>
	</body>
	</html>
}

templ HomePage() {
	@Layout("홈", "home") {
		<p>환영합니다!</p>
	}
}
----

`templ.KV("active", 조건)`은 조건이 참일 때만 `"active"` 클래스를 붙이는 templ의 조건부 클래스 헬퍼입니다(여러 클래스를 조건부로 조합할 땐 `templ.Classes`도 있습니다). 이렇게 컴포넌트에 매개변수를 하나 추가하는 것만으로, 그 컴포넌트를 쓰는 모든 페이지에서 일관된 방식으로 "현재 위치"를 표시할 수 있습니다 — 페이지마다 내비게이션 HTML을 따로 복사해서 `class="active"`를 손으로 넣었다면 하나라도 깜빡하기 쉬웠을 실수를, 컴포넌트 설계로 원천 차단한 것입니다.
====

== 요약

* `{ children... }`은 컴포넌트를 호출할 때 함께 전달한 블록 내용을 그 자리에 삽입하며, 공통 레이아웃(헤더·푸터)을 한 곳에서 관리하고 페이지별 내용만 갈아 끼우는 데 씁니다.
* templ 컴포넌트는 `templ.Component` 타입의 값이므로 다른 컴포넌트의 인자로 넘길 수 있어, "내용을 몰라도 되는" 범용 컴포넌트(카드, 리스트 래퍼)를 만들 수 있습니다.
* 이렇게 조립한 컴포넌트들은 일반 Go 함수처럼 합성되며, 렌더링 결과도 정확히 그 중첩 구조를 그대로 반영합니다.
* 다음 장에서는 지금까지 메모리(전역 변수)에만 저장했던 데이터를 SQLite 데이터베이스에 실제로 영속화합니다.
