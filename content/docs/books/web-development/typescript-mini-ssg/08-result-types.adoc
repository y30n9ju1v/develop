파일을 읽다가 실패할 수 있습니다 — 파일이 없거나, 권한이 없거나. `try/catch`로도 처리할 수 있지만, 이 장에서는 4장에서 배운 판별 유니온을 다시 활용해 **실패를 값으로** 표현하는 패턴을 봅니다.

== `Result<T, E>` 타입

[source,typescript]
----
// src/result.ts
export type Result<T, E> = { ok: true; value: T } | { ok: false; error: E };

export async function tryReadFile(filePath: string): Promise<Result<string, string>> {
  try {
    const content = await readFile(filePath, "utf-8");
    return { ok: true, value: content };
  } catch (err) {
    const message = err instanceof Error ? err.message : String(err);
    return { ok: false, error: message };
  }
}
----

`Result<T, E>`는 4장의 `Content` 유니온과 똑같은 모양입니다 — `ok`가 판별자입니다. `try/catch`는 이 함수 **안에서만** 쓰이고, 밖으로는 절대 예외가 던져지지 않습니다 — 호출하는 쪽은 항상 `Result` 값을 받고, `ok`를 확인해야만 `value`나 `error`에 접근할 수 있습니다.

`err instanceof Error`도 눈여겨볼 만합니다 — JavaScript의 `catch` 블록에 잡히는 값은 타입상 `unknown`입니다(무엇이든 `throw`될 수 있으니까요). `instanceof`로 좁혀야만 `.message`에 안전하게 접근할 수 있습니다 — 3장의 타입 가드와 원리가 같습니다.

== 실행 확인: 성공과 실패 둘 다

[source,typescript]
----
const ok = await tryReadFile("content/posts/hello-world.md");
console.log("ok case:", ok.ok, ok.ok ? ok.value.slice(0, 20) : "");

const fail = await tryReadFile("content/posts/does-not-exist.md");
console.log("fail case:", fail.ok, !fail.ok ? fail.error : "");
----

[source]
----
$ node dist-js/result_demo.js
ok case: true ---
title: 첫 번째 글
da
fail case: false ENOENT: no such file or directory, open 'content/posts/does-not-exist.md'
----

존재하는 파일은 `{ ok: true, value: "..." }`를, 존재하지 않는 파일은 `{ ok: false, error: "ENOENT: ..." }`를 돌려줍니다 — 둘 다 예외 없이, 평범한 값으로 처리됩니다. `ok.value`에 접근하기 전에 `ok.ok ? ... : ...`로 분기한 것도 우연이 아닙니다 — `ok`가 `false`일 수도 있는 상태에서 `ok.value`에 바로 접근하면, TypeScript가 `Property 'value' does not exist on type ...`라며 막습니다.

== 왜 `try/catch`만으로는 부족한가

`try/catch`가 나쁜 건 아닙니다 — 다만 **컴파일러가 "이 함수는 실패할 수 있다"는 걸 타입으로 강제하지 못합니다.** `throw`하는 함수를 호출하는 쪽이 `try/catch`로 감싸는 걸 깜빡해도, TypeScript는 아무 말도 하지 않습니다(자바의 checked exception과 다른 점입니다). `Result<T, E>`를 반환 타입으로 못박으면, 호출하는 쪽은 `.value`에 접근하기 위해서라도 `ok`를 확인할 수밖에 없습니다 — "실패 처리를 깜빡하는 것" 자체가 타입 에러가 됩니다.

== 요약

* `Result<T, E> = { ok: true; value: T } | { ok: false; error: E }`로 실패를 예외가 아니라 값으로 표현했습니다.
* 성공(`ok: true`)과 실패(`ok: false`) 두 경우를 실제로 실행해, 둘 다 예외 없이 평범한 값으로 처리된다는 걸 확인했습니다.
* `try/catch`와 달리, `Result`를 반환 타입으로 쓰면 "실패 처리를 깜빡하는 것"이 컴파일 에러로 강제된다는 게 핵심 차이입니다.
