== `Partial`로 "일부만 덮어쓰기"

[source,typescript]
----
// src/template.ts
export interface SiteConfig {
  title: string;
  baseUrl: string;
  description: string;
}

export function mergeConfig(defaults: SiteConfig, overrides: Partial<SiteConfig>): SiteConfig {
  return { ...defaults, ...overrides };
}
----

[source]
----
$ node dist-js/config_demo.js
{ title: '덮어쓴 제목', baseUrl: 'http://localhost', description: '기본 설명' }
----

`overrides: Partial<SiteConfig>`는 `SiteConfig`의 모든 필드를 선택적(`?`)으로 만든 타입입니다 — `{ title: "덮어쓴 제목" }`처럼 필드 하나만 있는 객체도 넘길 수 있습니다. `SiteConfig`를 직접 받았다면 세 필드를 전부 채워야 했을 것입니다.

== `Pick`으로 "일부만 골라내기"

[source,typescript]
----
export type CardInfo = Pick<SiteConfig, "title">;
----

`CardInfo`는 `{ title: string }`과 같습니다 — 목록 카드에는 제목만 필요하고 `baseUrl`이나 `description`은 필요 없을 때, `SiteConfig`를 통째로 요구하는 대신 필요한 조각만 정확히 표현할 수 있습니다.

== 이 유틸리티 타입들은 사실 평범한 타입이다

`Partial`과 `Pick`은 마법이 아닙니다 — TypeScript 표준 라이브러리에 **매핑 타입(mapped type)**이라는 평범한 문법으로 정의되어 있습니다. 직접 재현해봅니다.

[source,typescript]
----
interface SiteConfig {
  title: string;
  baseUrl: string;
  description: string;
}

// Partial<T>가 실제로 이렇게 정의되어 있다 (표준 라이브러리 정의, 이름만 바꿈)
type MyPartial<T> = { [K in keyof T]?: T[K] };

const override: MyPartial<SiteConfig> = { title: "새 제목" }; // 나머지는 생략 가능

type MyPick<T, K extends keyof T> = { [P in K]: T[P] };
const card: MyPick<SiteConfig, "title"> = { title: "카드용" };
----

[source]
----
$ npx tsc --strict --noEmit spike_mapped.ts
(에러 없음 — 컴파일 통과)
----

`{ [K in keyof T]?: T[K] }`를 읽는 법 — `keyof T`는 `T`의 모든 필드 이름을 문자열 리터럴 유니온으로 뽑아냅니다(`SiteConfig`라면 `"title" | "baseUrl" | "description"`). `[K in ...]`는 그 각각을 순회하면서 새 타입의 필드로 다시 만들고, 끝에 붙은 `?`가 선택적으로 만듭니다. `MyPick`의 `K extends keyof T`는 5장에서 배운 제네릭 제약이 그대로 다시 쓰인 것입니다 — "고를 필드 이름은 반드시 `T`에 실제로 존재하는 이름이어야 한다"는 제약입니다.

`Partial`, `Pick`, `Omit`, `Required`, `Readonly` 같은 유틸리티 타입들이 전부 이런 매핑 타입 몇 줄로 정의되어 있다는 걸 알면, "이 유틸리티 타입이 정확히 뭘 하는지" 헷갈릴 때마다 직접 펼쳐서 확인하는 습관을 들일 수 있습니다 — 에디터에서 `Partial` 위에 커서를 올리고 정의로 이동해보면 정확히 이 코드가 나옵니다.

== 요약

* `Partial<SiteConfig>`로 일부 필드만 덮어쓰는 병합 함수를, `Pick<SiteConfig, "title">`로 필요한 필드만 골라낸 타입을 만들었습니다.
* 이 유틸리티 타입들이 `{ [K in keyof T]?: T[K] }` 같은 매핑 타입으로 직접 재현 가능한, 특별할 것 없는 타입이라는 걸 실제 컴파일로 확인했습니다.
* `keyof`로 필드 이름 유니온을 뽑고, `K extends keyof T`로 5장의 제네릭 제약을 다시 활용하는 패턴을 봤습니다.
