== 이 책이 지은 것

1부에서 프로젝트를 셋업하고(`NodeNext` 모듈 시스템, `strict` 모드), `any`로 짠 가장 단순한 버전이 오타 하나를 조용히 `undefined`로 흘리는 걸 직접 겪었습니다. 2부에서는 이 문제를 정면으로 풀었습니다 — `unknown`과 커스텀 타입 가드로 외부 데이터를 검증하고(3장), 판별 유니온과 `never`를 이용한 완전성 검사로 콘텐츠 종류를 안전하게 구분하고(4장), 제네릭 제약과 구조적 타이핑으로 재사용 가능하면서도 안전한 함수를 짰습니다(5장). 3부에서는 유틸리티 타입이 사실 매핑 타입이라는 평범한 문법으로 만들어진다는 것(6장), `Promise.all`로 비동기 작업을 동시에 처리하는 것(7장), 예외 대신 값으로 실패를 다루는 `Result` 타입(8장), 클래스의 `implements`·`readonly`·`private`·추상 클래스(9장), 그리고 템플릿 리터럴 타입으로 문자열의 모양 자체를 타입으로 표현하는 것(10장)까지 실제 코드와 실제 컴파일 에러로 확인했습니다. 11장에서 이 모든 조각을 재작성 없이 이어, 실제 Markdown 파일을 진짜 HTML 사이트로 빌드했습니다.

== 이 책이 확인한 것과 다루지 않은 것

이 책의 모든 컴파일 에러와 실행 결과는 실제로 이 세션에서 `tsc`와 `node`로 재현한 것입니다 — "TypeScript가 이런 걸 막아줍니다"라고 설명만 하지 않고, 매번 실제 에러 메시지(`TS18048`, `TS2322`, `TS2353`, `TS2341`)를 그대로 실었습니다.

다루지 않은 것도 정직하게 남깁니다.

* **제네릭 타입 추론의 한계** — 이 책의 제네릭은 전부 인자로부터 타입이 자동으로 추론되는 단순한 경우였습니다. 여러 제네릭 매개변수가 서로 얽히거나, 조건부 타입(conditional types, `T extends U ? X : Y`)까지 가는 더 깊은 타입 레벨 프로그래밍은 다루지 않았습니다.
* **데코레이터** — 클래스나 메서드에 `@` 문법으로 부가 기능을 붙이는 데코레이터는 아직 완전히 표준화되지 않은 영역이라 이 책에서 제외했습니다.
* **캐싱과 증분 빌드** — 이 SSG는 매번 모든 파일을 처음부터 다시 빌드합니다. 파일이 수백 개로 늘어나면 바뀐 파일만 다시 빌드하는 전략이 필요한데, 이건 이 책의 범위(타입 시스템 자체를 배우는 것)를 벗어납니다.
* **실제 배포** — 빌드된 `dist/` 폴더를 실제 웹 서버나 CDN에 올리는 절차는 다루지 않았습니다.

== 다음 단계

이 책에서 지은 `tinyssg`는 장난감이지만, 그 위에서 확인한 패턴들 — `unknown` + 타입 가드로 외부 데이터 검증하기, 판별 유니온 + 완전성 검사로 분기 누락 막기, 제네릭 제약으로 재사용성과 안전성 둘 다 잡기 — 은 규모가 커진 실제 프로젝트에서도 그대로 통합니다. 다음으로 볼 만한 방향은 이 SSG에 캐싱을 붙여보는 것, 혹은 조건부 타입까지 다루는 더 깊은 타입 레벨 프로그래밍을 파보는 것입니다 — 이 사이트의 다른 TypeScript 관련 책(`ts-react-getting-started`)에서 프레임워크 위의 타입 활용을 이어서 볼 수도 있습니다.
