2장에서 심은 트랩 — 몇 초마다 무작위 좌석이 매진되는 것 — 은 이제 실제로 실패를 만들어냅니다. 조회한 시점엔 비어있던 좌석이, 예매를 확정하려는 순간엔 이미 팔려있을 수 있습니다.

== 실패를 실제로 재현하기

[source]
----
$ curl -s -X POST http://localhost:4100/api/reserve -H "Content-Type: application/json" -d '{"row":0,"col":0}'
{"ok":false,"message":"이미 매진된 좌석입니다"}
----

이미 매진된 좌석(`0행 0열`)을 예매하려 하면 정확히 이 응답이 옵니다. 다른 좌석으로 재시도하면 성공합니다.

[source]
----
$ curl -s -X POST http://localhost:4100/api/reserve -H "Content-Type: application/json" -d '{"row":4,"col":7}'
{"ok":true,"message":"예매 완료: 4행 7열"}
----

== 재시도 래퍼

이 실패를 흡수하는 가장 간단한 패턴은, 실패하면 다른 좌석 후보로 다시 시도하는 재시도 루프입니다. Playwright의 `page.evaluate()`는 (호스트 언어가 Python이든 JS든) 항상 브라우저 안에서 JavaScript를 실행하므로, 안에 넘기는 콜백 자체는 JS로 씁니다 — 바깥의 재시도 로직(반복, 로그, 조기 종료)은 Python입니다.

[source,python]
----
def reserve_with_retry(page, candidates, max_attempts=3):
    for attempt in range(max_attempts):
        if not candidates:
            break
        row, col = candidates.pop(0)
        result = page.evaluate(
            """({row, col}) => fetch('/api/reserve', {
                method: 'POST', headers: {'Content-Type':'application/json'},
                body: JSON.stringify({row, col})
            }).then(r => r.json())""",
            {"row": row, "col": col},
        )
        print(f"시도 {attempt + 1}: {row}행 {col}열 ->", result["message"])
        if result["ok"]:
            return result
    return {"ok": False, "message": "모든 후보 좌석이 실패했습니다"}
----

== 실행 확인

일부러 이미 매진된 좌석 두 개를 먼저 넣고, 세 번째만 열려 있는 좌석으로 후보 목록을 만들어 돌려봤습니다.

[source]
----
$ python pw_retry_demo.py
시도 1: 0행 0열 -> 이미 매진된 좌석입니다
시도 2: 0행 1열 -> 이미 매진된 좌석입니다
시도 3: 0행 6열 -> 예매 완료: 0행 6열
----

앞의 두 시도가 실패해도 예외를 던지지 않고 다음 후보로 넘어갔고, 세 번째 시도에서 실제로 예매가 완료됐습니다.

3부에서 LLM이 좌석 하나만 고르는 대신, **후보를 여러 개** 우선순위와 함께 돌려주도록 설계하면(13장에서 실제로 이렇게 바꿉니다) 이 재시도 루프가 그대로 맞물립니다 — LLM이 1순위로 고른 좌석이 이미 팔렸어도, 2순위 후보로 자동으로 넘어갈 수 있습니다.

== 무한정 재시도하지 않기

`max_attempts`를 두는 이유는 단순합니다 — 후보가 전부 팔렸거나, LLM이 계속 같은(이미 실패한) 좌석을 고르는 상황에서 무한 루프에 빠지지 않게 하기 위해서입니다. 재시도는 "일시적인 실패를 흡수하는 것"이지 "어떻게든 성공할 때까지 무한정 버티는 것"이 아닙니다 — 후자는 오히려 서버에 불필요한 부하를 줍니다.

== 요약

* 2장에서 심은 경쟁 조건이 실제로 예매 실패(`이미 매진된 좌석입니다`)를 만들어낸다는 걸 실측으로 확인했습니다.
* 실패 응답을 흡수하는 재시도 루프를 만들고, 후보 좌석을 순서대로 시도하며 실패 메시지를 그대로 로그로 남기게 했습니다.
* 재시도 횟수에 상한을 둬서, 모든 후보가 실패하는 상황에서도 무한 루프에 빠지지 않게 했습니다.

2부가 여기서 끝났습니다. 3부에서는 이 책의 핵심 — 캔버스 좌석맵처럼 규칙만으로는 다루기 어려운 부분을 크로미움 익스텐션과 LLM으로 처리하는 법 — 을 처음부터 짓습니다.
