지금까지 익스텐션의 뼈대(6~10장)를 다졌습니다. 이제 실제로 LLM을 호출합니다.

== 이 장의 실측 경계

서문에서 밝힌 대로, 이 세션에는 실제 OpenAI/Anthropic API 키가 없습니다. 그래서 이 장(과 12~14장)의 실행 결과는 **OpenAI Chat Completions API와 같은 HTTP 계약**(`POST /v1/chat/completions`, 같은 요청/응답 스키마, SSE 스트리밍)을 구현한 로컬 Express 서버로 얻었습니다. `background.js`의 코드는 base URL과 `Authorization` 헤더의 키만 바꾸면 실제 API에도 그대로 동작합니다 — 바뀌는 건 딱 한 줄, `LLM_BASE_URL` 상수뿐입니다.

[source,javascript]
----
// mock_llm.js -- 이 세션에서만 쓰는 로컬 모크 서버
app.post('/v1/chat/completions', (req, res) => {
  const { messages, stream } = req.body;
  const userMsg = messages[messages.length - 1];
  const hasImage = Array.isArray(userMsg.content) &&
    userMsg.content.some((c) => c.type === 'image_url');

  const replyText = hasImage
    ? JSON.stringify({ row: 2, col: 3, reason: '3루측 그늘, 앞뒤 여유 있는 자리' })
    : `요청 확인: ${userMsg.content}`;

  if (!stream) {
    return res.json({
      choices: [{ message: { role: 'assistant', content: replyText }, finish_reason: 'stop' }],
    });
  }
  // 스트리밍 분기는 14장에서 다룹니다
});
----

== background.js: fetch로 LLM 호출하기

[source,javascript]
----
const LLM_BASE_URL = 'http://localhost:4200'; // 실제라면 https://api.openai.com

async function pickSeat(screenshotDataUrl, preference) {
  const res = await fetch(`${LLM_BASE_URL}/v1/chat/completions`, {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({
      model: 'gpt-mock',
      stream: false,
      messages: [
        {
          role: 'user',
          content: [
            { type: 'text', text: `이 좌석맵에서 이 선호에 맞는 좌석을 골라줘: ${preference}` },
            { type: 'image_url', image_url: { url: screenshotDataUrl } },
          ],
        },
      ],
    }),
  });
  const data = await res.json();
  return JSON.parse(data.choices[0].message.content);
}
----

`content`가 문자열이 아니라 배열인 걸 눈여겨보세요 — `{ type: 'text', ... }`와 `{ type: 'image_url', ... }`를 함께 넣는 건 OpenAI 비전 API의 실제 스키마입니다. `image_url.url`엔 `https://...` 링크뿐 아니라 `data:image/png;base64,...` 형태의 데이터 URL도 그대로 넣을 수 있습니다 — 7장에서 `canvas.toDataURL()`이 만든 값이 정확히 이 형태입니다.

== 실행 확인

이 함수를 popup(8장)이 트리거하면, service worker가 스크린샷과 함께 이 요청을 보내고 판단 결과를 돌려받습니다. 15장에서 만드는 전체 파이프라인 실행 로그에서 이 부분이 실제로 작동하는 걸 확인할 수 있습니다.

[source]
----
popup result: {
  "chosen": {
    "col": 3,
    "reason": "3루측 그늘, 앞뒤 여유 있는 자리",
    "row": 2
  },
  "ok": true
}
----

service worker가 캔버스 이미지를 받아 LLM(여기선 모크)에 넘겼고, `{row: 2, col: 3, reason: ...}`이라는 판단이 돌아와 content script까지 전달됐습니다.

== 요약

* service worker의 `fetch`로 OpenAI 호환 `/v1/chat/completions` 엔드포인트를 호출하는 코드를 짰습니다 — base URL만 바꾸면 실제 API에도 그대로 씁니다.
* `content` 필드를 배열로 만들어 텍스트와 이미지(`image_url`)를 함께 보내는 게 비전 API 요청의 실제 스키마입니다.
* 이 세션엔 실제 API 키가 없어 로컬 모크 서버로 검증했다는 걸 명시적으로 밝혔습니다 — 12장부터는 이 경계를 매번 반복하지 않고, 이 장의 원칙을 그대로 따릅니다.
