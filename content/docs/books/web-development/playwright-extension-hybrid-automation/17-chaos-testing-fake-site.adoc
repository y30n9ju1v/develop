16장까지 만든 파이프라인이 "가끔 운 좋게" 성공하는 건지, 실제로 견고한 건지는 여러 번 돌려보지 않으면 알 수 없습니다. 이 장은 2장의 트랩(무작위 매진)을 더 가혹하게 만들어서 실측합니다.

== 첫 시도: 트랩을 너무 가혹하게 만들면 무의미해진다

먼저 매진 간격을 4초에서 200ms로 확 좁혀봤습니다.

[source]
----
$ node pw_chaos_retry.js
run 1: FAIL
run 2: FAIL
run 3: FAIL
run 4: FAIL
run 5: FAIL
최대 5번 재시도 허용 시 성공률: 0/5
----

재시도를 5번까지 허용해도 전부 실패했습니다. 원인을 로그로 파봤습니다.

[source]
----
attempt 0 -> 이미 매진된 좌석입니다
attempt 1 -> 이미 매진된 좌석입니다
attempt 2 -> 이미 매진된 좌석입니다
attempt 3 -> 이미 매진된 좌석입니다
attempt 4 -> 이미 매진된 좌석입니다
----

로그인·대기열 통과에 걸리는 몇 초 사이에, 200ms마다 좌석 하나씩(전체 40석 중) 팔려나가면 **좌석맵에 도달하기도 전에 이미 거의 다 매진**됩니다. 이건 파이프라인의 문제가 아니라 테스트 설계의 문제입니다 — 애초에 성공이 불가능한 조건을 만들어놓고 "견고하지 않다"고 결론 내리면 잘못된 진단입니다. 간격을 1.5초로 다시 조정했습니다.

== 재조정 후: 재시도 있음 vs 없음

같은 1.5초 간격에서, 재시도를 아예 안 하는 경우(1회 시도)와 5번까지 재시도하는 경우를 각각 5번씩 돌려 비교했습니다.

[source]
----
$ node pw_chaos_noretry.js   # 재시도 없음 (13장 이전 방식)
run 1: FAIL
run 2: SUCCESS
run 3: FAIL
run 4: FAIL
run 5: FAIL
최대 5번 재시도 허용 시 성공률: 1/5

$ node pw_chaos_retry.js     # 5장의 재시도 로직 적용
run 1: SUCCESS
run 2: SUCCESS
run 3: SUCCESS
run 4: SUCCESS
run 5: FAIL
최대 5번 재시도 허용 시 성공률: 4/5
----

같은 조건에서 재시도 없이는 5번 중 1번(20%), 재시도를 붙이면 5번 중 4번(80%) 성공했습니다. 5회조차 실패한 마지막 실행은, 매 시도마다 모크 LLM이 고른 좌석이 우연히 계속 이미 팔린 자리와 겹친 경우입니다 — 재시도가 성공을 보장하는 건 아니고, 실패 확률을 줄여줄 뿐이라는 것도 이 결과가 정직하게 보여줍니다.

== 이 수치를 어떻게 읽어야 하는가

이 80%라는 숫자 자체를 실제 예매 사이트에 대한 예측치로 쓰면 안 됩니다 — 이건 이 책이 만든 가짜 사이트의 특정 매진 속도(1.5초)와 좌석 수(40석)에서 나온 값입니다. 이 장에서 진짜 확인한 건 숫자 자체가 아니라 **방법론**입니다 — 파이프라인의 견고성을 주장이 아니라 "같은 조건에서 N번 돌려 성공률을 잰다"는 실측으로 검증했고, 그 결과 재시도 로직이 실제로 유의미한 차이를 만든다는 것까지 확인했습니다.

== 요약

* 트랩을 너무 가혹하게(200ms) 만들면 애초에 성공이 불가능해져서 견고성 측정 자체가 무의미해진다는 걸 첫 시도의 실패로 확인했습니다.
* 현실적인 간격(1.5초)에서, 재시도 없이는 5번 중 1번, 재시도를 붙이면 5번 중 4번 성공한다는 걸 실측했습니다.
* 이 성공률 수치는 이 가짜 사이트의 특정 조건에서만 유효합니다 — 이 장이 보여준 건 숫자가 아니라 "N번 돌려서 성공률을 잰다"는 검증 방법 자체입니다.
