== service worker에서 SSE 직접 파싱하기

브라우저의 `EventSource`는 `Authorization` 헤더를 못 붙이는 제약이 있어서(GET 요청만 지원), service worker에서는 `fetch`의 `ReadableStream`을 직접 읽어 SSE 프로토콜(`data: ...\n\n`)을 손으로 파싱합니다.

[source,javascript]
----
async function streamPick(preference, sender) {
  const key = await getApiKey();
  const res = await fetch(`${LLM_BASE_URL}/v1/chat/completions`, {
    method: 'POST',
    headers: {
      'Content-Type': 'application/json',
      ...(key ? { Authorization: `Bearer ${key}` } : {}),
    },
    body: JSON.stringify({ model: 'gpt-mock', stream: true, messages: [{ role: 'user', content: preference }] }),
  });

  const reader = res.body.getReader();
  const decoder = new TextDecoder();
  let buffer = '';
  while (true) {
    const { done, value } = await reader.read();
    if (done) break;
    buffer += decoder.decode(value, { stream: true });
    const lines = buffer.split('\n\n');
    buffer = lines.pop(); // 마지막 조각은 아직 완성되지 않았을 수 있으니 버퍼에 남긴다
    for (const line of lines) {
      if (!line.startsWith('data: ')) continue;
      const payload = line.slice(6);
      if (payload === '[DONE]') { chrome.runtime.sendMessage({ type: 'STREAM_DONE' }); return; }
      const parsed = JSON.parse(payload);
      chrome.runtime.sendMessage({ type: 'STREAM_CHUNK', delta: parsed.choices[0].delta.content || '' });
    }
  }
}
----

`buffer.split('\n\n')`로 자르고 마지막 조각을 다시 버퍼에 남기는 부분이 중요합니다 — 네트워크 청크가 SSE 이벤트 경계와 정확히 맞아떨어진다는 보장이 없어서, 완성되지 않은 조각을 섣불리 파싱하면 `JSON.parse`가 깨집니다.

== popup에서 받기: 9장의 방송 패턴

[source,javascript]
----
document.getElementById('stream').addEventListener('click', () => {
  document.getElementById('streamOut').textContent = '';
  chrome.runtime.sendMessage({ type: 'STREAM_PICK', preference: document.getElementById('pref').value });
});

chrome.runtime.onMessage.addListener((msg) => {
  if (msg.type === 'STREAM_CHUNK') {
    document.getElementById('streamOut').textContent += msg.delta;
  }
});
----

popup의 `#streamOut`에 조각들이 실제로 이어붙어 완성된 문장이 나타났습니다 — mock 서버가 응답을 6글자씩 잘라 20ms 간격으로 흘려보내는데도(`mock_llm.js`의 스트리밍 분기), 조각이 몇 개로 쪼개지든 popup 쪽에선 매끄럽게 이어집니다.

== 요약

* service worker에서는 `EventSource` 대신 `fetch`의 `ReadableStream`을 직접 읽어 SSE를 파싱해야 `Authorization` 헤더를 붙일 수 있습니다.
* 네트워크 청크와 SSE 이벤트 경계가 다를 수 있으므로, 완성되지 않은 마지막 조각을 버퍼에 남겨두는 처리가 필요합니다.
* 9장에서 구분한 방송 패턴 그대로, service worker가 청크마다 메시지를 쏘고 popup은 리스너로 받아 이어붙이는 구조로 실시간 스트리밍이 실제로 동작하는 걸 확인했습니다.
