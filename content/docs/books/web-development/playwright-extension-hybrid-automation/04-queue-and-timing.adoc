2장에서 확인했듯 대기열 순번은 호출마다 5~14씩 무작위로 줍니다 — "몇 번 클릭해야 0이 되는지"를 미리 계산할 방법이 없습니다. 이런 상황에서는 조건을 미리 계산하는 대신, **조건이 만족될 때까지 반복하는** 패턴이 정답입니다.

== 폴링 루프

[source,python]
----
position = float("inf")
while position > 0:
    page.click("#enter")
    position = int(page.locator("#qpos").inner_text())
    print("queue position:", position)

page.wait_for_selector("#seatmap-area", state="visible")
----

`while position > 0`이 핵심입니다 — 몇 번 반복할지 하드코딩하지 않고, 서버가 실제로 알려주는 값을 매번 다시 읽어서 종료 조건을 판단합니다.

== 실행 확인

3장의 로그인 코드 바로 뒤에 이 루프를 이어 붙여 실행합니다.

[source]
----
$ python pw_queue.py
queue position: 37
queue position: 25
queue position: 12
queue position: 6
queue position: 1
queue position: 0
seatmap now visible
----

6번 클릭 만에 대기열을 통과했습니다 — 순번이 무작위로 주는데도, "0이 될 때까지 반복한다"는 조건 하나로 정확히 대응했습니다. 만약 정해진 횟수(예: "10번 클릭하면 되겠지")로 하드코딩했다면, 어느 실행에서는 부족하고 어느 실행에서는 낭비였을 겁니다.

== 정시 진입: 특정 시각까지 기다리기

실제 예매는 대개 "오후 2시 정각에 오픈"처럼 정해진 시각이 있습니다. 이 경우 무작정 폴링하는 대신, 정확한 시각까지 기다렸다가 그 순간부터 폴링을 시작하는 게 낫습니다.

[source,python]
----
import time
from datetime import datetime, timedelta

def wait_until(target: datetime):
    remaining = (target - datetime.now()).total_seconds()
    if remaining > 0:
        time.sleep(remaining)

open_time = datetime.now() + timedelta(seconds=5)  # 예: 5초 뒤 오픈
wait_until(open_time)
# 이제부터 폴링 루프 시작
----

`time.sleep` 하나로 충분합니다 — 정교한 스케줄러가 필요 없습니다. 다만 시스템 시계와 서버 시계가 어긋나 있으면 오차가 생길 수 있다는 점은 실전에서 염두에 둘 만합니다(이 책은 이 오차 보정까지는 다루지 않습니다).

== 요약

* 대기열처럼 완료 시점을 예측할 수 없는 상황은 하드코딩된 횟수 대신 `while` 폴링으로 대응합니다.
* 실제로 6번 클릭 만에 대기열을 통과하는 걸 실행 로그로 확인했습니다 — 시도 때마다 필요한 횟수가 다르다는 것도 함께 보여줍니다.
* 정해진 오픈 시각이 있다면 `setTimeout`으로 그 시각까지 기다린 뒤 폴링을 시작하는 게 더 효율적입니다.
