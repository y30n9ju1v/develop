'''

1장에서는 카메라 자세 오차가 삼각측량 재투영 오차로 이어진다는 걸 한 시점(스냅샷)에서 확인했습니다. 이 장에서는 전체 주행 궤적(`40`프레임)으로 넓혀, extrinsic 오차의 **성격**(각 프레임마다 독립적인 오차인지, 서서히 누적되는 드리프트인지)이 재구성 오차에 얼마나 다르게 영향을 주는지 비교합니다. 이 비교가 3부 전체(포즈 그래프 최적화, 루프 클로저)의 동기가 됩니다.

== 두 가지 오차의 성격: 독립적 노이즈 vs 누적되는 드리프트

실제 로깅 시스템에서 extrinsic이 흔들리는 원인은 크게 두 가지 성격을 갖습니다.

* **독립적 노이즈(i.i.d. noise)**: 매 프레임마다 서로 무관하게 무작위로 흔들리는 오차. 예를 들어 매 순간의 진동이 그 순간의 카메라 자세 추정치에만 영향을 주고, 다음 순간의 오차와는 무관한 경우입니다.
* **누적 드리프트(drift)**: 프레임마다 아주 작은 변화가 이전 오차 위에 계속 쌓이는 오차. 캘리브레이션 자체가 시간이 지나면서(온도 변화, 지속적인 진동) 서서히 틀어지거나, 자세 추정(SLAM/INS) 자체가 적분 오차를 누적하는 경우가 여기 해당합니다.

두 경우 모두 "각 프레임의 자세가 정답에서 조금씩 벗어나 있다"는 점은 같지만, 그 벗어남들이 프레임 사이에서 **서로 무관한지, 서로 연관되어 있는지**가 다릅니다.

== 시뮬레이션: 40프레임 궤적과 15개 점으로 이루어진 장면

[source,python]
----
import numpy as np

def skew(w):
    return np.array([[0, -w[2], w[1]], [w[2], 0, -w[0]], [-w[1], w[0], 0]])

def exp_so3(w):
    theta = np.linalg.norm(w)
    if theta < 1e-8:
        return np.eye(3) + skew(w)
    axis = w / theta
    K = skew(axis)
    return np.eye(3) + np.sin(theta) * K + (1 - np.cos(theta)) * (K @ K)

f = 300.0
def project(P_world, R_wc, t_wc):
    P_cam = R_wc @ P_world + t_wc
    return np.array([f * P_cam[0] / P_cam[2], f * P_cam[1] / P_cam[2]])

def triangulate_point(obs_2d, poses, f):
    A = []
    for (x, y), (R, t) in zip(obs_2d, poses):
        r1, r2, r3 = R[0], R[1], R[2]
        row1, row2 = x * r3 - f * r1, y * r3 - f * r2
        b1, b2 = -(x * t[2] - f * t[0]), -(y * t[2] - f * t[1])
        A.append((row1, b1))
        A.append((row2, b2))
    Amat, bvec = np.array([a for a, b in A]), np.array([b for a, b in A])
    P, *_ = np.linalg.lstsq(Amat, bvec, rcond=None)
    return P

rng = np.random.default_rng(2)
n_frames = 40
points_true = np.array([0.0, 0.0, 5.0]) + rng.normal(0, 0.1, (15, 3))

true_poses = []
for i in range(n_frames):
    angle = 2 * np.pi * i / n_frames * 0.4
    cam_pos = np.array([2 * np.sin(angle), 0.2 * np.sin(2 * angle), 0.0])
    R = exp_so3(np.array([0, angle * 0.1, 0]))
    t = -R @ cam_pos
    true_poses.append((R, t))
----

== 두 가지 오차 만들기: 같은 "강도"를 다른 방식으로

두 오차 모두 매 프레임 `0.01`(독립) 또는 `0.003`(드리프트, **더 작은** 값을 씁니다) 표준편차의 회전/이동 잡음에서 출발합니다.

[source,python]
----
noise_std = 0.01

iid_poses = []                              # 독립적 노이즈: 매 프레임 그 자체로 완결된 오차
for (R, t) in true_poses:
    dR = exp_so3(rng.normal(0, noise_std, 3))
    dt = rng.normal(0, noise_std, 3)
    iid_poses.append((dR @ R, t + dt))

drift_poses = []                            # 누적 드리프트: 이전 오차 위에 작은 변화가 계속 쌓임
cum_rot, cum_trans = np.zeros(3), np.zeros(3)
for (R, t) in true_poses:
    cum_rot = cum_rot + rng.normal(0, noise_std * 0.3, 3)     # 스텝 크기는 독립 노이즈의 30%
    cum_trans = cum_trans + rng.normal(0, noise_std * 0.3, 3)
    drift_poses.append((exp_so3(cum_rot) @ R, t + cum_trans))
----

드리프트의 매 스텝 표준편차(`0.003`)는 독립 노이즈(`0.01`)의 `30%`밖에 안 됩니다 — 얼핏 보면 드리프트 쪽이 "덜 흔들리는" 것처럼 보입니다.

== 재구성 오차 비교: 얼마나 다른가

1장의 재투영 오차 계산을 그대로 궤적 전체(`40`프레임 × `15`점)로 확장합니다.

[source,python]
----
def mean_reproj_error(used_poses):
    errs = []
    for P in points_true:
        obs_true = [project(P, R, t) for R, t in true_poses]
        P_recon = triangulate_point(obs_true, used_poses, f)
        for o, (R, t) in zip(obs_true, true_poses):
            xr, yr = project(P_recon, R, t)
            errs.append(np.hypot(xr - o[0], yr - o[1]))
    return np.mean(errs)

print("독립적 노이즈 재투영 오차:", mean_reproj_error(iid_poses))
print("누적 드리프트 재투영 오차:", mean_reproj_error(drift_poses))
----

[source]
----
독립적 노이즈 재투영 오차: 0.7864
누적 드리프트 재투영 오차: 2.2445
----

매 스텝 크기가 `3`분의`1`밖에 안 되던 드리프트 쪽이, 오히려 **거의 `3`배 더 큰** 재구성 오차를 만들었습니다. "작은 흔들림처럼 보였던" 드리프트가 실제로는 훨씬 더 해로운 오차였던 것입니다.

== 왜 작은 드리프트가 더 해로운가

핵심은 삼각측량이 여러 시점의 관측을 **동시에** 만족하는 점을 찾는다는 데 있습니다. 독립적 노이즈는 어떤 프레임은 왼쪽으로, 어떤 프레임은 오른쪽으로, 서로 무관한 방향으로 흔들립니다 — 이런 오차들은 여러 시점에 걸쳐 어느 정도 "서로 상쇄"됩니다(한 프레임의 오차가 다른 프레임의 오차와 다른 방향을 향하니, 최소제곱이 그 사이 어딘가로 평균을 내면서 개별 오차의 영향이 부분적으로 줄어듭니다). 반면 드리프트는 인접한 프레임들이 **비슷한 방향으로 함께** 틀어져 있습니다 — 근처 프레임들끼리는 서로 "동의"하고 있으니 삼각측량 입장에서는 일관된 신호처럼 보이고, 이 일관되게 틀어진 그룹 전체가 상쇄되지 않은 채 재구성 결과를 그 방향으로 끌고 갑니다. 즉, 서로 다른 방향으로 흩어진 오차보다, 같은 방향으로 뭉친(비록 크기는 작더라도) 오차가 최소제곱 추정을 훨씬 크게 왜곡시킵니다.

== 이것이 3부(포즈 그래프 최적화)의 존재 이유다

이 발견은 이 책 3부 전체의 동기입니다. 독립적 노이즈는 관측이 많아질수록(더 많은 프레임, 더 많은 점) 어느 정도 저절로 평균 속에 묻히는 경향이 있지만, 드리프트는 관측을 아무리 늘려도 저절로 사라지지 않습니다 — 오히려 궤적이 길어질수록 드리프트가 더 많이 누적되어 문제가 커집니다. 이 누적 오차를 되돌리려면, 그저 데이터를 더 모으는 게 아니라 **드리프트가 만들어낼 수 없는 종류의 추가 정보**(예: "이 두 프레임이 사실은 같은 장소를 다시 지나갔다"는 루프 클로저 정보, 또는 "이 두 카메라는 리지드 리그로 고정되어 있으니 상대 위치가 항상 같아야 한다"는 제약)가 필요합니다. 7장에서는 이런 추가 정보를 포즈 그래프 최적화에 제약으로 녹여 넣어, 드리프트를 실제로 되돌리는 법을 다룹니다.

== 요약

* 독립적 노이즈(프레임마다 무관하게 흔들림)와 누적 드리프트(서서히 같은 방향으로 쌓이는 오차)는 크기가 같아도 재구성에 미치는 영향이 근본적으로 다릅니다.
* 이 실험에서는 스텝 크기가 `3`분의`1`인 드리프트가 오히려 독립 노이즈보다 거의 `3`배 큰 재투영 오차를 만들었습니다 — 서로 다른 방향으로 흩어진 오차는 부분적으로 상쇄되지만, 같은 방향으로 뭉친 오차는 그렇지 않기 때문입니다.
* 드리프트는 관측(프레임·점)을 아무리 늘려도 저절로 사라지지 않으며, 궤적이 길어질수록 오히려 더 커질 수 있습니다.
* 드리프트를 되돌리려면 데이터를 더 모으는 게 아니라 루프 클로저나 강체 제약처럼, 드리프트가 만들어낼 수 없는 종류의 추가 정보가 필요합니다 — 다음 장부터 이를 포즈 그래프 최적화로 구현합니다.
