== 이 책이 하려는 것

여러 카메라, 라이다, IMU를 동시에 돌리는 자율주행 로깅 차량에서 데이터를 받으면, 두 가지 문제가 거의 항상 함께 따라옵니다 — **센서마다 타임스탬프가 정확히 맞지 않는다**(타임싱크 오차)는 것과, **차량 진동·캘리브레이션 드리프트 때문에 프레임마다 카메라의 실제 위치·자세(extrinsic)가 캘리브레이션값과 조금씩 어긋난다**는 것입니다. 3D Gaussian Splatting(3DGS) 같은 재구성 기술(NVIDIA NuRec 같은 파이프라인 포함)은 "이 사진은 정확히 이 시각에, 정확히 이 위치·자세에서 찍혔다"는 전제 위에서 작동하는데, 이 전제가 조금만 깨져도 재구성 결과에 흐릿함, 고스팅(같은 물체가 두 번 겹쳐 보임), 표류하는 디테일 같은 문제가 나타납니다.

이 책은 이 두 문제 — 시간 정렬과 extrinsic 드리프트 보정 — 을 처음부터 끝까지 다루는 실무 지향적인 책입니다. 문제가 실제로 재구성 품질에 얼마나 영향을 주는지 정량적으로 확인하는 것(1부)에서 시작해, 서로 다른 주파수로 도는 센서들을 하나의 타임라인에 정렬하는 법(2부), 흔들리는 프레임간 extrinsic을 포즈 그래프 최적화로 다시 바로잡는 법(3부)을 거쳐, 이 둘을 하나의 파이프라인으로 묶고 3DGS에 넣기 전에 품질을 검증하는 법(4부)까지 쌓아 올립니다.

== 이 책의 방식: 문제를 직접 만들고, 직접 고치고, 직접 검증하고

이 시리즈의 다른 책들과 마찬가지로, 이 책의 모든 코드는 NumPy/SciPy로 직접 구현하고 실제로 실행해 검증합니다. 시간이 어긋나거나 흔들린 가짜 센서 로그를 직접 시뮬레이션해서 만들고("정답"이 무엇인지 알고 있는 상태에서 문제를 인위적으로 일으키고), 이 책에서 만든 정렬·보정 알고리즘이 그 문제를 실제로 얼마나 되돌려놓는지 정답과 비교해 수치로 확인합니다. 3부의 포즈 그래프 최적화는 이 시리즈의 "회전은 왜 어려운가"(리 군/리 대수) 책과 "모르는 곳에서 나를 찾는 법"(SLAM) 책에서 다진 `SO(3)`/`SE(3)` 도구를 그대로 가져와 씁니다 — 두 책을 먼저 읽었다면 3부가 한결 익숙하겠지만, 필요한 부분은 이 책 안에서도 다시 설명하므로 읽지 않았어도 무리 없이 따라올 수 있습니다.

== 누구를 위한 책인가

여러 센서를 동시에 기록하는 로깅 시스템을 다뤄본 적이 있거나, 3DGS/NeRF 같은 재구성 파이프라인에 실제 주행 로그를 넣어봤는데 결과물이 기대만큼 선명하지 않았던 경험이 있는 독자를 대상으로 합니다. Python과 NumPy에 익숙하다면 충분하고, 회전·자세를 다루는 수학(쿼터니언, `SE(3)`)에 익숙하지 않아도 이 책 안에서 필요한 만큼은 함께 설명합니다.
