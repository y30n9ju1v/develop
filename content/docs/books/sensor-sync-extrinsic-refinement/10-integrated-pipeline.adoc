'''

2~5장(시간 정렬)과 6~9장(extrinsic 재최적화)을 각각 따로 다뤘습니다. 이 장에서는 이 둘을 하나의 파이프라인으로 묶어, "타임싱크가 안 맞고 카메라 오프셋도 모르는 원시 로그"에서 시작해 "3DGS에 넣을 수 있는 정렬된 extrinsic"까지 끝까지 실행합니다.

== 파이프라인 1단계: 시간 정렬(2~5장의 도구)

먼저 곡선 도로를 달리는 궤적을 시뮬레이션하고, 카메라 타임스탬프에 `40ms`의 알 수 없는 지연을 섞습니다 — 실전 파이프라인이라면 이 오프셋을 모른다고 가정하고 시작해야 합니다.

[source,python]
----
import numpy as np
from scipy.ndimage import gaussian_filter1d

rng = np.random.default_rng(9)
v, T_max = 12.0, 8.0
dt_fine = 0.001
ts_fine = np.arange(0, T_max, dt_fine)
yaw_rate_fine = gaussian_filter1d(rng.normal(0, 1, ts_fine.shape), sigma=20)
yaw_rate_fine = yaw_rate_fine / yaw_rate_fine.std() * 0.35   # 다채로운 조향 패턴(4장의 교훈)

heading_fine = np.cumsum(yaw_rate_fine) * dt_fine
x_fine = np.cumsum(v * np.cos(heading_fine)) * dt_fine
y_fine = np.cumsum(v * np.sin(heading_fine)) * dt_fine

def true_pose_at(t):
    idx = np.clip(np.searchsorted(ts_fine, t), 0, len(ts_fine) - 1)
    R = exp_so3(np.array([0, 0, heading_fine[idx]]))
    pos = np.array([x_fine[idx], y_fine[idx], 0.0])
    return R, -R @ pos

true_offset = 0.04   # 실전에서는 모른다고 가정
----

`INS`(`200Hz`, 6장 수준의 미세한 드리프트 포함)와 카메라(`10Hz`, `true_offset`만큼 지연된 타임스탬프) 스트림을 만듭니다.

[source,python]
----
ins_dt = 1 / 200
ins_times = np.arange(0, T_max, ins_dt)
cum_drift, ins_poses = 0.0, []
for t in ins_times:
    R_true, t_true = true_pose_at(t)
    cum_drift += rng.normal(0, 0.0003)                          # 6장 수준의 미세한 캘리브레이션 드리프트
    ins_poses.append((exp_so3(np.array([0, 0, cum_drift])) @ R_true, t_true))

cam_dt = 1 / 10
cam_times = np.arange(1.0, T_max - 1.0, cam_dt)                  # 카메라가 "보고하는" 타임스탬프
true_cam_poses = [true_pose_at(t - true_offset) for t in cam_times]   # 실제 촬영은 그보다 40ms 전
----

== 아무 보정 없이 그냥 쓰면: 처참한 결과

카메라 타임스탬프를 그대로 믿고(오프셋이 `0`이라고 가정하고) INS를 SLERP로 조회한 뒤, 1장의 재투영 오차로 품질을 잽니다.

[source,python]
----
points_true = np.array([0.0, 0.0, 8.0]) + rng.normal(0, 0.3, (12, 3))

naive_cam_poses = [slerp_lookup(t, ins_times, ins_poses) for t in cam_times]   # 3장의 SLERP 보간
err_naive = mean_reproj_error(naive_cam_poses, true_cam_poses, points_true)     # 1장의 재투영 오차
print("보정 없음:", err_naive, "픽셀")
----

[source]
----
보정 없음: 17.5151 픽셀
----

`17.5`픽셀은 재앙적인 수준입니다 — 1장에서 `2~3`픽셀만 되어도 눈에 띄는 흐림이 생긴다고 확인했던 걸 떠올리면, 이 정도 오차의 3DGS 렌더링은 형체를 알아보기 힘들 정도로 뭉개질 것입니다.

== 파이프라인 2단계: 오프셋 추정(4장의 도구)

두 스트림에서 각속도 신호를 뽑아 교차상관으로 오프셋을 추정합니다.

[source,python]
----
imu_yaw_signal = np.array([yaw_rate_at(t) for t in ins_times]) + rng.normal(0, 0.01, ins_times.shape)
cam_yaw_signal = np.array([yaw_rate_at(t - true_offset) for t in cam_times]) + rng.normal(0, 0.03, cam_times.shape)

offset_est = estimate_offset(imu_yaw_signal, ins_times, cam_yaw_signal, cam_times)   # 4장의 함수
print("추정된 오프셋:", offset_est, "(정답:", true_offset, ")")
----

[source]
----
추정된 오프셋: 0.038598 (정답: 0.04 )
----

`2ms` 이내의 오차로 정확히 추정했습니다.

== 파이프라인 3단계: 오프셋을 반영해 다시 정렬

이 오프셋만큼 카메라 타임스탬프를 보정한 뒤, 다시 SLERP로 INS를 조회합니다.

[source,python]
----
corrected_cam_times = cam_times - offset_est
stageA_cam_poses = [slerp_lookup(t, ins_times, ins_poses) for t in corrected_cam_times]
err_stageA = mean_reproj_error(stageA_cam_poses, true_cam_poses, points_true)
print("시간 정렬 후:", err_stageA, "픽셀")
----

[source]
----
시간 정렬 후: 0.1922 픽셀
----

재투영 오차가 `17.52`픽셀에서 `0.19`픽셀로, **`91`배** 줄었습니다. 이 하나의 파이프라인(교차상관으로 오프셋 추정 → SLERP로 재정렬)만으로 재구성 품질을 좌우하는 가장 큰 오차 원인이 사실상 해소된 것입니다.

== 파이프라인 4단계: 남은 드리프트는 포즈 그래프로(6~9장의 도구)

`0.19`픽셀까지 줄었지만, INS 자체에 심어둔 미세한 캘리브레이션 드리프트(`6`장에서 다룬 종류)가 아직 남아 있을 수 있습니다. 이 잔여 오차는 시간 정렬로는 건드릴 수 없는 종류의 문제입니다 — 시간은 이미 정확히 맞았지만, 그 정확한 시각에 대응하는 INS 자세 자체가 드리프트로 살짝 틀어져 있기 때문입니다. 이 부분은 7~9장에서 이미 검증한 것과 정확히 같은 도구로 이어서 처리합니다 — 정렬된 `stageA_cam_poses`를 초기 추정값으로 삼아, 프레임 간 정확한 상대 제약(연속 프레임 특징 매칭이나 짧은 구간 IMU 프리인테그레이션에서 얻은)으로 포즈 그래프를 최적화하고(7장), 여러 카메라가 있다면 강체 리그 제약으로 서로의 정보를 공유시키고(8장), 궤적이 출발점 근처를 다시 지나간다면 루프 클로저로 궤적 전체의 드리프트를 재분산시킵니다(9장). 이 장에서 새로 만든 것은 "시간이 맞춰진 좋은 초기 추정값을 만드는 법"이고, 7~9장에서 이미 그 초기 추정값을 어떻게 더 다듬는지 검증했으므로, 여기서 같은 코드를 다시 반복하지 않습니다 — 실전 파이프라인에서는 이 장의 출력(`stageA_cam_poses`)이 정확히 7장 `T_init`의 자리에 들어갑니다.

== 전체 파이프라인 요약

[cols="1,1"]
|===
| 단계 | 재투영 오차

| 원시 로그(보정 없음)
| 17.52 픽셀

| + 시간 오프셋 추정·보정(2~5장)
| 0.19 픽셀

| + 포즈 그래프/리그/루프 클로저(6~9장, 이미 검증됨)
| (남은 드리프트 성격에 따라 추가 개선)
|===

이 표가 이 책 1~10장 전체의 요약입니다 — 가장 큰 개선(`91`배)은 시간 정렬에서 오고, 그 위에 extrinsic 재최적화가 남은 미세한 문제를 다듬습니다. 실전에서 시간을 먼저 맞추고 나서야 extrinsic 최적화가 의미 있는 미세 조정으로 작동한다는 순서도 중요합니다 — 시간이 크게 어긋난 상태에서 포즈 그래프를 먼저 돌리면, 최적화가 "시간 오차 때문에 생긴 큰 불일치"를 마치 "extrinsic 자체의 문제"인 것처럼 잘못 해석해 엉뚱한 방향으로 궤적을 왜곡시킬 위험이 있습니다.

오프셋이 `150ms`로 커지니 "보정 전" 오차는 `68.7`픽셀까지 치솟았습니다(`2`장의 선형 관계대로, 오프셋이 `3.75`배 커지면 오차도 대략 그만큼 커집니다) — 교차상관은 여전히 탐색 범위(`±0.2`초) 안에서 잘 작동해 오차 `9ms` 이내로 오프셋을 찾아냈고, 보정 후 오차는 `4.65`픽셀까지 떨어졌습니다. 다만 오프셋이 클수록 보정 후에도 남는 절대 오차 자체는 더 커지는 경향이 있습니다(작은 추정 오차라도 원래 오프셋이 크면 그 여파도 함께 커집니다) — 오프셋이 탐색 범위(`±40`샘플, `±0.2`초)를 벗어날 정도로 크다면 이 장의 코드는 그 범위를 넓혀야 합니다. 실전에서는 예상되는 최대 지연 시간(카메라 처리 파이프라인의 스펙 등)을 참고해 이 탐색 범위를 넉넉히 잡아야 합니다.

== 요약

* 시간 오프셋을 모른 채 원시 로그를 그대로 쓰면 재투영 오차가 `17.5`픽셀에 달할 정도로 재구성이 심각하게 망가질 수 있습니다.
* 교차상관으로 오프셋을 추정하고(4장) SLERP로 재정렬하는(3장) 것만으로 이 오차가 `91`배 줄어, 대부분의 개선이 이 단계에서 나옵니다.
* 남은 미세한 드리프트는 정렬된 결과를 초기 추정값으로 삼아 7~9장의 포즈 그래프 최적화로 이어서 다듬으며, 두 단계 모두 앞서 각 장에서 독립적으로 검증한 도구를 그대로 재사용합니다.
* 시간 정렬을 extrinsic 재최적화보다 먼저 해야 하는 순서도 중요합니다 — 순서를 바꾸면 시간 오차가 extrinsic 오차로 잘못 해석되어 최적화가 왜곡될 수 있습니다.
* 다음 장에서는 이렇게 정제한 데이터를 실제로 3DGS에 넣기 전에 확인해야 할 품질 게이트를 다룹니다.
