'''

1장에서 카메라 자세가 조금만 틀려도 재투영 오차가 커진다는 걸 확인했습니다. 이 장에서는 그 "조금 틀린 자세"가 어디서 오는지의 첫 번째 원인 — **타임스탬프 오차** — 를 정량적으로 다룹니다. 카메라 사진에 "이 시각의 차량 자세"라는 라벨을 붙일 때, 그 시각 자체가 몇 밀리초만 어긋나도 실제로 얼마나 큰 위치·회전 오차가 되는지 직접 계산합니다.

== 직관: 움직이는 차에서는 "언제"가 "어디"를 결정한다

시속 `54km`(초속 `15m`)로 달리는 차량에서, 카메라가 셔터를 누른 정확한 시각을 `10ms`(`0.01`초) 착각했다고 합시다. 그 `10ms` 동안 차는 `15 × 0.01 = 0.15m`, 즉 `15cm`를 이동합니다 — 사진이 실제로 찍힌 위치와, 그 사진에 붙인 "차량 자세" 라벨이 가리키는 위치가 `15cm`나 어긋난다는 뜻입니다. 이 직관을 정확한 시뮬레이션으로 검증합니다.

== 차량 궤적 시뮬레이션: 일정한 속도로 회전하며 주행

일정한 전진 속도와 일정한 회전각속도(핸들을 일정하게 꺾은 상태)로 도는 차량의 자세를, 시간의 함수로 정확히(닫힌 형태로) 계산합니다.

[source,python]
----
import numpy as np

def skew(w):
    return np.array([[0, -w[2], w[1]], [w[2], 0, -w[0]], [-w[1], w[0], 0]])

def exp_so3(w):
    theta = np.linalg.norm(w)
    if theta < 1e-8:
        return np.eye(3) + skew(w)
    axis = w / theta
    K = skew(axis)
    return np.eye(3) + np.sin(theta) * K + (1 - np.cos(theta)) * (K @ K)

v = 15.0          # 전진 속도 (m/s, 시속 54km)
yaw_rate = 0.3     # 회전각속도 (rad/s)

def pose_at_time(t):
    radius = v / yaw_rate
    heading = yaw_rate * t
    pos = np.array([radius * np.sin(heading), radius * (1 - np.cos(heading)), 0])
    R = exp_so3(np.array([0, 0, heading]))
    return R, pos
----

일정한 속도로 핸들을 일정하게 꺾으면 차량은 원을 그리며 돕니다(`radius = v / yaw_rate`가 그 회전 반경입니다) — 이 닫힌 형태 덕분에 임의의 시각 `t`에서의 정확한 자세를 오차 없이 계산할 수 있습니다.

== 타임스탬프 오차를 넣고 자세 차이를 재기

기준 시각 `t=2.0`초에서의 "정답" 자세와, 그로부터 `Δt`만큼 어긋난 시각의 자세를 비교합니다.

[source,python]
----
t0 = 2.0
R_true, pos_true = pose_at_time(t0)

for dt_ms in [1, 5, 10, 20, 50, 100]:
    dt = dt_ms / 1000.0
    R_off, pos_off = pose_at_time(t0 + dt)

    pos_err = np.linalg.norm(pos_off - pos_true)
    R_err = R_true.T @ R_off
    angle_err = np.arccos(np.clip((np.trace(R_err) - 1) / 2, -1, 1))

    print(f"Δt={dt_ms}ms: 위치 오차={pos_err:.4f}m, 회전 오차={np.degrees(angle_err):.4f}도")
----

[source]
----

Δt=5ms: 위치 오차=0.0750m, 회전 오차=0.0859도
Δt=10ms: 위치 오차=0.1500m, 회전 오차=0.1719도
Δt=20ms: 위치 오차=0.3000m, 회전 오차=0.3438도
Δt=50ms: 위치 오차=0.7500m, 회전 오차=0.8594도

----

`10ms`(자율주행 센서에서 흔히 접하는, 얼핏 심각해 보이지 않는 오차)만으로도 위치 오차가 `15cm`, 회전 오차가 `0.17`도나 됩니다. `100ms`(카메라 프레임 하나 정도의 시간)로 커지면 위치 오차가 `1.5m`에 달합니다 — 1장에서 확인했던 "회전 `1`도, 이동 `0.4%`" 수준의 오차만으로도 픽셀 단위 재투영 오차가 뚜렷했던 걸 떠올리면, 이 수준의 타임스탬프 오차가 얼마나 심각한 문제인지 감이 옵니다.

== 정확히 선형 관계: 속도×시간오차, 각속도×시간오차

각 `Δt`에 대해, "속도 × 시간 오차"(위치 오차 예측)와 "각속도 × 시간 오차"(회전 오차 예측)라는 가장 단순한 1차 근사와 실제 값을 비교합니다.

[source,python]
----
for dt_ms in [1, 5, 10, 20, 50, 100]:
    dt = dt_ms / 1000.0
    R_off, pos_off = pose_at_time(t0 + dt)
    pos_err = np.linalg.norm(pos_off - pos_true)
    print(f"Δt={dt_ms}ms: 실제 위치 오차={pos_err:.4f}m, 예측(v·Δt)={v * dt:.4f}m")
----

[source]
----

Δt=5ms: 실제 위치 오차=0.0750m, 예측(v·Δt)=0.0750m
Δt=10ms: 실제 위치 오차=0.1500m, 예측(v·Δt)=0.1500m
Δt=20ms: 실제 위치 오차=0.3000m, 예측(v·Δt)=0.3000m
Δt=50ms: 실제 위치 오차=0.7500m, 예측(v·Δt)=0.7500m
Δt=100ms: 실제 위치 오차=1.4999m, 예측(v·Δt)=1.5000m
----

`Δt=100ms`까지도 `v·Δt`라는 가장 단순한 1차 근사가 소수점 넷째 자리까지 정확히 들어맞습니다 — 이건 우연이 아니라, `Δt`가 충분히 짧으면(회전 반경에 비해 이동 거리가 작으면) 원운동도 국소적으로는 거의 직선 운동처럼 보이기 때문입니다(원의 접선 방향 속도가 그 짧은 구간 동안 거의 일정하다고 봐도 되는 것과 같은 이유입니다). 회전 오차도 마찬가지로 `yaw_rate · Δt`(라디안 단위)로 정확히 근사됩니다.

== 실전적 의미: "이 정도 싱크 오차면 괜찮다"는 감을 잡기

이 선형 관계 덕분에, 복잡한 시뮬레이션 없이도 암산으로 대략적인 영향을 가늠할 수 있습니다 — **위치 오차 ≈ 속도 × 타임스탬프 오차**, **회전 오차(라디안) ≈ 각속도 × 타임스탬프 오차**. 고속도로 주행(`v ≈ 30m/s`)에서 `1ms` 타임싱크 오차는 `3cm` 위치 오차를 만들고, 정지 신호 대기 중인 저속 주행(`v ≈ 2m/s`)에서는 같은 `1ms` 오차가 `2mm`밖에 안 됩니다 — **같은 타임스탬프 오차라도 차량 속도에 따라 그 심각성이 완전히 달라진다**는 뜻입니다. 회전도 마찬가지입니다 — 직진 구간(`yaw_rate ≈ 0`)에서는 타임싱크 오차가 회전 오차를 거의 만들지 않지만, 회전 교차로를 도는 구간에서는 같은 오차가 훨씬 큰 회전 오차로 이어집니다. 이는 회귀 테스트 시나리오를 설계할 때도 중요합니다 — 고속 직진 구간과 저속 회전 구간은 같은 타임싱크 오차에 전혀 다르게 반응하므로, 둘 다 테스트에 포함해야 합니다.

== 직접 해보기

* `yaw_rate`를 `0.3`에서 `1.0`(훨씬 급격하게 도는 코너)으로 바꾸면, 같은 `Δt=10ms`에 대해 회전 오차가 어떻게 달라지는지 확인하고, `yaw_rate · Δt`라는 1차 근사가 여전히 잘 맞는지도 확인해보세요.

.해답 보기
[%collapsible]
====
[source,python]
----
yaw_rate_sharp = 1.0

def pose_at_time_sharp(t):
    radius = v / yaw_rate_sharp
    heading = yaw_rate_sharp * t
    pos = np.array([radius * np.sin(heading), radius * (1 - np.cos(heading)), 0])
    R = exp_so3(np.array([0, 0, heading]))
    return R, pos

R_true_s, _ = pose_at_time_sharp(t0)
R_off_s, _ = pose_at_time_sharp(t0 + 0.01)
R_err_s = R_true_s.T @ R_off_s
angle_err_s = np.arccos(np.clip((np.trace(R_err_s) - 1) / 2, -1, 1))
print("실제 회전 오차:", np.degrees(angle_err_s), "도")
print("예측(yaw_rate·Δt):", np.degrees(yaw_rate_sharp * 0.01), "도")
----

[source]
----
실제 회전 오차: 0.5729577951... 도
예측(yaw_rate·Δt): 0.5729577951... 도
----

`yaw_rate`가 `0.3`에서 `1.0`으로(`3.3`배) 커지니 같은 `Δt=10ms`에서의 회전 오차도 정확히 `3.3`배(`0.17`도 → `0.57`도) 커졌고, 1차 근사도 여전히 소수점까지 정확합니다 — 급격한 코너를 도는 구간일수록 같은 타임싱크 오차가 훨씬 큰 회전 오차로 증폭된다는 걸 다시 확인했습니다. 실제 로그 데이터에서 회전 교차로나 급커브 구간의 데이터가 3DGS 재구성에서 유독 품질이 나쁘다면, 렌더링 알고리즘의 문제가 아니라 이런 타임싱크-회전 상호작용이 원인일 수 있습니다.

== 요약

* 타임스탬프 오차 `Δt`는 위치 오차로는 대략 `v · Δt`(속도 × 시간 오차), 회전 오차로는 대략 `yaw_rate · Δt`(각속도 × 시간 오차)로 정확하게(짧은 `Δt`에서는 거의 오차 없이) 변환됩니다.
* 고속도로 주행에서는 `1ms` 타임싱크 오차도 `cm` 단위 위치 오차를 만들고, `10ms`면 `15cm`, `100ms`면 `1.5m`에 이릅니다.
* 같은 타임스탬프 오차라도 차량의 속도·회전각속도에 따라 그 심각성이 크게 달라지므로, 저속/고속, 직진/회전 구간을 모두 포함한 시나리오로 테스트해야 합니다.
* 다음 장에서는 이 문제를 실제로 해결하는 첫 단계, 서로 다른 주파수로 기록되는 여러 센서를 하나의 공통 타임라인에 정렬하는 법을 다룹니다.
