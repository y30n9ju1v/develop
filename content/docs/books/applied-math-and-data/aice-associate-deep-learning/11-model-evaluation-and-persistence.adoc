10장에서 만든 CNN 모델은 프로그램이 끝나면 메모리에서 사라집니다. 실전(그리고 시험)에서는 학습한 모델을 파일로 저장해 나중에 다시 쓸 수 있어야 합니다. 이 장에서는 모델을 저장하고 불러오는 법, 그리고 전체 정확도 하나로는 보이지 않는 클래스별 성능 차이를 혼동행렬로 들여다보는 법을 다룹니다.

== 모델 저장하기

[source,python]
----
model.fit(X_train, y_train, epochs=20, batch_size=32, verbose=0, validation_data=(X_test, y_test))
print(model.evaluate(X_test, y_test, verbose=0)[1])   # 0.967

model.save("digits_cnn.keras")
----

`.keras` 확장자로 저장하면, 모델의 구조(층 구성)와 학습된 가중치, 심지어 `compile()`에서 지정한 옵티마이저 상태까지 파일 하나에 통째로 담깁니다.

== 모델 불러오기와 검증

[source,python]
----
loaded_model = keras.models.load_model("digits_cnn.keras")
acc_after = loaded_model.evaluate(X_test, y_test, verbose=0)[1]
print(acc_after)   # 0.967 (저장 전과 완전히 동일)
----

저장 전 정확도(`0.9667`)와 불러온 뒤 정확도가 소수점 이하까지 완전히 같습니다. 정확도가 우연히 같을 가능성을 배제하기 위해, 예측값 자체도 직접 비교해봅니다.

[source,python]
----
pred_before = model.predict(X_test[:20], verbose=0)
pred_after = loaded_model.predict(X_test[:20], verbose=0)
print(np.allclose(pred_before, pred_after, atol=1e-6))   # True
----

두 모델이 낸 예측 확률값이 (부동소수점 오차 이내로) 완전히 똑같습니다 — `save`/`load`가 가중치를 단 하나도 잃어버리지 않고 정확히 복원했다는 뜻입니다.

== 혼동행렬로 클래스별 성능 뜯어보기

[source,python]
----
from sklearn.metrics import confusion_matrix

y_pred = loaded_model.predict(X_test, verbose=0).argmax(axis=1)
cm = confusion_matrix(y_test, y_pred)
print(cm)
----

image::https://y30n9ju1v.github.io/develop/images/books/aice-associate-deep-learning/digits_confusion_matrix.png[손글씨 숫자 혼동행렬]

혼동행렬의 행은 실제 정답, 열은 모델의 예측입니다. 대각선(행과 열이 같은 칸)은 맞게 예측한 개수이고, 대각선 밖의 값은 헷갈린 경우입니다. 6장에서 이진 분류의 `2×2` 혼동행렬을 봤는데, 여기서는 클래스가 `10`개(숫자 `0~9`)라 `10×10` 행렬이 됩니다 — 원리는 똑같이 확장됩니다.

== 어떤 숫자가 가장 헷갈리는가

[source,python]
----
cm_offdiag = cm.copy()
np.fill_diagonal(cm_offdiag, 0)
most_confused = np.unravel_index(cm_offdiag.argmax(), cm_offdiag.shape)
print(most_confused, cm_offdiag[most_confused])
----

[source]
----
most confused pair (true, predicted): (9, 8)   count: 3
----

실제로는 `9`인데 `8`로 잘못 예측한 경우가 `3`건으로 가장 많습니다 — 손글씨로 쓴 `9`와 `8`은 둥근 부분이 비슷해서 사람이 봐도 헷갈릴 수 있는 모양이라는 걸 생각하면 납득이 가는 결과입니다. 전체 정확도(`96.7%`)라는 숫자 하나만 봐서는 "어떤 숫자를 어떤 숫자로 헷갈리는지"는 전혀 알 수 없었는데, 혼동행렬을 뜯어보고서야 이런 구체적인 패턴이 드러납니다.

== classification_report: 클래스별 정밀도·재현율 한 번에

[source,python]
----
from sklearn.metrics import classification_report

print(classification_report(y_test, y_pred, digits=3))
----

[source]
----
              precision    recall  f1-score   support
           8      0.865     0.914     0.889        35
           9      1.000     0.833     0.909        36
    accuracy                          0.967       360
----

클래스 `9`의 재현율이 `0.833`으로, 다른 대부분의 숫자(`1.000`에 가까운 값들)보다 뚜렷하게 낮습니다 — `9`인 샘플 중 `16.7%`를 다른 숫자(대부분 `8`)로 잘못 예측했다는 뜻이고, 이는 방금 혼동행렬에서 확인한 "`9→8` 오분류가 가장 많다"는 사실과 정확히 일치합니다. 클래스 `8`의 정밀도도 `0.865`로 낮은 편인데, 이건 다른 숫자(`9`뿐 아니라 `1`, `7`도 일부)가 `8`로 잘못 분류되는 경우가 있어서입니다.

[source,python]
----
per_class_acc = cm.diagonal() / cm.sum(axis=1)
print(per_class_acc.round(3))
----

[source]
----
[0.972 0.972 1.    1.    1.    1.    0.972 1.    0.914 0.833]
----

클래스별 정확도를 나열해보면 `8`(`0.914`)과 `9`(`0.833`)가 확실히 다른 숫자들보다 낮습니다 — 전체 정확도 `96.7%`라는 하나의 숫자 뒤에, 이렇게 클래스마다 다른 난이도가 숨어 있었다는 걸 확인할 수 있습니다.

== 왜 이게 중요한가

AICE 시험에서 "정확도 90% 이상 달성"처럼 전체 정확도 기준만 요구하더라도, 실전에서는 특정 클래스만 유난히 못 맞추는 모델이 문제가 되는 경우가 많습니다(예: 희귀하지만 중요한 클래스를 계속 놓치는 모델). 혼동행렬과 `classification_report`를 습관적으로 확인하는 것이, 모델을 "정확도 숫자 하나"가 아니라 "어디서 강하고 어디서 약한지"까지 이해하고 제출하는 습관입니다.

== 직접 해보기

* `model.save()` 대신 `model.save_weights()`(가중치만 저장)를 쓰고, 나중에 불러올 때는 똑같은 구조의 새 모델을 먼저 만든 뒤 `load_weights()`로 가중치만 얹어서, 이 방법도 예측이 완전히 동일하게 복원되는지 확인해보세요.

.해답 보기
[%collapsible]
====
[source,python]
----
model.save_weights("digits_cnn.weights.h5")

new_model = keras.Sequential([
    keras.Input(shape=(8, 8, 1)),
    keras.layers.Conv2D(16, (3, 3), activation="relu", padding="same"),
    keras.layers.MaxPooling2D((2, 2)),
    keras.layers.Conv2D(32, (3, 3), activation="relu", padding="same"),
    keras.layers.Flatten(),
    keras.layers.Dense(32, activation="relu"),
    keras.layers.Dense(10, activation="softmax"),
])
new_model.load_weights("digits_cnn.weights.h5")
new_model.compile(optimizer="adam", loss="sparse_categorical_crossentropy", metrics=["accuracy"])
print(new_model.evaluate(X_test, y_test, verbose=0)[1])
----

`save_weights`/`load_weights`는 가중치 숫자만 저장·복원하므로, 불러오는 쪽에서 원본과 **똑같은 층 구성**을 미리 코드로 다시 작성해둬야 합니다(층 하나라도 다르면 가중치 형태가 안 맞아 에러가 납니다). 반면 앞서 쓴 `model.save()`/`load_model()`은 층 구성 자체도 파일에 함께 저장하므로 구조를 다시 작성할 필요가 없습니다 — `save()`가 더 편리하지만, `save_weights()`는 같은 구조의 모델을 여러 번 다른 데이터로 학습시키며 가중치만 바꿔 끼우고 싶을 때 유용합니다.
====

== 요약

* `model.save()`/`keras.models.load_model()`로 모델의 구조와 가중치를 통째로 저장·복원할 수 있고, 저장 전후 예측이 완전히 동일하다는 걸 직접 확인했습니다.
* 혼동행렬은 어떤 클래스를 어떤 클래스로 헷갈리는지 구체적으로 보여주며, 전체 정확도만으로는 알 수 없는 정보를 드러냅니다.
* `classification_report`로 클래스별 정밀도·재현율을 한 번에 확인하면, 특정 클래스만 유난히 성능이 낮은 것을 놓치지 않을 수 있습니다.
* `save_weights`/`load_weights`는 가중치만 저장하는 경량 대안이지만, 불러올 때 동일한 모델 구조를 직접 다시 정의해야 합니다.
