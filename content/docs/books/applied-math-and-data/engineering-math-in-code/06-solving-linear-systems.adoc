1~2부는 미지수가 하나뿐인 문제만 다뤘습니다. 이 장부터 시작하는 3부는 **미지수가 여러 개, 서로 얽혀 있는** 문제를 다룹니다 — 그 첫걸음은 익숙한 도구인 연립방정식이지만, 그걸 행렬로 표현하고 컴퓨터가 체계적으로 풀도록 만드는 법입니다.

== 세 개의 루프가 얽힌 회로

세 개의 폐회로(mesh)가 서로 저항을 공유하며 연결된 회로를 생각해봅시다. 각 루프에 흐르는 전류를 `i1, i2, i3`라 하고, 키르히호프 전압 법칙을 각 루프에 적용하면 이런 연립방정식이 나옵니다.

[stem]
++++
\begin{aligned}
2i_1 - i_2 &= 10 \\
-i_1 + 3i_2 - i_3 &= 0 \\
-i_2 + 2i_3 &= 5
\end{aligned}
++++

`i2`가 첫째와 둘째 식에, `i2`와 `i3`가 둘째와 셋째 식에 걸쳐 등장합니다 — 어느 방정식도 혼자서는 못 풉니다. 이걸 행렬로 묶으면 $Ax = b$ 꼴이 됩니다.

== 잠깐, 행렬을 벡터에 곱한다는 게 정확히 뭘까

`Ax`(행렬 `A`를 벡터 `x`에 곱하는 것)가 이 장 전체, 그리고 이후 여러 장의 기초가 되므로, 그 계산이 정확히 무엇을 하는지 먼저 짚습니다. 벡터와 행렬 자체가 아직 낯설다면 0-3장(장바구니 가격표 예제)을 먼저 보고 와도 좋습니다. 규칙은 단순합니다 — **`A`의 `i`번째 행과 `x`를 성분별로 곱해서 다 더한 값**이 결과 벡터의 `i`번째 성분입니다.

[source,python]
----
import numpy as np

A = np.array([[2., -1., 0.],
              [-1., 3., -1.],
              [0., -1., 2.]])
i = np.array([1.0, 2.0, 3.0])  # 아무 값이나 넣어본 시험용 벡터 (연립방정식의 답이 아닙니다)

Ai = A @ i
manual = np.array([
    A[0,0]*i[0] + A[0,1]*i[1] + A[0,2]*i[2],
    A[1,0]*i[0] + A[1,1]*i[1] + A[1,2]*i[2],
    A[2,0]*i[0] + A[2,1]*i[1] + A[2,2]*i[2],
])
print("A @ i:", Ai)
print("행마다 손으로 곱해서 더한 값:", manual)
print("match:", np.allclose(Ai, manual))
----

[source]
----
A @ i: [0. 2. 4.]
행마다 손으로 곱해서 더한 값: [0. 2. 4.]
match: True
----

`A @ i`(NumPy에서 행렬곱을 뜻하는 연산자)가, `A`의 각 행을 `i`와 곱해서 더한 값을 그대로 계산합니다 — 이게 정확히 `Ax = b`가 뜻하는 바입니다. `A`의 첫째 행 `[2,-1,0]`과 미지수 벡터 `x=[i1,i2,i3]`을 이 방식으로 곱하면 `2*i1 - 1*i2 + 0*i3 = 2i1-i2`가 되는데, 이건 정확히 위 연립방정식의 첫째 줄(`2i1-i2=10`)의 왼쪽입니다 — 세 방정식을 각각 따로 쓰는 대신, 행렬 하나와 벡터 하나의 곱으로 한꺼번에 표현한 것뿐입니다.

[source,python]
----
b = np.array([10., 0., 5.])
----

== 가우스 소거법: 손으로 하던 걸 그대로 알고리즘으로

연립방정식을 손으로 풀 때 흔히 하는 일 — 한 식에 적당한 배수를 곱해서 다른 식에서 빼 미지수 하나를 지우는 것 — 을 체계적으로 반복하면 **가우스 소거법(Gaussian elimination)** 이 됩니다. 첫째 열의 대각선 아래를 전부 0으로 만들고, 그다음 둘째 열의 대각선 아래를 0으로 만드는 식으로 진행하면(**전진 소거, forward elimination**), 행렬이 위쪽 삼각형 모양(대각선 아래가 전부 0)이 됩니다 — 그러면 마지막 방정식은 미지수 하나짜리가 되어 바로 풀리고, 그 값을 위 식에 대입해 올라가면서(**후진 대입, back substitution**) 나머지를 순서대로 구합니다.

[source,python]
----
def gaussian_elimination(A, b):
    A = A.copy().astype(float)
    b = b.copy().astype(float)
    n = len(b)
    # 전진 소거: 대각선 아래를 전부 0으로
    for k in range(n-1):
        for i in range(k+1, n):
            factor = A[i,k] / A[k,k]
            A[i,k:] -= factor * A[k,k:]
            b[i] -= factor * b[k]
    # 후진 대입: 마지막 식부터 거꾸로 풀어 올라간다
    x = np.zeros(n)
    for i in range(n-1, -1, -1):
        x[i] = (b[i] - A[i,i+1:] @ x[i+1:]) / A[i,i]
    return x

x_hand = gaussian_elimination(A, b)
print("hand-rolled:", x_hand)
----

[source]
----
hand-rolled: [6.875 3.75  4.375]
----

`factor = A[i,k] / A[k,k]`가 정확히 "손으로 풀 때 곱하는 배수"이고, `A[i,k:] -= factor * A[k,k:]`가 "그 배수만큼 곱해서 빼는" 연산입니다 — 손으로 하던 소거를 한 줄씩 그대로 코드로 옮긴 것뿐입니다.

== 라이브러리 함수와 비교하고, 원래 식에 대입해 검산하기

[source,python]
----
x_np = np.linalg.solve(A, b)
print("np.linalg.solve:", x_np)
print("max diff:", np.max(np.abs(x_hand-x_np)))

print("A@x - b (0이어야 함):", A@x_hand - b)
----

[source]
----
np.linalg.solve: [6.875 3.75  4.375]
max diff: 0.0
A@x - b (0이어야 함): [0. 0. 0.]
----

손으로 짠 가우스 소거법과 NumPy의 `linalg.solve`(내부적으로는 LU 분해라는, 가우스 소거법을 행렬 형태로 정리한 더 정교한 버전을 씁니다)가 완전히 같은 답을 냅니다. 그리고 그 답을 원래 방정식에 다시 대입한 `A@x - b`가 정확히 `[0,0,0]`입니다 — "연립방정식을 풀었다"는 게 정확히 이 사실(원래 식들을 전부 동시에 만족시키는 값을 찾았다)을 뜻한다는 걸, 검산으로 확인했습니다.

== 직접 해보기

.해답 보기

[source,python]

A4 = np.array([[2., -1., 0., 0.],
               [-1., 3., -1., 0.],
               [0., -1., 2., -1.],
               [0., 0., -1., 2.]])
b4 = np.array([10., 0., 5., 3.])

x4 = gaussian_elimination(A4, b4)
print("hand-rolled:", x4)
print("np.linalg.solve:", np.linalg.solve(A4, b4))
print("A4@x4 - b4:", A4@x4 - b4)
----

`gaussian_elimination` 함수는 코드를 한 글자도 안 바꿨는데도 `4×4` 시스템에 그대로 동작합니다 — `n = len(b)`로 크기를 자동으로 알아내는 식으로 짰기 때문입니다. `3×3`이든 `4×4`든 "대각선 아래를 지우고, 거꾸로 풀어 올라간다"는 알고리즘 자체는 크기에 상관없이 똑같습니다.

== 요약

* 세 루프가 얽힌 회로에서 나오는 연립방정식을 행렬 형태(`Ax=b`)로 묶고, 가우스 소거법(전진 소거 + 후진 대입)을 직접 구현해서 풀었습니다.
* 손으로 짠 결과가 `np.linalg.solve`와 정확히 일치하고, 원래 방정식에 대입하면 정확히 0이 된다는 걸(`A@x-b=[0,0,0]`) 검산으로 확인했습니다.
* 이 알고리즘이 미지수 개수와 무관하게 똑같은 절차(대각선 아래 소거 → 거꾸로 대입)로 동작한다는 것도 4개짜리 시스템으로 확인했습니다.

다음 장에서는 "이 방정식이 항상 유일한 답을 갖는가"라는 질문을 다룹니다 — 답이 무한히 많거나 아예 없는 경우가 실제로 어떻게 생기는지, 그리고 그걸 미리 알아채는 도구(랭크)를 다룹니다.
