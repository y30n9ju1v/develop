'''

로봇의 자세(pose)는 회전만이 아니라 위치(이동)도 포함합니다. "회전 행렬 `R`과 이동 벡터 `t`를 따로 들고 다니면 되지 않나?"라고 생각할 수 있지만, 두 자세를 합성하거나(로봇이 A만큼 이동한 뒤 다시 B만큼 이동), 자세의 불확실성을 다루려면 회전과 이동을 하나의 대수적 구조로 묶는 게 훨씬 깔끔합니다. 이 장에서는 그 구조 — `SE(3)`(Special Euclidean group of dimension 3, 강체 운동군) — 를 `4x4` 동차행렬(homogeneous matrix)로 구현합니다.

== 4x4 동차행렬로 자세 표현하기

`3x3` 회전 `R`과 `3`차원 이동 `t`를 `4x4` 행렬 하나로 묶습니다.

[source,python]
----
import numpy as np

def make_se3(R, t):
    T = np.eye(4)
    T[:3, :3] = R
    T[:3, 3] = t
    return T

def random_so3(rng):
    A = rng.standard_normal((3, 3))
    Q, R = np.linalg.qr(A)
    Q = Q @ np.diag(np.sign(np.diag(R)))
    if np.linalg.det(Q) < 0:
        Q[:, 0] *= -1
    return Q

rng = np.random.default_rng(3)
R1, t1 = random_so3(rng), rng.standard_normal(3)
T1 = make_se3(R1, t1)
print(T1)
----

`4`번째 행이 `[0, 0, 0, 1]`로 고정된 이 특수한 구조 덕분에, 점 하나를 변환하는 것도, 자세 두 개를 합성하는 것도 **행렬 곱셈 하나**로 통일됩니다.

== 점 변환: 동차좌표로 회전과 이동을 한 번에

`3`차원 점 `p`에 `1`을 붙여 `4`차원 동차좌표로 만들면, `T @ p_h`가 정확히 `R @ p + t`(먼저 회전하고 이동)와 같아집니다.

[source,python]
----
p = rng.standard_normal(3)
p_homogeneous = np.append(p, 1.0)
p_transformed = (T1 @ p_homogeneous)[:3]

print(np.allclose(p_transformed, R1 @ p + t1))
----

[source]
----
True
----

회전과 이동을 따로 계산해서 더하는 것과, `T1` 하나를 곱하는 것이 정확히 같은 결과를 줍니다. 이 통일이 `SE(3)`을 쓰는 실전적인 이유 중 하나입니다 — 카메라 캘리브레이션, 로봇 좌표계 변환, 포즈 그래프 최적화 어디서나 "점을 변환한다"는 연산이 행렬 곱셈 하나로 끝납니다.

== SE(3)도 군이다: 공리 확인

`SE(3)`이 `4x4` 행렬 곱셈을 연산으로 하는 군이라는 것을, `SO(3)`에서 했던 것과 똑같은 방식으로 확인합니다.

=== 역원: 회전은 전치, 이동은 -R^T t

일반적인 `4x4` 역행렬을 계산할 필요 없이, `SE(3)`의 구조를 이용한 닫힌 형태 공식이 있습니다.

[source,python]
----
def se3_inv(T):
    R, t = T[:3, :3], T[:3, 3]
    T_inv = np.eye(4)
    T_inv[:3, :3] = R.T
    T_inv[:3, 3] = -R.T @ t
    return T_inv

T1_inv = se3_inv(T1)
print(np.allclose(T1 @ T1_inv, np.eye(4)))
print(np.allclose(np.linalg.inv(T1), T1_inv))    # 일반 역행렬과 정확히 일치
----

[source]
----
True
True
----

`-R^T t`라는 이동 부분이 처음엔 어색해 보이지만, 기하학적으로는 자명합니다 — "회전 `R`만큼 돌고 `t`만큼 이동한 것"을 되돌리려면, 먼저 `-t`만큼 되돌아간 뒤 `R^T`(역회전)만큼 돌아야 하는데, 이 순서를 하나의 `SE(3)` 원소로 정리하면 `-R^T t`가 됩니다. `NumPy`의 일반 `4x4` 역행렬 계산(`np.linalg.inv`)과 완전히 같은 결과를 주지만, 이 공식은 가우스 소거 없이 전치와 행렬-벡터 곱만으로 계산됩니다.

=== 닫힘: 두 자세의 합성이 여전히 SE(3)

[source,python]
----
R2, t2 = random_so3(rng), rng.standard_normal(3)
T2 = make_se3(R2, t2)
T3 = T1 @ T2

print(np.allclose(T3[:3, :3], R1 @ R2))
print(np.allclose(T3[:3, 3], R1 @ t2 + t1))
----

[source]
----
True
True
----

`T1 @ T2`의 회전 부분은 예상대로 `R1 @ R2`이지만, 이동 부분은 단순히 `t1 + t2`가 **아니라** `R1 @ t2 + t1`입니다 — `T2`의 이동이 `T1`의 회전 좌표계 기준으로 다시 회전된 뒤 더해집니다. 이게 회전과 이동을 따로 다룰 때 흔히 저지르는 실수(이동을 그냥 더해버리는 것)이고, `SE(3)` 동차행렬을 쓰면 이 회전-이동 결합이 행렬 곱셈에 자동으로 녹아 있어 실수할 여지가 없습니다.

=== 비가환성: SO(3)에서 물려받다

[source,python]
----
print(np.allclose(T1 @ T2, T2 @ T1))
----

[source]
----
False
----

`SO(3)`이 비가환군이었으니 `SE(3)`도 당연히 비가환군입니다 — "A만큼 이동한 뒤 B만큼 회전"과 "B만큼 회전한 뒤 A만큼 이동"은 다른 최종 자세를 만듭니다. 로봇이 "앞으로 `1m` 간 뒤 `90도` 회전"한 것과 "`90도` 회전한 뒤 앞으로 `1m`"이 완전히 다른 곳에 도착한다는 걸 떠올리면 직관적입니다.

== 왜 회전과 이동을 분리하면 안 되는가

혹시 "그냥 회전 `R`과 이동 `t`를 각각의 `SO(3)`, `R^3` 원소로 따로 다루면 안 되나?"라는 의문이 들 수 있습니다. 수학적으로는 가능합니다만(이를 "직접곱(direct product)" 구조라 부릅니다), `SE(3)`은 그것과 다릅니다 — 방금 확인했듯 `T1 @ T2`의 이동 부분이 `t1 + t2`가 아니라 `R1 @ t2 + t1`이기 때문입니다. 이 "뒤엉킴(coupling)"이 바로 강체가 실제로 움직이는 방식(회전하면 그 좌표계에 물려 있던 이동도 함께 회전한다)을 정확히 반영하는 것이고, 만약 회전과 이동을 정말 독립적으로(뒤엉킴 없이) 다루고 싶다면 그건 `SE(3)`이 아니라 다른 구조가 필요합니다.

다음 장에서는 이 `SE(3)`에도 5~6장에서 `SO(3)`에 했던 것과 같은 지수/로그 사상을 만듭니다 — 다만 이번엔 리 대수 `se(3)`의 원소가 회전 각속도뿐 아니라 "선속도"까지 포함하는 `6`차원 벡터(트위스트, twist)가 되고, 지수 사상 공식에도 `SO(3)`에는 없던 새로운 항이 등장합니다.

== 직접 해보기

* `T1 @ T2`와 `T2 @ T1`의 회전 부분과 이동 부분이 각각 어떻게 다른지 따로 출력해서, 회전 부분의 차이(`R1@R2` vs `R2@R1`, 6장에서 다룬 비가환성)와 이동 부분의 차이가 어떻게 서로 얽혀 있는지 확인해보세요.

== 요약

* `SE(3)`은 회전 `R`과 이동 `t`를 `4x4` 동차행렬로 묶은 것이며, 점 변환(`T @ p_h`)과 자세 합성(`T1 @ T2`) 모두 행렬 곱셈 하나로 통일됩니다.
* `SE(3)`의 역원은 `(R, t)⁻¹ = (R^T, -R^T t)`라는 닫힌 형태로 계산되며, 일반 `4x4` 역행렬과 정확히 일치합니다.
* 두 자세를 합성할 때 이동 부분은 `t1+t2`가 아니라 `R1@t2 + t1`으로, 회전과 이동이 뒤엉켜 있습니다 — 이 뒤엉킴이 강체 운동의 실제 성질을 정확히 반영합니다.
* `SO(3)`의 비가환성이 `SE(3)`에도 그대로 상속되어, 회전과 이동을 어떤 순서로 합성하느냐가 최종 자세에 영향을 줍니다.
* 다음 장에서는 `SE(3)`의 리 대수 `se(3)`(트위스트, `6`차원)과 그 지수/로그 사상을 구현합니다.
