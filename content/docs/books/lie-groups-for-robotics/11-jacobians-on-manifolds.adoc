10장에서 `R ⊞ δ = R @ exp(δ)`라는 연산을 정의했습니다. 그런데 사실 `⊞`를 정의하는 방법이 이것 하나만은 아닙니다 — `exp(δ) @ R`(증분을 왼쪽에 곱하기)도 똑같이 유효한 정의입니다. 어느 쪽을 쓰느냐에 따라 같은 함수의 야코비안이 다른 행렬로 나오고, 실전 SLAM/최적화 라이브러리마다 관례가 다릅니다. 이 장에서는 이 두 관례 — **오른쪽 섭동(right perturbation)**과 **왼쪽 섭동(left perturbation)** — 를 같은 함수에 각각 적용해 야코비안을 유도하고, 왜 둘이 다른지 확인합니다.

== 예제 함수: 회전으로 점 옮기기

`y = R @ p`(고정된 점 `p`를 회전 `R`로 옮긴 결과)를 `R`에 대해 미분하는 문제를 생각합니다. `R`은 `SO(3)`에 살고 있으니, "`R`에 대해 미분한다"는 말 자체가 리 대수 벡터 `δ`에 대한 미분(`R`을 `δ`로 섭동시켰을 때 `y`가 얼마나 변하는가)으로 정의해야 합니다.

[source,python]
----
import numpy as np

def skew(w):
    return np.array([[0, -w[2], w[1]], [w[2], 0, -w[0]], [-w[1], w[0], 0]])

def exp_so3(w):
    theta = np.linalg.norm(w)
    if theta < 1e-8:
        return np.eye(3) + skew(w)
    axis = w / theta
    K = skew(axis)
    return np.eye(3) + np.sin(theta) * K + (1 - np.cos(theta)) * (K @ K)

def random_so3(rng):
    A = rng.standard_normal((3, 3))
    Q, R = np.linalg.qr(A)
    Q = Q @ np.diag(np.sign(np.diag(R)))
    if np.linalg.det(Q) < 0:
        Q[:, 0] *= -1
    return Q

rng = np.random.default_rng(9)
R = random_so3(rng)
p = rng.standard_normal(3)
----

== 오른쪽 섭동: R → R @ exp(δ)

증분을 오른쪽에 곱하는 관례입니다 — "몸체 좌표계 기준으로 조금 더 회전시킨다"는 의미로 해석할 수 있습니다.

[source,python]
----
def f_right(delta):
    return (R @ exp_so3(delta)) @ p

def numerical_jacobian(f, dim=3, eps=1e-6):
    f0 = f(np.zeros(dim))
    J = np.zeros((len(f0), dim))
    for i in range(dim):
        d = np.zeros(dim)
        d[i] = eps
        J[:, i] = (f(d) - f(-d)) / (2 * eps)
    return J

J_right_numeric = numerical_jacobian(f_right)
J_right_analytic = -R @ skew(p)

print(np.allclose(J_right_numeric, J_right_analytic, atol=1e-5))
----

[source]
----
True
----

해석적 공식 `-R @ skew(p)`는 `exp(δ) ≈ I + skew(δ)`(1차 근사, 4장에서 확인한 성질)를 대입해서 유도됩니다 — `R @ (I + skew(δ)) @ p = Rp + R @ skew(δ) @ p`이고, `skew(δ) @ p = -skew(p) @ δ`(외적의 반대칭성)이므로 `δ`에 대한 선형 계수가 `-R @ skew(p)`가 됩니다.

== 왼쪽 섭동: R → exp(δ) @ R

증분을 왼쪽에 곱하는 관례입니다 — "세계 좌표계 기준으로 조금 더 회전시킨다"는 의미로 해석할 수 있습니다.

[source,python]
----
def f_left(delta):
    return (exp_so3(delta) @ R) @ p

J_left_numeric = numerical_jacobian(f_left)
J_left_analytic = -skew(R @ p)

print(np.allclose(J_left_numeric, J_left_analytic, atol=1e-5))
----

[source]
----
True
----

같은 방식으로 유도하면 이번엔 `-skew(R @ p)`(이미 회전된 점 `Rp`에 대한 반대칭 행렬)가 나옵니다 — `p` 자체가 아니라 `Rp`가 들어간다는 게 오른쪽 섭동과의 핵심적인 차이입니다.

== 두 야코비안은 실제로 다르다

[source,python]
----
print(np.allclose(J_right_numeric, J_left_numeric))
print("오른쪽 섭동 야코비안:\n", np.round(J_right_analytic, 3))
print("왼쪽 섭동 야코비안:\n", np.round(J_left_analytic, 3))
----

두 야코비안이 다른 행렬입니다. 이게 버그가 아니라 **다른 질문에 대한 다른 답**이라는 걸 이해하는 게 중요합니다 — 오른쪽 섭동은 "`R`을 몸체 좌표계 기준으로 조금 바꾸면 `y`가 어떻게 변하는가", 왼쪽 섭동은 "`R`을 세계 좌표계 기준으로 조금 바꾸면 `y`가 어떻게 변하는가"를 묻고 있고, 두 질문의 답이 다른 게 당연합니다.

== 실전에서 왜 중요한가: 관례를 섞으면 최적화가 깨진다

12장에서 만들 포즈 그래프 최적화는 여러 잔차(residual)의 야코비안을 모아 하나의 선형계를 풉니다. 만약 어떤 잔차는 오른쪽 섭동 야코비안으로, 다른 잔차는 왼쪽 섭동 야코비안으로 계산해서 섞어버리면(실전에서 실제로 발생하는 실수입니다 — 라이브러리마다 관례가 다르고, 직접 유도한 야코비안과 라이브러리가 기대하는 관례가 다를 수 있습니다), 최적화가 수렴하지 않거나 엉뚱한 방향으로 발산합니다. 두 야코비안 모두 `θ→0` 근처에서는 정확하지만(둘 다 방금 유한차분으로 검증했듯 정확한 도함수입니다), 최적화 스텝을 `⊞`로 되돌릴 때(10장) 오른쪽 섭동으로 계산한 야코비안은 반드시 오른쪽 `⊞`(`R @ exp(δ)`)로, 왼쪽 섭동으로 계산한 야코비안은 반드시 왼쪽 `⊞`(`exp(δ) @ R`)로 갱신해야 한다는 **일관성**이 중요합니다.

이 책의 나머지 장(12장 포즈 그래프, 13장 IMU 프리인테그레이션)에서는 일관되게 오른쪽 섭동(몸체 좌표계 기준 증분)을 사용합니다 — 로봇공학에서 더 흔히 쓰이는 관례이고, 9장의 애드조인트가 정확히 두 관례 사이를 오가는 변환을 제공합니다(`왼쪽 야코비안 = 오른쪽 야코비안 @ Ad_R`라는 관계가 성립합니다).

== 직접 해보기

* `왼쪽 야코비안 = 오른쪽 야코비안 @ Ad_R`(여기서 `Ad_R = R`, `SO(3)`의 애드조인트는 9장에서 확인했듯 그냥 `R`)이라는 관계가 실제로 성립하는지 확인해보세요.

.해답 보기
[%collapsible]
====
[source,python]
----
J_left_from_right = J_right_analytic @ R.T   # Ad_R = R이고 관계식은 J_left = J_right @ R^{-1} = J_right @ R^T
print(np.allclose(J_left_from_right, J_left_analytic))
----

[source]
----
True
----

`J_right @ R^T`가 정확히 `J_left`와 일치합니다. 직관적으로는, 오른쪽 섭동(`Rδ`, 몸체 기준)을 왼쪽 섭동(세계 기준)의 언어로 바꾸려면 몸체 기준 증분을 현재 회전 `R`로 세계 좌표계에 옮겨야 하는데(9장에서 다룬, 좌표계를 바꿔가며 트위스트를 옮기는 것과 정확히 같은 아이디어), 이 변환이 바로 `Ad_R = R`입니다. 두 야코비안이 서로 무관한 두 공식이 아니라, 애드조인트 하나로 정확히 연결되는 같은 사실의 두 표현이라는 것을 확인했습니다.
====

== 요약

* 같은 함수 `y = R @ p`의 야코비안도 `R`을 어떻게 섭동시키느냐(오른쪽 `R @ exp(δ)` vs 왼쪽 `exp(δ) @ R`)에 따라 `-R @ skew(p)`와 `-skew(R @ p)`라는 서로 다른 행렬로 나옵니다.
* 두 야코비안 모두 유한차분으로 정확함이 확인되는 올바른 도함수이며, 어느 게 "맞다"가 아니라 서로 다른 질문(몸체 기준 vs 세계 기준 섭동)에 대한 답입니다.
* 실전 최적화에서는 야코비안 계산과 `⊞` 갱신에 같은 섭동 관례를 일관되게 써야 하며, 두 관례를 섞으면 최적화가 깨집니다.
* 두 야코비안은 `J_left = J_right @ Ad_R`(`SO(3)`에서는 `Ad_R = R`)이라는 관계로 애드조인트를 통해 정확히 연결됩니다.
* 다음 장에서는 이 오른쪽 섭동 야코비안을 실제 포즈 그래프 최적화(비선형 최소제곱)에 적용해, 여러 `SE(3)` 자세를 동시에 최적화합니다.
