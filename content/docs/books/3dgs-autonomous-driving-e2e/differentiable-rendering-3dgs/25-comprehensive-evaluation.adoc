'''

이 책 전체에서 쌓은 지표들을 하나로 모읍니다. 렌더링 엔진에 실제로 있을 법한 버그 — **색 공간 변환 실수로 R(빨강)과 B(파랑) 채널이 뒤바뀌는 것** — 를 시뮬레이션하고, 지금까지 배운 지표들이 이 버그를 각각 얼마나 잘(혹은 못) 잡아내는지 직접 확인합니다.

== 시나리오: 색이 뒤바뀐 렌더러 버전

빨간빛이 도는 물체(`R=0.9, G=0.5, B=0.2` 정도의 색)를 여러 시점에서 촬영한 "정답" 이미지 `6`장을 만들고, 두 개의 렌더러로 각각 렌더링합니다.

[source,python]
----
import numpy as np
from scipy.ndimage import gaussian_filter

def make_view_rgb(N, cx, cy, size):
    img = np.zeros((N, N))
    half = size // 2
    img[cy - half:cy + half, cx - half:cx + half] = 1.0
    img = gaussian_filter(img, sigma=1.0)
    r, g, b = img * 0.9, img * 0.5, img * 0.2   # 붉은 빛이 도는 물체
    return np.stack([r, g, b], axis=2)

N = 48
gt_views = []
for k in range(6):
    cx, cy = 24 + int(3 * np.sin(k)), 24 + int(2 * np.cos(k))
    gt_views.append(make_view_rgb(N, cx, cy, size=16))
----

[source,python]
----
rng = np.random.default_rng(4)

def render_v1(gt):                          # v1: 정상 렌더러
    noise = rng.normal(0, 0.01, gt.shape)
    return np.clip(gaussian_filter(gt, sigma=(0.3, 0.3, 0)) + noise, 0, 1)

def render_v2_buggy(gt):                     # v2: 색 공간 버그가 섞인 새 버전
    noise = rng.normal(0, 0.01, gt.shape)
    rendered = np.clip(gaussian_filter(gt, sigma=(0.3, 0.3, 0)) + noise, 0, 1)
    return rendered[:, :, [2, 1, 0]]         # R, B 채널이 뒤바뀜(19장의 색맹 문제와 같은 조작)
----

`v1`은 정상적인 렌더러이고, `v2`는 구조·흐림 정도는 `v1`과 완전히 같지만 색 채널 순서가 뒤바뀌는 버그가 있다고 가정합니다 — 물체가 원래 붉었어야 하는데 이제는 파랗게 렌더링됩니다. 실제로 이런 버그(색 공간 변환 실수, 채널 순서 실수)는 렌더링 파이프라인에서 드물지 않게 발생합니다.

== PSNR/SSIM 기반 리포트: 버그가 보이는가

지금까지처럼 그레이스케일로 변환한 뒤 PSNR과 SSIM을 계산해, `v1`과 `v2`를 나란히 놓고 비교하는 흔한 회귀 테스트 리포트를 만들어봅니다.

[source,python]
----
def mse(a, b):
    return np.mean((a - b) ** 2)

def psnr(a, b, max_val=1.0):
    m = mse(a, b)
    return float('inf') if m == 0 else 10 * np.log10((max_val ** 2) / m)

rows = []
for k, gt in enumerate(gt_views):
    v1, v2 = render_v1(gt), render_v2_buggy(gt)
    gt_gray, v1_gray, v2_gray = gt.mean(axis=2), v1.mean(axis=2), v2.mean(axis=2)
    p1, p2 = psnr(gt_gray, v1_gray), psnr(gt_gray, v2_gray)
    s1, s2 = windowed_ssim(gt_gray, v1_gray), windowed_ssim(gt_gray, v2_gray)   # 18장의 함수
    rows.append((p1, p2, s1, s2))
    print(f"시점 {k}: PSNR v1={p1:.2f} v2={p2:.2f} | SSIM v1={s1:.4f} v2={s2:.4f}")

rows = np.array(rows)
print("평균 PSNR: v1 =", rows[:, 0].mean(), ", v2 =", rows[:, 1].mean())
print("평균 SSIM: v1 =", rows[:, 2].mean(), ", v2 =", rows[:, 3].mean())
----

충격적인 결과입니다 — 평균 PSNR은 `v2`(`45.53`dB)가 `v1`(`45.49`dB)보다 **오히려 살짝 더 높습니다**. 평균 SSIM은 `v2`가 아주 조금 낮지만(`0.8862` vs `0.8885`), 이 정도 차이는 18장에서 봤던 정상적인 표본 변동 범위 안에 있어 보입니다. 이 리포트만 본다면 "`v2`는 `v1`과 사실상 동등하거나 오히려 더 낫다"고 결론 내리고, 색이 완전히 뒤바뀌는 심각한 버그를 그대로 배포하게 됩니다. 13장에서 확인했던 그레이스케일 변환의 성질(`R`과 `B`를 바꿔도 평균은 그대로) 때문에, 그레이스케일에 기반한 두 지표 모두 이 버그에 원리적으로 눈이 멀어 있는 것입니다.

== 색상 지표 하나만 추가하면

이 버그를 잡기 위해 아주 간단한 지표 하나만 추가합니다 — 이미지 전체의 평균 RGB 색상이 정답과 얼마나 다른지 재는 것뿐입니다.

[source,python]
----
def color_distance(a_rgb, b_rgb):
    return np.linalg.norm(a_rgb.mean(axis=(0, 1)) - b_rgb.mean(axis=(0, 1)))

color_rows = []
for k, gt in enumerate(gt_views):
    v1, v2 = render_v1(gt), render_v2_buggy(gt)
    c1, c2 = color_distance(gt, v1), color_distance(gt, v2)
    color_rows.append((c1, c2))
    print(f"시점 {k}: 색상 거리 v1={c1:.4f}, v2={c2:.4f}")

color_rows = np.array(color_rows)
print("평균 색상 거리: v1 =", color_rows[:, 0].mean(), ", v2 =", color_rows[:, 1].mean())
----

이번엔 명확합니다 — `v2`의 색상 거리(`0.1101`)가 `v1`(`0.0057`)보다 **약 `19`배** 크고, 이 차이가 `6`개 시점 **모두**에서 거의 완벽하게 일관됩니다(`v1`은 항상 `0.005~0.006`대, `v2`는 항상 `0.110`대). PSNR·SSIM이 완전히 놓쳤던 문제를, 지표 하나를 추가하는 것만으로 확실하게 잡아냈습니다.

== 종합 리포트와 판정 기준

실전 회귀 테스트는 보통 "이 지표가 이 임계값을 넘으면 실패"라는 규칙(게이트)을 씁니다. 이번 실험 결과로 세 가지 규칙을 세워봅니다.

[cols="1,1,1,1"]
|===
| 지표 | v1 (기준) | v2 (신버전) | 판정

| 평균 PSNR (임계값: 기준 대비 -1dB 이내)
| 45.49
| 45.53
| 통과 (버그를 못 잡음)

| 평균 SSIM (임계값: 기준 대비 -0.02 이내)
| 0.8885
| 0.8862
| 통과 (버그를 못 잡음)

| 평균 색상 거리 (임계값: 0.05 이내)
| 0.0057
| 0.1101
| *실패* (버그를 정확히 잡음)
|===

PSNR과 SSIM 게이트만 갖춘 회귀 테스트라면 이 버그가 있는 버전을 그대로 통과시켰을 것입니다. 색상 지표라는 서로 다른 종류의 검사 하나를 추가함으로써, 다른 두 지표의 사각지대를 정확히 메웠습니다 — 이게 1~23장에 걸쳐 이 책이 반복해서 보여준 교훈입니다 — **어떤 지표든 특정 종류의 문제에는 원리적으로 눈이 멀어 있고, 그 사각지대는 다른 성격의 지표로만 메울 수 있습니다.**

== 이 책의 지표들을 정리하면

[cols="1,2"]
|===
| 지표 | 무엇을 잡는가, 무엇을 놓치는가

| MSE/PSNR (2~16장)
| 전반적인 밝기 차이는 잘 잡지만, 오차의 위치(구조 vs 무작위)를 구별 못 함

| SSIM (5~19장)
| 구조적 손상(노이즈)을 흐림보다 더 잘 잡지만, 미세한 정렬 오차에 과민하고 색은 아예 못 봄

| 지각적 지표/LPIPS 아이디어 (8~21장)
| 위치 이동에 둔감하면서 진짜 내용 차이는 잡지만, 설계(격자 크기 등)에 따라 성능이 크게 달라짐

| FID (10~23장)
| 개별 이미지가 아니라 집합 전체의 다양성·분포 차이를 잡지만, 충분히 큰 표본이 필요함

| 색상 거리 (이 장)
| 그레이스케일 기반 지표가 원리적으로 놓치는 색 채널 문제를 잡음
|===

실전에서 "3DGS 렌더링이 진짜와 같은가"를 판정할 때도 정확히 이런 조합이 필요합니다 — 어느 지표 하나도 혼자서는 충분하지 않고, 서로 다른 종류의 실패를 겨냥한 여러 지표를 함께 봐야, 그리고 24장에서 확인했듯 시나리오별로 나눠 봐야, "이 정도면 진짜와 같다고 믿을 만하다"는 판단에 실제로 신뢰가 생깁니다.

== 직접 해보기

* 이번엔 `G`(초록)와 `B`(파랑) 채널만 뒤바뀌는 버그(`rendered[:, :, [0, 2, 1]]`)를 시뮬레이션해서, 색상 거리 지표가 이것도 잡아내는지, 그리고 원래 물체의 색(`R=0.9, G=0.5, B=0.2`)에서 `G`와 `B`를 바꾸면 색 차이가 `R`과 `B`를 바꿀 때보다 더 큰지 작은지 확인해보세요.

`R`/`B` 교환(`0.110`)보다 `G`/`B` 교환(`0.047`)의 색상 거리가 훨씬 작습니다 — 원래 물체의 색(`R=0.9, G=0.5, B=0.2`)에서 `R`과 `B`의 차이(`0.7`)가 `G`와 `B`의 차이(`0.3`)보다 훨씬 크기 때문에, 두 채널을 바꿨을 때 생기는 색상 변화도 그만큼 더 큽니다. 이건 색상 거리 지표에도 한계가 있다는 뜻입니다 — 애초에 두 채널의 값 차이가 작은 물체(예: 회색에 가까운 물체)라면, 채널이 뒤바뀌어도 색상 거리가 작게 나와서 버그를 놓칠 수 있습니다. 어떤 지표도 모든 상황에서 완벽하지 않다는 걸 이 책의 마지막 예제에서도 다시 한번 확인하는 셈입니다 — 그래서 24장의 원칙(여러 지표를 함께, 시나리오를 나눠서 본다)이 결국 가장 중요합니다.

== 요약

* 색 채널이 뒤바뀌는 심각한 렌더링 버그를 그레이스케일 기반 PSNR/SSIM은 전혀 잡아내지 못했고, 심지어 PSNR은 버그가 있는 버전에 더 높은 점수를 줬습니다.
* 평균 RGB 색상 거리라는 아주 간단한 지표 하나를 추가하는 것만으로, 이 버그를 모든 시점에서 일관되게(`19`배 차이) 잡아낼 수 있었습니다.
* 이 책에서 다룬 모든 지표는 각자 특정한 종류의 문제에 원리적으로 눈이 멀어 있으며, 실전 회귀 테스트는 이 사각지대들을 서로 다른 지표들의 조합으로 메워야 합니다.
* 색상 거리 지표조차도 완벽하지 않습니다(채널 간 값 차이가 작은 경우 버그를 놓칠 수 있음) — "어떤 지표도 만능이 아니다"는 이 책 전체의 교훈이 마지막 예제에서도 그대로 재확인됩니다.
