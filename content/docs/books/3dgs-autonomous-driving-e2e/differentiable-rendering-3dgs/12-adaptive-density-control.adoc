'''

3장 연습문제에서 이미 확인한 사실이 있습니다 — 목표 이미지에 분리된 blob이 3개인데 가우시안이 2개뿐이면, 아무리 경사하강법을 오래 돌려도 손실이 특정 수준 이하로 내려가지 않았습니다(0.10 vs 3개 사용 시 0.10 — 구조적으로 표현 불가능했습니다). 지금까지 10~11장에서 배운 색상·위치 그래디언트는 **가우시안 개수가 고정된 상태에서** 파라미터를 조정하는 방법이었습니다. 이 장에서는 학습 도중 가우시안의 **개수 자체**를 조절하는 방법 — 3DGS 논문이 "적응적 밀도 제어(adaptive density control)"라고 부르는 절차 — 을 다룹니다.

== 표현력이 부족한 상황 재현하기

목표 이미지는 서로 떨어진 두 개의 원형 blob이지만, 시작은 그 사이에 걸쳐진 가우시안 하나뿐입니다.

[source,python]
----
true_gaussians = [
    make_gaussian([8, 16], 2.5, 2.0, 0, 2.0, [0.9, 0.3, 0.2], 0.9),
    make_gaussian([24, 16], 2.5, 2.0, 0, 2.0, [0.2, 0.4, 0.9], 0.9),
]
target_img, _ = rasterize_full(true_gaussians, H, W)

one_gaussian = [make_gaussian([16, 16], 6.0, 3.0, 0, 2.0, [0.5, 0.35, 0.55], 0.9)]
img1, _ = rasterize_full(one_gaussian, H, W)
loss1 = l2_loss(img1, target_img)
print(loss1)  # 0.00979
----

가우시안 하나로는 두 blob의 중간에 걸친 흐릿한 보라색 타원 하나가 최선입니다 — 8~11장에서 배운 어떤 그래디언트를 쓰든, 가우시안 하나로는 이 손실(`0.0098`)보다 크게 나아질 수 없습니다. 구조 자체가 부족하기 때문입니다.

== 분열(Split): 큰 가우시안 하나를 작은 가우시안 둘로

3DGS의 해법은, 학습 중 "충분히 표현하지 못하고 있는" 가우시안을 감지해서 두 개로 쪼개는 것입니다. 어느 방향으로 쪼갤지는 가우시안의 **가장 긴 주축 방향**(공분산의 최대 고유벡터)을 씁니다 — 그 방향이 그 가우시안이 "너무 퍼져 있는" 방향이기 때문입니다.

[source,python]
----
def split_gaussian(g, offset_scale=0.5):
    eigvals, eigvecs = np.linalg.eigh(g.Sigma2d)
    i_max = np.argmax(eigvals)
    direction = eigvecs[:, i_max]
    offset = direction * np.sqrt(eigvals[i_max]) * offset_scale
    new_scale_factor = 0.6  # 3DGS 논문의 관행: 분열된 가우시안은 원래보다 작게
    Sigma_small = g.Sigma2d * (new_scale_factor ** 2)
    g1 = SplatGaussian(g.mu2d + offset, Sigma_small, g.depth, g.color.copy(), g.opacity)
    g2 = SplatGaussian(g.mu2d - offset, Sigma_small, g.depth, g.color.copy(), g.opacity)
    return [g1, g2]
----

원래 가우시안의 색과 불투명도는 그대로 물려받고, 위치는 주축을 따라 반대 방향으로 밀어내고, 크기는 (겹치는 영역이 너무 커지지 않도록) `0.6`배로 줄입니다.

[source]
----
split centers: [19. 16.] [13. 16.]
loss right after split: 0.008990995502238398
----

분열 직후에는 손실이 거의 그대로입니다(`0.0098→0.0090`) — 당연합니다, 아직 위치를 학습시키지 않았으니까요. 하지만 이제 가우시안이 두 개가 되었으니, 11장의 위치 그래디언트로 각자 목표 blob 쪽으로 움직일 **여지**가 생겼습니다.

== 분열 후 학습: 이제야 목표를 따라잡는다

[source,python]
----
opt_gaussians = split_gaussian(one_gaussian[0])
lr = 8.0
for step in range(1500):
    grads, loss = position_grads(opt_gaussians, target_img)
    for g, grad in zip(sorted(opt_gaussians, key=lambda g: g.depth), grads):
        g.mu2d -= lr * grad
----

[source]
----
loss after split, before training: 0.008990995502238398
loss after split, after training:  0.002604539341794932
----

11장에서 유도한 위치 그래디언트를 그대로 재사용해서, 분열된 두 가우시안이 각자 자신에게 가까운 blob 쪽으로 이동합니다. 손실이 `0.0098`(가우시안 1개, 학습해도 안 내려가던 한계)에서 `0.0026`으로, 거의 `4`배 줄었습니다 — **파라미터 최적화만으로는 절대 넘을 수 없던 벽을, 개수를 늘려서 넘어선 것**입니다.

== 가지치기(Pruning): 쓸모없는 가우시안 제거하기

분열이 "부족한 곳에 더하기"라면, 가지치기는 반대 방향 — "쓸모없어진 가우시안을 지우기"입니다. 10장 연습문제에서 이미 확인했듯, 불투명도(`opacity`)가 `0`에 가까운 가우시안은 렌더링에 거의 기여하지 않고 그래디언트도 거의 `0`이라 학습이 더 이상 그 가우시안을 개선하지 못합니다 — 그런 가우시안은 계산 비용만 차지할 뿐이니 지워버리는 게 낫습니다.

[source,python]
----
gaussians_with_ghost = opt_gaussians + [make_gaussian([5, 5], 1.0, 1.0, 0, 2.0, [1,1,1], 0.001)]
img_before, _ = rasterize_full(gaussians_with_ghost, H, W)
pruned = [g for g in gaussians_with_ghost if g.opacity > 0.01]
img_after, _ = rasterize_full(pruned, H, W)
diff_prune = np.abs(img_before - img_after).max()
print(len(gaussians_with_ghost) - len(pruned), diff_prune)  # 1개 제거, 0.001
----

불투명도 `0.001`짜리 "유령" 가우시안을 제거해도 렌더링된 이미지의 최대 픽셀 차이는 `0.001`에 불과합니다 — 사실상 안 보이던 가우시안이었다는 뜻이고, 지워도 안전합니다.

== 분열과 가지치기를 함께 쓰는 이유

실전 3DGS 학습은 이 두 연산을 번갈아 반복합니다 — 학습 중 주기적으로, (1) 그래디언트가 크고 오래 남아있는(= 아직 목표를 잘 못 맞추고 있는) 가우시안을 분열시키고, (2) 불투명도가 거의 `0`으로 수렴한 가우시안을 가지치기합니다. 이렇게 하면 가우시안의 총 개수를 사람이 미리 정확히 맞출 필요 없이, 학습 과정이 스스로 "장면을 표현하는 데 실제로 필요한 만큼"으로 개수를 조절합니다 — 너무 적으면(3장의 한계처럼) 분열이 채워주고, 너무 많으면(중복되거나 안 보이는 가우시안) 가지치기가 정리합니다.

== 직접 해보기

* 분열할 때 `offset_scale`을 `0.5`가 아니라 `0.05`(거의 같은 위치에서 분열)로 바꾸면, 학습 후 손실이 어떻게 달라지는지 확인해보세요.

.해답 보기

----
opt_gaussians_close = split_gaussian(one_gaussian[0], offset_scale=0.05)
# ... 같은 학습 루프
----

`offset_scale`을 아주 작게 하면 두 가우시안이 거의 같은 위치에서 시작하지만, 11장 연습문제에서 확인했듯 완전히 겹쳐도 그래디언트는 `0`이 아니므로(목표가 대칭이 아닌 한) 학습은 여전히 진행됩니다. 다만 시작점이 목표 blob들로부터 더 멀리 떨어진 셈이라(원래 분열 지점이 이미 각 blob 쪽으로 어느 정도 다가가 있었으니), 같은 스텝 수로는 `offset_scale=0.5`일 때보다 수렴이 더 느립니다 — 분열 시 주축 방향으로 충분히 밀어내는 것이 수렴 속도에 실질적으로 도움이 된다는 걸 보여줍니다.

== 요약

* 파라미터(위치·색상 등) 최적화만으로는 가우시안 개수가 구조적으로 부족한 경우의 손실 한계를 넘을 수 없습니다(3장에서 이미 확인한 사실).
* 분열은 가장 긴 주축 방향으로 큰 가우시안을 두 개의 작은 가우시안으로 나누어, 표현력 자체를 늘립니다 — 분열 직후 손실은 거의 그대로지만, 이어지는 학습이 이 늘어난 표현력을 실제 개선으로 바꿉니다.
* 가지치기는 불투명도가 거의 0으로 수렴해 더 이상 그래디언트 신호가 없는 가우시안을 제거해도 렌더링 결과가 거의 바뀌지 않는다는 사실을 이용해, 계산 비용을 줄입니다.
* 분열과 가지치기를 학습 중 번갈아 반복하는 것이 실전 3DGS가 가우시안 개수를 자동으로 조절하는 방법입니다.

4부가 여기서 끝났습니다. 색상·위치 역전파(10~11장)와 개수 조절(12장)까지 갖췄으니, 이제 5부에서는 이렇게 만들어진 렌더링 결과를 정량적으로 어떻게 평가하는지, 그리고 1권에서 만든 카메라 포즈·점군이 이 모든 과정에 어떻게 연결되는지를 다룹니다.
