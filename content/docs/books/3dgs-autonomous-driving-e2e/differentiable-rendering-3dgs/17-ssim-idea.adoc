16장에서 흐림과 노이즈가 PSNR로는 거의 구별되지 않는다는 걸 확인했습니다. **SSIM(Structural Similarity Index, 구조적 유사도)**은 이 문제를 다른 각도로 풉니다 — 두 이미지를 통째로 비교하는 대신, "밝기가 비슷한가", "대비가 비슷한가", "구조(패턴)가 비슷한가"라는 세 가지 서로 다른 질문으로 나눠서 답하고, 그 세 답을 곱해서 최종 점수를 냅니다.

== 세 가지 질문

두 이미지(또는 이미지 영역) `a`와 `b`가 있을 때, SSIM은 이렇게 나눠 묻습니다.

* **밝기(luminance) `l(a,b)`**: 두 영역의 평균 밝기가 비슷한가?
* **대비(contrast) `c(a,b)`**: 두 영역의 밝기 흩어짐 정도(표준편차)가 비슷한가?
* **구조(structure) `s(a,b)`**: 평균과 흩어짐을 정규화하고 났을 때, 두 영역의 패턴이 같은 방향으로 움직이는가(공분산이 양수인가)?

각 질문의 답은 `-1`(완전히 반대)부터 `1`(완전히 같음) 사이의 값이고, 셋을 곱한 게 SSIM 점수입니다.

[source,python]
----
import numpy as np

def ssim_components(a, b, C1=(0.01) ** 2, C2=(0.03) ** 2):
    mu_a, mu_b = a.mean(), b.mean()
    var_a, var_b = a.var(), b.var()
    cov = ((a - mu_a) * (b - mu_b)).mean()

    l = (2 * mu_a * mu_b + C1) / (mu_a ** 2 + mu_b ** 2 + C1)
    c = (2 * np.sqrt(var_a) * np.sqrt(var_b) + C2) / (var_a + var_b + C2)
    s = (cov + C2 / 2) / (np.sqrt(var_a) * np.sqrt(var_b) + C2 / 2)

    return l, c, s, l * c * s
----

`C1`, `C2`는 분모가 `0`에 가까워질 때(예: 완전히 평평한 이미지) 수식이 불안정해지는 걸 막는 아주 작은 상수입니다. `l`의 식(`2μₐμᵦ/(μₐ²+μᵦ²)`, `C1` 생략)은 두 평균이 같을 때 정확히 `1`이 되고, 하나가 `0`에 가까워지면 `0`에 가까워지는 형태입니다 — `c`와 `s`도 비슷한 원리로 만들어져 있습니다.

== 16장의 예제에 그대로 적용해보기

16장에서 만든 사각형 이미지, 흐린 버전, 노이즈 버전에 이 함수를 그대로 적용합니다.

[source,python]
----
from scipy.ndimage import gaussian_filter

N = 32
img = np.zeros((N, N))
img[N // 4:3 * N // 4, N // 4:3 * N // 4] = 1.0

blurred = gaussian_filter(img, sigma=1.2)

rng = np.random.default_rng(1)
mse_blur = np.mean((img - blurred) ** 2)
noisy = img + rng.normal(0, np.sqrt(mse_blur), img.shape)

print("흐림:", ssim_components(img, blurred))
print("노이즈:", ssim_components(img, noisy))
----

[source]
----
흐림: (1.000, 0.993, 0.961, 0.955)
노이즈: (1.000, 0.999, 0.963, 0.961)
----

기대와 다르게, 흐림(`0.955`)과 노이즈(`0.961`)의 최종 SSIM 점수가 여전히 거의 같습니다 — 16장에서 PSNR이 실패했던 것과 똑같은 문제가 그대로 재현됐습니다. SSIM이라는 더 정교한 수식을 썼는데 왜 여전히 구별을 못 할까요?

== 문제는 수식이 아니라 "어디에 적용했는가"

방금 계산은 **이미지 전체**의 평균·분산·공분산을 한 번만 구해서 SSIM 공식에 넣었습니다. 그런데 이미지 전체의 평균 밝기나 전체 분산은, 노이즈가 이미지 구석구석에 흩어져 있든 흐림이 경계 부분에만 몰려 있든 크게 다르지 않을 수 있습니다 — 14장에서 MSE가 "전체 평균"만 보느라 오차의 위치를 놓쳤던 것과 똑같은 함정에, 이번엔 "전체 평균·분산·공분산"이라는 형태로 다시 걸린 것입니다.

SSIM 논문(Wang et al., 2004)이 실제로 제안한 방법은, 이미지 전체가 아니라 **작은 창(window)을 이미지 위에서 슬라이딩시키면서 각 위치에서 국소적으로 SSIM을 계산하고, 그 값들을 평균 내는 것**입니다. 이렇게 하면 "이미지의 이 부분은 구조가 잘 보존됐고, 저 부분은 노이즈로 망가졌다"는 국소적인 차이가 최종 점수에 반영될 수 있습니다. 다음 장에서 이 슬라이딩 창 버전을 직접 구현하고, 이번엔 정말로 흐림과 노이즈가 다른 점수를 받는지 확인합니다.

== 직접 해보기

* `l(a,b)`(밝기 항)만 따로 떼서, 원본 이미지와 원본에 상수 `0.3`을 더한 이미지(전체적으로 더 밝아진 이미지, `[0,1]` 범위를 벗어나지 않게 클리핑) 사이에서 어떤 값이 나오는지 확인하고, 이게 `1`(완전히 같음)에서 얼마나 멀어지는지 살펴보세요.

.해답 보기
[%collapsible]
====
[source,python]
----
brighter = np.clip(img + 0.3, 0, 1)
l, c, s, ssim_val = ssim_components(img, brighter)
print(f"l={l:.4f}, c={c:.4f}, s={s:.4f}, SSIM={ssim_val:.4f}")
----

[source]
----
l=0.8244, c=0.9398, s=1.0000, SSIM=0.7747
----

`s`(구조)는 정확히 `1.0`입니다 — 사각형이 있던 자리는 여전히 밝고 배경은 여전히 어두우니, 패턴 자체는 완전히 보존됐습니다. `l`(밝기)은 뚜렷하게 낮아졌고(`0.824`), `c`(대비)도 조금 낮아졌습니다(`0.940`) — `img + 0.3`이 `[0,1]` 범위를 넘는 부분을 `1.0`으로 잘라내면서(원래 사각형 값 `1.0`이 `1.3`이 됐다가 다시 `1.0`으로 잘림) 사각형 영역의 밝기 흩어짐(분산)이 살짝 달라졌기 때문입니다. `s`가 `1.0`으로 유지되면서 `l`과 `c`만 변했다는 게, SSIM이 "무엇이 달라졌는가"를 세 항목으로 분해해서 보여준다는 걸 잘 드러내는 예시입니다.
====

== 요약

* SSIM은 두 이미지의 닮음을 밝기(`l`), 대비(`c`), 구조(`s`) 세 요소로 나눠서 재고, 그 셋을 곱해 최종 점수를 냅니다.
* 이미지 전체에 대해 딱 한 번 SSIM을 계산하면(전역 SSIM), 16장의 흐림과 노이즈를 여전히 구별하지 못합니다 — 오차의 "위치"를 무시하는 MSE의 문제가 형태만 바꿔 다시 나타난 것입니다.
* SSIM이 실제로 유용해지는 건 이미지 전체가 아니라 작은 창을 슬라이딩시키며 국소적으로 계산할 때이며, 이 방식을 다음 장에서 직접 구현합니다.
