'''

"두 이미지가 얼마나 닮았는가"를 재려면, 먼저 컴퓨터가 이미지를 어떤 형태의 데이터로 다루는지 알아야 합니다. 이 장에서는 이미지를 **숫자로 이루어진 배열**로 다루는 법을 처음부터 봅니다.

== 이미지는 숫자로 이루어진 3차원 배열이다

컬러 이미지는 "높이 × 너비 × 채널(3)"이라는 3차원 배열입니다. 각 픽셀(가장 작은 점 하나)마다 빨강(R), 초록(G), 파랑(B) 값이 하나씩 있고, 이 세 값의 조합으로 그 픽셀의 색이 정해집니다.

[source,python]
----
import numpy as np

img = np.zeros((4, 4, 3), dtype=np.uint8)   # 4x4 픽셀짜리 검은 이미지
img[0, 0] = [255, 0, 0]      # 왼쪽 위: 빨강
img[1, 1] = [0, 255, 0]      # 대각선: 초록
img[2, 2] = [0, 0, 255]      # 대각선: 파랑
img[3, 3] = [255, 255, 255]  # 오른쪽 아래: 흰색

print(img.shape, img.dtype)
print("(0,0) 픽셀:", img[0, 0])
print("(1,1) 픽셀:", img[1, 1])
----

[source]
----
(4, 4, 3) uint8
(0,0) 픽셀: [255   0   0]
(1,1) 픽셀: [  0 255   0]
----

`img.shape`이 `(4, 4, 3)`이라는 건 "세로 `4`픽셀, 가로 `4`픽셀, 채널 `3`개(R, G, B)"라는 뜻입니다. `dtype=uint8`은 각 값이 `0`부터 `255`까지의 정수(부호 없는 `8`비트 정수)라는 뜻입니다 — `[255, 0, 0]`이 빨강이 최대치, 초록·파랑이 `0`이라 순수한 빨강을 나타냅니다.

== 왜 0~255인가: 8비트가 표현할 수 있는 범위

`8`비트는 `2^8 = 256`가지 값을 표현할 수 있어서, `0`부터 `255`까지의 정수로 밝기를 나타내는 게 이미지 저장의 오랜 관례입니다(JPEG, PNG 같은 일반적인 이미지 파일 형식이 대부분 이 범위를 씁니다). `0`은 그 채널이 완전히 꺼진 것(검정에 가까움), `255`는 완전히 켜진 것(그 색이 최대로 밝음)을 뜻합니다.

== 실수(float)로 바꾸기: 왜 계산은 0~1 범위로 하는가

이 책에서 다룰 지표들은 대부분 `0`부터 `1`까지의 실수 범위로 이미지를 다룹니다 — `uint8` 정수로 계산하면 나눗셈이나 뺄셈 도중 값이 `0` 밑으로 내려가거나 `255`를 넘어가면서 예상치 못한 오버플로(값이 순환해버리는 오류)가 생기기 쉽기 때문입니다.

[source,python]
----
img_float = img.astype(np.float64) / 255.0
print(img_float.min(), img_float.max())
----

[source]
----
0.0 1.0
----

`255`로 나눠서 전체 값을 `[0, 1]` 구간으로 압축했습니다. 이 책의 나머지 모든 장에서 이미지는 이 `[0, 1]` 범위의 실수 배열로 다룹니다.

== 그레이스케일: 색을 없애고 밝기만 남기기

일부 지표(특히 다음 장의 MSE, 15장의 PSNR)는 흑백(그레이스케일) 이미지에도 그대로 적용됩니다. 컬러 이미지를 그레이스케일로 바꾸는 가장 간단한 방법은 R, G, B의 평균을 내는 것입니다.

[source,python]
----
gray = img_float.mean(axis=2)
print(gray.shape)
print(np.round(gray, 3))
----

[source]
----
(4, 4)
[[0.333 0.    0.    0.   ]
 [0.    0.333 0.    0.   ]
 [0.    0.    0.333 0.   ]
 [0.    0.    0.    1.   ]]
----

`axis=2`는 세 번째 축(채널 축)을 따라 평균을 낸다는 뜻입니다 — 결과의 `shape`이 `(4, 4)`로, 채널 축이 사라지고 순수한 흑백 밝기 값만 남았습니다. `[255, 0, 0]`(순수 빨강)이었던 `(0,0)` 픽셀이 그레이스케일에서는 `0.333`(어두운 회색)이 됐습니다 — 참고로 실제 사람 눈은 초록에 훨씬 민감해서(초록이 밝기 인지에 가장 크게 기여), 정확한 밝기 변환은 `R×0.299 + G×0.587 + B×0.114` 같은 가중 평균을 쓰지만, 이 책에서는 단순함을 위해 단순 평균을 기본으로 씁니다.

== 직접 해보기

* `8×8` 크기의 이미지를 만들어 절반은 검은색(`[0,0,0]`), 절반은 흰색(`[255,255,255]`)인 체스판 비슷한 패턴을 채워보고, 그 이미지를 그레이스케일로 바꾼 뒤 `mean()`(전체 평균 밝기)이 얼마가 나오는지 예상해보고 확인해보세요.

.해답 보기
[%collapsible]
====
[source,python]
----
img2 = np.zeros((8, 8, 3), dtype=np.uint8)
img2[:4, :4] = [255, 255, 255]
img2[4:, 4:] = [255, 255, 255]

img2_float = img2.astype(np.float64) / 255.0
gray2 = img2_float.mean(axis=2)
print("전체 평균 밝기:", gray2.mean())
----

[source]
----
전체 평균 밝기: 0.5
----

`64`픽셀 중 절반(`32`픽셀)이 흰색(`1.0`), 절반이 검은색(`0.0`)이니 평균이 정확히 `0.5`가 나옵니다 — 이렇게 "평균"이라는 단순한 통계량 하나도, 이미지의 절반이 흰색이든 이미지 전체가 회색(`0.5`)이든 똑같은 값을 낼 수 있다는 걸 눈치채셨을 겁니다. 이 "단순한 통계량으로는 구조를 구분할 수 없다"는 문제가, 다음 장에서 다룰 MSE의 한계와 정확히 같은 뿌리를 갖고 있습니다.
====

== 요약

* 컬러 이미지는 "높이 × 너비 × 채널(3)" 모양의 배열이며, 각 픽셀은 R, G, B 세 값으로 색을 표현합니다.
* 픽셀 값은 보통 `0~255`(uint8) 범위로 저장되지만, 지표를 계산할 때는 오버플로를 피하기 위해 `[0, 1]` 범위의 실수로 바꿔서 다룹니다.
* 채널 축을 따라 평균을 내면 컬러 이미지를 그레이스케일로 바꿀 수 있으며, 이 책의 여러 지표가 그레이스케일을 기준으로 정의됩니다.
* 다음 장에서는 이렇게 숫자 배열로 표현된 두 이미지의 "차이"를 재는 가장 단순한 방법, MSE(평균제곱오차)를 다룹니다.
