'''

18장에서 SSIM이 PSNR로는 구별 못 했던 흐림과 노이즈를 뚜렷하게 구별해내는 걸 확인했습니다. 이 장에서는 SSIM도 여전히 완벽하지 않다는 것을, 두 가지 구체적인 실패 사례로 확인합니다.

== 실패 사례 1: 아주 조금만 밀려도 점수가 크게 떨어진다

부드러운 경계를 가진 사각형 이미지를 만들고, 옆으로 아주 조금(`1`~`5`픽셀)씩 밀어봅니다.

[source,python]
----
import numpy as np
from scipy.ndimage import gaussian_filter, shift, uniform_filter

N = 48
img = np.zeros((N, N))
img[N // 4:3 * N // 4, N // 4:3 * N // 4] = 1.0
img = gaussian_filter(img, sigma=1.0)   # 경계를 부드럽게

def windowed_ssim(a, b, win=7, C1=(0.01) ** 2, C2=(0.03) ** 2):
    mu_a = uniform_filter(a, win)
    mu_b = uniform_filter(b, win)
    mu_a2, mu_b2, mu_ab = mu_a * mu_a, mu_b * mu_b, mu_a * mu_b
    sigma_a2 = uniform_filter(a * a, win) - mu_a2
    sigma_b2 = uniform_filter(b * b, win) - mu_b2
    sigma_ab = uniform_filter(a * b, win) - mu_ab
    ssim_map = ((2 * mu_ab + C1) * (2 * sigma_ab + C2)) / \
               ((mu_a2 + mu_b2 + C1) * (sigma_a2 + sigma_b2 + C2))
    return ssim_map.mean()

def mse(a, b):
    return np.mean((a - b) ** 2)

def psnr(a, b, max_val=1.0):
    m = mse(a, b)
    return float('inf') if m == 0 else 10 * np.log10((max_val ** 2) / m)

for shift_px in [0, 1, 2, 3, 5]:
    shifted = shift(img, shift=[0, shift_px], order=1, mode='nearest')
    print(f"이동={shift_px}px: PSNR={psnr(img, shifted):.2f}, SSIM={windowed_ssim(img, shifted):.4f}")
----

[source]
----
이동=0px: PSNR=inf   SSIM=1.0000
이동=1px: PSNR=22.51  SSIM=0.9155
이동=2px: PSNR=17.00  SSIM=0.8273
이동=3px: PSNR=14.15  SSIM=0.7631
이동=5px: PSNR=11.08  SSIM=0.6763
----

`48×48` 이미지에서 단 `1`픽셀(전체 크기의 `2%`도 안 되는 미세한 오차) 이동만으로 SSIM이 `1.0`에서 `0.92`로, `5`픽셀 이동에서는 `0.68`까지 떨어졌습니다. 이 정도의 미세한 정렬 오차는 사람 눈에는 거의 안 보일 수도 있는데(같은 물체가 살짝 옆으로 밀려서 찍힌 두 사진), SSIM은 이걸 상당한 품질 저하로 평가합니다.

=== 왜 실무에서 이게 중요한가

3D Gaussian Splatting 같은 렌더링을 검증할 때, 렌더링된 이미지와 정답(ground truth) 사진 사이에 카메라 자세를 아주 살짝(서브픽셀 단위로) 잘못 추정했다는 이유만으로도 이런 미세한 정렬 오차가 생길 수 있습니다. 실제로는 렌더링 품질에 큰 문제가 없는데도, 이 정렬 오차 하나 때문에 SSIM 점수가 나쁘게 나올 수 있다는 뜻입니다 — "SSIM이 낮다"는 결과를 보고 무작정 "렌더링 품질이 나쁘다"고 결론짓기 전에, 정렬 오차가 원인은 아닌지 의심해봐야 합니다.

== 실패 사례 2: 색이 완전히 뒤바뀌어도 전혀 모른다

지금까지 이 책의 SSIM 구현은 그레이스케일(밝기)만 다뤘습니다. 빨강(R)과 파랑(B) 채널을 통째로 맞바꾼 이미지를 만들어봅니다 — 빨간 물체는 파랗게, 파란 물체는 빨갛게 보이는, 색이 완전히 다른 이미지입니다.

[source,python]
----
rng = np.random.default_rng(2)
N = 16
rgb = rng.random((N, N, 3))          # 무작위 컬러 이미지
rgb_swapped = rgb[:, :, [2, 1, 0]]    # R과 B 채널을 맞바꿈 (색이 완전히 달라짐)

gray1 = rgb.mean(axis=2)
gray2 = rgb_swapped.mean(axis=2)

print("그레이스케일 MSE:", mse(gray1, gray2))
print("전체 RGB MSE:", mse(rgb, rgb_swapped))
----

[source]
----
그레이스케일 MSE: 2.37e-33  (사실상 0)
전체 RGB MSE: 0.1122
----

그레이스케일 MSE가 사실상 `0`입니다 — 이건 우연이 아니라 수학적으로 항상 그렇습니다. 그레이스케일 값은 `(R+G+B)/3`(평균)인데, 평균은 더하는 순서를 바꿔도 결과가 같으므로, `R`과 `B`를 아무리 뒤바꿔도 `(R+G+B)/3`은 정확히 그대로입니다. 반면 원래 컬러 채널을 그대로 비교한 MSE(`0.1122`)는 이 색 차이를 뚜렷하게 잡아냅니다. 이 그레이스케일 이미지들로 windowed SSIM을 계산하면 어떻게 될지는 뻔합니다 — `gray1`과 `gray2`가 완전히 같은 배열이니, SSIM은 정확히 `1.0`(완벽하게 닮았다는 최고 점수)이 나옵니다. 색이 완전히 다른 두 이미지에 최고 점수를 준 것입니다.

== 두 실패가 알려주는 것

두 실패 사례는 원인이 다릅니다. **정렬 민감성**은 SSIM이 "같은 위치의 픽셀끼리" 비교한다는 근본적인 계산 방식에서 나옵니다(MSE도 똑같이 위치에 민감했다는 걸 14장에서 이미 봤습니다 — SSIM이 구조는 더 잘 보지만, 위치 자체는 여전히 픽셀 단위로 엄격하게 맞춰야 합니다). **색맹 문제**는 이 책에서 구현한 SSIM이 애초에 그레이스케일만 다뤘기 때문에 생긴, 구현 범위의 문제입니다(RGB 각 채널에 대해 SSIM을 따로 계산해서 평균 내는 식으로 어느 정도 보완할 수 있지만, 색조·채도 차이를 온전히 반영하려면 더 정교한 색공간 변환이 필요합니다).

두 한계 모두 결국 같은 메시지로 이어집니다 — SSIM은 MSE/PSNR보다 사람의 지각에 더 가깝지만, 여전히 "픽셀의 밝기 패턴"이라는 저수준 정보만 봅니다. 사람이 "이 두 이미지가 닮았다"고 판단할 때 실제로 쓰는 정보(물체의 정체, 질감, 전체적인 장면 구성)는 픽셀 값의 국소적 통계만으로는 다 담아낼 수 없습니다. 다음 장에서는 이 한계를 넘어서기 위해, 아예 신경망이 학습한 "이미지 특징"을 이용해 닮음을 재는 지각적 지표(LPIPS)의 아이디어를 다룹니다.

== 직접 해보기

* `1`픽셀 이동 시 SSIM이 `0.92`로 떨어진 것을, 창 크기(`win`)를 `15`로 키우면 어떻게 달라지는지 확인해보세요. 18장에서 창이 커질수록 국소적 민감도가 떨어진다는 걸 배웠으니, 이 정렬 오차에 대해서도 SSIM이 더 관대해지는지 봅니다.

.해답 보기
[%collapsible]
====
[source,python]
----
shifted_1px = shift(img, shift=[0, 1], order=1, mode='nearest')
for win in [7, 15, 25, 41]:
    print(f"win={win}:", windowed_ssim(img, shifted_1px, win=win))
----

[source]
----
win=7: 0.9155
win=15: 0.9154
win=25: 0.9453
win=41: 0.9807
----

의외의 결과입니다 — 창을 `7`에서 `15`로 키워도 점수가 거의 그대로입니다(`0.9155 → 0.9154`). 18장에서 노이즈에 대한 SSIM이 창을 조금만 키워도 빠르게 관대해졌던 것과 다릅니다. 창을 훨씬 더 크게(`25`, `41`, 거의 이미지 전체 크기) 키워야만 비로소 점수가 뚜렷하게 올라갑니다. 이유는 손상의 "성격"이 다르기 때문입니다 — 노이즈는 각 픽셀이 독립적으로 무작위이므로 창을 살짝만 넓혀도 그 무질서가 평균에 묻히지만, `1`픽셀 이동은 이미지 전체에 걸쳐 **일관되게** 모든 내용이 옆으로 밀린 것이라, 아주 큰 창으로 뭉뚱그리기 전까지는 "내용은 같은데 위치만 다르다"는 것을 국소적으로 알아챌 방법이 없습니다. 즉 SSIM의 창 크기는 노이즈에 대한 관대함은 쉽게 조절할 수 있어도, 정렬 오차에 대한 민감성은 훨씬 완고하게 남아 있다는 것을 보여줍니다.
====

== 요약

* SSIM은 `1`픽셀 미만의 미세한 정렬 오차에도 점수가 크게 떨어질 수 있으며, 이는 렌더링과 정답 이미지 사이에 카메라 자세가 아주 살짝만 어긋나도 실제 품질과 무관하게 낮은 점수가 나올 수 있다는 뜻입니다.
* 그레이스케일 기반 SSIM은 밝기의 평균으로만 색을 뭉개기 때문에, R과 B 채널이 완전히 뒤바뀌는 것처럼 밝기는 그대로인 채 색만 완전히 달라지는 손상을 전혀 잡아내지 못합니다.
* 두 한계 모두 SSIM이 여전히 픽셀 값의 저수준 통계만 본다는 근본적인 성질에서 나오며, 사람이 실제로 "닮음"을 판단하는 방식(물체·질감·구성)과는 거리가 있습니다.
* 다음 장에서는 신경망이 학습한 이미지 특징으로 닮음을 재는 지각적 유사도(LPIPS)의 아이디어를 살펴봅니다.
