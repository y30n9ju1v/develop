== 순방향 그래픽스와 역방향 그래픽스

전통적인 컴퓨터 그래픽스는 **장면 → 사진** 방향입니다 — 도형의 위치, 색, 조명을 알고 있으면, 그로부터 사진을 계산해냅니다(이걸 **렌더링**이라고 부릅니다). 이 책이 다루는 문제는 그 반대입니다 — **사진 → 장면**, 즉 이미 찍힌 사진들을 보고, 그 사진들을 만들어냈을 법한 장면(도형의 위치, 색)을 거꾸로 추측합니다. 이걸 **역그래픽스(inverse graphics)**라고 부릅니다.

== 아주 작은 역그래픽스 문제 만들기

가장 단순한 형태로 이 문제를 만들어봅니다 — 2차원도 3차원도 아닌, **1차원** "장면"입니다. 장면은 위치 `mu` 하나에 놓인 가우시안 모양의 밝기 신호이고, "렌더링"은 이 신호를 100개의 픽셀로 이루어진 1차원 "사진"으로 만드는 것입니다.

[source,python]
----
import numpy as np

n_pixels = 100
xs = np.linspace(-5, 5, n_pixels)
sigma = 0.5

def render(mu):
    """1D 장면 렌더링: 위치 mu에 있는 가우시안 형태의 밝기 신호를 이미지(100픽셀)로 만든다."""
    return np.exp(-0.5 * ((xs - mu) / sigma) ** 2)
----

이게 아무리 단순해 보여도, 뒤에서 다룰 3D Gaussian Splatting의 핵심 구조를 그대로 담고 있습니다 — "파라미터(위치)를 가진 도형(가우시안)을 렌더링 함수에 통과시켜 이미지를 만든다"는 게 이 책 전체의 반복되는 패턴입니다.

== 역방향 문제: 사진 한 장에서 mu를 복원하기

"정답" 장면(`mu_true = 1.3`)을 렌더링해서 만든 사진 한 장이 있다고 합시다. 여기에 약간의 관측 잡음도 섞습니다(실제 카메라 사진에 노이즈가 있는 것처럼).

[source,python]
----
mu_true = 1.3
target = render(mu_true) + rng.normal(scale=0.01, size=n_pixels)
----

이 `target` 사진만 보고, 그걸 만들어낸 `mu`가 얼마인지 되찾는 게 우리의 역그래픽스 문제입니다. 두 렌더링 결과가 얼마나 다른지는 **손실 함수(loss)**로 잽니다.

[source,python]
----
def loss(mu, target):
    """렌더링 결과와 목표 이미지 사이의 오차(제곱합)."""
    return np.sum((render(mu) - target) ** 2)
----

`mu`가 정답에 가까울수록 `loss`가 작아집니다 — 역그래픽스는 결국 "`loss`를 최소로 만드는 `mu`를 찾아라"라는 최적화 문제입니다.

== 방법 A: 그리드 탐색 (렌더러를 그냥 블랙박스로 취급하기)

가장 무식하지만 가장 이해하기 쉬운 방법은, 가능한 `mu` 값을 촘촘히 훑으면서 `loss`가 가장 작은 걸 고르는 것입니다.

[source,python]
----
def grid_search(target, lo=-5, hi=5, n=2000):
    candidates = np.linspace(lo, hi, n)
    losses = [loss(m, target) for m in candidates]
    best_idx = np.argmin(losses)
    return candidates[best_idx], n

mu_grid, n_evals_grid = grid_search(target)
print(mu_grid, n_evals_grid)  # 1.3032  2000
----

`2000`번 렌더링을 시도해서 `mu ≈ 1.3032`(진짜 값 `1.3`에 아주 가깝습니다)를 찾아냅니다. 문제는 **평가 횟수**입니다 — 이건 미지수가 딱 하나일 때 얘기입니다. 3DGS는 미지수(가우시안 하나당 위치·크기·색·불투명도 등 수십 개, 그런 가우시안이 수십만 개)가 수백만 개인데, 이 방식으로는 도저히 답을 찾을 수 없습니다.

== 방법 B: 그래디언트를 이용한 경사하강

`loss`를 `mu`에 대해 미분한 **그래디언트**(기울기)를 알면, 매번 "어느 방향으로 움직여야 `loss`가 줄어드는지"를 바로 알 수 있습니다 — 훑어볼 필요 없이 곧장 내리막으로 걸어가는 것입니다.

[source,python]
----
def loss_grad_analytic(mu, target):
    """loss를 mu에 대해 손으로 미분한 것 (연쇄법칙 적용)."""
    r = render(mu)
    d_r_d_mu = r * (xs - mu) / sigma ** 2  # d/dmu of exp(-0.5*((x-mu)/sigma)^2)
    d_loss_d_r = 2 * (r - target)
    return np.sum(d_loss_d_r * d_r_d_mu)
----

`render(mu)`를 `mu`로 미분한 것(`d_r_d_mu`)과, `loss`를 `render` 결과로 미분한 것(`d_loss_d_r`)을 곱해서 더한 게 바로 **연쇄법칙(chain rule)**입니다 — 다음 장에서 이 패턴을 자동화하는 자동미분을 다룹니다. 이 그래디언트가 정말 맞는지, **유한차분(finite difference)**으로 대조 확인부터 합니다.

[source,python]
----
eps = 1e-6
grad_analytic = loss_grad_analytic(0.5, target)
grad_numeric = (loss(0.5 + eps, target) - loss(0.5 - eps, target)) / (2 * eps)
print(grad_analytic, grad_numeric)  # -14.6553468857... -14.6553468862...
assert np.isclose(grad_analytic, grad_numeric, atol=1e-3)
----

손으로 미분한 값과, `mu`를 아주 살짝 흔들어보고 `loss`가 얼마나 바뀌는지로 근사한 값이 소수점 여러 자리까지 일치합니다 — 이 "유한차분 검증"은 이 책 전체에서 반복해서 쓸, 미분 공식이 맞는지 확인하는 표준적인 방법입니다.

== 실패해보기: 학습률이 너무 크면 엉뚱한 곳에 갇힌다

이제 이 그래디언트로 경사하강을 해봅니다. 처음에는 "크게크게 움직이면 더 빨리 수렴하겠지"라는 생각으로 학습률(`lr`, 한 걸음의 크기)을 `0.3`으로 크게 잡아봤습니다.

[source]
----
step 0: mu=0.3   grad=-12.71  (mu = 0.3 - 0.3*(-12.71) = 4.11로 이동)
step 1: mu=4.11  grad=-0.21
...
step 6: mu=6.72  grad=-0.0009  (그 뒤로 거의 안 움직임)
최종 결과: mu ≈ 6.72   (진짜 값 1.3과 전혀 다름!)
----

첫 걸음부터 `mu`가 `0.3`에서 `4.11`로, 정답(`1.3`)을 훌쩍 지나쳐버렸습니다 — 학습률이 너무 커서 그래디언트가 가리키는 방향으로 "성큼" 걸었는데, 그 한 걸음이 정답 근처를 그냥 지나쳐버린 것입니다. 더 큰 문제는 그다음입니다 — `mu=4.11`은 가우시안 신호(`sigma=0.5`짜리 좁은 봉우리)의 범위에서 한참 벗어난 곳이라, 그 지점에서의 그래디언트(`-0.21`)가 이미 아주 작습니다. `render(mu)`가 그 지점에서 이미 거의 `0`(가우시안 봉우리에서 멀리 떨어져 있으니까요)이라, 그 미분값도 거의 `0`이 되는 것입니다 — 마치 평평한 사막 한가운데 서 있는 것처럼, 그래디언트가 "이쪽이 내리막"이라고 알려줄 신호 자체가 사라져버립니다. 결국 아주 느린 속도로 엉뚱한 곳(`mu≈6.72`)에 멈춰버립니다.

이 현상을 **그래디언트 소실(vanishing gradient)**이라고 부르고, 좁고 뾰족한 형태(가우시안처럼)를 최적화할 때 특히 잘 생기는 문제입니다 — 4부에서 3D 가우시안을 실제로 최적화할 때 이 문제가 왜, 그리고 어떻게 다시 등장하는지 다시 다룹니다.

== 학습률을 낮춰 다시 시도하기

[source,python]
----
def gradient_descent(target, mu0=0.3, lr=0.02, steps=200):
    mu = mu0
    for _ in range(steps):
        g = loss_grad_analytic(mu, target)
        mu = mu - lr * g
    return mu, steps

mu_gd, n_evals_gd = gradient_descent(target)
print(mu_gd, n_evals_gd)  # 1.3025048...  200
assert abs(mu_gd - mu_true) < 0.02
----

학습률을 `0.02`로 훨씬 작게 잡으니, 이번엔 매 걸음이 봉우리를 지나치지 않고 착실하게 정답 쪽으로 다가가서 `200`번의 시도만으로 `mu ≈ 1.3025`(그리드 탐색의 `1.3032`와 거의 같은 정확도)에 도달합니다.

[source,python]
----
print(n_evals_grid / n_evals_gd)  # 10.0
assert n_evals_grid >= 10 * n_evals_gd
----

같은 정확도를 얻는 데, 그리드 탐색은 `2000`번, 그래디언트 기반 방법은 `200`번 — **10배** 적은 시도로 끝났습니다. 그리고 이 차이는 미지수가 하나뿐인 지금도 10배인데, 미지수가 수백만 개인 3DGS에서는 그리드 탐색이 아예 불가능한 반면 그래디언트 기반 방법은(적절한 학습률만 고르면) 여전히 작동합니다 — 이게 이 책 전체가 "미분 가능한 렌더링"을 고집하는 이유입니다.

== 직접 해보기

* 학습률을 `0.02`와 `0.3` 사이의 값(예를 들어 `0.1`)으로 시도해보고, 수렴하는지 실패하는지 확인해보세요.

.해답 보기
[%collapsible]
====
[source,python]
----
mu_mid, _ = gradient_descent(target, lr=0.1, steps=200)
print(mu_mid)
----

학습률이 정확히 어디부터 실패하기 시작하는지는 초기 위치와 신호의 폭(`sigma`)에 따라 달라집니다 — 이렇게 "안전한 학습률의 범위"를 미리 알기 어렵다는 게 실전 최적화의 어려움 중 하나이고, 실제 3DGS 구현들이 학습률을 훈련 도중 점점 줄여가는 스케줄을 쓰는 이유이기도 합니다(4부에서 다시 다룹니다).

== 요약

* 역그래픽스는 사진으로부터 장면 파라미터를 거꾸로 복원하는 문제이고, "렌더링 결과와 실제 사진의 차이"를 손실 함수로 정의합니다.
* 그리드 탐색은 이해하기 쉽지만 미지수가 많아지면 감당할 수 없이 느려지고, 그래디언트 기반 최적화는 훨씬 적은 시도로 답을 찾습니다.
* 미분 공식은 유한차분으로 대조 검증할 수 있고, 이 책 전체에서 이 검증을 반복해서 씁니다.
* 학습률이 너무 크면 정답을 지나쳐 그래디언트가 소실되는 평평한 영역에 갇힐 수 있다는 걸 직접 겪어봤습니다.
