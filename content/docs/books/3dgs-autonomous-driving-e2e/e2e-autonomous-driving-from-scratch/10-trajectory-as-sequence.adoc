'''

3부에서 BEV라는 풍부한 공간 표현을 완성했습니다. 이제 그 표현으로부터 실제로 "미래에 어디로 갈 것인가"라는 궤적을 뽑아내야 합니다. Planning Head를 신경망으로 만들기 전에, 이 장에서는 먼저 "궤적을 어떤 숫자들의 나열로 표현할 것인가"를 다룹니다 — 표현 방식의 선택이, 뒤에서 신경망이 얼마나 안정적으로 학습되는지에 직접 영향을 줍니다.

== 자전거 모델로 궤적 만들기

자율주행차의 운동을 흔히 "자전거 모델(bicycle model)"로 근사합니다 — 앞바퀴 조향각과 속도로 차량 전체의 움직임을 표현하는, 실제 차량 동역학의 단순화된 버전입니다.

[source,python]
----
def simulate_trajectory(v_profile, steer_profile, dt, wheelbase=2.7):
    poses = np.zeros((len(v_profile)+1, 3))
    for k in range(len(v_profile)):
        x, y, theta = poses[k]
        v, delta = v_profile[k], steer_profile[k]
        x_new = x + v * np.cos(theta) * dt
        y_new = y + v * np.sin(theta) * dt
        theta_new = wrap_angle(theta + (v / wheelbase) * np.tan(delta) * dt)
        poses[k+1] = [x_new, y_new, theta_new]
    return poses
----

SLAM 심화편에서 다룬 유니사이클 모델과 형태가 비슷하지만, 조향각(`delta`)이 `tan(delta)`를 통해 회전 속도에 영향을 준다는 점이 다릅니다 — 실제 자동차가 "조향각"이라는 하나의 손잡이로 회전하는 방식을 더 직접적으로 반영합니다.

== 검증 1: 직진 시나리오

[source,python]
----
v_straight = np.full(12, 8.0)      # 8m/s로 6초간 직진
steer_straight = np.zeros(12)
traj_straight = simulate_trajectory(v_straight, steer_straight, 0.5)
print(traj_straight[-1])   # [48. 0. 0.]
----

조향각이 `0`이면 `y`는 정확히 `0`으로 유지되고, `x`는 `속도 × 시간`(`8 × 6 = 48`)과 정확히 일치합니다 — 물리적으로 당연한 결과지만, 이런 극단적인(그래서 정답을 손으로 계산할 수 있는) 경우로 운동 모델 구현 자체를 검증하는 것이 이 시리즈에서 반복해온 습관입니다.

== 검증 2: 좌회전 시나리오

[source,python]
----
v_turn = np.full(12, 5.0)
steer_turn = np.full(12, np.radians(15))   # 15도 좌회전 유지
traj_turn = simulate_trajectory(v_turn, steer_turn, 0.5)
print(traj_turn[-1])   # [4.12  19.71  2.98]
----

`15°` 좌회전을 계속 유지하면, `6`초 뒤 `y`가 `19.71m`나 이동해 있고(왼쪽으로 크게 돌았다는 뜻), 헤딩(`theta`)도 `2.98`라디안(`~171°`)까지 돌아 있습니다 — 거의 `180°`에 가까운 유턴을 한 셈입니다.

== 궤적을 시퀀스로 표현하는 두 가지 방법

[source,python]
----
waypoints_abs = traj_turn[1:, :2]                       # 절대 좌표: 각 시점의 (x, y)
waypoints_delta = np.diff(traj_turn[:, :2], axis=0)       # 델타 좌표: 이전 시점 대비 변화량
----

[source]
----
absolute: [[2.5, 0.], [4.92, 0.61], [7.12, 1.8], ..., [4.12, 19.71]]
delta:    [[2.5, 0.], [2.42, 0.61], [2.20, 1.19], ..., [-2.29, 1.0]]
----

같은 궤적을 표현하는 두 가지 방법입니다 — 절대 좌표는 "각 시점에 정확히 어디에 있는가"를, 델타 좌표는 "각 시점에 직전보다 얼마나 움직였는가"를 나열합니다.

== 검증 3: 두 표현 사이의 왕복이 손실 없는가

[source,python]
----
reconstructed = np.cumsum(waypoints_delta, axis=0)
print(np.abs(reconstructed - waypoints_abs).max())   # 0.0
----

델타를 누적합(`cumsum`)하면 절대 좌표가 부동소수점 오차 하나 없이 정확히 복원됩니다 — 두 표현은 정보량 측면에서 완전히 동등하고, 어느 쪽을 선택해도 표현력을 잃지 않습니다.

== 검증 4: 그렇다면 왜 표현 방식이 중요한가 — 값의 범위

[source,python]
----
print(waypoints_abs.min(), waypoints_abs.max())    # 0.0 ~ 19.71
print(waypoints_delta.min(), waypoints_delta.max())  # -2.29 ~ 2.5
----

절대 좌표의 범위(`19.71`)가 델타 좌표의 범위(`4.79`)보다 `4`배 이상 넓습니다. 신경망이 회귀하는 목표값의 범위가 넓을수록(그리고 시나리오마다 그 범위가 들쭉날쭉할수록), 학습이 불안정해지는 경향이 있습니다 — AICE 책 7장에서 입력 특성의 스케일을 맞추는 게 중요했던 것과 같은 이유가, 여기서는 출력(목표값)에도 적용됩니다.

== 검증 5: 시간이 지날수록 벌어지는 차이

`200`개의 무작위 시나리오(서로 다른 속도·조향 프로파일)로 이 차이를 더 명확히 봅니다.

[source,python]
----
std_per_step_abs = all_abs.std(axis=(0,2))     # 각 미래 시점(스텝)마다의 분산
std_per_step_delta = all_delta.std(axis=(0,2))
print(std_per_step_abs)
print(std_per_step_delta)
----

[source]
----
per-step std (absolute): [2.08  3.93  5.91  7.85  9.82 11.89 13.8  15.73 17.7  19.7  21.6  23.52]
per-step std (delta):    [2.08  2.13  2.3   2.3   2.35  2.45  2.38  2.46  2.52  2.55  2.53  2.54]
----

절대 좌표의 분산은 첫 스텝(`2.08`)에서 마지막 스텝(`23.52`)까지 `11`배 이상 커집니다 — 먼 미래일수록 "어디에 있을지"의 불확실성(그리고 시나리오 간 차이)이 누적되어 커지는 게 당연하기 때문입니다. 반면 델타 좌표의 분산은 `2.08`에서 `2.54`로 거의 그대로입니다 — "한 스텝 동안 얼마나 움직이는가"는 먼 미래든 가까운 미래든 비슷한 범위(자동차의 속도 한계에 의해 자연스럽게 제한됨)이기 때문입니다.

== 이게 Planning Head 설계에 주는 함의

신경망이 절대 좌표를 직접 예측하도록 학습시키면, 가까운 미래(분산 작음)와 먼 미래(분산 큼)를 같은 손실 함수로 동시에 맞춰야 하는데, 이러면 손실이 자연스럽게 먼 미래 쪽에 지배되기 쉽습니다(분산이 큰 쪽의 오차가 절대적으로도 더 크게 나올 가능성이 높으므로). 델타(또는 이와 비슷하게 스케일을 고르게 만드는 표현)를 예측하도록 하면, 모든 시점의 예측 난이도가 더 비슷한 수준으로 맞춰집니다 — 다음 장에서 실제로 Transformer Decoder를 학습시킬 때, 이 선택이 학습 안정성에 실제로 영향을 주는지 직접 비교해봅니다.

== 직접 해보기

* `dt`를 `0.5`초에서 `0.1`초(더 촘촘한 시간 간격)로 줄이면, 델타 좌표의 값 범위가 어떻게 달라지는지 확인해보세요.

.해답 보기
[%collapsible]
====
[source,python]
----
traj_fine = simulate_trajectory(v_turn, steer_turn, dt=0.1)
# 6초를 유지하려면 스텝 수를 60개로 늘려야 함
waypoints_delta_fine = np.diff(traj_fine[:, :2], axis=0)
print(waypoints_delta_fine.min(), waypoints_delta_fine.max())
----

`dt`가 `5`배 작아지면(`0.5→0.1`), 한 스텝 동안 이동하는 거리도 대략 `5`배 작아집니다(같은 속도로 `5`배 짧은 시간만 움직이므로) — 델타 좌표의 범위도 그만큼 좁아집니다. 이건 시간 간격을 촘촘하게 할수록 델타 표현이 점점 더 다루기 쉬워진다는 뜻이지만, 동시에 같은 미래 시간(`6`초)을 예측하는 데 필요한 시퀀스 길이(스텝 수)는 `5`배 늘어난다는 대가도 따릅니다 — 예측할 시점 수와 각 시점의 값 범위 사이의 트레이드오프입니다.
====

== 요약

* 자전거 모델로 조향각과 속도 시퀀스로부터 실제 미래 궤적을 시뮬레이션했고, 직진·회전 두 극단적인 경우로 구현을 검증했습니다.
* 절대 좌표와 델타 좌표는 정보량이 완전히 동등해서(`cumsum`으로 손실 없이 왕복 가능), 어느 쪽을 골라도 표현력을 잃지 않습니다.
* 하지만 절대 좌표는 시간이 지날수록 값의 분산이 계속 커지는 반면(`11`배 이상), 델타 좌표는 상대적으로 안정된 범위를 유지한다는 걸 확인했습니다.
* 이 스케일 차이가 다음 장에서 신경망이 궤적을 예측하도록 학습시킬 때 실질적인 영향을 미칩니다.

다음 장에서는 이 장에서 다진 시퀀스 표현을 바탕으로, Transformer Decoder가 실제로 BEV 표현에서 미래 궤적을 생성하도록 학습시킵니다.
