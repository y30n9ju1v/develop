'''

3장까지는 "두 센서가 서로 몇 초 어긋나 있는지 이미 안다"고 가정했습니다. 실제로는 그 오프셋 자체를 모릅니다 — 카메라의 이미지 처리 파이프라인이 몇 밀리초의 지연을 갖는지, USB나 이더넷 전송이 얼마나 지연되는지는 데이터시트에 정확히 적혀 있지 않은 경우가 많습니다. 이 장에서는 **두 센서가 공통으로 측정하는 물리량**(예: 차량의 각속도)을 이용해, 그 오프셋 자체를 데이터로부터 추정하는 법을 다룹니다.

== 아이디어: 두 신호가 서로 닮은 지점을 찾는다

카메라 영상으로부터도(연속된 프레임 사이의 회전을 분석해) 차량의 각속도를 추정할 수 있고, IMU(자이로스코프)도 각속도를 직접 측정합니다 — 이 둘은 원리적으로 **같은 물리량**을 서로 다른 방식으로 관측한 것입니다. 두 신호가 정확히 같은 시간에 기록됐다면 두 곡선이 정확히 겹쳐야 하는데, 시간 오프셋이 있다면 한쪽이 다른 쪽보다 앞서거나 뒤처진 모양으로 나타납니다. 이 "얼마나 밀어야 두 곡선이 가장 잘 겹치는가"를 찾는 표준적인 방법이 **교차상관(cross-correlation)**입니다.

== 시뮬레이션: 지연된 카메라 신호 만들기

풍부한(다양한 주파수 성분을 가진) 조향 패턴을 만들고, IMU는 정확한 시각에, 카메라 기반 신호는 `35ms` 지연되고 더 낮은 주파수(`10Hz`)로, 더 노이즈가 심하게 샘플링됐다고 가정합니다.

[source,python]
----
import numpy as np
from scipy.ndimage import gaussian_filter1d

rng = np.random.default_rng(1)
true_offset = 0.035   # 카메라 파이프라인의 실제 지연시간(정답, 실전에서는 모른다고 가정)

fine_dt = 0.001
fine_times = np.arange(0, 20, fine_dt)
raw = rng.normal(0, 1, fine_times.shape)
true_signal = gaussian_filter1d(raw, sigma=15)         # 부드럽게 흔들리는 "진짜" 조향 패턴
true_signal = true_signal / true_signal.std() * 0.4

def true_yaw_rate(t):
    return np.interp(t, fine_times, true_signal)

imu_dt = 1 / 200
imu_times = np.arange(0, 20, imu_dt)
imu_yaw = true_yaw_rate(imu_times) + rng.normal(0, 0.01, imu_times.shape)     # 정확한 시각, 낮은 노이즈

cam_dt = 1 / 10
cam_times = np.arange(0, 20, cam_dt)
cam_yaw = true_yaw_rate(cam_times - true_offset) + rng.normal(0, 0.03, cam_times.shape)   # 지연 + 높은 노이즈
----

`cam_yaw`가 `true_yaw_rate(cam_times - true_offset)`로 정의된 건 — 카메라 시계가 `t`를 가리킬 때 실제로 관측되는 물리량은 `true_offset`만큼 **이전** 시각의 값이라는 뜻입니다(카메라 파이프라인의 처리 지연 때문에, 신호가 실제 발생 시점보다 "늦게" 도착합니다).

== 공통 타임라인으로 리샘플링하고 교차상관 계산하기

서로 다른 주파수의 두 신호를 비교하려면, 먼저 같은 시간 간격의 공통 타임라인으로 리샘플링해야 합니다(3장에서 다룬 보간을 그대로 씁니다).

[source,python]
----
common_dt = 0.005
common_times = np.arange(1, 18, common_dt)
imu_resampled = np.interp(common_times, imu_times, imu_yaw)
cam_resampled = np.interp(common_times, cam_times, cam_yaw)

imu_c = imu_resampled - imu_resampled.mean()
cam_c = cam_resampled - cam_resampled.mean()

corr = np.correlate(cam_c, imu_c, mode='full')
lags = np.arange(-len(imu_c) + 1, len(cam_c))

search_mask = (lags >= -40) & (lags <= 40)     # ±0.2초 범위만 탐색(현실적인 지연 범위)
best_lag = lags[search_mask][np.argmax(corr[search_mask])]

print("추정된 오프셋:", best_lag * common_dt, "초 (정답:", true_offset, ")")
----

[source]
----
추정된 오프셋: 0.035 초 (정답: 0.035 )
----

교차상관이 데이터만으로 정확히 `35ms`(공통 그리드 간격 `5ms`의 정수배인 `7`샘플)를 찾아냈습니다.

== 서브샘플 정밀도로 다듬기: 포물선 보간

방금 찾은 오프셋은 공통 그리드 간격(`5ms`)의 배수로만 나올 수 있습니다. 실제 오프셋이 그 배수에 정확히 맞아떨어질 이유는 없으므로, 교차상관 값이 최댓값 근처에서 어떻게 변하는지(포물선 모양으로 근사) 이용해 더 정밀한 값을 추정합니다.

[source,python]
----
peak_idx = np.where(lags == best_lag)[0][0]
y0, y1, y2 = corr[peak_idx - 1], corr[peak_idx], corr[peak_idx + 1]
delta = 0.5 * (y0 - y2) / (y0 - 2 * y1 + y2)     # 포물선의 꼭짓점 위치(그리드 간격 단위)

refined_offset = (best_lag + delta) * common_dt
print("정밀화된 오프셋:", refined_offset, "초")
print("오차:", abs(refined_offset - true_offset) * 1000, "ms")
----

[source]
----
정밀화된 오프셋: 0.03581932362639143 초
오차: 0.8193236263914285 ms
----

정밀화 전에는 그리드 간격(`5ms`) 단위로만 답할 수 있었는데, 포물선 보간으로 `1ms` 미만의 오차까지 좁혔습니다. 세 점(`y0, y1, y2`, 최댓값과 그 양옆)이 이루는 포물선의 꼭짓점이 진짜 최댓값의 위치에 더 가깝다는 아이디어인데, `y0, y1, y2`를 이차함수로 근사했을 때 미분이 `0`이 되는 지점을 구하는 공식이 바로 `0.5(y0-y2)/(y0-2y1+y2)`입니다.

== 왜 신호의 "풍부함"이 중요한가

2장 연습문제에서 예고했듯, 만약 조향 패턴이 단조롭고 느리게 변하는 신호였다면(예를 들어 일정한 코너링처럼 거의 일정한 값이 오래 유지되는 신호), 교차상관 곡선이 특정 지점에서 뾰족하게 튀지 않고 넓게 퍼진 모양이 되어 `35ms` 같은 미세한 지연을 구별하기 어려워집니다 — 실제로 이 장의 시뮬레이션에서 처음에 단순한 사인파 몇 개를 합친 신호로 시도했을 때, 교차상관이 `0ms`와 `35ms` 지점에서 거의 구별이 안 될 만큼 비슷한 값을 냈습니다(직접 확인하려면 `true_yaw_rate`를 `0.5*np.sin(0.7*t) + 0.3*np.sin(1.9*t)`처럼 매끄러운 소수의 사인파 합으로 바꿔보세요). 시간 오프셋 추정을 위해서는 **직진 구간이 아니라 다양한 속도로 방향을 바꾸는 구간**(급차선변경, 곡선 도로, 정차·출발 반복 등)의 데이터가 훨씬 유용합니다 — 신호가 다채롭게 변할수록 "이 정도 밀어야 딱 맞는다"는 지점이 뾰족하게 드러나기 때문입니다.

== 직접 해보기

* `true_offset`을 `0.035`가 아니라 `-0.02`(카메라가 IMU보다 오히려 먼저 도착하는 경우)로 바꿔도 같은 방법이 정확한 부호와 크기를 찾아내는지 확인해보세요.

[source,python]
----
true_offset_neg = -0.02
cam_yaw_neg = true_yaw_rate(cam_times - true_offset_neg) + rng.normal(0, 0.03, cam_times.shape)
cam_resampled_neg = np.interp(common_times, cam_times, cam_yaw_neg)
cam_c_neg = cam_resampled_neg - cam_resampled_neg.mean()

corr_neg = np.correlate(cam_c_neg, imu_c, mode='full')
best_lag_neg = lags[search_mask][np.argmax(corr_neg[search_mask])]
print("추정된 오프셋:", best_lag_neg * common_dt, "초 (정답:", true_offset_neg, ")")
----

[source]
----
추정된 오프셋: -0.02 초 (정답: -0.02 )
----

음수 오프셋(카메라가 IMU보다 먼저 기록되는, 즉 "지연"이 아니라 "앞섬")도 정확히 찾아냈습니다 — 교차상관은 어느 신호가 어느 방향으로 밀려 있는지에 대해 대칭적으로 작동하므로, 부호에 상관없이 같은 방법을 그대로 쓸 수 있습니다. 실전에서는 어느 센서가 더 지연되는지 미리 알 수 없는 경우가 많으므로, 이렇게 양쪽 부호를 모두 탐색 범위에 포함시키는 것이 중요합니다(이 장의 `search_mask`가 `-40`부터 `40`까지 양쪽을 다 포함했던 이유입니다).

== 요약

* 두 센서가 공통으로 측정하는 물리량(각속도 등)을 공통 타임라인에 리샘플링하고 교차상관을 계산하면, 두 신호가 가장 잘 겹치는 시간 오프셋을 데이터만으로 찾을 수 있습니다.
* 교차상관의 최댓값 근처 세 점을 포물선으로 근사하는 서브샘플 보간으로, 리샘플링 그리드 간격보다 훨씬 정밀한(이 실험에서는 `1ms` 미만) 오프셋 추정치를 얻을 수 있습니다.
* 신호가 다채롭게 변할수록(급격한 방향 전환이 많을수록) 교차상관의 최댓값이 뾰족하게 드러나 정확한 추정이 쉬워지고, 단조로운 신호에서는 오프셋을 구별하기 어렵습니다.
* 다음 장에서는 이렇게 추정한 오프셋과 3장의 보간이 실제로 얼마나 잘 맞아떨어졌는지, 정렬 품질 자체를 수치로 검증하는 법을 다룹니다.
