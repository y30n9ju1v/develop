'''

8장의 특징(가장자리 방향 히스토그램)은 위치에는 완전히 무감각했지만, 그 대가로 색 정보와 "이미지의 어느 부분이 다른지"에 대한 정보를 모두 잃었습니다. 이 장에서는 이미지를 작은 구역(격자)으로 나눠 **구역별로** 색과 가장자리 특징을 뽑는, 조금 더 정교한 토이(장난감) 버전을 만들어 지금까지의 모든 실패 사례에 다시 적용합니다.

== 격자 기반 특징 추출기

이미지를 `grid × grid`개의 구역으로 나누고, 각 구역마다 (1) 평균 색, (2) 가장자리 방향 히스토그램을 구해 이어붙입니다.

[source,python]
----
import numpy as np
from scipy.ndimage import sobel

def block_features(img_rgb, grid=2):
    H, W, _ = img_rgb.shape
    gray = img_rgb.mean(axis=2)
    gx, gy = sobel(gray, axis=1), sobel(gray, axis=0)
    mag = np.sqrt(gx ** 2 + gy ** 2)
    ang = np.arctan2(gy, gx)

    feats = []
    hs, ws = H // grid, W // grid
    for i in range(grid):
        for j in range(grid):
            region = img_rgb[i * hs:(i + 1) * hs, j * ws:(j + 1) * ws]
            region_mag = mag[i * hs:(i + 1) * hs, j * ws:(j + 1) * ws]
            region_ang = ang[i * hs:(i + 1) * hs, j * ws:(j + 1) * ws]

            color_mean = region.mean(axis=(0, 1))                      # 이 구역의 평균 R,G,B
            hist, _ = np.histogram(region_ang, bins=6, range=(-np.pi, np.pi), weights=region_mag)
            hist = hist / (hist.sum() + 1e-8)                          # 이 구역의 가장자리 방향 분포

            feats.append(np.concatenate([color_mean, hist]))
    return np.concatenate(feats)

def feature_distance(a, b, grid=2):
    return np.linalg.norm(block_features(a, grid) - block_features(b, grid))
----

`grid=2`면 이미지를 `2×2`(네 구역)로 나눠, 각 구역마다 색`3`개 + 방향 히스토그램`6`개 = `9`개의 숫자를 뽑고, 전체 `4`구역을 이어붙여 `36`개짜리 벡터로 이미지를 요약합니다. 색 정보를 포함시킨 게 7장의 색맹 문제를, 구역으로 나눈 게 8장의 "위치 정보를 완전히 잃는" 문제를 각각 겨냥한 개선입니다.

== 세 가지 실패 사례에 다시 적용하기

=== 색맹 문제(7장): 고쳐졌는가

[source,python]
----
rng = np.random.default_rng(2)
M = 16
rgb_small = rng.random((M, M, 3))
rgb_swapped = rgb_small[:, :, [2, 1, 0]]   # R, B 채널을 맞바꿈

print("색 교환 특징 거리:", feature_distance(rgb_small, rgb_swapped, grid=2))
----

[source]
----
색 교환 특징 거리: 0.0980
----

7장에서 그레이스케일 SSIM이 `1.0`(완벽하게 닮음, 완전히 틀린 판단)을 줬던 바로 그 색 교환에, 이번엔 `0`이 아닌 뚜렷한 거리(`0.098`)가 나왔습니다 — 각 구역의 평균 색(`color_mean`)을 특징에 포함시켰기 때문입니다.

=== 흐림 vs 노이즈(4·6장): 순서가 유지되는가

[source,python]
----
from scipy.ndimage import gaussian_filter

N = 48
gray_sq = np.zeros((N, N))
gray_sq[N // 4:3 * N // 4, N // 4:3 * N // 4] = 1.0
gray_sq = gaussian_filter(gray_sq, sigma=1.0)
img_rgb = np.stack([gray_sq] * 3, axis=2)

blurred = gaussian_filter(gray_sq, sigma=1.2)
mse_blur = np.mean((gray_sq - blurred) ** 2)
noisy = gray_sq + rng.normal(0, np.sqrt(mse_blur), gray_sq.shape)

blurred_rgb = np.stack([blurred] * 3, axis=2)
noisy_rgb = np.stack([noisy] * 3, axis=2)

print("흐림 특징 거리:", feature_distance(img_rgb, blurred_rgb, grid=2))
print("노이즈 특징 거리:", feature_distance(img_rgb, noisy_rgb, grid=2))
----

[source]
----
흐림 특징 거리: 0.4415
노이즈 특징 거리: 0.5383
----

6장의 windowed SSIM과 같은 순서(노이즈가 흐림보다 더 나쁘다)가 이번에도 유지됐습니다.

=== 정렬 민감성(7장): 나아졌는가

[source,python]
----
from scipy.ndimage import shift

shifted1 = shift(gray_sq, shift=[0, 1], order=1, mode='nearest')
shifted1_rgb = np.stack([shifted1] * 3, axis=2)

print("1픽셀 이동 특징 거리:", feature_distance(img_rgb, shifted1_rgb, grid=2))
----

[source]
----
1픽셀 이동 특징 거리: 0.0938
----

`1`픽셀 이동에 대한 거리(`0.094`)가 흐림(`0.442`)이나 노이즈(`0.538`)보다 훨씬 작습니다 — 미세한 정렬 오차를, 실제 화질 저하(흐림·노이즈)보다 훨씬 가벼운 문제로 취급했다는 뜻입니다. 7장에서 SSIM이 `1`픽셀 이동만으로도 점수가 크게 떨어졌던 것과 비교하면 뚜렷한 개선입니다.

== 격자 크기의 트레이드오프

`grid`를 키우면(구역을 더 잘게 나누면) 어떻게 될까요? 8장에서 예고했던 "위치 정보를 얼마나 남길 것인가"라는 선택이 정확히 이 파라미터입니다.

[source,python]
----
for grid in [1, 2, 4, 8]:
    print(f"grid={grid}: 1픽셀 이동 특징 거리 =", feature_distance(img_rgb, shifted1_rgb, grid=grid))
----

[source]
----
grid=1: 0.0000
grid=2: 0.0938
grid=4: 1.1807
grid=8: 1.3655
----

`grid=1`(이미지 전체를 구역 하나로, 8장의 전역 방식과 사실상 같음)은 `1`픽셀 이동에 완전히 무감각(`0.0`)하지만, `grid=8`(잘게 쪼갬)로 갈수록 이동에 점점 더 민감해집니다 — 구역이 작아질수록 "어느 구역에 무엇이 있는가"라는 위치 정보를 더 세밀하게 담게 되고, 그만큼 그 위치가 조금만 바뀌어도 특징이 크게 달라지기 때문입니다. `grid=2`는 색맹·흐림/노이즈 구별·정렬 둔감성이라는 세 마리 토끼를 어느 정도 균형 있게 잡은 지점이었던 셈입니다.

== 이 토이 지표의 한계: 여전히 손으로 설계했다

이 장의 특징 추출기가 8장보다 나아졌다고 해서 진짜 LPIPS를 대체할 수 있는 건 전혀 아닙니다. 격자 크기, 히스토그램 구간(`bins`) 수, 색과 가장자리를 어떤 비율로 섞을지 같은 모든 설계 선택을 **사람이 직접 정했습니다** — 그리고 이 설계가 "사람의 실제 지각 판단"과 얼마나 잘 맞는지는 전혀 검증하지 않았습니다(그저 우리가 앞서 만든 몇 가지 인위적인 실패 사례에서 그럴듯하게 작동했을 뿐입니다). 진짜 LPIPS는 이 두 가지를 모두 데이터로 대체합니다 — 특징 자체는 수백만 장의 이미지로 학습된 신경망이 스스로 찾아내고, 그 특징들의 중요도는 수만 건의 사람 판단 데이터로 보정합니다. 이 장에서 손으로 이렇게까지 설계해도 완벽과는 거리가 멀다는 걸 직접 겪어본 게, 왜 실전에서는 학습된 특징을 쓰는지에 대한 감을 잡는 데 도움이 될 것입니다.

== 직접 해보기

* 히스토그램 구간 수(`bins`)를 `6`에서 `2`(방향을 아주 거칠게만 구분)로 줄이면, 흐림과 노이즈를 구별하는 능력이 어떻게 달라지는지 확인해보세요.

[source,python]
----
def block_features_bins(img_rgb, grid=2, bins=6):
    H, W, _ = img_rgb.shape
    gray = img_rgb.mean(axis=2)
    gx, gy = sobel(gray, axis=1), sobel(gray, axis=0)
    mag = np.sqrt(gx ** 2 + gy ** 2)
    ang = np.arctan2(gy, gx)
    feats = []
    hs, ws = H // grid, W // grid
    for i in range(grid):
        for j in range(grid):
            region = img_rgb[i*hs:(i+1)*hs, j*ws:(j+1)*ws]
            region_mag = mag[i*hs:(i+1)*hs, j*ws:(j+1)*ws]
            region_ang = ang[i*hs:(i+1)*hs, j*ws:(j+1)*ws]
            color_mean = region.mean(axis=(0, 1))
            hist, _ = np.histogram(region_ang, bins=bins, range=(-np.pi, np.pi), weights=region_mag)
            hist = hist / (hist.sum() + 1e-8)
            feats.append(np.concatenate([color_mean, hist]))
    return np.concatenate(feats)

for bins in [2, 6]:
    fb = np.linalg.norm(block_features_bins(img_rgb, 2, bins) - block_features_bins(blurred_rgb, 2, bins))
    fn = np.linalg.norm(block_features_bins(img_rgb, 2, bins) - block_features_bins(noisy_rgb, 2, bins))
    print(f"bins={bins}: 흐림={fb:.4f}, 노이즈={fn:.4f}, 차이={fn - fb:.4f}")
----

[source]
----
bins=2: 흐림=0.4313, 노이즈=0.5816, 차이=0.1503
bins=6: 흐림=0.4415, 노이즈=0.5383, 차이=0.0968
----

예상과 반대되는 결과입니다 — `bins`을 `6`에서 `2`로 줄였는데도(방향 정보가 더 거칠어졌는데도) 흐림과 노이즈의 점수 차이는 오히려 더 커졌습니다(`0.097 → 0.150`). "특징을 세밀하게 쪼갤수록 항상 더 잘 구별한다"는 직관이 이 경우엔 틀렸다는 뜻입니다 — 노이즈는 방향이 거의 무작위로 흩어지므로 구간을 거칠게(`bins=2`) 나눠도 여전히 "이도 저도 아니게 고르게 퍼진 히스토그램"으로 나타나는 반면, 흐림은 원래 있던 몇 개의 뚜렷한 방향(사각형의 상하좌우 경계)이 구간을 거칠게 나눠도 여전히 그 소수의 구간에 몰리기 때문에, 오히려 거친 구간 수가 "뚜렷한 소수 방향 vs 고르게 흩어짐"이라는 차이를 더 선명하게 만든 것으로 보입니다. 이 결과는 특징 설계에서 "더 세밀하게"가 항상 "더 낫다"는 뜻이 아니라는 걸 보여주는 좋은 반례입니다 — 실제로 어떤 설계가 더 나은지는 이렇게 직접 실험해보기 전까지는 예측하기 어렵고, 이것이 바로 사람이 손으로 설계하는 특징의 근본적인 어려움입니다.

== 요약

* 이미지를 격자로 나눠 구역별 색과 가장자리 방향을 특징으로 삼으면, 색맹 문제(7장)를 고치고 흐림/노이즈의 상대적 순서(6장)를 유지하면서도 정렬 오차(7장)에는 훨씬 둔감한 지표를 만들 수 있습니다.
* 격자 크기는 "위치 정보를 얼마나 남길 것인가"의 다이얼입니다 — 구역이 클수록 정렬 오차에 둔감해지고, 작을수록 위치 변화에 민감해집니다.
* 이 토이 지표도 여전히 사람이 모든 설계를 직접 정했고 사람의 실제 판단으로 검증되지 않았다는 근본적인 한계가 있으며, 이것이 실전에서 학습된 특징(LPIPS)을 쓰는 이유입니다.
* 지금까지의 모든 지표(MSE, PSNR, SSIM, 토이 지각 지표)는 이미지 한 장과 다른 한 장을 비교했습니다 — 다음 부(10~11장)에서는 "이미지 한 장"이 아니라 "이미지 뭉치 전체"가 얼마나 그럴듯한지 재는 방법을 다룹니다.
