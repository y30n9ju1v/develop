1장에서 사진 한 장으로는 깊이를 알 수 없다는 걸 확인했습니다. 이 장에서는 **두 번째 사진**이 이 문제를 어떻게 좁혀주는지 봅니다.

== 한 점의 대응점은 아무 데나 있지 않다

카메라1에서 어떤 점 `x1`을 봤다고 합시다. 이 점이 실제로 3차원 공간 어디에 있는지는 모르지만(1장에서 본 깊이 모호성), "카메라1 중심에서 `x1` 방향으로 뻗은 광선(레이저 빔) 위 어딘가"라는 건 압니다. 이제 이 광선을 옆에 있는 카메라2가 바라보면, 카메라2의 이미지 평면에는 그 광선이 **하나의 직선**으로 길게 그려집니다 — 이 직선을 **에피폴라 선(epipolar line)**이라고 부릅니다.

대응점 `x2`(같은 3D 점이 카메라2에 찍힌 위치)는 **반드시 이 에피폴라 선 위에 있어야** 합니다. 원래라면 두 번째 사진 전체(수백만 픽셀)를 다 뒤져야 대응점을 찾을 수 있지만, 이제는 이 선 하나만 따라가며 1차원으로 탐색하면 되는 것입니다.

== 기본행렬: 대응점이 만족해야 할 방정식

이 기하학적 제약을 대수식으로 정확히 표현한 것이 **기본행렬(fundamental matrix) `F`**(3×3 행렬)입니다. 두 카메라의 상대적 자세(회전 `R`, 이동 `t`)와 내부 파라미터 `K1`, `K2`를 안다면 `F`를 만들 수 있고, 대응하는 두 점의 픽셀 좌표(동차좌표)는 항상 `x2ᵀ F x1 = 0`을 만족합니다.

이 수식은 알고 보면 **직선의 방정식 `ax + by + c = 0`**과 완전히 같은 형태입니다:

* `F x1`: 1번 사진의 점 `x1`을 넣으면 2번 사진에 그려질 **직선의 계수 `l2 = (a, b, c)`**를 만들어내는 변환기입니다.
* `x2ᵀ (F x1) = 0`: 2번 사진의 점 `x2`를 그 직선에 대입했을 때 **`a·u2 + b·v2 + c = 0`으로 딱 떨어진다**(즉, 점 `x2`가 직선 위에 올라타 있다)는 뜻입니다.

[source,python]
----
import numpy as np

def skew(v):
    """벡터 v의 외적을 행렬 곱으로 표현하는 반대칭(skew-symmetric) 행렬."""
    x, y, z = v
    return np.array([
        [0, -z, y],
        [z, 0, -x],
        [-y, x, 0],
    ])

def rotation_y(theta):
    c, s = np.cos(theta), np.sin(theta)
    return np.array([
        [c, 0, s],
        [0, 1, 0],
        [-s, 0, c],
    ])
----

`skew(v)`와 `rotation_y`가 갑자기 등장한 이유는 다음과 같습니다:

1. **외적(`×`)이 필요한 이유 (기하학적 조건)**: 카메라1의 중심, 카메라2의 중심, 그리고 3D 점 `X`는 공간에서 하나의 평면(에피폴라 평면)을 이룹니다. 이 "세 점이 한 평면에 놓인다(공면 조건)"는 기하학적 관계를 수식으로 쓰면 이동 벡터 `t`와의 **외적**이 포함된 `x2 · (t × R x1) = 0`이 됩니다.
2. **`skew` 행렬로 바꾸는 이유 (대수적 변환)**: 수식에 외적(`×`)이 섞여 있으면 전체를 `x2ᵀ F x1 = 0` 같은 깔끔한 행렬 곱으로 묶을 수 없습니다. 다행히 벡터 외적 `t × w`는 반대칭 행렬과의 행렬 곱 `skew(t) @ w`와 100% 동일하므로, 수식을 `x2ᵀ · (skew(t) @ R) · x1 = 0`으로 바꿔 쓸 수 있습니다. 이 가운데 묶인 **`skew(t) @ R`이 바로 본질행렬 `E`**가 됩니다.
3. **`rotation_y`**: 2장의 `rotation_z`처럼 카메라2를 y축 기준으로 회전 배치하기 위한 헬퍼 함수입니다.

== 두 카메라 설정하기

[source,python]
----
R1, t1 = np.eye(3), np.zeros(3)                 # 카메라1: 원점, 회전 없음
R2 = rotation_y(np.radians(10))                   # 카메라2: y축 기준 10도 회전
C2 = np.array([0.5, 0.0, 0.0])                    # 오른쪽으로 0.5m 이동
t2 = -R2 @ C2

K = np.array([
    [800.0, 0, 320.0],
    [0, 800.0, 240.0],
    [0, 0, 1],
])

def project(K, R, t, X_world):
    X_cam = R @ X_world + t
    x_h = K @ X_cam
    return x_h[:2] / x_h[2]
----

카메라1을 세계 좌표계의 원점에 두면(`R1=I, t1=0`), 2장에서 배운 강체 변환의 성질 덕분에 세계 좌표계가 곧 카메라1의 좌표계가 됩니다 — 카메라2로의 상대적 자세(`R_rel, t_rel`)를 그대로 `R2, t2`로 쓸 수 있습니다.

== 본질행렬에서 기본행렬로

[source,python]
----
R_rel, t_rel = R2, t2
E = skew(t_rel) @ R_rel
F = np.linalg.inv(K).T @ E @ np.linalg.inv(K)
----

`E = [t_rel]_× R_rel`(본질행렬, essential matrix)는 **정규화된**(내부 파라미터가 없는) 좌표계에서의 에피폴라 제약을 담습니다 — 5장에서 이 행렬 자체를 더 깊이 다룹니다. 여기에 내부 파라미터의 역행렬을 양쪽에서 씌우면(`Kᵀ⁻¹ E K⁻¹`), 실제 픽셀 좌표에 바로 쓸 수 있는 기본행렬 `F`가 됩니다.

== 에피폴라 제약을 실제로 확인하기

[source,python]
----
X_world = np.array([0.3, 0.2, 3.0])
x1 = project(K, R1, t1, X_world)
x2 = project(K, R2, t2, X_world)
print("x1:", x1, "x2:", x2)  # x1: [400.   293.33] x2: [406.71 293.53]

def to_homog(x):
    return np.array([x[0], x[1], 1.0])

residual = to_homog(x2) @ F @ to_homog(x1)
print("epipolar residual:", residual)   # 2.78e-17 (사실상 0)
assert abs(residual) < 1e-8
----

같은 3D 점 `X_world`를 두 카메라에 투영해서 얻은 진짜 대응점 쌍 `(x1, x2)`은, `x2ᵀ F x1`을 계산하면 부동소수점 오차 수준(`~10⁻¹⁷`)으로 정확히 `0`이 나옵니다 — 4장 서두에서 말한 "에피폴라 선 위에 있어야 한다"는 기하학적 제약이, 실제로는 이 대수 방정식 하나로 정확히 표현된다는 걸 확인했습니다.

== 대응되지 않는 점은 이 제약을 어긴다

[source,python]
----
x2_wrong = x2 + np.array([50.0, 0.0])
residual_wrong = to_homog(x2_wrong) @ F @ to_homog(x1)
print("wrong-pair residual:", residual_wrong)  # -0.000362
assert abs(residual_wrong) > 1e-4
----

`x2`를 픽셀 `50`만큼 억지로 옮긴(더 이상 진짜 대응점이 아닌) 좌표로 같은 계산을 하면, 잔차가 `0`에서 확 벗어납니다. 이 성질이 실전에서 그대로 쓰입니다 — 특징점을 잘못 매칭한 "이상치(outlier)"를 걸러낼 때, 에피폴라 잔차가 큰 쌍을 버리는 방식으로(3부의 SfM 파이프라인에서 다시 만납니다).

== F는 랭크 2 행렬이다

[source,python]
----
svals = np.linalg.svd(F, compute_uv=False)
print("singular values of F:", svals)
# [1.27e-02  2.81e-05  1.21e-37]
assert svals[2] < 1e-6 * svals[0]
----

`F`의 특이값(singular value) 세 개 중 마지막이 사실상 `0`이라는 걸 확인했습니다 — 즉 `F`는 **랭크(rank) 2** 행렬입니다. 이건 우연이 아니라 `E = [t]_× R`이라는 구성 자체에서 나오는 구조적 성질입니다(`[t]_×`가 이미 랭크 2이기 때문입니다). 실전에서 여러 점 쌍으로부터 `F`를 추정할 때(3부에서 다룹니다), 이 랭크 조건을 강제하는 게 추정 정확도를 크게 높입니다.

== 직접 해보기

* 카메라2의 이동을 `C2 = (0.5, 0.0, 0.0)`에서 `C2 = (0.0, 0.0, 0.0)`(즉 순수 회전만, 이동 없음)으로 바꾸면 `E`와 `F`가 어떻게 되는지 계산해보고, 그 결과가 왜 당연한지 생각해보세요.

.해답 보기
[%collapsible]
====
[source,python]
----
t_rel_zero = -R2 @ np.array([0.0, 0.0, 0.0])
E_zero = skew(t_rel_zero) @ R2
print(E_zero)  # 전부 0 행렬
----

`t_rel = 0`이면 `skew(t_rel)`이 영행렬이 되고, 따라서 `E = 0`, `F = 0`이 됩니다 — 에피폴라 제약이 아무 정보도 주지 않는다는 뜻입니다. 실제로 순수 회전(이동 없음)만 있는 두 카메라는 서로 다른 시점(viewpoint)이 아니라 그냥 "같은 자리에서 고개만 돌린" 것과 같아서, 깊이 정보를 전혀 새로 얻을 수 없습니다 — 삼각측량이 가능하려면 카메라 사이에 실제 이동(**시차, parallax**)이 있어야 한다는 사실을 이 극단적인 경우가 보여줍니다.
====

== 전체 코드

[source,python]
----
import numpy as np

# 1. 반대칭 행렬(skew), y축 회전행렬, 투영 함수 정의
def skew(v):
    """벡터 v의 외적을 행렬 곱으로 표현하는 반대칭(skew-symmetric) 행렬."""
    x, y, z = v
    return np.array([
        [0, -z, y],
        [z, 0, -x],
        [-y, x, 0],
    ])

def rotation_y(theta):
    c, s = np.cos(theta), np.sin(theta)
    return np.array([
        [c, 0, s],
        [0, 1, 0],
        [-s, 0, c],
    ])

def project(K, R, t, X_world):
    X_cam = R @ X_world + t
    x_h = K @ X_cam
    return x_h[:2] / x_h[2]

def to_homog(x):
    return np.array([x[0], x[1], 1.0])

# 2. 두 카메라의 내부/외부 파라미터 및 본질/기본행렬 구성
K = np.array([
    [800.0, 0, 320.0],
    [0, 800.0, 240.0],
    [0, 0, 1],
])

R1, t1 = np.eye(3), np.zeros(3)
R2 = rotation_y(np.radians(10))
C2 = np.array([0.5, 0.0, 0.0])
t2 = -R2 @ C2

R_rel, t_rel = R2, t2
E = skew(t_rel) @ R_rel
F = np.linalg.inv(K).T @ E @ np.linalg.inv(K)

# 3. 3D 점 투영 및 에피폴라 제약(x2.T @ F @ x1 == 0) 검증
X_world = np.array([0.3, 0.2, 3.0])
x1 = project(K, R1, t1, X_world)
x2 = project(K, R2, t2, X_world)
print("x1:", x1, "x2:", x2)

residual = to_homog(x2) @ F @ to_homog(x1)
print("epipolar residual:", residual)
assert abs(residual) < 1e-8

# 4. 잘못된 대응점에 대한 잔차 확인 (이상치 검출 원리)
x2_wrong = x2 + np.array([50.0, 0.0])
residual_wrong = to_homog(x2_wrong) @ F @ to_homog(x1)
print("wrong-pair residual:", residual_wrong)
assert abs(residual_wrong) > 1e-4

# 5. 기본행렬 F의 랭크 2 성질 검증 (SVD 특이값 확인)
svals = np.linalg.svd(F, compute_uv=False)
print("singular values of F:", svals)
assert svals[2] < 1e-6 * svals[0]

# 6. 직접 해보기: 이동이 없을 때(C2=[0,0,0], 순수 회전) E와 F는 영행렬
t_rel_zero = -R2 @ np.array([0.0, 0.0, 0.0])
E_zero = skew(t_rel_zero) @ R2
print("E_zero:\n", E_zero)
assert np.allclose(E_zero, np.zeros((3, 3)))
----

== 요약

* 카메라1에서 본 점은 카메라2의 이미지 평면에서 하나의 직선(에피폴라 선)으로 제약되고, 대응점은 반드시 그 직선 위에 있어야 합니다.
* 이 제약은 `x2ᵀ F x1 = 0`이라는 대수 방정식으로 정확히 표현되고, `F`는 본질행렬 `E = [t]_× R`에 내부 파라미터를 씌워 얻습니다.
* 진짜 대응점은 이 방정식을 만족하고, 잘못된 대응은 만족하지 않는다는 걸 직접 확인했습니다 — 이 성질이 이상치 제거의 기반입니다.
* `F`는 항상 랭크 2 행렬이고, 이동이 없는(순수 회전) 두 카메라 사이에서는 `E=F=0`이 되어 깊이 정보를 전혀 얻을 수 없습니다.

다음 장에서는 본질행렬 `E`를 실제로 분해해서, 두 카메라의 상대적 회전과 이동(자세)을 복원하는 법을 다룹니다.
