10장에서 오도메트리를 계속 이어붙이면 드리프트가 쌓인다는 걸 확인했습니다. 이 장에서는 궤적 전체를 다시 최적화하는 **포즈 그래프 최적화(pose graph optimization)**를 구현합니다 — 그리고 놀랍게도, 아직은 이게 10장의 체이닝과 **완전히 같은 답**을 준다는 걸 확인합니다. 왜 그런지, 그리고 무엇이 더 필요한지가 이 장의 핵심입니다.

== 궤적을 그래프로 표현하기

각 시점의 자세를 **노드(node)**로, 두 자세 사이에 알려진 상대 변환(오도메트리 측정치)을 **간선(edge)**으로 그리면, 궤적 전체가 하나의 그래프가 됩니다. 10장에서는 이 그래프를 그냥 순서대로 이어붙였을 뿐입니다 — 이 장에서는 대신, **모든 노드를 동시에 미지수로 두고, 모든 간선의 제약을 동시에 가장 잘 만족시키는 자세들을 찾습니다**. 9장의 번들 조정과 발상이 완전히 같습니다 — 다만 최적화 대상이 "카메라 자세 + 3D 점"이 아니라 "궤적의 자세들"뿐이라는 차이가 있습니다.

== 간선의 잔차: 예측된 상대 자세 vs 측정된 상대 자세

[source,python]
----
import numpy as np
from scipy.optimize import least_squares

edges = [(i, i + 1, noisy_relatives[i]) for i in range(n_steps)]  # 오도메트리 간선만

def pose_graph_residuals(params):
    poses = unpack_poses(params)
    res = []
    for i, j, (R_meas, t_meas) in edges:
        R_pred, t_pred = relative_pose(poses[i], poses[j])
        R_err = R_pred.T @ R_meas
        rot_res = rot_to_rodrigues(R_err)
        trans_res = t_pred - t_meas
        res.append(rot_res)
        res.append(trans_res)
    return np.concatenate(res)
----

각 간선 `(i, j)`마다, "현재 추정한 노드 `i`, `j`의 자세로부터 계산한 상대 변환"(`relative_pose`, 10장에서 이미 만든 함수)과 "실제로 측정된 상대 변환"(`noisy_relatives[i]`, 4~7장의 방법으로 얻었다고 가정하는 값) 사이의 차이가 잔차입니다. 회전 오차는 두 회전행렬의 차이를 다시 축-각 벡터로 바꿔서 재고(`R_err`가 항등행렬에 가까울수록 `rot_res`가 `0`에 가까워집니다), 이동 오차는 그냥 벡터 차입니다.

== 최적화 실행

[source,python]
----
x0 = pack_poses(chained_poses)  # 10장의 체이닝 결과를 초기값으로 사용
result = least_squares(pose_graph_residuals, x0, method="lm", xtol=1e-14, ftol=1e-14)
optimized_poses = unpack_poses(result.x)
----

9장과 마찬가지로 노드0을 원점에 고정해서 게이지를 없앱니다(포즈 그래프에는 9장 같은 스케일 모호성은 없습니다 — 모든 상대 자세에 이미 절대 크기의 이동 `t`가 들어있기 때문입니다). 초깃값은 10장에서 이미 구해둔 체이닝 결과를 그대로 씁니다.

== 놀라운 결과: 체이닝과 완전히 똑같다

[source,python]
----
max_diff = max(np.linalg.norm(op[1] - cp[1]) for op, cp in zip(optimized_poses, chained_poses))
print(max_diff)  # 1.63e-12
assert max_diff < 1e-6

loop_gap_opt = np.linalg.norm(optimized_poses[20][1] - optimized_poses[0][1])
print(loop_gap_opt)  # 0.626 -- 10장과 완전히 동일!
assert loop_gap_opt > 0.5
----

포즈 그래프 최적화를 돌렸는데도, 결과가 10장의 단순 체이닝과 소수점 12자리까지 **완전히 똑같습니다**. 드리프트(루프 간격 `0.626m`)도 전혀 줄어들지 않았습니다. 최적화라는 더 정교한 도구를 썼는데 왜 아무것도 나아지지 않았을까요?

== 왜 나아지지 않는가: 나무(tree) 구조에는 남는 자유도가 없다

이 결과는 버그가 아니라 **수학적으로 당연한 결과**입니다. 지금 이 그래프는 노드 `0-1-2-...-20`이 일렬로 이어진 **사슬(체인)**입니다 — 그래프 이론 용어로는 **나무(tree)** 구조(순환·루프가 전혀 없는 그래프)입니다. 나무 구조의 그래프에서는, 각 간선의 제약이 정확히 그 두 노드 사이의 자유도만 결정하고, 그 결정에 관여하는 다른 정보가 전혀 없습니다 — 노드1의 자세는 오직 노드0과 간선(0,1)만으로 정해지고, 노드2는 오직 노드1과 간선(1,2)로 정해지는 식입니다. 그러니 "모든 간선을 동시에 만족시키는 최적해"를 구해도, 그건 그냥 각 간선을 순서대로 적용한 것(체이닝)과 정확히 같습니다 — **되돌아볼 대상이 없으니 최적화도 새로 배울 게 없는 것**입니다.

== 순환이 있어야 정보가 생긴다

9장에서 번들 조정이 실제로 도움이 됐던 이유를 떠올려보세요 — 한 3D 점을 **여러 카메라가 동시에** 관측했기 때문에, 그 여러 관측이 서로를 견제하며 오차를 눌러줄 수 있었습니다. 포즈 그래프도 마찬가지입니다 — 지금처럼 노드 하나가 정확히 이웃 노드 하나와만 연결되어 있으면, 그 연결을 두 번 볼 방법이 없습니다. 하지만 만약 그래프에 **순환(cycle)**이 하나 생긴다면 — 예를 들어 "지금 위치가 예전 노드 `0`과 같은 곳"이라는 **두 번째 간선**이 노드 `20`과 노드 `0` 사이에 추가된다면 — 이제 노드 `0`에서 노드 `20`으로 가는 경로가 **두 가지**(사슬을 따라 20번 돌아가는 길, 그리고 새 간선으로 곧장 가는 길) 생깁니다. 이 두 경로가 서로 다른 답을 준다면, 최적화는 비로소 "둘을 절충해서 전체적으로 가장 그럴듯한 답"을 찾아야 하는 진짜 문제를 풀게 됩니다 — 이게 다음 장의 **루프 클로저**입니다.

== 직접 해보기

* 노드0과 노드20 사이에 "이 둘은 사실 같은 위치다"라는 완벽한 간선(`R=I, t=0`)을 하나 추가하면 `pose_graph_residuals`의 잔차 벡터 길이가 어떻게 바뀌는지(간선이 하나 늘었으니 잔차도 6개 늘어야 합니다) 확인해보세요. 실제로 최적화 결과가 어떻게 달라지는지는 다음 장에서 다룹니다.

.해답 보기

====
[source,python]
----
edges_with_loop = edges + [(20, 0, (np.eye(3), np.zeros(3)))]

def pose_graph_residuals_loop(params):
    poses = unpack_poses(params)
    res = []
    for i, j, (R_meas, t_meas) in edges_with_loop:
        R_pred, t_pred = relative_pose(poses[i], poses[j])
        res.append(rot_to_rodrigues(R_pred.T @ R_meas))
        res.append(t_pred - t_meas)
    return np.concatenate(res)

before_len = len(pose_graph_residuals(x0))
after_len = len(pose_graph_residuals_loop(x0))
print(before_len, after_len)  # 120, 126 -- 정확히 6개(회전3+이동3) 늘어남
assert after_len == before_len + 6
----

== 요약

* 포즈 그래프 최적화는 모든 노드(자세)를 동시에 미지수로 두고, 모든 간선(상대 자세 제약)을 동시에 만족시키는 해를 찾습니다.
* 그래프가 나무(순환 없는 사슬) 구조라면, 최적화는 단순 체이닝과 수학적으로 완전히 같은 결과를 줍니다 — 최적화라는 도구 자체는 옳지만, 활용할 여분의 정보가 그래프 구조에 없기 때문입니다.
* 정보가 생기려면 그래프에 순환(같은 곳을 가리키는 두 번째 경로)이 있어야 하고, 그 순환이 바로 루프 클로저 간선입니다.
