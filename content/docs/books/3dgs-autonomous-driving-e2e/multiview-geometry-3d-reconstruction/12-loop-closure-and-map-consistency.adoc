'''

11장에서 오도메트리 간선만으로는 포즈 그래프 최적화가 아무것도 개선하지 못한다는 걸 확인했습니다 — 사슬(나무) 구조에는 되돌아볼 여분의 정보가 없기 때문이었습니다. 이 장에서는 그 여분의 정보, **루프 클로저(loop closure)** 간선을 실제로 추가해서 무슨 일이 일어나는지 봅니다.

== 루프 클로저: "여기 예전에 와본 곳이다"

차량이 원을 한 바퀴 돌아 출발점 근처로 돌아왔다고 합시다. 7장에서 다룬 특징점 매칭(또는 더 전역적인 장소 인식 기법)으로, "지금 카메라가 보는 장면이 예전 노드 `0`에서 본 장면과 사실상 같다"는 걸 알아챌 수 있습니다. 이 인식 결과를 노드 `20`과 노드 `0` 사이의 **새로운 간선**으로 그래프에 추가하는 게 루프 클로저입니다.

[source,python]
----
import numpy as np

# 루프 클로저: 노드20이 노드0과 (거의) 같은 위치임을 검출했다고 가정 (약간의 검출 잡음 포함)
loop_closure_measurement = add_noise(np.eye(3), np.zeros(3), rot_sigma=0.005, trans_sigma=0.02)
all_edges = odometry_edges + [(n_steps, 0, loop_closure_measurement)]
----

`add_noise(np.eye(3), np.zeros(3), ...)`가 "회전 없음, 이동 없음"(완전히 같은 위치)이라는 진짜 관계에 약간의 검출 잡음을 섞은 것입니다 — 장소 인식이나 재정렬(re-registration) 과정도 완벽하지 않다는 걸 반영합니다. 이 간선 하나가 11장에서 본 나무 구조를, 노드 `0-1-...-20-0`이라는 **순환(cycle)**을 가진 그래프로 바꿔놓습니다.

== 순환이 생긴 그래프 다시 최적화하기

최적화 코드 자체는 11장과 완전히 같습니다 — 다른 건 오직 간선 목록에 이 한 줄이 늘었다는 것뿐입니다.

[source,python]
----
result_loop = least_squares(make_residual_fn(all_edges), x0, method="lm", xtol=1e-14, ftol=1e-14)
poses_loop = unpack_poses(result_loop.x)

loop_gap_after = np.linalg.norm(poses_loop[20][1] - poses_loop[0][1])
print(loop_gap_after)  # 0.062
assert loop_gap_after < 0.08
----

11장에서 `0.626m`였던 시작-끝 간격이 `0.062m`로 **10배 넘게** 줄었습니다. 루프 클로저 간선이 "노드20은 노드0과 거의 같은 곳이어야 한다"는 제약을 직접 걸어준 것이니 이 정도는 예상할 수 있는 결과입니다.

== 진짜 놀라운 결과: 루프 반대편도 좋아진다

여기서 확인해야 할 진짜 흥미로운 지점은, **루프 클로저 간선이 직접 관여하지 않는** 다른 노드들도 함께 좋아지는지입니다.

[source,python]
----
mid_err_before = np.linalg.norm(chained_poses[10][1] - true_poses[10][1])
mid_err_after = np.linalg.norm(poses_loop[10][1] - true_poses[10][1])
print(mid_err_before, mid_err_after)  # 0.365 -> 0.024
assert mid_err_after < mid_err_before

err_before = np.mean([np.linalg.norm(cp[1] - tp[1]) for cp, tp in zip(chained_poses, true_poses)])
err_after = np.mean([np.linalg.norm(op[1] - tp[1]) for op, tp in zip(poses_loop, true_poses)])
print(err_before, err_after)  # 0.328 -> 0.035
assert err_after < err_before
----

노드 `10`(원의 정반대편, 루프 클로저 간선과 아무 직접적 연결이 없는 노드입니다)의 오차가 `0.365m`에서 `0.024m`로, **15배 넘게** 줄었습니다. 궤적 전체의 평균 오차도 `0.328m`에서 `0.035m`로 줄었습니다 — 루프 클로저 간선 단 하나가, 그 간선과 전혀 맞닿지 않은 노드들의 정확도까지 끌어올린 것입니다.

== 왜 반대편까지 좋아지는가

이게 바로 포즈 그래프 **최적화**가 단순 체이닝을 이길 수 있는 지점입니다. 노드 `0`에서 노드 `20`으로 가는 경로가 이제 두 개입니다 — 사슬을 따라 20번 도는 긴 경로와, 새 간선으로 곧장 가는 짧은 경로입니다. 최적화는 이 두 경로가 내놓는 답이 서로 어긋나지 않도록, **사슬에 쌓여있던 오차 전체를 20개의 간선에 걸쳐 골고루 나눠 갚습니다** — 특정 한두 구간만 억지로 구부리는 게 아니라, 각 오도메트리 간선이 "믿을 만한 정도"에 비례해서 조금씩 양보하는 것입니다(9장의 번들 조정이 여러 카메라의 관측을 동시에 조율했던 것과 똑같은 정신입니다). 노드 `10`이 정확히 사슬의 "반대편 절반 지점"에 있으니, 이 재분배의 효과를 가장 균형 있게 받는 지점 중 하나가 되는 것입니다.

== 이게 3DGS와 왜 관련 있는가

자율주행 데이터셋으로 3DGS를 학습할 때, 차량이 같은 골목을 두 번 지나가거나 교차로를 순환하는 구간이 흔합니다. 이 장에서 확인한 루프 클로저가 없다면, 3DGS가 재구성하는 지도에는 "같은 건물이 서로 다른 두 위치에 겹쳐서" 나타나는 유령 같은 결과(이중 재구성, ghosting)가 생깁니다 — 카메라 궤적 자체가 드리프트로 어긋나 있으니, 그 위에 쌓은 3D 가우시안들도 어긋난 궤적을 따라 잘못 배치되기 때문입니다. 3DGS 파이프라인이 SLAM/SfM 프론트엔드의 루프 클로저 품질에 크게 의존하는 이유가 여기 있습니다 — 아무리 렌더링 품질이 좋아져도, 애초에 입력으로 들어가는 카메라 궤적이 어긋나 있으면 재구성 자체가 어긋납니다.

== 직접 해보기

* 루프 클로저 검출 자체가 틀렸다고(예를 들어 노드`20`과 노드`0`이 사실은 `0.5m` 떨어져 있는데 완전히 같은 곳이라고 잘못 검출했다고) 가정하고, 그런 **잘못된** 루프 클로저 간선을 추가하면 궤적 전체가 오히려 나빠지는지 확인해보세요.

.해답 보기
[%collapsible]
====
[source,python]
----
wrong_loop = (np.eye(3), np.array([0.5, 0.0, 0.0]))  # 실제로는 거의 (0,0,0)이어야 하는데 잘못 검출
wrong_edges = odometry_edges + [(n_steps, 0, wrong_loop)]

result_wrong = least_squares(make_residual_fn(wrong_edges), x0, method="lm", xtol=1e-14, ftol=1e-14)
poses_wrong = unpack_poses(result_wrong.x)

err_wrong = np.mean([np.linalg.norm(op[1] - tp[1]) for op, tp in zip(poses_wrong, true_poses)])
print(err_wrong)  # err_after(0.035)보다 뚜렷하게 나쁨
assert err_wrong > err_after
----

잘못된 루프 클로저는 궤적 전체를 "존재하지 않는 제약"에 억지로 맞추려다 오히려 왜곡시킵니다 — 실전 SLAM 시스템이 루프 클로저 후보를 받아들이기 전에 기하학적 일관성(4장의 에피폴라 제약 같은)으로 꼼꼼히 검증하는 이유가 여기 있습니다. 틀린 루프 클로저 하나가 정상적인 오도메트리 20개보다 지도를 더 심하게 망칠 수 있습니다.

== 요약

* 루프 클로저는 "지금 위치가 예전의 특정 위치와 같다"는 인식을 그래프의 새 간선으로 추가하는 것이고, 이 간선이 사슬 구조를 순환 구조로 바꿔줍니다.
* 순환이 생기면 포즈 그래프 최적화가 비로소 실제로 오차를 줄여줍니다 — 두 경로(먼 길, 지름길)가 서로 다른 답을 낼 때, 최적화가 그 차이를 전체 간선에 걸쳐 재분배합니다.
* 루프 클로저 간선과 직접 연결되지 않은 노드(반대편 지점)의 정확도까지 함께 좋아진다는 걸 직접 확인했습니다.
* 잘못된 루프 클로저는 오히려 지도 전체를 왜곡시킬 수 있어, 실전에서는 후보를 기하학적으로 검증하는 절차가 필수입니다.

4부가 여기서 끝났습니다. 5부에서는 지금까지 재구성한 카메라 궤적과 점군이 3D Gaussian Splatting 같은 최신 장면 표현의 입력으로 어떻게 이어지는지, 그리고 재구성 품질을 종합적으로 재는 법을 다룹니다.
