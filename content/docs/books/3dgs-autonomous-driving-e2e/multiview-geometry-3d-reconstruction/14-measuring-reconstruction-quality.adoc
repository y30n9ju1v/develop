이 책 곳곳에서 재구성이 얼마나 정확한지를 다양한 방식으로 쟀습니다 — 8장의 재투영 오차, 9장의 카메라·점 오차, 12장의 궤적 오차. 이 마지막 장에서는 이 지표들을 하나의 **품질 리포트**로 정리하고, "카메라를 더 쓰면 무조건 좋아지는가?"라는 실전적인 질문에 직접 답해봅니다.

== 세 가지 핵심 지표

[source,python]
----
import numpy as np

def reprojection_rmse(K, poses, points, observations):
    """모든 (카메라, 점) 관측에 대한 재투영 오차의 RMSE."""
    errs = []
    for ci, pi, px_obs in observations:
        R, t = poses[ci]
        px_pred = project(K, R, t, points[pi])
        errs.append(np.sum((px_pred - px_obs) ** 2))
    return np.sqrt(np.mean(errs))

def mean_track_length(observations, n_points):
    """각 3D 점이 평균적으로 몇 개의 카메라에서 관측됐는지."""
    counts = np.zeros(n_points)
    for ci, pi, px_obs in observations:
        counts[pi] += 1
    return counts.mean()

def point_cloud_density(points, k=4):
    from scipy.spatial import cKDTree
    tree = cKDTree(points)
    dists, _ = tree.query(points, k=k + 1)
    return dists[:, 1:].mean()
----

* **재투영 오차(reprojection RMSE)**: 8~9장에서 계속 써온 지표 — 복원된 자세·점으로 다시 투영했을 때 실제 관측과 얼마나 차이 나는지.
* **평균 트랙 길이(mean track length)**: 각 3D 점을 평균적으로 몇 개의 카메라가 함께 봤는지. 6장에서 확인했듯 여러 시점이 한 점을 보면 볼수록(다중 뷰) 그 점의 삼각측량이 안정적일 잠재력이 커집니다.
* **점군 밀도(13장에서 만든 함수)**: 재구성된 점들이 얼마나 조밀한지.

== 카메라 2대 vs 5대 비교 실험

[source,python]
----
poses_shallow, points_shallow, obs_shallow, true_shallow = build_scenario(n_cams=2)
poses_deep, points_deep, obs_deep, true_deep = build_scenario(n_cams=5)
----

같은 장면(점 15개, 픽셀 잡음 `0.2`)을 카메라 2대로만 찍은 "얕은" 재구성과, 카메라 5대로 찍은 "깊은" 재구성을 준비합니다. 두 경우 모두 **점 삼각측량 자체는 카메라 0번과 1번만 사용**합니다(8장의 첫 단계와 같습니다, 아직 9장의 번들 조정은 적용하지 않았습니다) — 나머지 카메라(2~4번)는 그저 "더 많이 관측했다"는 사실만 더할 뿐, 재구성 계산에는 아직 관여하지 않습니다.

== 무엇이 좋아졌고, 무엇이 그대로인가

세 가지가 눈에 띕니다.

* **평균 트랙 길이는 정직하게 `2.0` → `5.0`으로 늘었습니다** — 카메라를 더 쓰면 각 점을 더 많은 시점이 보게 된다는 건 그냥 사실이니까요.
* **점군 밀도와 점 오차는 완전히 그대로입니다** — 당연합니다. 점 좌표 자체를 여전히 카메라 0-1만으로 계산했으니, 추가 카메라를 몇 대 더 세워놔 봐야 이미 계산된 점의 위치는 1픽셀도 바뀌지 않습니다.
* **재투영 오차(RMSE)는 오히려 5배 가까이 나빠졌습니다(`0.122` → `0.600`)!**

세 번째가 이 장에서 가장 중요한 관찰입니다. 카메라를 늘렸는데 왜 품질 지표가 나빠질까요?

== 카메라를 그냥 세워두기만 하면 오히려 손해다

이유는 명확합니다 — 새로 추가한 카메라 2~4번은 카메라 0-1로부터 점점 더 멀리 떨어져 있는데, 그 점들의 3D 위치는 여전히 카메라 0-1 두 대만의 (다소 부정확한) 삼각측량 결과입니다. 그 부정확한 점을 카메라 0-1과 가까운 시점(카메라 1)으로 재투영하면 오차가 작지만, 훨씬 멀리 떨어진 시점(카메라 4)으로 재투영하면 작은 3D 위치 오차도 큰 각도 차이 때문에 훨씬 큰 픽셀 오차로 증폭됩니다 — 4~5장의 카이랄리티, 6장의 깊이-시차 트레이드오프에서 계속 봐온 "기하학적 배치가 오차를 증폭시킨다"는 패턴이 여기서도 그대로 나타난 것입니다.

**이 장의 결론이 이 책 전체의 결론이기도 합니다** — 카메라(관측)를 그냥 많이 모으는 것과, 그 관측들을 실제로 **함께 활용해서 재구성을 다듬는 것**은 전혀 다른 일입니다. 후자가 정확히 9장의 번들 조정이 하는 일입니다 — 만약 이 5대짜리 시나리오에 번들 조정을 적용했다면(9장의 방법을 그대로 여기 재사용할 수 있습니다), 점들이 카메라 0-1뿐 아니라 2~4번까지 전부를 고려해서 다시 계산되어, 재투영 오차가 다시 낮아졌을 것입니다. "카메라를 더 쓰면 무조건 좋아지는가?"라는 이 장 서두의 질문에 대한 정확한 답은 이렇습니다 — **더 많은 관측이 실제로 최적화에 반영될 때만** 좋아집니다.

== 3DGS 재구성 품질을 진단할 때도 똑같다

3DGS로 재구성한 결과가 "카메라를 늘렸는데도 왜 이상하지"라는 질문에 부딪힌다면, 이 장에서 확인한 패턴을 가장 먼저 의심해봐야 합니다 — 입력으로 준 사진(관측)이 많다고 저절로 품질이 좋아지는 게 아니라, 그 사진들이 SfM/번들 조정(3부) 단계에서 실제로 함께 최적화되었는지, 그리고 궤적에 드리프트(4부)가 남아있지 않은지가 진짜 원인인 경우가 대부분입니다. 이 책의 모든 장 — 카메라 모델(1부)부터 게이지 고정(9장), 루프 클로저(12장)까지 — 가 결국 "왜 사진이 많아도 재구성이 부정확할 수 있는가"라는 하나의 질문에 대한 서로 다른 답이었던 셈입니다.

== 요약

* 재투영 오차, 평균 트랙 길이, 점군 밀도를 함께 보면 재구성 품질을 다각도로 진단할 수 있습니다.
* 카메라를 늘려도 그 관측이 실제 재구성 계산(삼각측량, 번들 조정)에 반영되지 않으면, 트랙 길이만 늘어날 뿐 정확도는 오히려 나빠질 수 있습니다.
* "관측이 많다"와 "관측을 활용한다"는 다른 문제이고, 9장의 번들 조정과 12장의 루프 클로저가 바로 그 활용을 실제로 해내는 도구들이었습니다.
* 3DGS를 포함한 모든 다중뷰 재구성 파이프라인에서, 사진을 늘려도 품질이 오르지 않는다면 최적화 단계가 그 사진들을 실제로 함께 쓰고 있는지부터 확인해야 합니다.
