1~9장에서 이 책이 만든 것은 두 가지입니다 — 각 사진이 찍힌 **카메라 자세**(내부 파라미터 `K`와 외부 파라미터 `R, t`)와, 장면의 **성긴 3D 점군**(sparse point cloud, 특징점을 삼각측량한 결과)입니다. 3D Gaussian Splatting(3DGS)은 정확히 이 두 가지를 입력으로 받아 학습을 시작합니다. 이 장에서는 이 둘이 어떻게 3DGS의 출발점이 되는지와, 장면 표현에 넘길 때 어떤 형식으로 정리해야 하는지를 봅니다.

== 좌표계 관례의 차이: World-to-Camera vs Camera-to-World

2장에서 카메라 좌표계를 다룰 때 `X_cam = R·X_world + t`(World-to-Camera, W2C)라는 방향으로 정의했습니다. 그런데 NeRF나 3DGS 같은 최신 장면 표현 라이브러리들은 대개 반대 방향, **Camera-to-World(C2W)** 행렬(카메라가 세계 좌표계의 어디에, 어느 방향으로 있는지를 바로 나타내는 4×4 행렬)을 씁니다. 두 관례를 오가는 법을 정확히 알아야 합니다.

[source,python]
----
import numpy as np

def world_to_camera_matrix(R, t):
    M = np.eye(4)
    M[:3, :3] = R
    M[:3, 3] = t
    return M

def camera_to_world_matrix(R, t):
    """W2C 행렬의 역행렬. 카메라 좌표계의 점을 세계 좌표계로 되돌린다."""
    M = np.eye(4)
    M[:3, :3] = R.T
    M[:3, 3] = C  # C = -R^T t, 카메라 중심의 세계 좌표
    return M

W2C = world_to_camera_matrix(R, t)
C2W = camera_to_world_matrix(R, t)
assert np.allclose(W2C @ C2W, np.eye(4), atol=1e-10)
----

2장에서 이미 `t = -R·C`라는 관계를 다뤘던 걸 떠올려보세요 — C2W 행렬의 회전 부분은 `R`의 전치(`Rᵀ`, 회전행렬이니 전치가 곧 역행렬입니다)이고, 이동 부분은 정확히 카메라 중심 `C`입니다. `W2C @ C2W`가 정확히 항등행렬이 된다는 걸 확인해서, 두 행렬이 서로의 역변환이라는 걸 검증했습니다.

[source,python]
----
assert np.allclose(C2W[:3, 3], C)

origin_cam = np.array([0.0, 0.0, 0.0, 1.0])
origin_world = C2W @ origin_cam
assert np.allclose(origin_world[:3], C)
----

C2W 행렬로 "카메라 좌표계의 원점"(카메라 자신의 위치)을 세계 좌표계로 옮기면, 정확히 카메라 중심 `C`가 나옵니다 — C2W 행렬 자체가 "카메라가 세계 어디에 있는가"를 그대로 담고 있다는 뜻입니다. 8~9장에서 복원한 모든 카메라 자세를, COLMAP이나 3DGS 학습 스크립트가 기대하는 입력 형식으로 넘기려면 이런 변환이 실제로 필요합니다.

== 성긴 점군에서 가우시안들의 초기 배치로

3DGS는 이름 그대로 장면을 수많은 3차원 가우시안(중심 위치, 크기·방향을 나타내는 공분산, 색, 불투명도)의 집합으로 표현하고, 미분가능 렌더링으로 이 가우시안들을 실제 사진들과 맞아떨어지도록 최적화합니다. 이 최적화가 처음부터 무작위로 시작하는 게 아니라, 이 책에서 만든 **SfM 점군을 초기 위치로** 삼는다는 게 핵심입니다 — 각 3D 점 하나가 가우시안 하나의 시작 중심이 됩니다.

여기서 실전적인 질문이 하나 생깁니다 — **각 가우시안의 초기 크기는 얼마로 정해야 할까요?** 점 하나만으로는 "이 주변이 얼마나 넓은 영역을 나타내야 하는지" 알 수 없습니다. 실제 3DGS 구현(그리고 그 바탕이 된 COLMAP)이 쓰는 방법은, **각 점 주변의 이웃 점들과의 거리**로 초기 크기를 정하는 것입니다.

[source,python]
----
from scipy.spatial import cKDTree

def initial_gaussian_scales(points, k=4):
    """각 점의 초기 스케일(공분산 크기)을, 가장 가까운 k개 이웃까지의 평균 거리로 정한다."""
    tree = cKDTree(points)
    dists, _ = tree.query(points, k=k + 1)  # k+1: 자기 자신 포함
    mean_neighbor_dist = dists[:, 1:].mean(axis=1)  # 자기 자신(거리 0) 제외
    return mean_neighbor_dist
----

`cKDTree`(k-d 트리)는 최근접 이웃을 빠르게 찾는 자료구조입니다 — 점이 수만~수십만 개인 실전 점군에서도 이 계산이 감당할 만한 이유입니다. 각 점에서 가장 가까운 `k`개 이웃까지의 평균 거리를, 그 점이 나타낼 가우시안의 초기 "반지름"으로 씁니다 — 점들이 조밀하게 몰려 있는 영역(디테일이 많은 표면)은 작은 가우시안으로, 점들이 듬성듬성한 영역(재구성이 성긴 부분)은 큰 가우시안으로 시작한다는 뜻입니다.

== 조밀한 영역과 성긴 영역의 초기 크기 차이 확인하기

[source,python]
----
dense_cluster = rng.uniform(-0.5, 0.5, size=(30, 3)) * 0.1 + np.array([0, 0, 3])
sparse_cluster = rng.uniform(-0.5, 0.5, size=(30, 3)) * 1.0 + np.array([5, 0, 8])
points = np.vstack([dense_cluster, sparse_cluster])

scales = initial_gaussian_scales(points)
dense_scales, sparse_scales = scales[:30], scales[30:]
print(dense_scales.mean(), sparse_scales.mean())  # 0.031, 0.287
assert dense_scales.mean() < sparse_scales.mean()
----

간격 `0.1`짜리 조밀한 점군과 간격 `1.0`짜리 성긴 점군을 섞어 만들어, 초기 스케일을 계산해보면 조밀한 쪽이 평균 `0.031`, 성긴 쪽이 `0.287`로 거의 `10`배 차이가 납니다 — 점군의 밀도가 그대로 초기 가우시안의 크기에 반영된다는 걸 확인했습니다. 6장에서 "카메라에서 먼 점일수록 삼각측량 오차가 크다"는 걸 확인했던 걸 떠올려보면, 먼 배경의 점들은 대체로 서로 듬성듬성 떨어져 있기 마련이라(오차가 크다는 건 점들이 정확한 표면 위에 조밀하게 몰리지 못한다는 뜻이기도 합니다), 초기 가우시안도 크고 뭉툭하게 시작합니다 — 다음 장에서 이 관찰을 재구성 품질 지표와 연결합니다.

== 여기서 이어서 생각할 문제

이 장에서 만든 것 — 카메라들의 C2W 행렬 목록, 초기 위치와 크기를 가진 가우시안들의 집합 — 이 정확히 3DGS 학습의 시작점입니다. 이후 과정(미분가능 래스터화, 손실 함수, 경사하강으로 가우시안들의 위치·크기·색·불투명도를 실제 사진과 맞게 다듬는 것)은 별도의 렌더링·학습 문제입니다. 다만 이 책 전체가 보여준 사실 하나는 분명합니다 — **3DGS가 아무리 정교해도, 그 출발점(카메라 자세와 점군)이 부정확하면 결과도 부정확합니다.** 9장의 번들 조정이 "단순한 수학적 재미"가 아니라 3DGS 재구성 품질에 직결되는 이유입니다.

== 직접 해보기

* `k`(이웃 개수)를 `4`에서 `1`로 줄이면 초기 스케일 계산이 어떻게 달라지는지, 그리고 왜 `k=1`이 잡음에 더 취약한지 생각해보세요.

.해답 보기
[%collapsible]
====
[source,python]
----
scales_k1 = initial_gaussian_scales(points, k=1)
print(scales_k1[:30].mean(), scales_k1[30:].mean())
----

`k=1`이면 딱 **가장 가까운 이웃 하나**까지의 거리만으로 스케일을 정하게 되어, 그 한 점이 우연히 아주 가깝거나 먼 이상치라면 스케일 추정 전체가 그 하나에 휘둘립니다 — `k=4`처럼 여러 이웃의 평균을 쓰면 이런 이상치 하나의 영향이 평균 속에 희석되어 훨씬 안정적입니다. 8~9장에서 여러 관측을 동시에 활용해 오차를 억누르는 것과 같은 원리가, 여기서도 "여러 이웃을 함께 본다"는 형태로 반복됩니다.
====

== 요약

* NeRF/3DGS 계열은 이 책이 써온 World-to-Camera 대신 Camera-to-World 관례를 쓰고, `R`의 전치와 카메라 중심 `C`로 그 행렬을 직접 구성할 수 있습니다.
* 3DGS는 SfM 점군의 각 점을 가우시안 하나의 초기 중심으로 삼고, k-d 트리로 구한 이웃 거리로 초기 크기를 정합니다.
* 점군이 조밀한 영역은 작은 초기 가우시안으로, 성긴 영역은 큰 초기 가우시안으로 시작합니다 — 이 책에서 확인한 재구성 오차 특성이 그대로 3DGS의 출발 조건에 반영됩니다.
