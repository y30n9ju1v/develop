== 카메라는 정보를 짓누르는 장치다

카메라는 3차원 세계의 점 `(X, Y, Z)`를 2차원 이미지의 픽셀 `(u, v)`로 바꿉니다. 이 과정에서 **깊이(Z) 정보가 사라집니다** — 카메라에서 멀리 있는 큰 물체와 가까이 있는 작은 물체가 사진에서는 똑같은 크기로 찍힐 수 있는 이유입니다. 멀티뷰 기하학 전체가 이 "짓눌린 정보"를 여러 장의 사진으로부터 되살리는 문제이니, 먼저 카메라가 정확히 어떻게 정보를 짓누르는지부터 정의해야 합니다.

== 핀홀 카메라 모델

가장 단순하고 널리 쓰이는 모델은 **핀홀 카메라(pinhole camera)**입니다 — 렌즈 없이, 빛이 아주 작은 구멍(핀홀) 하나를 통과해 반대편 상에 맺힌다고 가정합니다. 카메라 좌표계(카메라 중심이 원점, Z축이 카메라가 바라보는 방향)에서 점 `(X, Y, Z)`가 있을 때, 이 점이 초점거리 `f`인 이미지 평면에 투영되는 위치는 닮은꼴 삼각형으로 유도됩니다 — `x = f·(X/Z)`, `y = f·(Y/Z)`. `Z`로 나눈다는 게 핵심입니다 — 같은 방향에 있는 점들은 깊이가 달라도 같은 위치에 투영됩니다(뒤에서 코드로 직접 확인합니다).

== 내부 파라미터 행렬 K

실제 이미지는 밀리미터 단위가 아니라 픽셀 단위로 저장되고, 이미지의 원점(왼쪽 위 모서리 등)이 광축과 이미지 평면이 만나는 점(주점, principal point)과 다릅니다. 이 변환들을 전부 하나의 행렬로 묶은 게 **내부 파라미터 행렬(intrinsic matrix) K**입니다.

[source,python]
----
import numpy as np

fx, fy = 800.0, 800.0   # 초점거리(픽셀 단위, 가로/세로 축각각)
cx, cy = 320.0, 240.0   # 주점(이미지 중심에 가까운 픽셀 좌표)
K = np.array([
    [fx, 0,  cx],
    [0,  fy, cy],
    [0,  0,  1],
])

def project(K, X_cam):
    """카메라 좌표계에서의 3D 점을 픽셀 좌표로 투영한다."""
    x_h = K @ X_cam          # 동차좌표 (Z를 아직 나누지 않음)
    return x_h[:2] / x_h[2]  # Z로 나눠서 픽셀 좌표를 얻음
----

`f`는 핀홀과 센서 사이의 물리적 거리(mm)지만, `fx`, `fy`는 이를 픽셀 단위로 환산한 값입니다 — `fx = f / sx`, `fy = f / sy` (`sx`, `sy`는 센서 픽셀 한 칸의 가로/세로 크기, mm/pixel). 픽셀이 정사각형이면 `fx = fy`이지만, 실제로는 가로세로 크기가 달라질 수 있어 캘리브레이션 결과에는 둘을 따로 표기합니다. `cx`, `cy`는 주점의 픽셀 좌표입니다. `K`를 3D 점의 동차좌표(homogeneous coordinate)에 곱한 뒤 세 번째 성분(원래 `Z`)으로 나누는 게, 위에서 본 "`Z`로 나눈다"는 원근 투영을 행렬 곱으로 표현한 것입니다.

== 실제로 투영해보고 확인하기

[source,python]
----
X_cam = np.array([0.5, 0.25, 2.0])
pixel = project(K, X_cam)
print("pixel:", pixel)   # [520. 340.]

expected_u = fx * (0.5 / 2.0) + cx
expected_v = fy * (0.25 / 2.0) + cy
assert np.allclose(pixel, [expected_u, expected_v])
----

카메라 앞 `Z=2m` 거리, 광축에서 `X=0.5m`, `Y=0.25m` 벗어난 점을 투영하면 픽셀 `(520, 340)`이 나옵니다 — 손으로 계산한 `fx·(X/Z) + cx = 800·0.25 + 320 = 520`과 정확히 일치합니다(`np.allclose`는 컴퓨터의 미세한 부동소수점 반올림 오차를 감안해 두 배열의 모든 원소가 실질적으로 같은지 검증해주는 NumPy 함수입니다).

== 광축 위의 점과 원근 투영의 깊이 무관성

[source,python]
----
on_axis = project(K, np.array([0.0, 0.0, 5.0]))
assert np.allclose(on_axis, [cx, cy])

p_near = project(K, np.array([0.5, 0.25, 2.0]))
p_far  = project(K, np.array([1.0, 0.5, 4.0]))
assert np.allclose(p_near, p_far)
----

`X=Y=0`인 점(광축 위의 점)은 깊이가 얼마든 정확히 주점 `(cx, cy)`로 투영됩니다 — 카메라가 정면으로 바라보는 방향의 점은 항상 이미지 중앙에 찍힌다는 뜻입니다. 더 흥미로운 건 두 번째 확인입니다 — `(0.5, 0.25, 2.0)`과 그 방향을 그대로 2배 늘인 `(1.0, 0.5, 4.0)`이 **똑같은 픽셀**로 투영됩니다. 이게 서두에서 말한 "깊이 정보의 소실"이 실제로 일어나는 모습입니다 — 사진 한 장만으로는 이 두 점을 구별할 수 없습니다. 이 모호함을 없애려면 다른 위치에서 찍은 두 번째 사진이 필요하고, 그게 이 책 2부의 주제입니다.

== 직접 해보기

* 초점거리를 2배로(`fx=fy=1600`) 늘리면, 같은 3D 점이 투영되는 픽셀이 주점에서 얼마나 더 멀어지는지 계산하고 코드로 확인해보세요.

.해답 보기
[%collapsible]
====
[source,python]
----
K2 = np.array([
    [1600.0, 0,      cx],
    [0,      1600.0, cy],
    [0,      0,      1],
])
pixel2 = project(K2, X_cam)
print(pixel2)  # [720. 440.]

# 주점으로부터의 거리(오프셋)가 정확히 2배가 된다
offset1 = pixel - np.array([cx, cy])   # [200. 100.] (fx=800일 때 주점으로부터의 거리)
offset2 = pixel2 - np.array([cx, cy])  # [400. 200.] (fx=1600일 때 주점으로부터의 거리, 정확히 2배)
assert np.allclose(offset2, 2 * offset1)
----

초점거리가 커지면 카메라가 "더 확대해서" 찍는 셈이라, 주점에서 벗어난 정도(오프셋)가 초점거리에 정비례해서 커집니다 — 망원 렌즈일수록 작은 각도 변화가 이미지에서 큰 픽셀 이동으로 나타나는 이유입니다.

여기서 "확대"는 화각(FOV)이 좁아진다는 뜻입니다 — `x = f·(X/Z)`에서 `f`가 커지면 같은 3D 점이 이미지 평면 위에서 더 먼 위치에 맺히므로, 같은 크기의 센서에는 더 좁은 각도 범위의 광선만 담기게 됩니다. 그 좁은 범위가 센서 전체를 채우니 물체가 더 크게(확대되어) 찍히는 것이죠 — 망원 렌즈가 배경은 좁게 잘라내면서 피사체를 크게 담는 것과 같은 원리입니다. 이건 센서 픽셀 크기(`sx`, `sy`)가 작아져서 `fx`가 커지는 경우와는 다릅니다 — 픽셀이 작아지는 건 같은 화각을 더 잘게 나눠 담는 해상도 증가일 뿐, 화각 자체는 그대로입니다.

== 요약

* 카메라는 3D 점 `(X,Y,Z)`를 `Z`로 나누는 원근 투영을 통해 2D 픽셀로 짓누릅니다 — 이 과정에서 깊이 정보가 사라집니다.
* 내부 파라미터 행렬 `K`(초점거리 `fx,fy`와 주점 `cx,cy`)가 이 투영을 실제 픽셀 좌표로 정확히 변환합니다.
* 같은 방향, 다른 깊이의 점들은 한 장의 사진에서 구별할 수 없다는 것을 코드로 직접 확인했습니다 — 이 모호함이 멀티뷰 기하학이 풀어야 할 근본 문제입니다.
