13장의 시나리오는 `weather=rain` 슬라이스에서 PSNR과 SSIM이 떨어졌다는 것을 잡아냈습니다. 하지만 그 회귀가 실제로 "주행"에 어떤 영향을 미치는지는 파이프라인이 한 번도 묻지 않았습니다. 렌더링이 흐려졌다고 해서 반드시 차가 위험하게 움직이는 것은 아니고, 반대로 렌더링 지표가 멀쩡해 보여도 E2E 모델이 산출하는 궤적·제동 판단 자체가 흔들릴 수 있습니다. 이 장은 이 간극을 메웁니다 — 지금까지 쌓아온 `compute-metrics` 단계, 슬라이스 롤업, 통계적 게이트를 새로 설계하지 않고, 그 위에 **폐루프(closed-loop) 주행 평가 지표**를 하나의 플러그인으로 얹습니다.

== 왜 렌더링 지표만으로는 부족한가

7장에서 렌더링 품질 지표와 기하/포즈 정확도 지표를 나란히 두기로 한 이유는 "회귀의 원인이 모델인지 입력인지 구분하기 위해서"였습니다. 하지만 두 지표 모두 "출력이 얼마나 정확한가"만 잽니다 — E2E 모델의 최종 산출물인 궤적·조향·가속 결정이 실제로 안전한가는 별개의 질문입니다. 맺음말 초안이 이 부분을 "이 책이 다루지 않은 것"으로 명시적으로 남겨뒀던 것도 그래서였습니다. 하지만 실무에서 3DGS 기반 시뮬레이터로 E2E 모델을 반복 평가하는 팀이라면, 렌더링된 장면을 다시 시뮬레이터에 태워 **폐루프**로 주행시키는 것 자체가 어렵지 않은 일입니다 — 렌더러가 이미 파이프라인 안에 있고(5장), 그 렌더러의 출력을 모델의 입력으로 되먹임(feedback)하기만 하면 됩니다. 이 되먹임 루프를 한 번 도는 것과, 그 결과를 렌더링 품질 지표와 같은 게이트로 판정하는 것은 이제 자연스러운 다음 단계입니다.

== 폐루프에서 무엇을 잴 것인가

이 책은 네 가지 지표를 추가합니다. 모두 "시퀀스 하나를 폐루프로 재생했을 때" 얻어지는 시계열에서 계산됩니다.

* **충돌률(collision rate)** — 시퀀스 재생 중 자차(ego) 바운딩 박스가 다른 에이전트나 정적 장애물의 바운딩 박스와 겹치는 프레임이 하나라도 있으면 그 시퀀스를 "충돌"로 집계합니다. 슬라이스(또는 전체) 단위로는 충돌이 발생한 시퀀스 비율로 집계합니다.
* **최소 TTC(Time-To-Collision)** — 매 프레임마다 자차와 가장 가까운 전방 에이전트 사이의 상대 속도로 충돌까지 남은 시간을 추정하고, 시퀀스 전체에서 가장 작은 값을 기록합니다. 값이 작을수록 위험한 순간에 가까웠다는 뜻입니다.
* **궤적 L2 오차** — 폐루프로 재생된 자차 궤적과, 원본 주행 로그(또는 골든런이 생성한 궤적)의 같은 시각 위치 사이의 유클리드 거리입니다. 렌더링 품질과 달리 이 지표는 "정답에서 얼마나 벗어났는가"를 직접 잽니다.
* **jerk(승차감)** — 가속도의 시간 미분입니다. 절댓값이 크면 급가속·급제동·급조향처럼 사람이 불편하게 느끼는 거동이 잦다는 뜻이고, 충돌이 없어도 회귀로 볼 만한 품질 저하입니다.

네 지표 중 앞의 둘(충돌률, 최소 TTC)은 "안전", 뒤의 둘(궤적 L2, jerk)은 "정확도"와 "승차감"을 각각 대표합니다 — 7장이 렌더링 품질과 기하 정확도를 나란히 둔 것과 같은 논리로, 이 네 지표도 서로 다른 실패 모드를 잡아내므로 하나로 뭉치지 않고 각각 따로 게이트를 겁니다.

== `compute-metrics` 단계에 폐루프 지표 플러그인 추가하기

7장의 `compare/metric_kernels.py`는 프레임 단위 함수(`frame_image_metrics`, `frame_pose_metrics`)를 이미 두 개 갖고 있습니다. 같은 패턴으로 시퀀스 단위 함수를 하나 더 추가합니다 — 폐루프 지표는 프레임 하나가 아니라 시퀀스 전체의 시계열이 있어야 계산되기 때문입니다.

[source,python]
----
# compare/closed_loop_kernels.py
import numpy as np


def sequence_closed_loop_metrics(
    ego_trajectory: np.ndarray,       # (T, 2) 폐루프 재생 중 자차 위치
    reference_trajectory: np.ndarray, # (T, 2) 원본 로그(또는 골든런) 자차 위치, 같은 타임스탬프
    ego_bbox_history: list,           # 프레임별 자차 바운딩 박스
    agent_bbox_history: list,         # 프레임별 다른 에이전트 바운딩 박스 목록
    ego_speed: np.ndarray,            # (T,) 자차 속도(m/s)
    closing_speed: np.ndarray,        # (T,) 가장 가까운 전방 에이전트와의 상대 접근 속도(m/s), 멀어지면 음수
    ego_accel: np.ndarray,            # (T,) 자차 종방향 가속도(m/s^2)
    dt: float,                        # 프레임 간 시간 간격(s)
) -> dict:
    collided = any(
        _bboxes_overlap(ego_box, agent_box)
        for ego_box, agents in zip(ego_bbox_history, agent_bbox_history)
        for agent_box in agents
    )

    approaching = closing_speed > 1e-3  # 접근 중이 아닌 프레임은 TTC가 정의되지 않음(무한대로 취급)
    distances = _nearest_agent_distance(ego_bbox_history, agent_bbox_history)
    ttc = np.full_like(closing_speed, fill_value=np.inf)
    ttc[approaching] = distances[approaching] / closing_speed[approaching]
    min_ttc_s = float(np.min(ttc)) if np.isfinite(ttc).any() else float("inf")

    l2_errors = np.linalg.norm(ego_trajectory - reference_trajectory, axis=1)
    jerk = np.diff(ego_accel) / dt

    return {
        "collided": collided,
        "min_ttc_s": min_ttc_s,
        "trajectory_l2_m": {
            "mean": float(l2_errors.mean()),
            "p95_worst": float(np.percentile(l2_errors, 95)),
        },
        "jerk_rms": float(np.sqrt(np.mean(jerk**2))),
    }
----

이 함수는 7장의 `frame_image_metrics`/`frame_pose_metrics`와 시그니처 층위가 다릅니다(프레임이 아니라 시퀀스 전체를 입력받습니다) — 그래서 `summarize_sequence`(7장)에 억지로 끼워 넣지 않고, `summarize_metrics.py`의 시퀀스 루프 안에서 별도로 한 번 더 호출하는 구조를 취합니다.

== DAG에 `closed-loop-replay` 단계 추가하기

6장의 `regression-dag`에 `render-candidate`가 끝난 뒤에만 실행되는 새 태스크를 추가합니다. `closed-loop-replay`와 `compute-metrics`는 언뜻 병렬로 돌 수 있을 것 같지만(둘 다 `render-candidate`의 출력만 있으면 되므로), `compute-metrics`가 `closed-loop-metrics` 아티팩트를 `closed-loop-replay`의 출력에서 받아야 하므로 실제로는 `compute-metrics`가 `closed-loop-replay`를 **기다려야** 합니다 — Argo Workflow는 아티팩트 참조만으로는 실행 순서를 보장하지 않고, `depends` 필드에 태스크 이름을 직접 나열해야 합니다. 그래서 `compute-metrics`의 `depends`는 `render-candidate`뿐 아니라 `closed-loop-replay`도 포함해야 합니다.

[source,yaml]
----
          - name: closed-loop-replay
            template: closed-loop-replay-tpl
            depends: "render-candidate"
            arguments:
              artifacts:
                - name: candidate-renders
                  from: "{{tasks.render-candidate.outputs.artifacts.renders}}"
              parameters:
                - {name: manifest-version, value: "{{workflow.parameters.manifest-version}}"}

          - name: compute-metrics
            template: compute-metrics-tpl
            depends: "render-candidate && closed-loop-replay"
            arguments:
              artifacts:
                - name: candidate-renders
                  from: "{{tasks.render-candidate.outputs.artifacts.renders}}"
                - name: closed-loop-metrics
                  from: "{{tasks.closed-loop-replay.outputs.artifacts.metrics}}"
              parameters:
                - {name: manifest-version, value: "{{workflow.parameters.manifest-version}}"}

          - name: compare-and-gate
            template: compare-and-gate-tpl
            depends: "fetch-baseline && compute-metrics"
            # ... 6장과 동일 ...

== 슬라이스 롤업에 자연스럽게 편입하기

7장의 `rollup_by_slice`는 시퀀스 요약 딕셔너리에서 이미 알고 있는 키(`psnr_db_mean`, `ssim_mean` 등)를 꺼내 슬라이스별로 평균 냅니다. 폐루프 지표를 추가하는 데 새로운 집계 로직이 필요하지 않습니다 — 같은 함수에 키 몇 개만 더하면 됩니다.

[source,python]
----
def rollup_by_slice(sequence_summaries: dict[str, dict], manifest: list) -> dict:
    by_slice: dict[str, list[dict]] = {}
    for seq in manifest:
        summary = sequence_summaries.get(seq.sequence_id)
        if summary is None:
            continue
        for axis, value in seq.slices.items():
            key = f"{axis}={value}"
            by_slice.setdefault(key, []).append(summary)

    rollup = {}
    for slice_key, summaries in by_slice.items():
        closed_loop_summaries = [s["closed_loop"] for s in summaries if "closed_loop" in s]
        rollup[slice_key] = {
            "n_sequences": len(summaries),
            "psnr_db_mean": sum(s["psnr_db"]["mean"] for s in summaries) / len(summaries),
            "ssim_mean": sum(s["ssim"]["mean"] for s in summaries) / len(summaries),
            "mean_reprojection_error_px": sum(
                s["mean_reprojection_error_px"]["mean"] for s in summaries
            ) / len(summaries),
        }
        if closed_loop_summaries:
            n = len(closed_loop_summaries)
            rollup[slice_key]["collision_rate"] = (
                sum(1 for c in closed_loop_summaries if c["collided"]) / n
            )
            rollup[slice_key]["min_ttc_s_worst"] = min(c["min_ttc_s"] for c in closed_loop_summaries)
            rollup[slice_key]["trajectory_l2_m_mean"] = sum(
                c["trajectory_l2_m"]["mean"] for c in closed_loop_summaries
            ) / n
            rollup[slice_key]["jerk_rms_mean"] = sum(c["jerk_rms"] for c in closed_loop_summaries) / n
    return rollup
----

`weather=rain`처럼 렌더링 품질이 이미 취약하다고 알려진 슬라이스(13장)는, 폐루프 지표를 더했을 때 충돌률이나 최소 TTC에서도 함께 나빠지는지 확인할 좋은 후보입니다 — 렌더링이 흐려진 만큼 모델이 전방 장애물을 늦게 인식해 최소 TTC가 줄어드는 인과관계가 실제로 있다면, 이 슬라이스 롤업이 그 관계를 처음으로 수치로 드러냅니다.

== 8장의 부트스트랩 게이트에 편입하기

폐루프 지표도 결국 "시퀀스별 숫자 하나"로 요약되므로, 8장의 `bootstrap_regression_test` 함수를 그대로 재사용할 수 있습니다 — 새로운 통계 로직을 만들 필요가 없습니다. 다만 지표마다 "좋음"의 방향이 다르다는 점(7장 연습문제에서 지적했던 `higher_is_better` 문제)이 여기서 더 분명해집니다 — 충돌률과 jerk와 궤적 L2 오차는 낮을수록 좋고, 최소 TTC는 높을수록 좋습니다. `tolerance_bands.yaml`에 방향을 명시적으로 추가합니다.

[source,yaml]
----
# tolerance_bands.yaml (8장 스키마에 폐루프 지표 추가)
psnr_db:
  min_effect: 0.15
  confidence: 0.95
  higher_is_better: true
collision_rate:
  min_effect: 0.01        # 슬라이스 내 충돌률이 1%p 이상 늘면 실질적 회귀
  confidence: 0.95
  higher_is_better: false
min_ttc_s:
  min_effect: 0.3          # 초 단위, 최악 TTC가 0.3초 이상 줄면 회귀
  confidence: 0.95
  higher_is_better: true
trajectory_l2_m:
  min_effect: 0.1
  confidence: 0.95
  higher_is_better: false
jerk_rms:
  min_effect: 0.2
  confidence: 0.90        # 폐루프 재생 자체의 노이즈가 렌더링보다 커서 신뢰수준을 LPIPS와 비슷하게 낮춤
  higher_is_better: false
----

`bootstrap_regression_test`가 항상 "베이스라인 - 후보"를 "높을수록 좋음" 기준으로 계산했던 것(8장 `RegressionVerdict.delta` 정의)을 떠올리면, `higher_is_better: false`인 지표는 호출 전에 부호를 뒤집어야 합니다.

[source,python]
----
# compare/statistical_gate.py에 추가하는 얇은 래퍼
def run_gate_for_metric(samples_baseline, samples_candidate, metric_name, band) -> "RegressionVerdict":
    sign = 1.0 if band["higher_is_better"] else -1.0
    return bootstrap_regression_test(
        samples_baseline=sign * samples_baseline,
        samples_candidate=sign * samples_candidate,
        metric_name=metric_name,
        min_effect=band["min_effect"],
        confidence=band["confidence"],
    )
----

이렇게 하면 8장의 검정 함수, 다중 비교 보정(벤저미니-호크버그), 리포트 스키마(`regression_verdicts`, `overall_gate_result`)를 전혀 손대지 않고 네 가지 폐루프 지표가 같은 게이트 로직 안으로 들어옵니다.

== 반복 실행 횟수는 폐루프에서 특히 더 중요하다

11장에서 GPU 렌더링의 비결정성 원천을 다뤘습니다. 폐루프 재생은 여기에 한 가지 원천을 더합니다 — 시뮬레이터가 한 스텝의 자차 위치를 조금이라도 다르게 계산하면, 다음 스텝의 모델 입력이 달라지고, 이것이 스텝마다 누적되는 **복리 오차(compounding error)**를 만듭니다. 렌더링 품질 지표의 노이즈가 프레임마다 독립적인 것과 달리, 폐루프 궤적의 노이즈는 시퀀스가 길어질수록 커지는 경향이 있습니다. 따라서 8장의 `required_repeats` 계산을 폐루프 지표에 그대로 적용할 때는, 렌더링 지표보다 더 큰 `noise_std`를 실측해 넣어야 합니다 — 11장의 노이즈 감시 워크플로가 폐루프 지표도 함께 감시 대상에 포함시켜야 하는 이유이기도 합니다.

== 요약

* 렌더링 품질과 기하 정확도만으로는 E2E 모델의 최종 산출물(궤적·제동 판단)이 실제로 안전한지 알 수 없습니다 — 충돌률, 최소 TTC, 궤적 L2 오차, jerk 네 가지 폐루프 지표로 이 간극을 메웁니다.
* 폐루프 지표는 시퀀스 단위 시계열이 필요하므로 `closed_loop_kernels.py`라는 별도 모듈로 분리하고, 6장의 DAG에 `closed-loop-replay`라는 조건부 병렬 태스크로 추가합니다.
* 7장의 슬라이스 롤업, 8장의 부트스트랩 게이트와 다중 비교 보정은 새로 만들 필요 없이 그대로 재사용되며, `tolerance_bands.yaml`에 `higher_is_better` 방향과 지표별 `min_effect`만 추가하면 됩니다.
* 폐루프 재생은 시뮬레이션 스텝이 누적되는 복리 오차 때문에 렌더링 지표보다 노이즈가 크므로, 11장의 노이즈 감시와 8장의 반복 횟수 계산에 폐루프 지표를 반드시 포함시켜야 합니다.

== 연습문제

. `sequence_closed_loop_metrics`가 `ego_bbox_history`/`agent_bbox_history`를 입력으로 요구하는데, 이 값들을 3DGS 렌더링 결과에서 직접 얻을 수 없다면(에이전트 위치 자체는 시뮬레이터나 별도 트래커가 필요합니다) 어떤 추가 컴포넌트가 파이프라인에 필요할지 생각해보세요.
. `min_ttc_s`처럼 "낮을수록 위험"한 지표에서, 애초에 위험한 상황(급커브, 정체 구간)을 포함하는 슬라이스는 최소 TTC가 원래도 낮게 나올 수 있습니다. 이런 슬라이스의 골든런 기준값을 4장의 골든런 승격 절차에서 어떻게 별도로 잡아야 8장의 게이트가 오탐하지 않을지 설계해보세요.
