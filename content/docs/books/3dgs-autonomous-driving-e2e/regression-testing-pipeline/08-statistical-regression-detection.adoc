== 몇 번을 반복 실행해야 충분한가

첫 번째 질문은 "N번 반복 실행"에서 `N`을 얼마로 잡을 것인가입니다. `N`이 너무 작으면 평균 추정치 자체가 불안정하고, `N`이 너무 크면 GPU 클러스터 비용이 커집니다(4장·5장에서 이미 렌더링 잡이 GPU를 요구한다고 했습니다). 표준오차(standard error)가 `σ/√N`으로 줄어드는 것을 이용해, 목표 정밀도에 필요한 최소 `N`을 역산할 수 있습니다.

[source,python]
----
import numpy as np

def required_repeats(noise_std: float, target_stderr: float) -> int:
    """평균의 표준오차를 target_stderr 이하로 낮추는 데 필요한 최소 반복 횟수."""
    n = (noise_std / target_stderr) ** 2
    return int(np.ceil(n))

# 4장 골든런 검증에서 확인한 PSNR 반복 실행 표준편차가 0.15dB라고 가정
print(required_repeats(noise_std=0.15, target_stderr=0.05))
----

[source]
----
9
----

노이즈 표준편차가 `0.15dB`일 때, 평균의 표준오차를 `0.05dB` 이하로 낮추려면 약 `9`회 반복이 필요합니다. 실무에서는 이 계산을 매번 하지 않고, 4장의 골든런 자기 검증 단계에서 미리 측정한 노이즈 대역을 파이프라인 설정값으로 고정해둡니다.

== 부트스트랩으로 차이의 신뢰구간 구하기

2장에서 스케치했던 부트스트랩 판정을 실제로 완성합니다. 핵심 아이디어는 "베이스라인 평균과 신규 평균의 차이"가 우연이 아니라고 볼 수 있을 만큼 신뢰구간이 0으로부터 충분히 떨어져 있는지를 보는 것입니다.

[source,python]
----
# compare/statistical_gate.py
import numpy as np
from dataclasses import dataclass

@dataclass
class RegressionVerdict:
    metric_name: str
    baseline_mean: float
    candidate_mean: float
    delta: float                 # baseline - candidate (지표가 "높을수록 좋음" 기준)
    ci_lower: float
    ci_upper: float
    is_regression: bool
    reason: str


def bootstrap_regression_test(
    samples_baseline: np.ndarray,
    samples_candidate: np.ndarray,
    metric_name: str,
    min_effect: float,
    confidence: float = 0.95,
    n_boot: int = 2000,
    seed: int = 0,
) -> RegressionVerdict:
    rng = np.random.default_rng(seed)
    delta = samples_baseline.mean() - samples_candidate.mean()

    boot_deltas = np.empty(n_boot)
    for i in range(n_boot):
        b = rng.choice(samples_baseline, size=len(samples_baseline), replace=True)
        c = rng.choice(samples_candidate, size=len(samples_candidate), replace=True)
        boot_deltas[i] = b.mean() - c.mean()

    alpha = 1 - confidence
    ci_lower = float(np.percentile(boot_deltas, 100 * alpha / 2))
    ci_upper = float(np.percentile(boot_deltas, 100 * (1 - alpha / 2)))

    if delta < min_effect:
        is_regression, reason = False, "평균 차이가 실질적 임계값(min_effect)보다 작음"
    elif ci_lower <= 0:
        is_regression, reason = False, "신뢰구간이 0을 포함 — 통계적으로 유의하지 않음"
    else:
        is_regression, reason = True, "실질적으로 크고 통계적으로 유의한 하락"

    return RegressionVerdict(
        metric_name=metric_name,
        baseline_mean=float(samples_baseline.mean()),
        candidate_mean=float(samples_candidate.mean()),
        delta=float(delta),
        ci_lower=ci_lower,
        ci_upper=ci_upper,
        is_regression=is_regression,
        reason=reason,
    )
----

이 함수를 실제 숫자로 돌려봅니다. 노이즈 표준편차 `0.15dB`인 상황에서, 진짜로 `0.4dB`만큼 회귀한 경우와 회귀가 전혀 없는 경우를 각각 9회씩 반복 실행했다고 가정합니다.

[source,python]
----
rng = np.random.default_rng(7)

# 케이스 1: 진짜 회귀 (참값 31.20 -> 30.80, 0.4dB 하락)
baseline_1 = 31.20 + rng.normal(0, 0.15, 9)
candidate_1 = 30.80 + rng.normal(0, 0.15, 9)
verdict_1 = bootstrap_regression_test(baseline_1, candidate_1, "psnr_db", min_effect=0.15)

# 케이스 2: 회귀 없음 (노이즈만 존재)
baseline_2 = 31.20 + rng.normal(0, 0.15, 9)
candidate_2 = 31.20 + rng.normal(0, 0.15, 9)
verdict_2 = bootstrap_regression_test(baseline_2, candidate_2, "psnr_db", min_effect=0.15)

for v in (verdict_1, verdict_2):
    print(f"{v.metric_name}: delta={v.delta:.3f}, CI=[{v.ci_lower:.3f}, {v.ci_upper:.3f}], "
          f"회귀={v.is_regression} ({v.reason})")
----

== 허용 오차 대역: 지표마다 다른 노이즈 특성

모든 지표가 같은 크기의 노이즈를 갖지 않습니다. PSNR은 비교적 안정적이지만 LPIPS 같은 신경망 기반 지표는 실행마다 더 크게 흔들릴 수 있고, 재투영 오차는 시퀀스의 기하학적 배치에 따라 지표별로 노이즈 스케일 자체가 다릅니다. 이 책의 파이프라인은 지표별 `min_effect`와 신뢰수준을 하드코딩하지 않고, 4장의 골든런 자기 검증 단계에서 측정한 노이즈 대역을 설정 파일로 관리합니다.

[source,yaml]
----
# tolerance_bands.yaml
psnr_db:
  min_effect: 0.15        # dB, 이보다 작은 차이는 무조건 무시
  confidence: 0.95
ssim:
  min_effect: 0.005
  confidence: 0.95
lpips:
  min_effect: 0.01
  confidence: 0.90        # LPIPS 노이즈가 더 커서 신뢰수준을 살짝 낮춤
mean_reprojection_error_px:
  min_effect: 0.2
  confidence: 0.95
----

== 다중 비교 문제: 지표와 슬라이스가 늘어날수록 오탐도 늘어난다

7장에서 슬라이스별로도 지표를 계산한다고 했습니다. 슬라이스가 10개, 지표가 4개면 40번의 독립적인 통계 검정을 돌리는 셈이고, 각 검정이 신뢰수준 95%(오탐률 5%)라 해도 40번 중 최소 하나가 우연히 "회귀"로 잘못 나올 확률은 상당히 커집니다(`1 - 0.95^40 ≈ 87%`). 이 문제를 다중 비교(multiple comparisons) 문제라고 부르며, 벤저미니-호크버그(Benjamini-Hochberg) 절차 같은 표준적인 방법으로 완화합니다.

[source,python]
----
def benjamini_hochberg_correction(p_values: list[float], fdr: float = 0.05) -> list[bool]:
    """p-value 목록을 받아, 위양성 비율(FDR)을 fdr 이하로 통제하며 유의한 항목을 표시."""
    n = len(p_values)
    order = np.argsort(p_values)
    sorted_p = np.array(p_values)[order]
    thresholds = (np.arange(1, n + 1) / n) * fdr

    significant = sorted_p <= thresholds
    if not significant.any():
        return [False] * n
    max_significant_rank = np.max(np.where(significant)[0])

    result = np.zeros(n, dtype=bool)
    result[order[: max_significant_rank + 1]] = True
    return result.tolist()
----

부트스트랩 신뢰구간 대신 p-value가 필요하면, 신뢰구간 대신 순열 검정(permutation test)으로 p-value를 직접 얻거나, 부트스트랩 분포에서 "delta가 0 이하일 확률"을 근사 p-value로 씁니다. 슬라이스가 많지 않은 파이프라인 초기 단계에서는 이 보정을 생략해도 되지만, 슬라이스가 늘어날수록(4장에서 다룬 슬라이스 커버리지 확장과 맞물려) 이 보정이 점점 중요해집니다.

== 리포트에 통계 결과 통합하기

7장의 JSON 스키마에 `regression_verdicts` 필드를 추가해, 어떤 지표·슬라이스가 회귀로 판정됐는지 명시적으로 남깁니다.

[source,json]
----
{
  "manifest_version": "v2026.05.20",
  "regression_verdicts": [
    {
      "scope": "overall",
      "metric_name": "psnr_db",
      "delta": 0.417,
      "ci": [0.201, 0.633],
      "is_regression": true
    },
    {
      "scope": "slice:weather=rain",
      "metric_name": "ssim",
      "delta": 0.031,
      "ci": [0.008, 0.054],
      "is_regression": true
    },
    {
      "scope": "slice:time_of_day=night",
      "metric_name": "mean_reprojection_error_px",
      "delta": -0.05,
      "ci": [-0.31, 0.21],
      "is_regression": false
    }
  ],
  "overall_gate_result": "FAIL"
}
----

`overall_gate_result`는 `regression_verdicts` 중 하나라도 `is_regression: true`면 `FAIL`이 되며, 이 값이 6장의 `compare-and-gate-tpl` 종료 코드와 9장의 CI 게이트 판정에 그대로 쓰입니다.

== 요약

* 표준오차 공식으로 목표 정밀도에 필요한 최소 반복 횟수를 역산할 수 있고, 이 값은 4장의 골든런 자기 검증에서 측정한 노이즈 대역에 근거해야 합니다.
* 부트스트랩으로 베이스라인-신규 평균 차이의 신뢰구간을 구하면, 단일 실행 비교보다 훨씬 안정적으로 진짜 회귀와 노이즈를 구분할 수 있습니다.
* 지표마다 노이즈 특성이 다르므로 `min_effect`와 신뢰수준을 지표별로 다르게 설정한 허용 오차 대역을 씁니다.
* 슬라이스와 지표가 늘어날수록 다중 비교 문제로 오탐이 누적되며, 벤저미니-호크버그 같은 보정이 필요해집니다.
* 최종 리포트는 각 스코프(전체/슬라이스)·지표별 판정 결과를 모두 담아, 게이트 결과(`overall_gate_result`)를 명확한 근거와 함께 기록합니다.
