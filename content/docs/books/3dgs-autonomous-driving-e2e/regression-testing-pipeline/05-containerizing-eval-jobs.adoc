== 왜 컨테이너화가 회귀 테스트의 전제조건인가

1장에서 다룬 비결정성의 상당 부분은 사실 "환경 차이"에서 옵니다 — 어제는 CUDA 12.1이었는데 오늘은 12.2로 자동 업데이트됐다거나, PyTorch가 마이너 버전이 올라갔다거나, 시스템에 깔린 BLAS 라이브러리가 다르다거나. 이런 환경 차이는 진짜 회귀와 구분할 수 없는 잡음을 만들어냅니다. 컨테이너화는 이 잡음의 원천 중 상당 부분을 제거합니다 — 의존성 버전을 이미지 안에 고정해두면, "어제 이미지"와 "오늘 이미지"의 차이가 정확히 우리가 의도한 변경(모델 체크포인트, 혹은 명시적인 의존성 업그레이드 커밋)으로 좁혀집니다.

== Dockerfile: 렌더링/평가 잡

GPU 연산이 필요한 렌더링 잡은 CUDA가 포함된 베이스 이미지에서 시작하고, 모든 Python 의존성 버전을 고정합니다.

[source,dockerfile]
----
# Dockerfile.render-eval
FROM nvidia/cuda:12.2.2-cudnn8-runtime-ubuntu22.04

ENV DEBIAN_FRONTEND=noninteractive \
    PYTHONUNBUFFERED=1 \
    PIP_NO_CACHE_DIR=1

RUN apt-get update && apt-get install -y --no-install-recommends \
        python3.10 python3-pip git libgl1 libglib2.0-0 \
    && rm -rf /var/lib/apt/lists/*

WORKDIR /workspace

# 의존성을 코드보다 먼저 복사해 Docker 레이어 캐시를 최대한 활용
COPY requirements.lock.txt .
RUN pip3 install --no-cache-dir -r requirements.lock.txt

COPY src/ ./src/
COPY eval/ ./eval/

# 컨테이너 안에서 정확히 어떤 버전이 깔렸는지 이미지 자체에 기록해두면
# 나중에 회귀 원인 추적(9장, 13장) 시 매우 유용합니다.
RUN pip3 freeze > /workspace/installed-versions.lock

ENTRYPOINT ["python3", "-m", "eval.run_eval"]
----

`requirements.lock.txt`는 느슨한 범위 지정(`torch>=2.0`)이 아니라 정확한 버전(`torch==2.3.1+cu121`)으로 고정합니다. 느슨한 범위는 CI가 실행될 때마다 다른 버전을 끌어올 위험이 있고, 이는 회귀 테스트의 재현성을 정면으로 해칩니다.

[source]
----
# requirements.lock.txt (발췌)
torch==2.3.1+cu121
numpy==1.26.4
scipy==1.13.0
opencv-python-headless==4.9.0.80
lpips==0.1.4
rerun-sdk==0.16.1
boto3==1.34.100
----

== GPU 접근을 kind 클러스터에 연결하기

`kind`는 기본적으로 Docker 컨테이너 안에서 동작하기 때문에, GPU를 실제로 파드에 노출하려면 호스트에 NVIDIA Container Toolkit이 설치되어 있고 `kind` 노드 컨테이너가 그 GPU 런타임을 상속하도록 설정해야 합니다. 로컬 개발 환경에 GPU가 없는 경우가 흔하므로, 이 책의 로컬 파이프라인은 렌더링 잡을 **목(mock) 모드**로 대체해 DAG 배선과 지표 계산·비교·게이트 로직을 검증하고, 실제 GPU 렌더링은 12장에서 다루는 클라우드 GPU 노드 풀에서 수행합니다. 목 모드는 환경변수 하나로 전환합니다.

[source,python]
----
# eval/run_eval.py (골격)
import argparse
import json
import os
from pathlib import Path

def render_and_evaluate(checkpoint_path: str, sequence_dir: Path, out_dir: Path, mock: bool) -> dict:
    """체크포인트로 시퀀스를 렌더링하고, 참조 이미지와 비교해 지표를 낸다."""
    if mock:
        # GPU가 없는 로컬 검증용 — 결정론적 가짜 지표를 낸다.
        return {"psnr_db": 31.0, "ssim": 0.90, "lpips": 0.08, "frames": 0, "mock": True}

    # 실제 경로: 3DGS 렌더러 로드 → 프레임별 렌더링 → 참조와 비교
    from src.renderer import GaussianSplatRenderer
    from src.metrics import compute_psnr, compute_ssim, compute_lpips

    renderer = GaussianSplatRenderer.from_checkpoint(checkpoint_path)
    psnr_list, ssim_list, lpips_list = [], [], []
    frame_paths = sorted(sequence_dir.glob("images/frame_*.png"))
    for frame_path in frame_paths:
        pose = renderer.load_pose_for(frame_path)
        rendered = renderer.render(pose)
        reference = renderer.load_reference(frame_path)
        psnr_list.append(compute_psnr(rendered, reference))
        ssim_list.append(compute_ssim(rendered, reference))
        lpips_list.append(compute_lpips(rendered, reference))
        renderer.save_render(out_dir / frame_path.name, rendered)

    n = len(frame_paths)
    return {
        "psnr_db": sum(psnr_list) / n,
        "ssim": sum(ssim_list) / n,
        "lpips": sum(lpips_list) / n,
        "frames": n,
        "mock": False,
    }


def main():
    parser = argparse.ArgumentParser()
    parser.add_argument("--checkpoint", required=True)
    parser.add_argument("--sequence-dir", required=True, type=Path)
    parser.add_argument("--out-dir", required=True, type=Path)
    parser.add_argument("--mock", action="store_true", default=os.environ.get("EVAL_MOCK") == "1")
    args = parser.parse_args()

    args.out_dir.mkdir(parents=True, exist_ok=True)
    metrics = render_and_evaluate(args.checkpoint, args.sequence_dir, args.out_dir, args.mock)

    report_path = args.out_dir / "metrics.json"
    report_path.write_text(json.dumps(metrics, indent=2))
    print(f"지표 리포트 작성 완료: {report_path}")
    print(json.dumps(metrics, indent=2))


if __name__ == "__main__":
    main()
----

`compute_psnr`/`compute_ssim`/`compute_lpips`는 "닮았다는 걸 어떻게 잴까" 책 3장·6장·9장에서 구현한 함수를 그대로 `src/metrics.py`로 옮겨온 것입니다 — 이 책에서 새로 재구현하지 않고, 검증된 구현을 재사용하는 것이 핵심입니다. 7장에서 이 재사용 경계를 더 명확히 다룹니다.

== 컨테이너 이미지를 kind 클러스터에 넣기

`kind` 클러스터는 기본적으로 외부 레지스트리에서 이미지를 받아오므로, 로컬에서 빌드한 이미지를 클러스터가 쓰게 하려면 `kind load`로 직접 밀어 넣거나, 3장에서 설정한 로컬 레지스트리(`kind-registry`)에 푸시합니다.

[source,bash]
----
docker build -t regression-eval:dev -f Dockerfile.render-eval .
kind load docker-image regression-eval:dev --name regression-ci

# 혹은 로컬 레지스트리를 쓰는 경우
docker tag regression-eval:dev localhost:5001/regression-eval:dev
docker push localhost:5001/regression-eval:dev
----

CI(9장)에서는 매 커밋마다 이미지를 새로 빌드하고 `checkpoint-hash` 혹은 `git-sha`를 이미지 태그에 새겨, 어떤 코드/의존성 조합으로 평가가 실행됐는지 항상 역추적할 수 있게 합니다.

[source,bash]
----
GIT_SHA=$(git rev-parse --short HEAD)
docker build -t "regression-eval:${GIT_SHA}" -f Dockerfile.render-eval .
----

== 비교 잡: GPU가 필요 없는 가벼운 컨테이너

렌더링 잡과 달리, 두 지표 리포트를 비교해 회귀 여부를 판정하는 잡(6장 DAG의 `compare` 단계)은 GPU도 3DGS 관련 무거운 의존성도 필요 없습니다. 별도의 가벼운 이미지로 분리해두면 빌드·시작 시간이 짧아지고, 워커 노드의 GPU 자원을 불필요하게 점유하지 않습니다.

[source,dockerfile]
----
# Dockerfile.compare
FROM python:3.11-slim

WORKDIR /workspace
COPY requirements.compare.lock.txt .
RUN pip install --no-cache-dir -r requirements.compare.lock.txt
COPY compare/ ./compare/

ENTRYPOINT ["python", "-m", "compare.run_compare"]
----

이렇게 잡을 GPU 필요 여부에 따라 이미지를 분리하는 패턴은 6장에서 Argo Workflow의 `nodeSelector`/`resources` 설정과 맞물려 실제로 클러스터에 어떻게 스케줄링되는지 다시 등장합니다.

== 요약

* 컨테이너화는 회귀 테스트의 전제조건입니다 — 의존성 버전을 이미지 안에 고정해야 "환경 차이"라는 잡음을 진짜 회귀와 구분할 수 있습니다.
* 렌더링/평가 잡은 GPU 베이스 이미지와 고정된 `requirements.lock.txt`로 패키징하고, 로컬 개발에서는 GPU 없이도 DAG 배선을 검증할 수 있는 목(mock) 모드를 둡니다.
* 지표 계산 함수는 "닮았다는 걸 어떻게 잴까" 책에서 이미 구현·검증한 것을 그대로 재사용합니다.
* 비교/게이트 잡처럼 GPU가 필요 없는 단계는 별도의 가벼운 이미지로 분리해 자원 사용을 최적화합니다.
* 이미지 태그에 git SHA를 새겨, 어떤 코드 상태로 평가가 실행됐는지 항상 역추적할 수 있게 합니다.

== 연습문제

. `Dockerfile.render-eval`에서 `requirements.lock.txt`를 느슨한 버전 범위(`torch>=2.0`)로 바꾸면 어떤 문제가 생길 수 있는지, 1장의 "의존성 업그레이드" 회귀 원인과 연결지어 설명해보세요.
. `render_and_evaluate` 함수의 목 모드가 항상 동일한 고정값(`psnr_db: 31.0` 등)을 반환하는 대신, "결정론적이지만 시퀀스 ID에 따라 달라지는" 값을 반환하도록 바꿔보세요(예: 시퀀스 ID 문자열의 해시를 시드로 사용). 이렇게 하면 DAG 배선 테스트에서 어떤 이점이 생기는지 생각해보세요.
