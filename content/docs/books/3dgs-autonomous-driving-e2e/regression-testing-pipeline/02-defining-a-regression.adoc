1장에서 "회귀"라는 말을 느슨하게 써왔습니다. 이 장에서는 이 말을 파이프라인이 실제로 코드로 판정할 수 있을 만큼 형식적으로 정의합니다.

== 회귀 판정에 필요한 세 가지 요소

임의의 새 체크포인트 `C_new`가 기존 체크포인트 `C_base`에 비해 회귀했는지 판단하려면, 다음 세 가지가 필요합니다.

1. **비교 대상(베이스라인)** — 무엇과 비교할 것인가. 직전 배포된 체크포인트인지, 특정 시점에 고정한 "골든" 체크포인트인지.
2. **측정 지표(metric)** — 무엇을 잴 것인가. 렌더링 품질인지, 기하 정확도인지, 둘 다인지.
3. **판정 규칙(decision rule)** — 지표 값의 차이가 "정상 변동"과 "진짜 회귀" 중 어느 쪽인지 가르는 기준.

이 세 가지가 다 갖춰져야 "회귀 테스트를 통과/실패했다"는 문장이 의미를 가집니다. 이 장은 이 세 요소를 각각 다룹니다.

== 측정 지표: 렌더링 품질과 기하 정확도를 함께 본다

이 파이프라인은 두 축의 지표를 함께 씁니다.

=== 렌더링 품질 지표

"닮았다는 걸 어떻게 잴까" 책에서 구현한 지표들을 그대로 재사용합니다.

* **PSNR**(Peak Signal-to-Noise Ratio) — 픽셀 단위 오차를 데시벨 스케일로 표현한 지표. 계산이 빠르고 해석이 직관적이지만, 사람의 지각과는 종종 어긋납니다(같은 PSNR이라도 블러와 노이즈는 사람에게 다르게 느껴집니다).
* **SSIM**(Structural Similarity) — 밝기·대비·구조를 분리해서 비교하는 지표로, 국소적인 구조 왜곡(고스팅, 흐림)에 PSNR보다 민감합니다.
* **LPIPS류 지각적 지표** — 신경망 특징 공간에서 거리를 재는 지표로, 사람이 느끼는 "다르다"는 감각에 가장 가깝지만 계산 비용이 큽니다.

세 지표는 서로 다른 실패 모드에 민감하므로, 회귀 판정에는 하나만 쓰기보다 세 지표를 함께 보고 "왜 나빠졌는가"의 단서로 삼는 편이 안전합니다.

=== 기하/포즈 정확도 지표

"흔들리는 로그를 선명한 3DGS로" 책에서 다룬 지표를 재사용합니다.

* **재투영 오차**(reprojection error) — 추정된 3D 구조를 카메라에 다시 투영했을 때 실제 관측 픽셀과 얼마나 떨어지는가.
* **포즈 오차**(pose error) — 추정된 카메라 자세가 참조 자세(GPS/INS 앵커나 정밀 측량값)와 회전·이동 성분에서 얼마나 다른가.

이 지표들이 중요한 이유는, 렌더링 품질이 떨어졌을 때 그 원인이 **모델 자체의 문제**인지 **입력 포즈의 문제**인지를 구분하는 유일한 단서이기 때문입니다. 렌더링 품질만 보고 있으면 "이번 체크포인트가 나빠졌다"고 오판하기 쉽지만, 실제로는 이번 평가에 쓰인 주행 로그의 포즈 추정이 우연히 더 흔들렸을 뿐일 수도 있습니다.

== 베이스라인: "직전 버전"이 아니라 "골든런"

가장 단순한 접근은 "직전에 배포한 체크포인트"를 베이스라인으로 삼는 것입니다. 하지만 이 방식에는 함정이 있습니다 — 회귀가 한 번에 크게 오지 않고 여러 체크포인트에 걸쳐 조금씩 누적되면(예: 매번 0.1dB씩 열 번), 매번 "직전 대비 큰 차이 없음"으로 통과하다가 어느새 1dB가 빠져 있는 상황을 놓칩니다. 이를 **회귀의 누적(drift of the baseline)**이라고 부릅니다.

이 책은 두 가지 베이스라인을 동시에 씁니다.

* **직전 베이스라인(rolling baseline)** — 매 체크포인트를 직전 통과한 체크포인트와 비교. 급격한 회귀를 빠르게 잡는 데 유용합니다.
* **골든런(golden run)** — 특정 시점에 사람이 검수하고 "이 품질을 최저선으로 유지한다"고 고정한 체크포인트. 절대적인 하한선 역할을 하며, 누적 드리프트를 잡습니다.

4장에서 이 골든런을 실제로 어떻게 만들고 버전 관리하는지 다룹니다.

== 판정 규칙: 임계값 대 통계적 검정

가장 단순한 판정 규칙은 고정 임계값입니다.

[source,python]
----
def is_regression_naive(psnr_new: float, psnr_base: float, threshold_db: float = 0.2) -> bool:
    return (psnr_base - psnr_new) > threshold_db
----

이 방식의 문제는 1장에서 본 비결정성입니다 — `psnr_base`와 `psnr_new` 둘 다 단일 실행의 결과라면, 이 차이가 진짜 회귀인지 실행 간 노이즈인지 알 방법이 없습니다. `threshold_db`를 너무 작게 잡으면 노이즈에도 실패하고(오탐, false positive), 너무 크게 잡으면 진짜 회귀를 놓칩니다(미탐, false negative).

이 책이 지향하는 방식은 **여러 번 반복 실행해 분포를 얻고, 그 분포를 통계적으로 비교**하는 것입니다. 개념만 먼저 스케치하면 다음과 같습니다.

[source,python]
----
import numpy as np

def is_regression_statistical(
    samples_new: np.ndarray,   # 새 체크포인트를 N회 반복 평가한 PSNR 표본들
    samples_base: np.ndarray,  # 베이스라인을 N회 반복 평가한 PSNR 표본들
    min_effect_db: float = 0.15,   # "의미 있는" 차이로 볼 최소 크기
    confidence: float = 0.95,
) -> bool:
    diff = samples_base.mean() - samples_new.mean()
    if diff < min_effect_db:
        return False   # 평균 차이 자체가 무의미하게 작음
    # 부트스트랩으로 diff의 신뢰구간 하한이 0보다 크게 떨어져 있는지 확인
    boot_diffs = []
    rng = np.random.default_rng(0)
    for _ in range(2000):
        b = rng.choice(samples_base, size=len(samples_base), replace=True)
        n = rng.choice(samples_new, size=len(samples_new), replace=True)
        boot_diffs.append(b.mean() - n.mean())
    lower = np.percentile(boot_diffs, (1 - confidence) * 100)
    return lower > 0
----

이 스케치는 "평균 차이가 실질적으로 의미 있는 크기(`min_effect_db`)를 넘고, 그 차이가 통계적으로도 우연이 아니라고 볼 만큼(부트스트랩 신뢰구간 하한이 양수) 확실할 때만" 회귀로 판정합니다. 이 접근을 8장에서 훨씬 깊이 다듬습니다 — 몇 번을 반복 실행해야 충분한지, 부트스트랩 표본 수는 얼마가 적절한지, 여러 지표를 동시에 볼 때 다중 비교 문제는 어떻게 다룰지까지 포함해서요.

== 단일 실행 비교의 위험성: 숫자로 확인하기

임계값 방식이 왜 위험한지 아주 단순한 시뮬레이션으로 감을 잡아봅니다. 완전히 동일한 모델(회귀 없음)을 실행마다 약간의 노이즈(표준편차 0.15dB)를 섞어 10번 "평가"했다고 가정합니다.

[source,python]
----
import numpy as np

rng = np.random.default_rng(42)
true_psnr = 31.20
noise_std = 0.15

runs_base = true_psnr + rng.normal(0, noise_std, 10)
runs_new = true_psnr + rng.normal(0, noise_std, 10)   # 실제로는 동일한 모델

naive_false_positives = sum(
    (b - n) > 0.2 for b, n in zip(runs_base, runs_new)
)
print(f"단일 쌍 비교 10회 중 임계값(0.2dB) 오탐 횟수: {naive_false_positives}")
print(f"베이스라인 평균: {runs_base.mean():.3f}, 신규 평균: {runs_new.mean():.3f}")
----

다음과 같은 결과를 얻습니다.

[source]
----
단일 쌍 비교 10회 중 임계값(0.2dB) 오탐 횟수: 2
베이스라인 평균: 31.187, 신규 평균: 31.234
----

회귀가 전혀 없는데도(같은 참 값 `31.20`), 실행을 단 한 번씩만 뽑아 비교하면 10번 중 2번은 "회귀"라고 잘못 판정합니다. 반면 평균을 비교하면(`31.187` vs `31.234`) 차이가 노이즈 수준(`0.15dB` 표준편차)보다 작아 회귀가 아니라는 게 명확합니다. 이 격차 — 단일 실행 비교의 불안정함과 평균/분포 비교의 안정성 — 이 8장에서 통계적 검정을 도입하는 근본적인 이유입니다.

== 회귀의 스코프: 전체 평균인가, 슬라이스인가

1장의 시나리오 A(맑은 날 고속도로만 나빠진 경우)에서 봤듯, 전체 평균만 보는 판정 규칙은 특정 조건의 회귀를 숨길 수 있습니다. 이 책의 파이프라인은 처음부터 평가 데이터셋을 **슬라이스**(날씨, 시간대, 도로 유형, 속도 구간 등)로 나누어, 전체 평균뿐 아니라 각 슬라이스별로도 회귀 판정을 돌립니다. 이 슬라이스 설계는 4장(베이스라인 데이터셋 구축)에서 구체화합니다.

== 요약

* 회귀 판정에는 비교 대상(베이스라인), 측정 지표, 판정 규칙이라는 세 요소가 모두 필요합니다.
* 이 파이프라인은 렌더링 품질 지표(PSNR/SSIM/LPIPS)와 기하/포즈 정확도 지표(재투영 오차, 포즈 오차)를 함께 봐서, 품질 저하의 원인이 모델인지 입력 포즈인지 구분합니다.
* 직전 버전만 베이스라인으로 삼으면 회귀가 여러 체크포인트에 걸쳐 조금씩 누적되는 것을 놓칠 수 있어, 롤링 베이스라인과 고정된 골든런을 함께 씁니다.
* 단일 실행 비교에 고정 임계값을 적용하는 방식은 비결정성 때문에 오탐·미탐을 반복하며, 여러 번 반복 실행한 분포를 통계적으로 비교하는 방식이 훨씬 안정적입니다.
* 전체 평균만이 아니라 날씨·시간대·도로 유형 같은 슬라이스별로도 회귀를 판정해야 특정 조건에서만 나타나는 회귀를 놓치지 않습니다.

== 연습문제

. 위 시뮬레이션 코드에서 `noise_std`를 `0.05`로 줄이면 오탐 횟수가 어떻게 바뀌는지, `0.3`으로 늘리면 어떻게 바뀌는지 직접 실행해 확인해보세요. 노이즈 크기와 오탐률의 관계를 한 문장으로 설명해보세요.
. 여러분이 다루는(혹은 상상하는) 3DGS/E2E 평가 데이터셋을 어떤 슬라이스(예: 날씨, 시간대, 속도 구간, 센서 종류)로 나눌 수 있을지 최소 4가지를 나열하고, 각 슬라이스에서 어떤 종류의 회귀가 특히 드러나기 쉬울지 설명해보세요.
