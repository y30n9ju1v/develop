'''

3~5장에서 클러스터, 아티팩트 저장소, 컨테이너 이미지를 준비했습니다. 이 장에서는 이 모든 조각을 하나의 Argo Workflow DAG로 엮어, "새 체크포인트 하나가 들어오면 끝까지 자동으로 회귀 여부가 판정되는" 파이프라인을 완성합니다.

== DAG로 표현할 단계들

2장과 3장에서 정한 흐름을 다시 정리하면 다음과 같은 의존관계를 가진 5단계입니다.

----
fetch-baseline ──┐
                 ├──▶ compare-and-gate
render-candidate┘
       │
       ▼
compute-metrics
----

정확히는 `render-candidate`가 끝나야 `compute-metrics`를 돌릴 수 있고, `compute-metrics`와 `fetch-baseline`(베이스라인의 기존 지표 리포트를 가져오는 가벼운 단계)이 모두 끝나야 `compare-and-gate`를 돌릴 수 있습니다. Argo Workflow의 `dag` 템플릿은 이 의존관계를 `depends` 필드로 명시적으로 표현합니다.

== 전체 Workflow 매니페스트

[source,yaml]
----
# regression-workflow.yaml
apiVersion: argoproj.io/v1alpha1
kind: Workflow
metadata:
  generateName: regression-test-
  namespace: argo
spec:
  entrypoint: regression-dag
  arguments:
    parameters:
      - name: checkpoint-uri
        value: "s3://model-checkpoints/checkpoint-2026-08-14-a.pt"
      - name: golden-run-tag
        value: "checkpoint-2026-05-18-rc3"
      - name: manifest-version
        value: "v2026.05.20"

  artifactRepositoryRef:
    configMap: artifact-repositories
    key: minio-regression

  templates:
    - name: regression-dag
      dag:
        tasks:
          - name: fetch-baseline
            template: fetch-baseline-tpl
            arguments:
              parameters:
                - {name: golden-run-tag, value: "{{workflow.parameters.golden-run-tag}}"}
                - {name: manifest-version, value: "{{workflow.parameters.manifest-version}}"}

          - name: render-candidate
            template: render-candidate-tpl
            arguments:
              parameters:
                - {name: checkpoint-uri, value: "{{workflow.parameters.checkpoint-uri}}"}
                - {name: manifest-version, value: "{{workflow.parameters.manifest-version}}"}

          - name: compute-metrics
            template: compute-metrics-tpl
            depends: "render-candidate"
            arguments:
              artifacts:
                - name: candidate-renders
                  from: "{{tasks.render-candidate.outputs.artifacts.renders}}"
              parameters:
                - {name: manifest-version, value: "{{workflow.parameters.manifest-version}}"}

          - name: compare-and-gate
            template: compare-and-gate-tpl
            depends: "fetch-baseline && compute-metrics"
            arguments:
              artifacts:
                - name: baseline-metrics
                  from: "{{tasks.fetch-baseline.outputs.artifacts.metrics}}"
                - name: candidate-metrics
                  from: "{{tasks.compute-metrics.outputs.artifacts.metrics}}"

    - name: fetch-baseline-tpl
      inputs:
        parameters:
          - name: golden-run-tag
          - name: manifest-version
      container:
        image: localhost:5001/regression-compare:dev
        command: ["python", "-m", "compare.fetch_baseline"]
        args:
          - "--golden-run-tag={{inputs.parameters.golden-run-tag}}"
          - "--manifest-version={{inputs.parameters.manifest-version}}"
          - "--out=/out/baseline_metrics.json"
        resources:
          requests: {cpu: "250m", memory: "256Mi"}
      outputs:
        artifacts:
          - name: metrics
            path: /out/baseline_metrics.json

    - name: render-candidate-tpl
      inputs:
        parameters:
          - name: checkpoint-uri
          - name: manifest-version
      container:
        image: localhost:5001/regression-eval:dev
        command: ["python3", "-m", "eval.run_eval"]
        args:
          - "--checkpoint={{inputs.parameters.checkpoint-uri}}"
          - "--sequence-dir=/data/baseline-inputs"
          - "--out-dir=/out"
        env:
          - {name: EVAL_MOCK, value: "1"}   # 로컬 kind 검증 시 목 모드, 12장에서 GPU 클러스터로 전환 시 제거
        resources:
          requests: {cpu: "2", memory: "4Gi"}
          limits: {nvidia.com/gpu: "1"}
        volumeMounts:
          - {name: baseline-inputs, mountPath: /data/baseline-inputs}
      nodeSelector:
        workload: eval-jobs
      volumes:
        - name: baseline-inputs
          persistentVolumeClaim: {claimName: baseline-inputs-pvc}
      outputs:
        artifacts:
          - name: renders
            path: /out

    - name: compute-metrics-tpl
      inputs:
        parameters:
          - name: manifest-version
        artifacts:
          - name: candidate-renders
            path: /in/renders
      container:
        image: localhost:5001/regression-compare:dev
        command: ["python", "-m", "compare.summarize_metrics"]
        args:
          - "--renders-dir=/in/renders"
          - "--manifest-version={{inputs.parameters.manifest-version}}"
          - "--out=/out/candidate_metrics.json"
        resources:
          requests: {cpu: "500m", memory: "512Mi"}
      outputs:
        artifacts:
          - name: metrics
            path: /out/candidate_metrics.json

    - name: compare-and-gate-tpl
      inputs:
        artifacts:
          - name: baseline-metrics
            path: /in/baseline_metrics.json
          - name: candidate-metrics
            path: /in/candidate_metrics.json
      container:
        image: localhost:5001/regression-compare:dev
        command: ["python", "-m", "compare.run_compare"]
        args:
          - "--baseline=/in/baseline_metrics.json"
          - "--candidate=/in/candidate_metrics.json"
          - "--report-out=/out/regression_report.json"
        resources:
          requests: {cpu: "250m", memory: "256Mi"}
      outputs:
        artifacts:
          - name: report
            path: /out/regression_report.json
----

== 이 YAML에서 눈여겨볼 세 가지

**첫째, `fetch-baseline`과 `render-candidate`는 서로 `depends`가 없어 병렬로 실행됩니다.** 베이스라인 지표는 이미 4장에서 골든런 승격 시 계산되어 MinIO에 저장돼 있으므로, 이번 실행에서 다시 렌더링할 필요 없이 가벼운 `fetch` 잡으로 가져오기만 하면 됩니다. 반면 `render-candidate`는 GPU를 쓰는 무거운 잡입니다. 이 둘을 병렬로 돌리는 것만으로 DAG의 전체 실행 시간(critical path)이 크게 줄어듭니다.

**둘째, 아티팩트는 `outputs.artifacts` → `{{tasks.X.outputs.artifacts.Y}}` → `inputs.artifacts`로 연결되고, 실제 전달은 3장에서 배치한 MinIO를 거칩니다.** `render-candidate-tpl`이 `/out`에 쓴 렌더링 결과물은 컨트롤러가 자동으로 MinIO에 업로드하고, `compute-metrics-tpl`이 시작될 때 자동으로 `/in/renders`에 내려받습니다. 파드 사이의 데이터 흐름을 수동으로 배관할 필요가 없습니다.

**셋째, GPU가 필요한 단계(`render-candidate-tpl`)만 `nodeSelector: {workload: eval-jobs}`와 `limits: {nvidia.com/gpu: "1"}`을 갖고, 나머지 단계는 가벼운 리소스 요청만 가집니다.** 이 구분은 5장에서 이미지를 GPU용/비GPU용으로 나눈 것과 짝을 이룹니다.

== 워크플로 제출과 상태 확인

[source,bash]
----

  --parameter checkpoint-uri=s3://model-checkpoints/checkpoint-2026-08-14-a.pt \
  --watch
----

== 게이트 실패를 워크플로 실패로 전파하기

`compare-and-gate-tpl`이 회귀를 감지하면, 리포트를 남기는 것만으로는 CI가 자동으로 머지를 막지 않습니다. 컨테이너의 종료 코드(exit code)를 0이 아닌 값으로 만들어야 Argo Workflow 자체가 `Failed` 상태가 되고, 이 상태를 9장에서 CI가 체크하게 됩니다.

[source,python]
----
# compare/run_compare.py 골격 (판정 로직 자체는 8장에서 통계적으로 확장)
import json
import sys

def main():
    with open("/in/baseline_metrics.json") as f:
        baseline = json.load(f)
    with open("/in/candidate_metrics.json") as f:
        candidate = json.load(f)

    delta_psnr = candidate["psnr_db"] - baseline["psnr_db"]
    is_regression = delta_psnr < -0.2   # 2장의 임계값 스케치, 8장에서 통계적 검정으로 대체

    report = {
        "baseline_psnr_db": baseline["psnr_db"],
        "candidate_psnr_db": candidate["psnr_db"],
        "delta_psnr_db": delta_psnr,
        "is_regression": is_regression,
    }
    with open("/out/regression_report.json", "w") as f:
        json.dump(report, f, indent=2)

    print(json.dumps(report, indent=2))
    if is_regression:
        print("회귀 감지됨 — 워크플로를 실패로 표시합니다.", file=sys.stderr)
        sys.exit(1)


if __name__ == "__main__":
    main()
----

== 요약

* Argo Workflow의 `dag` 템플릿은 `depends` 필드로 단계 간 의존관계를 명시적으로 표현하며, 독립적인 단계(베이스라인 가져오기, 렌더링)는 자동으로 병렬 실행됩니다.
* 아티팩트는 `outputs.artifacts`/`inputs.artifacts`와 `{{tasks.X.outputs...}}` 참조로 단계 사이를 흐르고, 실제 전달은 MinIO를 거쳐 컨트롤러가 자동으로 처리합니다.
* GPU가 필요한 단계와 그렇지 않은 단계를 `nodeSelector`/`resources`로 구분해 클러스터 자원을 효율적으로 씁니다.
* 회귀 판정 잡이 0이 아닌 종료 코드로 끝나면 워크플로 전체가 `Failed`로 표시되고, 이 신호를 9장에서 CI/CD가 감지해 머지를 막습니다.
