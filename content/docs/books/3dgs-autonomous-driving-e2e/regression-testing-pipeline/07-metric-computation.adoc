6장에서 DAG의 `compute-metrics-tpl` 단계가 렌더링 결과물을 받아 지표를 계산한다고만 스케치했습니다. 이 장에서는 그 안에서 정확히 무엇을 계산하고, 어떻게 슬라이스별로 집계하고, 어떤 스키마의 JSON으로 내보내는지 구체화합니다.

== 두 축의 지표를 한곳에 모으기

2장에서 정한 대로, 이 단계는 렌더링 품질 지표와 기하/포즈 정확도 지표를 함께 계산합니다.

[source,python]
----
# compare/metric_kernels.py
# PSNR/SSIM/LPIPS는 "닮았다는 걸 어떻게 잴까" 책 3장·6장·9장의 구현을 그대로 재사용합니다.
from image_fidelity.psnr import compute_psnr
from image_fidelity.ssim import compute_ssim
from image_fidelity.perceptual import compute_lpips_like

# 재투영 오차는 "흔들리는 로그를 선명한 3DGS로" 책 1장·7장의 구현을 재사용합니다.
from sensor_sync.geometry import triangulate_point, project
from sensor_sync.pose_error import rotation_error_deg, translation_error


def frame_image_metrics(rendered, reference) -> dict:
    return {
        "psnr_db": compute_psnr(rendered, reference),
        "ssim": compute_ssim(rendered, reference),
        "lpips": compute_lpips_like(rendered, reference),
    }


def frame_pose_metrics(estimated_pose, reference_pose, landmarks_world, observations_2d) -> dict:
    R_est, t_est = estimated_pose
    R_ref, t_ref = reference_pose
    reproj_errors = [
        # 추정 포즈로 삼각측량한 점을, 참조(정답에 가까운) 포즈에 다시 투영했을 때의 오차
        __import__("numpy").hypot(*(project(P, R_est, t_est) - obs))
        for P, obs in zip(landmarks_world, observations_2d)
    ]
    return {
        "rotation_error_deg": rotation_error_deg(R_est, R_ref),
        "translation_error_m": translation_error(t_est, t_ref),
        "mean_reprojection_error_px": sum(reproj_errors) / len(reproj_errors),
    }
----

이 책은 `image_fidelity`와 `sensor_sync` 모듈을 새로 재구현하지 않고 그대로 임포트합니다 — 이 재사용 자체가 4장에서 강조한 "검증된 코드를 신뢰하고 새 파이프라인에 얹는다"는 원칙의 실천입니다.

== 시퀀스 단위로 집계하기

한 시퀀스는 수백 프레임으로 이루어지므로, 프레임별 지표를 시퀀스 단위 통계(평균, 표준편차, 최악값)로 집계합니다. 평균만 남기면 "가끔 몇 프레임만 심하게 나쁜" 경우를 놓치므로, 최악 프레임의 지표도 함께 기록합니다.

[source,python]
----
# compare/summarize_metrics.py
import json
from pathlib import Path
import numpy as np

def summarize_sequence(frame_metrics: list[dict]) -> dict:
    keys = frame_metrics[0].keys()
    summary = {}
    for key in keys:
        values = np.array([m[key] for m in frame_metrics])
        summary[key] = {
            "mean": float(values.mean()),
            "std": float(values.std()),
            "p95_worst": float(np.percentile(values, 95 if "error" in key or key == "lpips" else 5)),
            "min": float(values.min()),
            "max": float(values.max()),
        }
    return summary
----

`p95_worst`는 지표의 성격에 따라 방향이 달라집니다 — PSNR/SSIM은 낮을수록 나쁘므로 하위 5퍼센타일이 "최악"이고, LPIPS·재투영 오차·회전 오차는 높을수록 나쁘므로 상위 95퍼센타일이 "최악"입니다.

== 슬라이스별 롤업

4장에서 정의한 슬라이스 메타데이터를 이용해, 시퀀스 단위 요약을 다시 슬라이스 단위로 롤업합니다.

[source,python]
----
def rollup_by_slice(sequence_summaries: dict[str, dict], manifest: list) -> dict:
    """sequence_summaries: {sequence_id: summary}, manifest: BaselineSequence 목록"""
    by_slice: dict[str, list[dict]] = {}
    for seq in manifest:
        summary = sequence_summaries.get(seq.sequence_id)
        if summary is None:
            continue
        for axis, value in seq.slices.items():
            key = f"{axis}={value}"
            by_slice.setdefault(key, []).append(summary)

    rollup = {}
    for slice_key, summaries in by_slice.items():
        rollup[slice_key] = {
            "n_sequences": len(summaries),
            "psnr_db_mean": sum(s["psnr_db"]["mean"] for s in summaries) / len(summaries),
            "ssim_mean": sum(s["ssim"]["mean"] for s in summaries) / len(summaries),
            "lpips_mean": sum(s["lpips"]["mean"] for s in summaries) / len(summaries),
            "mean_reprojection_error_px": sum(
                s["mean_reprojection_error_px"]["mean"] for s in summaries
            ) / len(summaries),
        }
    return rollup
----

== 통일된 리포트 스키마

`compute-metrics` 단계가 최종적으로 내보내는 JSON은 전체 요약, 시퀀스별 요약, 슬라이스별 롤업 세 계층을 모두 담습니다 — 8장의 통계적 검정과 10장의 Rerun 시각화 둘 다 이 하나의 스키마를 소비합니다.

[source,json]
----
{
  "checkpoint_uri": "s3://model-checkpoints/checkpoint-2026-08-14-a.pt",
  "manifest_version": "v2026.05.20",
  "overall": {
    "psnr_db": {"mean": 31.05, "std": 0.42, "p95_worst": 30.11},
    "ssim": {"mean": 0.887, "std": 0.021, "p95_worst": 0.849},
    "lpips": {"mean": 0.091, "std": 0.014, "p95_worst": 0.121},
    "mean_reprojection_error_px": {"mean": 0.74, "std": 0.31, "p95_worst": 1.42}
  },
  "by_sequence": {
    "seq-0001": { "psnr_db": {"mean": 31.4, "std": 0.2}, "...": "..." },
    "seq-0002": { "psnr_db": {"mean": 29.8, "std": 0.5}, "...": "..." }
  },
  "by_slice": {
    "weather=clear": {"n_sequences": 68, "psnr_db_mean": 31.6, "...": "..."},
    "weather=rain": {"n_sequences": 14, "psnr_db_mean": 29.1, "...": "..."},
    "time_of_day=night": {"n_sequences": 11, "psnr_db_mean": 28.7, "...": "..."}
  }

----

이 예시는 `weather=rain`과 `time_of_day=night` 슬라이스의 PSNR이 전체 평균(`31.05`)보다 눈에 띄게 낮다는 걸 보여줍니다 — 이 자체가 회귀는 아니지만(원래도 어려운 조건일 수 있으므로), 골든런 대비 이 슬라이스들의 하락 폭이 다른 슬라이스보다 크다면 8장의 통계적 검정에서 그 슬라이스만 회귀로 표시될 수 있습니다.

== `compute-metrics-tpl`의 실제 구현 골격

6장 DAG의 해당 단계가 실행하는 엔트리포인트는 다음과 같은 흐름입니다.

[source,python]
----
# compare/summarize_metrics.py의 main()
def main():
    parser = argparse.ArgumentParser()
    parser.add_argument("--renders-dir", required=True, type=Path)
    parser.add_argument("--manifest-version", required=True)
    parser.add_argument("--out", required=True, type=Path)
    args = parser.parse_args()

    manifest = load_manifest(args.manifest_version)
    sequence_summaries = {}
    for seq in manifest:
        frame_metrics = compute_frame_metrics_for_sequence(seq, args.renders_dir)
        sequence_summaries[seq.sequence_id] = summarize_sequence(frame_metrics)

    overall = summarize_sequence(
        [m for seq_metrics in sequence_summaries.values() for m in [seq_metrics]]
    )
    report = {
        "manifest_version": args.manifest_version,
        "overall": overall,
        "by_sequence": sequence_summaries,
        "by_slice": rollup_by_slice(sequence_summaries, manifest),
    }
    args.out.write_text(json.dumps(report, indent=2))
----

== 요약

* `compute-metrics` 단계는 렌더링 품질 지표(PSNR/SSIM/LPIPS)와 기하/포즈 정확도 지표(재투영 오차, 회전/이동 오차)를 함께 계산하며, 두 지표의 구현은 사이블링 두 책에서 이미 검증된 코드를 그대로 임포트해 재사용합니다.
* 프레임 단위 지표는 시퀀스 단위로(평균·표준편차·최악 퍼센타일), 시퀀스 단위 요약은 다시 슬라이스 단위로 롤업됩니다.
* 최종 리포트는 전체/시퀀스별/슬라이스별 세 계층을 모두 담는 통일된 JSON 스키마로 내보내지고, 이 스키마를 8장의 통계적 검정과 10장의 시각화가 함께 소비합니다.

== 연습문제

. `frame_pose_metrics`가 `landmarks_world`와 `observations_2d`를 입력으로 요구하는데, 실제 3DGS 파이프라인에서는 이 값들을 어디서 얻을 수 있을지(예: SfM 재구성, 라이다 포인트클라우드) 생각해보세요.
. `summarize_sequence`가 `p95_worst`를 지표 이름에 `"error"`가 포함되는지로 방향을 판단하는데, 이 방식이 깨지기 쉬운 이유(예: 새로운 지표 이름이 추가될 때)를 지적하고, 더 견고한 설계(예: 지표별 메타데이터에 `higher_is_better: bool` 필드를 명시)를 스케치해보세요.
