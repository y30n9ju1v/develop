1장에서는 미분 공식을 손으로 유도했습니다. 실제 3DGS는 파라미터가 수백만 개라 손으로 미분할 수 없습니다 — 이 장에서는 **연쇄법칙을 기계적으로, 자동으로** 적용하는 도구, 자동미분(autodiff)을 처음부터 구현합니다.

== 핵심 아이디어: 계산을 그래프로 기록하기

`(a*b + a) ** 2`처럼 여러 연산을 조합한 계산을 떠올려보세요. 이 계산은 사실 작은 연산들의 사슬입니다 — `a*b`를 계산하고, 그 결과에 `a`를 더하고, 마지막으로 제곱합니다. 자동미분의 핵심 아이디어는, **이 사슬을 계산하는 동시에 기록해두고**, 나중에 그 기록을 거꾸로 훑으면서 연쇄법칙을 자동으로 적용하는 것입니다.

== Value 클래스: 계산 그래프의 노드

[source,python]
----
import math

class Value:
    """계산 그래프의 노드 하나. 순전파 값과, 나중에 채워질 그래디언트를 함께 들고 다닌다."""
    def __init__(self, data, parents=(), local_grads=(), label=""):
        self.data = data
        self.grad = 0.0
        self.parents = parents          # 이 값을 만드는 데 쓰인 입력 노드들
        self.local_grads = local_grads  # 각 입력에 대한 "국소" 미분값

    def __add__(self, other):
        other = other if isinstance(other, Value) else Value(other)
        return Value(self.data + other.data, (self, other), (1.0, 1.0), "+")

    def __mul__(self, other):
        other = other if isinstance(other, Value) else Value(other)
        return Value(self.data * other.data, (self, other), (other.data, self.data), "*")

    def __pow__(self, p):
        return Value(self.data ** p, (self,), (p * self.data ** (p - 1),), f"**{p}")

    def exp(self):
        e = math.exp(self.data)
        return Value(e, (self,), (e,), "exp")
----

`Value`는 파이썬의 숫자를 대신하는 객체이고, `+`, `*`, `**`, `exp` 같은 연산을 오버로딩해서 "이 값이 어떤 부모들로부터, 어떤 국소 미분값으로 만들어졌는지"를 계속 기록합니다. 예를 들어 `a * b`를 계산하면, 결과 노드는 부모(`a`, `b`)와 **국소 미분값**(`d(a*b)/da = b`, `d(a*b)/db = a`, 이건 그냥 곱셈의 미분 공식입니다)을 함께 저장합니다.

== 역전파: 그래프를 거꾸로 훑으며 연쇄법칙 적용하기

[source,python]
----
def backward(self):
    """역전파: 위상정렬 순서로 그래디언트를 뒤에서 앞으로 흘려보낸다."""
    topo, visited = [], set()
    def build(v):
        if id(v) not in visited:
            visited.add(id(v))
            for p in v.parents:
                build(p)
            topo.append(v)
    build(self)
    self.grad = 1.0  # dL/dL = 1
    for v in reversed(topo):
        for p, lg in zip(v.parents, v.local_grads):
            p.grad += v.grad * lg  # 연쇄법칙: 상류 그래디언트 * 국소 미분
----

`backward()`는 최종 결과(예를 들어 손실 함수 값)에서 시작해서, 계산 그래프를 거슬러 올라가며 각 노드의 그래디언트를 채웁니다. 핵심은 딱 한 줄입니다 — `p.grad += v.grad * lg`. 이게 정확히 연쇄법칙(`dL/dp = dL/dv · dv/dp`)입니다 — "지금까지 누적된 상류 그래디언트"(`v.grad`)에 "이 연산 하나의 국소 미분"(`lg`)을 곱해서 부모에게 넘겨줍니다. `topo`(위상정렬)는 각 노드가 자신에게 의존하는 모든 노드보다 먼저 처리되도록(즉 역순으로는 나중에 처리되도록) 순서를 보장합니다.

== 엔진 자체를 검증하기

[source,python]
----
def f_numpy(a, b):
    return (a * b + a) ** 2

a_val, b_val = 2.0, 3.0
a, b = Value(a_val), Value(b_val)
out = (a * b + a) ** 2
out.backward()

eps = 1e-6
df_da_numeric = (f_numpy(a_val + eps, b_val) - f_numpy(a_val - eps, b_val)) / (2 * eps)
df_db_numeric = (f_numpy(a_val, b_val + eps) - f_numpy(a_val, b_val - eps)) / (2 * eps)
print(a.grad, df_da_numeric)  # 64.0  64.00000000184036
print(b.grad, df_db_numeric)  # 32.0  32.00000000092018
assert math.isclose(a.grad, df_da_numeric, rel_tol=1e-4)
assert math.isclose(b.grad, df_db_numeric, rel_tol=1e-4)
----

`f(a,b) = (a·b + a)²`이라는, 곱셈·덧셈·거듭제곱이 섞인 계산에 대해 `Value` 엔진이 계산한 그래디언트가 유한차분과 정확히 일치합니다 — `a`와 `b`에 대해 각각 단 한 번의 `backward()` 호출로 **동시에** 두 그래디언트를 얻었다는 것도 눈여겨보세요. 손으로 미분했다면 `∂f/∂a`와 `∂f/∂b`를 따로따로 유도해야 했을 것입니다.

== 1장의 렌더러를 자동미분으로 다시 풀기

이제 1장에서 손으로 미분했던 1D 렌더러를 이 엔진으로 다시 짜봅니다.

[source,python]
----
def render_autodiff(mu, target_vals):
    """Value 엔진으로 1D 렌더러 + 손실을 계산한다. mu는 Value, target_vals는 숫자 배열."""
    total_loss = Value(0.0)
    for x, t in zip(xs, target_vals):
        diff = Value(x) - mu
        exponent = (diff * diff) * (-0.5 / sigma ** 2)
        r = exponent.exp()
        err = r - Value(float(t))
        total_loss = total_loss + err * err
    return total_loss

mu_node = Value(0.5)
loss_node = render_autodiff(mu_node, target)
loss_node.backward()
----

여기서 중요한 건, **미분 공식을 단 한 줄도 직접 쓰지 않았다**는 것입니다 — `Value`가 제공하는 `+`, `-`, `*`, `exp`만으로 렌더링과 손실 계산을 그대로 옮겨 적었을 뿐인데, `backward()` 한 번으로 `mu`에 대한 그래디언트가 자동으로 채워집니다.

== 손으로 미분한 결과와 정확히 일치하는지 확인

[source,python]
----
def loss_grad_analytic(mu, target_vals):
    r = np.exp(-0.5 * ((xs - mu) / sigma) ** 2)
    d_r_d_mu = r * (xs - mu) / sigma ** 2
    d_loss_d_r = 2 * (r - target_vals)
    return np.sum(d_loss_d_r * d_r_d_mu)

grad_manual = loss_grad_analytic(0.5, target)
print(mu_node.grad, grad_manual)  # -14.655346885730854  -14.655346885730857
assert math.isclose(mu_node.grad, grad_manual, rel_tol=1e-6)
----

자동미분 엔진이 계산한 그래디언트(`-14.6553468857...`)와 1장에서 연쇄법칙을 손으로 적용해서 유도한 그래디언트(`-14.6553468857...`)가 소수점 12자리까지 정확히 일치합니다 — **자동미분이 하는 일이 결국 우리가 1장에서 손으로 한 것과 완전히 같은 계산이라는 것**, 다만 그 계산을 프로그램이 대신 추적하고 실행해준다는 것뿐이라는 걸 직접 확인했습니다.

== 왜 이게 3DGS에서 필수적인가

3DGS의 가우시안 하나는 위치(3), 회전(4, 쿼터니언), 크기(3), 불투명도(1), 색(구면조화계수를 쓰면 채널당 여러 개) 같은 수십 개의 파라미터를 가지고, 장면 하나에는 이런 가우시안이 수십만~수백만 개 있습니다. 이 모든 파라미터에 대한 그래디언트를 손으로 유도하는 건 사실상 불가능하지만, 이 장에서 만든 것과 같은(다만 훨씬 정교하고 빠른) 자동미분 엔진이 있으면, 렌더링 코드를 한 번 잘 짜두기만 하면 그래디언트는 **공짜로** 따라옵니다 — 실제 3DGS 구현들이 CUDA로 최적화된 자동미분(PyTorch의 `autograd` 등)을 쓰는 이유입니다.

== 직접 해보기

* `Value` 클래스에 나눗셈(`__truediv__`, `a/b`)을 추가해보세요 — `a/b`는 `a * b**(-1)`로 표현할 수 있다는 걸 이용하면 새 연산을 직접 만들 필요 없이 이미 있는 `*`와 `**`만으로 구현할 수 있습니다.

.해답 보기
[%collapsible]
====
[source,python]
----
def __truediv__(self, other):
    other = other if isinstance(other, Value) else Value(other)
    return self * (other ** -1)

Value.__truediv__ = __truediv__

a, b = Value(6.0), Value(3.0)
out = a / b
out.backward()
print(out.data, a.grad, b.grad)  # 2.0  0.333...  -0.666...
assert math.isclose(a.grad, 1/3, rel_tol=1e-6)
assert math.isclose(b.grad, -6/9, rel_tol=1e-6)
----

새로운 연산 `__truediv__`를 처음부터 국소 미분을 유도해서 만들 수도 있지만, **이미 미분이 정의된 연산들의 조합으로 표현**하면 그 연산들의 `backward` 로직을 그대로 재사용할 수 있습니다 — 실전 자동미분 라이브러리들도 가능하면 이런 식으로 기본 연산의 조합으로 복잡한 연산을 표현해서 구현을 단순하게 유지합니다.
====

== 요약

* 자동미분은 계산 과정을 그래프로 기록해두고, 그 그래프를 거꾸로 훑으며 연쇄법칙을 기계적으로 적용하는 기법입니다.
* `Value` 클래스의 각 연산은 자기 자신의 국소 미분값을 알고 있고, `backward()`가 이 국소 미분들을 상류 그래디언트와 곱해 누적시킵니다.
* 자동미분으로 얻은 그래디언트가 1장에서 손으로 유도한 것과 정확히 일치한다는 걸 확인했습니다 — 자동미분은 새로운 수학이 아니라, 손으로 하던 연쇄법칙을 프로그램이 대신해주는 것입니다.
* 미분이 정의된 기본 연산들을 조합하면, 새로운 연산의 미분도 따로 유도할 필요 없이 자동으로 따라옵니다.
