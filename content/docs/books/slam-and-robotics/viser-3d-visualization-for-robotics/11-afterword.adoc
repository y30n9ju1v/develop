== 이 책에서 다룬 것

`viser.ViserServer()` 두 줄로 브라우저 뷰어를 띄우는 것부터 시작해(1장), 이름의 슬래시 경로로 좌표 프레임을 계층적으로 중첩시키고(2장), 컴퓨터 비전에 특화된 카메라 프러스텀으로 내부·외부 파라미터를 함께 시각화하고(3장), 메시와 조명으로 표면에 입체감을 더하고(4장), GUI 패널과 클릭 이벤트로 씬과 상호작용하고(5, 6장), 대량의 포인트클라우드와 3D Gaussian Splats를 다루고(7, 8장), 시간에 따라 변하는 궤적을 재생하는 법(9장)까지 다뤘습니다. 마지막 장(10장)에서는 이 모든 조각을 하나의 작은 뷰어 앱으로 조립했습니다.

이 책의 모든 예제는 실제로 `viser.ViserServer()`를 띄우고 씬을 구성하는 완결된 스크립트였고, 콜백이 실제로 발동하는지, 씬 트리 구조가 의도한 대로 만들어지는지를 매번 `assert`로 확인했습니다. Viser 자체가 "숫자가 맞는지"가 아니라 "모양이 맞는지"를 눈으로 검증하기 위한 도구이지만, 그 배선(어떤 값이 어떤 물체의 어떤 속성으로 흘러가는지)만큼은 브라우저 없이도 코드로 검증할 수 있다는 것을 이 시리즈의 다른 책들과 같은 방식으로 보여드리고 싶었습니다.

== 다음 단계

이 책은 Viser의 핵심 개념을 다뤘지만, 실전에 통합하려면 몇 가지를 더 살펴볼 만합니다.

* **URDF/로봇 모델 로딩**: `viser.extras`에는 URDF 파일을 읽어 로봇의 링크와 관절을 자동으로 씬 트리에 구성해주는 헬퍼가 있습니다. 이 책의 2장에서 손으로 만든 프레임 계층을, 실제 로봇 모델에서는 URDF 파서가 대신 만들어 줍니다.
* **`.glb`/`.obj` 메시 불러오기**: 4장에서는 정점·면을 직접 정의했지만, 실전에서는 대개 이미 만들어진 3D 모델 파일을 `add_glb`나 `trimesh` 라이브러리와 연동한 `add_mesh_trimesh`로 불러옵니다.
* **원격 서버에 접속하기**: 이 책의 모든 예제는 `localhost`에서 서버와 브라우저가 같은 컴퓨터에 있었습니다. 클라우드에서 학습 중인 3DGS/SLAM 파이프라인에서 Viser 서버를 띄우고, SSH 포트 포워딩이나 사내 네트워크를 통해 로컬 브라우저로 접속하는 방식도 흔한 사용 패턴입니다.
* **`server.scene.get_render` / `as_html`**: 뷰어를 계속 띄워두는 대신, 특정 시점의 렌더링을 이미지로 저장하거나(`get_render`) 씬 전체를 정적 HTML 파일로 내보내(`as_html`) 리포트나 문서에 첨부하는 것도 가능합니다.

== 이 시리즈와의 연결

이 책의 3장(카메라 프러스텀)은 앞서 나온 link:../../3dgs-autonomous-driving-e2e/multiview-geometry-3d-reconstruction/[멀티뷰 기하 책]의 내부·외부 파라미터 공식을 그대로 시각화로 옮긴 것이었고, 8장(Gaussian Splats)은 3DGS 파이프라인의 학습 결과를 확인하는 데 곧바로 쓸 수 있습니다. 두 책의 코드로 계산한 숫자가 "맞다"는 것을 확인했다면, 이제 이 책의 코드로 그 숫자가 "그럴듯한 모양"을 만드는지도 확인할 수 있습니다 — 계산과 시각화, 이 둘을 오가는 습관이 3D 파이프라인을 디버깅하는 가장 실용적인 방법입니다.
