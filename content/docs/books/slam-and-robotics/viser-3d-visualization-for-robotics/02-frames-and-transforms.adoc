1장에서는 이름을 그냥 물체를 구분하는 라벨처럼 썼습니다. 사실 이름은 훨씬 더 중요한 역할을 합니다 — 슬래시로 나뉜 경로가 씬 트리 안에서 **부모-자식 관계**를 결정합니다. 이 관계를 이해하면 "로봇이 이동하면 로봇에 달린 카메라도 같이 이동한다"처럼 계층적인 자세를 자연스럽게 표현할 수 있습니다.

== 프레임: 위치와 방향을 가진 좌표축

`add_frame`은 그 자리에 작은 좌표축(빨강 x, 초록 y, 파랑 z)을 그리는 물체입니다.

[source,python]
----
import viser
from scipy.spatial.transform import Rotation

server = viser.ViserServer()
server.scene.world_axes.visible = True


def quat_wxyz(rotation: Rotation) -> tuple[float, float, float, float]:
    x, y, z, w = rotation.as_quat()
    return (w, x, y, z)


robot_rotation = Rotation.from_euler("z", 45, degrees=True)
robot_frame = server.scene.add_frame(
    "/robot",
    wxyz=quat_wxyz(robot_rotation),
    position=(1.0, 0.0, 0.0),
    axes_length=0.4,
    axes_radius=0.01,
)
----

Viser는 회전을 `(w, x, y, z)` 순서의 쿼터니언으로 받습니다(SciPy의 `Rotation.as_quat()`는 `(x, y, z, w)` 순서를 반환하므로 `quat_wxyz` 같은 작은 변환 함수가 필요합니다 — 이 순서 차이를 놓치면 회전이 엉뚱하게 나오니 주의하세요). 이 코드는 세계 좌표 `(1, 0, 0)`에 z축 기준 45도 회전한 프레임을 하나 만듭니다 — "로봇이 이 위치에, 이 방향으로 서 있다"는 뜻입니다.

== 이름의 슬래시가 부모를 결정한다

이제 이 로봇에 달린 카메라를 추가합니다.

[source,python]
----
camera_frame = server.scene.add_frame(
    "/robot/camera",
    wxyz=quat_wxyz(Rotation.identity()),
    position=(0.2, 0.0, 0.3),
    axes_length=0.2,
    axes_radius=0.008,
)

assert robot_frame.name == "/robot"
assert camera_frame.name == "/robot/camera"
----

이름이 `/robot/camera`이므로, Viser는 이 프레임을 `/robot`의 **자식**으로 취급합니다. `position=(0.2, 0.0, 0.3)`은 세계 좌표가 아니라 **부모(`/robot`) 기준 로컬 좌표**입니다 — 로봇 원점에서 카메라가 앞으로 0.2m, 위로 0.3m 떨어진 곳에 달려 있다는 뜻입니다. 이렇게 상대 좌표로 자식을 붙여두면, 나중에 `robot_frame.position`이나 `robot_frame.wxyz`를 바꾸는 것만으로 카메라를 포함한 전체 하위 트리가 통째로 움직입니다 — 로봇이 이동할 때마다 카메라 위치를 일일이 다시 계산할 필요가 없습니다.

== 로컬 좌표를 세계 좌표로 직접 계산해보기

브라우저로 확인하기 전에, 이 계층 구조가 실제로 어떤 세계 좌표를 만드는지 손으로 검증해봅니다.

[source,python]
----
import numpy as np

robot_world_R = robot_rotation.as_matrix()
robot_world_t = np.array([1.0, 0.0, 0.0])
camera_local_t = np.array([0.2, 0.0, 0.3])

camera_world_t = robot_world_R @ camera_local_t + robot_world_t
print("camera world position:", camera_world_t)
expected = np.array([1.0 + 0.2 / np.sqrt(2), 0.2 / np.sqrt(2), 0.3])
assert np.allclose(camera_world_t, expected, atol=1e-10)
----

`camera_world_t = R·(로컬 위치) + t`는 앞선 멀티뷰 기하 책에서 다룬 외부 파라미터 공식과 똑같은 강체 변환입니다 — 부모 프레임에 자식을 붙이는 것은 결국 "부모의 `(R, t)`를 자식의 로컬 좌표에 적용해 세계 좌표를 얻는다"는 강체 변환의 합성입니다. z축 기준 45도 회전이 로컬 x축(전방)을 세계 좌표계에서 대각선 방향으로 돌려놓았기 때문에, 카메라의 세계 좌표 `x`와 `y` 모두 로봇 위치에서 `0.2/√2`만큼씩 어긋난 값이 나옵니다. `z` 값은 회전축이 z축이라 영향을 받지 않고 로컬 값 `0.3`이 그대로 더해집니다.

== 직접 해보기

* 로봇이 z축 기준 `90`도 회전했을 때, 로컬 좌표 `(0.2, 0.0, 0.3)`에 달린 카메라의 세계 좌표를 손으로 예측해보고 코드로 확인해보세요.

.해답 보기
[%collapsible]
====
[source,python]
----
robot_rotation_90 = Rotation.from_euler("z", 90, degrees=True)
R90 = robot_rotation_90.as_matrix()
camera_world_90 = R90 @ camera_local_t + robot_world_t
print(camera_world_90)  # [1. 0.2 0.3]
assert np.allclose(camera_world_90, [1.0, 0.2, 0.3], atol=1e-10)
----

z축 기준 90도 회전은 로컬 x축을 세계 y축으로 완전히 돌려놓습니다. 그래서 로컬 `x=0.2`가 세계 `y=0.2`로 그대로 옮겨가고, 세계 `x`는 로봇 위치 `1.0`에서 변하지 않습니다 — `z=0.3`은 이번에도 회전과 무관하게 그대로 유지됩니다.

== 요약

* `add_frame(name, wxyz, position)`은 씬에 좌표축을 그리고, Viser는 쿼터니언을 `(w, x, y, z)` 순서로 받습니다.
* 이름의 슬래시 경로(`/robot/camera`)가 씬 트리의 부모-자식 관계를 정의하고, 자식의 `position`/`wxyz`는 부모 기준 로컬 좌표입니다.
* 부모 프레임을 움직이면 그 하위 트리 전체가 함께 움직입니다 — 이는 `X_world = R·X_local + t` 강체 변환을 계층적으로 합성한 것과 같습니다.
