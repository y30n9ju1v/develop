4장에서는 "지금 관측한 게 몇 번 랜드마크인지 이미 안다"고 가정했습니다. 실전에서는 센서가 "저기 뭔가 보인다"고만 알려줄 뿐, 그게 지도에 이미 있는 랜드마크 중 무엇인지, 아니면 처음 보는 새 랜드마크인지는 로봇이 스스로 판단해야 합니다. 이 판단이 틀리면 — 서로 다른 두 랜드마크의 관측을 하나로 착각하면 — SLAM 전체가 오염됩니다. 이 장에서는 이 판단(데이터 연관)을 확률적으로 하는 표준 방법과, 그게 실패하는 지점을 직접 확인합니다.

== 마할라노비스 거리: "확률적으로 얼마나 가까운가"

두 점 사이의 유클리드 거리는 불확실성을 무시합니다. 마할라노비스 거리는 "이 관측이 이 랜드마크의 예측 위치에서, 그 불확실성을 감안하면 얼마나 그럴듯한가"를 잽니다.

[source,python]
----
def mahalanobis_distance(mu, Sigma, z, landmark_idx, R, dim):
    landmark = mu[3+2*landmark_idx : 3+2*landmark_idx+2]
    z_pred = measurement_model(mu[:3], landmark)
    y = z - z_pred
    y[1] = wrap_angle(y[1])
    H = measurement_jacobian_full(mu, landmark_idx, dim)
    S = H @ Sigma @ H.T + R          # 잔차의 공분산 (3장의 EKF 갱신에서 이미 계산하던 바로 그 S)
    return y @ np.linalg.inv(S) @ y   # y^T S^-1 y
----

이 값은 3장·4장의 EKF 갱신에서 이미 계산하고 있던 `S`(잔차의 공분산)를 그대로 재사용합니다 — 불확실성이 큰 방향(예: 로봇에서 멀리 있어 range 오차가 큰 랜드마크)으로는 같은 유클리드 거리라도 마할라노비스 거리가 작게 나옵니다.

== 최근접 이웃 연관과 게이팅

[source,python]
----
def associate(mu, Sigma, z, n_landmarks, R, dim, gate=9.21):
    dists = [mahalanobis_distance(mu, Sigma, z, li, R, dim) for li in range(n_landmarks)]
    best = int(np.argmin(dists))
    if dists[best] > gate:
        return None   # 어떤 기존 랜드마크와도 충분히 가깝지 않음 -> 새 랜드마크 후보
    return best
----

가장 마할라노비스 거리가 작은 랜드마크를 고르되, 그 거리조차 `gate`(문턱값)를 넘으면 "기존 랜드마크 중 아무것도 아니다"로 판정해 새 랜드마크 후보로 남겨둡니다. `gate=9.21`은 2차원 관측에서 카이제곱 분포의 `99%` 신뢰구간에 해당하는 값입니다 — 통계적으로 "정말 다른 랜드마크일 가능성이 `99%`"라는 기준입니다.

== 검증 1: 랜드마크가 떨어져 있으면 연관은 거의 완벽하다

[source,python]
----
true_landmarks = np.array([[5.0, 5.0], [-5.0, 5.0], [-5.0, -5.0], [5.0, -5.0]])
# 랜드마크 위치를 정확히 안다고 가정하고(연관 로직만 검증), 50번 무작위 관측
correct = 0
for trial in range(50):
    li_true = rng.integers(0, 4)
    z = measurement_model(mu[:3], true_landmarks[li_true]) + noise
    li_assoc = associate(mu, Sigma, z, 4, R_meas, dim)
    correct += (li_assoc == li_true)
print(correct)   # 50/50
----

네 랜드마크가 서로 `10m` 이상 떨어져 있는 이 설정에서는 `50`번 모두 올바르게 연관됩니다 — 센서 노이즈 수준(`R_meas`)에 비해 랜드마크 사이 거리가 훨씬 커서, 어느 랜드마크에서 온 관측인지 헷갈릴 여지가 없습니다.

== 검증 2: 랜드마크가 가까이 있으면 진짜로 헷갈린다

이번엔 랜드마크 두 개(`0`번과 `1`번)를 `0.36m`밖에 안 떨어지게 배치합니다.

[source,python]
----
close_landmarks = np.array([[5.0, 5.0], [5.3, 5.2], [-5.0, -5.0], [5.0, -5.0]])

correct_close = 0
ambiguous_count = 0
for trial in range(50):
    li_true = rng.choice([0, 1])   # 헷갈리는 두 랜드마크 중 하나를 관측
    z = measurement_model(mu2[:3], close_landmarks[li_true]) + noise
    li_assoc = associate(mu2, Sigma2, z, 4, R_meas, dim)
    correct_close += (li_assoc == li_true)
    if li_assoc in (0, 1) and li_assoc != li_true:
        ambiguous_count += 1
print(correct_close, ambiguous_count)
----

[source]
----
correct association: 34/50 (landmarks close together), misassociated: 16
----

`50`번 중 `16`번(`32%`)이 실제로 잘못 연관됐습니다 — 센서 노이즈(`range` 표준편차 `0.3`)가 두 랜드마크 사이 거리(`0.36`)와 비슷한 수준이라, 통계적으로 어느 쪽에서 온 관측인지 판별하기 어려운 상황을 인위적으로 만든 것입니다.

== 검증 3: 잘못된 연관이 실제로 지도를 오염시키는가

[source,python]
----
z_true1 = measurement_model(mu3[:3], close_landmarks[1])   # 실제로는 랜드마크 1을 관측
z1 = z_true1 + noise

# 실수로 랜드마크 0으로 잘못 연관됐다고 가정하고 그대로 갱신
mu3_wrong, _ = slam_update(mu3, Sigma3, z1, 0, R_meas, dim)
err_landmark0 = np.linalg.norm(mu3_wrong[3:5] - close_landmarks[0])

# 올바르게 랜드마크 1로 연관했을 때와 비교
mu3_right, _ = slam_update(mu3, Sigma3, z1, 1, R_meas, dim)
err_landmark1_right = np.linalg.norm(mu3_right[5:7] - close_landmarks[1])
print(err_landmark0, err_landmark1_right)
----

[source]
----
landmark 0 error after being updated with landmark 1's observation: 0.082
landmark 1 error after correct association: 0.011
----

랜드마크 `1`의 관측을 랜드마크 `0`으로 착각해서 갱신하면, 랜드마크 `0`의 위치 추정 오차(`0.082`)가 올바르게 연관했을 때의 오차(`0.011`)보다 `7`배 이상 커집니다 — 랜드마크 `1`의 실제 위치 쪽으로 랜드마크 `0`의 추정치가 끌려갔기 때문입니다. 이게 딱 한 번의 오연관이지만, SLAM이 수백~수천 번의 관측을 처리하는 실전에서는 이런 오연관이 누적되면 지도 전체가 서서히, 그러나 되돌릴 수 없이 뒤틀립니다 — 한번 잘못 갱신된 랜드마크 위치는 EKF 안에서 스스로 고쳐지지 않습니다.

== 왜 이게 SLAM에서 특히 어려운 문제인가

이 예제에서는 랜드마크의 "진짜" 위치를 알고 있었지만, 실전 SLAM에서는 랜드마크 위치 자체가 추정 중이라 더 불확실합니다 — 로봇이 막 탐험을 시작해 자기 위치도 불확실한 초반에는, 그 불확실성이 랜드마크 추정에도 그대로 전파되어(4장에서 확인한 상관관계) 데이터 연관이 훨씬 더 어려워집니다. 게다가 실제 환경에는 진짜 새 랜드마크(처음 보는 물체)와 지도에 이미 있는 랜드마크가 섞여 있어서, "게이트를 넘었으니 새 랜드마크"라는 판단도 완벽하지 않습니다 — 애매한 경우 아예 그 관측을 버리는(모든 갱신을 보류하는) 보수적인 전략이 실전에서 흔히 쓰입니다.

== 직접 해보기

* `gate` 값을 `9.21`(`99%` 신뢰구간)에서 `3.0`(훨씬 엄격한 기준)으로 낮추면, 검증 2의 오연관 횟수(`16/50`)가 어떻게 바뀌는지, 그리고 "새 랜드마크"로 잘못 분류되는(`None` 반환) 횟수는 얼마나 늘어나는지 확인해보세요.

[source,python]
----
strict_ambiguous = 0
strict_none = 0
for trial in range(50):
    li_true = rng.choice([0, 1])
    z = measurement_model(mu2[:3], close_landmarks[li_true]) + noise
    li_assoc = associate(mu2, Sigma2, z, 4, R_meas, dim, gate=3.0)
    if li_assoc is None:
        strict_none += 1
    elif li_assoc != li_true:
        strict_ambiguous += 1
print(strict_ambiguous, strict_none)
----

`gate`를 낮추면 애매한 관측을 "새 랜드마크 후보"(`None`)로 더 자주 분류하게 되어, 잘못된 기존 랜드마크로 오연관되는 횟수(`ambiguous`)는 줄어듭니다. 하지만 그 대가로 실제로는 기존 랜드마크인데 새 랜드마크로 잘못 판단하는 경우도 늘어나서, 지도에 같은 물리적 랜드마크가 여러 개의 서로 다른 "가짜 랜드마크"로 중복 생성되는 문제가 생길 수 있습니다 — `gate` 값은 "잘못된 기존 랜드마크로 오염시키는 위험"과 "같은 랜드마크를 중복 생성하는 위험" 사이의 트레이드오프를 조절하는 손잡이입니다.

== 요약

* 마할라노비스 거리는 잔차의 불확실성(`S`)까지 고려해 "이 관측이 이 랜드마크일 확률적 그럴듯함"을 재고, EKF 갱신에서 이미 계산하는 `S`를 그대로 재사용할 수 있습니다.
* 최근접 이웃 연관에 게이팅(문턱값)을 더해, 어떤 기존 랜드마크와도 충분히 가깝지 않은 관측은 새 랜드마크 후보로 분류합니다.
* 랜드마크가 충분히 떨어져 있으면 연관이 거의 완벽했지만, 센서 노이즈 수준으로 가까이 있으면 `32%`가 잘못 연관되는 걸 직접 확인했습니다.
* 잘못된 연관을 그대로 SLAM 갱신에 쓰면 잘못된 랜드마크의 추정치가 실제 위치에서 멀어지며 지도가 오염되고, 이 오염은 EKF 안에서 스스로 고쳐지지 않습니다.

다음 장에서는 EKF-SLAM 자체의 근본적인 한계 — 이 근사가 결국 필터를 실제보다 과신하게 만드는 일관성 문제와, 랜드마크가 많아질수록 계산량이 감당할 수 없이 커지는 문제 — 를 다루며 2부를 마무리합니다.
