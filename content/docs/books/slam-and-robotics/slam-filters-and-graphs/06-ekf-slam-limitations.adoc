'''

4~5장에서 EKF-SLAM을 구현하고, 데이터 연관 실패가 지도를 오염시킬 수 있다는 걸 봤습니다. 이 장에서는 데이터 연관이 완벽하더라도 EKF-SLAM 자체가 가진 두 가지 근본적인 한계를 다룹니다 — 필터가 스스로 보고하는 불확실성이 실제 오차보다 낙관적일 수 있다는 **일관성** 문제, 그리고 랜드마크가 늘어날수록 감당할 수 없이 커지는 **계산 복잡도** 문제입니다.

== 일관성이란 무엇인가

필터는 매 순간 "내 추정 오차의 공분산은 이만큼이다"(`Sigma`)라고 스스로 보고합니다. **일관적인(consistent)** 필터란, 이 자체 보고가 실제 오차와 통계적으로 맞아떨어지는 필터입니다 — 예컨대 `Sigma`가 "오차가 `±0.5m` 안에 있을 확률이 `95%`"라고 말했다면, 실제로도 대략 그 정도 확률로 맞아야 합니다. EKF의 국소 선형화 근사는 이 약속을 깨뜨릴 수 있습니다 — 비선형성이 강할수록 필터가 실제보다 더 확신하게(과신, overconfident) 되는 경향이 있습니다.

== NEES: 일관성을 재는 숫자

정규화 추정오차제곱(Normalized Estimation Error Squared, NEES)은 "실제 오차가 필터가 보고한 불확실성에 비해 얼마나 큰가"를 하나의 숫자로 잽니다.

[source,python]
----
err = mu[:3] - true_pose               # 실제 오차 (필터 추정 - 참값)
err[2] = wrap_angle(err[2])
nees = err @ np.linalg.inv(Sigma[:3,:3]) @ err
----

`err`을 `Sigma`(필터가 보고한 불확실성)로 "정규화"한 것입니다 — 필터가 정확히 일관적이라면, `3`차원 상태(로봇 포즈)에서 NEES의 기댓값은 정확히 `3`(자유도)이 됩니다. 필터가 실제 오차를 과소평가(과신)하고 있다면 NEES는 `3`보다 뚜렷하게 커집니다.

== 실험: 회전이 급할수록, 프로세스 노이즈를 과소평가할수록 일관성이 나빠지는가

두 조건을 비교합니다 — (1) 완만한 회전(`w=0.2`)에 필터의 프로세스 노이즈(`Q`)를 실제와 맞게 설정한 경우, (2) 급격한 회전(`w=1.5`, 매 스텝 더 큰 각도를 회전해 선형화 오차가 커짐)에 `Q`를 실제의 `1/10`로 **과소평가**한 경우(로봇이 명령을 실제로 얼마나 못 따르는지 필터가 알고 있는 것보다 낙관적으로 가정한, 실전에서 매우 흔한 잘못된 튜닝입니다).

[source,python]
----
nees_normal = []  # w=0.2, Q_scale=1.0 (제대로 튜닝)
nees_high = []    # w=1.5, Q_scale=0.1 (급회전 + Q 과소평가)
# ... 30번의 독립 시행, 각 150스텝
----

[source]
----
mean NEES (low nonlinearity, well-tuned Q):  1.87
mean NEES (high nonlinearity, Q underestimated): 4.81
expected NEES if consistent: 3.0

fraction of NEES > 7.81 (95% 신뢰구간 문턱값):
  low:  0.98%   (기대치 5%보다 낮음 -- 오히려 다소 보수적)
  high: 18.3%   (기대치 5%의 거의 4배)
----

일관적인 필터라면 NEES가 `7.81`(카이제곱(3) 분포의 `95%` 지점)을 넘는 비율이 대략 `5%`여야 합니다. 제대로 튜닝된 조건(`low`)은 오히려 `0.98%`로 다소 보수적인(실제보다 불확실성을 크게 보는) 편이지만, 급회전과 `Q` 과소평가가 겹친 조건(`high`)은 `18.3%` — 기대치의 거의 `4`배에 달합니다. 이건 실제 오차가 필터의 자체 보고(`Sigma`)보다 자주, 그리고 크게 벗어난다는 뜻입니다 — **필터가 실제로는 확신할 근거가 부족한데도 확신하고 있는** 상태입니다.

== 왜 과신이 위험한가

과신하는 필터는 위험합니다 — 칼만 이득(`K`)이 `Sigma`에 비례해서 계산되므로(2~4장에서 계속 봤듯), `Sigma`를 실제보다 작게 보고하는 필터는 새 측정값을 실제로 필요한 만큼 신뢰하지 않고, 자기 자신의 (틀렸을 수도 있는) 기존 추정을 과도하게 고집합니다. 한번 틀어진 추정이 스스로 고쳐지기 더 어려워지는 악순환입니다 — 이게 EKF-SLAM이 실전에서 "그럴듯하게 잘 작동하다가, 특정 조건(급회전, 빠른 이동)에서 갑자기 무너지는" 현상의 근본 원인 중 하나입니다.

== 두 번째 한계: 계산 복잡도

EKF-SLAM의 상태 벡터는 로봇 포즈 `3`개 + 랜드마크마다 `2`개씩입니다. 공분산 행렬 `Sigma`는 이 상태 벡터 크기의 **제곱**에 비례하는 원소를 가지므로, 갱신 한 번(`Sigma @ H.T`, `H @ Sigma @ H.T` 등 행렬 곱)의 계산량도 랜드마크 수의 제곱에 비례해서 늘어납니다.

[source,python]
----
landmark_counts = [5, 20, 50, 100, 200]
for n_lm in landmark_counts:
    dim = 3 + 2*n_lm
    # ... 갱신 한 번의 시간을 20회 측정해 중앙값을 취함
    print(n_lm, dim, median_time)
----

[source]
----
n_landmarks=   5  dim=  13  median update time=0.0181 ms
n_landmarks=  20  dim=  43  median update time=0.0255 ms
n_landmarks=  50  dim= 103  median update time=0.0504 ms
n_landmarks= 100  dim= 203  median update time=0.1568 ms
n_landmarks= 200  dim= 403  median update time=0.8053 ms
----

[source,python]
----
ratio_landmarks = 200 / 50   # 4배
ratio_time = 0.8053 / 0.0504  # 16.0배
----

랜드마크 수를 `50`에서 `200`으로 `4`배 늘리니, 갱신 한 번에 걸리는 시간이 정확히 `16`배(`4²`) 늘었습니다 — `O(n²)`라는 이론적 예측과 실측이 정확히 일치합니다. 랜드마크가 `200`개면 그럭저럭 버틸 만하지만, 실제 라이다 기반 SLAM이 다루는 랜드마크(특징점) 수는 수천~수만 개에 달합니다 — `n=10,000`이면 `n=200`일 때보다 `2,500`배 느려진다는 뜻이고, 이는 실시간 SLAM에서 감당할 수 없는 수준입니다.

== 이 두 한계가 SLAM 역사를 이끈 방향

EKF-SLAM의 이 두 한계(과신 가능성, `O(n²)` 계산량)가, 로봇공학 커뮤니티가 다른 패러다임을 찾아 나선 직접적인 이유입니다. 3부에서 다룰 파티클 필터/FastSLAM은 계산 복잡도 문제를 랜드마크별로 독립적인 서브필터로 분해해서 `O(n)`에 가깝게 줄이고, 4부에서 다룰 그래프 기반 SLAM은 애초에 모든 시점의 포즈를 하나의 큰 최적화 문제로 미뤄뒀다가 필요할 때만 한꺼번에(그리고 희소 행렬 구조를 활용해 효율적으로) 풀어서, 매 스텝 전체 공분산을 유지해야 하는 부담 자체를 없앱니다.

== 직접 해보기

* `Q_scale`을 `0.1`(과소평가)이 아니라 `10.0`(과대평가, 필터가 실제보다 로봇의 움직임을 훨씬 못 믿는 경우)으로 바꾸면, NEES가 어떻게 달라지는지 확인해보세요.

.해답 보기
[%collapsible]
====
[source,python]
----
nees_over = np.concatenate([run_one_trial(rng, high_nonlinearity=False, Q_scale=10.0) for _ in range(30)])
print(nees_over.mean(), (nees_over > 7.81).mean())
----

`Q`를 과대평가하면(필터가 로봇의 실제 움직임보다 훨씬 불확실하다고 가정하면), 필터는 반대 방향으로 치우칩니다 — 매 예측마다 `Sigma`를 필요 이상으로 크게 부풀리므로, NEES 평균이 `3`보다 오히려 작아지는(과소신, underconfident) 경향을 보이게 됩니다. 과신은 위험하지만(존재하지 않는 확신으로 잘못된 추정을 고집), 과소신은 비효율적입니다(실제로는 꽤 정확한 추정인데도 불필요하게 불확실하다고 취급해, 이후 관측을 과도하게 반영하며 노이즈에 민감해집니다). `Q` 튜닝은 이 두 극단 사이에서 실제 시스템의 노이즈 특성과 최대한 가깝게 맞추는 작업입니다.
====

== 요약

* NEES(정규화 추정오차제곱)는 필터가 스스로 보고하는 불확실성이 실제 오차와 통계적으로 맞아떨어지는지(일관성)를 재는 지표이며, 일관적인 필터라면 그 기댓값이 상태의 자유도와 같아야 합니다.
* 급격한 회전(선형화 오차 증가)과 프로세스 노이즈 과소평가가 겹치면, EKF-SLAM의 NEES가 기댓값의 `1.6`배로 뛰고 `95%` 신뢰구간을 넘는 비율이 기대치의 거의 `4`배가 되는 뚜렷한 과신을 직접 확인했습니다.
* EKF-SLAM의 갱신 계산량은 랜드마크 수의 제곱(`O(n²)`)에 비례하며, 랜드마크를 `4`배 늘리면 시간이 정확히 `16`배 늘어나는 것을 실측으로 확인했습니다.
* 이 두 한계(과신 가능성, `O(n²)` 계산량)가 SLAM 커뮤니티를 파티클 필터와 그래프 기반 SLAM이라는 다른 패러다임으로 이끈 근본적인 이유입니다.

2부에서 EKF 기반 SLAM의 원리와 한계를 모두 다졌습니다. 3부에서는 첫 번째 대안 패러다임 — 가우시안이라는 제약 자체를 버리고 수많은 가상의 가설(파티클)로 분포를 표현하는 파티클 필터를 다룹니다.
