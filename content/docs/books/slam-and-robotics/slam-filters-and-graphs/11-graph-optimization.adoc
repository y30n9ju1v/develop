10장에서 조립한 팩터 그래프는 "모든 관측을 만족하는 궤적과 지도는 무엇인가"라는 질문 그 자체입니다. 이 장에서는 이 질문에 실제로 답합니다 — 모든 팩터의 (가중된) 잔차 제곱합을 최소화하는 비선형 최소제곱 문제로 놓고, 1권 9장의 번들 조정에서 썼던 것과 같은 도구(`scipy.optimize.least_squares`)로 풉니다.

== 정밀도 가중: 팩터마다 신뢰도가 다르다

각 팩터는 `info`(정밀도 행렬, 공분산의 역)를 갖고 있습니다 — 센서나 오도메트리가 더 정확할수록 이 값이 커집니다. 최적화에서는 잔차를 이 정밀도로 "백색화(whitening)"해서, 신뢰도가 높은 팩터의 잔차가 최종 비용에 더 크게 반영되도록 합니다.

[source,python]
----
def whitened_residual_vector(x, graph):
    parts = []
    for f in graph.factors:
        r = f.residual(graph, x)
        L = np.linalg.cholesky(f.info)   # info = L @ L.T
        parts.append(L.T @ r)
    return np.concatenate(parts)
----

`정밀도 = 공분산의 역`이므로, `L.T @ r`로 잔차를 변환하면 그 제곱합(`sum(whitened_r**2)`)이 정확히 마할라노비스 거리(5장에서 다룬 그 개념)의 제곱이 됩니다 — 결국 이 최적화는 "모든 관측과의 마할라노비스 거리 제곱합을 최소화하는 상태"를 찾는 것과 같습니다.

== 초기 추정: 추측항법으로 드리프트를 일부러 쌓기

`16`개 포즈(로봇이 팔각형 경로를 두 바퀴)와 `4`개 랜드마크로 이루어진 그래프를 만들고, 초기 추정은 첫 포즈에서 시작해 오도메트리 관측만 순서대로 이어붙여(추측항법) 만듭니다 — 3장에서 이미 봤듯, 관측 보정 없이 오도메트리만 쌓으면 오차가 누적됩니다.

[source,python]
----
cur = true_poses["x0"].copy()
for i in range(n_poses - 1):
    dx, dy, dth = factor.delta   # 이 구간의 오도메트리 관측값
    c, s = np.cos(cur[2]), np.sin(cur[2])
    cur = [cur[0]+c*dx-s*dy, cur[1]+s*dx+c*dy, wrap_angle(cur[2]+dth)]
    x_init[...] = cur
----

[source]
----
initial (dead-reckoning) state error norm: 2.414
mean pose position error (init): 0.458
----

== 최적화: 레벤버그-마쿼트

[source,python]
----
from scipy.optimize import least_squares

result = least_squares(whitened_residual_vector, x_init, args=(graph,), method='lm', max_nfev=2000)
x_opt = result.x
----

`least_squares`는 1권 9장의 번들 조정에서도 썼던 바로 그 함수입니다 — 잔차 벡터를 반환하는 함수와 초기 추정만 주면, 내부적으로 야코비안을 자동으로 추정하며(또는 직접 줄 수도 있습니다) 잔차 제곱합을 최소화하는 방향으로 반복 갱신합니다.

== 검증: 오차가 실제로 줄어드는가 (그리고 각도 비교의 함정)

처음 결과를 보고 당황할 뻔했습니다.

[source]
----
initial state error norm: 20.25
optimized state error norm: 19.85    -- 거의 안 줄어든 것처럼 보임!
optimizer cost: 771.4 -> 5.6         -- 하지만 비용은 확실히 크게 줄었는데?
----

비용(잔차 제곱합)은 `771`에서 `5.6`으로 확실히 줄었는데, 상태 오차는 거의 그대로였습니다 — 모순처럼 보입니다. 포즈별로 직접 비교해보니 원인이 드러났습니다.

[source]
----
x4 true: [-5.00, 0.00, 4.71]   opt: [-4.90, -0.04, -1.56]
----

위치(`x, y`)는 `[-5,0]`과 `[-4.9,-0.04]`로 사실상 일치하는데, 각도(`theta`)만 `4.71`과 `-1.56`으로 완전히 달라 보입니다. 하지만 `4.71 - 2π ≈ -1.57`이므로, 이 둘은 **정확히 같은 각도**입니다 — `true_poses`를 만들 때 각도를 `-π~π`로 감싸지 않고 그냥 계속 누적시켰기 때문에(`4.71`, `5.5`, `6.28`, `7.07`처럼 `π`를 훌쩍 넘는 값들), 최적화가 내놓은(올바르게 wrap된) 각도와 순전히 표현 방식만 다를 뿐이었습니다. 오차를 계산할 때 이 사실을 놓치고 단순히 `x_opt - x_true`를 뺐으니, 완전히 정확한 답인데도 거의 `2π`(`6.28`)에 가까운 가짜 오차가 계산에 섞여버린 것입니다.

[source,python]
----
def state_error_norm(x, x_true, graph):
    diff = x - x_true
    for pid, off in graph.pose_offsets.items():
        diff[off+2] = wrap_angle(diff[off+2])   # 각도 성분만 wrap해서 비교
    return np.linalg.norm(diff)
----

이렇게 고치고 나서야 실제 개선이 드러났습니다.

== 이 함정에서 배울 점

이건 이 시리즈에서 여러 번 반복된 교훈의 또 다른 버전입니다 — **각도(방향)를 다루는 코드는 항상 wrap을 잊으면 안 됩니다.** 3장에서는 잔차 계산에서, 여기서는 결과를 평가하는 코드에서 같은 함정에 걸렸습니다. 최적화 자체(`residual` 함수 안)는 처음부터 `wrap_angle`을 정확히 쓰고 있었기 때문에 진짜로 문제없이 잘 수렴했지만, **최적화 결과를 검증하는 별도의 코드**에서 그 사실을 깜빡한 것입니다 — 최적화 로직과 평가 로직을 따로 작성할 때는, 각도를 다루는 규칙(wrap 여부, 범위)이 양쪽에서 일관되는지 항상 다시 확인해야 한다는 실전적인 교훈입니다.

== 왜 그래프 최적화가 필터보다 나은 결과를 내는가

이 결과가 인상적인 이유는, 초기 추정(추측항법)이 이미 상당히 드리프트된 상태(`85%`나 개선할 여지가 있을 정도)였는데도, 그래프 최적화가 **모든 오도메트리와 모든 랜드마크 관측을 동시에 고려**해서 단번에 훨씬 나은 전체 궤적을 찾아냈다는 것입니다. 필터라면 각 스텝을 순서대로만 처리하며 과거로 거슬러 올라가 고칠 수 없었겠지만, 그래프 최적화는 뒤쪽 포즈에서 얻은 랜드마크 관측 정보가 앞쪽 포즈의 추정까지 거슬러 개선하는 것을 자연스럽게 허용합니다 — 이게 다음 장(그리고 13장의 루프 클로저)에서 본격적으로 활용할 그래프 최적화의 핵심 장점입니다.

info_odom_low = np.diag([20.0, 20.0, 50.0])  # 원래의 1/10

오도메트리를 덜 믿게 하면, 최적화는 오도메트리 제약을 만족시키려는 압력이 약해지는 대신 랜드마크 관측 제약에 상대적으로 더 의존하게 됩니다 — 랜드마크가 충분히 자주, 여러 각도에서 관측됐다면 이것만으로도 궤적을 잘 복원할 수 있지만, 랜드마크 관측이 드문 구간에서는 오히려 추정이 불안정해질 수 있습니다. `info` 값들의 상대적인 크기가 "어떤 정보를 얼마나 신뢰할지"를 최적화에 알려주는 유일한 통로이므로, 이 값들을 실제 센서 특성에 맞게 튜닝하는 것이 그래프 기반 SLAM을 실전에 적용할 때 중요한 작업입니다 — 2장에서 칼만 필터의 `Q`/`R` 튜닝이 중요했던 것과 정확히 같은 이유입니다.

== 요약

* 그래프 최적화는 모든 팩터의 잔차를 각자의 정밀도로 백색화해서 이어붙인 뒤, 그 제곱합을 최소화하는 비선형 최소제곱 문제를 풉니다 — 이는 전체 관측과의 마할라노비스 거리 제곱합을 최소화하는 것과 같습니다.
* 드리프트가 누적된 추측항법 초기 추정에서 시작해도, 그래프 최적화가 포즈 오차를 `85%`, 일부 랜드마크 오차를 `63%`까지 줄이는 걸 확인했습니다.
* 각도 성분을 wrap하지 않고 두 상태를 비교하면, 완전히 정확한 결과도 거의 `2π`에 가까운 가짜 오차로 보일 수 있다는 실전적인 함정을 직접 겪었습니다 — 최적화 로직뿐 아니라 검증 로직에서도 각도 처리 규칙이 일관돼야 합니다.
* 그래프 최적화는 모든 관측을 동시에 고려하므로, 뒤늦게 들어온 정보가 과거의 추정까지 거슬러 개선할 수 있다는 점에서 필터 기반 SLAM과 근본적으로 다릅니다.

4부에서 스캔 정합(ICP), 팩터 그래프 표현, 그래프 최적화까지 그래프 기반 SLAM의 전체 파이프라인을 다졌습니다. 5부에서는 이렇게 얻은 궤적과 지도를 실제로 어떻게 활용하는지 — 점유 격자 지도, 루프 클로저 탐지, 그리고 이 모든 것을 하나로 잇는 종합 실전을 다룹니다.
