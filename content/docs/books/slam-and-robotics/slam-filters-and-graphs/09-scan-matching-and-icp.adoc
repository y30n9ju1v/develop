지금까지 다룬 필터 기반 SLAM(EKF-SLAM, FastSLAM)은 랜드마크(점 하나하나)를 관측 단위로 삼았습니다. 라이다처럼 한 번에 수백 개의 점(스캔)을 쏟아내는 센서에는 다른 접근이 자연스럽습니다 — 개별 점을 랜드마크로 추적하는 대신, **두 스캔 전체를 통째로 정렬**해서 그 사이의 로봇 이동(회전+이동)을 추정하는 것입니다. 이 장에서 다루는 ICP(Iterative Closest Point)가 이 스캔 매칭의 표준 알고리즘입니다.

== 문제: 두 점군 사이의 강체 변환 찾기

로봇이 어떤 방에서 라이다 스캔 하나(`scan1`)를 찍고, 조금 이동한 뒤 또 스캔(`scan2`)을 찍었습니다. 두 스캔은 같은 벽을 서로 다른 위치·각도에서 본 것이므로, `scan2`를 적절히 회전·이동시키면 `scan1`과 거의 겹쳐야 합니다. 문제는 **어느 점이 어느 점에 대응하는지 모른다**는 것입니다 — 이게 1권에서 다룬 특징점 매칭과 근본적으로 다른 점입니다. 특징점은 고유한 특징으로 대응을 찾지만, 라이다 점은 벽 위의 그냥 한 점이라 서로 구별이 안 됩니다.

== ICP의 핵심 아이디어: 대응을 모르면, 일단 가장 가까운 점으로 가정한다

[source,python]
----
from scipy.spatial import cKDTree

def icp(source, target, max_iters=50, tol=1e-7):
    src = source.copy()
    R_total, t_total = np.eye(2), np.zeros(2)
    tree = cKDTree(target)
    for it in range(max_iters):
        dists, idx = tree.query(src)              # (1) 각 소스 점에서 가장 가까운 타깃 점을 대응으로 가정
        matched_target = target[idx]
        # ... (2) 이 (틀릴 수도 있는) 대응으로 최적 변환을 구함
        # ... (3) 그 변환을 적용하고 반복
----

ICP의 이름 그대로입니다 — "가장 가까운 점"을 잠정적인 대응으로 삼고, 그 대응 아래서 최적의 정렬을 구한 뒤, 정렬이 나아지면 대응도 더 정확해지므로 다시 가장 가까운 점을 찾는 과정을 반복합니다. 1권 6장의 k-d 트리(`scipy.spatial.cKDTree`)를 여기서도 그대로 재사용해서, "가장 가까운 점 찾기"를 효율적으로 합니다.

== 최적 변환 구하기: 1권의 SVD 정합을 재사용

대응이 주어졌을 때 "이 대응을 가장 잘 만족하는 회전·이동은 무엇인가"는, 1권 9장의 번들 조정에서도 잠깐 다뤘던 절차 정합(Procrustes) 문제입니다.

[source,python]
----
src_mean, tgt_mean = src.mean(axis=0), matched_target.mean(axis=0)
src_centered = src - src_mean
tgt_centered = matched_target - tgt_mean
H = src_centered.T @ tgt_centered
U, S, Vt = np.linalg.svd(H)
R = Vt.T @ U.T
if np.linalg.det(R) < 0:      # 반사(reflection)가 나오면 안 되므로 방지
    Vt[-1, :] *= -1
    R = Vt.T @ U.T
t = tgt_mean - R @ src_mean
----

두 점군을 각자의 중심으로 옮긴 뒤, 그 교차공분산 `H`를 SVD로 분해해서 최적 회전을 구하는 절차입니다 — 이 시리즈의 1권(카메라 포즈 복원)에서도 SVD가 "최적의 강체 변환을 찾는" 도구로 반복해서 등장했는데, 여기서도 같은 역할을 합니다.

== 검증: 알려진 변환을 정확히 복원하는가

`scan1`을 알려진 회전(`0.3`라디안)과 이동(`[0.5, -0.3]`)으로 변형해 `scan2`를 인위적으로 만들고, ICP가 이 변환을 되찾을 수 있는지 확인합니다.

[source,python]
----
R_true = rotation_matrix(0.3)
scan2 = rigid_transform(scan1, R_true, [0.5, -0.3]) + noise

R_est, t_est, errors, n_iters = icp(scan2, scan1)
theta_recovered = np.arctan2(R_recovered_inv[1,0], R_recovered_inv[0,0])
print(theta_recovered, t_recovered_inv)
----

----

`21`번의 반복 만에 회전은 소수점 셋째 자리까지, 이동은 `0.005` 이내로 정확히 복원됐습니다. 오차(각 점과 가장 가까운 대응점 사이의 평균 거리)도 `0.458`에서 `0.024`까지 매끄럽게 줄어듭니다.

== 검증: 오차가 정말로 단조 감소하는가

[source,python]
----
for i in range(1, len(errors)):
    assert errors[i] <= errors[i-1] + 1e-9
----

ICP의 이론적으로 보장된 성질 하나가 바로 이것입니다 — 각 반복(최근접점 재계산 + SVD 재정합)이 정렬 오차를 절대 악화시키지 않습니다(같은 대응 아래서 SVD가 찾는 변환이 그 오차를 최소화하는 정확한 해이기 때문입니다). 실제로 `50`번의 반복 전체에서 오차가 단 한 번도 이전 값보다 커지지 않았습니다.

== 실패 사례: 큰 초기 오정렬은 지역최적해에 빠진다

이번엔 `scan1`을 거의 `180°`(`π - 0.1`)만큼 회전시켜 `scan2`를 만듭니다. 이 방은 직사각형이라 좌우·상하로 어느 정도 대칭적입니다.

[source,python]
----
true_theta_big = np.pi - 0.1
R_est_big, t_est_big, errors_big, _ = icp(scan2b, scan1b)
theta_est_big = np.arctan2(R_est_big[1,0], R_est_big[0,0])
----

[source]
----
true (inverse) theta: -3.04    recovered: 0.108
angle error: 3.13   (거의 pi -- 완전히 다른 회전으로 수렴)
----

ICP가 찾은 회전(`0.108`)은 실제 정답(`-3.04`)과 `π`에 가까운 차이가 날 만큼 완전히 다릅니다. 왜 이런 일이 생길까요 — ICP는 매 반복 "지금 위치에서 가장 가까운 점"만 보고 판단하는 **지역적인** 방법입니다. 초기 정렬이 크게 어긋난 상태(`180°` 근처)에서 시작하면, "가장 가까운 점" 대응 자체가 처음부터 완전히 잘못 잡히고(예: 왼쪽 벽의 점이 원래 오른쪽 벽에 대응해야 하는데, 지금 당장 가까운 반대쪽 벽에 잘못 대응됨), 이후로는 그 잘못된 대응을 계속 "정답"처럼 여기고 국소적으로만 개선해 나가다가, 오차가 줄어드는(하지만 전역적으로는 틀린) 어떤 지점에 갇혀버립니다.

== 왜 이게 실전에서 중요한가

ICP는 "이미 대략 맞는 근처에서 시작하면" 매우 정확하고 안정적이지만, 초기 추정이 크게 틀리면 이번 실험처럼 완전히 엉뚱한 결과를 그럴듯하게(오차가 계속 줄어드는 것처럼 보이면서) 내놓을 수 있습니다. 실전 SLAM에서는 그래서 ICP를 실행하기 전에 좋은 초기 추정을 마련하는 게 필수입니다 — 오도메트리(바퀴 회전수로 추정한 대략적인 이동)나, 3장의 EKF 예측값을 초기 추정으로 사용하는 게 흔한 방법입니다. 다음 장에서 다룰 팩터 그래프에서도, ICP로 얻은 스캔 정합 결과를 "제약 조건" 하나로 사용하게 되는데, 이런 지역최적해에 빠진 잘못된 정합이 섞여 들어가면 전체 그래프가 오염될 수 있다는 걸 염두에 둬야 합니다.

== 직접 해보기

* 초기 회전 오차를 `π - 0.1`이 아니라 `π/2`(`90°`)로 줄이면, ICP가 성공하는지 실패하는지 확인해보세요. 성공과 실패의 경계가 대략 어디쯤인지 감을 잡아보세요.

.해답 보기

[source,python]
----
for test_theta in [np.pi/6, np.pi/4, np.pi/3, np.pi/2, 2*np.pi/3]:
    R_true_t = rotation_matrix(test_theta)
    scan2_t = rigid_transform(scan1b, R_true_t, [0.1,0.1]) + rng.normal(0,0.02,scan1b.shape)
    R_est_t, t_est_t, _, _ = icp(scan2_t, scan1b)
    theta_est_t = np.arctan2(R_est_t[1,0], R_est_t[0,0])
    angle_err = abs(((theta_est_t - (-test_theta)) + np.pi) % (2*np.pi) - np.pi)
    print(f"{test_theta:.2f}: angle_error={angle_err:.3f}")
----

회전 오차가 작을 때(`30°`, `45°` 근처)는 대부분 성공하지만, `90°`를 넘어서면서부터 실패 확률이 눈에 띄게 늘어나는 경향을 보일 것입니다 — 정확한 경계는 방의 형태와 노이즈 수준에 따라 다르지만, "초기 오차가 클수록 위험하다"는 정성적인 경향 자체는 이 실험에서도 일관되게 나타납니다. 이게 바로 ICP가 "지역(local)" 정합 방법이라 불리는 이유이고, 5장에서 다룬 EKF-SLAM의 데이터 연관 문제와 본질적으로 같은 종류의 함정(그럴듯해 보이지만 틀린 대응에 갇히는 것)입니다.

== 요약

* ICP는 두 점군 사이의 대응을 모를 때, "가장 가까운 점"을 잠정 대응으로 삼아 최적 정렬(SVD 기반)을 구하고, 그 정렬로 대응을 다시 찾는 과정을 반복해서 수렴시킵니다.
* 알려진 회전·이동으로 검증했을 때, `21`번의 반복만으로 회전은 소수점 셋째 자리까지 정확히 복원됐고, 정렬 오차가 매 반복 단조 감소한다는 이론적 성질도 직접 확인했습니다.
* 초기 정렬이 크게(`180°` 근처) 어긋나면, 대칭적인 환경 구조 때문에 ICP가 완전히 잘못된 지역최적해에 빠질 수 있다는 걸 실증했습니다.
* 좋은 초기 추정(오도메트리, 필터 예측값)을 마련하는 것이 ICP를 안전하게 쓰기 위한 전제 조건입니다.
