'''
수학에는 어떤 대상들이 서로 '같다'고 말하는 여러 방법이 있습니다. 가장 엄격한 기준은 *동등성(equality)*입니다. 두 대상 사이에 어떠한 차이도 발견할 수 없을 때, 우리는 둘이 같다고 말합니다. 이 경우 하나를 다른 하나로 상상 가능한 모든 맥락에서 자유롭게 대체할 수 있습니다. 예를 들어, 가환 다이어그램(commuting diagram)을 다룰 때마다 우리는 모피즘의 동등성을 사용해 왔습니다. 모피즘들은 홈 집합(hom-set)을 형성하고, 집합의 원소는 동등성 비교가 가능하기 때문입니다.

하지만 동등성은 때로 너무 엄격한 기준입니다. 실질적인 목적에서는 동일하지만 엄밀히는 같지 않은 경우가 얼마든지 있기 때문입니다. 예를 들어 쌍(pair) 타입 ``(Bool, Char)``은 ``(Char, Bool)``과 엄격하게 같지는 않지만, 두 타입이 담고 있는 정보는 동일합니다. 이러한 개념을 가장 잘 포착하는 것이 바로 두 타입 사이의 *동형 모피즘(isomorphism)*입니다. 동형 모피즘은 역이 존재하는 모피즘으로, 모피즘이기에 구조를 보존하고, '동형(iso)'이기에 어느 쪽에서 시작하든 왕복했을 때 제자리로 돌아옵니다. 쌍 타입의 경우, 이러한 동형 모피즘은 ``swap``이라 불립니다.

[source,haskell]
----
swap       :: (a,b) -> (b,a)
swap (a,b) = (b,a)
----

``swap``은 흥미롭게도 자기 자신이 역함수입니다.

== 수반과 단위/코단위 쌍 (Adjunction and Unit/Counit Pair)

두 카테고리가 동형이라는 말을 함자(functor)라는 카테고리 간의 매핑으로 표현할 수 있습니다. 카테고리 C와 D가 동형이 되려면, C에서 D로 가는 가역 함자 R("오른쪽")이 존재해야 합니다. 다시 말해, D에서 C로 돌아오는 또 다른 함자 L("왼쪽")이 존재하여 R과 합성했을 때 항등 함자 I가 되어야 합니다. 이때 가능한 합성은 ``R ∘ L``과 ``L ∘ R`` 두 가지이며, 대응하는 항등 함자도 C와 D에 각각 하나씩 있습니다.

하지만 여기서 까다로운 문제가 발생합니다. 두 함자가 '같다'는 것은 정확히 무엇을 의미할까요? 다음 식에서 말하는 동등성은 무엇을 뜻할까요?

[source,haskell]
----
R ∘ L = ID
----

또는 이 식은 어떤가요?

[source,haskell]
----
L ∘ R = IC
----

객체의 동등성을 통해 함자의 동등성을 정의하는 것이 합리적으로 보일 수 있습니다. 즉, 두 함자가 같은 객체에 작용할 때 같은 객체를 만들어내야 한다는 것입니다. 하지만 일반적인 카테고리에서는 객체 사이의 동등성이라는 개념이 정의되어 있지 않습니다. 카테고리의 정의 자체에 포함되어 있지 않기 때문입니다. ('동등성이 실제로 무엇인가'라는 토끼굴 속으로 더 깊이 들어가면 결국 호모토피 타입 이론(Homotopy Type Theory)에 도달하게 됩니다.)

그렇다면 함자는 카테고리들의 카테고리(Cat)에서 모피즘이므로 동등성을 비교할 수 있어야 한다고 반론할 수도 있습니다. 실제로 객체들이 집합을 이루는 작은 카테고리(small category)의 경우, 집합 원소의 동등성을 이용해 객체를 비교할 수 있습니다.

하지만 Cat은 사실 *2-카테고리(2-category)*입니다. 2-카테고리의 홈 집합(hom-set)은 추가적인 구조를 가집니다. 바로 1-모피즘들 사이에 작용하는 2-모피즘이 존재한다는 것입니다. Cat에서 1-모피즘은 함자이고, 2-모피즘은 자연 변환(natural transformation)입니다. 따라서 함자를 다룰 때는 '동등성' 대신 *자연 동형 모피즘(natural isomorphism)*을 사용하는 것이 훨씬 자연스럽습니다 (이 언어유희는 피할 수가 없네요!).

따라서 카테고리의 동형 모피즘 대신 더 일반적인 개념인 *카테고리의 동치(equivalence of categories)*를 고려하는 것이 합리적입니다. 두 카테고리 C와 D가 동치라는 것은, 두 카테고리를 오가는 두 함자가 존재하고 이들의 합성(어느 방향이든)이 항등 함자와 자연 동형(naturally isomorphic)이라는 뜻입니다. 다시 말해 합성 ``R ∘ L``과 항등 함자 ``ID`` 사이에 양방향 자연 변환이 있고, ``L ∘ R``과 항등 함자 ``IC`` 사이에도 또 다른 양방향 자연 변환이 존재합니다.

*수반(Adjunction)*은 이 동치보다도 조건이 훨씬 느슨합니다. 두 함자의 합성이 항등 함자와 동형일 필요조차 없기 때문입니다. 대신 ``ID``에서 ``R ∘ L``로 가는 '한 방향' 자연 변환과, ``L ∘ R``에서 ``IC``로 가는 또 다른 '한 방향' 자연 변환이 존재하기만 하면 됩니다. 이 두 자연 변환의 시그니처는 다음과 같습니다.

[source,haskell]
----
η :: ID -> R ∘ L
ε :: L ∘ R -> IC
----

여기서 ``η``는 수반의 *단위(unit)*, ``ε``는 *코단위(counit)*라고 부릅니다.

이 정의의 비대칭성에 주목하세요. 일반적으로 다음의 나머지 두 매핑은 존재하지 않습니다.

[source,haskell]
----
R ∘ L -> ID -- 항상 가능한 것은 아님
IC -> L ∘ R -- 항상 가능한 것은 아님
----

이러한 비대칭성 때문에 함자 L은 함자 R의 *좌수반(left adjoint)*이라 부르고, 함자 R은 L의 *우수반(right adjoint)*이라 부릅니다. (물론 '좌'와 '우'라는 명칭은 다이어그램을 어떻게 그리느냐에 따라 달라질 수 있습니다.)

수반을 간결하게 표기하면 다음과 같습니다.

[source,haskell]
----
L ⊣ R
----

수반을 더 잘 이해하기 위해 단위와 코단위를 좀 더 자세히 분석해 봅시다.

먼저 단위부터 살펴봅시다. 단위는 자연 변환이므로 모피즘의 족(family of morphisms)입니다. 카테고리 D의 객체 ``d``가 주어지면, ``η``의 구성 요소(component)는 ``I d``(즉 ``d``)와 ``(R ∘ L) d`` 사이의 모피즘입니다. 다이어그램에서는 이를 ``d'``라고 부릅니다.

[source,haskell]
----
ηd :: d -> (R ∘ L) d
----

합성 ``R ∘ L``이 카테고리 D의 *엔도함자(endofunctor)*라는 점에 주목하세요.

이 식이 말해주는 것은, 우리가 객체 d를 임의로 선택한 후 왕복 함자 ``R ∘ L``을 이용해 대상 객체 d'를 고를 수 있다는 점입니다. 그런 다음 모피즘 ``ηd``라는 화살표를 대상 객체 쪽으로 쏩니다.

마찬가지로 코단위 ``ε``의 구성 요소는 다음과 같이 설명할 수 있습니다.

[source,haskell]
----
εc :: (L ∘ R) c -> c
----

이는 카테고리 C에서 임의의 객체 c를 종착점으로 선택하고, 왕복 함자 ``L ∘ R``을 이용해 시작 객체 ``c' = (L ∘ R) c``를 찾을 수 있다는 뜻입니다. 그런 다음 시작점 ``c'``에서 종착점 ``c``를 향해 모피즘 ``εc``라는 화살표를 쏩니다.

단위와 코단위를 바라보는 또 다른 관점도 있습니다. 단위는 D에서 항등 함자를 넣을 수 있는 곳이라면 어디든 합성 ``R ∘ L``을 도입할 수 있게 해주고, 코단위는 합성 ``L ∘ R``을 제거하여 C의 항등 함자로 대체할 수 있게 해줍니다. 이로부터 '도입한 뒤 다시 제거하면 아무것도 바뀌지 않아야 한다'는 자연스러운 일관성 조건이 도출됩니다.

[source,haskell]
----
L = L ∘ ID -> L ∘ R ∘ L -> IC ∘ L  = L
----

[source,haskell]
----
R = ID ∘ R -> R ∘ L ∘ R -> R ∘ IC = R
----

이 조건들은 다이어그램을 가환하게 만들므로 *삼각형 항등식(triangular identities)*이라 부릅니다.

이 다이어그램들은 함자 카테고리에서 그려집니다. 화살표들은 자연 변환이며, 이들의 합성은 자연 변환의 수평 합성(horizontal composition)입니다. 구성 요소별로 풀어 쓰면 다음과 같습니다.

[source,haskell]
----
ε L d ∘ L η d = id L d
R ε c ∘ η R c = id R c
----

우리는 하스켈에서 단위와 코단위를 다른 이름으로 자주 만납니다. 단위는 ``return``(또는 ``Applicative`` 정의의 ``pure``)으로 잘 알려져 있습니다.

[source,haskell]
----
return :: d -> m d
----

코단위는 ``extract``라는 이름으로 알려져 있습니다.

[source,haskell]
----
extract :: w c -> c
----

여기서 ``m``은 ``R ∘ L``에 대응하는 엔도함자이고, ``w``는 ``L ∘ R``에 대응하는 엔도함자입니다. 나중에 배우겠지만, 이들은 각각 모나드(monad)와 코모나드(comonad) 정의의 핵심 요소가 됩니다.

엔도함자를 컨테이너로 생각한다면, 단위(또는 ``return``)는 임의 타입의 값을 감싸는 기본 상자를 만드는 다형성 함수입니다. 코단위(또는 ``extract``)는 반대로 컨테이너에서 값 하나를 꺼내오거나 추출하는 역할을 합니다.

나중에 살펴보겠지만, 모든 수반 함자 쌍은 모나드와 코모나드를 정의합니다. 역으로, 모든 모나드나 코모나드는 수반 함자 쌍으로 분해(factorize)될 수 있습니다. 다만 이 분해는 유일하지 않습니다.

하스켈에서는 모나드를 매우 활발하게 사용하지만, 이를 수반 함자 쌍으로 분해하는 경우는 드뭅니다. 그렇게 해서 얻은 함자들이 대개 하스켈의 카테고리인 ``Hask``를 벗어나기 때문입니다.

그래도 하스켈에서 엔도함자들 사이의 수반을 정의하는 것은 가능합니다. ``Data.Functor.Adjunction``에서 가져온 정의의 일부는 다음과 같습니다.

[source,haskell]
----
class (Functor f, Representable u) =>
      Adjunction f u | f -> u, u -> f where
  unit         :: a -> u (f a)
  counit       :: f (u a) -> a
----

이 정의에는 약간의 설명이 필요합니다. 우선 이것은 두 개의 매개변수 ``f``와 ``u``를 가지는 다중 매개변수 타입 클래스입니다. 두 타입 생성자 사이에 ``Adjunction``이라는 관계를 설정합니다.

수직 막대(``|``) 뒤의 조건들은 *함수 종속성(functional dependency)*을 나타냅니다. 예를 들어 ``f -> u``는 ``f``가 결정되면 ``u``도 유일하게 정해진다는 뜻입니다(타입 생성자에 대한 함수). 반대로 ``u -> f``는 ``u``를 알면 ``f``가 유일하게 결정된다는 의미입니다.

하스켈에서 왜 우수반 ``u``가 자동으로 *표현 가능 함자(representable functor)*가 되어야 하는지는 잠시 후에 설명하겠습니다.

== 수반과 홈 집합 (Adjunctions and Hom-Sets)

홈 집합(hom-set)들 사이의 자연 동형 모피즘을 이용해 수반을 정의할 수도 있습니다. 이 정의는 우리가 지금까지 공부한 보편적 구성(universal construction)과 아주 잘 연결됩니다. "어떤 구성을 유일하게 분해하는 모피즘이 존재한다"는 말을 들을 때마다, 그것을 어떤 집합에서 홈 집합으로 가는 매핑이라고 생각하면 됩니다. 이것이 곧 "유일한 모피즘을 선택한다"는 말의 본질입니다.

더 나아가, 이러한 분해는 종종 자연 변환으로 설명됩니다. 분해란 어떤 모피즘이 두 모피즘(인수)의 합성과 같다는 가환 다이어그램을 동반합니다. 자연 변환은 모피즘을 가환 다이어그램으로 대응시킵니다. 따라서 보편적 구성에서는 모피즘에서 가환 다이어그램으로, 다시 유일한 모피즘으로 이동합니다. 결국 우리는 한 홈 집합에서 (대개 다른 카테고리에 있는) 다른 홈 집합으로 가는 모피즘 간 매핑을 얻게 됩니다. 이 매핑이 가역적(invertible)이며 모든 홈 집합에 대해 자연스럽게 확장될 수 있다면, 그것이 바로 수반입니다.

보편적 구성과 수반의 가장 큰 차이점은 수반이 *전역적(globally)*으로 정의된다는 점입니다. 보편적 구성을 사용하면 카테고리 내의 특정 객체 쌍에 대해서만 곱을 정의할 수 있습니다(다른 쌍에 대해서는 곱이 존재하지 않을 수 있음). 반면 우리가 곧 살펴볼 것처럼, 만약 모든 객체 쌍에 대해 곱이 존재한다면 이는 수반을 통해 깔끔하게 정의할 수 있습니다.

홈 집합을 이용한 수반의 대안적 정의는 다음과 같습니다. 이전처럼 두 함자 ``L \:: D -> C``와 ``R \:: C -> D``가 있다고 합시다. 카테고리 D에서 시작 객체 d를, C에서 대상 객체 c를 임의로 선택합니다. L을 이용해 시작 객체 d를 C로 옮기면, 이제 C 안에는 ``L d``와 ``c``라는 두 대상이 있습니다. 이들은 다음의 홈 집합을 가집니다.

[source,haskell]
----
C(L d, c)
----

마찬가지로 R을 이용해 대상 객체 c를 D로 옮기면, D 안에는 ``d``와 ``R c``라는 두 대상이 생깁니다. 이들 또한 다음의 홈 집합을 이룹니다.

[source,haskell]
----
D(d, R c)
----

L이 R의 좌수반이 되기 위한 조건은 다음의 홈 집합들 사이에 동형 모피즘이 존재하는 것입니다.

[source,haskell]
----
C(L d, c) ≅ D(d, R c)
----

이 동형 모피즘은 d와 c에 대해 자연스러워야(natural) 합니다.

여기서 자연스럽다(natural)는 말은 시작점 d가 D 안에서, 종착점 c가 C 안에서 매끄럽게 변할 수 있다는 뜻입니다. 더 정확히 말하면, C에서 Set으로 가는 다음 두 (공변) 함자 사이에 자연 변환 ``φ``가 존재한다는 의미입니다.

[source,haskell]
----
c -> C(L d, c)
c -> D(d, R c)
----

또한 다음의 (반변) 함자들 사이에는 또 다른 자연 변환 ``ψ``가 작용합니다.

[source,haskell]
----
d -> C(L d, c)
d -> D(d, R c)
----

그리고 이 두 자연 변환은 반드시 가역적이어야 합니다.

수반의 두 가지 정의가 서로 동등하다는 것을 보이기는 어렵지 않습니다. 예를 들어 홈 집합의 동형 모피즘으로부터 단위 변환을 유도해 봅시다.

[source,haskell]
----
C(L d, c) ≅ D(d, R c)
----

이 식은 임의의 객체 c에 대해 성립하므로, ``c = L d``인 경우에도 성립해야 합니다.

[source,haskell]
----
C(L d, L d) ≅ D(d, (R ∘ L) d)
----

왼쪽 홈 집합에는 적어도 하나의 모피즘, 즉 항등 모피즘(identity)이 존재합니다. 자연 변환은 이 항등 모피즘을 ``D(d, (R ∘ L) d)``의 한 원소로 보내거나, 항등 함자 I를 명시적으로 써서 ``D(I d, (R ∘ L) d)``의 모피즘으로 매핑합니다.

이렇게 해서 d에 의해 매개변수화된 모피즘들의 모임을 얻었습니다. 이들은 함자 I와 함자 ``R ∘ L`` 사이의 자연 변환을 형성하며(자연성 조건은 쉽게 확인할 수 있습니다), 이것이 바로 우리의 단위 ``η``입니다.

반대로 단위와 코단위가 존재한다고 가정하면 홈 집합 사이의 변환을 정의할 수 있습니다. 예를 들어 홈 집합 ``C(L d, c)``에서 임의의 모피즘 f를 선택해 봅시다. 우리는 f에 작용하여 ``D(d, R c)``에 속하는 모피즘을 만들어내는 ``φ``를 정의하고자 합니다.

선택지가 많지 않습니다. 먼저 R을 이용해 f를 들어올리면(lift), ``R (L d)``에서 ``R c``로 가는 모피즘 ``R f``를 얻게 되는데, 이는 ``D((R ∘ L) d, R c)``의 원소입니다.

우리가 최종적으로 얻어야 하는 것은 ``φ``의 구성 요소, 즉 d에서 ``R c``로 가는 모피즘입니다. 이는 어렵지 않습니다. 단위 ``ηd``를 사용해 d에서 ``(R ∘ L) d``로 갈 수 있기 때문입니다. 따라서 다음처럼 정의할 수 있습니다.

[source,haskell]
----
φf = R f ∘ ηd
----

다른 방향도 마찬가지이며, ``ψ``의 유도 과정 또한 유사합니다.

하스켈의 ``Adjunction`` 정의로 돌아가 보면, 자연 변환 ``φ``와 ``ψ``는 각각 다형성 함수인 ``leftAdjunct``와 ``rightAdjunct``로 대체되어 있습니다. 여기서 함자 L과 R은 각각 ``f``와 ``u``로 불립니다.

[source,haskell]
----
class (Functor f, Representable u) =>
      Adjunction f u | f -> u, u -> f where
  leftAdjunct  :: (f a -> b) -> (a -> u b)
  rightAdjunct :: (a -> u b) -> (f a -> b)
----

단위/코단위 표현과 ``leftAdjunct``/``rightAdjunct`` 표현 사이의 등가성은 다음의 관계를 통해 증명됩니다.

[source,haskell]
----
unit           = leftAdjunct id
counit         = rightAdjunct id
leftAdjunct f  = fmap f . unit
rightAdjunct f = counit . fmap f
----

카테고리 이론에서의 수반 개념이 어떻게 하스켈 코드로 번역되는지 직접 따라가 보는 것은 매우 교육적인 과정입니다. 꼭 한번 도전해 보시길 권장합니다.

이제 하스켈에서 왜 우수반이 자동으로 표현 가능 함자가 되는지 설명할 수 있습니다. 첫 번째 근사로, 하스켈 타입의 카테고리를 집합의 카테고리(Set)로 취급할 수 있기 때문입니다.

오른쪽 카테고리 D가 Set이면, 우수반 R은 C에서 Set으로 가는 함자가 됩니다. 어떤 함자가 표현 가능하려면, ``C(rep, _)``라는 hom-함자가 R과 자연 동형이 되게 하는 객체 ``rep``이 C 안에 존재해야 합니다. R이 Set에서 C로 가는 어떤 함자 L의 우수반이라면, 그러한 객체는 항상 존재합니다. 바로 단일 원소 집합 ``()``를 L로 옮긴 이미지입니다.

[source,haskell]
----
rep = L ()
----

실제로 수반은 다음 두 홈 집합이 자연 동형임을 말해줍니다.

[source,haskell]
----
C(L (), c) ≅ Set((), R c)
----

주어진 c에 대해 오른쪽 집합은 단일 원소 집합 ``()``에서 ``R c``로 가는 함수들의 집합입니다. 이전에 본 것처럼 그러한 함수 각각은 집합 ``R c``에서 원소 하나를 선택합니다. 따라서 이러한 함수들의 집합은 집합 ``R c`` 자체와 동형입니다. 그러므로 다음을 얻습니다.

[source,haskell]
----
C(L (), -) ≅ R
----

이는 R이 실제로 표현 가능함을 보여줍니다.

== 수반으로부터의 곱 (Product from Adjunction)

이전에 우리는 보편적 구성을 통해 여러 개념을 도입했습니다. 이러한 개념 중 상당수는 전역적으로 정의될 때 수반을 이용하는 편이 훨씬 표현하기 쉽습니다. 가장 간단한 비자명한(non-trivial) 예가 바로 곱(product)입니다. 곱의 보편적 구성의 핵심은, 곱처럼 생긴 모든 후보를 보편적인 곱을 통해 분해(factorize)할 수 있다는 점입니다.

더 정확히 말하면, 두 객체 a와 b의 곱 ``(a × b)``(하스켈 표기법으로는 ``(a, b)``)는 ``fst``와 ``snd``라는 두 모피즘을 갖추고 있습니다. 만약 ``p \:: c -> a``와 ``q \:: c -> b``라는 두 모피즘을 갖춘 다른 후보 객체 c가 있다면, p와 q를 각각 ``fst``와 ``snd``를 통해 분해하는 유일한 모피즘 ``m \:: c -> (a, b)``가 반드시 존재합니다.

앞서 보았듯이 하스켈에서는 이 두 사영(projection)으로부터 해당 모피즘을 생성하는 ``factorizer``를 구현할 수 있습니다.

[source,haskell]
----
factorizer :: (c -> a) -> (c -> b) -> (c -> (a, b))
factorizer p q = \x -> (p x, q x)
----

다음의 분해 조건들이 성립함을 쉽게 확인할 수 있습니다.

[source,haskell]
----
fst . factorizer p q = p
snd . factorizer p q = q
----

우리는 모피즘 쌍 (p, q)를 입력받아 새로운 모피즘 ``m = factorizer p q``를 내뱉는 매핑을 가지게 된 것입니다.

그렇다면 이를 수반 정의에 필요한 홈 집합 사이의 매핑으로 어떻게 바꿀 수 있을까요? 핵심은 Hask를 벗어나 모피즘 쌍을 *곱 카테고리(product category)*의 단일 모피즘으로 취급하는 것입니다.

잠시 곱 카테고리를 떠올려 봅시다. 임의의 두 카테고리 C와 D가 있을 때, 곱 카테고리 ``C×D``의 객체는 C의 객체와 D의 객체의 쌍이며, 모피즘 또한 각 카테고리 모피즘의 쌍입니다.

카테고리 C에서 곱을 정의하려면 곱 카테고리 ``C×C``에서 시작해야 합니다. C에서의 모피즘 쌍은 ``C×C``에서의 단일 모피즘이기 때문입니다.

곱을 정의하기 위해 곱 카테고리를 사용한다는 점이 처음에는 혼란스러울 수 있습니다. 하지만 이 둘은 매우 다른 곱입니다. 곱 카테고리를 정의하는 데는 보편적 구성이 필요 없습니다. 객체 쌍과 모피즘 쌍이라는 개념만 있으면 됩니다.

하지만 C의 객체 쌍은 C의 객체가 아닙니다. 그것은 다른 카테고리인 ``C×C``의 객체입니다. 이 쌍을 형식적으로 ``<a, b>``라고 쓸 수 있습니다. 여기서 a와 b는 C의 객체입니다. 반면 보편적 구성은 C의 객체 ``a × b``(또는 하스켈의 ``(a, b)``)를 정의하기 위해 필요합니다. 이 객체는 보편적 구성이 명시한 방식으로 쌍 ``<a, b>``를 나타내야(represent) 합니다. 이러한 객체가 항상 존재하는 것은 아니며, 어떤 쌍에 대해서는 존재하지만 다른 쌍에 대해서는 존재하지 않을 수도 있습니다.

이제 ``factorizer``를 홈 집합 간의 매핑으로 바라봅시다. 첫 번째 홈 집합은 곱 카테고리 ``C×C``에 있고, 두 번째는 C에 있습니다. ``C×C``의 일반적인 모피즘은 모피즘 쌍 ``<f, g>``입니다.

[source,haskell]
----
f :: c' -> a
g :: c'' -> b
----

여기서 ``c''``는 ``c'``와 다를 수 있습니다. 하지만 곱을 정의하기 위해 우리가 관심을 두는 것은 ``C×C``의 특별한 모피즘, 즉 동일한 시작 객체 c를 공유하는 쌍 p와 q입니다. 이는 문제없습니다. 수반의 정의에서 왼쪽 홈 집합의 시작 객체는 임의의 객체가 아니라 오른쪽 카테고리의 어떤 객체에 작용한 왼쪽 함자 L의 결과이기 때문입니다. 여기에 딱 맞는 함자는 C에서 ``C×C``로 가는 *대각선 함자(diagonal functor)*입니다. 객체에 대한 작용은 다음과 같습니다.

[source,haskell]
----
Δ c = <c, c>
----

따라서 우리의 수반에서 왼쪽 홈 집합은 다음과 같습니다.

[source,haskell]
----
(C×C)(Δ c, <a, b>)
----

이것은 곱 카테고리의 홈 집합입니다. 그 원소는 우리가 ``factorizer``의 인자로 인식하는 모피즘 쌍들입니다.

[source,haskell]
----
(c -> a) -> (c -> b) ...
----

오른쪽 홈 집합은 C에 있으며, 시작 객체 c와 어떤 함자 R이 ``C×C``의 대상 객체에 작용한 결과 사이를 잇습니다. 이는 쌍 ``<a, b>``를 곱 객체 ``a × b``로 매핑하는 함자입니다. 이 홈 집합의 원소를 우리는 ``factorizer``의 결과로 인식합니다.

[source,haskell]
----
... -> (c -> (a, b))
----

아직 완전한 수반은 아닙니다. 먼저 ``factorizer``가 가역적이어야 합니다. 홈 집합들 사이의 동형 모피즘을 구축하는 중이기 때문입니다. ``factorizer``의 역은 모피즘 m에서 시작해야 합니다. 즉, 어떤 객체 c에서 곱 객체 ``a × b``로 가는 모피즘에서 시작합니다. 다시 말해 m은 다음의 원소입니다.

[source,haskell]
----
C(c, a×b)
----

역 factorizer는 m을 ``C×C``의 모피즘 ``<p, q>``로 매핑해야 합니다. 이는 ``<c, c>``에서 ``<a, b>``로 가는 모피즘, 즉 다음의 원소입니다.

[source,haskell]
----
(C×C)(Δ c, <a, b>)
----

이 매핑이 존재한다면, 대각선 함자에 대한 우수반이 존재한다고 결론 내립니다. 이 함자가 곱을 정의합니다.

하스켈에서는 m을 각각 ``fst``, ``snd``와 합성하여 항상 factorizer의 역을 구성할 수 있습니다.

[source,haskell]
----
p = fst ∘ m
q = snd ∘ m
----

곱을 정의하는 두 방식의 동치성 증명을 완성하려면 홈 집합 간의 매핑이 a, b, c에 대해 자연스럽다는 것도 보여야 합니다. 이는 헌신적인 독자를 위한 연습 문제로 남겨두겠습니다.

지금까지 한 일을 요약하면 다음과 같습니다. 카테고리적 곱은 대각선 함자의 우수반으로 전역적으로 정의될 수 있습니다.

[source,haskell]
----
(C × C)(Δ c, <a, b>) ≅ C(c, a×b)
----

여기서 ``a × b``는 우수반 함자 Product가 쌍 ``<a, b>``에 작용한 결과입니다. ``C×C``에서 출발하는 모든 함자는 이항 함자(bifunctor)이므로 Product도 이항 함자입니다. 하스켈에서 Product 이항 함자는 간단히 ``(,)``로 씁니다. 두 타입에 적용하면 곱 타입을 얻습니다. 예를 들어:

[source,haskell]
----
(,) Int Bool ~ (Int, Bool)
----

== 수반으로부터의 지수 (Exponential from Adjunction)

지수 stem:[b^a], 또는 함수 객체 stem:[a \Rightarrow b]도 보편적 구성으로 정의할 수 있습니다. 모든 객체 쌍에 대해 이 구성이 존재한다면, 수반으로 볼 수 있습니다. 다시 한번 핵심 명제에 집중합니다.

[source,haskell]
----
g :: z × a -> b
----

가 있으면, 유일한 모피즘

[source,haskell]
----
h :: z -> (a⇒b)
----

이 존재한다.

이 명제는 홈 집합 간의 매핑을 확립합니다.

이 경우 모든 객체가 같은 카테고리에 있으므로, 두 수반 함자는 엔도함자입니다. 왼쪽 (엔도) 함자 L은 객체 z에 작용하여 ``z × a``를 만듭니다. 이는 고정된 a와의 곱을 취하는 함자입니다.

우측 (엔도) 함자 R은 b에 작용하여 함수 객체 stem:[a \Rightarrow b] (또는 stem:[b^a])를 만듭니다. 여기서도 a는 고정되어 있습니다. 이 두 함자 사이의 수반은 흔히 다음과 같이 씁니다.

[source,haskell]
----
- × a ⊣ (-)^a
----

이 수반의 기반이 되는 홈 집합 간의 매핑은 보편적 구성에서 사용한 다이어그램을 다시 그려보면 가장 잘 보입니다.

``eval`` 모피즘이 바로 이 수반의 *코단위*라는 점에 주목하세요.

[source,haskell]
----
(a⇒b) × a -> b
----

다음이 성립하기 때문입니다.

[source,haskell]
----
(a⇒b) × a = (L ∘ R) b
----

이전에 보편적 구성이 동형을 제외하고 유일한 객체를 정의한다고 말했습니다. 그래서 우리는 "그(the)" 곱과 "그(the)" 지수를 말할 수 있습니다. 이 성질은 수반에도 적용됩니다. 함자가 수반을 가지면, 그 수반은 동형을 제외하고 유일합니다.

== 도전 과제

1. 다음의 두 (반변) 함자 사이의 변환 ``ψ``에 대한 자연성 사각형(naturality square)을 유도해 보세요.
   - ``a -> C(L a, b)``
   - ``a -> D(a, R b)``
2. 수반의 두 번째 정의인 홈 집합 동형 모피즘으로부터 코단위 ``ε``를 유도해 보세요.
3. 수반의 두 가지 정의가 서로 동등하다는 증명을 완성해 보세요.
4. 코프로덕트(coproduct)가 수반을 통해 정의될 수 있음을 보여 보세요. 코프로덕트의 factorizer 정의부터 시작하면 좋습니다.
5. 코프로덕트가 대각선 함자의 좌수반임을 증명해 보세요.
6. 하스켈에서 곱과 함수 객체 사이의 수반을 직접 정의해 보세요.
