== 화살표를 따르라 (Follow the Arrows)

고대 그리스의 극작가 에우리피데스는 이렇게 말했습니다. "사람은 그가 사귀는 친구를 보면 알 수 있다." 우리는 관계로 정의됩니다. 카테고리 이론에서 이보다 더 진실인 말은 없습니다. 카테고리 안에서 특정 객체를 구별하고 싶다면, 그 객체가 다른 객체들(그리고 자기 자신)과 맺고 있는 관계의 패턴을 기술하는 방법밖에 없습니다. 이러한 관계는 모피즘(morphism)으로 정의됩니다.

카테고리 이론에는 *보편 구성(universal construction)* 이라는 강력한 방법이 있습니다. 이는 객체를 다른 객체들과의 관계를 통해 정의하는 방식입니다. 그 방법 중 하나는 이렇습니다. 먼저 객체와 모피즘으로 이루어진 특정한 패턴(모양)을 선택합니다. 그런 다음 카테고리 전체에서 그 패턴이 나타나는 모든 경우를 찾습니다. 패턴이 충분히 일반적이고 카테고리가 크다면, 아마도 매우 많은 결과를 얻게 될 것입니다. 핵심은 이 결과들 사이에 일종의 순위를 매겨서, 가장 적합한 것을 선택하는 것입니다.

이 과정은 우리가 웹 검색을 하는 방식과 비슷합니다. 검색어는 패턴과 같습니다. 매우 일반적인 검색어는 많은 결과를 제공합니다. 재현율(recall)은 높지만, 관련 없는 내용이 포함될 수도 있습니다. 관련 없는 결과를 제거하려면 검색어를 더 구체화해야 합니다. 그러면 정밀도(precision)가 높아집니다. 마지막으로 검색 엔진이 결과의 순위를 매기면, 우리가 정말로 원하던 단 하나의 결과가 목록의 맨 위에 나타나게 됩니다.

== 초기 객체 (Initial Object)

가장 단순한 패턴은 객체 하나입니다. 당연히 주어진 카테고리 안에 있는 객체 수만큼 이 패턴의 인스턴스도 많을 것입니다. 선택지가 너무 많습니다. 우리는 이들 사이에 일종의 순위를 정하여 계층 구조의 최상위에 있는 객체를 찾아야 합니다. 우리가 동원할 수 있는 유일한 수단은 모피즘뿐입니다.

모피즘을 화살표로 생각해 봅시다. 카테고리 내에서 화살표들이 전반적으로 한쪽 끝에서 다른 쪽 끝으로 흐르는 모습을 상상할 수 있습니다. 이는 순서 카테고리(ordered category), 예를 들어 부분순서집합(partial order)에서 실제로 그렇습니다. 객체 stem:[a]에서 stem:[b]로 가는 화살표(모피즘)가 있으면 객체 stem:[a]가 stem:[b]보다 "더 초기적(more initial)"이라고 말함으로써 객체 간 우선순위 개념을 일반화할 수 있습니다. 그러면 *초기 객체*를 '다른 모든 객체로 향하는 화살표를 가진 객체'로 정의할 수 있습니다.

물론 그런 객체가 반드시 존재한다는 보장은 없습니다. 그래도 괜찮습니다. 더 큰 문제는 그런 객체가 너무 많을 수도 있다는 점입니다. 재현율은 좋지만 정밀도가 떨어지는 상황이죠. 해결책은 순서 카테고리에서 힌트를 얻는 것입니다. 순서 카테고리는 임의의 두 객체 사이에 최대 하나의 화살표만 허용합니다. 즉, 어떤 객체보다 '작거나 같다'고 말할 수 있는 방법은 단 하나뿐이라는 뜻입니다. 이 통찰이 초기 객체의 다음 정의로 이어집니다.

[quote]
____
*초기 객체(Initial object)*는 카테고리 안의 어떠한 객체로든 향하는 모피즘이 오직 하나만 존재하는 객체입니다.
____

하지만 이 정의조차도 (초기 객체가 존재할 경우) 초기 객체의 절대적인 유일성을 보장하지는 않습니다. 대신 그에 못지않게 중요한 성질인 *동형 모피즘을 제외한 유일성(uniqueness up to isomorphism)*을 보장합니다. 동형 모피즘(isomorphism)은 카테고리 이론에서 매우 중요하므로 잠시 후에 다루겠습니다. 일단은 '동형 모피즘을 제외한 유일성' 덕분에 초기 객체를 정관사 'the'를 붙여 '그 초기 객체'라고 부를 수 있다는 점만 확인하고 넘어가겠습니다.

몇 가지 예시를 들어보겠습니다. 부분순서집합(poset)에서 초기 객체는 최소 원소(least element)입니다. 어떤 poset에는 초기 객체가 없을 수도 있습니다. 예를 들어 작거나 같음(stem:[\le]) 관계를 모피즘으로 갖는 양수와 음수를 포함한 정수 전체 집합에는 초기 객체가 없습니다.

집합과 함수의 카테고리(Set)에서 초기 객체는 공집합입니다. 기억하시겠지만, 공집합은 하스켈 타입 ``Void``에 대응하며(C++에는 대응하는 타입이 없습니다), ``Void``에서 다른 임의의 타입으로 가는 유일한 다형 함수는 ``absurd``라고 불립니다.

[source,haskell]
----
absurd :: Void -> a
----

바로 이 모피즘족(family of morphisms)이 ``Void``를 타입 카테고리의 초기 객체로 만듭니다.

== 종단 객체 (Terminal Object)

단일 객체 패턴을 계속 사용하되, 객체의 순위를 매기는 방식을 반대로 바꿔봅시다. stem:[b]에서 stem:[a]로 가는 모피즘이 있으면 객체 stem:[a]가 stem:[b]보다 "더 종단적(more terminal)"이라고 말하겠습니다(방향이 반전된 것에 주목하세요). 이제 카테고리의 다른 모든 객체보다 더 종단적인 객체를 찾아보겠습니다. 여기서도 유일성을 강조하겠습니다.

[quote]
____
*종단 객체(Terminal object)*는 카테고리 안의 어떠한 객체로부터든 그 객체로 향하는 모피즘이 오직 하나만 존재하는 객체입니다.
____

종단 객체 역시 동형 모피즘을 제외하면 유일하며, 이 점은 곧 증명하겠습니다. 우선 예시부터 보시죠. poset에서 종단 객체는 (존재한다면) 가장 큰 원소입니다. 집합 카테고리에서 종단 객체는 싱글톤(singleton, 원소가 하나뿐인 집합)입니다. 이미 언급했듯이 싱글톤은 C++의 ``void`` 타입과 하스켈의 유닛 타입 ``()``에 해당합니다. 이 타입은 단 하나의 값만 가질 수 있는데, C++에서는 암시적이지만 하스켈에서는 ``()``로 명시적으로 표기합니다. 또한 임의의 타입에서 유닛 타입으로 가는 순수 함수는 하나뿐이라는 점도 확인했습니다.

[source,haskell]
----
unit :: a -> ()
unit _ = ()
----

이로써 종단 객체의 모든 조건이 충족되었습니다.

이 예시에서 유일성 조건이 매우 결정적이라는 점에 주목하세요. 왜냐하면 (공집합을 제외한) 모든 집합이 다른 모든 집합들로부터 들어오는 모피즘을 가지고 있기 때문입니다. 예를 들어, 모든 타입에 대해 정의할 수 있는 불리언 값 함수(술어, predicate)가 있습니다.

[source,haskell]
----
yes :: a -> Bool
yes _ = True
----

하지만 ``Bool``은 종단 객체가 아닙니다. 모든 타입에서 나오는 불리언 값 함수가 적어도 하나 더 있기 때문입니다.

[source,haskell]
----
no :: a -> Bool
no _ = False
----

유일성을 요구함으로써, 종단 객체의 정의를 정확히 하나의 타입으로 좁히는 데 필요한 정밀도를 얻을 수 있습니다.

== 쌍대성 (Duality)

초기 객체와 종단 객체를 정의한 방식 사이의 대칭성을 눈치채지 않을 수 없습니다. 둘 사이의 유일한 차이는 모피즘의 방향뿐입니다. 사실 임의의 카테고리 stem:[C]에 대해 모든 화살표를 반대로 뒤집기만 하면 *반대 카테고리(opposite category, stem:[C^{op}])*를 정의할 수 있습니다. 합성 규칙을 동시에 재정의하는 한, 반대 카테고리는 카테고리의 모든 요구 사항을 자동으로 만족합니다.

원래의 모피즘 stem:[f: a \to b]와 stem:[g: b \to c]가 stem:[h = g \circ f]에 의해 stem:[h: a \to c]로 합성되었다고 합시다. 그러면 뒤집힌 모피즘 stem:[f^{op}: b \to a]와 stem:[g^{op}: c \to b]는 stem:[h^{op} = f^{op} \circ g^{op}]에 의해 stem:[h^{op}: c \to a]로 합성됩니다. 그리고 항등 화살표를 뒤집는 것은 (말장난 주의!) 아무 연산도 하지 않는 것(no-op)과 같습니다.

쌍대성(duality)은 카테고리 이론의 매우 중요한 속성입니다. 카테고리 이론을 연구하는 수학자들의 생산성을 두 배로 높여주기 때문입니다. 여러분이 어떤 구성을 생각해내면 그에 반대되는 구성이 항상 존재하며, 어떤 정리를 하나 증명하면 자동으로 또 다른 하나를 공짜로 얻게 됩니다. 반대 카테고리의 구성에는 종종 "여(co-)"라는 접두사가 붙습니다. 그래서 곱(product)과 여곱(coproduct), 모나드(monad)와 코모나드(comonad), 원뿔(cone)과 코원뿔(cocone), 극한(limit)과 여극한(colimit) 등이 있게 됩니다. 참고로 '코코모나드(cocomonad)' 같은 것은 없습니다. 화살표를 두 번 뒤집으면 원래 상태로 돌아오기 때문입니다.

결론적으로, 종단 객체는 반대 카테고리에서의 초기 객체입니다.

== 동형 모피즘 (Isomorphisms)

프로그래머인 우리는 '같음(equality)'을 정의하는 것이 결코 사소한 일이 아님을 잘 알고 있습니다. 두 객체가 같다는 것은 무엇을 의미할까요? 메모리의 같은 위치를 점유해야 할까요(포인터 상의 동등성)? 아니면 모든 구성 요소의 값이 같기만 하면 충분할까요? 한 복소수는 실수부와 허수부로 표현되고, 다른 복소수는 절댓값(modulus)과 편각(angle)으로 표현되어 있다면 이 둘은 같을까요?

수학자들이 동등성의 의미를 완벽하게 정립했을 것 같지만, 사실 그렇지 않습니다. 수학자들도 여러 정의가 경합하는 똑같은 상황에 놓여 있습니다. 명제적 동등성(propositional equality), 내포적 동등성(intensional equality), 외연적 동등성(extensional equality), 그리고 호모토피 타입 이론(homotopy type theory)에서 경로로서의 동등성 등이 있습니다. 그리고 이보다 더 약한 개념인 동형 모피즘(isomorphism), 더 나아가 동치(equivalence) 개념도 있습니다.

동형 모피즘의 직관은 이렇습니다. 동형인 두 객체는 '똑같아 보인다'는 것입니다. 즉, 형태(shape)가 같다는 의미죠. 이는 한 객체의 모든 부분이 다른 객체의 어떤 부분과 일대일로 대응됨을 뜻합니다. 우리가 가진 도구로 측정하는 한, 두 객체는 서로의 완벽한 복사본입니다. 수학적으로 이는 객체 stem:[a]에서 stem:[b]로 가는 대응(mapping)이 있고, 다시 stem:[b]에서 stem:[a]로 돌아오는 대응이 있으며, 이 둘이 서로의 *역(inverse)*이 된다는 것을 의미합니다. 카테고리 이론에서는 이 대응을 모피즘으로 대체합니다. 동형 모피즘은 가역적인(invertible) 모피즘, 즉 서로가 서로의 역이 되는 한 쌍의 모피즘을 의미합니다.

우리는 합성과 항등의 관점에서 역을 이해합니다. 모피즘 stem:[g]가 stem:[f]의 역이려면, 그들의 합성이 항등 모피즘이어야 합니다. 모피즘을 합성하는 방법은 두 가지이므로 실제로는 두 개의 방정식이 필요합니다.

[source]
----
f . g = id
g . f = id
----

초기(종단) 객체가 '동형 모피즘을 제외하면 유일하다'고 한 것은 임의의 두 초기(종단) 객체가 서로 동형이라는 뜻입니다. 이는 쉽게 확인할 수 있습니다. 두 초기 객체 stem:[i_1]과 stem:[i_2]가 있다고 가정해 봅시다. stem:[i_1]이 초기 객체이므로 stem:[i_1]에서 stem:[i_2]로 가는 유일한 모피즘 stem:[f]가 존재합니다. 마찬가지로 stem:[i_2]가 초기 객체이므로 stem:[i_2]에서 stem:[i_1]로 가는 유일한 모피즘 stem:[g]가 존재합니다. 그렇다면 이 두 모피즘의 합성은 무엇일까요?

<!-- image -->

*이 다이어그램의 모든 모피즘은 유일합니다.*

합성 stem:[g \circ f]는 stem:[i_1]에서 stem:[i_1]로 가는 모피즘이어야 합니다. 그런데 stem:[i_1]은 초기 객체이므로 stem:[i_1]에서 자기 자신으로 가는 모피즘은 오직 하나뿐입니다. 우리는 카테고리 공리에 의해 stem:[i_1]에서 stem:[i_1]로 가는 항등 모피즘이 존재함을 알고 있고, 자리가 하나뿐이므로 그 모피즘은 반드시 항등 모피즘이어야 합니다. 따라서 stem:[g \circ f]는 항등 모피즘입니다. 마찬가지로 stem:[f \circ g] 도 항등 모피즘이어야 합니다. stem:[i_2]에서 stem:[i_2]로 가는 모피즘은 오직 하나뿐이기 때문입니다. 이로써 stem:[f]와 stem:[g]는 서로의 역임이 증명되었습니다. 따라서 임의의 두 초기 객체는 서로 동형입니다.

이 증명에서 초기 객체에서 자기 자신으로 가는 모피즘의 '유일성'을 결정적으로 사용했음에 주목하세요. 그것 없이는 '동형 모피즘을 제외한 유일성'을 증명할 수 없습니다. 그런데 왜 stem:[f]와 stem:[g]의 유일성까지 필요할까요? 초기 객체는 동형 모피즘을 제외하면 유일할 뿐만 아니라, *유일한 동형 모피즘(unique isomorphism)*에 의해서 유일하기 때문입니다. 원칙적으로는 두 객체 사이에 여러 개의 동형 모피즘이 있을 수도 있지만, 여기서는 그렇지 않습니다. 이 '유일한 동형 모피즘에 의한 유일성'은 모든 보편 구성의 중요한 속성입니다.

== 곱 (Products)

다음 보편 구성은 곱(product)입니다. 우리는 두 집합의 카르테시안 곱(cartesian product)이 '쌍(pair)의 집합'이라는 점을 알고 있습니다. 그렇다면 곱 집합을 구성 집합들과 연결해주는 패턴은 무엇일까요? 이를 찾아낼 수 있다면 다른 카테고리로도 일반화할 수 있을 것입니다.

우리가 말할 수 있는 전부는, 곱에서 각 구성 성분으로 향하는 두 개의 함수, 즉 *사영(projection)*이 존재한다는 것입니다. 하스켈에서 이 두 함수는 ``fst``와 ``snd``라고 불리며 각각 쌍의 첫 번째와 두 번째 요소를 꺼냅니다.

[source,haskell]
----
fst :: (a, b) -> a
fst (x, y) = x

snd :: (a, b) -> b
snd (x, y) = y
----

여기서 함수는 인자를 패턴 매칭하여 정의되었습니다. ``(x, y)``는 임의의 쌍과 매치되는 패턴이며, 요소들을 변수 ``x``와 ``y``로 추출합니다.

이 정의는 와일드카드(``_``)를 써서 더 단순하게 만들 수도 있습니다.

[source,haskell]
----
fst (x, _) = x
snd (_, y) = y
----

C++라면 다음과 같은 템플릿 함수를 사용할 것입니다.

[source,cpp]
----
template<class A, class B>
A fst(pair<A, B> const & p) {
    return p.first;
}
----

이 겉보기에 매우 제한적인 지식만 가지고, 집합 카테고리에서 두 집합 stem:[a, b]의 곱을 이끌어낼 객체와 모피즘의 패턴을 정의해 봅시다. 이 패턴은 객체 stem:[c]와 그로부터 각각 stem:[a]와 stem:[b]로 연결되는 두 모피즘 stem:[p, q]로 이루어져 있습니다.

[source,haskell]
----
p :: c -> a
q :: c -> b
----

이 패턴에 들어맞는 모든 stem:[c]가 곱의 후보가 될 수 있습니다. 후보는 아주 많을 수 있습니다.

예를 들어, 하스켈 타입 ``Int``와 ``Bool``을 곱의 구성 요소로 정하고 후보들을 살펴봅시다.

첫 번째 후보는 바로 ``Int``입니다. ``Int``가 ``Int``와 ``Bool``의 곱 후보가 될 수 있을까요? 네, 가능합니다. 다음과 같이 사영을 정의하면 됩니다.

[source,haskell]
----
p :: Int -> Int
p x = x

q :: Int -> Bool
q _ = True
----

다소 빈약해 보이지만, 어쨌든 최소한의 조건은 만족합니다.

다른 후보로는 ``(Int, Int, Bool)``이라는 트리플(triple, 3개 요소 튜플)이 있습니다. 다음 두 모피즘을 정의하면 정당한 후보가 됩니다.

[source,haskell]
----
p :: (Int, Int, Bool) -> Int
p (x, _, _) = x

q :: (Int, Int, Bool) -> Bool
q (_, _, b) = b
----

눈치채셨겠지만, 첫 번째 후보는 너무 작아서 곱의 ``Int`` 차원만 다루고 있고, 두 번째 후보는 너무 커서 불필요하게 ``Int`` 차원을 중복해서 가지고 있습니다.

하지만 우리는 아직 보편 구성의 또 다른 부분인 '순위 매기기'를 적용하지 않았습니다. 우리는 위 패턴의 두 인스턴스를 비교하고 싶습니다. 후보 객체 stem:[c]와 사영 stem:[p, q], 그리고 또 다른 후보 stem:[c']와 사영 stem:[p', q']가 있다고 해 봅시다. 만약 stem:[c']에서 stem:[c]로 가는 모피즘 stem:[m]이 존재한다면 stem:[c]가 stem:[c']보다 "더 낫다"고 말하고 싶을 것입니다. 하지만 그것만으로는 부족합니다. 우리는 사영들 또한 "더 낫거나" 혹은 "더 보편적(universal)"이기를 원합니다. 이는 사영 stem:[p']와 stem:[q']가 stem:[m]과 stem:[p, q]를 이용해 재구성될 수 있음을 뜻합니다.

[source,haskell]
----
p' = p . m
q' = q . m
----

이 방정식을 다르게 해석하면, *stem:[m]이 stem:[p']와 stem:[q']를 인수분해(factorize)한다*고 볼 수 있습니다. 마치 자연수의 곱셈 방정식에서 stem:[m]이 stem:[p']와 stem:[q']의 공통 인수인 것처럼 생각하면 됩니다.

직관을 돕기 위해, 정규 사영 ``fst``와 ``snd``를 가진 쌍 ``(Int, Bool)``이 앞서 제시한 두 후보보다 실제로 왜 더 나은지 보여드리겠습니다.

첫 번째 후보에 대한 대응 stem:[m]은 다음과 같습니다.

[source,haskell]
----
m :: Int -> (Int, Bool)
m x = (x, True)
----

실제로 두 사영 stem:[p, q]는 다음과 같이 재구성됩니다.

[source,haskell]
----
p x = fst (m x) = x
q x = snd (m x) = True
----

두 번째 예시의 stem:[m]도 다음과 같이 유일하게 결정됩니다.

[source,haskell]
----
m (x, _, b) = (x, b)
----

이로써 ``(Int, Bool)``이 두 후보보다 낫다는 것을 알 수 있습니다. 이제 반대로 다른 후보가 ``(Int, Bool)``보다 나을 수 없는 이유도 살펴봅시다. 과연 stem:[p, q]를 이용해 ``fst, snd``를 재구성할 수 있는 stem:[m']을 찾을 수 있을까요?

[source,haskell]
----
fst = p . m'
snd = q . m'
----

첫 번째 예시에서 stem:[q]는 항상 ``True``만 반환합니다. 하지만 쌍들 중에는 두 번째 요소가 ``False``인 경우도 있다는 것을 우리는 압니다. 따라서 stem:[q]를 통해서는 ``snd``를 재구성할 수 없습니다.

두 번째 예시는 다릅니다. stem:[p]나 stem:[q]를 거친 후에도 충분한 정보가 남아있지만, ``fst``와 ``snd``를 인수분해하는 방법이 한 가지만 있는 게 아닙니다. stem:[p]와 stem:[q] 모두 트리플의 두 번째 요소를 무시하기 때문에, 우리의 stem:[m']은 그 자리에 무엇이든 넣을 수 있습니다.

[source,haskell]
----
m' (x, b) = (x, x, b)
----

또는

[source,haskell]
----
m' (x, b) = (x, 42, b)
----

이런 식으로 말이죠.

정리하자면, 두 개의 사영 stem:[p, q]를 가진 어떤 타입 stem:[c]가 주어지더라도 stem:[c]에서 카르테시안 곱 ``(a, b)``로 가는 유일한 모피즘 stem:[m]이 존재하여 이들을 인수분해합니다. 사실 이 stem:[m]은 stem:[p]와 stem:[q]의 결과를 쌍으로 묶어줄 뿐입니다.

[source,haskell]
----
m :: c -> (a, b)
m x = (p x, q x)
----

이것이 카르테시안 곱 ``(a, b)``를 이 패턴의 최적의 결과로 만들어 주며, 보편 구성이 집합 카테고리에서 잘 작동함을 보여줍니다. 보편 구성은 임의의 두 집합에 대해 그 곱을 정확히 끄집어냅니다.

이제 집합을 잠시 잊고, 동일한 보편 구성을 사용하여 임의의 카테고리에서 두 객체의 곱을 정의해 봅시다. 그런 곱이 항상 존재하는 것은 아니지만, 존재할 때는 유일한 동형 모피즘에 의해서 유일합니다.

[quote]
____
두 객체 stem:[a]와 stem:[b]의 *곱(Product)*은 두 개의 사영을 갖춘 객체 stem:[c]로서, 두 개의 사영을 갖춘 임의의 다른 객체 stem:[c']에 대해 stem:[c']에서 stem:[c]로 가며 사영들을 인수분해하는 유일한 모피즘 stem:[m]이 존재하는 객체입니다.
____

두 후보로부터 인수분해 모피즘 stem:[m]을 생성하는 (고차) 함수를 때로는 *인수분해 함수(factorizer)*라고 부릅니다. 우리의 경우 다음과 같은 함수가 될 것입니다.

[source,haskell]
----
factorizer :: (c -> a) -> (c -> b) -> (c -> (a, b))
factorizer p q = \x -> (p x, q x)
----

== 여곱 (Coproduct)

카테고리 이론의 모든 구성이 그렇듯, 곱 역시 쌍대(dual)를 가지며 이를 *여곱(coproduct)*이라 부릅니다. 곱 패턴에서 화살표 방향을 뒤집으면, 두 개의 *주입(injection)* stem:[i, j]를 갖춘 객체 stem:[c]가 됩니다. 이들은 stem:[a, b]에서 stem:[c]로 가는 모피즘입니다.

[source,haskell]
----
i :: a -> c
j :: b -> c
----

순위 기준도 반전됩니다. 주입 stem:[i', j']를 갖춘 객체 stem:[c']보다 객체 stem:[c]가 "더 낫다"는 것은, stem:[c]에서 stem:[c']로 가며 주입들을 인수분해하는 모피즘 stem:[m]이 존재함을 뜻합니다.

[source,haskell]
----
i' = m . i
j' = m . j
----

이런 "최적의" 객체, 즉 다른 어떠한 패턴과도 연결되는 유일한 모피즘을 갖는 객체를 여곱이라 부르며, 존재한다면 유일한 동형 모피즘 범위 내에서 유일합니다.

[quote]
____
두 객체 stem:[a]와 stem:[b]의 *여곱(Coproduct)*은 두 개의 주입을 갖춘 객체 stem:[c]로서, 두 개의 주입을 갖춘 임의의 다른 객체 stem:[c']에 대해 stem:[c]에서 stem:[c']로 가며 주입들을 인수분해하는 유일한 모피즘 stem:[m]이 존재하는 객체입니다.
____

집합 카테고리에서 여곱은 두 집합의 *서로소 합집합(disjoint union)*입니다. stem:[a, b]의 서로소 합집합의 원소는 stem:[a]의 원소이거나 stem:[b]의 원소입니다. 만약 두 집합이 겹친다면, 서로소 합집합은 공통된 부분의 복사본을 각각 하나씩 총 두 개 가지게 됩니다. 서로소 합집합의 원소는 그 출처가 어디인지 나타내는 식별자가 태그된 상태라고 생각하면 쉽습니다.

프로그래머에게 여곱은 타입을 통해 이해하는 것이 더 쉽습니다. 바로 두 타입의 *태그 있는 합집합(tagged union)*입니다. C++은 ``union``을 지원하지만 태그가 달려있지 않습니다. 즉, 프로그램의 어딘가에서 유니온의 어떤 멤버가 현재 유효한 값인지 직접 추적해야 합니다. 태그 있는 합집합을 만들려면 태그(열거형)를 정의하고 이를 유니온과 결합해야 합니다. 예를 들어 ``int``와 ``char const *``의 태그 있는 합집합은 다음과 같이 구현될 수 있습니다.

[source,cpp]
----
struct Contact {
    enum { isPhone, isEmail } tag;
    union { int phoneNum; char const * emailAddr; };
};
----

두 주입은 생성자나 함수로 구현될 수 있습니다. 다음은 ``PhoneNum``이라는 함수로 구현된 첫 번째 주입의 예시입니다.

[source,cpp]
----
Contact PhoneNum(int n) {
    Contact c;
    c.tag = isPhone;
    c.phoneNum = n;
    return c;
}
----

이 함수는 정수형 값을 ``Contact`` 타입 안으로 주입합니다.

태그 있는 합집합은 *배리언트(variant)*라고도 불리며, Boost 라이브러리에는 매우 일반적인 배리언트 구현체인 ``boost\::variant``가 있습니다.

하스켈에서는 세로 막대(|)로 데이터 생성자들을 구분하여 임의의 데이터 타입들을 태그 있는 합집합으로 묶을 수 있습니다. 위의 ``Contact`` 예시는 다음과 같이 선언됩니다.

[source,haskell]
----
data Contact = PhoneNum Int | EmailAddr String
----

여기서 ``PhoneNum``과 ``EmailAddr``은 주입(생성자)인 동시에 패턴 매칭 시 사용되는 태그 역할도 수행합니다. 예를 들어 전화번호를 이용해 연락처를 만드는 방법은 다음과 같습니다.

[source,haskell]
----
helpdesk :: Contact
helpdesk = PhoneNum 2222222
----

하스켈에 기본 쌍(pair)으로 내장된 곱의 정규 구현과 달리, 여곱의 정규 구현은 표준 ``Prelude`` 라이브러리에 선언된 ``Either``라는 데이터 타입입니다.

[source,haskell]
----
data Either a b = Left a | Right b
----

``Either``는 두 타입 stem:[a, b]를 매개변수로 받으며, stem:[a] 타입 값을 받는 ``Left``와 stem:[b] 타입 값을 받는 ``Right``라는 두 개의 생성자를 가집니다.

곱에 대해 인수분해 함수를 정의했던 것처럼, 여곱에 대해서도 정의할 수 있습니다. 후보 타입 stem:[c]와 두 후보 주입 stem:[i, j]가 주어졌을 때, ``Either``에 대한 인수분해 함수는 다음과 같은 인수분해 모피즘을 생성합니다.

[source,haskell]
----
factorizer :: (a -> c) -> (b -> c) -> Either a b -> c
factorizer i j (Left a)  = i a
factorizer i j (Right b) = j b
----

== 비대칭성 (Asymmetry)

우리는 지금까지 두 쌍의 쌍대 정의를 살펴보았습니다. 종단 객체의 정의는 초기 객체 정의의 화살표 방향을 뒤집어서 얻어지며, 여곱의 정의 또한 곱의 정의로부터 비슷한 방식으로 얻어집니다. 하지만 집합 카테고리에서 초기 객체와 종단 객체는 매우 다르게 생겼으며, 여곱과 곱 또한 매우 다릅니다. 나중에 보겠지만, 곱은 곱셈처럼 동작하고 종단 객체는 '1'의 역할을 수행하는 반면, 여곱은 덧셈처럼 동작하고 초기 객체는 '0'의 역할을 합니다. 실제로 유한 집합의 경우, 곱의 크기는 각 집합 크기의 곱이고, 여곱의 크기는 그 합과 같습니다.

이는 집합 카테고리가 화살표 반전에 대해 대칭적이지 않음을 잘 보여줍니다.

공집합은 임의의 집합으로 가는 유일한 모피즘(``absurd`` 함수)을 갖지만, 되돌아오는 모피즘은 전혀 없습니다. 반면 싱글톤 집합(종단 객체)은 임의의 집합으로부터 들어오는 유일한 모피즘을 가지지만, 동시에 모든 집합(공집합 제외)으로 나가는 모피즘들도 가지고 있습니다. 이미 보았듯이 종단 객체로부터 나가는 이러한 모피즘들은 다른 집합에서 '원소를 선택하는' 매우 중요한 역할을 수행합니다. 공집합은 원소가 없으므로 선택할 것이 없습니다.

싱글톤 집합이 곱과 맺고 있는 관계는 싱글톤 집합을 여곱으로부터 뚜렷하게 구별해 줍니다. 유닛 타입 ``()``로 표현되는 싱글톤 집합을 곱 패턴의 (매우 열등한) 후보군 중 하나로 생각해 봅시다. 그리고 이 싱글톤에서 각 구성 집합으로 가는 두 개의 사영 stem:[p, q]를 정의합니다. 각각은 두 집합 중 하나에서 구체적인 원소를 하나 선택하게 됩니다. 곱은 보편적(universal)이므로, 우리의 후보(싱글톤)에서 곱으로 가는 유일한 모피즘 stem:[m]이 존재하며, 이 stem:[m] 역시 곱 집합에서 원소 하나, 즉 구체적인 쌍 하나를 선택합니다. 그리고 이 모피즘은 두 사영을 다음과 같이 인수분해합니다.

[source,haskell]
----
p = fst . m
q = snd . m
----

싱글톤 집합의 유일한 원소인 ``()``를 대입해 보면, 이 방정식들이 다음과 같이 됩니다.

[source,haskell]
----
p () = fst (m ())
q () = snd (m ())
----

stem:[m()]은 stem:[m]에 의해 선택된 곱 집합의 원소이므로, 위 식들은 stem:[p]가 첫 번째 집합에서 선택한 원소 stem:[p()]가 바로 stem:[m]이 선택한 쌍의 첫 번째 요소라는 점을 말해줍니다. stem:[q()] 역시 마찬가집니다. 이는 곱의 원소가 각 구성 집합에서 뽑은 원소들의 쌍이라는 우리의 직관과 완벽하게 일치합니다.

여곱에는 이처럼 간단한 해석이 존재하지 않습니다. 싱글톤 집합을 여곱의 후보로 삼아 원소를 추출해 보려 해도, 여기서는 원소가 나가는 두 사영이 아니라 원소가 들어오는 두 주입이 있을 뿐입니다. 주입 모피즘은 출처에 대해 아무것도 알려주지 않습니다. 입력 파라미터를 무시한다는 점을 이미 보았습니다. 여곱에서 우리 후보인 싱글톤으로 가는 유일한 모피즘 또한 마찬가지입니다. 이처럼 집합 카테고리는 초기 객체라는 입구에서 볼 때와 종단 객체라는 출구에서 볼 때 그 모습이 매우 다르게 보입니다.

이것은 집합 자체의 본질적인 속성이라기보다는 모피즘으로 사용되는 '함수'의 속성입니다. 함수는 일반적으로 비대칭적이기 때문입니다. 설명해 보겠습니다.

함수는 정의역(domain) 집합의 모든 원소에 대해 정의되어야 하지만(프로그래밍에서는 이를 *전함수(total function)*라 부릅니다), 공역(codomain)의 모든 원소를 다 채울 필요는 없습니다. 공역에서 단 하나의 원소만 선택하는 싱글톤 집합으로부터의 함수가 그 극단적인 사례입니다. 사실 공집합으로부터의 함수가 진짜 극단입니다. 정의역의 크기가 공역보다 훨씬 작을 때, 우리는 종종 그런 함수를 정의역을 공역에 *임베딩(embedding)*하는 것으로 생각합니다. 예를 들어 싱글톤 집합으로부터의 함수는 그 유일한 원소를 공역에 임베딩하는 것으로 볼 수 있습니다. 저는 이를 임베딩 함수라고 부르지만, 수학자들은 그 반대 개념에 이름을 붙이는 것을 선호합니다. 공역을 빈틈없이 채우는 함수를 *전사 함수(surjective)* 또는 *위로의 함수(onto)*라고 부릅니다.

비대칭성의 또 다른 원인은 함수가 정의역의 여러 원소를 공역의 한 원소로 몰아넣을 수 있다는 점입니다. 이를 *붕괴(collapse)*시킨다고 표현할 수 있습니다. 집합 전체를 싱글톤으로 매핑하는 함수가 그 극단적인 예입니다. 바로 그런 일을 하는 다형 함수 ``unit``을 이미 보았습니다. 붕괴는 합성을 통해 더욱 심해질 수 있습니다. 두 붕괴 함수의 합성은 개별 함수들보다 훨씬 더 많이 붕괴시킵니다. 수학자들은 붕괴하지 않는 함수를 *단사 함수(injective)* 또는 *일대일 함수(one-to-one)*라고 부릅니다.

물론 임베딩도 붕괴도 일어나지 않는 함수들도 존재합니다. 이를 *전단사 함수(bijection)*라 부르며, 이들은 가역적(invertible)이므로 진정으로 대칭적입니다. 집합 카테고리에서 동형 모피즘은 전단사 함수와 같습니다.

1. 종단 객체가 유일한 동형 모피즘을 제외하면 유일함을 증명해 보세요.
2. 부분순서집합(poset)에서 두 객체의 곱은 무엇일까요? (힌트: 보편 구성을 사용해 보세요.)
3. poset에서 두 객체의 여곱은 무엇일까요?
4. 하스켈의 ``Either``와 동일한 기능을 수행하는 제네릭 타입을 여러분이 좋아하는 언어(하스켈 제외)로 작성해 보세요.
5. 다음 주입 모피즘이 정의된 ``int``보다 ``Either``가 "더 나은" 여곱임을 증명해 보세요.
+
[source,cpp]
----
   int i(int n) { return n; }
   int j(bool b) { return b? 0: 1; }
----
+
힌트: stem:[i, j]를 인수분해하는 ``int m(Either const & e);`` 함수를 정의해 보세요.
6. 이전 문제에 이어, stem:[i, j] 주입을 가진 ``int``가 왜 ``Either``보다 "더 나을 수 없는지" 논리적으로 설명해 보세요.
7. 다음 주입 모피즘들에 대해서는 어떻게 생각하시나요?
+
[source,cpp]
----
   int i(int n) {
       if (n < 0) return n;
       return n + 2;
   }
   int j(bool b) { return b? 0: 1; }
----
8. ``int``와 ``bool``의 여곱에 대한 열등한 후보를 하나 고안해 보세요. ``Either``보다 나을 수 없는 이유는 그것에서 ``Either``로 가는 허용 가능한 모피즘이 여러 개이기 때문입니다.
