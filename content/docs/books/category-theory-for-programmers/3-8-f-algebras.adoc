'''
우리는 모노이드를 집합으로, 단일 객체 카테고리로, 또는 모노이드 카테고리의 객체로 정의하는 여러 방식을 보았습니다. 이 단순한 개념에서 과연 얼마나 더 많은 것을 짜낼 수 있을까요?

한번 시도해 봅시다. 집합 ``m``과 두 함수의 쌍으로 정의된 모노이드를 가져와 보겠습니다.

[source,haskell]
----
μ :: m × m -> m
η :: 1 -> m
----

여기서 ``1``은 Set에서의 종단 객체(terminal object), 즉 싱글턴 집합입니다. 첫 번째 함수는 곱셈을 정의하고(원소 쌍을 받아 그 곱을 반환), 두 번째 함수는 ``m``에서 단위 원소를 선택합니다. 이런 시그니처를 가진 함수 두 개를 아무렇게나 골라도 모노이드가 되는 것은 아닙니다. 모노이드가 되려면 결합 법칙과 단위 법칙이라는 추가 조건을 만족해야 합니다. 하지만 잠시 그 조건은 잊고 "잠재적인 모노이드"만 고려합시다.

함수의 쌍은 두 함수 집합의 카르테시안 곱의 원소입니다. 이런 함수 집합들을 지수 객체로 표현할 수 있다는 것을 우리는 알고 있습니다.

[source,haskell]
----
μ ∈ m^(m×m)
η ∈ m^1
----

이 두 집합의 카르테시안 곱은 다음과 같습니다.

[source,haskell]
----
m^(m×m) × m^1
----

고등학교 대수(모든 카르테시안 닫힌 카테고리에서 성립)를 사용하면 이를 다음과 같이 다시 쓸 수 있습니다.

[source,haskell]
----
m^(m×m + 1)
----

더하기 기호는 Set에서의 코프로덕트를 나타냅니다. 우리는 방금 함수 쌍을 하나의 함수, 즉 다음 집합의 원소로 대체했습니다.

[source,haskell]
----
m × m + 1 -> m
----

이 함수 집합의 모든 원소는 하나의 잠재적인 모노이드입니다.

이런 정식화의 아름다움은 흥미로운 일반화로 이어진다는 것입니다. 예를 들어 이 언어로 군(group)을 어떻게 설명할 수 있을까요? 군은 모든 원소에 역원을 할당하는 함수가 하나 더 있는 모노이드입니다. 역원 함수의 타입은 ``m -> m``입니다. 예를 들어 정수는 덧셈을 이항 연산으로, 0을 단위원으로, 부정을 역원으로 하는 군을 형성합니다. 군을 정의하려면 다음 세 함수로 시작합니다.

[source,haskell]
----
m × m -> m
m -> m
1 -> m
----

이전처럼 이 세 함수를 하나의 함수 집합으로 결합할 수 있습니다.

[source,haskell]
----
m × m + m + 1 -> m
----

하나의 이항 연산자(덧셈), 하나의 단항 연산자(부정), 하나의 0항 연산자(단위원, 여기서는 0)로 시작했습니다. 이들을 하나의 함수로 합쳤습니다. 이 시그니처를 가진 모든 함수는 잠재적인 군을 정의합니다.

이런 식으로 계속 갈 수 있습니다. 예를 들어 환(ring)을 정의하려면 이항 연산자와 0항 연산자를 하나씩 더 추가하면 됩니다. 매번 우리는 왼쪽이 거듭제곱들의 합(0제곱, 즉 종단 객체 포함 가능)이고 오른쪽이 집합 자체인 함수 타입에 도달합니다.

이제 과감하게 일반화해 봅시다. 먼저 집합을 객체로, 함수를 모피즘으로 바꿀 수 있습니다. stem:[n]항 연산자는 stem:[n]차 곱으로부터의 모피즘으로 정의할 수 있습니다. 이는 유한 곱을 지원하는 카테고리가 필요하다는 의미입니다. 0항 연산자를 위해서는 종단 객체가 있어야 합니다. 즉 카르테시안 카테고리가 필요합니다. 이 연산자들을 결합하려면 지수가 필요하므로 카르테시안 닫힌 카테고리여야 합니다. 마지막으로 대수적 곡예를 완성하려면 코프로덕트도 필요합니다.

아니면 이 공식을 유도한 과정은 잊고 최종 결과에만 집중할 수도 있습니다. 모피즘 왼쪽의 "곱들의 합"은 하나의 엔도함자를 정의합니다. 임의의 엔도함자 stem:[F]를 선택하면 어떨까요? 이 경우 카테고리에 아무 제약도 둘 필요가 없습니다. 이렇게 얻는 것이 바로 *F-대수*입니다.

F-대수는 엔도함자 stem:[F], 객체 stem:[a], 그리고 다음과 같은 모피즘으로 구성된 삼조입니다.

[source,haskell]
----
F a -> a
----

객체 stem:[a]는 흔히 *운반자(carrier)*, 기저 객체 또는 프로그래밍 맥락에서는 *운반자 타입*이라 불립니다. 모피즘은 보통 *평가 함수* 또는 *구조 모피즘*이라 불립니다. 함자 stem:[F]를 표현식을 형성하는 것으로, 모피즘을 그 표현식을 평가하는 것으로 생각하면 됩니다.

하스켈에서 F-대수를 정의하면 다음과 같습니다.

[source,haskell]
----
type Algebra f a = f a -> a
----

이는 대수를 평가 함수 그 자체로 정의합니다.

모노이드 예에서 해당 함자는 다음과 같습니다.

[source,haskell]
----
data MonF a = MEmpty | MAppend a a
----

이는 1 + a × a의 하스켈 표현입니다(대수적 자료 구조를 기억하세요).

환은 다음 함자로 정의됩니다.

[source,haskell]
----
data RingF a = RZero
             | ROne
             | RAdd a a
             | RMul a a
             | RNeg a
----

이는 1 + 1 + a × a + a × a + a의 하스켈 표현입니다.

환의 예로는 정수 집합이 있습니다. ``Integer``를 운반자 타입으로 선택하고 평가 함수를 다음과 같이 정의할 수 있습니다.

[source,haskell]
----
evalZ :: Algebra RingF Integer
evalZ RZero      = 0
evalZ ROne       = 1
evalZ (RAdd m n) = m + n
evalZ (RMul m n) = m * n
evalZ (RNeg n)   = -n
----

동일한 함자 ``RingF``를 기반으로 하는 더 많은 F-대수가 있습니다. 예를 들어 다항식도 환을 형성하고, 정사각 행렬도 환을 형성합니다.

보시다시피, 함자의 역할은 대수의 평가자를 사용하여 평가할 수 있는 표현식을 생성하는 것입니다. 지금까지는 매우 간단한 표현식만 살펴보았습니다. 우리가 진정으로 관심을 갖는 것은 재귀를 사용하여 정의할 수 있는 더 정교한 표현식입니다.

== 재귀 (Recursion)

임의의 표현식 트리(expression tree)를 생성하는 한 가지 방법은 함자 정의 내부에 있는 변수 stem:[a]를 재귀로 대체하는 것입니다. 예를 들어 환에 대한 임의의 표현식은 다음과 같은 트리 형태의 데이터 구조로 생성될 수 있습니다.

[source,haskell]
----
data Expr = RZero
          | ROne
          | RAdd Expr Expr
          | RMul Expr Expr
          | RNeg Expr
----

이제 원래의 환 평가자를 다음과 같이 재귀 버전으로 바꿀 수 있습니다.

[source,haskell]
----
evalZ :: Expr -> Integer
evalZ RZero        = 0
evalZ ROne         = 1
evalZ (RAdd e1 e2) = evalZ e1 + evalZ e2
evalZ (RMul e1 e2) = evalZ e1 * evalZ e2
evalZ (RNeg e)     = -(evalZ e)
----

모든 정수를 1들의 합으로 표현해야 한다는 점 때문에 여전히 실용적이지는 않지만, 긴급 상황에서는 쓸 만합니다.

그렇다면 F-대수의 언어로 이러한 표현식 트리를 어떻게 설명할 수 있을까요? 함자 정의에 있는 자유 타입 변수(free type variable)를 그 결과물로 재귀적으로 대체하는 과정을 어떻게든 형식화해야 합니다. 이 과정을 단계별로 진행한다고 상상해 보죠. 먼저 깊이가 1인 트리를 다음과 같이 정의합니다.

[source,haskell]
----
type RingF1 a = RingF (RingF a)
----

우리는 ``RingF`` 정의의 "구멍"들을 ``RingF a``가 생성한 깊이 0인 트리들로 채우고 있습니다. 깊이가 2인 트리 역시 비슷하게 얻을 수 있습니다.

[source,haskell]
----
type RingF2 a = RingF (RingF (RingF a))
----

또는 다음과 같이 쓸 수도 있겠죠.

[source,haskell]
----
type RingF2 a = RingF (RingF1 a)
----

이 과정을 계속 반복하면 다음과 같은 상징적인 방정식을 얻게 됩니다.

[source,haskell]
----
type RingF(n+1) a = RingF (RingFn a)
----

개념적으로 이 과정을 무한히 반복하면 마침내 ``Expr``에 도달하게 됩니다. 여기서 ``Expr``이 stem:[a]에 의존하지 않는다는 점에 주목하세요. 시작점이 어디든 결국 같은 곳에 도달하게 됩니다. 임의의 카테고리 속 임의의 엔도함자에 대해 항상 성립하는 이야기는 아니지만, ``Set`` 카테고리에서는 상황이 좋습니다.

물론 이것은 대략적인 설명일 뿐이며, 나중에 좀 더 엄밀하게 다룰 것입니다.

엔도함자를 무한히 여러 번 적용하면 고정점(fixed point)이 생성됩니다. 고정점은 다음과 같이 정의된 객체입니다.

[source,haskell]
----
Fix f = f (Fix f)
----

이 정의의 직관은 ``Fix f``를 얻기 위해 ``f``를 무한히 여러 번 적용했으므로, 한 번 더 적용해도 아무것도 변하지 않는다는 것입니다. 하스켈에서 고정점의 정의는 다음과 같습니다.

[source,haskell]
----
newtype Fix f = Fix (f (Fix f))
----

논란의 여지가 있지만, 정의되는 타입의 이름과 생성자의 이름이 다른 것이 더 읽기 쉬울 것입니다.

[source,haskell]
----
newtype Fix f = In (f (Fix f))
----

하지만 저는 통용되는 표기법을 따르겠습니다. 생성자 ``Fix`` (또는 원한다면 ``In``)는 함수로 볼 수 있습니다.

[source,haskell]
----
Fix :: f (Fix f) -> Fix f
----

함자 적용의 한 수준을 벗겨내는 함수도 있습니다.

[source,haskell]
----
unFix :: Fix f -> f (Fix f)
unFix (Fix x) = x
----

이 두 함수는 서로의 역원입니다. 나중에 이 함수들을 사용할 것입니다.

== F-대수 카테고리 (Category of F-Algebras)

여기에 가장 오래된 기법이 하나 있습니다. 새로운 객체를 만드는 방법을 고안할 때마다, 그 객체들이 카테고리를 형성하는지 살펴보는 것입니다. 놀랍지 않게도, 주어진 엔도함자 stem:[F]에 대한 대수들은 카테고리를 형성합니다. 이 카테고리의 객체는 대수, 즉 원래 카테고리 stem:[C]에서 온 운반자 객체 stem:[a]와 모피즘 stem:[F a \to a]의 쌍입니다.

그림을 완성하기 위해, F-대수 카테고리에서의 모피즘을 정의해야 합니다. 모피즘은 하나의 대수 stem:[(a, f)]를 다른 대수 stem:[(b, g)]로 매핑해야 합니다. 우리는 이를 원래 카테고리에서 stem:[a]에서 stem:[b]로 가는, 운반자들을 매핑하는 모피즘 stem:[m]으로 정의할 것입니다. 물론 아무 모피즘이나 다 되는 것은 아닙니다. 두 평가 함수(evaluator)와 양립 가능한 모피즘을 원하죠. (우리는 이러한 구조를 보존하는 모피즘을 *준동형 모피즘(homomorphism)*이라고 부릅니다.)

F-대수의 준동형 모피즘을 정의하는 방법은 다음과 같습니다. 먼저 stem:[m]을 다음과 같은 매핑으로 리프트(lift)할 수 있다는 점에 주목하세요.

[source,haskell]
----
F m :: F a -> F b
----

그다음 stem:[g]를 따라 stem:[b]로 갈 수 있습니다. 또는 stem:[f]를 사용하여 stem:[F a]에서 stem:[a]로 이동한 후 stem:[m]을 따라갈 수도 있습니다. 우리는 이 두 경로가 같기를 원합니다.

[source,haskell]
----
g ∘ F m = m ∘ f
----

이것이 실제로 카테고리라는 것을 쉽게 확신할 수 있을 것입니다. (힌트: stem:[C]의 항등 모피즘은 잘 작동하며, 준동형 모피즘의 합성 역시 준동형 모피즘입니다.)

F-대수 카테고리의 초기 객체(initial object)가 존재한다면 이를 *초기 대수(initial algebra)*라고 부릅니다. 이 초기 대수의 운반자를 stem:[i], 평가 함수를 stem:[j \:: F i \to i]라고 합시다. stem:[j], 즉 초기 대수의 평가 함수는 동형 모피즘(isomorphism)임이 밝혀집니다. 이 결과는 *램벡의 정리(Lambek's theorem)*로 알려져 있습니다. 증명은 초기 객체의 정의에 기초하며, 초기 객체에서 다른 임의의 F-대수로 가는 유일한 준동형 모피즘 stem:[m]이 존재해야 한다는 조건을 요구합니다. stem:[m]이 준동형 모피즘이므로 다음 다이어그램이 가환(commute)해야 합니다.

이제 운반자가 stem:[F i]인 대수를 하나 만들어 봅시다. 그러한 대수의 평가 함수는 stem:[F (F i)]에서 stem:[F i]로 가는 모피즘이어야 합니다. 우리는 단순히 stem:[j]를 리프트하여 그러한 평가 함수를 쉽게 만들 수 있습니다.

[source,haskell]
----
F j :: F (F i) -> F i
----

stem:[(i, j)]가 초기 대수이므로, 그로부터 stem:[(F i, F j)]로 가는 유일한 준동형 모피즘 stem:[m]이 반드시 존재해야 합니다. 따라서 다음 다이어그램이 가환해야 합니다.

하지만 다음과 같이 자명하게 가환하는 다이어그램도 존재합니다. (두 경로가 같습니다!)

이는 stem:[j]가 stem:[(F i, F j)]에서 stem:[(i, j)]로 가는 대수의 준동형 모피즘임을 보여주는 것으로 해석할 수 있습니다. 이제 이 두 다이어그램을 하나로 합쳐 봅시다.

이 다이어그램은 다시 stem:[j \circ m]이 대수들의 준동형 모피즘임을 보여주는 것으로 해석될 수 있습니다. 다만 이 경우에는 두 대수가 서로 같습니다. 게다가 stem:[(i, j)]가 초기 대수이므로 자기 자신으로 가는 준동형 모피즘은 단 하나, 즉 항등 모피즘 stem:[id_i]뿐입니다. 이는 준동형 모피즘임을 우리는 알고 있죠. 따라서 stem:[j \circ m = id_i]입니다. 이 사실과 왼쪽 다이어그램의 가환성을 이용하면 stem:[m \circ j = id_{Fi}]임을 증명할 수 있습니다. 이는 stem:[m]이 stem:[j]의 역원이며, 따라서 stem:[j]가 동형 모피즘임을 보여줍니다.

[source,haskell]
----
F i ≅ i
----

결국 이는 stem:[i]가 stem:[F]의 고정점이라는 말입니다. 이것이 바로 원래의 대략적 설명 이면에 있는 형식적인 증명입니다.

하스켈로 돌아와서 생각해 보죠. 우리는 stem:[i]를 ``Fix f``로, stem:[j]를 생성자 ``Fix``로, 그 역원을 ``unFix``로 인식합니다. 램벡의 정리의 동형 모피즘은 초기 대수를 얻기 위해 함자 stem:[f]를 취하고 그 인수 stem:[a]를 ``Fix f``로 대체한다는 사실을 말해줍니다. 또한 고정점이 왜 stem:[a]에 의존하지 않는지도 알 수 있죠.

=== 자연수 (Natural Numbers)

자연수 역시 F-대수로 정의할 수 있습니다. 그 시작점은 다음과 같은 모피즘의 쌍입니다.

[source,haskell]
----
zero :: 1 -> N
succ :: N -> N
----

첫 번째 모피즘은 0을 선택하고, 두 번째 모피즘은 모든 수를 그 다음 수로 매핑합니다. 이전과 마찬가지로 이 둘을 하나로 합칠 수 있습니다.

[source,haskell]
----
1 + N -> N
----

왼쪽 항은 하나의 함자를 정의하며, 이는 하스켈로 다음과 같이 쓸 수 있습니다.

[source,haskell]
----
data NatF a = ZeroF | SuccF a
----

이 함자의 고정점(즉, 함자가 생성하는 초기 대수)은 하스켈에서 다음과 같이 인코딩될 수 있습니다.

[source,haskell]
----
data Nat = Zero | Succ Nat
----

자연수는 0이거나, 다른 수의 후속값(successor)입니다. 이것은 자연수에 대한 *페아노 표현(Peano representation)*으로 알려져 있습니다.

== 카타모피즘 (Catamorphisms)

이제 초기성 조건(initiality condition)을 하스켈 표기법으로 다시 써봅시다. 초기 대수를 ``Fix f``라고 부르겠습니다. 그 평가 함수는 생성자 ``Fix``입니다. 초기 대수에서 같은 함자를 공유하는 다른 임의의 대수로 가는 유일한 모피즘 stem:[m]이 존재합니다. 운반자가 stem:[a]이고 평가 함수가 ``alg``인 대수를 하나 선택해 보겠습니다.

그런데 stem:[m]이 무엇인지 주목해보세요. 이것은 고정점에 대한 평가 함수, 즉 재귀 표현식 트리 전체에 대한 평가 함수입니다. 이를 구현하는 일반적인 방법을 찾아보겠습니다.

램벡의 정리는 생성자 ``Fix``가 동형 모피즘임을 알려줍니다. 그 역원은 ``unFix``라고 불렀죠. 따라서 이 다이어그램에서 화살표 하나의 방향을 뒤집어 다음과 같이 만들 수 있습니다.

이 다이어그램의 가환 조건을 식으로 써보겠습니다.

[source,haskell]
----
m = alg . fmap m . unFix
----

우리는 이 방정식을 stem:[m]에 대한 재귀적 정의로 해석할 수 있습니다. 이 재귀는 함자 stem:[f]를 사용하여 생성된 모든 유한 트리에 대해 반드시 종료됩니다. ``fmap m``이 함자 stem:[f]의 최상위 계층 아래에서 작동한다는 점을 생각하면 이를 알 수 있습니다. 다시 말해, 원래 트리의 자식(children)들에 대해 작동하는 것이죠. 자식들은 항상 원래 트리보다 한 레벨 더 얕습니다.

``Fix f``로 만들어진 트리에 ``m``을 적용하면 어떤 일이 일어나는지 살펴봅시다. ``unFix``의 동작은 생성자를 벗겨내어 트리의 최상위 레벨을 드러냅니다. 그런 다음 최상위 노드의 모든 자식에 ``m``을 적용합니다. 그 결과로 stem:[a] 타입의 값들이 생성됩니다. 마지막으로, 비재귀(non-recursive) 평가 함수 ``alg``를 적용하여 이 결과들을 결합합니다. 여기서 핵심은 평가 함수 ``alg``가 단순한 비재귀 함수라는 점입니다.

어떤 대수 ``alg``에 대해서도 이 작업을 수행할 수 있으므로, 대수를 파라미터로 받아 우리가 stem:[m]이라고 불렀던 함수를 반환해 주는 고차 함수(higher-order function)를 정의하는 것이 합리적입니다. 이 고차 함수를 *카타모피즘(catamorphism)*이라고 부릅니다.

[source,haskell]
----
cata :: Functor f => (f a -> a) -> Fix f -> a
cata alg = alg . fmap (cata alg) . unFix
----

그 예시를 살펴보겠습니다. 자연수를 정의하는 함자를 취합니다.

[source,haskell]
----
data NatF a = ZeroF | SuccF a
----

``(Int, Int)``를 운반자 타입으로 선택하고 대수를 다음과 같이 정의합시다.

[source,haskell]
----
fib :: NatF (Int, Int) -> (Int, Int)
fib ZeroF = (1, 1)
fib (SuccF (m, n)) = (n, m + n)
----

이 대수에 대한 카타모피즘 ``cata fib``가 피보나치 수를 계산한다는 것을 쉽게 확신할 수 있습니다.

일반적으로 ``NatF``에 대한 대수는 재귀 관계를 정의합니다. 즉, 현재 원소의 값을 이전 원소의 관점에서 정의하는 것이죠. 그러면 카타모피즘은 해당 수열의 n번째 원소를 평가합니다.

== Fold (접기)

원소 타입 ``e``를 가진 리스트는 다음 함자의 초기 대수입니다.

[source,haskell]
----
data ListF e a = NilF | ConsF e a
----

실제로 변수 stem:[a]를 재귀의 결과(이를 ``List e``라고 부릅시다)로 대체하면 다음을 얻습니다.

[source,haskell]
----
data List e = Nil | Cons e (List e)
----

리스트 함자에 대한 대수는 특정 운반자 타입을 선택하고, 두 생성자에 대한 패턴 매칭을 수행하는 함수를 정의합니다. ``NilF``에 대한 값은 빈 리스트를 평가하는 방법을 알려주고, ``ConsF``에 대한 값은 현재 원소를 이전에 누적된 값과 결합하는 방법을 알려줍니다.

예를 들어, 리스트의 길이를 계산하는 데 사용될 수 있는 대수가 있습니다 (운반자 타입은 ``Int``).

[source,haskell]
----
lenAlg :: ListF e Int -> Int
lenAlg (ConsF e n) = n + 1
lenAlg NilF = 0
----

실제로 결과 카타모피즘 ``cata lenAlg``는 리스트의 길이를 계산합니다. 평가 함수가 (1) 리스트 원소와 누산기(accumulator)를 받아 새로운 누산기를 반환하는 함수와, (2) 시작값(여기서는 0)의 조합이라는 점에 주목하세요. 값의 타입과 누산기의 타입은 운반자 타입에 의해 결정됩니다.

이를 기존의 하스켈 정의와 비교해 봅시다.

[source,haskell]
----
length = foldr (\e n -> n + 1) 0
----

``foldr``에 전달되는 두 인수는 대수의 두 성분과 정확히 일치합니다.

다른 예시를 시도해 봅시다.

[source,haskell]
----
sumAlg :: ListF Double Double -> Double
sumAlg (ConsF e s) = e + s
sumAlg NilF = 0.0
----

이 역시 다음 코드와 비교해 보세요.

[source,haskell]
----
sum = foldr (\e s -> e + s) 0.0
----

보시다시피 ``foldr``는 리스트에 특화된 카타모피즘의 편리한 버전일 뿐입니다.

== 코대수 (Coalgebras)

평소처럼, 모피즘의 방향을 뒤집은 *F-코대수(F-coalgebra)*라는 쌍대(dual) 구성이 있습니다.

[source,haskell]
----
a -> F a
----

주어진 함자에 대한 코대수들 역시 카테고리를 형성하며, 준동형 모피즘은 코대수의 구조를 보존합니다. 이 카테고리의 종단 객체(terminal object) stem:[(t, u)]를 *종단(또는 최종) 코대수(terminal (or final) coalgebra)*라고 부릅니다. 다른 모든 대수 stem:[(a, f)]에서 종단 코대수로 가는 유일한 준동형 모피즘 stem:[m]이 존재하여 다음 다이어그램을 가환하게 만듭니다.

종단 코대수는 함자의 고정점입니다. 즉, 모피즘 stem:[u \:: t \to F t]는 동형 모피즘입니다 (코대수에 대한 램벡의 정리).

[source,haskell]
----
F t ≅ t
----

프로그래밍에서 종단 코대수는 대개 (무한할 수도 있는) 데이터 구조나 전이 시스템(transition system)을 생성하는 레시피로 해석됩니다.

카타모피즘이 초기 대수를 평가하는 데 사용될 수 있는 것처럼, *아나모피즘(anamorphism)*은 종단 코대수를 코평가(coevaluate)하는 데 사용될 수 있습니다.

[source,haskell]
----
ana :: Functor f => (a -> f a) -> a -> Fix f
ana coalg = Fix . fmap (ana coalg) . coalg
----

코대수의 전형적인 예시는 원소 타입 ``e``의 무한 스트림을 고정점으로 갖는 함자를 기반으로 합니다. 다음 함자죠.

[source,haskell]
----
data StreamF e a = StreamF e a
  deriving Functor
----

그리고 이 함자의 고정점은 다음과 같습니다.

[source,haskell]
----
data Stream e = Stream e (Stream e)
----

``StreamF e``에 대한 코대수는 타입 ``a``인 시드(seed)를 받아, 원소와 다음 시드로 구성된 쌍(``StreamF``는 쌍의 세련된 이름입니다)을 생성하는 함수입니다.

제곱수의 리스트나 역수의 리스트처럼 무한 수열을 생성하는 코대수의 간단한 예시들을 쉽게 만들 수 있습니다.

좀 더 흥미로운 예는 소수의 리스트를 생성하는 코대수입니다. 묘수는 무한 리스트를 운반자로 사용하는 것입니다. 시작 시드는 ``[2..]`` 리스트입니다. 다음 시드는 이 리스트의 꼬리(tail)에서 2의 모든 배수를 제거한 리스트가 됩니다. 즉, 3으로 시작하는 홀수들의 리스트죠. 다음 단계에서는 이 리스트의 꼬리를 가져와 3의 모든 배수를 제거하는 식으로 계속됩니다. 에라토스테네스의 체(sieve of Eratosthenes)의 원리를 인식할 수 있을 것입니다. 이 코대수는 다음 함수로 구현됩니다.

[source,haskell]
----
era :: [Int] -> StreamF Int [Int]
era (p : ns) = StreamF p (filter (notdiv p) ns)
    where notdiv p n = n `mod` p /= 0
----

이 코대수에 대한 아나모피즘은 소수의 리스트를 생성합니다.

[source,haskell]
----
primes = ana era [2..]
----

스트림은 무한 리스트이므로, 이를 하스켈 리스트로 변환할 수 있어야 합니다. 이를 위해 동일한 ``StreamF`` 함자를 사용하여 대수를 만들고, 그 위에서 카타모피즘을 실행할 수 있습니다. 예를 들어 다음은 스트림을 리스트로 변환하는 카타모피즘입니다.

[source,haskell]
----
toListC :: Fix (StreamF e) -> [e]
toListC = cata al
   where al :: StreamF e [e] -> [e]
         al (StreamF e a) = e : a
----

여기서 동일한 고정점이 동일한 엔도함자에 대해 초기 대수이자 종단 코대수 역할을 동시에 하고 있습니다. 임의의 카테고리에서 항상 이런 일이 벌어지는 것은 아닙니다. 일반적으로 엔도함자는 여러 개의 고정점(또는 고정점이 전혀 없을 수도)을 가질 수 있습니다. 초기 대수는 이른바 *최소 고정점(least fixed point)*이고, 종단 코대수는 *최대 고정점(greatest fixed point)*입니다. 하지만 하스켈에서는 두 고정점이 같은 공식으로 정의되며 서로 일치합니다.

리스트에 대한 아나모피즘은 ``unfold``라고 불립니다. 유한 리스트를 생성하기 위해 함자는 ``Maybe`` 쌍을 생성하도록 수정됩니다.

[source,haskell]
----
unfoldr :: (b -> Maybe (a, b)) -> b -> [a]
----

``Nothing`` 값은 리스트 생성을 종료합니다.

코대수의 흥미로운 사례는 렌즈와 관련이 있습니다. 렌즈는 게터(getter)와 세터(setter)의 쌍으로 표현될 수 있습니다.

[source,haskell]
----
set :: a -> s -> a
get :: a -> s
----

여기서 ``a``는 대개 타입 ``s``의 필드를 가진 곱 데이터 타입입니다. 게터는 그 필드의 값을 가져오고, 세터는 해당 필드를 새로운 값으로 교체합니다. 이 두 함수는 하나로 합쳐질 수 있습니다.

[source,haskell]
----
a -> (s, s -> a)
----

이 함수를 더 고쳐 쓰면 다음과 같습니다.

[source,haskell]
----
a -> Store s a
----

여기서 우리는 다음과 같은 함자를 정의했습니다.

[source,haskell]
----
data Store s a = Store (s -> a) s
----

이는 곱의 합으로 만들어진 단순한 대수적 함자가 아니라는 점에 주목하세요. 여기에는 지수(exponential) stem:[a^s]가 포함되어 있습니다.

렌즈는 운반자 타입 ``a``를 가진 이 함자의 코대수입니다. 우리는 이전에 ``Store s``가 코모나드이기도 하다는 것을 보았습니다. 잘 동작하는(well-behaved) 렌즈는 코모나드 구조와 양립하는 코대수에 해당함이 밝혀집니다. 다음 섹션에서 이에 대해 이야기하겠습니다.
