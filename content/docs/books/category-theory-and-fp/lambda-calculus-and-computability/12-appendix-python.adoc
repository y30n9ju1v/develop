이 부록은 본문과 독립적입니다 — 건너뛰어도 이 책을 이해하는 데 전혀 지장이 없습니다. 본문이 논증만으로 보여준 것들을, 파이썬의 `lambda`(2장에서 본 그 `λ`입니다)로 실제로 실행해 확인합니다. 새 개념은 없습니다 — 지금까지 읽은 걸 코드로 다시 확인할 뿐입니다.

== 처치 수와 후속자

[source,python]
----
# 처치 수: n은 "함수 f를 n번 적용하는 함수"
ZERO = lambda f: lambda x: x

def succ(n):
    return lambda f: lambda x: f(n(f)(x))

def to_int(n):
    return n(lambda x: x + 1)(0)   # f를 "1 더하기"로, x를 0으로 두면 몇 번 적용됐는지 셀 수 있다

def from_int(k):
    n = ZERO
    for _ in range(k):
        n = succ(n)
    return n
----

`to_int`는 3장에서 다루지 않은 작은 트릭입니다 — 처치 수에게 "1을 더하는 함수"를 `f`로, `0`을 `x`로 건네주면, 그 처치 수가 몇 번 반복하는 절차였는지가 실제 정수로 드러납니다.

== 더하기: 실제로 5가 나오는가

[source,python]
----
TWO = from_int(2)
THREE = from_int(3)

def church_add(m, n):
    return m(succ)(n)   # 3장: "m이 정의한 횟수만큼, succ를 n에 적용한다"
----

[source]
----
>>> to_int(TWO)
2
>>> to_int(THREE)
3
>>> to_int(church_add(TWO, THREE))
5
----

3장에서 논증만으로 따라갔던 "재귀도 뺄셈도 없는 더하기"가, 실제로 `2 + 3 = 5`를 계산해냅니다.

== 참/거짓과 if

[source,python]
----
TRUE = lambda t: lambda f: t     # 4장: 첫 번째를 고른다
FALSE = lambda t: lambda f: f    # 4장: 두 번째를 고른다

def church_if(cond, then_branch, else_branch):
    return cond(then_branch)(else_branch)   # 새 규칙 없이, 조건에 두 선택지를 그냥 넣는다
----

[source]
----
>>> church_if(TRUE, "yes", "no")
'yes'
>>> church_if(FALSE, "yes", "no")
'no'
----

4장에서 말한 대로, `church_if`는 `cond` 자리에 온 함수(`참` 또는 `거짓`)에 두 선택지를 순서대로 넣어보는 것 말고 아무것도 하지 않습니다.

== Y 콤비네이터: 이름 없이 재귀하기

파이썬은 값을 즉시 계산하는 언어라서, 5장에서 설명한 순수한 형태의 Y 콤비네이터를 그대로 쓰면 무한 재귀에 빠져버립니다. 대신 이 문제를 피하도록 살짝 손본 버전(**Z 콤비네이터**라고 부릅니다 — 게으르게 평가하는 언어라면 원래 형태의 Y 콤비네이터를 그대로 쓸 수 있습니다)을 씁니다. 핵심 아이디어(자기 자신에게 함수를 적용하는 것)는 그대로입니다.

[source,python]
----
Z = lambda f: (lambda x: f(lambda v: x(x)(v)))(lambda x: f(lambda v: x(x)(v)))

def fact_gen(self_fact):
    # self_fact가 "팩토리얼처럼 동작하는 도구"다 -- 5장에서 조수에게 건넨 그 도구.
    # fact_gen 자신은 어디에도 자기 이름을 참조하지 않는다.
    return lambda n: 1 if n == 0 else n * self_fact(n - 1)

factorial = Z(fact_gen)
----

[source]
----
>>> factorial(5)
120
----

`fact_gen`이라는 함수 정의 어디에도 `factorial`이라는 이름이 등장하지 않습니다 — `self_fact`는 그냥 매개변수 이름일 뿐, `fact_gen`이 자기 자신을 가리키는 진짜 방법은 `Z`가 5장에서 설명한 자기 적용으로 뒤에서 조달해줍니다. 그런데도 `factorial(5)`는 정확히 `120`을 계산해냅니다 — 5장에서 "역설처럼 보였던" 이름 없는 재귀가, 실제로 동작한다는 걸 확인했습니다.

== 요약

* 처치 수와 후속자로 만든 덧셈이 실제로 `2 + 3 = 5`를 계산한다는 걸 실행으로 확인했습니다.
* 참/거짓을 "선택하는 함수"로 정의한 것만으로 `if`가 새 규칙 없이 동작한다는 것도 확인했습니다.
* 이름을 한 번도 쓰지 않은 `fact_gen`이, Z 콤비네이터(파이썬에 맞게 손본 Y 콤비네이터)를 통과하는 것만으로 실제로 재귀하는 `factorial`이 된다는 걸 `factorial(5) == 120`으로 확인했습니다.

이 부록에서 다룬 것은 본문 2~5장이 논증으로 보여준 것의 아주 작은 확인일 뿐입니다 — 더 깊이 파고들고 싶다면, 실제 람다 계산식을 그대로 축약해나가는 인터프리터를 직접 짜보는 것도 좋은 다음 걸음입니다.
