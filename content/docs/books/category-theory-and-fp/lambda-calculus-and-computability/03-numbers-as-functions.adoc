2부가 여기서 시작됩니다. 

우리의 첫 번째 거대한 도전 과제는 바로 **"오직 함수만으로 숫자를 창조해내는 것"**입니다.

== 발상의 전환: 숫자는 사물이 아니라 '반복 횟수'다

우리는 보통 숫자 `3`을 사과 3개나 손가락 3개 같은 '구체적인 물건의 개수'로 생각합니다.

하지만 람다 계산법에는 물건이나 메모리 상자 같은 것이 없습니다. 오직 함수뿐입니다. 그래서 처치는 기발한 발상의 전환을 해냈습니다.

> **"숫자 3이란, 어떤 행동을 3번 반복해서 실행하는 절차 그 자체가 아닐까?"**

예를 들어 "문 두드리기"라는 행동(`f`)이 있고 시작 상태(`x`)가 있다면, 숫자 `3`은 **"문을 똑, 똑, 똑 세 번 두드리는 동작"**으로 정의할 수 있습니다. 숫자가 정적인 명사가 아니라 **역동적인 동사(행동 절차)**가 되는 것입니다.

이 아이디어로 만든 숫자를 창시자의 이름을 따서 **처치 수(Church Numeral)**라고 부릅니다.

....
 [처치 수의 구조]
  함수 f(할 일)와 시작값 x(출발점)를 받아서, f를 n번 겹쳐서 실행한다!

   0 :  λf. λx. x                 (f를 0번 적용, x 그대로 반환)
   1 :  λf. λx. f x               (f를 1번 적용)
   2 :  λf. λx. f (f x)           (f를 2번 적용)
   3 :  λf. λx. f (f (f x))       (f를 3번 적용)
   n :  λf. λx. f (f (...(f x)))  (f를 n번 적용)
....

* 숫자 `0`은 "`f`를 한 번도 쓰지 않고 시작값 `x`를 그대로 돌려주는 함수"입니다.
* 숫자 `1`은 "`f`를 딱 1번 적용하는 함수"입니다.
* 숫자 `2`는 "`f`를 2번 중첩해서 적용하는 함수"입니다.

[NOTE]
====
**처치 수는 왜 `f`와 `x` 두 개의 인자를 받나요?**  
`f`는 "반복할 구체적인 동작"이고, `x`는 "그 동작을 시작할 출발점(초기값)"입니다. 즉, 처치 수는 "무슨 행동(`f`)을 어디서부터(`x`) 반복할지" 전달받을 준비가 된 완벽한 템플릿입니다.
====

== 다음 숫자로 넘어가기: 후속자 (Successor)

숫자 `3`이 있다면, 그 다음 숫자인 `4`는 어떻게 만들 수 있을까요?

간단합니다. "`f`를 3번 적용하는 함수"의 바깥쪽에 **"`f`를 딱 1번 더 감싸주는 일"**을 하면 됩니다. 이렇게 어떤 숫자를 받아 그 다음 숫자(1을 더한 숫자)를 만들어내는 함수를 **후속자(successor, 줄여서 `succ`)**라고 부릅니다.

....
                 [ 후속자(succ)의 동작 원리 ]

      어떤 처치 수 n               바깥에 f를 1번 더 감싼다!
   ┌──────────────────┐           ┌────────────────────────┐
   │ λf. λx. f (f x)  │  ──succ──►│ λf. λx. f ( f (f x) )   │
   └──────────────────┘           └────────────────────────┘
          (숫자 2)                           (숫자 3)
....

후속자 함수는 숫자의 본질을 몰라도 됩니다. 그저 "입력받은 수 `n`이 하는 일에 `f`를 한 번 더 얹어준다"는 규칙만 있으면, `0`에서 출발해 후속자를 누적해서 적용하는 것만으로 `1, 2, 3, 4...` 모든 자연수를 무한히 만들어낼 수 있습니다.

== 더하기: 2 + 3은 어떻게 계산할까?

이제 두 숫자 `2`와 `3`을 더해봅시다. 우리는 보통 초등학교에서 자릿수를 맞추거나 손가락을 꼽으며 덧셈을 배웁니다. 하지만 람다 계산법에서는 상상 이상으로 우아하게 해결됩니다.

처치 수 `2`의 본질을 다시 떠올려보세요. **`2`는 "어떤 함수를 2번 반복 실행하는 기계"**였습니다. 그렇다면 이렇게 하면 어떨까요?

> **"`3`이라는 숫자를 손에 쥐고, 그 위에 '후속자(1 더하기)'를 `2`번 실행한다!"**

....
                    [ 처치 수 덧셈 (2 + 3) ]

              후속자(succ)를 '2번' 반복해서 '3'에 적용한다!

                         2   succ   3
                         │     │    │
                         ▼     ▼    ▼
                       succ ( succ  3 )
                       ────┬─────────
                           │ 3에 1을 더하면 4!
                           ▼
                         succ  4
                         ────┬──
                             │ 4에 1을 더하면 5!
                             ▼
                             5
....

놀랍지 않습니까?
`2 + 3`을 계산하기 위해 새로운 복잡한 덧셈 기계를 발명할 필요가 전혀 없었습니다. 숫자 `2` 자체가 이미 "2번 반복하는 기계"였기 때문에, 반복할 함수 자리에 **후속자(`succ`)**를 넣고 시작값 자리에 **`3`**을 넣기만 하면 자연스럽게 `5`가 튀어나옵니다.

== 왜 이것이 혁명적인가?

우리가 지금까지 사용한 재료를 되돌아봅시다.

* 우리가 쓴 것: **함수 만들기(`λ`)**, **함수 대입하기(`적용`)** 단 두 가지!
* 우리가 만들어낸 것: **모든 자연수(`0, 1, 2, 3...`)**, **1 더하기(`succ`)**, **덧셈(`add`)**

숫자를 저장할 메모리 칩도, CPU의 덧셈 연산 장치(ALU)도 필요 없었습니다. 오직 "함수를 어떻게 조합하는가"라는 순수한 논리적 규칙만으로 무(無)에서 완벽한 산술 체계를 건설한 것입니다.

== 요약

* **처치 수**: 숫자를 "어떤 함수 `f`를 시작값 `x`에 몇 번 반복 적용할 것인가"라는 실행 절차로 정의합니다.
* **후속자 (`succ`)**: 기존 숫자의 실행 절차 바깥에 `f`를 1번 더 씌워 다음 숫자를 만드는 함수입니다.
* **덧셈**: 숫자 `m`의 반복 능력을 그대로 이용하여, 숫자 `n`에 후속자 함수를 `m`번 연속 적용하는 방식으로 덧셈을 수행합니다.

[TIP]
====
**곱셈(`2 × 3`)은 어떻게 생각할 수 있을까?**  
덧셈이 "후속자를 2번 반복"하는 것이었다면, 곱셈 `2 × 3`은 **"3을 더하는 동작을 2번 반복"**하는 것으로 아주 자연스럽게 확장할 수 있습니다. 람다 계산법에서는 모든 복잡한 연산이 이처럼 단순한 반복의 반복으로 아름답게 풀려나갑니다.
====
