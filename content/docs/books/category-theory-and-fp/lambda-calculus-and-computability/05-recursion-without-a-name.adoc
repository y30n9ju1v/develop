'''

프로그래밍에서 반복문을 흉내 내거나 팩토리얼(`n!`)을 계산할 때 가장 강력한 도구가 바로 **재귀(Recursion)**입니다.

예를 들어 팩토리얼은 보통 이렇게 정의합니다.
> "`factorial(n)`은 `n`이 `0`이면 `1`을 돌려주고, 아니면 `n * factorial(n - 1)`을 계산한다."

이 정의를 유심히 보면, 함수 본문 안에서 **`factorial`이라는 자기 자신의 이름**을 직접 부르고 있습니다.

그런데 2장에서 배운 람다 계산법의 기본 규칙을 떠올려 보세요. **람다 계산법의 함수에는 애초에 '이름'이라는 개념이 없습니다.** `λx. x`는 그저 규칙 덩어리일 뿐, 스스로를 가리킬 명찰이 존재하지 않습니다.

> **이름이 없는 함수가, 어떻게 자기 자신을 다시 호출할 수 있을까요?**

이 불가능해 보이는 역설을 풀어내는 과정은 람다 계산법에서 가장 극적이고 아름다운 순간입니다.

== 1단계: 나 자신을 '이름'이 아니라 '인자'로 받기

먼저 발상을 바꾸어 봅시다. 팩토리얼 함수가 직접 자기 자신을 부르는 대신, **"다음 재귀 단계에서 대신 일해줄 도구(조수)"를 외부에서 인자로 건네받는 방식**으로 함수를 만듭니다.

....
                 [ 1단계: 조수를 건네받는 함수 (fact_gen) ]

    λ조수. λn. if (n == 0) then 1 else (n * 조수(n - 1))
      ▲                                       │
      └───────────────────────────────────────┘
          "재귀 호출이 필요할 때, 내 이름을 부르는 대신
           밖에서 건네받은 '조수'에게 다음 계산을 맡긴다"
....

이 함수 자체에는 아무런 재귀도 없습니다. 자기 이름을 부르지도 않습니다. 그저 "외부에서 `조수`라는 함수 하나를 넘겨주면, 그걸 이용해 1단계를 계산하는 평범한 함수"일 뿐입니다.

그런데 이제 진짜 문제가 생겼습니다.
> **이 조수 자리에 건네줄 '팩토리얼처럼 동작하는 도구'는 대체 어디서 구해와야 할까요?**

== 2단계: 마법의 열쇠 — 함수를 자기 자신에게 적용하기

여기서 람다 계산법만의 천재적인 트릭이 등장합니다. 바로 **"함수에게 그 함수 자기 자신을 인자로 먹이는 것(Self-Application)"**입니다.

2장에서 우리는 함수에 `사과`도 넣어보고 `바나나`도 넣어보았습니다. 함수도 하나의 값에 불과하므로, **함수에 함수 자기 자신을 넣지 못할 이유가 전혀 없습니다.**

....
    어떤 함수 h가 있을 때:  h  h   (h를 h 자신에게 대입한다)
....

이 "자기 적용"을 활용하여 다음과 같은 기막힌 장치를 만듭니다.

> "함수 `x`를 받아서, `x`를 `x` 자신에게 대입한 결과(`x x`)를 아까 만든 공장에 건네주는 함수를 만든 뒤, **그 함수를 통째로 자기 자신에게 대입한다.**"

....
          [ 자기 적용이 만들어내는 무한한 도구의 샘물 ]

    ( λx. 조수_공장 (x x) )  ( λx. 조수_공장 (x x) )
      ───────┬───────────    ───────────────────────
             │                     ▲
             └──── 인자로 쏙 들어감 ──┘
                     ▼
       조수_공장 ( (λx. ...) (λx. ...) )
                     ▲
                     └─ 처음의 그 모양이 그대로 다시 복제됨
....

첫 번째 괄호의 `x` 자리에 두 번째 괄호가 쏙 대입되는 순간, **바깥쪽에 `조수_공장`이 한 겹 껍질처럼 벗겨져 나오면서 안쪽에는 처음과 똑같은 모양의 표현식이 다시 복제**됩니다.

== 3단계: Y 콤비네이터의 완성

이 장치가 바로 컴퓨터 과학 역사상 가장 유명한 함수 중 하나인 **Y 콤비네이터 (Y Combinator)**입니다.

....
    Y = λf. (λx. f (x x)) (λx. f (x x))
....

Y 콤비네이터에 아까 만든 팩토리얼 공장(`F`)을 넣으면 다음과 같은 기적이 일어납니다.

....
    Y F  ──►  F (Y F)  ──►  F (F (Y F))  ──►  F (F (F (Y F))) ...
....

1. `Y F`를 계산하면 `F`의 인자로 다시 `Y F`가 들어갑니다.
2. 팩토리얼 계산 도중 다음 단계의 조수가 필요할 때마다, `Y`가 자기 복제를 일으켜 **새로운 조수를 무한히 샘솟듯 길어 올려 줍니다.**
3. 마침내 `n == 0`이 되어 더 이상 조수가 필요 없는 기저 조건(Base Case)에 도달하면, 조수 호출을 멈추고 `1`을 반환하며 전체 계산이 끝납니다.

[NOTE]
====
**무한 루프에 빠져 영원히 멈추지 않는 것 아닌가요?**  
`n == 0`일 때 조수를 호출하지 않고 바로 `1`을 반환하도록 `if` 조건을 짜두었기 때문에, 무한히 복제되던 고리는 `0`에 도달하는 순간 뚝 끊어집니다. 필요한 만큼만 조수를 꺼내 쓰고 멈추는 것입니다.
====

== 이게 왜 역사적인 발견인가?

Y 콤비네이터 자체의 정의를 다시 찬찬히 뜯어보세요.
`Y` 안에는 **그 어떤 재귀도, 그 어떤 이름도 적혀있지 않습니다.**

오직 "함수를 만들고, 함수를 자기 자신에게 대입한다"는 단 하나의 조작만으로, **영원히 스스로를 복제하며 되풀이하는 '재귀 구조'를 무(無)에서 완벽히 창조**해 낸 것입니다.

프로그래밍 언어들이 편의를 위해 제공하는 `function factorial()` 같은 이름표는, 사실 이론적으로 전혀 필요 없는 편리한 껍데기에 불과했다는 사실이 증명된 순간입니다.

== 요약

* **재귀의 역설**: 람다 계산법에는 이름이 없어서 자기 자신을 직접 호출할 수 없습니다.
* **조수 패턴**: 재귀 호출 자리에 대신 들어갈 도구(조수)를 인자로 받는 껍데기 함수를 만듭니다.
* **자기 적용과 Y 콤비네이터**: 함수를 자기 자신에게 대입하는 기교(`x x`)를 통해, 이름 없이도 필요할 때마다 다음 단계의 함수를 무한히 길어 올리는 **고정점 결합자(Y Combinator)**를 완성했습니다.

[TIP]
====
**생각해보기**:  
거울 두 개를 서로 마주 보게 놓으면 거울 속에 거울이 끝없이 비치는 무한한 터널이 생깁니다. Y 콤비네이터의 `x x`(함수가 자기 자신을 비추는 것)는 바로 이 두 개의 거울과 같습니다.
====
