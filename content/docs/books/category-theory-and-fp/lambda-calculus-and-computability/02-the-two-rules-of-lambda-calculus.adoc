람다 계산법(Lambda Calculus)의 세상에는 오직 단 하나의 재료만 존재합니다. 바로 **함수**입니다.

그리고 이 세계에서 우리가 할 수 있는 행동도 딱 두 가지뿐입니다.

1. **함수를 만드는 것 (추상화)**
2. **함수에 무언가를 넣어보는 것 (적용)**

이 두 가지 규칙만으로 덧셈, 곱셈, 논리 연산, 재귀까지 모든 것을 해냅니다. 어떻게 그것이 가능한지 기본 규칙부터 살펴봅시다.

== 규칙 1: 함수 만들기 (추상화)

"어떤 것을 받아서, 그것을 그대로 돌려주는 함수"를 만든다고 해봅시다.

일반적인 프로그래밍 언어라면 `function identity(x) { return x; }`처럼 함수의 이름을 짓겠지만, 람다 계산법에서는 **이름을 붙일 필요조차 없습니다.** 그저 "받은 것을 그대로 돌려준다"는 규칙 자체가 함수입니다.

이를 람다 기호(`λ`, 그리스 문자 람다)를 써서 다음과 같이 적습니다.

....
           λ x .  x
           ──┬── ─┬─
             │    └─ 본문 (Body): "받은 x를 그대로 돌려준다"
             └────── 매개변수 선언: "x라는 입력을 받겠다"
....

* `λx.`는 "`x`라는 입력을 받겠다"는 선언입니다.
* 뒤에 오는 `x`는 "받은 그것을 그대로 결과로 내놓겠다"는 본문입니다.

이렇게 구체적인 값 대신 형태나 패턴 자체를 함수로 정의하는 행위를 **추상화(abstraction)**라고 부릅니다.

마치 **붕어빵 틀**을 만드는 것과 같습니다. 아직 틀 안에 팥을 넣을지 슈크림을 넣을지 정하지 않았지만, "무엇이든 반죽을 넣으면 붕어빵 모양으로 찍어낸다"는 틀(규칙) 자체는 이미 완성되어 있는 것입니다.

== 규칙 2: 함수에 넣어보기 (적용)

이제 완성된 붕어빵 틀에 재료를 넣어봅시다.

`λx. x`라는 함수에 `사과`를 넣는 것을 람다 계산법에서는 괄호를 써서 **`(λx. x) 사과`**라고 나란히 적습니다. 이 함수는 "받은 것을 그대로 돌려주는" 함수이므로, 결과는 당연히 `사과`가 됩니다.

이렇게 함수에 입력값을 전달하여 결과를 얻는 행위를 **적용(application)**이라고 부릅니다.

== 유일한 계산 메커니즘: 베타 축약 (Beta Reduction)

함수를 만들고(추상화), 그 함수에 무언가를 넣으면(적용), 드디어 **계산**이 일어납니다.

`(λx. x) 사과`가 `사과`라는 결과로 바뀌는 이 한 걸음의 계산 과정을 **베타 축약(β-reduction)**이라고 부릅니다.

....
    ( λ x .  x )  사과
        │    │     ▲
        │    └─────┘   [ x 자리에 '사과'를 대입! ]
        └─────────────
              ▼
            사과
....

원리는 아주 단순합니다.
> **"함수의 본문에서, 입력으로 받기로 한 변수 이름(`x`)이 나오는 모든 자리를, 실제로 전달받은 값(`사과`)으로 쏙 바꿔치기(대입)한다."**

람다 계산법의 모든 계산은 덧셈이든, 곱셈이든, 조건문이든, 복잡한 재귀이든 간에 **이 베타 축약 하나를 몇 번이고 반복하는 것**이 전부입니다.

== 인자가 2개 이상일 때는? 커링 (Currying)

그런데 실생활에서는 "두 수를 더하는 함수"처럼 인자를 2개 이상 받는 함수가 필요합니다. 람다 계산법은 항상 입력을 딱 1개만 받도록 설계되었는데, 어떻게 여러 개의 입력을 처리할까요?

답은 **"함수가 또 다른 함수를 돌려주게 만드는 것"**입니다.

예를 들어, "첫 번째 받은 것은 기억해 두고, 두 번째 받은 것은 무시한 채 첫 번째 것만 돌려주는 함수"를 만들어 봅시다.

....
    λx. λy. x
....

이 함수에 `사과`와 `바나나`를 차례대로 넣어봅시다: `((λx. λy. x) 사과) 바나나`

....
 1단계: 사과를 먼저 넣는다
   ( λx. (λy. x) ) 사과  ──[베타 축약: x 자리에 사과 대입]──►  λy. 사과
   (결과: "무엇을 받든 사과를 돌려주는" 새로운 함수가 탄생함!)

 2단계: 그 결과 함수에 바나나를 넣는다
   ( λy. 사과 ) 바나나  ──[베타 축약: y 자리에 바나나 대입]──►  사과
   (y는 본문에 쓰이지 않으므로 바나나는 버려지고 '사과'만 남음)
....

이처럼 여러 개의 인자를 받는 함수를 **"인자를 하나씩 받아서 다음 함수를 반환하는 함수의 연쇄"**로 표현하는 방식을 **커링(Currying)**이라고 부릅니다.

[NOTE]
====
**흔히 헷갈리는 지점: 변수 이름이 겹치면 어떻게 하나요?**  
`λx. x`와 `λy. y`는 이름만 다를 뿐 완전히 똑같이 "받은 것을 그대로 돌려주는 함수"입니다. 만약 바깥의 변수 이름과 안쪽의 변수 이름이 우연히 겹쳐서 헷갈릴 때는, 충돌하지 않도록 안쪽 변수의 이름을 `z`나 `w`로 안전하게 바꾸어 주면 됩니다. 이 변수 이름 바꾸기 규칙을 **알파 변환(α-conversion)**이라고 부릅니다.
====

== 이것만으로 정말 충분할까?

* **재료**: 함수 만들기(`λ`), 함수에 대입하기(`적용`)
* **계산 규칙**: 베타 축약 (바꿔치기)

정말 이 두 가지만으로 숫자, 덧셈, 참/거짓, `if`문, 반복문까지 전부 만들어낼 수 있을까요?

언뜻 보면 "숫자 `0` 하나도 없는데 어떻게 계산을 한단 말인가?" 하고 의심이 들 수 있습니다. 하지만 2부에서 바로 이 의문을 정면으로 돌파합니다. 아무것도 없는 백지상태에서 순수한 함수만으로 현대 컴퓨터의 모든 빌딩 블록을 조립해 내는 마법이 펼쳐집니다.

== 요약

* **추상화 (`λx. 본문`)**: 이름을 붙이지 않고 규칙 자체를 정의하여 함수를 만드는 것입니다.
* **적용 (`(함수) 값`)**: 만들어진 함수에 인자를 건네는 것입니다.
* **베타 축약**: 본문 속 변수를 전달받은 값으로 치환하는 유일한 계산 규칙입니다.
* **커링**: 단일 인자 함수를 겹겹이 중첩하여 다중 인자를 처리하는 기법입니다.

[TIP]
====
**직접 손으로 축약해보기**:  
"두 번째로 받은 것만 돌려주는 함수"는 `λx. λy. y`입니다. 이 함수에 `사과`와 `바나나`를 순서대로 넣었을 때(`((λx. λy. y) 사과) 바나나`), 베타 축약 2단계를 거쳐 최종적으로 `바나나`가 남는 과정을 종이에 직접 단계별로 적어보세요!
====

1부가 끝났습니다. 이제 2부에서는 이 두 가지 규칙만으로 숫자를 만들어 냅니다.
