6장에서 우리는 섀넌이 증명한 "속도를 깎아먹지 않고도 오류를 없앨 수 있는 마법의 부호가 존재한다"는 약속을 보았습니다.

이제 이 약속을 현실로 바꾸는 구체적인 엔지니어링의 정수, **오류 정정 부호(Error-Correcting Code, ECC)**를 직접 조립해 봅시다.

== 1단계: 오류 감지만 가능한 단순 패리티 비트

`1011`이라는 4비트 데이터를 보낸다고 해봅시다.

여기에 맨 끝에 비트 1개를 덧붙이는데, **"데이터 안의 1의 개수가 짝수이면 0, 홀수이면 1"**을 붙이기로 약속합니다. 이것을 **패리티 비트(Parity Bit, 홀짝 검사 비트)**라고 부릅니다.

* 보낸 데이터: `1011` (1이 3개로 홀수) $\rightarrow$ 패리티 `1`을 붙여 **`10111`** 전송

수신자가 받은 데이터를 검사했을 때:
* 만약 전송 중 1비트가 뒤집혀 `10011`이 도착했다면? $\rightarrow$ 1의 개수가 3개(홀수)여야 하는데 2개(짝수)가 되었으므로, **"신호에 오류가 발생했다!"는 사실을 즉시 감지**해 냅니다.

하지만 이 단순 패리티에는 치명적인 한계가 있습니다.  
**"뭔가 틀렸다는 건 알겠는데, 5개의 비트 중 도대체 몇 번째 비트가 뒤집혔는지는 전혀 알 수가 없다!"**는 점입니다. 따라서 수신자가 할 수 있는 일은 "처음부터 다시 보내주세요(재전송)"라고 요청하는 것뿐입니다.

== 2단계: 패리티를 겹쳐서 '오류의 위치'까지 짚어내기

여기서 리처드 해밍(Richard Hamming)이라는 천재가 기막힌 아이디어를 냈습니다.

> **"패리티 비트를 가로와 세로, 두 방향으로 겹쳐서 십자 검사를 하면 어떻게 될까?"**

4비트 데이터(`1, 0, 1, 1`)를 **2x2 바둑판 격자**에 배치해 봅시다.

....
                   [ 2차원 격자 패리티의 오류 위치 특정 ]

     【 송신 시 2x2 격자 및 가로/세로 패리티 생성 】
                1열   2열   [가로 패리티]
         1행     1     0   ──►  1 (1이 1개, 홀수)
         2행     1     1   ──►  0 (1이 2개, 짝수)
                 │     │
                 ▼     ▼
     [세로 패리티] 0     1   (총 8비트 전송: 1 0 1 1 + 1 0 0 1)
────────────────────────────────────────────────────────────────────────
     【 수신 시 잡음 발생: 2행 1열의 비트가 '0'으로 뒤집힘 】
                1열   2열   [수신된 패리티]  [실제 계산]    [판정]
         1행     1     0         1              1          정상
         2행   【0】   1         0              1     ──► 【2행 에러】
                 │     │
                 ▼     ▼
     [수신 패리티] 0     1
     [실제 계산]   1     1
     [판정]     【1열 에러】 정상
                                    │
                                    ▼
       【 십자 교차점: [2행] × [1열] = 다름 아닌 바로 저 '0'이 범인이다 】
       ──► "다시 보낼 필요 없이, 저 비트를 즉시 '1'로 뒤집어서 고친다"
....

가로 패리티 검사관이 "2행이 이상합니다!"라고 외치고, 세로 패리티 검사관이 "1열이 이상합니다!"라고 외칩니다.

두 검사관의 시선이 교차하는 지점은 **정확히 '2행 1열' 단 한 칸**입니다

오류가 난 위치를 정확히 짚어냈으므로, 수신자는 **재전송 요청을 할 필요도 없이 그 자리에서 비트를 반대로 뒤집어 완벽하게 원본을 즉시 복원(오류 정정, Error Correction)**해 냅니다

== 단순 반복과의 결정적 차이: 자원의 대절약

5장의 단순 반복과 효율성을 비교해 봅시다.

* **5장의 단순 3회 반복**: 4비트를 안전하게 보내려면 총 **12비트**가 필요 (속도 33%).
* **7장의 2차원 패리티**: 4비트에 가로/세로 패리티 4비트만 더해 총 **8비트**면 위치 특정 및 완벽 복원 가능 (속도 50%).

훨씬 더 적은 여분의 비트만 덧붙이고도, 오류의 위치까지 정확히 찾아내는 강력한 능력을 얻었습니다

[NOTE]
====
**오류 정정 부호는 여분의 비트를 전혀 안 쓰는 마법인가요?**  
그렇지 않습니다. 오류를 감지하고 스스로 고치기 위해서는 반드시 **약간의 여분의 비트(Redundancy)**를 덧붙여야 합니다.  
6장의 채널 용량 정리가 의미하는 바는, "단순 반복처럼 무식하게 속도를 깎아먹지 않고, **채널 용량이 허용하는 아주 최소한의 여분 비트만으로도 완벽한 무오류를 달성할 수 있다**"는 뜻입니다.
====

== 오늘날 우리 주변의 오류 정정 부호

이 격자 패리티 아이디어를 고차원 수학(갈루아 체, 선형대수)으로 극대화한 것이 현대의 **리드-솔로몬 부호(Reed-Solomon Code)**와 **LDPC 부호**입니다.

* **음악 CD / DVD**: 디스크 표면에 동전으로 흠집이 깊게 나도 음악이 튀지 않고 매끄럽게 재생되는 비밀이 바로 이 오류 정정 부호 덕분입니다.
* **QR 코드**: 카메라로 찍는 QR 코드의 모서리가 찢어지거나 가려져 있어도 스마트폰이 0.1초 만에 인식하는 비결입니다.
* **심우주 탐사선**: 수십억 킬로미터 떨어진 명왕성에서 보이저 2호가 보내오는 극미약한 신호도 깨끗한 사진으로 복원해 냅니다.

== 요약

* **패리티 비트**: 데이터의 1의 개수 홀짝을 맞춰 단 1비트의 여분으로 오류 발생 여부를 감지합니다.
* **2차원 패리티(오류 정정)**: 가로와 세로의 십자 교차 검사를 통해 오류의 정확한 위치를 짚어내고 즉시 반전 복원합니다.
* **현대 통신의 방패**: CD, 와이파이, 5G, QR 코드, 우주 통신에 이르기까지 디지털 세상의 모든 안정성을 지탱합니다.

[TIP]
====
**확인 질문**: 2x2 격자 패리티에서 만약 비트가 '동시에 2개' 뒤집히면(예: 1행 1열과 2행 2열), 왜 단 하나의 십자 교차점을 특정하기 어려워지는지 머릿속으로 상상해 보세요 (이것이 2개 이상의 오류를 잡기 위해 더 높은 차원의 해밍 부호가 필요한 이유입니다.)
====
