서문의 질문으로 다시 시작해 봅시다.

> **"동전 던지기 결과"와 "오늘 아침 해가 떴다는 소식" 중,  
> 왜 동전 던지기가 더 많은 정보를 담고 있을까요?**

이 장에서는 우리의 이 직관을 수학적으로 엄밀한 숫자(비트)로 변환하는 마법을 배웁니다.

== 스무고개 놀이로 확인하는 직관

어릴 적 하던 스무고개 놀이를 떠올려 봅시다.

상대가 마음속으로 "1부터 8까지의 자연수 중 하나"를 정했다고 해봅시다. 여러분은 "예/아니오" 질문만으로 그 숫자를 맞혀야 합니다. 가장 현명한 전략은 무엇일까요?

....
                   [ 스무고개 이진 탐색 트리 (후보 8개) ]

                            [ 1 ~ 8 ] (후보 8개)
                                │ "4보다 큰가?"
                 ┌──────────────┴──────────────┐
                 ▼ (아니오)                      ▼ (예)
             [ 1 ~ 4 ]                       [ 5 ~ 8 ] (후보 4개)
                 │ "2보다 큰가?"                  │
          ┌──────┴──────┐                 ┌──────┴──────┐
          ▼             ▼                 ▼             ▼
       [ 1 ~ 2 ]     [ 3 ~ 4 ]         [ 5 ~ 6 ]     [ 7 ~ 8 ] (후보 2개)
          │ "1인가?"
       ┌──┴──┐
       ▼     ▼
      [1]   [2] ──► 【 정답 확정 (후보 1개) 】
....

매번 후보를 정확히 절반으로 쪼개는 질문을 던지면:
* 후보 **8개**일 때: 질문 **3번** (8 → 4 → 2 → 1)
* 후보 **16개**일 때: 질문 **4번** (16 → 8 → 4 → 2 → 1)
* 후보 **1,000개**일 때: 질문 약 **10번** (1024 → 512 → ... → 1)

여기서 경이로운 규칙이 발견됩니다.  
후보가 **2배**씩 곱해져 폭발할 때마다, 필요한 질문의 개수는 정직하게 딱 **+1번**씩만 늘어납니다

== 로그($\log_2$): "2배 늘어날 때 1씩 커지는" 셈법

수학에서 "후보가 2배가 될 때마다 값이 1씩 늘어나는" 성질을 표현하는 완벽한 도구가 바로 **밑이 2인 로그($\log_2$)**입니다.

어려운 로그 공식은 잊어버려도 좋습니다. 로그란 단순히 **"후보를 1이 될 때까지 반으로 몇 번 쪼개야 하는가?"를 세는 횟수**일 뿐입니다.

* $\log_2(8) = 3$ (8을 반으로 3번 쪼개면 1이 됨)
* $\log_2(16) = 4$ (16을 반으로 4번 쪼개면 1이 됨)
* $\log_2(1024) = 10$ (1024를 반으로 10번 쪼개면 1이 됨)

스무고개에서 손으로 세었던 질문 횟수가, 사실은 정확한 로그의 계산 결과였던 것입니다

== 섀넌의 정의: "확률이 낮을수록(놀라울수록) 정보량이 크다"

이제 이 상황을 확률로 옮겨 적어 봅시다.

8개의 숫자 중 하나를 무작위로 뽑을 때, 특정 숫자 하나가 당첨될 확률은 **$p = 1/8$**입니다. 섀넌은 이 사건이 발생했을 때 우리가 얻는 **정보량(Information)**을 다음과 같이 정의했습니다.

> **정보량 = 확률의 역수($1/p$)에 로그($\log_2$)를 취한 값**  
> $$I(x) = \log_2\left(\frac{1}{p}\right) = -\log_2(p)$$

....
                   [ 확률과 정보량의 산출 파이프라인 ]

      사건의 확률 p ──► [ 역수 취하기 1/p ] ──► [ 밑이 2인 로그 log₂ ] ──► 정보량 (비트)
     (예: p = 1/8)       (후보의 개수: 8)         (반으로 쪼갠 횟수: 3)      ( 3 비트 )
....

* **"오늘 아침 해가 떴다"**: 일어날 확률이 $p \approx 1$ (100%)이므로, 역수는 $1$이고 $\log_2(1) = \mathbf{0}$입니다. **정보량이 0비트**입니다 (새로운 것이 전혀 없음).
* **"동전 던지기 앞면"**: 일어날 확률이 $p = 1/2$ (50%)이므로, 역수는 $2$이고 $\log_2(2) = \mathbf{1}$입니다. **정확히 1비트의 정보량**입니다

우리가 일상에서 느끼는 "놀라움의 크기"가 완벽한 숫자로 변환된 것입니다.

== 우체국 저울에 비유하기

섀넌의 정보량을 **우체국의 택배 저울**에 비유해 봅시다.

....
                       [ 우체국 저울 비유 ]

                 ┌───────────────────────────┐
                 │  [ 무게: 2.5 kg ] (측정값)  │
                 └─────────────┬─────────────┘
                               ▼
            [ 저울은 상자 안의 '의미'를 모른다 ]
            • 상자 안에 10억 원짜리 다이아몬드가 들었든,
            • 길가의 흔한 자갈돌이 들었든,
            ──► 저울은 오직 【물리적 무게】만 잰다
....

우체국 저울은 상자 안에 러브레터가 들었든 돌멩이가 들었든 상관없이 오직 '무게'만 잽니다.

마찬가지로 섀넌의 정보량은 그 소식이 얼마나 감동적이거나 유용한지(의미)는 전혀 따지지 않고, 오직 **"그 소식이 일어날 확률이 얼마나 희박했는가(불확실성)"**라는 하나의 수치만 잽니다.

[NOTE]
====
**"정보량이 크다"는 것이 "더 중요하고 유용한 소식"이라는 뜻인가요?**  
가장 흔한 오해입니다 섀넌의 정보 이론에서 정보량이란 순수하게 **"예측하기 얼마나 어려웠는가"**만을 측정합니다. 내일 로또 1등 번호(확률이 수백만 분의 1로 극히 희박하므로 정보량이 매우 큼)와, 길거리의 모래알 번호(역시 확률이 희박해 정보량이 큼)는 정보 이론의 관점에서는 똑같이 거대한 정보량을 가집니다.
====

== 손으로 확인하는 일기예보

사막 지대의 일기예보를 예로 들어봅시다.

1. **"내일 사막에 비가 온다"** (확률 $p = 1/4$):
   * 역수: $4$
   * 정보량: $\log_2(4) = \mathbf{2\text{ 비트}}$
2. **"내일 사막에 비가 안 온다(맑음)"** (확률 $p = 3/4$):
   * 역수: $4/3 \approx 1.33$
   * 정보량: $\log_2(1.33) \approx \mathbf{0.41\text{ 비트}}$

사막에서는 맑은 날이 너무 당연하기 때문에 소식으로서의 가치(0.41비트)가 낮지만, 비가 온다는 드문 사건은 무려 2비트의 큰 놀라움을 줍니다.

== "비트(bit)"라는 단위의 탄생

여기서 정보량을 측정하는 기본 단위인 **비트(bit, Binary Digit)**가 공식적으로 탄생했습니다.

> **1비트(bit)란, 확률이 정확히 50%인 사건(동전 던지기) 하나가 주는 정보의 기본 단위이다.**

컴퓨터가 모든 데이터를 `0`과 `1`이라는 스위치로 저장하는 이유가 바로 여기에 있습니다. "0인가 1인가?"라는 단 한 번의 질문이 정확히 1비트의 불확실성을 해소해 주기 때문입니다.

== 요약

* **스무고개와 로그**: 후보가 2배씩 늘어날 때 질문은 1회씩 늘어나며, 이것이 밑이 2인 로그($\log_2$)의 본질입니다.
* **정보량의 정의**: 사건의 확률 $p$에 대해 $I(x) = \log_2(1/p)$로 정의되며, 확률이 낮을수록(놀라울수록) 정보량이 큽니다.
* **1비트의 정의**: 확률 50%인 이진 선택(동전 던지기)이 해소해 주는 정보량이 정확히 1비트입니다.
