'''

3장에서 좋은 압축 방법이 엔트로피에 가까운 평균 부호 길이를 만든다는 걸 봤습니다. 이 장에서는 이게 "가까워질 수 있다"에서 그치지 않고, **엔트로피 아래로는 절대 내려갈 수 없다**는 엄밀한 한계라는 걸 봅니다.

== 압축률 경쟁에는 끝이 있다

압축 프로그램을 만드는 회사들은 계속 더 나은 압축률을 놓고 경쟁합니다. 그런데 이 경쟁에는 절대 넘을 수 없는 벽이 있습니다 — **섀넌의 소스 코딩 정리(Shannon's source coding theorem)**는, 어떤 정보 소스든 그 소스의 엔트로피보다 평균적으로 더 짧은 부호로는 손실 없이(정보를 하나도 잃지 않고) 표현할 수 없다는 걸 증명합니다. 아무리 천재적인 알고리즘을 고안해도, 이 벽 아래로는 내려갈 수 없습니다 — 이건 "아직 발견 못 한 알고리즘이 있을 수도 있다"는 게 아니라, **논리적으로 불가능하다**는 증명입니다.

== 왜 이런 한계가 있는가: 되돌릴 수 있어야 한다

이 한계가 왜 생기는지 감을 잡아봅시다 — 압축은 "손실 없이" 되돌릴 수 있어야 합니다(압축을 풀었을 때 원본과 정확히 같아야 합니다). 그런데 만약 압축 결과의 평균 길이가 엔트로피보다 짧다면, 서로 다른 원본 메시지 여러 개가 같은(혹은 그보다 적은 가짓수의) 압축 결과로 몰릴 수밖에 없는 상황이 반드시 생깁니다 — 마치 100개의 서로 다른 물건을 10개의 상자에만 나눠 담으려는 것과 같습니다, 어느 상자엔가는 반드시 물건이 두 개 이상 들어갈 수밖에 없습니다(이런 논리를 **비둘기집 원리**라고 부릅니다). 두 개의 서로 다른 원본이 같은 압축 결과를 갖게 되면, 압축을 풀 때 그 둘을 구분할 방법이 없어져서 "손실 없이 되돌린다"는 조건이 깨집니다.

[NOTE]
====
**흔히 헷갈리는 지점**: "손실 없는 압축"에 이 한계가 있다는 걸 "모든 압축에 이 한계가 있다"로 오해하기 쉽습니다. JPEG 이미지나 MP3 음악 파일 같은 **손실 압축(lossy compression)**은 이 정리의 대상이 아닙니다 — 손실 압축은 애초에 "사람 눈/귀가 잘 못 느끼는 정보를 일부러 버려서" 더 작게 만드는 것이라, "정확히 되돌릴 수 있어야 한다"는 이 정리의 전제 자체를 만족하지 않습니다. 이 장의 한계는 ZIP처럼 원본을 한 비트도 잃지 않고 복원해야 하는 압축에만 적용됩니다.
====

== 좌석에 비유하기

비둘기집 원리를 극장 좌석에 비유하면 더 또렷해집니다 — 관객이 100명인데 좌석이 90개뿐이라면, 아무리 좌석 배치를 영리하게 바꿔도 최소 10명은 자리를 나눠 앉거나 겹칠 수밖에 없습니다. "손실 없는 압축"이 요구하는 건 정확히 "관객 100명이 전부 서로 다른 좌석에 앉아야 한다"는 것과 같습니다 — 원본 메시지 하나하나(관객)가 압축된 결과(좌석) 하나하나와 정확히 1대1로 대응해야, 나중에 좌석 번호만 보고도 어느 관객이었는지 되돌릴 수 있습니다. 압축 결과의 가짓수(좌석 수)가 원본의 정보량(엔트로피)이 요구하는 것보다 적으면, 관객 수가 좌석 수를 넘어서는 것과 똑같은 상황이 벌어져 되돌릴 방법이 사라집니다.

== 한계에 얼마나 가까이 갈 수 있는가

섀넌의 소스 코딩 정리는 두 가지를 함께 말해줍니다 — (1) 엔트로피 아래로는 절대 못 내려간다는 것과, (2) **엔트로피에 원하는 만큼 가깝게는 도달할 수 있다**는 것입니다. 3장에서 본 허프만 부호화는 실전에서 꽤 좋은 근사치를 주지만, 산술 부호화(arithmetic coding) 같은 더 정교한 기법을 쓰면 이론적 한계인 엔트로피에 거의 정확히 도달하는 압축이 가능합니다. 즉 "완벽한 압축"이란 존재하지 않지만, "엔트로피만큼 압축된 것"에 원하는 만큼 근접한 압축은 원리적으로 항상 가능합니다.

== 이 한계가 실전에 주는 의미

이 정리 덕분에, 압축 소프트웨어를 만드는 사람들은 "우리 알고리즘이 얼마나 더 개선될 여지가 있는가"를 구체적으로 알 수 있습니다 — 어떤 데이터의 엔트로피를 미리 계산해두면, 지금 쓰는 압축 프로그램이 그 이론적 한계에 얼마나 가까운지(혹은 아직 개선할 여지가 얼마나 남았는지) 정확히 잴 수 있습니다. 부록에서 실제 텍스트로 이걸 직접 확인해봅니다.

[TIP]
====
**확인 질문**: "완전히 무작위한 데이터(엔트로피가 최대인 데이터)는 왜 손실 없이는 거의 압축이 안 되는지"를, 이 장에서 배운 소스 코딩 정리로 설명해보세요. (힌트: 엔트로피가 이미 최대값에 가깝다면, "엔트로피 아래로는 못 내려간다"는 한계와 원래 데이터의 크기 사이에 남는 여유가 얼마나 될까요?)
====

== 요약

* 섀넌의 소스 코딩 정리는, 어떤 정보 소스든 그 엔트로피보다 평균적으로 더 짧게는 손실 없이 압축할 수 없다는 것을 증명합니다.
* 이 한계는 비둘기집 원리와 비슷한 논리(서로 다른 원본이 더 적은 가짓수의 압축 결과로 몰리면 되돌릴 수 없다)에서 나옵니다.
* 이 정리는 손실 압축(JPEG, MP3)에는 적용되지 않고, 원본을 정확히 복원해야 하는 손실 없는 압축에만 적용됩니다.

2부가 여기서 끝났습니다. 3부에서는 압축과는 또 다른 축, 노이즈가 섞인 통신선을 통해 정보를 보내는 문제를 다룹니다.
