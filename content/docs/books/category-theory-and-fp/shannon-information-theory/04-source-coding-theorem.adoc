'''

3장에서 우리는 허프만 부호화를 통해 데이터의 평균 부호 길이를 엔트로피($1.75$비트)까지 줄일 수 있음을 보았습니다.

그렇다면 더 뛰어난 천재가 나타나서 새로운 알고리즘을 개발하면, 이 데이터를 **$1.5$비트나 $1.0$비트로 더 줄여서 압축**할 수 있을까요?

== 압축 경쟁에 그어진 절대적인 한계선

섀넌은 단호하게 **"불가능하다"**고 선언했습니다.

1948년 발표된 **섀넌의 소스 코딩 정리(Shannon's Source Coding Theorem)**는 다음을 완벽하게 증명했습니다.

> **"어떤 정보 소스(텍스트, 파일 등)든,  
> 원본 데이터를 단 1비트의 손실도 없이 100% 복원하기 위해서는,  
> 【그 데이터의 엔트로피 $H(X)$】보다 평균적으로 더 적은 비트로 압축하는 것이 수학적으로 절대 불가능하다!"**

....
                   [ 섀넌의 소스 코딩 정리 한계선 ]

     평균 부호 길이 (L)
        ▲
        │   [ 압축 가능한 영역 ]
        │   • 고정 길이 (2.0 비트)
        │   • 허프만 부호화 (1.75 비트)
        │   • 산술 부호화 (1.7501 비트)
        │
   ─────┼───────────────────────────────────── ◄── 【 엔트로피 한계선: H(X) = 1.75 비트 】
        │
        │   【 무손실 압축 절대 불가능 영역 】
        │   (아무리 뛰어난 천재가 와도 원천 차단)
        └─────────────────────────────────────►
....

이것은 "아직 더 좋은 압축 알고리즘을 못 찾았다"는 뜻이 아니라, 빛의 속도를 넘을 수 없다는 물리학 법칙처럼 **논리적·수학적으로 원천 차단된 우주의 한계선**입니다.

== 왜 엔트로피 밑으로는 못 내려갈까: 극장 좌석 비유

이 한계가 왜 발생하는지 직관적으로 이해해 봅시다.

....
                       [ 극장 좌석 비유 ]

   【 서로 다른 원본 메시지: 100가지 】     【 압축된 표현: 90가지 좌석 】
   ┌───┬───┬───┬───┬───┬───┐              ┌───┬───┬───┬───┬───┐
   │ 1 │ 2 │ 3 │ 4 │...│100│ ──► 대입 ──► │ A │ B │ C │...│ 90│
   └───┴───┴───┴───┴───┴───┘              └───┴───┴───┴───┴───┘
                                                     │
                                                     ▼
   [ 비둘기집 원리: 최소 2개 이상의 서로 다른 원본이 같은 좌석에 겹쳐 앉음 ]
   ──► "압축을 풀 때 원래 1번이었는지 2번이었는지 구분 불가" (손실 발생)
....

무손실 압축이란 압축을 풀었을 때 단 하나의 오차도 없이 원본으로 되돌릴 수 있어야 합니다.

만약 엔트로피가 요구하는 비트 수보다 더 적은 비트만 쓰게 되면, **서로 다른 100개의 원본 파일이 90개의 압축 코드로 겹쳐서 저장**되는 사태가 반드시 발생합니다(**비둘기집 원리**).

이렇게 되면 압축을 해제할 때 원래 파일이 무엇이었는지 구분할 방법이 영원히 사라져 버립니다.

== 섀넌이 건네준 두 가지 진실

섀넌의 소스 코딩 정리는 절망만 안겨준 것이 아닙니다. 동전의 양면처럼 두 가지 진실을 함께 알려주었습니다.

1. **절대 한계**: 엔트로피 $H(X)$ 아래로는 단 1비트도 더 줄일 수 없다.
2. **달성 가능성**: 엔트로피 $H(X)$에 **우리가 원하는 만큼 무한히 가깝게 도달하는 압축 알고리즘은 언제나 만들 수 있다!**

실제로 허프만 부호화나 현대의 **산술 부호화(Arithmetic Coding)** 같은 기법들은, 데이터 덩어리를 길게 묶어 처리함으로써 이론적 한계인 엔트로피에 99.99%까지 완벽하게 근접하는 압축률을 달성하고 있습니다.

[NOTE]
====
**JPEG 사진이나 MP3 음악은 왜 엄청나게 줄어드나요?**  
가장 중요한 구분입니다. 이 정리는 원본을 100% 한 글자도 틀리지 않고 복원해야 하는 **무손실 압축(ZIP, PNG)**에만 적용됩니다.  
JPEG나 MP3 같은 **손실 압축(Lossy Compression)**은 "인간의 눈이나 귀가 눈치채지 못하는 미세한 데이터는 그냥 과감히 버린다"는 전제를 깔고 들어가므로, 섀넌의 무손실 엔트로피 한계선보다 훨씬 더 작게 용량을 줄일 수 있습니다.
====

== 요약

* **소스 코딩 정리**: 어떤 정보 소스든 그 소스의 엔트로피 $H(X)$ 이하로는 무손실 압축이 불가능합니다.
* **비둘기집 원리**: 엔트로피보다 적은 비트를 쓰면 서로 다른 원본이 같은 부호로 겹치게 되어 원래대로 복원할 수 없습니다.
* **이론적 완성**: 엔트로피는 압축 소프트웨어 엔지니어들이 도달할 수 있는 '궁극의 목표 기준선' 역할을 합니다.

[TIP]
====
**확인 질문**: 100% 무작위 난수로 가득 찬 파일(엔트로피가 최대인 파일)은 왜 ZIP 프로그램으로 압축해도 용량이 거의 1바이트도 줄어들지 않는지, 본문의 소스 코딩 정리로 설명해 보세요
====
