하지만 2장에서 정의한 **엔트로피 공식**을 파이썬 코드로 직접 구현하고, 4장에서 배운 **"엔트로피가 압축의 절대 한계선이다"**라는 섀넌의 주장이 실제 압축 프로그램(gzip)에서 어떻게 작동하는지 눈으로 직접 확인하는 것은 대단히 흥미진진한 경험입니다.

== 1. 파이썬으로 엔트로피를 계산하는 코드

2장의 정의대로, 텍스트 안에 등장하는 각 문자의 출현 빈도를 세어 확률 $p$를 구하고, 정보량($-p \log_2 p$)을 모두 더해 글자당 평균 엔트로피를 계산합니다.

[source,python]
----
import math, collections, gzip

def shannon_entropy_per_char(text):
    counts = collections.Counter(text)
    n = len(text)
    entropy = 0.0
    for char, cnt in counts.items():
        p = cnt / n
        entropy -= p * math.log2(p)
    return entropy   # 문자 1개당 평균 몇 비트의 정보량을 담고 있는가?
----

== 3. 결과 분석: 무작위 텍스트에서 증명된 섀넌의 정리

가장 먼저 세 번째인 **완전 무작위 텍스트**를 주목해 봅시다.

문자 단위 엔트로피로 계산한 이론적 최소 크기(**`13,131.7` 바이트**)와, 실제 `gzip` 압축 크기(**`13,332` 바이트**)가 **소름 돋을 정도로 거의 완벽하게 일치**합니다

무작위 난수 데이터에는 압축 프로그램이 활용할 수 있는 패턴이 전혀 없기 때문에, 4장에서 배운 **섀넌의 소스 코딩 정리가 예측한 그대로 엔트로피 한계선에 딱 걸려 더 이상 압축되지 않은 것**입니다.

== 4. 흥미로운 수수께끼: gzip이 '이론적 최소치'를 뛰어넘은 이유?

그런데 1번(반복)과 2번(자연어) 텍스트를 보면 기이한 현상이 나타납니다.

문자 단위 엔트로피로 계산했을 때는 각각 2,000바이트와 8,485바이트가 한계라고 나왔는데, 실제 `gzip`은 **51바이트, 297바이트라는 터무니없이 작은 크기로 압축**해 버렸습니다

[NOTE]
====
**섀넌의 정리는 여전히 100% 완벽하게 옳습니다!**  
소스 코딩 정리에서 말하는 '엔트로피'는 **문자들 사이의 모든 문맥과 순서, 긴 구절의 반복 관계까지 완벽하게 반영한 '진짜 엔트로피'**를 뜻합니다.  
우리가 파이썬으로 짠 코드는 오직 '한 글자씩의 빈도'만 잰 엉성한 상한선 근사치였을 뿐입니다. `gzip`은 인간 언어에 존재하는 풍부한 구절 반복 패턴을 파악하여, 진짜 엔트로피 한계선에 가깝게 훨씬 더 깊이 압축해 낸 것입니다.
====

== 요약

* **무작위 텍스트의 실측**: 패턴이 없는 데이터에서는 문자 단위 엔트로피와 실제 gzip 압축률이 완벽하게 일치하며 섀넌의 정리가 입증됩니다.
* **자연어의 구조적 패턴**: 실제 언어 텍스트는 글자 사이의 강력한 상관관계(단어, 문장)를 가지고 있어, 단순 문자 빈도보다 훨씬 더 작게 압축될 수 있습니다.
* **진짜 엔트로피의 의미**: 섀넌의 소스 코딩 정리는 모든 통계적 상관관계를 고려한 진짜 엔트로피 아래로는 그 어떤 알고리즘도 내려갈 수 없음을 선언합니다.
