이 부록은 본문과 독립적입니다 — 건너뛰어도 이 책을 이해하는 데 지장이 없습니다. 2장에서 정의한 엔트로피를 실제 텍스트에 대해 파이썬으로 계산하고, 4장에서 본 "엔트로피가 압축의 한계"라는 주장이 실제 압축 프로그램(gzip)에서 어떻게 나타나는지 확인합니다.

== 엔트로피를 계산하는 코드

2장에서 정의한 대로, 텍스트에 등장하는 각 문자의 빈도로 확률을 추정하고, 그 확률로 엔트로피를 계산합니다.

[source,python]
----
import math, collections, gzip

def shannon_entropy_per_char(text):
    counts = collections.Counter(text)
    n = len(text)
    entropy = 0.0
    for c, cnt in counts.items():
        p = cnt / n
        entropy -= p * math.log2(p)
    return entropy   # 문자 하나당 평균 몇 비트의 정보량인지
----

== 세 가지 텍스트로 실험하기

성격이 다른 텍스트 세 가지를 준비했습니다 — (1) `ab`를 계속 반복한 텍스트(패턴이 극단적으로 뚜렷함), (2) 찰스 디킨스의 `두 도시 이야기`의 유명한 첫 문단을 반복한 자연어 텍스트, (3) 완전히 무작위로 고른 출력 가능한 문자들의 나열입니다. 각각에 대해 문자 단위 엔트로피를 계산하고("이론적 최소 크기"로 환산), 실제 gzip으로 압축한 크기와 비교했습니다.

[source]
----
--- Repetitive (ababab...) ---
  original size:          16000 bytes (16000 chars)
  entropy per char:      1.0000 bits
  theoretical minimum:   2000.0 bytes (entropy bound)
  gzip actual size:          51 bytes
  gzip ratio:            313.73x

--- Natural English (A Tale of Two Cities excerpt, repeated) ---
  original size:          16640 bytes (16640 chars)
  entropy per char:      4.0796 bits
  theoretical minimum:   8485.5 bytes (entropy bound)
  gzip actual size:         297 bytes
  gzip ratio:             56.03x

--- Random printable characters ---
  original size:          16000 bytes (16000 chars)
  entropy per char:      6.5658 bits
  theoretical minimum:  13131.7 bytes (entropy bound)
  gzip actual size:       13332 bytes
  gzip ratio:              1.20x
----

== 무작위 텍스트: 이론과 정확히 맞아떨어지는 경우

가장 먼저 눈여겨볼 결과는 세 번째, 완전히 무작위한 텍스트입니다 — 문자 단위 엔트로피로 계산한 "이론적 최소 크기"(`13131.7`바이트)와 실제 gzip 압축 크기(`13332`바이트)가 거의 정확히 일치합니다. 이건 4장에서 배운 소스 코딩 정리가 예측한 그대로입니다 — 완전히 무작위한 데이터에는 gzip이 활용할 만한 추가 패턴이 전혀 없어서, 문자 빈도만으로 계산한 엔트로피가 이 데이터의 진짜 한계에 아주 가깝고, gzip은 그 한계 가까이까지 다가가되 더 줄이지는 못합니다.

== 반복 텍스트와 자연어: gzip이 "이론적 최소치"를 뛰어넘는 이유

그런데 앞의 두 텍스트에서는 뜻밖의 결과가 나왔습니다 — gzip 압축 크기가 문자 단위 엔트로피로 계산한 "이론적 최소치"보다 **훨씬 작습니다**(반복 텍스트는 `2000`바이트가 한계라고 계산했는데 실제로는 `51`바이트까지 줄었고, 자연어 텍스트도 `8485.5`바이트가 한계라고 계산했는데 실제로는 `297`바이트까지 줄었습니다). 이건 4장에서 배운 소스 코딩 정리를 어기는 게 아닙니다 — **이 부록이 계산한 "문자 단위 엔트로피"가 애초에 이 텍스트들의 진짜 엔트로피를 정확히 재지 못했기 때문**입니다.

문자 단위 엔트로피는 "각 문자가 다른 문자들과 완전히 독립적으로, 그저 정해진 빈도로만 나타난다"고 가정합니다. 하지만 `abababab...`처럼 반복되는 텍스트나, 자연어 텍스트("of times"라는 구절이 반복되는 것처럼 긴 패턴이 있는 텍스트)에는 **문자들 사이의 순서 관계(어떤 문자 다음에 어떤 문자가 자주 오는지, 나아가 어떤 구절이 통째로 반복되는지)**라는, 문자 하나하나의 빈도만 봐서는 절대 드러나지 않는 훨씬 강력한 패턴이 숨어 있습니다. gzip은(2장~3장에서 다룬 것보다 훨씬 정교한 방식으로) 이런 반복되는 구절 자체를 통째로 찾아내 짧은 참조로 바꿔버리는데, 이건 "문자 하나의 확률"이 아니라 "이미 나온 긴 조각이 다시 나올 확률"까지 활용하는 것입니다.

[NOTE]
====
**흔히 헷갈리는 지점**: "gzip이 이론적 한계보다 더 압축했으니 섀넌의 정리가 틀린 것 아니냐"고 오해하기 쉽습니다. 그렇지 않습니다 — 소스 코딩 정리가 말하는 "엔트로피"는 **그 정보 소스의 진짜 확률 구조 전체(문자 사이의 모든 상관관계까지 포함)**를 반영한 값입니다. 이 부록에서 계산한 "문자 단위 엔트로피"는 그 진짜 값의 **엉성한 근사치(상한선)**일 뿐입니다 — 문자들 사이의 관계를 무시하고 각 문자를 독립으로 취급하니, 반복되는 텍스트의 진짜 엔트로피(훨씬 낮습니다)를 실제보다 부풀려 계산한 것입니다. gzip은 이 부록이 놓친 진짜 패턴(반복 구절)을 활용해서, 우리가 잘못 추정한 상한선보다 더 깊이 압축한 것뿐입니다 — 진짜 엔트로피(문자 사이의 모든 상관관계를 반영한 값)보다 더 압축하는 건 여전히 불가능합니다.
====

== 요약

* 완전히 무작위한 텍스트에서는 문자 단위 엔트로피로 계산한 이론적 한계(`13131.7`바이트)와 실제 gzip 압축 크기(`13332`바이트)가 거의 정확히 일치한다는 걸 확인했습니다 — 무작위 데이터에는 gzip이 활용할 추가 패턴이 없기 때문입니다.
* 반복 텍스트와 자연어 텍스트에서는 gzip이 문자 단위 엔트로피로 계산한 값보다 훨씬 더 작게 압축했는데, 이는 소스 코딩 정리를 어긴 게 아니라 문자 단위 엔트로피가 문자들 사이의 순서 패턴(반복되는 구절)을 놓친 **엉성한 근사치**였기 때문입니다.
* 진짜 엔트로피(모든 통계적 상관관계를 반영한 값)보다 더 압축하는 것은 여전히 불가능하며, 실제 압축 프로그램의 성능을 정확히 이해하려면 문자 하나하나가 아니라 텍스트 전체의 구조적 패턴까지 반영한 엔트로피를 따져야 한다는 걸 이 실험으로 확인했습니다.

이 부록에서 다룬 건 본문 2~4장이 논증으로 보여준 것의 아주 작은 확인일 뿐입니다 — 더 파고들고 싶다면, 문자 하나가 아니라 두 글자·세 글자 단위(순서쌍, 순서세쌍)의 빈도로 엔트로피를 다시 계산해서, 그 값이 문자 단위 엔트로피보다 얼마나 더 gzip의 실제 압축률에 가까워지는지 직접 실험해보는 것도 좋은 다음 걸음입니다.
