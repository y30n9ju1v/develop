인도에는 체스판과 쌀알에 얽힌 유명한 전설이 하나 전해 내려옵니다.

체스를 발명하여 왕을 즐겁게 한 현자가 상을 청했습니다. 현자는 소박하게 청했습니다.
> **"왕이시여, 체스판 첫 번째 칸에 쌀 1톨, 두 번째 칸에 2톨, 세 번째 칸에 4톨... 이렇게 매 칸마다 앞 칸의 딱 2배씩만 쌀알을 채워 주십시오."**

왕은 "그까짓 쌀알 몇 가마니쯤이야" 하며 흔쾌히 승낙했습니다.

== 체스판이 삼켜버린 지구

하지만 계산을 시작하자 왕실 재정관들은 사색이 되었습니다.

체스판은 총 64칸입니다. 매 칸마다 2배씩 늘어나면 마지막 64번째 칸에 놓아야 할 쌀알의 개수는 무려 **$2^{63}$ 톨 (약 9,223,372,036,854,775,808 톨 = 약 900경 톨)**에 달합니다

....
                 [ 체스판 위의 지수적 폭발 (Exponential Growth) ]

   1번째 칸: 1톨 (2⁰)
   2번째 칸: 2톨 (2¹)
   3번째 칸: 4톨 (2²)
   4번째 칸: 8톨 (2³)
   ...
   10번째 칸: 512톨 (약 밥 반 공기)
   ...
   20번째 칸: 약 52만 톨 (쌀 한 포대)
   ...
   64번째 칸: 약 922경 톨 ──► 【 인류 역사상 생산된 모든 쌀보다 많음 】
....

칸 수가 겨우 64개로 늘어났을 뿐인데, 숫자는 지구 전체의 수용량을 순식간에 초월해 버렸습니다.

여기서 가장 중요한 핵심은 숫자의 크기가 아니라 **"늘어나는 속도 그 자체"**입니다. 입력이 하나 늘어날 때마다 시간과 자원이 '조금 더' 늘어나는 것이 아니라 **통째로 '2배'씩 곱해지는 것**, 이것이 바로 **지수적 증가(Exponential Growth)**의 무서움입니다.

== 컴퓨터 과학의 두 세계: 다항 시간 vs 지수 시간

컴퓨터 과학에서는 어떤 알고리즘이 "빠르고 효율적인가"를 따질 때, 시계 초침을 재는 대신 **"입력 크기 $n$이 커질 때 걸리는 계산 횟수가 어떤 속도로 늘어나는가"**를 측정합니다.

그리고 세상의 모든 알고리즘을 크게 두 부류로 엄격하게 나눕니다.

....
                   [ 다항 시간 vs 지수 시간 비교 차트 ]

     계산 횟수
        ▲                                     / [ 지수 시간: 2ⁿ ]
        │                                    /  (순식간에 우주 나이 초과)
        │                                   /
        │                                  /
        │                                 /
        │                                /
        │                    [ 다항 시간: n² ]
        │                   /  (컴퓨터로 감당 가능)
        │               _--'
        │          _--''
        └─────────┴──────────────────────────────► 입력 크기 n
                 n=10     n=30        n=60
....

|===
| 입력 크기 ($n$) | 다항 시간 ($n^2$, $n$의 거듭제곱) | 지수 시간 ($2^n$, 2배씩 폭발)

| **$n = 10$** | **$100$ 번** (0.0001초) | **$1,024$ 번** (0.001초)
| **$n = 20$** | **$400$ 번** (0.0004초) | **$1,048,576$ 번** (약 1초)
| **$n = 30$** | **$900$ 번** (0.0009초) | **약 10억 번** (약 17분)
| **$n = 60$** | **$3,600$ 번** (0.003초) | **약 $10^{18}$ 번 (약 365억 년)**
|===

$n$이 10에서 60으로 겨우 6배 늘어났을 뿐인데:
* **다항 시간($n^2$)**: 0.0001초에서 **0.003초**로 여전히 눈 깜짝할 사이에 끝납니다.
* **지수 시간($2^n$)**: 0.001초에서 **365억 년(우주의 나이인 138억 년의 거의 3배)**이라는 상상하기 어려운 시간으로 치솟아 버립니다.

== 왜 '다항 시간'이 효율성의 절대 잣대인가?

지수 시간 알고리즘은 아무리 최신 슈퍼컴퓨터를 사 오더라도 결코 해결할 수 없습니다. 컴퓨터 성능을 10배 빠르게 업그레이드해 보았자, 지수 시간 알고리즘이 다룰 수 있는 데이터 크기($n$)는 고작 서너 칸 늘어나는 데 그치기 때문입니다.

반면 다항 시간 알고리즘은 컴퓨터가 빨라지면 다룰 수 있는 문제의 크기도 정직하게 비례하여 쭉쭉 늘어납니다.

따라서 컴퓨터 과학자들은 **"다항 시간(Polynomial Time) 안에 풀 수 있는 알고리즘이 존재하는가?"**를 **"현실적인 시간 안에 풀 수 있는가"를 가르는 유일한 절대 기준선**으로 채택했습니다.

[NOTE]
====
**흔히 헷갈리는 지점: $n^{100}$도 다항 시간인데 실전에서 빠른가요?**  
수학적으로 $n^{100}$도 다항식이지만 실전에서는 감당하기 어렵습니다. "다항 시간 = 효율적"이라는 정의는 현실의 모든 알고리즘을 100% 만족시키는 완벽한 잣대라기보다는, **"지수 시간이라는 감당 불가능한 괴물과 명확한 이론적 경계선을 긋기 위한 가장 우아한 기준"**입니다. 다행히 우리가 실무에서 만나는 대부분의 다항 시간 알고리즘은 $n, n \log n, n^2, n^3$ 정도의 낮은 차수를 가집니다.
====

== 요약

* **체스판의 쌀알**: 매 칸마다 2배씩 늘어나는 지수적 증가는 입력이 조금만 커져도 우주의 한계를 가뿐히 넘어섭니다.
* **다항 시간($n^k$)**: 입력이 커져도 계산량이 완만하게 늘어나 컴퓨터로 충분히 감당할 수 있는 효율적인 영역입니다.
* **지수 시간($2^n$)**: 입력이 조금만 커져도 계산량이 폭발하여 슈퍼컴퓨터로도 영원히 답을 낼 수 없는 영역입니다.

[TIP]
====
**직접 체감해보기**:  
$n$이 $5$에서 $10$으로 딱 2배 늘어났을 때, 다항 시간 $n^3$은 $125 \rightarrow 1,000$으로 **8배** 늘어나는 반면, 지수 시간 $2^n$은 $32 \rightarrow 1,024$로 **32배** 폭증합니다. 입력이 2배 커질 때 두 세계의 격차가 얼마나 벌어지는지 느껴보세요
====
