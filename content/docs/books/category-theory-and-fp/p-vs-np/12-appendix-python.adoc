이 부록은 본문과 독립적입니다 — 건너뛰어도 이 책을 이해하는 데 지장이 없습니다. 3장에서 소개한 **부분집합 합 문제**("숫자 목록에서 몇 개를 골라 더하면 정확히 목표값이 되는가")를 실제로 브루트포스(모든 가능성을 하나하나 확인하는 가장 단순한 방법)로 풀어보면서, 1장에서 말로만 설명한 지수적 폭발이 정말로 컴퓨터 위에서 벌어지는지 시간을 재봅니다.

== 브루트포스로 모든 부분집합 확인하기

숫자가 `n`개 있으면, "고른다/안 고른다"의 조합은 `2ⁿ`가지입니다. 이 모든 조합을 하나씩 만들어서 합을 확인하는 게 가장 단순한 풀이법입니다.

[source,python]
----
def brute_force_subset_sum(nums, target):
    n = len(nums)
    for mask in range(2 ** n):        # mask의 각 비트가 "이 숫자를 고를지"를 나타낸다
        total = 0
        for i in range(n):
            if mask & (1 << i):
                total += nums[i]
        if total == target:
            return mask                # 찾았다 - 이 조합이 정답
    return None                         # 2^n가지를 전부 확인했는데도 없다
----

일부러 **답이 존재하지 않는** 목표값(모든 숫자의 합보다 1 큰 값)을 줘서, `2ⁿ`가지 조합을 하나도 빠짐없이 전부 확인해야 하는 최악의 경우를 만듭니다 — 1장에서 다룬 "지수 시간"이 정말로 `n`에 따라 얼마나 폭발하는지 보려면, 중간에 운 좋게 일찍 답을 찾아버리는 경우가 아니라 이렇게 끝까지 확인해야 하는 경우를 재야 합니다.

== 실제로 걸린 시간

`n`을 16부터 24까지 2씩 늘려가며(총 다섯 번) 실제로 실행하고 시간을 쟀습니다(2026년, 일반적인 노트북 환경).

[source]
----
n=16  2^n=     65536  solve=    35.06ms  found=False
n=18  2^n=    262144  solve=   136.30ms  found=False
n=20  2^n=   1048576  solve=   612.96ms  found=False
n=22  2^n=   4194304  solve=  2711.86ms  found=False
n=24  2^n=  16777216  solve= 11798.02ms  found=False
----

`n`이 `16`에서 `24`로, 겨우 8만큼(그것도 두 배가 아니라 1.5배 늘어난 것뿐입니다) 늘었는데, 걸린 시간은 `35ms`에서 `11798ms`로 **약 336배** 늘었습니다. `n`을 `2`씩 늘릴 때마다 걸리는 시간이 대략 4배씩(`2²`) 뛰는 것도 확인할 수 있습니다 — 정확히 `2ⁿ`라는 지수 함수의 모양 그대로입니다. 이 추세를 그대로 이어가면 `n=40`쯤에서 이미 몇 시간, `n=60`이면 수십 년이 걸리는 영역에 들어갑니다 — 1장의 체스판 쌀알과 똑같은 폭발이 실제 컴퓨터 위에서 그대로 재현된 것입니다.

== 반면 확인은 여전히 순식간

이번엔 `n=24`짜리 목록에서, "이 조합이 정답이다"라고 이미 답(후보)이 주어졌다고 가정하고, 그게 맞는지만 확인하는 시간을 재봅니다.

[source,python]
----
def verify(nums, target, mask):
    return sum(nums[i] for i in range(len(nums)) if mask & (1 << i)) == target
----

[source]
----
verify (n=24): 0.0101ms  correct=True
----

같은 `n=24` 문제인데, 브루트포스로 풀 때는 `11798ms`가 걸렸던 반면, 답 후보 하나를 확인하는 데는 `0.01ms`가 채 안 걸렸습니다 — 거의 **백만 배** 차이입니다. 3장에서 말로 설명했던 "풀기는 어려운데 확인은 쉽다"는 NP의 핵심 감각이, 실제 숫자로 이렇게 극명하게 갈린다는 걸 확인했습니다.

[NOTE]
====
**흔히 헷갈리는 지점**: 이 브루트포스가 느리다고 해서 "부분집합 합 문제는 P에 속하지 않는다"는 게 증명된 건 아닙니다(4장, 7장에서 다룬 내용을 떠올려보세요 — "이 방법이 느리다"는 것과 "다항 시간 방법이 존재하지 않는다"는 건 다른 이야기입니다). 실제로 부분집합 합 문제는 숫자들이 크지 않을 때는 브루트포스보다 훨씬 빠른 특수한 기법(동적 계획법)이 있습니다 — 다만 그 기법도 숫자 자체의 크기에 비례해서 느려지기 때문에(엄밀한 의미의 다항 시간이 아닙니다), NP-완전이라는 이 문제의 지위를 뒤집지는 못합니다.
====

== 요약

* 부분집합 합 문제를 브루트포스로 직접 실행해, `n`이 `16`에서 `24`로 늘어나는 동안 걸리는 시간이 `35ms`에서 `11798ms`로(약 336배) 폭증한다는 걸 실측했습니다 — 1장의 지수적 증가가 실제 컴퓨터 위에서 그대로 나타납니다.
* 같은 `n=24` 문제에서, 답 후보 하나를 확인하는 데는 `0.01ms`밖에 걸리지 않아, 풀이와 확인 사이에 백만 배에 가까운 시간 차이를 직접 확인했습니다.
* 이 격차가, 3장에서 논증으로만 설명했던 "NP: 확인은 쉬운데 풀기는 어렵다"는 감각의 실측 버전입니다.

이 부록에서 다룬 건 본문 1~3장이 논증으로 보여준 것의 아주 작은 확인일 뿐입니다 — 더 파고들고 싶다면, 부분집합 합 문제의 동적 계획법 풀이를 직접 구현해서 이 브루트포스와 속도를 비교해보는 것도 좋은 다음 걸음입니다.
