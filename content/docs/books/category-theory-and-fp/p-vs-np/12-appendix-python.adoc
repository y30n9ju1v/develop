'''

이 부록은 본문과 독립적입니다 — 건너뛰어도 책의 내용을 이해하는 데 전혀 지장이 없습니다.

하지만 1장에서 배운 **지수 시간($2^n$)의 무시무시한 폭발**과, 3장에서 배운 **NP의 "답 확인은 순식간이다"**라는 핵심 감각이 컴퓨터 위에서 **실제로 어떻게 벌어지는지 눈으로 직접 측정하고 확인하는 것**은 대단히 짜릿한 경험입니다.

NP-완전 문제의 대표 주자인 **부분집합 합 문제(Subset Sum Problem)**를 파이썬으로 직접 작성하고 실행 시간을 재봅시다.

== 부분집합 합 문제란?

> **"주어진 $n$개의 숫자 목록에서, 몇 개를 골라 더했을 때 정확히 목표값(Target)이 되는 조합이 존재하는가?"**

숫자가 $n$개 주어지면, 각 숫자를 "선택한다(1) / 선택하지 않는다(0)"의 모든 가능한 부분집합의 개수는 정확히 **$2^n$ 가지**입니다.

== 1. 모든 경우를 다 뒤지는 브루트포스 풀이 ($O(2^n)$)

모든 $2^n$개의 조합을 하나도 빠짐없이 검사하는 가장 단순한 알고리즘입니다.

[source,python]
----
def brute_force_subset_sum(nums, target):
    n = len(nums)
    # 0부터 2^n - 1까지의 모든 비트마스크를 순회 (총 2^n 가지)
    for mask in range(2 ** n):
        total = 0
        for i in range(n):
            if mask & (1 << i):       # i번째 숫자가 선택되었는가?
                total += nums[i]
        if total == target:
            return mask               # 정답 조합을 찾았다
    return None                        # 2^n 가지를 전부 뒤졌는데도 없음
----

지수적 증가의 실체를 정확히 측정하기 위해, **답이 존재하지 않는 최악의 경우(Worst Case)**를 주어 컴퓨터가 $2^n$가지 조합을 끝까지 100% 탐색하도록 만듭니다.

== 2. 실제 노트북에서 측정한 벤치마크 결과

$n$을 16부터 24까지 겨우 2씩 늘려가며 실제 실행 시간을 측정했습니다 (일반적인 M-시리즈 노트북 환경).

....
                 [ 부분집합 합 문제의 실측 계산 시간 ]

   입력 크기 (n)    탐색할 경우의 수 (2ⁿ)       실제 풀이 시간 (solve)
   ───────────────────────────────────────────────────────────────────
   n = 16                 65,536 가지             35.06 ms
   n = 18                262,144 가지            136.30 ms (약 4배 ↑)
   n = 20              1,048,576 가지            612.96 ms (약 4.5배 ↑)
   n = 22              4,194,304 가지          2,711.86 ms (약 4.4배 ↑)
   n = 24             16,777,216 가지         11,798.02 ms (약 4.3배 ↑)
....

* $n$이 16에서 24로 **겨우 8만큼(1.5배) 늘어났을 뿐**인데, 풀이 시간은 **35ms에서 약 11.8초로 무려 336배 폭증**했습니다
* $n$이 2 늘어날 때마다 시간이 정확히 $2^2 = 4$배씩 곱해집니다.
* 이 추세라면 $n=40$일 때 며칠, $n=60$이면 수천 년이 걸립니다. 체스판의 쌀알이 현실의 CPU 위에서 그대로 재현된 것입니다.

== 3. 반면 정답 확인(검증)은 얼마나 걸릴까? ($O(n)$)

이번에는 누군가 "이 조합(`mask`)이 정답이야!"라며 답을 주었을 때, 그게 맞는지 검산하는 함수를 돌려봅니다.

[source,python]
----
def verify_subset_sum(nums, target, mask):
    # 선택된 숫자들의 합을 단 한 번만 계산하여 비교 (O(n) 다항 시간)
    return sum(nums[i] for i in range(len(nums)) if mask & (1 << i)) == target
----

[source]
----
verify (n = 24): 0.0101 ms (약 10 마이크로초)
----

== 결과: 100만 배의 거대한 격차

....
                 [ n=24 일 때 풀기와 확인하기의 실측 비교 ]

      【 답을 직접 찾기 (풀기) 】 ──► 11,798.02 ms (약 11.8초)
                                           │
                                           │  【 약 1,168,000 배 차이 】
                                           ▼
      【 주어진 답을 검증 (확인) 】 ──►      0.01 ms (0.00001초)
....

똑같은 $n=24$ 문제인데:
* 직접 풀 때는 **11,800ms**가 걸렸지만,
* 답을 검산할 때는 **0.01ms**밖에 걸리지 않았습니다.

**"풀기는 어려운데 확인은 백만 배나 쉽다"**는 NP의 핵심 정의가 컴퓨터 위에서 명백한 숫자로 증명된 것입니다

[NOTE]
====
**"부분집합 합 문제는 동적 계획법(DP)으로 빠르게 풀 수 있지 않나요?"**  
좋은 지적입니다 부분집합 합 문제는 숫자들이 작을 때 표를 채우는 동적 계획법(DP)으로 빠르게 풀 수 있습니다. 하지만 이 알고리즘의 실행 시간은 '숫자의 개수($n$)'가 아니라 '숫자 자체의 크기($W$)'에 비례하므로, 엄밀한 의미의 다항 시간이 아니라 **의사 다항 시간(Pseudo-polynomial Time)**에 불과합니다. 숫자의 자릿수가 커지면 여전히 지수 시간으로 폭발하므로, NP-완전이라는 이 문제의 본질적 난이도는 변하지 않습니다.
====

== 요약

* **지수 폭발의 실측**: $n$이 16에서 24로 늘어나는 동안 풀이 시간이 35ms에서 11.8초로 336배 폭증했습니다.
* **검증의 순식간**: 같은 $n=24$에서 검산 시간은 0.01ms로, 풀이와 확인 사이에 **100만 배가 넘는 경이로운 시간 격차**를 실측했습니다.
* **NP의 실체**: 3장에서 배운 "NP의 비대칭성"이 추상적인 사변이 아니라 실제 컴퓨터 시스템의 물리적 현실임을 확인했습니다.
