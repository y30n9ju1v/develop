3장에서 `P ⊆ NP`(P가 NP 안에 들어있다)까지는 쉽게 보였습니다. 이제 이 책의 제목이 던지는 진짜 질문을 세워봅시다.

== 질문: 반대 방향도 성립하는가

`P ⊆ NP`는 "풀 수 있으면 확인도 된다"는, 상식적으로 당연한 방향이었습니다. 진짜 질문은 이겁니다 — **"확인이 쉬운 문제는 전부, 사실은 풀이도 쉬운 것 아닐까?"** 다시 말해 `NP ⊆ P`도 성립해서, 결국 `P = NP`가 되는 건 아닐까요?

직관적으로는 "아니오"일 것 같습니다 — 스도쿠 답을 확인하는 것과 스도쿠를 처음부터 푸는 것은 체감상 너무 다른 일이니까요. 하지만 **직관과 증명은 다릅니다.** "확인 쉬운 문제 중에 풀이가 어려운 게 정말 존재한다"는 걸 수학적으로 증명한 사람은 지금까지 아무도 없습니다. 그렇다고 "모든 확인 쉬운 문제는 사실 풀이도 쉽다(P=NP)"는 걸 증명한 사람도 없습니다. 이게 바로 **P vs NP 문제**입니다 — 둘 중 어느 쪽인지, 반세기 넘게 아무도 답을 내놓지 못했습니다.

== 만약 P=NP라면 무슨 일이 벌어지는가

여기서 왜 이게 그렇게 큰 문제인지 감을 잡아봅시다. 만약 정말로 `P=NP`라면, "정답을 확인하기 쉬운 모든 문제는 다항 시간 안에 풀 수도 있다"는 뜻이 됩니다 — 스도쿠도, 최적의 트럭 배송 경로도, 심지어(이 부분은 8장에서 다시 다루지만) 오늘날의 암호 체계가 기대는 어려운 문제들도 전부 다항 시간에 풀리는 방법이 원리적으로 **존재한다**는 뜻입니다. "존재한다"와 "우리가 그 방법을 찾았다"는 다른 이야기지만, 존재 자체가 보장된다는 것만으로도 세상이 크게 흔들릴 만한 소식입니다.

반대로 `P≠NP`라면, 확인은 쉬운데 풀이는 근본적으로(어떤 영리한 방법을 써도) 다항 시간 안에는 불가능한 문제가 실제로 존재한다는 뜻입니다 — 우리가 지금 스도쿠나 최적 경로 찾기 앞에서 느끼는 "확인은 금방인데 풀기는 왜 이렇게 어렵지"라는 감각이, 단순히 우리가 게을러서가 아니라 **논리적으로 필연적인 한계**라는 뜻이 됩니다.

[NOTE]
====
**흔히 헷갈리는 지점**: "아직 아무도 다항 시간 알고리즘을 못 찾았다"는 걸 "그러니 `P≠NP`가 맞다"는 증거로 여기기 쉽습니다. 하지만 이건 증명이 아닙니다 — 2장에서 본 소수 판정 문제처럼, 오랫동안 아무도 못 찾다가 나중에 다항 시간 알고리즘이 발견된 사례가 실제로 있었습니다. "지금까지 못 찾았다"는 건 강력한 정황일 뿐, `P≠NP`가 참이라는 수학적 증명이 되지는 않습니다 — 이 구분이 이 문제가 왜 여전히 "미해결"인지의 핵심입니다.
====

== 대부분의 전문가는 어느 쪽을 믿는가

증명되지는 않았지만, 컴퓨터 과학자 대부분은 `P≠NP`일 거라고 믿습니다 — 반세기 가까이 전 세계의 뛰어난 사람들이 스도쿠나 부분집합 합 문제 같은 것들에 다항 시간 알고리즘을 찾으려고 매달렸는데도 하나도 못 찾았다는 사실이, 비록 증명은 아니어도 상당히 강력한 정황 증거이기 때문입니다. 하지만 "많은 사람이 그렇게 믿는다"는 것과 "증명됐다"는 것은 전혀 다른 이야기라는 걸 이 책은 계속 강조할 것입니다.

[TIP]
====
**확인 질문**: `P ⊆ NP`는 이 책 3장에서 이미 증명하듯이 보여준 방향이고, `NP ⊆ P`(즉 P=NP)는 아직 아무도 증명도 반증도 못한 방향입니다. 이 둘의 차이를 자신의 말로 한 문장씩 정리해보고, 왜 "증명된 방향"과 "증명되지 않은 방향"이 이 장에서 이렇게 뚜렷하게 나뉘는지 생각해보세요.
====

== 요약

* 이 책의 핵심 질문은 "확인이 쉬운 문제는 전부 풀이도 쉬운가", 즉 `NP ⊆ P`(그래서 `P=NP`)가 성립하는가입니다.
* `P=NP`인지 `P≠NP`인지는 반세기 넘게 증명도 반증도 되지 않은 미해결 문제입니다.
* 대부분의 전문가는 `P≠NP`를 믿지만, 이건 정황 증거에 기반한 믿음이지 수학적 증명이 아닙니다.
