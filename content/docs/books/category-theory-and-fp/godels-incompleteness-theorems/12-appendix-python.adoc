이 부록은 본문과 독립적입니다 — 건너뛰어도 이 책을 이해하는 데 지장이 없습니다. 6장에서 "문장틀에 자기 자신의 괴델 수를 채워 넣는다"는 방법으로 자기 지시적 문장 `G`를 만들었습니다. 이 부록에서는 정확히 같은 정신(자기 자신을 코드나 데이터로 다뤄서, 결국 자기 자신을 만들어내게 하는 것)을 실제 프로그램으로 구현한 **쿼인(quine)** — 실행하면 자기 자신의 소스 코드를 그대로 출력하는 프로그램 — 을 파이썬으로 직접 만들어 실행합니다.

== 쿼인을 만드는 발상

쿼인을 만드는 핵심 아이디어는 6장의 사진 비유와 정확히 같습니다 — 프로그램의 소스 코드 중 "고정된 틀"과 "그 틀 자신을 표현한 데이터"를 분리해서, 그 데이터를 틀에 채워 넣으면 원래의 전체 소스가 다시 나오게 만드는 것입니다. 6장에서 "빈칸이 있는 문장틀"에 "그 틀 자신의 괴델 수"를 채워 넣었던 것처럼, 여기서는 "문자열 하나를 출력 형식에 채워 넣는 코드"에 "그 코드 자신을 나타내는 문자열"을 채워 넣습니다.

[source,python]
----
s = 's = %r\nprint(s %% s)'
print(s % s)
----

이 프로그램을 뜯어봅시다 — 변수 `s`에는 "`s = ` 다음에 어떤 문자열이 오고, 그다음 줄에 `print(s % s)`가 온다"는 틀이 문자열로 저장되어 있습니다(`%r`은 "이 자리에 문자열을 따옴표로 감싸 그대로 채워 넣어라"는 표시입니다). `print(s % s)`는 이 틀(`s`) 안의 `%r` 자리에 **바로 그 틀 자신(`s`)**을 채워 넣어서 출력하라는 뜻입니다 — 6장의 "빈칸에 틀 자신의 괴델 수를 채워 넣는다"는 구성을, 괴델 수 대신 문자열로 그대로 재현한 것입니다.

== 실제로 실행해서 확인하기

이 프로그램을 실행한 출력을, 원래 소스 코드와 실제로 비교해봤습니다.

[source]
----
$ python3 quine.py > quine_output.py
$ diff quine.py quine_output.py
(차이 없음)
----

`diff`가 아무 차이도 보고하지 않았습니다 — 프로그램을 실행한 결과가, 그 프로그램 자신의 소스 코드와 **문자 그대로 정확히 일치**한다는 뜻입니다. 여기서 한 걸음 더 나아가, 이 출력물(`quine_output.py`)을 **다시 실행**해봤습니다.

[source]
----
$ python3 quine_output.py > quine_output2.py
$ diff quine_output.py quine_output2.py
(차이 없음)
----

역시 차이가 없습니다 — 이 프로그램은 몇 번을 다시 실행해도 항상 정확히 자기 자신을 출력하는, 진짜 **고정점(fixed point)**입니다. 6장에서 다룬 `G`가 "자기 자신의 괴델 수를 담고 있어서, 자기 자신에 대한 문장이 되는" 고정점이었던 것과 정확히 같은 구조를, 여기서는 "자기 자신의 소스 코드를 출력하는" 실행 가능한 형태로 직접 확인한 것입니다.

[NOTE]
====
**흔히 헷갈리는 지점**: 쿼인이 "자기 자신을 읽어서 출력하는 프로그램"이라고 오해하기 쉽습니다(예를 들어 자기 파일을 열어서 그 내용을 그대로 화면에 뿌리는 프로그램). 진짜 쿼인은 **자신의 소스 코드를 담은 파일을 전혀 읽지 않고도** 자기 자신을 재구성해 출력합니다 — 본문의 코드는 파일을 여는 어떤 명령도 쓰지 않았습니다, 오직 "틀"과 "그 틀 자신을 나타내는 문자열"만으로 전체를 재구성했습니다. 이 차이가 중요한 이유는, 6장의 `G`도 "자기 괴델 수가 적힌 어딘가를 참조"하는 게 아니라, **대각선 보조정리라는 순수한 논리적 구성만으로** 자기 자신을 가리키게 되기 때문입니다 — 쿼인과 `G` 둘 다, "바깥에서 자신을 들여다보는" 게 아니라 "자기 안의 구조만으로 자기 자신을 만들어낸다"는 게 핵심입니다.
====

== 이 실험이 확인해주는 것

이 부록이 보여주는 건 크지 않지만 분명합니다 — 6장에서 "빈칸을 채워 자기 자신을 가리키는 문장을 만든다"는 구성이, 추상적인 논리 게임이 아니라 실제로 컴퓨터 위에서 몇 줄의 코드로 구현되고 실행되며 검증까지 되는, **실재하는 구성**이라는 것입니다. 괴델의 `G`가 "궤변처럼 들리지만 실제로는 엄밀하게 지어지는 문장"이었던 것처럼, 쿼인도 "역설처럼 들리지만 실제로 동작하는 프로그램"입니다 — 자기 지시가 논리적으로도, 실제 코드로도 모순 없이 구현될 수 있다는 걸 이 부록에서 직접 확인했습니다.

== 요약

* `s = 's = %r\nprint(s %% s)'; print(s % s)`라는 파이썬 쿼인을 작성해 실제로 실행했더니, 출력이 원본 소스 코드와 한 글자도 다르지 않다는 걸 `diff`로 확인했습니다.
* 이 출력물을 다시 실행해도 똑같은 결과가 나온다는 걸 확인해, 이 프로그램이 진짜 고정점이라는 걸 검증했습니다.
* 쿼인은 파일을 읽지 않고도 "틀과 그 틀 자신을 나타내는 데이터"만으로 자기 자신을 재구성하는데, 이게 6장의 대각선 보조정리(빈칸에 자기 자신의 괴델 수를 채워 넣는 것)와 정확히 같은 자기 지시 구조를 실제 코드로 구현한 것입니다.

이 부록에서 다룬 건 본문 5~6장이 논증으로 보여준 것의 아주 작은 확인일 뿐입니다 — 더 파고들고 싶다면, 파이썬이 아닌 다른 언어(C나 자바스크립트)로도 쿼인을 직접 짜보면서, "틀과 자기 참조 데이터를 분리한다"는 이 발상이 언어를 가리지 않고 통한다는 걸 확인해보는 것도 좋은 다음 걸음입니다.
