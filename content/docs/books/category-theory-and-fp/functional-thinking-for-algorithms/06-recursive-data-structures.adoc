== 리스트의 정의를 다시 보기

1장에서 리스트를 이렇게 정의했습니다.

....
    리스트 = 비어있거나(`[]`), 머리 하나와 꼬리 하나로 이루어져 있다.
....

여기서 "꼬리"가 뭔지 다시 봅시다 — 꼬리도 결국 **리스트**입니다. 즉 리스트라는 정의 안에 리스트라는 단어가 다시 등장합니다. 이게 재귀적 정의가 함수뿐 아니라 **자료구조**에도 적용될 수 있다는 첫 번째 힌트입니다. 지금까지는 "이미 주어진" 파이썬 리스트(`[1, 2, 3]`)를 재귀 함수로 다뤘지만, 이번엔 자료구조 자체를 재귀적으로 지어보겠습니다.

== 트리를 같은 방식으로 정의하기

트리(tree)를 리스트와 똑같은 틀로 정의해봅시다.

....
    이진 트리 = 비어있거나, 값 하나와 두 개의 부분 트리(왼쪽, 오른쪽)로 이루어져 있다.
....

리스트의 "꼬리 하나"가 트리에서는 "부분 트리 두 개(왼쪽, 오른쪽)"로 바뀌었을 뿐, 정의의 모양은 똑같습니다 — **비어있는 경우(기저 사례)와, 자기 자신을 참조하는 경우(재귀 사례)**. 이걸 파이썬 클래스로 옮기면:

[source,python]
----
class Node:
    def __init__(self, value, left=None, right=None):
        self.value = value
        self.left = left    # None이면 왼쪽 부분 트리가 비어있다는 뜻
        self.right = right  # None이면 오른쪽 부분 트리가 비어있다는 뜻
----

`left`와 `right`가 `None`이면 "빈 트리"(기저 사례)이고, `Node` 객체가 들어있으면 "값 하나 + 부분 트리 두 개"(재귀 사례)입니다. 다음 트리를 만들어봅시다.

....
        4
      /   \
     2     7
    / \     \
   1   3     9
....

[source,python]
----
t = Node(4,
          Node(2, Node(1), Node(3)),
          Node(7, None, Node(9)))
----

== 트리 위의 함수들도 정의를 그대로 옮기면 된다

리스트 함수를 짤 때 했던 것과 완전히 같은 방식으로, 트리 함수도 "기저 사례는? 재귀 사례는?"만 물으면 됩니다.

**트리의 노드 개수**: 빈 트리는 `0`개. 노드가 있는 트리는 `1개(자기 자신) + 왼쪽 부분 트리의 개수 + 오른쪽 부분 트리의 개수`.

[source,python]
----
def tree_size(node):
    if node is None:
        return 0
    return 1 + tree_size(node.left) + tree_size(node.right)
----

**트리의 깊이**: 빈 트리는 `0`. 노드가 있는 트리는 `1 + (왼쪽과 오른쪽 중 더 깊은 쪽의 깊이)`.

[source,python]
----
def tree_depth(node):
    if node is None:
        return 0
    return 1 + max(tree_depth(node.left), tree_depth(node.right))
----

**트리 값의 합**: 빈 트리는 `0`. 노드가 있는 트리는 `자기 값 + 왼쪽 합 + 오른쪽 합`.

[source,python]
----
def tree_sum(node):
    if node is None:
        return 0
    return node.value + tree_sum(node.left) + tree_sum(node.right)
----

[source]
----
tree_size(t)   -> 6
tree_depth(t)  -> 3
tree_sum(t)    -> 26
tree_size(None) -> 0
----

리스트 함수(`length`, `sum_list`)와 나란히 놓아보면, 정확히 같은 틀에서 "재귀 호출이 하나(꼬리)냐 둘(왼쪽·오른쪽)이냐"만 다르다는 게 보입니다.

....
[ 리스트 함수 ]                        [ 트리 함수 ]

length([])       = 0                  tree_size(빈 트리)  = 0
length(머리:꼬리) = 1 + length(꼬리)    tree_size(노드)     = 1 + tree_size(왼쪽) + tree_size(오른쪽)
....

== 트리 위에서 구조적 귀납이 어떻게 바뀌는가

2장에서 리스트 함수를 증명할 때는 "귀납 가정"이 하나였습니다 — "길이 `k`인 리스트에 대해 맞다고 가정하면". 트리는 재귀 호출이 두 갈래(왼쪽, 오른쪽)이므로, 귀납 가정도 **두 갈래 모두에 대해** 세웁니다.

**증명하고 싶은 것**: 모든 트리 `node`에 대해, `tree_size(node)`는 `node`가 담고 있는 실제 노드 개수와 같다.

**기저 사례**: `node`가 `None`(빈 트리)일 때. `tree_size(None)`은 `0`을 반환하고, 빈 트리의 실제 노드 개수도 `0`이므로 맞습니다.

**귀납 가정**: `node.left`와 `node.right`(각각 `node`보다 작은 부분 트리)에 대해서는 이미 `tree_size`가 맞게 동작한다고 가정합니다.

**귀납 단계**: `node`가 실제 노드를 가진 경우, `tree_size(node) = 1 + tree_size(node.left) + tree_size(node.right)`입니다. 귀납 가정에 의해 `tree_size(node.left)`와 `tree_size(node.right)`는 각각 왼쪽·오른쪽 부분 트리의 실제 노드 개수와 같습니다. 그러니 `tree_size(node)`는 `1`(자기 자신) + 왼쪽 실제 개수 + 오른쪽 실제 개수, 즉 `node` 전체의 실제 노드 개수와 정확히 일치합니다.

[NOTE]
====
**"더 작다"는 게 숫자가 아니어도 되는가**
1~5장에서는 "더 작은 문제"가 항상 숫자(`n-1`)나 리스트 길이(`k`보다 작은 리스트)로 측정됐습니다. 트리에서는 "더 작다"는 게 **부분 트리로 내려가는 것**을 뜻합니다 — 숫자로 정확히 재긴 어렵지만, `node.left`와 `node.right`가 `node` 자신보다 "덜 복잡하다"(노드 수가 적거나, 최소한 자기 자신은 포함하지 않는다)는 건 명백합니다. 구조적 귀납이라는 이름 자체가 이걸 가리킵니다 — 숫자의 크기가 아니라 **자료구조의 구조**(부분으로 쪼개는 방식)를 따라 증명이 진행된다는 뜻입니다. 리스트의 "꼬리"도, 트리의 "부분 트리"도, 결국 "원래 것보다 구조적으로 더 작은 조각"이라는 공통점 위에서 똑같은 논증이 통합니다.
====

== 트리를 순회하며 리스트로 만들기

트리와 리스트를 잇는 함수도 하나 봅시다 — 트리를 훑어서 정렬된 순서로 리스트를 만드는 **중위 순회(inorder traversal)**입니다.

....
    inorder(빈 트리) = []
    inorder(노드)     = inorder(왼쪽) + [자기 값] + inorder(오른쪽)
....

[source,python]
----
def inorder(node):
    if node is None:
        return []
    return inorder(node.left) + [node.value] + inorder(node.right)
----

[source]
----
inorder(t) -> [1, 2, 3, 4, 7, 9]
----

흥미롭게도 결과가 `[1, 2, 3, 4, 7, 9]`, 오름차순으로 정렬되어 있습니다. 이건 우연이 아니라, `t`를 만들 때 "왼쪽엔 항상 더 작은 값, 오른쪽엔 항상 더 큰 값"이 오도록 일부러 배치했기 때문입니다. 다음 장에서 이 성질(**이진 탐색 트리**)을 본격적으로 다룹니다 — 트리 모양 자체에 정렬 순서를 담아두면 무슨 일이 가능해지는지 보게 됩니다.

== 직접 해보기

트리를 좌우 대칭으로 뒤집는 `mirror` 함수를 재귀적으로 정의하고 코드로 짜보세요.

* 기저 사례: 빈 트리를 뒤집으면 무엇이 되나요?
* 재귀 사례: 노드 하나를 뒤집으려면, 왼쪽과 오른쪽 부분 트리에 각각 무슨 일이 일어나야 하나요?

.해답 보기
[%collapsible]
====
[source,python]
----
def mirror(node):
    if node is None:
        return None
    return Node(node.value, mirror(node.right), mirror(node.left))
----

[source]
----
inorder(t)          -> [1, 2, 3, 4, 7, 9]
inorder(mirror(t))  -> [9, 7, 4, 3, 2, 1]
----

기저 사례는 "빈 트리를 뒤집어도 빈 트리"입니다. 재귀 사례는 "새 노드를 만들되, 원래 오른쪽을 뒤집은 것을 새 왼쪽으로, 원래 왼쪽을 뒤집은 것을 새 오른쪽으로 넣는다"입니다. `mirror(t)`를 중위 순회하면 원래 순서의 정반대(내림차순)가 나온다는 것도, `mirror`가 왼쪽/오른쪽을 실제로 맞바꾸고 있다는 증거입니다.
====

== 요약

* 리스트가 "비어있거나, 머리 + 꼬리"로 재귀적으로 정의되듯, 트리도 "비어있거나, 값 + 두 부분 트리"로 재귀적으로 정의할 수 있습니다. 자료구조 자체가 재귀적 정의를 가지면, 그 위에서 동작하는 함수도 자연스럽게 재귀적으로 정의됩니다.
* 트리 함수는 재귀 호출이 두 갈래(왼쪽, 오른쪽)라는 점만 리스트와 다를 뿐, "기저 사례 + 재귀 사례"라는 틀은 똑같습니다.
* 구조적 귀납은 "더 작은 숫자"가 아니라 "더 작은 부분 구조"(리스트의 꼬리, 트리의 부분 트리)를 따라가는 증명 방식입니다. 트리에서는 귀납 가정을 왼쪽과 오른쪽, 두 갈래 모두에 대해 세워야 합니다.

다음 장에서는 값을 정해진 규칙(왼쪽엔 더 작은 값, 오른쪽엔 더 큰 값)에 따라 배치한 **이진 탐색 트리**를 다룹니다. 5장의 이진 탐색이 정렬된 리스트 위에서 했던 일을, 트리라는 자료구조 자체가 대신 해주면 무엇이 좋아지는지 봅니다.
