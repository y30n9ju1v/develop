== 그리디란 무엇인가

10장의 BFS는 "간선 개수"만 세면 최단 거리를 구할 수 있었습니다(모든 간선이 똑같이 "한 걸음"이었으니까요). 이번엔 간선마다 **가중치(weight)**가 다른 그래프에서 최단 경로를 구해봅니다 — 도시 사이의 거리, 도로의 통행 시간처럼요.

....
[ 가중치 그래프 예제: 간선과 무게 ]

    A - B : 4        B - D : 1
    A - C : 1        C - D : 5
    C - E : 8        D - E : 2
....

[source,python]
----
graph = {
    "A": [("B", 4), ("C", 1)],
    "B": [("A", 4), ("D", 1)],
    "C": [("A", 1), ("D", 5), ("E", 8)],
    "D": [("B", 1), ("C", 5), ("E", 2)],
    "E": [("C", 8), ("D", 2)],
}
----

**다익스트라 알고리즘(Dijkstra's algorithm)**의 전략은 단순합니다 — 매 단계마다, **아직 확정하지 않은 노드 중 지금까지 알려진 거리가 가장 짧은 노드**를 하나 골라 확정합니다. 미래를 내다보거나 여러 경우의 수를 따져보지 않고, **눈앞에서 가장 좋아 보이는 걸 그냥 고르는** 이런 전략을 **그리디(greedy)**라고 부릅니다.

[source,python]
----
import heapq

def dijkstra(graph, start):
    dist = {node: float("inf") for node in graph}
    dist[start] = 0
    pq = [(0, start)]
    visited = set()
    while pq:
        d, node = heapq.heappop(pq)   # 지금까지 알려진 거리 중 가장 짧은 것을 고른다
        if node in visited:
            continue
        visited.add(node)
        for neighbor, weight in graph[node]:
            new_dist = d + weight
            if new_dist < dist[neighbor]:
                dist[neighbor] = new_dist
                heapq.heappush(pq, (new_dist, neighbor))
    return dist
----

[source]
----
dijkstra(graph, "A") -> {'A': 0, 'B': 4, 'C': 1, 'D': 5, 'E': 7}
----

== 그리디가 왜 위험할 수 있는가

그리디 전략은 항상 위험한 도박처럼 보일 수 있습니다 — "지금 당장 가장 좋아 보이는 것"이 "전체적으로 가장 좋은 것"이라는 보장이 있나요? 사실 대부분의 문제에서는 **없습니다.** 등산할 때 매 순간 가장 가파르게 올라가는 방향만 골라도 정상에 도착한다는 보장이 없는 것과 비슷합니다(다른 봉우리의 중턱에서 막힐 수 있죠). 그래서 그리디 알고리즘을 쓰려면, "이 문제에서는 매 순간의 최선이 정말로 전체 최적해로 이어진다"는 걸 **증명**해야 합니다. 증명 없이 그리디를 쓰는 건 그냥 운에 맡기는 것과 다르지 않습니다.

다익스트라가 맞는 이유를 2장에서 배운 구조적 귀납으로 확인해봅시다.

**증명하고 싶은 것**: 어떤 노드가 `visited`에 추가되는 순간, 그때 확정된 거리(`d`)는 시작점에서 그 노드까지의 진짜 최단 거리다.

**기저 사례**: 첫 번째로 `visited`에 들어가는 건 항상 `start` 자신이고, 거리 `0`은 자명하게 최단 거리입니다.

**귀납 가정**: 지금까지 `visited`에 들어간 노드들의 확정된 거리는 모두 진짜 최단 거리라고 가정합니다.

**귀납 단계**: 다음으로 확정될 노드 `v`를 봅시다(우선순위 큐에서 가장 작은 거리로 뽑힌 노드입니다). `v`로 가는 진짜 최단 경로가 있다면, 그 경로는 어느 지점에서 `visited`(이미 확정된 노드들)를 떠나 `visited` 밖으로 나가야 합니다. 그런데 **모든 간선의 가중치는 `0`보다 크므로**, `visited`를 떠나는 첫 걸음까지의 거리만 해도 이미 `v`가 뽑힐 때의 거리(`d`) 이상일 수밖에 없습니다 — 왜냐하면 그 첫 걸음 지점도 우선순위 큐 안에 있었을 것이고, `v`가 가장 작은 값으로 뽑혔다는 건 다른 모든 후보가 `d` 이상이라는 뜻이기 때문입니다. 그러니 `visited`를 거쳐 다른 경로로 돌아가 봤자 `v`를 더 짧게 만들 수 없고, 지금 확정하는 `d`가 곧 최단 거리입니다.

기저 사례와 귀납 단계가 확인되었으니, **모든 노드가 확정되는 순간마다** 그 거리가 최단 거리라는 게 증명됩니다.

[NOTE]
====
**"가중치가 0보다 크다"는 조건이 왜 중요한가**
방금 증명에서 "간선 가중치가 항상 양수"라는 조건을 썼습니다. 만약 음수 가중치 간선이 있다면 어떻게 될까요? `visited`를 떠나는 첫걸음이 오히려 지금까지의 거리보다 **더 짧아질 수** 있으므로, 이미 확정한 노드를 나중에 더 짧은 경로로 다시 갱신해야 하는 상황이 생길 수 있습니다 — 그러면 "한 번 확정하면 다시 안 바뀐다"는 귀납 가정 자체가 무너집니다. 실제로 다익스트라는 음수 가중치가 있는 그래프에서는 틀린 답을 낼 수 있습니다(이런 경우엔 벨만-포드 알고리즘 같은 다른 방법을 씁니다). **그리디 알고리즘의 정당성 증명은 항상 문제의 조건에 강하게 의존한다**는 걸 보여주는 좋은 예시입니다 — 조건이 하나 바뀌면 증명도, 심지어 알고리즘 자체의 정답 여부도 바뀝니다.
====

== 다른 얼굴의 그리디: 최소 신장 트리

그래프의 모든 노드를 가장 싼 비용으로 하나로 연결하는 문제(도로망을 최소 비용으로 짓는 것과 비슷합니다)를 **최소 신장 트리(minimum spanning tree, MST)**라고 부릅니다. 이 문제도 그리디로 풉니다 — 대표적으로 **프림 알고리즘(Prim's algorithm)**은 다익스트라와 거의 똑같은 뼈대를 씁니다.

....
[ 다익스트라 vs 프림, 뼈대 비교 ]

  다익스트라: 매번 "시작점에서부터의 누적 거리"가 가장 짧은 노드를 확정
  프림:      매번 "지금까지 만든 트리에서 새 노드까지의 간선 하나"가 가장 싼 것을 확정
....

차이는 딱 하나 — 다익스트라는 "시작점부터의 누적 거리"를 기준으로 삼고, 프림은 "지금 트리에 걸쳐 있는 간선 하나의 무게"만 기준으로 삼습니다. 코드로 보면 이 차이가 얼마나 작은지 느껴집니다.

[source,python]
----
def prim_mst(graph, start):
    visited = {start}
    edges = [(w, start, v) for v, w in graph[start]]
    heapq.heapify(edges)
    mst = []
    total = 0
    while edges and len(visited) < len(graph):
        w, u, v = heapq.heappop(edges)
        if v in visited:
            continue
        visited.add(v)
        mst.append((u, v, w))
        total += w
        for nxt, w2 in graph[v]:
            if nxt not in visited:
                heapq.heappush(edges, (w2, v, nxt))
    return mst, total
----

[source]
----
prim_mst(graph, "A") -> ([('A', 'C', 1), ('A', 'B', 4), ('B', 'D', 1), ('D', 'E', 2)], 8)
----

프림의 그리디 선택("트리 밖으로 나가는 가장 싼 간선을 고른다")이 왜 정당한지도 다익스트라와 비슷한 모양의 귀납으로 증명할 수 있습니다 — "지금까지 고른 간선들이 어떤 최소 신장 트리의 일부일 수 있다"는 걸 귀납 가정으로 잡고, 매번 고르는 최소 간선을 추가해도 그 성질이 깨지지 않는다는 걸 보이는 식입니다(이 논증을 **교환 논증(exchange argument)**이라고 부르는데, 상세한 증명은 이 책의 범위를 넘어서는 그래프 이론 교재에서 다룹니다).

== 요약

* 그리디 알고리즘은 매 순간 눈앞의 최선만 선택합니다. 이게 전체 최적해로 이어진다는 보장은 문제마다 다르므로, 반드시 **증명**이 필요합니다 — 증명 없는 그리디는 운에 맡기는 것과 같습니다.
* 다익스트라의 정당성은 구조적 귀납으로 증명됩니다 — 이미 확정한 노드들의 거리가 전부 최단 거리라는 귀납 가정 위에서, 다음으로 확정되는 노드의 거리도 최단 거리라는 걸 보입니다. 이 증명은 **모든 간선 가중치가 양수**라는 조건에 의존합니다.
* 최소 신장 트리를 구하는 프림 알고리즘은 다익스트라와 거의 같은 뼈대를 쓰지만, "시작점부터의 누적 거리" 대신 "트리에 새로 붙는 간선 하나의 무게"만 본다는 점에서 갈립니다.

이제 이 책의 핵심 도구(재귀, 귀납)를 정렬·자료구조·동적 계획법·그래프까지 두루 적용해봤습니다. 마지막 부에서는 두 가지로 마무리합니다 — 재귀를 실전에서 반복문으로 바꾸는 법(12장), 그리고 이 모든 이야기가 애초에 왜 가능했는지를 람다 계산법으로 되짚어보는 것(13장)입니다.
