== 지나온 길

1장에서 시작한 질문 하나로 이 책 전체를 관통했습니다 — **"재귀란 정의를 정의로 푸는 것이다."** 그 위에 쌓아 올린 게 이겁니다.

....
[ 이 책에서 반복된 하나의 틀 ]

  기저 사례 + 재귀 사례                 (1장: 재귀적 정의)
        │
        ▼
  기저 사례가 맞고, 더 작은 경우가        (2장: 구조적 귀납 — 왜 항상 맞는가)
  맞으면 더 큰 경우도 맞다
        │
        ▼
  재귀 관계를 풀면 실행 시간이 나온다     (3장: T(n) = ... 을 펼쳐 적기)
        │
        ▼
  이 틀을 정렬(4~5장), 트리(6~7장),
  DP(8~9장), 그래프(10~11장)에 반복 적용
        │
        ▼
  실전에서는 반복문으로 바꾸기도 한다     (12장: 꼬리 재귀 → 루프)
....

정렬 알고리즘의 시간 복잡도를 외우는 대신, 매번 "기저 사례가 뭔가, 재귀 사례가 어떻게 더 작아지는가, 그러므로 귀납이 어떻게 성립하는가"라는 같은 세 질문을 던졌습니다. 이제 마지막으로, 이 틀 자체가 **왜 처음부터 성립할 수 있었는지**를 물어볼 차례입니다.

== 이름 없이 재귀하기, 다시

link:../lambda-calculus-and-computability/[람다 계산법과 계산 가능성] 5장은 파이썬의 `def factorial(n): ... factorial(n-1) ...`처럼 이름으로 자기 자신을 부르지 않고도 재귀가 가능하다는 걸 **Y 콤비네이터**로 보였습니다. 그 책 부록에서 실제로 실행해 확인한 코드를 그대로 가져와 봅시다(파이썬은 값을 즉시 계산하는 언어라 순수한 Y 콤비네이터 대신 **Z 콤비네이터**라는 변형을 씁니다 — 핵심 원리는 같습니다).

[source,python]
----
Z = lambda f: (lambda x: f(lambda v: x(x)(v)))(lambda x: f(lambda v: x(x)(v)))

def fact_gen(self_fact):
    return lambda n: 1 if n == 0 else n * self_fact(n - 1)

factorial = Z(fact_gen)
----

[source]
----
factorial(0)  -> 1
factorial(1)  -> 1
factorial(5)  -> 120
factorial(10) -> 3628800
----

`fact_gen`을 1장의 정의와 나란히 놓아봅시다.

....
[ 1장: factorial의 재귀 정의 ]              [ fact_gen: 이름 없는 버전 ]

def factorial(n):                          def fact_gen(self_fact):
    if n == 0:                                  return lambda n:
        return 1                                    1 if n == 0
    return n * factorial(n - 1)                     else n * self_fact(n - 1)
....

모양이 거의 똑같습니다. 차이는 딱 하나 — `factorial(n-1)`이라고 **자기 이름을 직접 부르는** 대신, `self_fact(n-1)`이라고 **매개변수로 받은 것을 부릅니다.** `fact_gen`은 재귀 함수가 아니라, **"재귀할 방법이 하나 주어지면, 그걸 이용해 팩토리얼 하나를 만들어주는 함수를 만드는 함수"**입니다. `Z`가 하는 일은 이 `fact_gen`에게 정확히 "재귀할 방법"으로 **자기 자신이 만들어낼 결과**를 되먹여주는 것입니다.

== 재귀는 고정점을 찾는 것이었다

이게 왜 중요한 통찰인지 짚어봅시다. `fact_gen`이 받는 `self_fact`에 진짜 `factorial` 함수를 넣으면 무슨 일이 벌어질까요?

....
    fact_gen(factorial) 은
        lambda n: 1 if n == 0 else n * factorial(n - 1)
    인데, 이건 factorial 자기 자신과 정확히 똑같은 함수입니다.

    즉:  fact_gen(factorial) = factorial
....

`factorial`은 `fact_gen`에 넣었을 때 **자기 자신이 다시 나오는** 특별한 입력입니다. 수학에서 `f(x) = x`를 만족하는 `x`를 `f`의 **고정점(fixed point)**이라고 부릅니다. `Z`(그리고 순수한 형태인 Y 콤비네이터)는 바로 이 고정점을 찾아주는 절차입니다 — **"재귀 사례를 한 겹 담고 있는 함수"를 받아서, 그 함수의 고정점(= 완성된 재귀 함수)을 돌려주는 것**입니다.

이제 2장에서 배운 구조적 귀납을 다시 봅시다. 귀납의 귀납 단계는 항상 이런 모양이었습니다 — **"더 작은 경우(`n-1`)가 맞다고 가정하면, 그 위에서 지금 경우(`n`)도 맞다는 걸 보인다."** 이건 `fact_gen`의 정의와 정확히 같은 문장입니다: "`self_fact`(더 작은 경우들에 대한 정답)가 주어지면, 그걸로 지금 `n`에 대한 정답을 만들어낸다." **구조적 귀납이 통하는 이유는, 재귀적 정의 자체가 이미 "더 작은 경우의 정답으로 큰 경우의 정답을 조립하는 함수"(`fact_gen` 같은 것)의 고정점을 묘사하고 있기 때문**입니다. 우리가 2장에서 "귀납 가정"이라고 부른 것이, 사실은 `self_fact` 자리에 들어갈 "아직 완성되지 않았지만 있다고 치는 더 작은 답"이었던 것입니다.

[NOTE]
====
**왜 굳이 이 우회로를 통해서 봐야 하는가**
파이썬은 `def factorial(n): ...`처럼 함수가 자기 이름을 직접 참조하게 해주므로, 실전에서 `Z` 콤비네이터를 쓸 일은 거의 없습니다. 이 장에서 Y/Z 콤비네이터를 다시 꺼낸 이유는 실용적인 도구를 알려주려는 게 아니라, **"자기 이름으로 자기를 부른다"는 편리한 문법을 걷어내고 나면 재귀의 정체가 무엇인지**를 보여주기 위해서입니다. 이름으로 자기를 부르는 건 재귀를 쓰는 여러 방법 중 하나(가장 편한 방법)일 뿐, 재귀의 본질은 "더 작은 경우의 답으로 더 큰 경우의 답을 조립하는 규칙의 고정점"에 있습니다. 이 사실을 한 번 보고 나면, 2장의 "귀납 가정"이 단순한 증명 기법의 요령이 아니라 재귀적 정의 그 자체의 수학적 실체라는 게 또렷해집니다.
====

== 처치 수와 반복: 숫자 안에 이미 들어있던 귀납

람다 계산법 책 3장은 숫자를 함수로 표현하는 **처치 수(Church numeral)**를 다뤘습니다. 숫자 `n`을 "어떤 함수 `f`를 `n`번 반복 적용하는 절차"로 정의하죠. 이것도 이 책의 틀로 다시 읽을 수 있습니다.

....
[ 처치 수의 재귀적 정의 ]

    0 = "f를 0번 적용" = 시작값을 그대로 반환
    n = "f를 n번 적용" = f(n-1번 적용한 결과)
....

이건 1장에서 본 팩토리얼의 정의(`0! = 1`, `n! = n × (n-1)!`)와 완전히 같은 모양입니다 — 기저 사례(`0`번 적용 = 아무것도 안 함)와 재귀 사례(`n`번 적용 = 한 번 더 적용한 `n-1`번). **숫자 그 자체가 이미 "기저 사례 + 재귀 사례"라는 틀로 정의되어 있었던 것**입니다. 이 책의 1장이 "재귀는 정의를 정의로 푸는 것"이라고 말한 문장이, 사실은 **자연수라는 가장 기본적인 개념 자체가 재귀적으로 정의된다**는 훨씬 오래된 사실(19세기 수학자 페아노가 공리로 정리한 것) 위에 서 있었던 셈입니다.

== 책을 마치며

이 책의 목표는 "알고리즘을 몇 개 더 아는 것"이 아니라, 알고리즘을 처음 마주쳤을 때 스스로에게 물을 수 있는 질문을 손에 쥐여주는 것이었습니다.

* 이 문제의 **기저 사례**는 무엇인가?
* **재귀 사례**는 어떻게 더 작은 문제로 향하는가?
* 그게 왜 **항상** 맞는지, 구조적 귀납이나 불변식으로 확인할 수 있는가?
* 재귀 관계를 세우면 실행 시간이 얼마나 나오는가?

이 네 가지 질문은 정렬에도, 트리에도, 동적 계획법에도, 그래프에도 똑같이 통했습니다. 그리고 이 장에서 본 것처럼, 이 질문들이 통하는 이유 자체가 함수라는 가장 단순한 재료 하나에서 나온다는 것도 확인했습니다.

혹시 이 책을 link:../lambda-calculus-and-computability/[람다 계산법과 계산 가능성]과 함께 읽지 않으셨다면, 이제 그 책의 5장(이름 없이 재귀하기)과 3장(숫자를 함수로 표현하기)을 읽어보시길 권합니다 — 이 장에서 급하게 스친 Y/Z 콤비네이터와 처치 수를, 붕어빵 틀과 스무고개 같은 비유로 훨씬 천천히 짚어줍니다. 그 책이 "함수만으로 무엇을 만들 수 있는가"를 보여줬다면, 이 책은 "그렇게 만들어진 재귀로 무엇을 풀 수 있는가"를 보여줬습니다. 두 책은 결국 같은 이야기의 앞뒤입니다.
