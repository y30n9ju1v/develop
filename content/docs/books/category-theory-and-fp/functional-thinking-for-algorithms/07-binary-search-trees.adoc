== 트리 모양 자체에 정렬 순서를 새겨 넣기

5장의 이진 탐색은 **이미 정렬된 리스트** 위에서 동작했습니다. 정렬 순서가 리스트라는 나열 안에 들어있었죠. 이번엔 정렬 순서를 **트리의 모양** 자체에 새겨 넣어봅니다. 이런 트리를 **이진 탐색 트리(binary search tree, BST)**라고 부르고, 규칙은 이렇습니다.

....
    모든 노드에 대해:
      왼쪽 부분 트리의 모든 값 < 이 노드의 값 < 오른쪽 부분 트리의 모든 값
....

[NOTE]
====
**"모든 값"이라는 말에 주의하세요**: 이 규칙은 "바로 왼쪽 자식"만이 아니라 **왼쪽 부분 트리 전체에 있는 모든 값**에 대해 성립해야 합니다. 노드 하나의 왼쪽 자식만 작다고 확인하는 걸로는 부족합니다 — 왼쪽 자식의 오른쪽 자식이 원래 노드보다 커져 버리면 규칙이 깨지기 때문입니다. 이 "전체에 대해"라는 조건이 6장에서 본 재귀적 정의와 잘 맞아떨어집니다: "왼쪽 부분 트리 자체가 이미 이 규칙을 만족하는 BST이고, 그 전체가 이 노드의 값보다 작다"는 재귀적인 조건이기 때문입니다.
====

== 삽입과 탐색을 재귀로 짜기

이 규칙을 지키면서 값을 삽입하는 함수를 봅시다. 기저 사례는 "빈 자리를 찾으면 거기에 새 노드를 만든다"이고, 재귀 사례는 "넣을 값이 지금 노드보다 작으면 왼쪽으로, 크면 오른쪽으로 내려간다"입니다.

[source,python]
----
class Node:
    def __init__(self, value, left=None, right=None):
        self.value = value
        self.left = left
        self.right = right

def bst_insert(node, value):
    if node is None:
        return Node(value)
    if value < node.value:
        return Node(node.value, bst_insert(node.left, value), node.right)
    else:
        return Node(node.value, node.left, bst_insert(node.right, value))

def bst_search(node, target):
    if node is None:
        return False
    if node.value == target:
        return True
    elif target < node.value:
        return bst_search(node.left, target)
    else:
        return bst_search(node.right, target)
----

[source,python]
----
t = None
for v in [5, 3, 8, 1, 4, 7, 9]:
    t = bst_insert(t, v)
----

[source]
----
inorder(t)             -> [1, 3, 4, 5, 7, 8, 9]
bst_search(t, 7)        -> True
bst_search(t, 6)        -> False
----

6장에서 만든 `inorder` 순회를 그대로 돌려보면 `[1, 3, 4, 5, 7, 8, 9]`, 오름차순으로 나옵니다. 이건 BST 규칙을 지키며 삽입한 결과가 항상 이렇게 나온다는 사실 자체를 보여줍니다.

`bst_search`가 5장의 이진 탐색과 얼마나 닮았는지 나란히 봅시다.

....
[ 5장: 정렬된 리스트 위의 이진 탐색 ]           [ 7장: BST 위의 탐색 ]

target < lst[mid] → 왼쪽 절반으로               target < node.value → 왼쪽 자식으로
target > lst[mid] → 오른쪽 절반으로              target > node.value → 오른쪽 자식으로
....

똑같은 아이디어를 리스트의 인덱스 범위(`lo`, `hi`)로 구현하면 5장의 이진 탐색이고, 트리의 포인터(`left`, `right`)로 구현하면 이번 장의 BST 탐색입니다.

== 정당성: 삽입이 규칙을 깨지 않는다는 것

`bst_search`가 맞다는 걸 증명하려면, 사실 그보다 먼저 **"BST 규칙이 항상 유지된다"**는 걸 확인해야 합니다. 이건 `bst_insert`에 대한 귀납으로 보입니다.

**증명하고 싶은 것**: `t`가 BST 규칙을 만족하는 트리라면, `bst_insert(t, value)`도 BST 규칙을 만족하는 트리다.

**기저 사례**: `t`가 `None`(빈 트리)일 때. `Node(value)`를 새로 만드는데, 자식이 둘 다 없는 노드 하나짜리 트리는 규칙을 만족할 수밖에 없습니다(비교할 다른 값이 없으니까요).

**귀납 가정**: `t.left`와 `t.right`에 삽입하는 경우에는 이미 각각 규칙을 만족하는 결과가 나온다고 가정합니다.

**귀납 단계**: `value < t.value`인 경우, `bst_insert(t.left, value)`를 새 왼쪽으로 씁니다. 귀납 가정에 의해 이 결과는 BST 규칙을 만족합니다. 그리고 `value < t.value`이니, 새로 들어간 `value`를 포함한 왼쪽 부분 트리 전체가 여전히 `t.value`보다 작다는 것도 보장됩니다(`value`도 작고, 원래 왼쪽 부분 트리의 다른 값들도 이미 작았으니까). 오른쪽은 건드리지 않았으니 그대로 규칙을 만족합니다. `value >= t.value`인 경우도 대칭적으로 성립합니다.

규칙이 항상 유지된다는 게 확인됐으니, `bst_search`가 "왼쪽엔 더 작은 값만, 오른쪽엔 더 큰 값만 있다"는 전제 위에서 방향을 고르는 것도 정당화됩니다 — 5장 이진 탐색의 불변식 논증과 정확히 같은 이유로 맞습니다.

== 삽입 순서가 속도를 좌우한다

탐색이 몇 걸음 걸리는지는 트리의 **깊이**에 달려 있습니다(한 걸음마다 한 층씩 내려가니까요). 그런데 깊이는 **어떤 순서로 값을 넣었는지**에 따라 완전히 달라집니다.

[source,python]
----
def tree_depth(node):
    if node is None:
        return 0
    return 1 + max(tree_depth(node.left), tree_depth(node.right))

t = None
for v in [5, 3, 8, 1, 4, 7, 9]:  # 뒤섞인 순서
    t = bst_insert(t, v)
print("뒤섞인 순서로 삽입한 깊이:", tree_depth(t))

t2 = None
for v in [1, 2, 3, 4, 5, 6, 7]:  # 이미 정렬된 순서
    t2 = bst_insert(t2, v)
print("정렬된 순서로 삽입한 깊이:", tree_depth(t2))
----

[source]
----
뒤섞인 순서로 삽입한 깊이: 3
정렬된 순서로 삽입한 깊이: 7
----

노드 `7`개가 똑같이 들어있는데, 뒤섞인 순서로 넣으면 깊이 `3`(대략 `log₂7 ≈ 2.8`에 가까움), 정렬된 순서로 넣으면 깊이 `7`(노드 개수와 같음)입니다. 정렬된 순서로 넣으면 매번 "지금까지 넣은 것 중 가장 큰 값"을 넣는 셈이라, 항상 오른쪽으로만 내려가서 사실상 **한 줄짜리 리스트와 다를 바 없는 모양**이 됩니다.

....
[ 뒤섞인 순서: 5,3,8,1,4,7,9 ]              [ 정렬된 순서: 1,2,3,4,5,6,7 ]

           5                                  1
         /   \                                 \
        3     8                                 2
       / \   / \                                 \
      1   4 7   9                                  3
                                                      \
      깊이 3, 탐색 O(log n)                             ⋱
                                                          7
                                              깊이 7, 탐색 O(n)
....

이건 5장에서 본 퀵 정렬의 "피벗 선택이 균형을 좌우한다"는 문제와 정확히 같은 그림입니다 — **재귀적으로 반씩 쪼개질 거라고 기대했던 구조가, 입력 순서에 따라 한쪽으로 쏠린 사슬로 퇴화할 수 있다**는 것입니다. `search`의 재귀 관계는 `T(depth)`이므로, 깊이가 `log n`이면 `O(log n)`, 깊이가 `n`이면 `O(n)`이 됩니다.

[TIP]
====
이 문제를 해결하려고 나온 것이 **자가 균형 트리(self-balancing tree)**입니다 — AVL 트리, 레드-블랙 트리 같은 자료구조는 삽입할 때마다 트리 모양을 조금씩 재조정해서, 어떤 순서로 넣든 깊이가 항상 `O(log n)`을 넘지 않도록 보장합니다. 이 책에서는 구현까지 다루진 않지만, "BST의 탐색 속도는 깊이에 달려 있고, 깊이는 삽입 순서에 따라 나빠질 수 있다"는 이 장의 결론이 왜 그런 자료구조가 필요한지에 대한 답입니다.
====

== 직접 해보기

BST에서 최솟값을 찾는 `bst_min` 함수를 재귀적으로 정의해보세요. BST 규칙(왼쪽엔 항상 더 작은 값)을 생각하면, 최솟값이 어느 방향에 있을지 힌트가 됩니다.

.해답 보기
[%collapsible]
====
[source,python]
----
def bst_min(node):
    if node.left is None:
        return node.value
    return bst_min(node.left)
----

[source]
----
bst_min(t)  -> 1     # t = [5,3,8,1,4,7,9]로 만든 트리
----

기저 사례는 "왼쪽 자식이 없는 노드에 도달했다"이고(그 노드보다 작은 게 더 없다는 뜻이니, 그게 최솟값입니다), 재귀 사례는 "왼쪽으로 계속 내려간다"입니다. BST 규칙 덕분에 "가장 왼쪽으로 끝까지 내려가면 최솟값이 나온다"는 게 보장되고, 이 함수도 트리의 깊이만큼만 걸리므로 삽입 순서가 나쁘면(정렬된 순서로 삽입) 최악의 경우 `O(n)`이 됩니다.
====

== 요약

* 이진 탐색 트리는 "왼쪽 부분 트리의 모든 값 < 노드 값 < 오른쪽 부분 트리의 모든 값"이라는 규칙을, 트리 모양 자체에 재귀적으로 새겨 넣은 자료구조입니다.
* `bst_insert`가 이 규칙을 항상 유지한다는 걸 구조적 귀납으로 증명하면, `bst_search`가 왼쪽/오른쪽 방향을 고르는 게 왜 정당한지도 함께 설명됩니다.
* 탐색 속도는 트리의 깊이에 달려 있고, 깊이는 삽입 순서에 따라 `O(log n)`(뒤섞인 순서)과 `O(n)`(정렬된 순서로 삽입해 사슬처럼 퇴화하는 경우) 사이를 오갑니다 — 5장의 퀵 정렬 피벗 문제와 같은 패턴입니다.
