== 팩토리얼을 두 가지 방식으로 정의해보기

`5!`(5 팩토리얼)이 뭐냐고 물으면, 대부분 이렇게 답할 겁니다: "5 곱하기 4 곱하기 3 곱하기 2 곱하기 1." 이걸 그대로 코드로 옮기면 반복문이 나옵니다.

[source,python]
----
def factorial_loop(n):
    result = 1
    for i in range(1, n + 1):
        result *= i
    return result
----

이건 완전히 맞는 코드입니다. 그런데 팩토리얼을 정의하는 **또 다른 방법**이 있습니다 — 수학 교과서에 나오는 정의를 그대로 봅시다.

....
    0! = 1
    n! = n × (n-1)!      (n > 0일 때)
....

이 정의는 `!`이라는 걸 **`!` 자기 자신을 써서** 정의합니다. 언뜻 순환 논리처럼 보이지만, 잘 보면 오른쪽의 `(n-1)!`은 왼쪽의 `n!`보다 **항상 더 작은 문제**입니다. `5!`를 구하려면 `4!`가 필요하고, `4!`를 구하려면 `3!`이 필요하고... 이렇게 계속 작아지다가 결국 `0!`에 도달하는데, `0!`은 더 이상 자기 자신을 참조하지 않고 그냥 `1`이라고 못박아 둡니다.

이 정의를 코드로 옮기면 이렇게 됩니다.

[source,python]
----
def factorial(n):
    if n == 0:
        return 1
    return n * factorial(n - 1)
----

[source]
----
factorial(0) = 1
factorial(1) = 1
factorial(2) = 2
factorial(3) = 6
factorial(4) = 24
factorial(5) = 120
----

....
[ factorial(3)의 호출과 반환 과정 ]

  호출 단계 (내려가기):
    factorial(3) = 3 × factorial(2)
                       2 × factorial(1)
                              1 × factorial(0)
                                     1 (기저 사례 도달!)

  반환 단계 (올라오며 곱하기):
    factorial(0) = 1
    factorial(1) = 1 × 1 = 1
    factorial(2) = 2 × 1 = 2
    factorial(3) = 3 × 2 = 6
....

여기서 강조하고 싶은 게 있습니다. 이 코드는 "반복문을 재귀로 바꾼 트릭"이 아닙니다. **수학 교과서의 정의를 글자 그대로 옮겨 적은 것**입니다. `if n == 0: return 1`이 `0! = 1`이고, `return n * factorial(n - 1)`이 `n! = n × (n-1)!`입니다. 번역에 가깝지, 발명이 아닙니다.

== 모든 재귀적 정의가 가진 두 부품

방금 본 팩토리얼 정의를 뜯어보면 항상 두 부분으로 나뉩니다.

* **기저 사례(base case)**: 더 이상 자기 자신을 참조하지 않고, 답을 직접 말해주는 지점. (`0! = 1`)
* **재귀 사례(recursive case)**: 더 작은 문제에 대한 답을 이용해서 지금 문제의 답을 만드는 규칙. (`n! = n × (n-1)!`)

이 두 부품이 재귀적 정의를 이루는 전부입니다. 앞으로 이 책에서 만날 모든 재귀 함수 — 정렬, 트리 순회, 동적 계획법 — 는 결국 "기저 사례가 뭔가?"와 "재귀 사례가 어떻게 더 작은 문제로 쪼개는가?"라는 두 질문에 대한 답입니다.

리스트 길이를 구하는 함수로 한 번 더 연습해봅시다. 리스트를 "비어있거나, 아니면 머리(head) 하나에 나머지 꼬리(tail)가 붙은 것"으로 봅니다.

....
    length([]) = 0
    length([머리 | 꼬리]) = 1 + length(꼬리)
....

[source,python]
----
def length(lst):
    if lst == []:
        return 0
    return 1 + length(lst[1:])
----

[source]
----
length([]) = 0
length([7]) = 1
length(['a', 'b', 'c', 'd']) = 4
----

기저 사례는 빈 리스트(`[]`), 재귀 사례는 "머리 하나를 떼어내고, 나머지 꼬리의 길이에 1을 더한다"입니다. 리스트 합계를 구하는 함수도 똑같은 모양입니다.

[source,python]
----
def sum_list(lst):
    if lst == []:
        return 0
    return lst[0] + sum_list(lst[1:])
----

[source]
----
sum_list([1, 2, 3, 4, 5]) = 15
----

`length`와 `sum_list`는 하는 일이 다른데도 코드 모양이 거의 똑같습니다. 이건 우연이 아닙니다 — 둘 다 "리스트를 재귀적으로 정의한다"는 같은 틀 위에서, 재귀 사례가 하는 계산만 다르게 채워 넣은 것뿐입니다. 이 틀 자체는 2부에서 병합 정렬을 볼 때도, 4부에서 트리를 순회할 때도 똑같이 반복됩니다.

== 왜 무한히 반복되지 않는가

재귀를 처음 볼 때 흔히 드는 걱정이 있습니다. "함수가 자기 자신을 부르면 영원히 안 끝나는 거 아닌가?" 답은: **재귀 사례가 항상 기저 사례에 더 가까운 더 작은 문제로 향해야 한다**는 것입니다.

`factorial(n)`은 `factorial(n-1)`을 부르고, `n-1`은 `n`보다 항상 작습니다. `length(lst)`는 `length(lst[1:])`를 부르고, `lst[1:]`는 `lst`보다 항상 원소가 하나 적습니다. 이렇게 "인자가 매번 엄격하게 작아진다"는 게 보장되면, 언젠가는 반드시 기저 사례에 도달하고 재귀가 멈춥니다.

[NOTE]
====
**흔히 헷갈리는 지점**: "재귀는 반복문보다 느리다"는 말을 자주 듣습니다. 파이썬 같은 언어에서는 함수를 호출할 때마다 실행 상태를 스택에 쌓아두는 비용이 있어서, 단순히 실행 속도만 보면 반복문이 더 빠른 경우가 많은 건 사실입니다. 하지만 이 책이 재귀를 다시 소개하는 이유는 "재귀가 반복문보다 빠르다"고 주장하려는 게 아닙니다. **재귀적 정의는 "왜 이 알고리즘이 맞는가"를 증명하기에 훨씬 편리한 형태**라는 게 핵심입니다 — 다음 장에서 바로 이 증명 방법(구조적 귀납)을 다룹니다. 실행 속도가 중요한 상황에서 재귀를 반복문으로 바꾸는 법은 12장에서 따로 다룹니다.
====

반대로, 재귀 사례가 기저 사례로 향하지 않으면 무슨 일이 벌어지는지도 확인해봅시다.

[source,python]
----
def broken_factorial(n):
    if n == 0:
        return 1
    return n * broken_factorial(n)  # n - 1이 아니라 n을 그대로 넘김
----

이 함수를 `broken_factorial(5)`로 불러보면, `n`이 절대 `0`에 가까워지지 않으므로 기저 사례에 영원히 도달하지 못합니다. 파이썬에서 이걸 실행하면 `RecursionError: maximum recursion depth exceeded`가 뜨는데, 이건 파이썬이 무한 재귀를 막기 위해 걸어둔 안전장치가 작동한 것입니다. 재귀가 멈추려면 **재귀 사례가 매번 더 작은 문제를 향해야 한다**는 조건이 코드 차원에서 반드시 지켜져야 한다는 걸 보여주는 예시입니다.

== 이름 없이도 재귀할 수 있다는 것

만약 link:../lambda-calculus-and-computability/[람다 계산법과 계산 가능성]의 5장을 읽으셨다면, 여기서 흥미로운 연결점이 하나 있습니다. 그 장에서는 `def factorial(n): ...`처럼 함수에 이름을 붙이지 않고도(즉 `factorial`이라는 이름으로 자기 자신을 부르지 않고도) 재귀가 가능하다는 걸 Y 콤비네이터로 보였습니다.

이게 말해주는 건 이겁니다 — **재귀는 "함수가 자기 이름을 아는 특별한 문법"이 아니라, 함수라는 재료 자체에서 자연스럽게 나오는 성질**이라는 것입니다. 파이썬의 `def factorial(n): ... factorial(n-1) ...`처럼 이름으로 자기 자신을 부르는 건 재귀를 쓰는 여러 방법 중 하나(이자 가장 편한 방법)일 뿐, 재귀의 본질은 "더 작은 자기 자신을 참조하는 정의"에 있습니다. 이 책에서는 편의를 위해 이름을 붙인 형태로 재귀를 계속 쓰지만, 그 이름이 재귀의 필수 조건은 아니라는 걸 기억해두면 좋습니다.

== 직접 해보기

리스트에서 최댓값을 찾는 함수를 재귀적 정의로 먼저 써보고, 그다음 코드로 옮겨보세요.

* 기저 사례: 원소가 하나뿐인 리스트의 최댓값은 무엇일까요?
* 재귀 사례: 리스트의 머리와, 꼬리의 최댓값 중 어느 쪽이 크냐에 따라 답이 달라지려면 어떻게 써야 할까요?

.해답 보기
[%collapsible]
====
[source,python]
----
def find_max(lst):
    if len(lst) == 1:
        return lst[0]
    rest_max = find_max(lst[1:])
    return lst[0] if lst[0] > rest_max else rest_max
----

[source]
----
find_max([3, 7, 2, 9, 4]) = 9
find_max([5]) = 5
----

기저 사례는 원소가 하나뿐인 리스트(`len(lst) == 1`)이고, 재귀 사례는 "머리를 떼어내고, 꼬리의 최댓값을 먼저 구한 다음, 머리와 그 최댓값을 비교"하는 것입니다. 빈 리스트(`[]`)는 최댓값이 정의되지 않으므로 기저 사례로 삼지 않았다는 점도 눈여겨보세요 — 기저 사례를 어디로 잡을지는 문제의 정의 자체에 달려 있습니다.
====

== 요약

* 재귀는 반복문의 변형이 아니라, **정의를 정의로 푸는 방법**입니다. 팩토리얼처럼 수학 교과서에 이미 있는 정의를 코드로 그대로 옮긴 것이 재귀 함수입니다.
* 모든 재귀적 정의는 **기저 사례**(자기 자신을 참조하지 않고 답을 직접 말하는 지점)와 **재귀 사례**(더 작은 문제의 답으로 지금 문제의 답을 만드는 규칙), 이 두 부품으로 이루어집니다.
* 재귀가 멈추는 이유는 재귀 사례가 매번 기저 사례에 더 가까운, 엄격하게 더 작은 문제를 향하기 때문입니다. 이 조건이 깨지면(예: 인자를 줄이지 않고 그대로 넘기면) 무한 재귀에 빠집니다.

다음 장에서는 이 재귀적 정의가 **왜 항상 맞는지**를 증명하는 방법인 구조적 귀납을 다룹니다. "기저 사례가 맞고, 재귀 사례가 더 작은 경우에서 더 큰 경우로 정당성을 물려준다면, 모든 경우에 대해 맞는다"는 논증이 어떻게 성립하는지 확인합니다.
