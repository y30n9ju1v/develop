'''
지금까지는 함수 타입의 의미를 대략적으로만 짚고 넘어갔습니다. 하지만 함수 타입은 다른 타입들과는 확실히 다릅니다.

예를 들어 ``Integer``는 그저 정수의 집합일 뿐입니다. ``Bool``은 두 원소를 가진 집합이죠. 하지만 함수 타입 ``a -> b``는 그보다 더 많은 의미를 담고 있습니다. 이는 객체 stem:[a]와 stem:[b] 사이의 모피즘(morphism)들의 집합입니다. 어떤 카테고리에서든 두 객체 사이의 모피즘 집합을 *홈-집합(hom-set)*이라고 부릅니다. 카테고리 *Set*에서는 모든 홈-집합이 그 자체로 같은 카테고리 안의 객체가 됩니다. 홈-집합 역시 결국 '집합'이기 때문입니다.

[source,text]
----
  [ Set 카테고리에서의 내부 Hom-집합 ]

     Set
    ┌───────────────────────────────────────────────┐
    │                                               │
    │      a ────────────── f ─────────────> b      │
    │                                               │
    │         Set(a, b) = a -> b (자체 집합)        │
    │         ┌─────────────────────────┐           │
    │         │  • f   • g   • h  ...   │           │
    │         └─────────────────────────┘           │
    └───────────────────────────────────────────────┘
----

*Set*에서 홈-집합은 그 자체로 하나의 집합입니다.

하지만 홈-집합이 카테고리 외부에 존재하는 다른 카테고리들에서는 상황이 다릅니다. 이런 경우를 *외부 홈-집합(external hom-set)*이라고 부르기도 합니다.

[source,text]
----
  [ 일반 카테고리 C에서의 외부 Hom-집합 ]

     카테고리 C                       카테고리 Set
    ┌─────────────────────────┐      ┌─────────────────────────┐
    │    a ──── f ────> b     │ ───> │  Hom-set C(a, b)        │
    │    │              │     │      │  ┌───────────────────┐  │
    │    │              │     │      │  │ • f   • g   • h   │  │
    │    v              v     │      │  └───────────────────┘  │
    └─────────────────────────┘      └─────────────────────────┘
----

카테고리 stem:[C]의 홈-집합은 외부 집합입니다.

함수 타입을 특별하게 만드는 것은 바로 카테고리 *Set*의 이 '자기 참조적(self-referential)'인 성질입니다. 하지만 적어도 일부 카테고리에서는 홈-집합을 나타내는 객체를 직접 구성할 수 있는 방법이 있습니다. 이러한 객체를 *내부 홈-집합(internal hom-set)*이라고 부릅니다.

== 보편 구성 (Universal Construction)

잠시 함수 타입이 집합이라는 사실은 잊고, 함수 타입(또는 더 일반적인 의미의 내부 홈-집합)을 처음부터 구성해 봅시다. 늘 그렇듯 카테고리 *Set*에서 힌트를 얻겠지만, 집합만이 가진 고유한 속성은 사용하지 않도록 주의할 것입니다. 그래야 이 구성이 다른 카테고리에서도 자동으로 작동할 테니까요.

함수 타입은 인자(argument) 타입과 결과(result) 타입 사이의 관계 때문에 복합 타입(composite type)으로 볼 수 있습니다. 우리는 이미 복합 타입을 구성하는 방법들, 즉 객체 간의 관계를 이용하는 것들을 보았습니다. 보편 구성을 통해 곱(product) 타입과 여곱(coproduct) 타입을 정의했던 것처럼 말이죠. 함수 타입을 정의할 때도 같은 방법을 쓸 수 있습니다. 이때 우리는 세 개의 객체가 포함된 패턴이 필요합니다. 우리가 구성하려는 함수 타입, 인자 타입, 그리고 결과 타입입니다.

이 세 타입을 엮는 가장 명백한 패턴은 *함수 적용(function application)* 또는 *평가(evaluation)*입니다. 함수 타입의 후보를 stem:[z]라고 부르겠습니다(*Set*이 아닌 카테고리에서는 stem:[z]도 그저 다른 객체와 다를 바 없는 평범한 객체입니다). 인자 타입을 객체 stem:[a]라고 하면, 적용(application)은 이 쌍 stem:[(z, a)]을 결과 타입 stem:[b](객체)로 대응시킵니다. 즉, 우리에게는 세 개의 객체가 있고, 그중 두 개(stem:[a]와 stem:[b], 인자 타입과 결과 타입을 나타내는 것)는 고정되어 있습니다.

또한 '매핑'인 '적용'이 있습니다. 이 매핑을 우리 패턴에 어떻게 녹여낼 수 있을까요? 만약 우리가 객체 내부를 들여다볼 수 있다면, 함수 stem:[f](stem:[z]의 원소)와 인자 stem:[x](stem:[a]의 원소)를 짝지어 stem:[f\ x](stem:[b]의 원소인 "stem:[f]를 stem:[x]에 적용한 결과")로 매핑할 수 있을 것입니다.

[source,text]
----
  [ 원소 관점에서의 함수 적용 ]

     z (함수 집합)       a (인자 집합)           b (결과 집합)
    ┌───────────┐       ┌───────────┐          ┌───────────┐
    │  • f      │   ×   │  • x      │ ── eval ─>   • f x   │
    └───────────┘       └───────────┘          └───────────┘
----

*Set*에서는 함수 집합 stem:[z]에서 함수 stem:[f]를 고르고, 집합(타입) stem:[a]에서 인자 stem:[x]를 고를 수 있습니다. 그러면 집합(타입) stem:[b]의 원소 stem:[f\ x]를 얻게 됩니다.

하지만 개별 쌍 stem:[(f, x)]를 일일이 다루는 대신, 함수 타입 stem:[z]와 인자 타입 stem:[a]의 전체 곱(product)에 대해 이야기할 수도 있습니다. 곱 stem:[z \times a]는 하나의 객체이며, 우리는 이 객체에서 stem:[b]로 가는 화살표 stem:[g]를 '적용 모피즘'으로 선택할 수 있습니다. 카테고리 *Set*라면 stem:[g]는 모든 쌍 stem:[(f, x)]를 stem:[f\ x]로 매핑하는 함수가 되겠죠.

요약하자면 패턴은 이렇습니다. 두 객체 stem:[z]와 stem:[a]의 곱이 모피즘 stem:[g]를 통해 또 다른 객체 stem:[b]와 연결되는 구조입니다.

[source,text]
----
  [ 보편 구성의 시작점: 후보 객체 z와 적용 사상 g ]

               z × a ──────── g ────────> b
               (후보 곱)                   (결과 객체)
----

보편 구성의 시작점이 되는 객체와 모피즘의 패턴

이 패턴이 보편 구성을 통해 함수 타입을 단 하나로 특정할 만큼 충분히 구체적일까요? 모든 카테고리에서 그런 것은 아니지만, 우리가 관심을 두는 카테고리들에서는 그렇습니다. 또 다른 질문이 생길 수 있습니다. 곱을 먼저 정의하지 않고도 함수 객체를 정의할 수 있을까요? 곱이 존재하지 않거나, 특정 객체 쌍에 대해 곱이 없는 카테고리도 있습니다. 결론부터 말하면 '아니요'입니다. 곱 타입이 없다면 함수 타입도 존재할 수 없습니다. 이 부분은 나중에 '지수(exponential)'를 다룰 때 다시 살펴보겠습니다.

보편 구성을 다시 떠올려 봅시다. 우리는 먼저 객체와 모피즘의 패턴에서 시작합니다. 이것은 일종의 '느슨한 쿼리'와 같아서 보통 수많은 검색 결과(후보)가 나옵니다. 특히 *Set*에서는 거의 모든 것이 서로 연결되어 있습니다. 어떤 객체 stem:[z]를 가져오든 stem:[a]와의 곱을 만들 수 있고, 거기서 stem:[b]로 가는 함수도 (stem:[b]가 공집합이 아닌 한) 반드시 존재하니까요.

이때 우리의 비밀 무기인 *순위 매기기(ranking)*를 사용합니다. 대개는 후보 객체들 사이의 매핑을 요구하고, 이 매핑이 우리가 만든 구성을 어떤 식으로든 '인수분해(factorize)'하도록 함으로써 순위를 정합니다. 우리 예시에서는 객체 stem:[z]와 stem:[z \times a]에서 stem:[b]로 가는 모피즘 stem:[g]가, 다른 후보 stem:[z']와 그에 딸린 적용 stem:[g']보다 '더 낫다'고 규정할 것입니다. 이는 오직 stem:[z']에서 stem:[z]로 가는 매핑 stem:[h]가 존재하여 stem:[g']의 적용이 stem:[g]를 거쳐서 인수분해될 때만 성립합니다. (힌트: 그림을 보면서 이 문장을 읽어보세요.)

[source,text]
----
  [ 함수 객체 후보들 사이의 순위 매기기 ]

              z' × a ───────── g' ────────> b
                 │                         ^
                 │                         │
             h × id                        │ g
                 │                         │
                 v                         │
               z × a ──────────────────────/
----

함수 객체 후보들 사이의 순위 정하기

자, 이제 조금 까다로운 부분이 나옵니다. 제가 이 보편 구성을 지금까지 미루어둔 이유가 바로 여기에 있습니다. 모피즘 stem:[h \:: z' \to z]가 주어졌을 때, 우리는 stem:[z']와 stem:[z] 둘 다 stem:[a]와 곱해진 형태가 포함된 다이어그램을 완성하고 싶습니다. 즉 stem:[z']에서 stem:[z]로 가는 매핑 stem:[h]가 있을 때, 실제로 필요한 것은 stem:[z' \times a]에서 stem:[z \times a]로 가는 매핑입니다. 이제 우리는 '곱의 함자성(functoriality of the product)'을 배웠으니 이를 어떻게 하는지 압니다. 곱 자체가 함자(더 정확하게는 엔도-쌍함자, endo-bi-functor)이므로, 모피즘의 쌍을 '들어 올릴(lift)' 수 있습니다. 다시 말해, 객체의 곱뿐만 아니라 모피즘의 곱도 정의할 수 있다는 뜻입니다.

곱 stem:[z' \times a]의 두 번째 성분은 건드리지 않을 것이므로, 모피즘의 쌍 stem:[(h, \text{id})]를 들어 올릴 것입니다(여기서 stem:[\text{id}]는 stem:[a] 위의 항등 모피즘입니다).

따라서 하나의 적용 stem:[g]를 통해 다른 적용 stem:[g']를 인수분해하는 공식은 다음과 같습니다.

[source]
----
g' = g ∘ (h × id)
----

여기서 핵심은 모피즘에 대한 곱의 작용입니다.

보편 구성의 세 번째 단계는 '보편적으로 가장 좋은' 객체를 선택하는 것입니다. 이 객체를 stem:[a \Rightarrow b]라고 부르겠습니다(이를 하나의 객체를 가리키는 상징적인 이름으로 생각하세요. 하스켈의 타입클래스 제약 조건과 혼동하지 마시기 바랍니다. 나중에 다른 이름들도 살펴보겠습니다). 이 객체는 stem:[(a \Rightarrow b) \times a]에서 stem:[b]로 가는 자기만의 적용 모피즘을 가지고 있는데, 이를 stem:[\text{eval}]이라고 부르겠습니다. 어떤 후보 객체라도 stem:[a \Rightarrow b]로 가는 유일한 매핑이 존재하고, 그 후보의 적용 모피즘 stem:[g]가 stem:[\text{eval}]을 통해 인수분해된다면, stem:[a \Rightarrow b]가 바로 보편적으로 가장 좋은 객체입니다. 이 객체는 우리가 정한 순위에 따라 그 어떤 객체보다도 우월합니다.

[source,text]
----
  [ 보편적 함수 객체 (지수 b^a)와 eval 가환 다이어그램 ]

               z × a ───────── g ─────────> b
                 │                         ^
                 │                         │
             h × id                        │ eval
                 │                         │
                 v                         │
          (a ⇒ b) × a ─────────────────────/
           (b^a × a)

    * 보편 방정식: g = eval ∘ (h × id_a)
    * 유일한 인수분해 사상: h = curry g = \z -> \a -> g (z, a)
----

보편 함수 객체의 정의. 앞서 본 것과 같은 다이어그램이지만, 이제 stem:[a \Rightarrow b]가 보편적 대상입니다.

형식적으로 나타내면:

[quote]
____
모든 객체 쌍 stem:[a, b]에 대한 *함수 객체* stem:[a \Rightarrow b]는 다음을 만족하는 객체입니다:
____
[quote]
____
- 적용 모피즘 stem:[\text{eval} \:: (a \Rightarrow b) \times a \to b]가 존재하며,
____
[quote]
____
- 임의의 객체 stem:[z]와 모피즘 stem:[g \:: z \times a \to b]에 대해, stem:[g = \text{eval} \circ (h \times \text{id})]를 만족하는 유일한 모피즘 stem:[h \:: z \to (a \Rightarrow b)]가 존재합니다.
____

물론 주어진 카테고리에서 어떤 객체 쌍 stem:[a, b]에 대해 그러한 객체 stem:[a \Rightarrow b]가 존재한다는 보장은 없습니다. 하지만 *Set*에서는 항상 존재합니다. 게다가 *Set*에서 이 객체는 홈-집합 stem:[\text{Set}(a, b)]와 동형(isomorphic)입니다.

이것이 바로 하스켈에서 함수 타입 ``a -> b``를 카테고리 이론의 함수 객체 stem:[a \Rightarrow b]로 해석하는 이유입니다.

== 커링 (Currying)

함수 객체의 후보들을 다시 한번 살펴봅시다. 이번에는 모피즘 stem:[g]를 stem:[z]와 stem:[a]라는 두 변수를 가진 함수로 생각해보는 겁니다.

[source,haskell]
----
g :: z × a -> b
----

곱으로부터의 모피즘은 우리가 '이변수 함수'라고 부르는 개념에 가장 가깝습니다. 특히 카테고리 *Set*에서 stem:[g]는 집합 stem:[z]와 stem:[a]의 값들의 쌍을 인자로 받는 함수입니다.

한편, 보편 속성(universal property)은 그러한 각 stem:[g]마다 stem:[z]를 함수 객체 stem:[a \Rightarrow b]로 매핑하는 유일한 모피즘 stem:[h]가 존재함을 알려줍니다.

[source,haskell]
----
h :: z -> (a ⇒ b)
----

*Set*에서 이는 stem:[h]가 stem:[z] 타입의 변수를 하나 받아 "stem:[a]에서 stem:[b]로 가는 함수"를 반환하는 함수임을 의미합니다. 즉 stem:[h]는 *고차 함수(higher-order function)*입니다. 결과적으로 보편 구성은 '이변수 함수'와 '함수를 반환하는 일변수 함수' 사이의 일대일 대응 관계를 정립합니다. 이 대응 관계를 *커링(currying)*이라고 하며, stem:[h]를 stem:[g]의 *커링된 버전(curried version)*이라고 부릅니다.

이 대응은 일대일입니다. 왜냐하면 어떤 stem:[g]가 주어지면 그에 대응하는 유일한 stem:[h]가 있고, 반대로 어떤 stem:[h]가 주어지더라도 다음 공식을 통해 이변수 함수 stem:[g]를 언제든 재구성할 수 있기 때문입니다.

[source,haskell]
----
g = eval ∘ (h × id)
----

이때 함수 stem:[g]를 stem:[h]의 *언커링된 버전(uncurried version)*이라고 부릅니다.

커링은 하스켈 문법에 아예 내장되어 있습니다. 함수를 반환하는 함수인

[source,haskell]
----
a -> (b -> c)
----

는 보통 이변수 함수로 여겨집니다. 괄호를 생략한 타입 시그니처를 읽는 방식이 바로 그렇죠.

[source,haskell]
----
a -> b -> c
----

이런 해석은 우리가 다중 인자 함수를 정의하는 방식에서도 명확히 드러납니다. 예를 들어볼까요?

[source,haskell]
----
catstr :: String -> String -> String
catstr s s' = s ++ s'
----

같은 함수를 함수를 반환하는 일인자 함수(람다)로도 쓸 수 있습니다.

[source,haskell]
----
catstr' s = \s' -> s ++ s'
----

두 정의는 완전히 동일하며, 어느 쪽이든 인자 하나만 부분 적용(partial application)하여 일인자 함수를 만들어낼 수 있습니다.

[source,haskell]
----
greet :: String -> String
greet = catstr "Hello "
----

엄밀히 따지면, '진짜' 이변수 함수는 쌍(곱 타입)을 인자로 받는 함수입니다.

[source,haskell]
----
(a, b) -> c
----

두 표현 사이를 변환하는 것은 아주 간단하며, 이를 수행하는 두 고차 함수는 이름도 직관적인 ``curry``와 ``uncurry``입니다.

[source,haskell]
----
curry :: ((a, b) -> c) -> (a -> b -> c)
curry f a b = f (a, b)
----

그리고

[source,haskell]
----
uncurry :: (a -> b -> c) -> ((a, b) -> c)
uncurry f (a, b) = f a b
----

여기서 ``curry``가 바로 함수 객체의 보편 구성을 위한 '인수분해 함수(factorizer)'라는 점에 주목하세요. 다음과 같은 형태로 다시 써보면 그 의미가 더 명확해집니다.

[source,haskell]
----
factorizer :: ((a, b) -> c) -> (a -> (b -> c))
factorizer g = \a -> (\b -> g (a, b))
----

(복습하자면, 인수분해 함수는 후보로부터 인수분해하는 함수를 만들어내는 도구입니다.)

C++와 같은 비함수형 언어에서도 커링은 가능하지만 그리 간단하지는 않습니다. C++의 다중 인자 함수는 하스켈에서 튜플을 받는 함수와 대응한다고 볼 수 있습니다(물론 C++에는 ``std\::tuple``을 명시적으로 받는 함수, 가변 인자 함수(variadic function), 초기화 리스트를 받는 함수 등 더 복잡한 경우들이 있어 혼란스러울 수 있습니다).

C++ 함수는 ``std\::bind`` 템플릿을 사용하여 부분 적용할 수 있습니다. 예를 들어 두 문자열을 받는 함수가 있다면,

[source,cpp]
----
std::string catstr(std::string s1, std::string s2) {
    return s1 + s2;
}
----

다음과 같이 일인자 함수를 만들 수 있습니다.

[source,cpp]
----
using namespace std::placeholders;

auto greet = std::bind(catstr, "Hello ", _1);
std::cout << greet("Haskell Curry");
----

C++나 자바보다 훨씬 함수형인 스칼라(Scala)는 그 중간쯤에 있습니다. 만약 정의하려는 함수가 부분 적용될 것임을 미리 안다면, 인자 목록을 여러 개로 나누어 정의합니다.

[source,scala]
----
def catstr(s1: String)(s2: String) = s1 + s2
----

물론 이는 라이브러리 작성자에게 어느 정도의 선견지명이 필요합니다.

== 지수 (Exponentials)

수학 문헌에서 함수 객체, 혹은 두 객체 stem:[a, b] 사이의 내부 홈-객체는 종종 *지수(exponential)*라고 불리며 stem:[b^a]로 표기됩니다. 인자 타입이 지수 자리에 있다는 점이 흥미롭죠. 처음에는 이 표기법이 생소할 수 있지만, 함수와 곱 사이의 관계를 생각해보면 아주 타당합니다. 우리는 이미 내부 홈-객체의 보편 구성에서 곱을 사용한다는 것을 보았지만, 그 연결 고리는 생각보다 더 깊습니다.

이는 유한 타입(stem:[\text{Bool}], stem:[\text{Char}], 혹은 stem:[\text{Int}]나 stem:[\text{Double}]처럼 가질 수 있는 값의 수가 유한한 타입) 사이의 함수를 생각할 때 가장 잘 드러납니다. 이러한 함수들은 원칙적으로 완전히 메모이제이션(memoization)하거나 룩업 테이블 같은 데이터 구조로 바꿀 수 있습니다. 이것이 바로 모피즘인 '함수'와 객체인 '함수 타입' 사이의 동등성의 핵심입니다.

예를 들어 stem:[\text{Bool}]을 인자로 받는 (순수) 함수는 단 두 개의 값(stem:[\text{False}]에 대응하는 값과 stem:[\text{True}]에 대응하는 값)만 있으면 완전히 명시됩니다. stem:[\text{Bool}]에서 stem:[\text{Int}]로 가는 모든 가능한 함수의 집합은 결국 'stem:[\text{Int}]의 쌍'들의 집합과 같습니다. 이는 곱 stem:[\text{Int} \times \text{Int}]와 같고, 표기법을 조금 창의적으로 써보면 stem:[\text{Int}^2]이 됩니다.

또 다른 예로 256개의 값을 가지는 C++의 ``char`` 타입을 봅시다(하스켈의 ``Char``는 유니코드를 써서 이보다 훨씬 큽니다). C++ 표준 라이브러리의 ``<cctype>`` 부분에는 보통 룩업 테이블로 구현되는 함수들이 많습니다. ``isupper``나 ``isspace`` 같은 함수들은 테이블을 사용해 구현되는데, 이는 결국 256개의 불리언 값으로 이루어진 튜플과 같습니다. 튜플은 곱 타입이므로, 우리는 256개의 불리언을 곱한 형태, 즉 stem:[\text{bool} \times \text{bool} \times \cdots \times \text{bool}]을 다루고 있는 셈입니다. 산술에서 반복된 곱은 거듭제곱으로 정의되죠. stem:[\text{bool}]을 자기 자신과 256번(혹은 ``char``의 크기만큼) '곱하면' stem:[\text{bool}]의 stem:[\text{char}] 제곱, 즉 stem:[\text{bool}^{\text{char}}]를 얻게 됩니다.

그렇다면 stem:[\text{bool}]의 256-튜플로 정의된 타입에는 총 몇 개의 값이 있을까요? 정확히 stem:[2^{256}]개입니다. 이는 또한 ``char``에서 ``bool``로 가는 서로 다른 함수의 개수와도 일치하며, 각 함수는 고유한 256-튜플에 대응합니다. 마찬가지로 ``bool``에서 ``char``로 가는 함수의 개수는 stem:[256^2]이 되는 식입니다. 함수 타입에 대한 지수 표기법은 이런 경우들을 완벽하게 설명해줍니다.

우리가 ``int``나 ``double``을 인자로 받는 함수를 실제로 완전히 메모이제이션하고 싶지는 않겠지만, 함수와 데이터 타입 사이의 이러한 동등성은 실용성을 떠나 언제나 존재합니다. 리스트, 문자열, 트리와 같은 무한 타입도 마찬가지입니다. 이런 타입들을 인자로 받는 함수를 즉시(eagerly) 메모이제이션하려면 무한한 저장 공간이 필요하겠지만, 하스켈은 지연 평가(lazy evaluation) 언어이기 때문에 지연 평가되는 (무한한) 데이터 구조와 함수 사이의 경계가 아주 모호합니다. 이러한 '함수 대 데이터의 이중성'은 하스켈의 함수 타입을 카테고리 이론의 지수 객체(우리의 데이터 개념에 더 가까운 것)와 동일시하는 근거가 됩니다.

== 카르테시안 폐카테고리 (Cartesian Closed Categories)

지금까지는 타입과 함수의 모델로 카테고리 *Set*만을 다뤄왔지만, 같은 목적으로 사용될 수 있는 더 넓은 카테고리의 카테고리들이 있다는 점을 짚고 넘어갈 만합니다. 이러한 카테고리들을 *카르테시안 폐카테고리(Cartesian Closed Category)*라고 부르며, *Set*은 그중 한 예일 뿐입니다.

카르테시안 폐카테고리는 반드시 다음을 포함해야 합니다:

- 종단 객체(terminal object)
- 모든 객체 쌍에 대한 곱(product)
- 모든 객체 쌍에 대한 지수(exponential)

지수를 (무한히 반복될 수 있는) 곱으로 본다면, 카르테시안 폐카테고리는 임의 항수(arity)에 대한 곱을 지원하는 카테고리라고 생각할 수 있습니다. 특히 종단 객체는 '영(0)개 객체의 곱' 혹은 '객체의 0제곱'으로 볼 수 있습니다.

컴퓨터 과학의 관점에서 카르테시안 폐카테고리가 흥미로운 이유는, 모든 정적 타입 프로그래밍 언어의 기초가 되는 *단순 타입 람다 계산법(simply typed lambda calculus)*에 대한 모델을 제공하기 때문입니다.

종단 객체와 곱은 각각 그에 대응하는 쌍대(dual) 개념인 초기 객체와 여곱을 가집니다. 이 두 가지를 모두 지원하면서 곱이 여곱에 대해 분배 법칙을 만족하는 카르테시안 폐카테고리를,

[source]
----
a × (b + c) = a × b + a × c
(b + c) × a = b × a + c × a
----

*이중 카르테시안 폐카테고리(bicartesian closed category)*라고 부릅니다. 다음 섹션에서 보겠지만, *Set*이 대표적인 예인 이중 카르테시안 폐카테고리는 매우 흥미로운 성질들을 가지고 있습니다.

== 지수와 대수적 자료형 (Exponentials and Algebraic Data Types)

함수 타입을 지수로 해석하는 관점은 대수적 자료형 체계와 아주 잘 어우러집니다. 숫자 0과 1, 합, 곱, 지수를 연결하는 고등학교 수준의 기본 대수학 항등식들이, 이중 카르테시안 폐카테고리에서의 초기/종단 객체, 여곱, 곱, 지수 사이에서도 거의 그대로 성립한다는 사실이 밝혀졌습니다. 아직 이를 증명할 도구(수반 함자나 요네다 보조정리 등)는 없지만, 귀중한 직관을 얻기 위해 그 목록을 나열해 보겠습니다.

=== 0제곱 (Zeroth Power)

stem:[a^0 = 1]

카테고리 이론적으로 해석하면 0은 초기 객체, 1은 종단 객체, 등호는 동형(isomorphism)으로 바뀝니다. 지수는 내부 홈-객체죠. 이 특정 지수는 초기 객체에서 임의의 객체 stem:[a]로 가는 모피즘의 집합을 나타냅니다. 초기 객체의 정의에 따라 그러한 모피즘은 정확히 하나뿐이므로, 홈-집합 stem:[C(0, a)]는 단일 원소 집합입니다. 단일 원소 집합은 *Set*에서 종단 객체이므로 이 항등식은 *Set*에서 당연하게 성립합니다. 중요한 점은 이것이 모든 이중 카르테시안 폐카테고리에서 성립한다는 사실입니다.

하스켈에서는 0을 ``Void``로, 1을 유닛 타입 ``()``으로, 지수를 함수 타입으로 바꿉니다. 즉, ``Void``에서 어떤 타입 ``a``로 가는 함수의 집합은 유닛 타입(단일 원소 집합)과 동등하다는 주장입니다. 다시 말해 ``Void -> a`` 함수는 오직 하나뿐이라는 뜻이죠. 우리는 이미 이 함수를 보았습니다. 바로 ``absurd``입니다.

여기에는 두 가지 까다로운 점이 있습니다. 첫째는 하스켈에 엄밀한 의미의 '비어 있는 타입'이 없다는 것입니다. 모든 타입은 '끝나지 않는 계산의 결과'인 바텀(bottom, stem:[\bot])을 포함하기 때문입니다. 둘째는 ``absurd``의 모든 구현이 결과적으로 동일하다는 점입니다. 무엇을 하든 간에 아무도 그 함수를 실제로 호출할 수 없기 때문입니다. ``Void`` 타입의 값을 전달할 방법이 없으니까요. (만약 끝나지 않는 계산을 전달하려 한다면, 함수는 절대 반환되지 않을 것입니다!)

=== 1의 거듭제곱 (Powers of One)

stem:[1^a = 1]

이 항등식은 *Set*에서 종단 객체의 정의를 재진술합니다. 즉, 모든 객체에서 종단 객체로 가는 유일한 모피즘이 존재한다는 것이죠. 일반적으로 stem:[a]에서 종단 객체로 가는 내부 홈-객체는 종단 객체 자체와 동형입니다.

하스켈로 치면, 어떤 타입 ``a``에서 유닛 타입으로 가는 함수는 단 하나뿐입니다. 이 함수 역시 이미 본 적이 있죠. 바로 ``unit`` 함수입니다. ``()``에 부분 적용된 ``const`` 함수로 생각할 수도 있습니다.

=== 1제곱 (First Power)

stem:[a^1 = a]

이는 종단 객체로부터의 모피즘을 통해 객체 stem:[a]의 '원소'들을 고를 수 있다는 관찰을 재진술한 것입니다. 그러한 모피즘들의 집합은 객체 자신과 동형입니다. *Set*과 하스켈에서 이 동형 관계는 집합 stem:[a]의 원소들과 그 원소들을 직접 고르는 함수 ``() -> a`` 사이에 성립합니다.

=== 합의 지수 (Exponentials of Sums)

stem:[a^{b+c} = a^b \times a^c]

카테고리 이론적으로는 여곱에서 나가는 지수 객체가 두 지수 객체의 곱과 동형임을 의미합니다. 하스켈에서 이 대수적 항등식은 매우 실용적인 의미를 가집니다. 바로 '합 타입(sum type)을 인자로 받는 함수는 각 개별 타입을 인자로 받는 함수들의 쌍과 동등하다'는 것입니다. 이는 우리가 합 타입에 대해 함수를 정의할 때 쓰는 '케이스 분석(case analysis)' 그 자체입니다. ``case`` 문을 써서 하나의 함수를 만드는 대신, 보통 우리는 각 타입 생성자를 따로 다루는 두 개 이상의 함수로 나눕니다. 예를 들어 ``Either Int Double`` 타입을 인자로 받는 함수를 봅시다.

[source,haskell]
----
f :: Either Int Double -> String
----

이 함수는 ``Int``에서의 함수와 ``Double``에서의 함수의 쌍으로 정의될 수 있습니다.

[source,haskell]
----
f (Left n)  = if n < 0 then "Negative int" else "Positive int"
f (Right x) = if x < 0.0 then "Negative double" else "Positive double"
----

여기서 ``n``은 ``Int``이고 ``x``는 ``Double``입니다.

=== 지수의 지수 (Exponentials of Exponentials)

stem:[(a^b)^c = a^{b \times c}]

이는 순수하게 지수 객체의 관점에서 커링(currying)을 표현한 것에 불과합니다. '함수를 반환하는 함수'는 '곱(이변수 함수)으로부터 나가는 함수'와 동등하다는 뜻입니다.

=== 곱에 대한 지수 (Exponentials over Products)

stem:[(a \times b)^c = a^c \times b^c]

하스켈로 풀면 이렇습니다. '쌍(pair)을 반환하는 함수'는 '각 성분을 반환하는 두 함수의 쌍'과 동등합니다.

고등학교 때 배웠던 이 간단한 대수학 항등식들이 카테고리 이론으로 확장되어 함수형 프로그래밍에서 실제적인 응용으로 이어진다는 점은 정말 놀랍지 않나요?

== 커리-하워드 동형대응 (Curry-Howard Isomorphism)

앞서 논리학과 대수적 자료형 사이의 대응 관계를 언급한 적이 있습니다. ``Void`` 타입과 유닛 타입 ``()``은 각각 거짓(stem:[\bot])과 참(stem:[\top])에 대응합니다. 곱 타입과 합 타입은 논리곱(stem:[\land], AND)과 논리합(stem:[\lor], OR)에 대응하죠. 이 체계에서 우리가 방금 정의한 함수 타입은 바로 *논리적 함의(stem:[\Rightarrow], implication)*에 해당합니다. 즉, 타입 ``a -> b``는 "만약 stem:[a]라면 stem:[b]이다"라고 읽을 수 있습니다.

*커리-하워드 동형대응(Curry-Howard isomorphism)*에 따르면, 모든 타입은 하나의 *명제(proposition)*, 즉 참과 거짓을 가릴 수 있는 진술로 해석될 수 있습니다. 그리고 어떤 타입이 원소를 가진다면(inhabited) 그 명제는 '참'이고, 그렇지 않다면 '거짓'이라고 간주합니다. 특히 논리적 함의는 그에 해당하는 함수 타입이 원소를 가질 때 참이 됩니다. 즉 그 타입의 함수를 실제로 구현할 수 있을 때 참인 것이죠. 따라서 *함수의 구현은 곧 정리의 증명*입니다. 프로그램을 작성하는 것이 정리를 증명하는 과정과 같아지는 셈입니다. 몇 가지 예를 들어보죠.

함수 객체의 정의에서 도입했던 ``eval`` 함수를 다시 봅시다. 시그니처는 이랬죠.

[source,haskell]
----
eval :: ((a -> b), a) -> b
----

이 함수는 함수와 그 인자의 쌍을 받아 적절한 타입의 결과를 내놓습니다. 이는 다음 모피즘의 하스켈 구현입니다.

[source,haskell]
----
eval :: (a ⇒ b) × a -> b
----

이 시그니처를 커리-하워드 동형대응을 이용해 논리 술어로 번역하면 다음과 같습니다.

stem:[((a \Rightarrow b) \land a) \Rightarrow b]

이 문장은 이렇게 읽힙니다. "만약 stem:[b]가 stem:[a]로부터 유도된다는 것이 참이고 stem:[a]도 참이라면, stem:[b]는 반드시 참이어야 한다." 이는 매우 직관적인 결론이며, 고대부터 전해 내려오는 논증 형식인 *모두스 포넨스(modus ponens)* 그 자체입니다. 우리는 다음과 같이 함수를 구현함으로써 이 정리를 증명할 수 있습니다.

[source,haskell]
----
eval :: ((a -> b), a) -> b
eval (f, x) = f x
----

만약 당신이 stem:[a]를 받아 stem:[b]를 주는 함수 stem:[f]와 stem:[a] 타입의 구체적인 값 stem:[x]를 쌍으로 준다면, 저는 그저 stem:[f]를 stem:[x]에 적용함으로써 stem:[b] 타입의 값을 만들어낼 수 있습니다. 이 함수를 구현해냈다는 것은 ``((a -> b), a) -> b`` 타입이 원소를 가짐을 보여준 것이고, 따라서 우리 논리 체계에서 모두스 포넨스는 '참'임이 증명된 것입니다.

그렇다면 명백히 '거짓'인 술어는 어떨까요? 예를 들어 "stem:[a] 혹은 stem:[b]가 참이면 stem:[a]는 참이다"라는 문장을 봅시다.

stem:[a \lor b \Rightarrow a]

이는 명백히 틀렸습니다. stem:[a]는 거짓이고 stem:[b]만 참인 경우를 고르면 바로 반례가 되니까요. 이 술어를 커리-하워드 동형대응을 이용해 함수 시그니처로 옮기면 다음과 같습니다.

[source,haskell]
----
Either a b -> a
----

아무리 애를 써도 이 함수는 구현할 수 없습니다. ``Right`` 값이 들어왔을 때 타입 ``a``에 해당하는 값을 만들어낼 방법이 없기 때문입니다(우리는 지금 '순수 함수' 이야기만 하고 있다는 점을 잊지 마세요).

마지막으로 ``absurd`` 함수의 의미를 되새겨 봅시다.

[source,haskell]
----
absurd :: Void -> a
----

``Void``를 '거짓'으로 번역하면 식은 다음과 같이 변합니다.

stem:[\bot \Rightarrow a]

"거짓으로부터는 무엇이든 유도할 수 있다(ex falso quodlibet)"는 유명한 논리학 원칙입니다. 하스켈에서 이 문장(함수)을 증명(구현)하는 한 방법은 다음과 같습니다.

[source,haskell]
----
absurd (Void a) = absurd a
----

여기서 ``Void``는 보통 이렇게 정의됩니다.

[source,haskell]
----
newtype Void = Void Void
----

언제나 그렇듯 ``Void``는 조금 까다롭습니다. 이 정의대로라면 값을 하나라도 만들려면 이미 또 다른 ``Void`` 값이 있어야 하므로, 결국 누구도 값을 생성할 수 없습니다. 따라서 ``absurd`` 함수는 그 누구도 결코 호출할 수 없는 함수가 됩니다.

이 예시들은 모두 흥미롭지만, 커리-하워드 동형대응에 실질적인 쓸모가 있을까요? 평범한 현업 프로그래밍에서는 드문 일일지도 모르겠습니다. 하지만 *아그다(Agda)*나 *코크(Coq)* 같은 프로그래밍 언어들은 커리-하워드 동형대응을 활용하여 정리를 증명하는 데 사용됩니다.

컴퓨터는 단지 수학자들의 계산을 돕는 수준을 넘어, 수학의 근본적인 토대 자체를 혁명적으로 바꾸고 있습니다. 최근의 가장 뜨거운 연구 주제는 *호모토피 타입 이론(Homotopy Type Theory)*이라고 불리는 분야로, 타입 이론의 연장선상에 있습니다. 이 이론은 온통 불리언, 정수, 곱과 여곱, 함수 타입들로 가득 차 있죠. 그리고 모든 의심을 말끔히 씻어내듯, 이론의 공식화 작업 자체가 코크와 아그다를 통해 이루어지고 있습니다. 컴퓨터는 여러 방면에서 세상을 혁명적으로 바꾸어나가고 있습니다.
