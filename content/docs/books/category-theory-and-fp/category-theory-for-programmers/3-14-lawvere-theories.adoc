오늘날 모나드를 언급하지 않고 함수형 프로그래밍을 이야기할 수는 없습니다. 하지만 우연의 역사 속에서, 만약 에우제니오 모기(Eugenio Moggi)가 모나드 대신 로베르 이론(Lawvere theories)에 주목했다면 어땠을까요? 그런 평행 우주가 존재한다면 어떤 모습일지 탐험해 봅시다.

== 보편 대수 (Universal Algebra)

대수를 설명하는 방식은 추상화 수준에 따라 다양합니다. 우리는 모노이드, 군, 환(ring) 같은 구조들을 기술할 수 있는 통일된 언어를 찾으려 합니다. 가장 단순한 수준에서는, 이런 구조들이 모두 집합의 원소들에 대한 연산과 그 연산이 따라야 하는 법칙으로 정의됩니다. 예컨대 모노이드는 결합 법칙을 만족하는 이항 연산으로 정의됩니다. 단위 원소와 단위 법칙도 있죠. 여기서 조금만 생각을 확장하면, 단위 원소를 '0항 연산'으로 볼 수 있습니다. 즉 인수를 받지 않고 집합의 특별한 원소를 반환하는 연산입니다. 군을 정의하려면 원소를 받아 그 역원을 반환하는 단항 연산을 추가하면 됩니다. 이에 맞는 좌·우 역원 법칙도 필요합니다. 환은 두 개의 이항 연산과 몇 가지 법칙을 더 정의하고요. 이런 식으로 계속 확장할 수 있습니다.

큰 그림에서 보면, 대수는 다양한 stem:[n]에 대한 stem:[n]항 연산들의 모음과, 등식 항등원(equational identities)들의 집합으로 정의됩니다. 이 항등원들은 모두 전칭 한정(universally quantified)됩니다. 결합 법칙은 세 원소의 모든 가능한 조합에서 성립해야 한다는 식입니다.

흥미로운 점은, 이 정의로는 체(field)를 다룰 수 없다는 것입니다. 이유는 간단합니다. 0(덧셈의 단위 원소)은 곱셈에 대한 역원을 갖지 않기 때문입니다. 체의 역원 법칙은 전칭 한정될 수 없습니다.

보편 대수의 정의는 ``Set``을 넘어 다른 카테고리로도 확장할 수 있습니다. 연산(함수)을 모피즘(morphism)으로 바꾸면 됩니다. 집합 대신 객체 stem:[a] 하나를 선택합니다. 이 객체를 '일반 객체(generic object)'라고 부릅니다. 단항 연산은 stem:[a]의 엔도모피즘(endomorphism)입니다. 그렇다면 다른 아리티(arity)는 어떨까요? 아리티란 연산이 받는 인수의 개수를 말합니다. 이항 연산(아리티 2)은 곱 stem:[a \times a]에서 stem:[a]로 가는 모피즘으로 정의됩니다. 일반적으로 stem:[n]항 연산은 stem:[a]의 stem:[n]제곱에서 stem:[a]로 가는 모피즘입니다.

[source,haskell]
----
αn :: an -> a
----

0항 연산은 종단 객체(stem:[a]의 0제곱)에서 오는 모피즘입니다. 결론적으로, 어떤 대수든 정의하려면 객체들이 하나의 특별한 객체 stem:[a]의 거듭제곱으로만 이루어진 카테고리가 있으면 됩니다. 구체적인 대수 정보는 이 카테고리의 hom-집합에 담깁니다. 이것이 로베르 이론의 핵심입니다.

로베르 이론의 도출은 여러 단계를 거치므로, 여기 로드맵이 있습니다:

- 유한 집합의 카테고리 ``FinSet``
- 그 스켈레톤(skeleton) stem:[F]
- 그 반대 카테고리 stem:[F^{op}]
- 로베르 이론 stem:[L]: 카테고리 ``Law``의 객체
- 로베르 이론의 모델 stem:[M]: 카테고리 stem:[Mod(L, Set)]의 객체
    

== 로베르 이론 (Lawvere Theories)

모든 로베르 이론은 공통의 뼈대를 공유합니다. 로베르 이론의 모든 객체는 단 하나의 객체로부터 곱(정확히는 거듭제곱)만으로 생성됩니다. 그렇다면 일반적인 카테고리에서 이런 곱을 어떻게 정의할까요? 답은, 더 단순한 카테고리로부터의 모피즘을 이용하면 된다는 것입니다. 흥미롭게도 이 단순한 카테고리는 곱 대신 코프로덕트(coproduct)를 정의할 수 있습니다. 우리는 반변 함자(contravariant functor)를 써서 이를 대상 카테고리에 끼워넣습니다. 반변 함자는 코프로덕트를 곱으로, 주입(injection)을 투영(projection)으로 뒤집습니다.

로베르 카테고리의 뼈대로는 유한 집합의 카테고리 ``FinSet``이 가장 자연스럽습니다. 이 카테고리는 공집합 0, 단일 원소 집합 1, 두 원소 집합 2 등을 포함합니다. 이 카테고리의 모든 객체는 단일 원소 집합으로부터 코프로덕트를 통해 생성됩니다. 공집합은 0항 코프로덕트의 특수한 경우로 봅니다. 예를 들어, 두 원소 집합은 두 개의 단일 원소 집합의 합입니다. 즉 stem:[2 = 1 + 1]입니다. 하스켈로는 다음과 같이 표현됩니다.

[source,haskell]
----
type Two = Either () ()
----

공집합은 하나뿐이라고 생각하기 쉽지만, 구별되는 단일 원소 집합은 여러 개 있을 수 있습니다. 예를 들어 집합 stem:[1 + 0]은 stem:[0 + 1]과 다르고, 1과도 다릅니다. 이들이 모두 동형(isomorphic)임에도 불구하고 말입니다. 집합 카테고리에서 코프로덕트는 엄밀한 의미의 결합 법칙을 따르지 않습니다. 이 문제는 동형인 집합들을 모두 하나로 동일시하는 카테고리를 만들면 해결됩니다. 이런 카테고리를 스켈레톤(skeleton)이라고 합니다. 모든 로베르 이론의 뼈대는 바로 ``FinSet``의 스켈레톤 stem:[F]입니다. 이 카테고리의 객체는 ``FinSet``의 원소 개수에 대응하는 자연수(0 포함)로 식별됩니다. 코프로덕트는 덧셈 역할을 합니다. stem:[F]의 모피즘은 유한 집합 사이의 함수에 대응합니다. 예를 들어 0에서 stem:[n]으로 가는 유일한 모피즘이 있고(공집합은 초기 객체), stem:[n]에서 0으로 가는 모피즘은 없으며(stem:[0 \to 0] 제외), 1에서 stem:[n]으로 가는 stem:[n]개의 모피즘(주입들)이 있고, stem:[n]에서 1로 가는 모피즘은 하나입니다. 여기서 stem:[n]은 동형을 통해 묶인 모든 stem:[n]개 원소 집합에 대응하는 stem:[F]의 객체입니다.

카테고리 stem:[F]를 이용하면 로베르 이론을 형식적으로 정의할 수 있습니다. 로베르 이론은 다음과 같은 특별한 함자가 갖춰진 카테고리 stem:[L]입니다.

[source,haskell]
----
IL :: Fop -> L
----

이 함자는 객체들 사이에서 일대일 대응(bijection)이어야 하며, 유한 곱을 보존해야 합니다. stem:[F^{op}]에서의 곱은 stem:[F]에서의 코프로덕트와 같습니다.

[source,haskell]
----
IL (m × n) = IL m × IL n
----

종종 이 함자를 '객체 위의 항등(identity-on-objects)' 함자라고도 부릅니다. stem:[F]와 stem:[L]의 객체가 본질적으로 같기 때문입니다. 따라서 우리는 이들에 같은 이름, 즉 자연수를 씁니다. 다만 stem:[F]의 객체는 집합 자체가 아니라 동형인 집합들의 클래스라는 점을 기억해야 합니다.

stem:[L]의 hom-집합은 일반적으로 stem:[F^{op}]보다 풍부합니다. ``FinSet``의 함수에 대응하는 모피즘 외에도 다른 모피즘이 포함될 수 있습니다. 전자를 가끔 기본 곱 연산(basic product operations)이라고 부릅니다. 로베르 이론의 등식 법칙은 바로 이런 모피즘 안에 인코딩됩니다.

핵심 관찰은 다음과 같습니다. stem:[F]의 단일 원소 집합 1은 stem:[L]의 어떤 객체(역시 1이라 부름)로 매핑되고, stem:[L]의 다른 모든 객체는 자동으로 이 객체의 거듭제곱이 됩니다. 예컨대 stem:[F]의 두 원소 집합 2는 코프로덕트 stem:[1+1]이므로, stem:[L]에서는 곱 stem:[1 \times 1](또는 stem:[1^2])로 매핑됩니다. 이런 의미에서 카테고리 stem:[F]는 stem:[L]의 '로그'처럼 작동합니다.

stem:[L]의 모피즘 중에는 함자 stem:[I_L]이 stem:[F]로부터 옮겨온 것들이 있습니다. 이들은 stem:[L] 안에서 구조적 역할을 합니다. 특히 코프로덕트의 주입(injection) stem:[i_k]는 곱의 투영(projection) stem:[p_k]가 됩니다. 투영을 다음처럼 생각하면 직관적입니다.

[source,haskell]
----
pk :: 1n -> 1
----

이는 stem:[n]개 변수를 받는 함수 중 stem:[k]번째 변수만 선택하고 나머지는 무시하는 함수의 원형입니다. 반대로, stem:[F]에서의 상수 모피즘 stem:[n \to 1]은 stem:[L]에서 대각 모피즘(diagonal morphism) stem:[1 \to 1^n]이 됩니다. 이는 변수 복제에 해당합니다.

stem:[L]에서 흥미로운 모피즘은 투영 이외의 stem:[n]항 연산을 정의하는 것들입니다. 바로 이런 모피즘이 하나의 로베르 이론을 다른 이론과 구별합니다. 여기에는 대수를 정의하는 곱셈, 덧셈, 단위 원소 선택 등이 포함됩니다. 하지만 stem:[L]이 완전한 카테고리가 되려면 복합 연산 stem:[n \to m](또는 stem:[1^n \to 1^m])도 필요합니다. 카테고리의 단순한 구조 덕분에 이런 연산은 stem:[n \to 1] 타입의 더 간단한 모피즘들의 곱으로 분해됩니다. 이는 "곱을 반환하는 함수는 함수들의 곱이다"라는 명제의 일반화입니다. 앞서 본 것처럼 hom-함자가 연속적이라는 사실과도 연결됩니다.

로베르 이론 stem:[L]은 stem:[F^{op}]를 기반으로 하며, 곱을 정의하는 '기본적인' 모피즘들을 stem:[F^{op}]로부터 물려받습니다. 여기에 stem:[n]항 연산을 기술하는 '흥미로운' 모피즘들(점선 화살표)이 추가됩니다.

로베르 이론들은 ``Law``라는 카테고리를 이룹니다. 이 카테고리의 모피즘은 유한 곱을 보존하면서 함자 stem:[I]와 가환(commute)하는 함자입니다. 두 로베르 이론 stem:[(L, I_L)]과 stem:[(L', I'_{L'})]이 주어졌을 때, 그들 사이의 모피즘은 다음 조건을 만족하는 함자 stem:[F: L \to L']입니다.

[source,haskell]
----
F (m × n) = F m × F n
F ∘ IL = I'L'
----

[source,text]
----
  [ 로베르 이론 (Lawvere Theory L) 과 모델 (Model M) 의 계층 구조 ]

  1. 로베르 이론의 골격:
       FinSet ── 스켈레톤 ──> F ── op ──> F^{op} ─── I_L ───> L
       (유한 집합)            (자연수, +)    (자연수, ×)   (유한 곱 보존)
       • 대상: 1, 1², 1³, ..., 1ⁿ (단일 제네릭 객체 1의 거듭제곱)
       • 사상: n항 연산 α_n : 1ⁿ -> 1 (투영 p_k 외에 곱셈, 덧셈, 단위 등)

  2. 모델 (Model M : L -> Set):
       L ────────────────── M ──────────────────> Set
       1  ──────────────────────────────────────> a = M(1) (운반자 집합)
       1ⁿ ──────────────────────────────────────> aⁿ = M(1ⁿ) ≅ (M 1)ⁿ
       α_n : 1ⁿ -> 1 ───────────────────────────> f_α : aⁿ -> a (n항 함수)

       * 유한 곱 보존: M(1ⁿ × 1ᵐ) ≅ M(1ⁿ) × M(1ᵐ)
       * 모든 대수 방정식(결합법칙, 단위법칙 등)이 L의 사상 합성 속에 인코딩!
----

로베르 이론 사이의 모피즘은 "한 이론을 다른 이론 내부에서 해석한다"는 아이디어를 캡슐화합니다. 예를 들어, 역원을 무시한다면 군의 곱셈을 모노이드의 곱셈으로 해석할 수 있겠죠.

로베르 카테고리의 가장 간단한 자명한 예는 ``Fop`` 자체입니다 (``IL``에 대해 항등 함자를 선택하는 것에 해당). 연산이나 법칙이 없는 이 로베르 이론은 ``Law``에서 초기 객체입니다.

이 시점에서 로베르 이론의 비자명한 예시를 제시하면 매우 도움이 되겠지만, 모델이 무엇인지 먼저 이해하지 않고는 설명하기 어려울 것입니다.

== 로베르 이론의 모델 (Models of Lawvere Theories)

로베르 이론을 이해하는 열쇠는, 하나의 이론이 동일한 구조를 공유하는 수많은 개별 대수(algebra)들을 일반화하고 있다는 사실을 깨닫는 것입니다. 예를 들어 모노이드의 로베르 이론은 '모노이드가 된다는 것'의 정수를 설명하며, 이는 당연히 모든 모노이드에 대해 유효해야 합니다. 특정한 모노이드 하나하나가 바로 이러한 이론의 '모델(model)'이 됩니다. 모델은 로베르 이론 stem:[L]에서 집합의 카테고리 ``Set``으로 가는 함자로 정의됩니다. (모델에 다른 카테고리를 사용하는 로베르 이론의 일반화도 존재하지만, 여기서는 ``Set``에만 집중하겠습니다.) stem:[L]의 구조가 곱(product)에 크게 의존하기 때문에, 우리는 이 함자가 유한 곱을 보존할 것을 요구합니다. 따라서 로베르 이론 stem:[L]에 대한 모델(혹은 로베르 이론 stem:[L] 위에서의 대수)은 다음을 만족하는 함자로 정의됩니다.

[source,haskell]
----
M :: L -> Set
M (a × b) ≅ M a × M b
----

여기서 곱의 보존을 '동형성(isomorphism)'까지만 요구한다는 점에 주목하십시오. 이는 매우 중요한데, 만약 엄격하게 곱을 보존해야 한다고 요구한다면 대부분의 흥미로운 이론들이 배제될 것이기 때문입니다.

모델이 곱을 보존한다는 것은 ``Set``에서의 stem:[M]의 상(image)이 객체 1의 상인 stem:[M 1]의 거듭제곱들로 생성된 집합들의 수열임을 의미합니다. 이 집합 stem:[M 1]을 stem:[a]라고 부릅시다. (이 집합은 가끔 정렬, sort라고 불리며 이러한 대수는 단일 정렬, single-sorted 대수라고 합니다. 다중 정렬 대수에 대한 로베르 이론의 일반화도 존재합니다.) 특히, stem:[L]에서의 이항 연산은 다음과 같은 함수로 매핑됩니다.

[source,haskell]
----
a × a -> a
----

여느 함자와 마찬가지로, stem:[L]에서의 여러 모피즘들이 ``Set``의 동일한 함수로 뭉쳐질(collapsed) 수도 있습니다.

덧붙여 말하면, 모든 법칙이 전칭 한정된 등식이라는 사실은 모든 로베르 이론이 '자명한 모델(trivial model)'을 가지고 있음을 의미합니다. 즉 모든 객체를 단일 원소 집합으로, 모든 모피즘을 그 위의 항등 함수로 매핑하는 상수 함자가 그것입니다.

stem:[L]에서의 일반적인 모피즘 stem:[m \to n]은 다음과 같은 함수로 매핑됩니다.

[source,haskell]
----
am -> an
----

만약 두 모델 stem:[M]과 stem:[N]이 있다면, 그들 사이의 자연 변환(natural transformation)은 stem:[n]으로 인덱싱된 함수들의 패밀리가 됩니다.

[source,haskell]
----
μn :: M n -> N n
----

혹은 동일하게 다음과 같이 쓸 수 있습니다.

[source,haskell]
----
μn :: an -> bn
----

여기서 stem:[b = N 1]입니다.

이때 자연성 조건(naturality condition)이 stem:[n]항 연산의 보존을 보장한다는 점을 확인하십시오.

[source,haskell]
----
N f ∘ μn = μ1 ∘ M f
----

여기서 stem:[f: n \to 1]은 stem:[L]에서의 어떤 stem:[n]항 연산입니다.

모델을 정의하는 함자들은 자연 변환을 모피즘으로 하는 모델의 카테고리 stem:[Mod(L, Set)]을 형성합니다.

가장 단순한 로베르 카테고리 stem:[F^{op}]의 모델을 생각해 봅시다. 이러한 모델은 객체 1에서의 값 stem:[M 1]에 의해 완전히 결정됩니다. stem:[M 1]은 어떤 집합이든 될 수 있으므로, 이러한 모델은 ``Set``에 존재하는 집합의 개수만큼 존재합니다. 게다가 stem:[Mod(F^{op}, Set)]에서의 모든 모피즘(함자 stem:[M]과 stem:[N] 사이의 자연 변환)은 stem:[M 1]에서의 성분(component)에 의해 유일하게 결정됩니다. 역으로, 임의의 함수 stem:[M 1 \to N 1]은 두 모델 stem:[M]과 stem:[N] 사이의 자연 변환을 유도합니다. 따라서 stem:[Mod(F^{op}, Set)]은 ``Set``과 동등(equivalent)합니다.

== 모노이드 이론 (The Theory of Monoids)

가장 간단한 비자명한 로베르 이론의 예시는 바로 모노이드의 구조를 설명하는 이론입니다. 이는 가능한 모든 모노이드의 구조를 추출해낸 단일한 이론으로, 이 이론의 모델들은 모노이드의 카테고리 ``Mon`` 전체를 포괄합니다. 우리는 이미 앞선 장에서, 모든 모노이드는 적절한 자유 모노이드(free monoid) 상에서 모피즘들의 부분 집합을 하나로 식별함으로써 얻어질 수 있다는 보편적 구성을 살펴본 바 있습니다. 즉, 단 하나의 자유 모노이드만으로도 이미 수많은 모노이드들을 일반화할 수 있는 것이죠. 하지만 자유 모노이드는 무수히 많이 존재합니다. 모노이드의 로베르 이론 stem:[L_{Mon}]은 이 모든 것들을 하나의 우아한 구성으로 결합해 냅니다.

모든 모노이드는 단위 원소를 가져야 하므로, stem:[L_{Mon}]에는 0에서 1로 가는 특별한 모피즘 stem:[\eta]가 있어야 합니다. stem:[F]에는 이에 대응하는 모피즘이 존재할 수 없다는 점에 주목하십시오. 만약 존재한다면 stem:[1 \to 0] 방향이어야 할 텐데, ``FinSet``에서 단일 원소 집합에서 공집합으로 가는 함수는 존재하지 않기 때문입니다.

다음으로 stem:[2 \to 1] 형태의 모피즘들, 즉 stem:[L_{Mon}(2, 1)]의 원소들을 살펴봅시다. 여기에는 모든 이항 연산의 원형들이 포함되어야 합니다. stem:[Mod(L_{Mon}, Set)]에서 모델을 구축할 때, 이러한 모피즘들은 데카르트 곱 stem:[M 1 \times M 1]에서 stem:[M 1]로 가는 함수, 즉 두 개의 인수를 받는 함수로 매핑될 것입니다.

여기서 질문이 하나 생깁니다. 오직 모노이드 연산자만을 사용하여 구현할 수 있는 '두 인수를 받는 함수'는 과연 몇 개나 될까요? 두 인수를 각각 stem:[a]와 stem:[b]라고 부릅시다. 우선 두 인수를 모두 무시하고 모노이드의 단위 원소를 반환하는 함수가 하나 있을 것이고, stem:[a]와 stem:[b]를 각각 반환하는 두 개의 투영 함수가 있을 것입니다. 그 뒤를 이어 stem:[ab], stem:[ba], stem:[aa], stem:[bb], stem:[aab] 등을 반환하는 함수들이 등장하겠죠... 사실 두 인수를 받는 함수의 개수는 stem:[a]와 stem:[b]를 생성원(generator)으로 하는 자유 모노이드의 원소 개수와 정확히 일치합니다. 모델 중 하나가 바로 자유 모노이드이기 때문에, stem:[L_{Mon}(2, 1)]은 반드시 이러한 모피즘들을 모두 포함하고 있어야 합니다. 자유 모노이드에서는 이들이 각각 서로 다른 함수에 해당하기 때문이죠. 다른 모델에서는 stem:[L_{Mon}(2, 1)]의 여러 모피즘들이 하나의 함수로 뭉쳐질 수도 있겠지만, 자유 모노이드만큼은 이들을 모두 구별해 냅니다.

stem:[n]개의 생성원을 가진 자유 모노이드를 stem:[n^*]라고 표시한다면, 우리는 hom-집합 stem:[L(2, 1)]을 모노이드 카테고리 ``Mon``에서의 hom-집합 stem:[Mon(1^*, 2^*)]와 식별할 수 있습니다. 일반적으로 우리는 stem:[L_{Mon}(m, n)]을 stem:[Mon(n^*, m^*)]으로 정의합니다. 다시 말해, 카테고리 stem:[L_{Mon}]은 자유 모노이드 카테고리의 반대 카테고리(opposite category)입니다.

모노이드 로베르 이론의 모델 카테고리 stem:[Mod(L_{Mon}, Set)]은 모든 모노이드의 카테고리 ``Mon``과 동등합니다.

== 로베르 이론과 모나드 (Lawvere Theories and Monads)

기억하시겠지만, 대수적 이론은 모나드(monad), 특히 모나드에 대한 대수(monad algebra)를 통해 설명될 수 있습니다. 그러니 로베르 이론과 모나드 사이에 깊은 연관성이 있다는 점은 그리 놀라운 일이 아닐 것입니다.

먼저, 로베르 이론이 어떻게 모나드를 유도하는지 살펴보겠습니다. 이는 망각 함자(forgetful functor)와 자유 함자(free functor) 사이의 수반(adjunction) 관계를 통해 이루어집니다. 망각 함자 stem:[U]는 각 모델에 대해 해당 집합을 할당합니다. 이 집합은 stem:[Mod(L, Set)]의 함자 stem:[M]을 stem:[L]의 객체 1에 대해 평가함으로써 얻어집니다.

stem:[U]를 도출하는 또 다른 방법은 stem:[F^{op}]가 ``Law``의 초기 객체라는 사실을 이용하는 것입니다. 이는 어떤 로베르 이론 stem:[L]에 대해서도 유일한 함자 stem:[F^{op} \to L]이 존재함을 의미합니다. 이 함자는 모델들에 대해 다음과 같이 반대 방향의 함자를 유도합니다(모델이란 이론에서 집합으로 가는 함자이기 때문입니다).

[source,haskell]
----
Mod(L, Set) -> Mod(Fop, Set)
----

우리가 이미 논의했듯이 stem:[F^{op}]의 모델 카테고리는 ``Set``과 동등하므로, 우리는 다음과 같은 망각 함자를 얻게 됩니다.

[source,haskell]
----
U :: Mod(L, Set) -> Set
----

이렇게 정의된 stem:[U]가 항상 좌수반(left adjoint)인 자유 함자 stem:[F]를 가진다는 사실을 증명할 수 있습니다.

유한 집합의 경우 이를 쉽게 확인할 수 있습니다. 자유 함자 stem:[F]는 '자유 대수(free algebras)'를 생성합니다. 자유 대수란 stem:[n]개의 생성원을 가진 유한 집합으로부터 생성된 stem:[Mod(L, Set)] 내의 특정한 모델을 말합니다. 우리는 stem:[F]를 다음과 같은 표현 가능 함자(representable functor)로 구현할 수 있습니다.

[source,haskell]
----
L(n, -) :: L -> Set
----

이것이 실제로 '자유' 함자임을 보이려면, 이것이 망각 함자의 좌수반임을 증명하기만 하면 됩니다.

[source,haskell]
----
Mod(L(n, -), M) ≅ Set(n, U(M))
----

우변을 단순화해 봅시다.

[source,haskell]
----
Set(n, U(M)) ≅ Set(n, M 1) ≅ (M 1)n ≅ M n
----

(여기서는 모피즘의 집합이 지수와 동형이며, 이 경우에는 반복된 곱과 같다는 사실을 이용했습니다.) 이 수반 관계는 바로 요네다 보조정리(Yoneda lemma)의 결과입니다.

[source,haskell]
----
[L, Set](L(n, -), M) ≅ M n
----

망각 함자와 자유 함자를 결합하여 우리는 ``Set`` 위에서의 모나드 stem:[T = U \circ F]를 정의할 수 있습니다. 즉, 모든 로베르 이론은 모나드를 생성합니다.

그리고 이 모나드에 대한 대수의 카테고리는 원래 모델의 카테고리와 동등하다는 것이 밝혀졌습니다.

모나드 대수는 모나드를 통해 형성된 표현식을 평가하는 방법을 정의한다는 점을 상기해 보십시오. 로베르 이론은 표현식을 생성하는 데 사용할 수 있는 stem:[n]항 연산들을 정의하고, 모델은 이러한 표현식들을 평가하는 수단을 제공합니다.

하지만 모나드와 로베르 이론 사이의 연결이 항상 양방향으로 작용하는 것은 아닙니다. 오직 유한적(finitary) 모나드만이 로베르 이론으로 이어집니다. 유한적 모나드는 유한적 함자(finitary functor)를 기반으로 합니다. ``Set`` 위에서의 유한적 함자는 유한 집합에 대한 자신의 작용에 의해 완전히 결정됩니다. 임의의 집합 stem:[a]에 대한 작용은 다음과 같은 코엔드(coend)를 통해 얻을 수 있습니다.

[source,haskell]
----
F a = ∫ n an × (F n)
----

코엔드는 코프로덕트 혹은 합(sum)의 일반화이기 때문에, 이 공식은 거듭제곱 급수 전개(power series expansion)를 일반화한 것이라고 볼 수 있습니다. 아니면 함자가 일종의 '메모리 컨테이너'라는 직관을 떠올려 보십시오. 이 경우 stem:[a]의 유한적 컨테이너는 '모양(shape)'과 '내용물(content)'의 합으로 설명될 수 있습니다. 공식에서 stem:[F n]은 stem:[n]개의 원소를 담을 수 있는 모양들의 집합이고, 내용물은 stem:[n]개의 원소들로 이루어진 튜플, 즉 stem:[a^n]의 원소입니다. 예를 들어 목록(list) 함자는 모든 아리티(arity)에 대해 정확히 하나의 모양을 가지는 유한적 함자입니다. 트리는 아리티 하나당 더 많은 모양들을 가질 수 있는 식이죠.

먼저, 로베르 이론에서 유도된 모든 모나드는 유한적이며 다음과 같은 코엔드로 표현될 수 있습니다.

[source,haskell]
----
TL a = ∫ n an × L(n, 1)
----

반대로 ``Set`` 위에서의 임의의 유한적 모나드 stem:[T]가 주어지면, 우리는 로베르 이론을 구축할 수 있습니다. 먼저 stem:[T]에 대한 클라이슬리 카테고리(Kleisli category)를 만듭니다. 기억하시겠지만, 클라이슬리 카테고리에서 stem:[a]에서 stem:[b]로 가는 모피즘은 기저(underlying) 카테고리에서의 다음과 같은 모피즘으로 주어집니다.

[source,haskell]
----
a -> T b
----

이를 유한 집합으로 제한하면 다음과 같습니다.

[source,haskell]
----
m -> T n
----

이러한 클라이슬리 카테고리의 반대 카테고리 stem:[Kl(T)^{op}]를 유한 집합으로 제한한 것이 바로 우리가 찾는 로베르 이론입니다. 특히 stem:[L]에서의 stem:[n]항 연산을 설명하는 hom-집합 stem:[L(n, 1)]은 stem:[Kl(T)(1, n)]과 같습니다.

프로그래밍에서 마주치는 대부분의 모나드들은 유한적입니다. 다만 컨티뉴에이션(continuation) 모나드는 예외적으로 유한적이지 않죠. 물론 로베르 이론의 개념을 유한 연산을 넘어선 범위까지 확장하는 것도 가능합니다.

== 코엔드로서의 모나드 (Monads as Coends)

코엔드 공식을 조금 더 자세히 파헤쳐 보겠습니다.

[source,haskell]
----
TL a = ∫ n an × L(n, 1)
----

우선 이 코엔드는 stem:[F] 위에서 다음과 같이 정의된 프로함자(profunctor) stem:[P]에 대해 취해집니다.

[source,haskell]
----
P n m = an × L(m, 1)
----

이 프로함자는 첫 번째 인수 stem:[n]에 대해 반변(contravariant)입니다. 모피즘을 어떻게 리프트(lift)하는지 생각해 봅시다. ``FinSet``에서의 모피즘이란 유한 집합의 매핑 stem:[f: m \to n]입니다. 이러한 매핑은 stem:[n]개의 원소 중 stem:[m]개를 선택(중복 허용)하는 것을 의미하죠. 이는 stem:[a]의 거듭제곱들 사이의 매핑으로 다음과 같이 리프트될 수 있습니다(방향에 주의하세요).

[source,haskell]
----
an -> am
----

이 리프팅은 단순히 stem:[n]개 원소로 이루어진 튜플 stem:[(a_1, a_2, \dots, a_n)]에서 stem:[m]개의 원소를 (중복을 포함하여) 골라내는 작업입니다.

예를 들어 stem:[f_k: 1 \to n] ( stem:[n]개 원소 집합에서 stem:[k]번째 원소를 선택하는 함수)을 선택해 봅시다. 이는 stem:[a]의 stem:[n]개 원소가 담긴 튜플을 받아 stem:[k]번째 원소를 반환하는 함수로 리프트됩니다.

혹은 stem:[f: m \to 1] (모든 stem:[m]개의 원소를 하나로 매핑하는 상수 함수)을 택해 봅시다. 이에 대한 리프팅은 stem:[a]의 단일 원소를 하나 받아 이를 stem:[m]번 복제(duplicate)하는 함수입니다.

[source,haskell]
----
λx -> (x, x, ... x)
----

이 프로함자가 두 번째 인수에 대해 공변(covariant)이라는 점은 얼핏 봐서는 명확하지 않을 수 있습니다. 사실 hom-함수 stem:[L(m, 1)]은 stem:[m]에 대해 반변입니다. 하지만 우리는 카테고리 stem:[L]이 아닌 카테고리 stem:[F] 위에서 코엔드를 취하고 있습니다. 코엔드 변수 stem:[n]은 유한 집합들(혹은 그 스켈레톤) 위를 움직입니다. 카테고리 stem:[L]은 stem:[F]의 반대 카테고리를 포함하고 있으므로, stem:[F]에서의 모피즘 stem:[m \to n]은 stem:[L]에서 stem:[L(n, m)]의 원소가 됩니다(이 내장은 함자 stem:[I_L]에 의해 주어집니다).

함자 stem:[L(m, 1)]이 stem:[F]에서 ``Set``으로 가는 함자로서 잘 동작하는지 확인해 봅시다. 함수 stem:[f: m \to n]을 리프트하고 싶으므로, 우리의 목표는 stem:[L(m, 1)]에서 stem:[L(n, 1)]로 가는 함수를 구현하는 것입니다. 함수 stem:[f]에 대응하여 stem:[L]에는 stem:[n]에서 stem:[m]으로 가는 모피즘이 존재합니다(방향에 주의). 이 모피즘을 stem:[L(m, 1)]과 선합성(pre-composing)하면 stem:[L(n, 1)]의 부분 집합을 얻게 됩니다.

이때 함수 stem:[1 \to n]을 리프트함으로써 stem:[L(1, 1)]에서 stem:[L(n, 1)]로 건너갈 수 있다는 사실을 주목해 두십시오. 이 점은 나중에 활용할 것입니다.

반변 함자 stem:[a^n]과 공변 함자 stem:[L(m, 1)]의 곱은 stem:[F^{op} \times F \to Set] 형태의 프로함자가 됩니다. 코엔드는 프로함수의 모든 대각(diagonal) 원소들의 코프로덕트(서로소 합) 중 일부 원소들을 하나로 식별하여 정의할 수 있다는 점을 상기하십시오. 이 식별 과정이 바로 코쐐기 조건(cowedge conditions)에 대응합니다.

여기서 코엔드는 모든 stem:[n]에 대한 stem:[a^n \times L(n, 1)] 들의 서로소 합으로 시작됩니다. 이 식별 과정은 코엔드를 코이퀄라이저(coequalizer)로 표현함으로써 생성할 수 있습니다. 먼저 대각선 밖의 항인 stem:[a^n \times L(m, 1)]에서 시작합니다. 대각선 위로 올라가기 위해 우리는 모피즘 stem:[f: m \to n]을 곱의 첫 번째 성분에 적용하거나, 혹은 두 번째 성분에 적용할 수 있습니다. 그렇게 해서 나온 두 결과를 하나로 식별하는 것입니다.

저는 앞서 stem:[f: 1 \to n]의 리프팅이 다음과 같은 두 가지 변환으로 이어진다는 것을 보여드렸습니다.

[source,haskell]
----
an -> a
----

그리고

[source,haskell]
----
L(1, 1) -> L(n, 1)
----

따라서 stem:[a^n \times L(1, 1)]에서 시작하여 우리는 다음 두 곳에 도달할 수 있습니다. stem:[\langle f, id \rangle]를 리프트하면 다음과 같이 되고,

[source,haskell]
----
a × L(1, 1)
----

stem:[\langle id, f \rangle]를 리프트하면 다음과 같이 됩니다.

[source,haskell]
----
an × L(n, 1)
----

하지만 이것이 stem:[a^n \times L(n, 1)]의 모든 원소가 stem:[a \times L(1, 1)]과 식별될 수 있다는 뜻은 아닙니다. 왜냐하면 stem:[L(n, 1)]의 모든 원소가 stem:[L(1, 1)]로부터 도달 가능한 것은 아니기 때문입니다. 우리가 리프트할 수 있는 것은 오직 stem:[F]에 존재하는 모피즘들뿐임을 기억하십시오. stem:[L]에 존재하는 비자명한(non-trivial) stem:[n]항 연산들은 모피즘 stem:[f: 1 \to n]을 리프트하는 것만으로는 결코 만들어낼 수 없습니다.

다시 말해, 코엔드 공식의 모든 항 중에서도 기본 모피즘(basic morphisms)들을 적용하여 stem:[L(1, 1)]로부터 도달할 수 있는 영역에 대해서만 항들을 식별할 수 있습니다. 이들은 모두 stem:[a \times L(1, 1)]과 동등합니다. 여기서 기본 모피즘이란 stem:[F]에 있는 모피즘들의 이미지(image)를 말합니다.

로베르 이론의 가장 단순한 사례인 stem:[F^{op}] 자체에서는 이것이 어떻게 작동하는지 봅시다. 이러한 이론에서는 모든 stem:[L(n, 1)]이 stem:[L(1, 1)]로부터 도달 가능합니다. stem:[L(1, 1)]은 항등 모피즘만을 포함하는 단일 원소 집합이고, stem:[L(n, 1)]은 stem:[F]에서의 주입 stem:[1 \to n]에 대응하는 모피즘들(즉, 기본 모피즘들)만을 포함하기 때문입니다. 따라서 코프로덕트의 모든 항들이 서로 식별되어 우리는 다음을 얻게 됩니다.

[source,haskell]
----
T a = a × L(1, 1) = a
----

이는 바로 항등(identity) 모나드입니다.

== 부작용에 대한 로베르 이론

모나드와 로베르 이론 사이에는 이토록 강력한 연결 고리가 존재하기에, "로베르 이론이 프로그래밍에서 모나드의 대안으로 쓰일 수 있을까?"라는 질문을 던지는 것은 매우 자연스럽습니다. 모나드의 가장 큰 문제점은 합성이 깔끔하지 않다는 것인데, 모든 모나드에 통용되는 범용적인 모나드 트랜스포머 같은 레시피가 없기 때문입니다. 로베르 이론은 이 지점에서 강점을 가집니다. 즉 코프로덕트와 텐서 곱(tensor products)을 통해 이론들을 합성할 수 있습니다. 반면, 오직 유한적 모나드만이 로베르 이론으로 쉽게 변환될 수 있다는 단점도 있습니다. 여기서 가장 큰 예외는 컨티뉴에이션 모나드입니다. 이 분야에 대해서는 현재 활발한 연구가 진행 중입니다(참고 문헌을 확인하세요).

로베르 이론이 부수 효과(side effects)를 어떻게 설명하는지 맛보기로 보여드리기 위해, 전통적으로 ``Maybe`` 모나드로 구현되는 '예외(exceptions)'라는 간단한 사례를 논의해 보겠습니다.

``Maybe`` 모나드는 단 하나의 0항 연산 stem:[0 \to 1]을 가진 로베르 이론으로부터 생성됩니다. 이 이론의 모델은 1을 어떤 집합 stem:[a]로 매핑하고, 0항 연산을 다음과 같은 함수로 매핑하는 함자입니다.

[source,haskell]
----
raise :: () -> a
----

우리는 코엔드 공식을 통해 ``Maybe`` 모나드를 다시 복구해낼 수 있습니다. 0항 연산의 추가가 hom-집합 stem:[L(n, 1)]에 어떤 영향을 주는지 살펴봅시다. 단순히 새로운 stem:[L(0, 1)]을 생성하는 것(이는 stem:[F^{op}]에는 없던 것입니다) 외에도, 이는 stem:[L(n, 1)]에 새로운 모피즘들을 추가합니다. 이들은 stem:[n \to 0] 형태의 모피즘과 우리의 stem:[0 \to 1]을 합성한 결과물들입니다. 이러한 기여분들은 코엔드 공식에서 모두 stem:[a^0 \times L(0, 1)]과 식별되는데, 왜냐하면 이들은 다음과 같은 곳으로부터 얻어질 수 있기 때문입니다.

[source,haskell]
----
an × L(0, 1)
----

이때 stem:[0 \to n]을 두 가지 다른 방식으로 리프트함으로써 말이죠.

결국 코엔드는 다음과 같이 축소됩니다.

[source,haskell]
----
TL a = a0 + a1
----

혹은 하스켈 표기법으로 쓰자면 다음과 같습니다.

[source,haskell]
----
type Maybe a = Either () a
----

이는 다음의 정의와 동등합니다.

[source,haskell]
----
data Maybe a = Nothing | Just a
----

단, 이 로베르 이론은 예외를 '발생(raising)'시키는 것만 지원할 뿐, 예외 '처리(handling)'는 지원하지 않는다는 점에 유의하십시오.

== 도전 과제

1. stem:[F](FinSet의 스켈레톤)에서 2와 3 사이의 모든 모피즘을 열거해 보시오.
2. 모노이드의 로베르 이론에 대한 모델의 카테고리가 리스트(list) 모나드에 대한 모나드 대수의 카테고리와 동등함을 보이시오.
3. 모노이드의 로베르 이론이 리스트 모나드를 생성함을 보이시오. 이때 이항 연산들이 그에 대응하는 클라이슬리 화살표(Kleisli arrows)들을 사용하여 생성될 수 있음을 보이시오.
4. ``FinSet``은 ``Set``의 부분 카테고리이며, 이를 ``Set`` 내부로 내장하는 함자가 존재합니다. ``Set`` 위에서의 모든 함자는 ``FinSet``으로 제한(restrict)될 수 있습니다. 이때 임의의 유한적 함자는 자기 자신의 제한에 대한 좌 칸 확장(left Kan extension)임을 보이시오.
