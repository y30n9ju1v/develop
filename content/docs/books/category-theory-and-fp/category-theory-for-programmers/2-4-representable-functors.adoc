'''
집합은 카테고리 이론적 객체를 제외하면 가장 특징 없는 덩어리에 가깝습니다. 집합은 원소를 가지지만, 그 원소에 대해 말할 수 있는 것은 많지 않습니다. 유한 집합이라면 원소의 개수를 셀 수는 있을 것입니다. 무한 집합의 원소 개수도 기수(cardinal number)를 사용하면 어느 정도 가늠할 수 있습니다. 예를 들어, 자연수의 집합은 실수의 집합보다 작습니다. 둘 다 무한하지만요. 하지만 놀랍게도 유리수의 집합은 자연수의 집합과 크기가 같습니다.

그 외에 집합에 대한 모든 정보는 집합 간의 함수, 특히 가역 함수인 동형 모피즘(isomorphism)에 인코딩될 수 있습니다. 사실상 동형인 두 집합은 동일한 것입니다. 기초 수학자들의 분노를 사기 전에 덧붙이자면, 사실 '동등함(equality)'과 '동형임(isomorphism)'의 차이를 구별하는 것은 근본적으로 매우 중요합니다. 실제로 이는 최신 수학 분야인 호모토피 타입 이론(Homotopy Type Theory, HoTT)의 주요 관심사 중 하나이기도 합니다. HoTT를 언급하는 이유는 이것이 계산(computation)에서 영감을 얻은 순수 수학 이론이기 때문입니다. HoTT의 주요 제창자 중 한 명인 블라디미르 보에보드스키(Vladimir Voevodsky)는 Coq 정리 증명기를 연구하던 중 중대한 깨달음을 얻었다고 합니다. 수학과 프로그래밍 사이의 상호작용은 이처럼 양방향으로 일어납니다.

집합에 관한 중요한 교훈 중 하나는, 서로 다른 종류의 원소를 가진 집합들을 비교해도 괜찮다는 점입니다. 예를 들어, 주어진 자연 변환들의 집합이 어떤 모피즘들의 집합과 동형이라고 말할 수 있는데, 이는 '집합은 결국 집합일 뿐'이기 때문입니다. 이 경우 동형이라는 것은 한 집합의 모든 자연 변환에 대해 다른 집합의 유일한 모피즘이 일대일로 대응된다는 것을 의미합니다. 서로 짝을 지을 수 있다는 것이죠. 서로 다른 카테고리의 객체라면 사과와 오렌지를 직접 비교할 수는 없겠지만, 사과들의 집합과 오렌지들의 집합은 비교할 수 있습니다. 종종 카테고리 이론의 문제를 집합론의 문제로 변환하는 것이 필요한 통찰력을 제공하거나, 심지어 귀중한 정리를 증명하는 데 도움을 주기도 합니다.

== Hom 함자

모든 카테고리에는 ``Set``으로 가는 표준적인 대응 관계(canonical mapping)들이 갖춰져 있습니다. 이 대응 관계들은 사실 함자(functor)이므로 카테고리의 구조를 보존합니다. 그런 대응 관계 중 하나를 직접 만들어 봅시다.

카테고리 ``C``에서 객체 ``a``를 하나 고정하고, ``C``의 다른 객체 ``x``를 선택합시다. 그러면 hom-set ``C(a, x)``는 하나의 집합이며, 곧 ``Set``의 객체입니다. ``a``를 고정한 상태에서 ``x``를 변화시키면 ``C(a, x)`` 역시 ``Set`` 내에서 변화할 것입니다. 즉, 우리는 ``x``에서 ``Set``으로 가는 대응 관계를 얻게 됩니다.

hom-set을 두 번째 인수에 대한 대응 관계로 간주하고 있음을 강조하기 위해 다음과 같은 표기법을 사용합니다.

[source,haskell]
----
C(a, -)
----

여기서 대시(``-``)는 인수가 들어갈 플레이스홀더(placeholder) 역할을 합니다.

이러한 객체 간의 대응 관계는 모피즘 간의 대응 관계로 쉽게 확장할 수 있습니다. ``C``에서 임의의 두 객체 ``x``와 ``y`` 사이의 모피즘 ``f``를 취해봅시다. 방금 정의한 대응 관계에 따라 객체 ``x``는 집합 ``C(a, x)``로, 객체 ``y``는 집합 ``C(a, y)``로 매핑됩니다. 이 대응 관계가 함자가 되려면, ``f``는 두 집합 사이의 함수로 매핑되어야 합니다.

[source,haskell]
----
C(a, x) -> C(a, y)
----

이 함수를 점별(point-wise) 정의, 즉 각 인수에 대해 개별적으로 정의해 봅시다. 인수로 ``C(a, x)``의 임의의 원소를 하나 선택해야 합니다. 이를 ``h``라고 부릅시다. 모피즘은 끝과 끝이 맞으면 합성할 수 있습니다. 마침 ``h``의 공역이 ``f``의 정의역과 일치하므로, 다음과 같은 합성이 가능합니다.

[source,haskell]
----
f ∘ h :: a -> y
----

이 합성 결과는 ``a``에서 ``y``로 가는 모피즘이며, 따라서 ``C(a, y)``의 원소입니다.

우리는 방금 ``C(a, x)``에서 ``C(a, y)``로 가는 함수를 찾아냈으며, 이 함수가 바로 ``f``의 상(image)이 됩니다. 혼동의 여지가 없다면, 이 리프트된(lifted) 함수를 다음과 같이 표기합니다.

[source,haskell]
----
C(a, f)
----

그리고 모피즘 ``h``에 대한 이 함수의 작용은 다음과 같습니다.

[source,haskell]
----
C(a, f) h = f ∘ h
----

이러한 구성은 모든 카테고리에서 작동하므로, 하스켈 타입의 카테고리에서도 당연히 작동합니다. 하스켈에서 이 hom-함자는 리더 함자(Reader functor)로 더 잘 알려져 있습니다.

[source,haskell]
----
type Reader a x = a -> x
----

[source,haskell]
----
instance Functor (Reader a) where
    fmap f h = f . h
----

이제 hom-set의 출발점(source)을 고정하는 대신 도착점(target)을 고정하면 어떻게 되는지 생각해 봅시다. 다시 말해, 다음과 같은 대응 관계가

[source,haskell]
----
C(-, a)
----

역시 함자가 되는가 하는 질문입니다. 결론부터 말하면 함자가 맞습니다. 하지만 공변(covariant) 함자가 아니라 반변(contravariant) 함자입니다. 모피즘의 끝을 맞추는 과정에서 ``C(a, -)``의 경우처럼 선합성(precomposition)이 아니라 ``f``에 의한 후합성(postcomposition)이 일어나기 때문입니다.

우리는 하스켈에서 이 반변 함자를 이미 본 적이 있습니다. 우리는 그것을 ``Op``라고 불렀습니다:

[source,haskell]
----
type Op a x = x -> a
----

[source,haskell]
----
instance Contravariant (Op a) where
    contramap f h = h . f
----

마지막으로, 두 객체를 모두 변화시키면 첫 번째 인자에 대해서는 반변이고 두 번째 인자에 대해서는 공변인 프로함자(profunctor) ``C(-, =)``를 얻을 수 있습니다 (두 인자가 독립적으로 변할 수 있음을 강조하기 위해 두 번째 플레이스홀더에는 이중 대시를 사용했습니다). 이 프로함자는 지난번 함자성(functoriality)에 관해 이야기할 때 이미 살펴본 바 있습니다.

[source,haskell]
----
instance Profunctor (->) where
  dimap ab cd bc = cd . bc . ab
  lmap = flip (.)
  rmap = (.)
----

중요한 교훈은 이 관찰이 어떤 카테고리에서도 성립한다는 것입니다. 즉, 객체를 hom-set으로 대응시키는 것은 함자적(functorial)입니다. 반변성은 반대 카테고리(opposite category)로부터의 대응과 동일하므로, 이 사실을 다음과 같이 간결하게 표현할 수 있습니다.

[source,haskell]
----
C(-, =) :: Cop × C -> Set
----

== 표현 가능 함자 (Representable Functors)

카테고리 ``C``의 객체 ``a``를 선택할 때마다 ``C``에서 ``Set``으로 가는 함자를 하나씩 얻게 된다는 것을 보았습니다. 이러한 종류의 구조 보존 대응 관계를 ``Set``을 통한 *표현(representation)*이라고 부릅니다. ``C``의 객체와 모피즘을 각각 ``Set``의 집합과 함수로 표현하는 것이죠.

함자 ``C(a, -)`` 그 자체를 *표현 가능(representable)*이라고 부르기도 합니다. 더 일반적으로, 어떤 객체 ``a``를 선택했을 때 그 hom-함자와 자연적으로 동형인 임의의 함자 ``F``를 표현 가능 함자라고 합니다. ``C(a, -)``가 ``Set`` 값을 가지는 함자이므로, ``F`` 역시 반드시 ``Set`` 값을 가지는 함자여야 합니다.

앞서 우리는 동형인 집합들을 사실상 같은 것으로 생각한다고 말했습니다. 좀 더 일반화하자면, 카테고리 내에서도 동형인 객체들은 동일한 것으로 간주합니다. 객체란 모피즘을 통해 다른 객체(및 자기 자신)와 맺는 관계 외에는 별다른 내부 구조를 가지지 않기 때문입니다.

예를 들어, 앞서 살펴본 모노이드의 카테고리 ``Mon``은 처음에는 집합을 모델로 삼아 만들어졌습니다. 하지만 우리는 모피즘을 고를 때 해당 집합의 모노이드 구조를 보존하는 함수들만을 신중하게 선택했죠. 따라서 ``Mon``의 두 객체가 동형이라면(즉, 그들 사이에 가역 모피즘이 존재한다면), 두 객체는 정확히 동일한 구조를 가집니다. 그 바탕이 되는 집합과 함수를 들여다보면, 한 모노이드의 단위원이 다른 모노이드의 단위원으로 매핑되고, 두 원소의 곱이 매핑된 결과물들의 곱으로 대응됨을 알 수 있을 것입니다.

같은 논리를 함자에게도 적용할 수 있습니다. 두 카테고리 사이의 함자들은 자연 변환이 모피즘 역할을 수행하는 카테고리를 형성합니다. 따라서 두 함자 사이에 가역 자연 변환(invertible natural transformation)이 존재한다면, 그 두 함자는 동형이며 사실상 동일한 것으로 볼 수 있습니다.

이런 관점에서 표현 가능 함자의 정의를 다시 분석해 봅시다. ``F``가 표현 가능하려면 다음이 필요합니다. 첫째, 카테고리 ``C`` 내의 어떤 객체 ``a``가 존재해야 합니다. 둘째, ``C(a, -)``에서 ``F``로 가는 자연 변환 ``α``가 있어야 하고, 그 반대 방향의 자연 변환 ``β``도 존재해야 합니다. 마지막으로, 이 둘을 합성한 결과가 항등 자연 변환이어야 합니다.

어떤 객체 ``x``에서 자연 변환 ``α``의 성분(component)을 살펴봅시다. 이는 ``Set``에서의 함수입니다.

[source,haskell]
----
αx :: C(a, x) -> F x
----

이 변환에 대한 자연성 조건(naturality condition)에 따르면, ``x``에서 ``y``로 가는 임의의 모피즘 ``f``에 대해 다음 다이어그램이 가환(commute)해야 합니다.

[source,haskell]
----
F f ∘ αx = αy ∘ C(a, f)
----

하스켈에서는 자연 변환을 다형성 함수(polymorphic function)로 대체할 것입니다.

[source,haskell]
----
alpha :: forall x. (a -> x) -> F x
----

여기서 ``forall`` 한정사는 써도 되고 안 써도 됩니다. 자연성 조건은 다음과 같습니다.

[source,haskell]
----
fmap f . alpha = alpha . fmap f
----

이 조건은 매개변수성(parametricity) 덕분에 자동으로 보장됩니다 (앞서 언급했던 '공짜 정리(theorems for free)' 중 하나입니다). 이때 왼쪽의 ``fmap``은 함자 ``F``에 의해 정의된 것이며, 오른쪽의 ``fmap``은 리더 함자(Reader functor)에 의해 정의된 것임을 유의해야 합니다. 리더 함자의 ``fmap``은 단순히 함수의 선합성(precomposition)일 뿐이므로, 이를 더 명시적으로 적을 수 있습니다. ``C(a, x)``의 원소 ``h``에 작용할 때, 자연성 조건은 다음과 같이 단순화됩니다.

[source,haskell]
----
fmap f (alpha h) = alpha (f . h)
----

반대 방향의 변환인 ``beta``는 다음과 같습니다.

[source,haskell]
----
beta :: forall x. F x -> (a -> x)
----

``beta`` 역시 자연성 조건을 만족해야 하며, ``alpha``의 역변환이어야 합니다.

[source,haskell]
----
α ∘ β = id = β ∘ α
----

나중에 배우겠지만, ``F a``가 비어 있지 않은 한 ``C(a, -)``에서 ``Set`` 값을 가지는 임의의 함자 ``F``로 가는 자연 변환은 항상 존재합니다(요네다 보조정리, Yoneda's lemma). 하지만 그 변환이 반드시 가역적(invertible)인 것은 아닙니다.

하스켈에서 리스트 함자와 ``Int``를 ``a``로 사용하는 예를 들어 보겠습니다. 다음은 그 역할을 하는 자연 변환입니다.

[source,haskell]
----
alpha :: forall x. (Int -> x) -> [x]
alpha h = map h [12]
----

임의로 숫자 12를 택해 이를 포함하는 싱글턴 리스트(singleton list)를 만들었습니다. 여기에 함수 ``h``를 ``map``하면 ``h``가 반환하는 타입의 원소들로 이루어진 리스트를 얻을 수 있죠. (사실 정수 리스트의 개수만큼이나 많은 자연 변환이 존재할 수 있습니다.)

자연성 조건은 ``map``(리스트 버전의 ``fmap``)의 합성 가능성과 동일합니다.

[source,haskell]
----
map f (map h [12]) = map (f . h) [12]
----

하지만 역변환을 찾으려고 하면, 임의의 타입 ``x``를 담은 리스트에서 ``x``를 반환하는 함수로 가는 경로를 찾아야 합니다.

[source,haskell]
----
beta :: forall x. [x] -> (Int -> x)
----

리스트에서 ``head`` 같은 함수로 ``x``를 꺼내오는 것을 생각할 수 있겠지만, 빈 리스트에 대해서는 작동하지 않을 것입니다. ``Int`` 대신 어떤 타입을 ``a``로 고르더라도 이 문제를 해결할 수는 없습니다. 따라서 리스트 함자는 표현 가능하지 않습니다.

하스켈의 (엔도) 함자가 일종의 컨테이너와 비슷하다는 이야기를 했던 것을 기억하시나요? 같은 맥락에서 표현 가능 함자는 함수 호출의 메모이제이션된(memoized) 결과를 저장하는 컨테이너라고 생각할 수 있습니다. 하스켈에서 hom-set의 원소는 곧 함수이기 때문입니다. 표현 객체인 ``C(a, -)``의 타입 ``a``는 *키 타입(key type)*으로 간주되며, 이 키를 통해 테이블화된(tabulated) 함수의 값에 접근할 수 있습니다. 앞에서 ``α``라고 불렀던 변환은 ``tabulate``라 부르고, 그 역인 ``β``는 ``index``라고 부릅니다. 다음은 (약간 단순화된) ``Representable`` 클래스의 정의입니다.

[source,haskell]
----
class Representable f where
   type Rep f :: *
   tabulate :: (Rep f -> x) -> f x
   index    :: f x -> Rep f -> x
----

여기서 ``Rep f``로 정의된 표현 타입 ``a``가 ``Representable`` 정의의 일부임을 눈여겨보세요. 별표(``*``)는 ``Rep f``가 타입 생성자나 다른 종류가 아닌 구체적인 타입(type)임을 의미합니다.

비어 있을 수 없는 무한 리스트인 *스트림(Stream)*은 표현 가능합니다.

[source,haskell]
----
data Stream x = Cons x (Stream x)
----

스트림은 ``Integer``를 인자로 받는 함수의 메모이제이션된 값들로 볼 수 있습니다. (엄밀히 따지면 음수가 없는 자연수를 써야 하겠지만, 코드를 복잡하게 만들지 않기 위해 일단 넘어가겠습니다.)

그런 함수를 테이블화(tabulate)하려면 무한한 스트림을 생성해야 합니다. 물론 하스켈이 지연 평가(lazy evaluation)를 수행하기에 가능한 일이죠. 각 값은 정말로 필요할 때(on demand) 평가됩니다. 메모이제이션된 값에는 ``index``를 사용해 접근합니다.

[source,haskell]
----
instance Representable Stream where
    type Rep Stream = Integer
    tabulate f = Cons (f 0) (tabulate (f . (+1)))
    index (Cons b bs) n = if n == 0 then b else index bs (n - 1)
----

[source,text]
----
  [ 표현 가능 함자 (Representable Functor)의 이중성: 함수 vs 컨테이너 ]

    함수 관점: (Rep f -> x)                    컨테이너 관점: f x
    (계산/로직 표현)                           (메모이제이션/데이터 표현)
    ───────────────────────────             ──────────────────────────
           (Integer -> x)                         Stream x
               │                                      │
               │ ─── tabulate (함수를 데이터로 변환) ──>│
               │                                      │
               │<─── index (데이터를 함수로 조회) ──── │
               v                                      v
           f 0, f 1, f 2...                  Cons (f 0) (Cons (f 1) ...)

    * 자연 동형 (Natural Isomorphism): C(a, -) ≅ F (-)
    * tabulate ∘ index = id,  index ∘ tabulate = id
----

하나의 메모이제이션 체계만으로 임의의 반환 타입을 가진 함수들 전체를 아우를 수 있다는 점이 매우 흥미롭습니다.

반변 함자의 표현 가능성도 비슷하게 정의됩니다. 다만 이때는 ``C(-, a)``의 두 번째 인자를 고정합니다. 또는 ``Cop(a, -)``가 ``C(-, a)``와 같다는 점을 이용해 ``Cop``에서 ``Set``으로 가는 함자로 생각할 수도 있습니다.

표현 가능성에는 재미있는 반전이 숨어 있습니다. 카르테시안 닫힌 카테고리(cartesian closed category)에서 hom-set을 지수 객체(exponential object)로 취급할 수 있다는 점을 기억해 보세요. hom-set ``C(a, x)``는 ``x^a``와 동등하며, 표현 가능 함자 ``F``에 대해 다음과 같이 쓸 수 있습니다.

[source]
----
F = -^a
----

재미를 위해 양변에 로그를 취해 볼까요?

[source]
----
a = log F
----

물론 이는 순전히 형식적인 변환일 뿐이지만, 로그의 성질을 알고 있다면 꽤 유용합니다. 실제로 곱 타입(product type) 기반의 함자는 합 타입(sum type)으로 표현될 수 있고, 반대로 합 타입 함자(예: 리스트 함자)는 일반적으로 표현 가능하지 않다는 사실이 알려져 있습니다.

마지막으로, 표현 가능 함자가 우리에게 동일한 대상에 대한 두 가지 서로 다른 구현을 제공한다는 점에 주목해 봅시다. 하나는 함수이고, 다른 하나는 데이터 구조입니다. 두 구현은 정확히 같은 내용을 가집니다. 같은 키로 접근하면 같은 값을 반환합니다. 이것이 제가 말하고자 했던 "같음"의 의미입니다. 자연적으로 동형인 두 함자는 그 내용에 관한 한 동일합니다. 반면 두 표현 방식은 종종 구현이 다르며 성능 특성도 다를 수 있습니다. 메모이제이션은 성능 향상을 위해 사용되며 실행 시간을 대폭 단축할 수 있습니다. 동일한 계산에 대해 서로 다른 표현을 생성할 수 있다는 것은 실무적으로 매우 가치 있습니다. 놀랍게도 카테고리 이론은 성능에는 전혀 관심이 없으면서도, 실용적 가치가 있는 대안적 구현을 탐색할 수 있는 풍부한 기회를 제공합니다.
