'''
프로그래머에게 모나드를 언급하면 아마 효과(effect)에 대해 이야기하게 될 것입니다. 반면 수학자에게 모나드는 대수(algebra)에 관한 것이죠. 대수에 대해서는 나중에 자세히 다루겠습니다. 대수는 프로그래밍에서도 중요한 역할을 하는데, 그 전에 먼저 대수와 모나드의 관계에 대해 약간의 직관을 제공하고 싶습니다. 지금 단계에서는 다소 대략적인 설명이지만, 일단 따라와 주시기 바랍니다.

대수는 식(expression)을 만들고, 조작하고, 평가하는 것입니다. 식은 연산자를 사용해 구성되죠. 간단한 예를 하나 들어보겠습니다.

[source,haskell]
----
x^2 + 2x + 1
----

이 식은 ``x``와 같은 변수와 1이나 2 같은 상수를 더하기나 곱하기 같은 연산자로 묶어서 만들어집니다. 프로그래머는 흔히 이런 식을 트리(tree) 구조로 생각합니다.

트리는 컨테이너입니다. 더 일반적으로 말하면, 식은 변수를 담는 컨테이너입니다. 카테고리 이론에서 컨테이너는 엔도함자(endofunctor)로 표현됩니다. 변수 ``x``에 타입 ``a``를 할당하면, 이 식은 ``m a`` 타입을 갖습니다. 여기서 ``m``은 식 트리를 만드는 엔도함자입니다. (복잡한 분기 구조를 가진 식은 보통 재귀적으로 정의된 엔도함자로 만들어집니다.)

식에 대해 가장 흔히 수행하는 연산은 무엇일까요? 바로 치환(substitution)입니다. 변수를 다른 식으로 교체하는 것이죠. 예를 들어, 위 예시에서 ``x``를 ``y - 1``로 바꾸면 다음과 같습니다.

[source,haskell]
----
(y - 1)^2 + 2(y - 1) + 1
----

무슨 일이 일어났는지 정리해 봅시다. 타입 ``m a``인 식에 타입 ``a -> m b``의 변환을 적용했습니다(``b``는 ``y``의 타입). 그 결과 타입 ``m b``인 식이 나왔습니다. 시그니처로 쓰면 다음과 같습니다.

[source,haskell]
----
m a -> (a -> m b) -> m b
----

그렇습니다. 바로 모나드 ``bind``의 시그니처입니다.

지금까지는 동기 부여였습니다. 이제 모나드의 수학으로 들어가 봅시다. 수학자들은 프로그래머와 다른 표기법을 사용합니다. 엔도함자에는 보통 문자 ``T``를, ``join``에는 그리스 문자 ``μ``(뮤)를, ``return``에는 ``η``(에타)를 씁니다. ``join``과 ``return``은 모두 다형적 함수이므로, 이들이 자연 변환(natural transformation)에 해당할 것이라고 짐작할 수 있습니다.

따라서 카테고리 이론에서 모나드는 한 쌍의 자연 변환 ``μ``와 ``η``를 갖춘 엔도함자 ``T``로 정의됩니다.

``μ``는 함자의 제곱 T²에서 T로 가는 자연 변환입니다. 제곱은 함자를 자기 자신과 합성한 T ∘ T입니다. (이런 제곱은 엔도함자에서만 가능합니다.)

[source,haskell]
----
μ :: T² -> T
----

이 자연 변환의 객체 ``a``에서의 성분(component)은 다음 모피즘(morphism)입니다.

[source,haskell]
----
μ_a :: T (T a) -> T a
----

하스켈 카테고리(Hask)에서는 이것이 우리가 정의한 ``join``으로 직접 변환됩니다.

``η``는 항등 함자 I와 T 사이의 자연 변환입니다.

[source,haskell]
----
η :: I -> T
----

항등 함자 I는 객체 ``a``에 작용하면 그냥 ``a``가 되므로, ``η``의 성분은 다음 모피즘입니다.

[source,haskell]
----
η_a :: a -> T a
----

이것은 우리가 아는 ``return`` 정의로 직접 변환됩니다.

이 자연 변환들은 몇 가지 추가 법칙을 만족해야 합니다. 이 법칙들을 바라보는 한 가지 방식은 엔도함자 T에 대한 클라이슬리 카테고리를 정의할 수 있게 해준다는 것입니다. ``a``와 ``b`` 사이의 클라이슬리 화살표는 모피즘 ``a -> T b``로 정의된다는 것을 기억하세요. 두 화살표의 합성(아래첨자 T를 붙인 원으로 표기합니다)은 ``μ``를 사용해 구현할 수 있습니다.

[source,haskell]
----
g ∘_T f = μ_c ∘ (T g) ∘ f
----

여기서

[source,haskell]
----
f :: a -> T b
g :: b -> T c
----

``T``는 함자이므로 모피즘 ``g``에 적용할 수 있습니다. 하스켈 표기법으로 쓰면 이 공식이 훨씬 친숙할 것입니다.

[source,haskell]
----
f >=> g = join . fmap g . f
----

또는 성분별로 쓰면 다음과 같습니다.

[source,haskell]
----
(f >=> g) a = join (fmap g (f a))
----

대수적으로 해석하면, 이것은 두 번의 연속적인 치환을 합성하는 것입니다.

클라이슬리 화살표가 카테고리를 형성하려면, 합성이 결합법칙을 만족해야 하고 ``η_a``가 ``a``에서의 항등 클라이슬리 화살표여야 합니다. 이 요구사항은 ``μ``와 ``η``에 대한 모나드 법칙으로 번역됩니다. 하지만 이 법칙들을 모노이드(monoid) 법칙처럼 보이게 만드는 다른 방법도 있습니다. 실제로 ``μ``는 종종 곱셈(multiplication), ``η``는 단위(unit)라고 불립니다.

대략적으로 말하면, 결합법칙은 T의 세제곱 T³을 T로 축소하는 두 가지 방법이 동일한 결과를 주어야 한다고 말합니다. 두 단위 법칙(좌단위, 우단위)은 ``η``를 T에 적용한 다음 ``μ``로 축소하면 다시 T를 얻는다고 말합니다.

자연 변환과 함자를 합성하므로 상황이 조금 까다롭습니다. 수평 합성(horizontal composition)을 잠시 복습해 봅시다. 예를 들어 T³은 T² 뒤에 T가 합성된 것으로 볼 수 있습니다. 여기에 두 자연 변환의 수평 합성을 적용할 수 있습니다.

[source,haskell]
----
I_T ∘ μ
----

그러면 T ∘ T를 얻고, 여기에 다시 ``μ``를 적용하면 T가 됩니다. I_T는 T에서 T로 가는 항등 자연 변환입니다. 이런 형태의 수평 합성 I_T ∘ μ는 종종 T ∘ μ로 줄여 씁니다. 함자와 자연 변환을 직접 합성하는 것은 의미가 없으므로, 이 맥락에서 T는 항등 자연 변환 I_T를 의미한다는 것이 명백하고, 혼동의 여지가 없습니다.

또한 (엔도)함자 카테고리 [C, C]에서 다이어그램을 그릴 수도 있습니다.

아니면 T³을 T² ∘ T의 합성으로 보고 μ ∘ T를 적용할 수 있습니다. 결과는 역시 T ∘ T이고, 다시 ``μ``를 사용해 T로 축소할 수 있습니다. 우리는 두 경로가 동일한 결과를 만들어내도록 요구합니다.

마찬가지로, 항등 함자 I 뒤에 T가 합성된 것에 수평 합성 η ∘ T를 적용하면 T²를 얻고, 이것을 ``μ``로 축소할 수 있습니다. 결과는 T에 항등 자연 변환을 직접 적용한 것과 같아야 합니다. 비슷하게 T ∘ η에 대해서도 마찬가지입니다.

이 법칙들이 클라이슬리 화살표의 합성이 카테고리 법칙을 만족하도록 보장한다는 것을 납득할 수 있습니다.

모나드와 모노이드 사이의 유사성은 놀랍습니다. 곱셈 ``μ``, 단위 ``η``, 결합법칙, 단위 법칙을 모두 가지고 있습니다. 하지만 우리의 모노이드 정의는 모나드를 모노이드로 설명하기에는 너무 좁습니다. 그러므로 모노이드 개념을 일반화해 봅시다.

== 모노이달 카테고리

일반적인 모노이드 정의로 돌아가 봅시다. 모노이드는 이항 연산과 단위라 불리는 특별한 원소를 가진 집합입니다. 하스켈에서는 타입클래스로 표현할 수 있습니다.

[source,haskell]
----
class Monoid m where
    mappend :: m -> m -> m
    mempty  :: m
----

이항 연산 ``mappend``는 결합법칙을 만족해야 하고, 단위 ``mempty``와의 곱셈은 항등원(no-op)이어야 합니다.

하스켈에서 ``mappend`` 정의는 커링(currying)되어 있습니다. 이것은 ``m``의 모든 원소를 함수로 매핑하는 것으로 해석될 수 있습니다.

[source,haskell]
----
mappend :: m -> (m -> m)
----

이런 해석이 모노이드를 단일 객체 카테고리로 정의하게 해줍니다. 이 카테고리에서 엔도모피즘(``m -> m``)이 모노이드의 원소를 나타냅니다. 하지만 커링은 하스켈에 내장되어 있으므로, 곱셈의 다른 정의로 시작할 수도 있습니다.

[source,haskell]
----
mu :: (m, m) -> m
----

여기서 카르테시안 곱 ``(m, m)``이 곱해질 쌍들의 소스가 됩니다.

이 정의는 다른 일반화 경로를 제시합니다. 카르테시안 곱을 카테고리적 곱으로 대체하는 것입니다. 곱이 전역적으로 정의된 카테고리에서 시작해, 거기서 객체 ``m``을 선택하고, 곱셈을 모피즘으로 정의할 수 있습니다.

[source,haskell]
----
μ :: m × m -> m
----

하지만 문제가 하나 있습니다. 임의의 카테고리에서는 객체 내부를 들여다볼 수 없는데, 어떻게 단위 원소를 선택할까요? 여기 트릭이 있습니다. 원소 선택은 싱글턴 집합에서 오는 함수와 동등하다는 것을 기억하세요. 하스켈에서는 ``mempty`` 정의를 함수로 대체할 수 있습니다.

[source,haskell]
----
eta :: () -> m
----

싱글턴은 Set에서 종결 객체이므로, 이 정의를 종결 객체 t를 가진 모든 카테고리로 자연스럽게 일반화할 수 있습니다.

[source,haskell]
----
η :: t -> m
----

이렇게 하면 원소에 대해 말하지 않고도 단위 "원소"를 선택할 수 있습니다.

단일 객체 카테고리로서의 모노이드 정의와 달리, 여기서 모노이드 법칙은 자동으로 만족되지 않습니다. 법칙을 부과해야 합니다. 하지만 법칙을 공식화하려면 기반이 되는 카테고리적 곱 자체의 모노이달 구조를 확립해야 합니다. 먼저 하스켈에서 모노이달 구조가 어떻게 작동하는지 복습해 봅시다.

결합법칙부터 시작합니다. 하스켈에서 대응하는 등식 법칙은 다음과 같습니다.

[source,haskell]
----
mu (x, mu (y, z)) = mu (mu (x, y), z)
----

다른 카테고리로 일반화하려면, 먼저 이것을 함수(모피즘)들의 동등성으로 다시 써야 합니다. 개별 변수에 대한 작용을 추상화해야 합니다. 즉, 포인트 프리(point-free) 표기법을 사용해야 합니다. 카르테시안 곱이 이항 함자라는 것을 알면, 좌변을 다음과 같이 쓸 수 있습니다.

[source,haskell]
----
(mu . bimap id mu)(x, (y, z))
----

우변은 다음과 같습니다.

[source,haskell]
----
(mu . bimap mu id)((x, y), z)
----

이것이 거의 원하는 형태입니다. 불행히도 카르테시안 곱은 엄격하게 결합적이지 않습니다. ``(x, (y, z))``는 ``((x, y), z)``와 같지 않으므로, 포인트 프리로 다음과 같이 쓸 수는 없습니다.

[source,haskell]
----
mu . bimap id mu = mu . bimap mu id
----

반면에 두 쌍의 중첩은 동형입니다. 그들 사이를 변환하는 가역 함수가 있는데, 이것을 결합자(associator)라고 부릅니다.

[source,haskell]
----
alpha :: ((a, b), c) -> (a, (b, c))
alpha ((x, y), z) = (x, (y, z))
----

결합자의 도움으로, ``mu``에 대한 포인트 프리 결합법칙을 쓸 수 있습니다.

[source,haskell]
----
mu . bimap id mu . alpha = mu . bimap mu id
----

단위 법칙에도 비슷한 트릭을 적용할 수 있습니다. 새 표기법에서 단위 법칙은 다음 형태를 취합니다.

[source,haskell]
----
mu (eta (), x) = x
mu (x, eta ()) = x
----

다음과 같이 다시 쓸 수 있습니다.

[source,haskell]
----
(mu . bimap eta id) ((), x) = lambda ((), x)
(mu . bimap id eta) (x, ()) = rho (x, ())
----

동형 ``lambda``와 ``rho``는 각각 좌단위자(left unitor)와 우단위자(right unitor)라고 불립니다. 이들은 단위 ``()``가 동형을 제외하면 카르테시안 곱의 항등원이라는 사실을 증명합니다.

[source,haskell]
----
lambda :: ((), a) -> a
lambda ((), x) = x
----

[source,haskell]
----
rho :: (a, ()) -> a
rho (x, ()) = x
----

따라서 단위 법칙의 포인트 프리 버전은 다음과 같습니다.

[source,haskell]
----
mu . bimap eta id = lambda
mu . bimap id eta = rho
----

우리는 기반 카르테시안 곱 자체가 타입 카테고리에서 모노이달 곱셈처럼 작동한다는 사실을 사용해, ``mu``와 ``eta``에 대한 포인트 프리 모노이드 법칙을 공식화했습니다. 카르테시안 곱의 결합법칙과 단위 법칙은 동형을 제외하면 유효하다는 것을 명심하세요.

알고 보니 이 법칙들은 곱과 종결 객체가 있는 모든 카테고리로 일반화할 수 있습니다. 카테고리적 곱은 실제로 동형을 제외하면 결합적이고, 종결 객체도 동형을 제외하면 단위입니다. 결합자와 두 단위자는 자연 동형입니다. 법칙들은 가환 다이어그램으로 표현할 수 있습니다.

곱은 이항 함자이므로 모피즘의 쌍을 리프트할 수 있다는 점에 주목하세요. 하스켈에서는 ``bimap``을 사용해 이것을 했습니다.

여기서 멈춰서 곱과 종결 객체가 있는 모든 카테고리 위에 모노이드를 정의할 수 있다고 말할 수 있습니다. 객체 ``m``과 모노이드 법칙을 만족하는 두 모피즘 ``μ``와 ``η``를 선택하기만 하면 모노이드를 가지게 됩니다. 하지만 더 잘할 수 있습니다. ``μ``와 ``η``에 대한 법칙을 공식화하는 데 완전한 카테고리적 곱이 필요하지 않습니다. 곱은 투영을 사용하는 보편 구성으로 정의된다는 것을 기억하세요. 우리는 모노이드 법칙 공식화에서 어떤 투영도 사용하지 않았습니다.

곱이 아니면서 곱처럼 동작하는 이항 함자를 텐서 곱(tensor product)이라고 부르며, 종종 중위 연산자 ⊗로 표기합니다. 일반적인 텐서 곱의 정의는 조금 까다롭지만, 걱정하지 마세요. 그 속성들을 나열하겠습니다. 가장 중요한 것은 동형을 제외하면 결합적이라는 것입니다.

마찬가지로, 객체 ``t``가 종결 객체일 필요는 없습니다. 우리는 종결 속성, 즉 모든 객체에서 그곳으로 가는 유일한 모피즘의 존재를 사용하지 않았습니다. 필요한 것은 텐서 곱과 조화롭게 작동하는 것입니다. 즉, 동형을 제외하면 텐서 곱의 단위가 되기를 원합니다. 모두 정리해 봅시다.

모노이달 카테고리는 다음으로 이루어진 카테고리 C입니다.

텐서 곱이라 불리는 이항 함자:

[source,haskell]
----
⊗ :: C × C -> C
----

그리고 단위 객체라 불리는 구별된 객체 i, 결합자와 좌단위자 및 우단위자라 불리는 세 자연 동형과 함께:

[source,haskell]
----
α_a_b_c :: (a ⊗ b) ⊗ c -> a ⊗ (b ⊗ c)
λ_a :: i ⊗ a -> a
ρ_a :: a ⊗ i -> a
----

(네 개 텐서 곱을 단순화하기 위한 일관성 조건도 있습니다.)

중요한 것은 텐서 곱이 많은 익숙한 이항 함자들을 설명한다는 것입니다. 특히 곱, 코프로덕트, 그리고 곧 보겠지만 엔도함자의 합성에도 작동합니다(그리고 Day 컨볼루션 같은 더 난해한 곱들에도). 모노이달 카테고리는 풍부한 카테고리(enriched category)의 공식화에서 필수적인 역할을 할 것입니다.

== 모노이달 카테고리 내의 모노이드

이제 모노이달 카테고리라는 더 일반적인 설정에서 모노이드를 정의할 준비가 되었습니다. 객체 ``m``을 선택하는 것으로 시작합니다. 텐서 곱을 사용해 ``m``의 거듭제곱을 만들 수 있습니다. ``m``의 제곱은 m ⊗ m입니다. ``m``의 세제곱을 만드는 두 가지 방법이 있지만, 결합자를 통해 동형입니다. ``m``의 더 높은 거듭제곱도 마찬가지입니다(여기서 일관성 조건이 필요합니다). 모노이드를 형성하려면 두 모피즘을 선택해야 합니다.

[source,haskell]
----
μ :: m ⊗ m -> m
η :: i -> m
----

여기서 i는 텐서 곱의 단위 객체입니다.

이 모피즘들은 결합법칙과 단위 법칙을 만족해야 하며, 다음 가환 다이어그램으로 표현할 수 있습니다.

텐서 곱이 이항 함자라는 것이 필수적입니다. ``μ ⊗ id``나 ``η ⊗ id`` 같은 곱을 형성하려면 모피즘의 쌍을 리프트해야 하기 때문입니다. 이 다이어그램들은 카테고리적 곱에 대한 이전 결과들의 직접적인 일반화입니다.

== 모노이드로서의 모나드

모노이달 구조는 예상치 못한 곳에서 나타납니다. 그런 곳 중 하나가 함자 카테고리입니다. 조금만 눈을 가늘게 뜨면, 함자 합성을 곱셈의 한 형태로 볼 수 있을 것입니다. 문제는 임의의 두 함자를 합성할 수 없다는 것입니다. 한 함자의 대상 카테고리가 다른 함자의 소스 카테고리여야 합니다. 이것은 모피즘 합성의 일반적인 규칙입니다. 그리고 알다시피, 함자는 실제로 카테고리 Cat의 모피즘입니다. 하지만 엔도모피즘(같은 객체로 되돌아가는 모피즘)이 항상 합성 가능한 것처럼, 엔도함자도 그렇습니다.

주어진 카테고리 C에 대해, C에서 C로의 엔도함자들은 함자 카테고리 [C, C]를 형성합니다. 그 객체들은 엔도함자이고, 모피즘들은 그들 사이의 자연 변환입니다. 이 카테고리에서 임의의 두 객체, 엔도함자 F와 G를 취해, 그들의 합성인 세 번째 객체 F ∘ G를 만들 수 있습니다. 이것은 엔도함자입니다.

엔도함자 합성이 텐서 곱의 좋은 후보일까요? 먼저 이항 함자인지 확인해야 합니다. 모피즘의 쌍을 리프트하는 데 사용할 수 있을까요? 여기서 자연 변환을 말합니다. 텐서 곱에 대한 ``bimap``의 유사물의 시그니처는 다음과 같을 것입니다.

[source,haskell]
----
bimap :: (a -> b) -> (c -> d) -> (a ⊗ c -> b ⊗ d)
----

객체를 엔도함자로, 화살표를 자연 변환으로, 텐서 곱을 합성으로 대체하면 다음을 얻습니다.

[source,haskell]
----
(F -> F') -> (G -> G') -> (F ∘ G -> F' ∘ G')
----

이것이 수평 합성의 특수한 경우임을 알아차릴 것입니다.

또한 엔도함자 합성의 항등원 역할을 할 수 있는 항등 엔도함자 I도 있습니다. 게다가 함자 합성은 결합적입니다. 사실 결합법칙과 단위 법칙이 엄격합니다. 결합자나 두 단위자가 필요 없습니다. 따라서 엔도함자들은 함자 합성을 텐서 곱으로 하는 엄격한 모노이달 카테고리를 형성합니다.

이 카테고리에서 모노이드는 무엇일까요? 객체, 즉 엔도함자 T와 두 모피즘, 즉 자연 변환입니다.

[source,haskell]
----
μ :: T ∘ T -> T
η :: I -> T
----

뿐만 아니라, 여기 모노이드 법칙이 있습니다.

[source,text]
----
  [ 모노이드로서의 모나드 (Monad Laws in [C, C]) ]

  1. 결합 법칙 (Associativity):
            μ ∘ T
       T³ ─────────> T²
       │             │
   T ∘ μ             │ μ
       v             v
       T² ─────────> T
             μ
       (μ ∘ (μ ∘ T) = μ ∘ (T ∘ μ))
       (join . fmap join = join . join)

  2. 좌우 단위 법칙 (Left & Right Unit Laws):
            η ∘ T               T ∘ η
       T <────────── T² ──────────> T
        \            ^             /
         \           │            /
      id_T\          │ μ         / id_T
           \         │          /
            v        │         v
                     T
       (μ ∘ (η ∘ T) = id_T = μ ∘ (T ∘ η))
       (join . return = id = join . fmap return)
----

이것들은 정확히 우리가 전에 본 모나드 법칙입니다. 이제 샌더스 맥 레인의 유명한 인용구를 이해합니다.

[quote]
____
결국, 모나드는 엔도함자 카테고리의 모노이드일 뿐이다.
____

함수형 프로그래밍 콘퍼런스에서 티셔츠에 새겨진 것을 본 적이 있을 것입니다.

== 수반에서 나온 모나드

수반 L ⊣ R은 두 카테고리 C와 D 사이를 오가는 함자 쌍입니다. 두 엔도함자 R ∘ L과 L ∘ R을 만들도록 합성하는 두 가지 방법이 있습니다. 수반에 따라, 이 엔도함자들은 단위(unit)와 여단위(counit)라 불리는 두 자연 변환을 통해 항등 함자에 관련됩니다.

[source,haskell]
----
η :: I_D -> R ∘ L
ε :: L ∘ R -> I_C
----

즉시 수반의 단위가 모나드의 단위처럼 보인다는 것을 알 수 있습니다. 알고 보니 엔도함자 R ∘ L은 실제로 모나드입니다. ``η``와 함께 갈 적절한 ``μ``를 정의하기만 하면 됩니다. 이것은 엔도함자의 제곱과 엔도함자 자체 사이의 자연 변환, 또는 수반 함자들의 관점에서 다음과 같습니다.

[source,haskell]
----
R ∘ L ∘ R ∘ L -> R ∘ L
----

그리고 실제로 여단위를 사용해 중간의 L ∘ R을 무너뜨릴 수 있습니다. ``μ``의 정확한 공식은 수평 합성으로 주어집니다.

[source,haskell]
----
μ = R ∘ ε ∘ L
----

모나드 법칙은 수반의 단위와 여단위가 만족하는 항등식과 교환 법칙에서 따라옵니다.

하스켈에서는 수반에서 파생된 모나드를 많이 보지 못하는데, 수반은 보통 두 카테고리를 포함하기 때문입니다. 하지만 지수 또는 함수 객체의 정의는 예외입니다. 여기 이 수반을 형성하는 두 엔도함자가 있습니다.

[source,haskell]
----
L z = z × s
R b = s ⇒ b
----

그들의 합성이 익숙한 상태 모나드라는 것을 알아차릴 것입니다.

[source,haskell]
----
R (L z) = s ⇒ (z × s)
----

하스켈에서 이 모나드를 전에 봤습니다.

[source,haskell]
----
newtype State s a = State (s -> (a, s))
----

수반을 하스켈로도 번역해 봅시다. 왼쪽 함자는 곱 함자입니다.

[source,haskell]
----
newtype Prod s a = Prod (a, s)
----

오른쪽 함자는 리더 함자입니다.

[source,haskell]
----
newtype Reader s a = Reader (s -> a)
----

그들은 수반을 형성합니다.

[source,haskell]
----
instance Adjunction (Prod s) (Reader s) where
  counit (Prod (Reader f, s)) = f s
  unit a = Reader (\s -> Prod (a, s))
----

곱 함자 뒤의 리더 함자 합성이 실제로 상태 함자와 동등하다는 것을 쉽게 납득할 수 있습니다.

[source,haskell]
----
newtype State s a = State (s -> (a, s))
----

예상대로, 수반의 단위는 상태 모나드의 ``return`` 함수와 동등합니다. 여단위는 인수에 작용하는 함수를 평가하여 작동합니다. 이것은 함수 ``runState``의 언커링된 버전으로 인식할 수 있습니다.

[source,haskell]
----
runState :: State s a -> s -> (a, s)
runState (State f) s = f s
----

(여단위에서 쌍에 작용하므로 언커링되었습니다.)

이제 상태 모나드에 대한 ``join``을 자연 변환 ``μ``의 성분으로 정의할 수 있습니다. 이를 위해 세 자연 변환의 수평 합성이 필요합니다.

[source,haskell]
----
μ = R ∘ ε ∘ L
----

즉, 여단위 ``ε``를 리더 함자의 한 레벨을 가로질러 몰래 넣어야 합니다. ``fmap``을 직접 호출할 수 없는데, 컴파일러가 리더 함자가 아니라 상태 함자용을 선택할 것이기 때문입니다. 하지만 리더 함자에 대한 ``fmap``은 왼쪽 함수 합성일 뿐이라는 것을 기억하세요. 그래서 함수 합성을 직접 사용하겠습니다.

먼저 ``State`` 데이터 생성자를 벗겨 상태 함자 내부의 함수를 노출해야 합니다. 이것은 ``runState``를 사용해 이루어집니다.

[source,haskell]
----
ssa :: State s (State s a)
runState ssa :: s -> (State s a, s)
----

그런 다음 여단위, 즉 ``uncurry runState``로 정의되는 것과 왼쪽 합성합니다. 마지막으로, ``State`` 데이터 생성자로 다시 감쌉니다.

[source,haskell]
----
join :: State s (State s a) -> State s a
join ssa = State (uncurry runState . runState ssa)
----

이것이 실제로 상태 모나드에 대한 ``join``의 구현입니다.

모든 수반이 모나드를 낳을 뿐만 아니라, 역도 참입니다. 모든 모나드는 두 수반 함자의 합성으로 인수분해될 수 있습니다. 하지만 그런 인수분해는 유일하지 않습니다.
