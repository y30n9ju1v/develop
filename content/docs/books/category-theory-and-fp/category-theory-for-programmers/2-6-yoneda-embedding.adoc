_link:../[전체 목차] · 이전: link:../2-5-the-yoneda-lemma/[요네다 보조정리 (The Yoneda Lemma)] · 다음: link:../3-1-its-all-about-morphisms/[모든 것은 모피즘에 관한 것이다 (It’s All About Morphisms)]_

'''
이전에 우리는 카테고리 ``C``에서 객체 ``a``를 고정하면 매핑 ``C(a, -)``가 ``C``에서 ``Set``으로 가는 (공변) 함자가 된다는 것을 보았습니다.

[source,haskell]
----
x -> C(a, x)
----

(공역이 *Set*인 이유는 홈 집합 ``C(a, x)``가 집합이기 때문입니다.) 우리는 이 매핑을 *홈 함자(hom-functor)*라고 부르며, 이전에 모피즘에 대한 작용도 정의한 바 있습니다.

이제 이 매핑에서 ``a``를 변화시켜 봅시다. 그러면 임의의 ``a``에 홈 함자 ``C(a, -)``를 할당하는 새로운 매핑을 얻게 됩니다.

[source,haskell]
----
a -> C(a, -)
----

이것은 카테고리 ``C``의 객체들을 함자로 매핑하는 것입니다. 함자는 함자 카테고리(자연 변환 섹션의 함자 카테고리 참조)의 객체입니다. ``C``에서 ``Set``으로 가는 함자 카테고리를 ``[C, Set]``으로 표기하겠습니다. 또한 홈 함자가 대표적인 *표현 가능 함자(representable functor)*라는 점도 기억하실 것입니다.

두 카테고리 사이에 객체 매핑이 존재할 때마다, 우리는 자연스럽게 그 매핑이 함자인지 묻게 됩니다. 다시 말해, 한 카테고리의 모피즘을 다른 카테고리의 모피즘으로 리프트할 수 있는지 확인하는 것입니다. *C*에서의 모피즘은 단순히 ``C(a, b)``의 원소이지만, 함자 카테고리 ``[C, Set]``에서의 모피즘은 자연 변환입니다. 따라서 우리는 모피즘을 자연 변환으로 매핑하는 방법을 찾아야 합니다.

모피즘 ``f \:: a -> b``에 해당하는 자연 변환을 찾을 수 있는지 살펴봅시다. 먼저 ``a``와 ``b``가 무엇에 매핑되는지 보겠습니다. 각각 두 함자 ``C(a, -)``와 ``C(b, -)``에 매핑됩니다. 따라서 우리는 이 두 함자 사이의 자연 변환이 필요합니다.

여기서 핵심 기법은 요네다 보조정리를 사용하는 것입니다.

[source,haskell]
----
[C, Set](C(a, -), F) ≅ F a
----

여기서 일반적인 함자 ``F``를 홈 함자 ``C(b, -)``로 바꿉니다. 그러면 다음을 얻습니다.

[source,haskell]
----
[C, Set](C(a, -), C(b, -)) ≅ C(b, a)
----

이것이 바로 우리가 찾던 두 홈 함자 사이의 자연 변환입니다. 다만 약간의 반전이 있습니다. 자연 변환과 모피즘(즉 ``C(b, a)``의 원소) 사이의 매핑이 "반대" 방향으로 진행된다는 것입니다. 하지만 괜찮습니다. 이는 우리가 다루는 함자가 반변 함자임을 의미할 뿐입니다.

사실 우리는 기대했던 것보다 훨씬 더 많은 것을 얻었습니다. *C*에서 ``[C, Set]``으로의 매핑은 단순한 반변 함자가 아니라 *완전 충실 함자(fully faithful functor)*입니다. 완전성과 충실성은 함자가 홈 집합을 어떻게 매핑하는지 설명하는 속성입니다.

*충실 함자(faithful functor)*는 홈 집합에 대해 단사 함수입니다. 즉, 서로 다른 모피즘을 서로 다른 모피즘에 매핑하며, 둘을 하나로 합치지 않습니다.

*완전 함자(full functor)*는 홈 집합에 대해 전사 함수입니다. 즉, 한 홈 집합을 다른 홈 집합 위로 완전히 대응시켜, 대상 홈 집합을 빠짐없이 덮습니다.

*완전 충실 함자* ``F``는 홈 집합에 대해 전단사 함수입니다. 즉, 두 집합의 모든 원소가 일대일로 대응됩니다. 원본 카테고리 *C*의 모든 객체 쌍 ``a``와 ``b``에 대해, ``C(a, b)``와 ``D(F a, F b)`` 사이에 전단사가 존재합니다. 여기서 *D*는 ``F``의 대상 카테고리이며, 우리의 경우 함자 카테고리 ``[C, Set]``입니다. 주의할 점은 이것이 ``F``가 객체 수준에서도 전단사임을 의미하지는 않는다는 것입니다. *D*에는 ``F``의 이미지에 포함되지 않는 객체가 있을 수 있으며, 그러한 객체들에 대한 홈 집합에 관해서는 아무것도 말할 수 없습니다.

== 매장 (The Embedding)

방금 설명한 (반변) 함자, 즉 ``C``의 객체를 ``[C, Set]``의 함자로 대응시키는 매핑은 다음과 같이 표현됩니다.

[source,haskell]
----
a -> C(a, -)
----

이것이 바로 *요네다 매장(Yoneda embedding)*을 정의합니다. 요네다 매장은 카테고리 *C*(엄밀히 말하면 반변성 때문에 C<sup>op</sup>)를 함자 카테고리 ``[C, Set]`` 내부에 심습니다. 이는 *C*의 객체를 함자로 매핑할 뿐만 아니라, 그들 사이의 모든 연결 관계, 즉 모피즘을 충실하게 보존합니다.

이는 매우 유용한 결과입니다. 수학자들은 공역이 *Set*인 함자 카테고리에 대해 많은 것을 알고 있기 때문입니다. 임의의 카테고리 *C*를 함자 카테고리에 매장함으로써, 해당 카테고리에 대한 깊은 통찰을 얻을 수 있습니다.

물론 요네다 매장의 쌍대 버전도 있으며, 이를 *코-요네다 매장(co-Yoneda embedding)*이라고 부릅니다. 홈 집합에서 출발 객체 대신 도착 객체를 고정하여 ``C(-, a)``에서 시작할 수도 있습니다. 그러면 반변 홈 함자를 얻게 됩니다. *C*에서 *Set*으로 가는 반변 함자는 우리에게 익숙한 *프리시프(presheaf)*입니다(극한과 코리미트 참조). 코-요네다 매장은 카테고리 *C*를 프리시프 카테고리에 매장하는 것을 정의하며, 모피즘에 대한 작용은 다음과 같습니다.

[source,haskell]
----
[C, Set](C(-, a), C(-, b)) ≅ C(a, b)
----

마찬가지로 프리시프 카테고리는 수학적으로 잘 알려진 영역이므로, 임의의 카테고리를 그 안에 매장할 수 있다는 점은 큰 이득입니다.

== 하스켈에 대한 응용

하스켈에서 요네다 매장은 리더 함자들 사이의 자연 변환과 반대 방향으로 가는 함수 사이의 동형 모피즘으로 표현할 수 있습니다.

[source,haskell]
----
forall x. (a -> x) -> (b -> x) ≅ b -> a
----

(리더 함자는 ``((->) a)``와 동등하다는 점을 기억하세요.)

위 식의 왼쪽은 ``a -> x`` 함수와 ``b`` 타입의 값을 받아 ``x`` 타입의 값을 생성하는 다형성 함수입니다(여기서는 ``b -> x`` 주변의 괄호를 없애는 언커링을 적용했습니다). 이것이 모든 ``x``에 대해 가능하려면, 이 함수는 ``b``를 ``a``로 변환하는 방법을 알고 있어야 합니다. 즉, 내부적으로 ``b -> a`` 함수에 접근할 수 있어야 합니다.

그러한 변환 함수 ``btoa``가 주어지면, 식의 왼쪽(이를 ``fromY``라고 부릅시다)을 다음과 같이 정의할 수 있습니다.

[source,haskell]
----
fromY :: (a -> x) -> b -> x
fromY f b = f (btoa b)
----

반대로 ``fromY`` 함수가 주어지면, ``fromY``에 항등 함수를 넘겨 호출함으로써 변환 함수를 복구할 수 있습니다.

[source,haskell]
----
fromY id :: b -> a
----

이를 통해 ``fromY`` 타입의 함수와 ``btoa`` 사이의 전단사가 성립함을 알 수 있습니다.

이 동형 모피즘을 바라보는 또 다른 관점은, 이것을 ``b``에서 ``a``로 가는 함수의 *CPS 인코딩*(Continuation Passing Style)으로 보는 것입니다. 인자 ``a -> x``는 계속(continuation), 즉 핸들러입니다. 결과는 ``b -> x`` 함수이며, 이 함수를 ``b`` 타입의 값으로 호출하면 인코딩된 함수가 계속과 미리 합성되어 실행됩니다.

또한 요네다 매장은 하스켈의 일부 데이터 구조에 대한 대안적인 표현 방식을 설명해 줍니다. 특히 ``Control.Lens`` 라이브러리의 렌즈(lens)를 구현할 때 매우 유용한 표현 방식을 제공합니다.

== 원순서 예제 (Preorder Example)

이 예제는 로버트 하퍼(Robert Harper)가 제안했습니다. 요네다 매장을 *원순서(preorder)*로 정의된 카테고리에 적용한 사례입니다. 원순서는 원소들 사이에 순서 관계가 있는 집합으로, 전통적으로 ``<=``(작거나 같음)로 표기합니다. "원(pre)"이라는 접두사가 붙은 이유는 이 관계가 추이적이고 반사적이어야 하지만 반대칭적일 필요는 없기 때문입니다(따라서 순환이 존재할 수 있습니다).

원순서 관계를 가진 집합은 카테고리를 형성합니다. 객체는 집합의 원소들입니다. 객체 ``a``에서 ``b``로 가는 모피즘은, 두 객체를 비교할 수 없거나 ``a <= b``가 거짓인 경우에는 존재하지 않습니다. 반면 ``a <= b``가 참이면 존재하며, ``a``에서 ``b``를 가리킵니다. 한 객체에서 다른 객체로 가는 모피즘은 최대 하나뿐입니다. 따라서 이런 카테고리의 모든 홈 집합은 공집합이거나 단일 원소 집합입니다. 이러한 카테고리를 *야윈(thin) 카테고리*라고 부릅니다.

이 구조가 실제로 카테고리임을 확인하기는 쉽습니다. ``a <= b``이고 ``b <= c``이면 ``a <= c``이므로 화살표는 합성 가능하며, 합성은 결합법칙을 만족합니다. 또한 모든 원소는 자기 자신보다 작거나 같으므로(반사성), 항등 화살표도 존재합니다.

이제 원순서 카테고리에 코-요네다 매장을 적용해 봅시다. 특히 모피즘에 대한 작용에 주목하겠습니다.

[source,haskell]
----
[C, Set](C(-, a), C(-, b)) ≅ C(a, b)
----

오른쪽의 홈 집합은 ``a <= b``인 경우에만 비어 있지 않으며, 그 경우 단일 원소 집합이 됩니다. 결과적으로 ``a <= b``이면 왼쪽에도 단일한 자연 변환이 존재하게 됩니다. 그렇지 않으면 자연 변환은 존재하지 않습니다.

그렇다면 원순서에서 홈 함자 사이의 자연 변환은 구체적으로 무엇일까요? 집합 ``C(-, a)``와 ``C(-, b)`` 사이의 함수들의 패밀리여야 합니다. 원순서에서 이 집합들은 각각 공집합이거나 단원소 집합입니다. 우리가 사용할 수 있는 함수의 종류를 살펴봅시다.

공집합에서 공집합으로 가는 함수(공집합에 작용하는 항등 함수), 공집합에서 단원소 집합으로 가는 ``absurd`` 함수(공집합의 원소가 없으므로 아무 일도 하지 않음), 단원소 집합에서 단원소 집합으로 가는 함수(항등 함수)가 있습니다. 유일하게 금지된 조합은 단원소 집합에서 공집합으로 가는 매핑입니다. 그 단 하나의 원소를 어디로 보내야 할지 정의할 수 없기 때문입니다.

따라서 우리의 자연 변환은 결코 단원소 홈 집합을 빈 홈 집합으로 연결하지 않습니다. 다시 말해, ``x <= a``(즉 ``C(x, a)``가 단원소 집합)라면 ``C(x, b)``는 비어 있을 수 없습니다. ``C(x, b)``가 비어 있지 않다는 것은 ``x <= b``임을 의미합니다. 결국 자연 변환이 존재하려면, 모든 ``x``에 대해 ``x <= a``이면 ``x <= b``여야 합니다.

[source,haskell]
----
모든 x에 대하여, x ≤ a ⇒ x ≤ b
----

반면 코-요네다에 따르면 이 자연 변환의 존재는 ``C(a, b)``가 비어 있지 않음, 즉 ``a <= b``와 동치입니다. 이를 종합하면 다음과 같은 결론을 얻습니다.

[source,haskell]
----
a ≤ b 이면 그리고 그때에만 (if and only if), 모든 x에 대하여 x ≤ a ⇒ x ≤ b
----

이 결과는 직접 유도할 수도 있었습니다. 직관적으로 생각하면, ``a <= b``라면 ``a``보다 작은 모든 원소는 ``b``보다도 작아야 합니다. 반대로 오른쪽 조건에서 ``x``를 ``a``로 치환하면 ``a <= b``가 따라 나옵니다. 하지만 이 결과를 요네다 매장을 통해 이끌어내는 과정이 훨씬 더 흥미진진하다는 점은 인정하실 것입니다.

== 자연성 (Naturality)

요네다 보조정리는 자연 변환의 집합과 *Set*의 어떤 객체 사이의 동형 모피즘을 확립합니다. 자연 변환은 함자 카테고리 ``[C, Set]``의 모피즘이며, 두 함자 사이의 자연 변환 집합은 해당 카테고리의 홈 집합입니다. 요네다 보조정리는 다음의 동형 모피즘을 제시합니다.

[source,haskell]
----
[C, Set](C(a, -), F) ≅ F a
----

이 동형 모피즘은 ``F``와 ``a`` 모두에 대해 자연적입니다. 다시 말해, 곱 카테고리 ``[C, Set] × C``에서 가져온 쌍 ``(F, a)``에 대해 자연적입니다. 여기서 우리는 ``F``를 함자 카테고리의 객체로 취급하고 있다는 점에 주목하세요.

이것이 무엇을 의미하는지 잠시 생각해 봅시다. *자연 동형 모피즘*은 두 함자 사이의 가역적인 자연 변환입니다. 실제로 우리 동형 모피즘의 오른쪽은 함자입니다. ``[C, Set] × C``에서 *Set*으로 가는 함자로, 쌍 ``(F, a)``에 작용하면 집합을 내놓습니다. 그 작용은 함자 ``F``를 객체 ``a``에서 평가한 결과입니다. 이를 *평가 함자*라고 부릅니다.

왼쪽 또한 ``(F, a)``를 자연 변환의 집합 ``C, Set, F)``으로 매핑하는 함자입니다.

이들이 실제로 함자임을 보이려면 모피즘에 대한 작용도 정의해야 합니다. 쌍 ``(F, a)``와 ``(G, b)`` 사이의 모피즘은 무엇일까요? 모피즘의 쌍 ``(Φ, f)``입니다. 여기서 ``Φ``는 함자들 사이의 모피즘, 즉 자연 변환이고, ``f``는 *C*의 일반적인 모피즘입니다.

평가 함자는 이 쌍 ``(Φ, f)``를 받아 두 집합 ``F a``와 ``G b`` 사이의 함수로 매핑합니다. 이 함수는 ``a``에서의 ``Φ``의 성분(``F a``를 ``G a``로 매핑)과 함자 ``G``에 의해 리프트된 모피즘 ``f``를 사용하여 쉽게 구성할 수 있습니다.

[source,haskell]
----
(G f) ∘ Φa
----

참고로 ``Φ``의 자연성에 의해, 이는 다음과도 같습니다.

[source,haskell]
----
Φb ∘ (F f)
----

동형 모피즘 전체의 자연성은 여기서 증명하지 않겠습니다. 어떤 함자들이 관여하는지 확립하고 나면 증명은 상당히 기계적이기 때문입니다. 이 동형 모피즘이 함자와 자연 변환들로 구성되었다는 사실로부터 자연성이 따라 나옵니다. 논리적으로 틀릴 여지가 전혀 없습니다.
