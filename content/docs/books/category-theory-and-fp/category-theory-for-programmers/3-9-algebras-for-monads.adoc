'''
엔도함자를 표현식을 정의하는 방식으로 해석한다면, 대수(algebra)는 표현식을 평가할 수 있게 해주고 모나드(monad)는 표현식을 형성하고 조작할 수 있게 해줍니다. 대수와 모나드를 결합하면 많은 기능을 얻을 수 있을 뿐만 아니라 몇 가지 흥미로운 질문에도 답할 수 있습니다. 그중 하나가 바로 모나드와 수반(adjunction) 사이의 관계입니다. 우리가 이미 보았듯이, 모든 수반은 모나드(및 코모나드)를 정의합니다. 그렇다면 반대로 "모든 모나드(또는 코모나드)는 수반으로부터 유도될 수 있을까?"라는 질문을 던질 수 있습니다. 답은 "그렇다"입니다. 주어진 모나드를 생성하는 수반은 수없이 많으며(가족을 이룰 정도로 많습니다), 그중 두 가지 대표적인 수반을 소개해 드리겠습니다.

정의를 다시 살펴보겠습니다. 모나드 ``m``은 일정한 코히어런스(coherence) 조건을 만족하는 두 자연 변환(natural transformation)을 갖춘 엔도함자입니다. 이 자연 변환의 ``a``에서의 성분(component)은 다음과 같습니다.

[source,haskell]
----
ηa :: a -> m a
μa :: m (m a) -> m a
----

동일한 엔도함자에 대한 대수는 특정 객체인 운반자(carrier) ``a``의 선택과 다음 모피즘으로 구성됩니다.

[source,haskell]
----
alg :: m a -> a
----

가장 먼저 주목할 점은 대수가 ``ηa``와는 반대 방향으로 간다는 사실입니다. 직관적으로 ``ηa``는 타입 ``a``의 값에서 자명한(trivial) 표현식을 생성합니다. 대수를 모나드와 호환되게 만드는 첫 번째 코히어런스 조건은, 운반자가 ``a``인 대수를 사용하여 이 표현식을 평가하면 원래 값이 그대로 돌아온다는 것을 보장합니다.

[source,haskell]
----
alg ∘ ηa = ida
----

두 번째 조건은 이중으로 중첩된 표현식 ``m (m a)``를 평가하는 방법이 두 가지 있다는 사실에서 비롯됩니다. 먼저 ``μa``를 적용하여 표현식을 평탄화(flatten)한 다음 대수의 평가 함수를 사용할 수 있습니다. 또는 리프팅된 평가 함수를 적용하여 내부 표현식들을 먼저 평가한 다음, 그 결과에 다시 평가 함수를 적용할 수도 있습니다. 이 두 전략이 동등해야 합니다.

[source,haskell]
----
alg ∘ μa = alg ∘ m alg
----

[source,text]
----
  [ T-대수 (T-Algebra, (a, alg)) 의 코히어런스 가환 다이어그램 ]

  1. 단위 법칙 (Unit Law):
          a ════════ id_a ════════> a
          │                         ^
     η_a  │                         │ alg
          v                         │
         T a ───────────────────────╯
         (alg ∘ η_a = id_a)

  2. 결합 법칙 (Associativity):
         T (T a) ────── T alg ──────> T a
            │                          │
        μ_a │                          │ alg
            v                          v
           T a ───────── alg ─────────> a
         (alg ∘ μ_a = alg ∘ T alg)
----

여기서 ``m alg``는 함자 ``m``을 사용하여 ``alg``를 리프팅한 결과인 모피즘입니다. 다음 가환 다이어그램(commuting diagram)은 이 두 조건을 설명합니다(이후의 내용을 고려하여 ``m``을 ``T``로 바꿨습니다).

이 조건들을 하스켈로 표현하면 다음과 같습니다.

[source,haskell]
----
alg . return = id
alg . join = alg . fmap alg
----

간단한 예시를 살펴보겠습니다. 리스트 엔도함자에 대한 대수는 어떤 타입 ``a``와, ``a``의 리스트로부터 ``a``를 생성하는 함수로 구성됩니다. 이 함수를 ``foldr``을 사용하여 표현할 수 있는데, 요소 타입과 어큐뮬레이터(accumulator) 타입을 모두 ``a``로 선택하면 됩니다.

[source,haskell]
----
foldr :: (a -> a -> a) -> a -> [a] -> a
----

이 특정 대수는 인수가 두 개인 함수(이를 ``f``라고 합시다)와 초기값 ``z``로 지정됩니다. 리스트 함자는 모나드이기도 하며, ``return``은 값을 단일 원소 리스트(singleton list)로 만듭니다. ``return`` 이후에 대수(여기서는 ``foldr f z``)를 합성하면 ``x``는 다음과 같이 변환됩니다.

[source,haskell]
----
foldr f z [x] = x `f` z
----

여기서 ``f``의 작용은 중위 표기법(infix notation)으로 썼습니다. 대수가 모나드와 호환되려면 모든 ``x``에 대해 다음 코히어런스 조건이 만족되어야 합니다.

[source,haskell]
----
x `f` z = x
----

``f``를 이항 연산자로 생각하면, 이 조건은 ``z``가 우단위(right unit)라는 것을 알려줍니다.

두 번째 코히어런스 조건은 리스트의 리스트에 대해 작동합니다. ``join``의 작용은 개별 리스트들을 하나로 연결(concatenate)합니다. 그 다음 결과 리스트를 접을 수 있습니다. 반면에, 개별 리스트들을 먼저 접고 나서 그 결과들을 다시 접을 수도 있습니다. 다시 ``f``를 이항 연산자로 해석하면, 이 조건은 이 이항 연산이 결합 법칙(associative)을 만족해야 함을 알려줍니다. 이러한 조건들은 ``(a, f, z)``가 모노이드(monoid)일 때 확실히 충족됩니다.

수학자들은 모나드를 주로 stem:[T]라고 부르므로, 이와 호환되는 대수를 *T-대수(stem:[T]-algebras)*라고 부릅니다. 카테고리 stem:[C]의 어떤 모나드 stem:[T]에 대한 stem:[T]-대수들은 *아일렌베르크-무어(Eilenberg-Moore) 카테고리*라고 불리는 새로운 카테고리를 형성하며, 보통 stem:[C^T]로 표기합니다. 이 카테고리의 모피즘은 대수 간의 *준동형 모피즘(homomorphism)*입니다. 이 준동형 모피즘은 우리가 이전에 F-대수에서 보았던 정의와 동일합니다.

stem:[T]-대수는 운반자 객체와 평가 함수로 이루어진 쌍 stem:[(a, f)]입니다. stem:[C^T]에서 stem:[C]로 가는 당연한 *망각 함자(forgetful functor)* stem:[U^T]가 있는데, 이는 stem:[(a, f)]를 단순히 stem:[a]로 매핑합니다. 또한 stem:[T]-대수의 준동형 모피즘을 stem:[C]에서의 해당 운반자 객체 사이의 모피즘으로 매핑합니다. 수반에 대해 논의했던 때를 기억하신다면, 망각 함자의 좌수반(left adjoint)을 *자유 함자(free functor)*라고 부른다는 것을 기억하실 것입니다.

stem:[U^T]의 좌수반은 stem:[F^T]라고 부릅니다. 이는 stem:[C]의 객체 stem:[a]를 stem:[C^T]의 *자유 대수(free algebra)*로 매핑합니다. 이 자유 대수의 운반자는 stem:[T a]입니다. 평가 함수는 stem:[T (T a)]에서 stem:[T a]로 가는 모피즘이 필요한데, stem:[T]가 모나드이므로 모나드의 곱셈 stem:[\mu_a] (하스켈의 ``join``)를 평가 함수로 사용할 수 있습니다.

이것이 실제로 stem:[T]-대수임을 확인해봅시다. 그러려면 다음 두 코히어런스 조건을 만족해야 합니다.

[source,haskell]
----
alg ∘ ηTa = idTa
----

[source,haskell]
----
alg ∘ μa = alg ∘ T alg
----

하지만 대수 ``alg`` 자리에 stem:[\mu]를 대입하면, 이는 단지 모나드 법칙이 될 뿐입니다.

앞서 보았듯이 모든 수반은 모나드를 정의합니다. 그런데 stem:[F^T]와 stem:[U^T] 사이의 이 수반이 정의하는 모나드가 바로 아일렌베르크-무어 카테고리를 구성하는 데 사용한 그 모나드 stem:[T]라는 사실이 밝혀집니다. 이 구성은 모든 모나드에 대해 가능하므로, *모든 모나드는 수반으로부터 생성될 수 있다*는 결론을 얻게 됩니다. 나중에 동일한 모나드를 생성하는 또 다른 수반도 보여드리겠습니다.

계획은 다음과 같습니다. 먼저 stem:[F^T]가 실제로 stem:[U^T]의 좌수반임을 보이겠습니다. 이를 위해 이 수반의 단위(unit)와 코단위(counit)를 정의하고, 해당 삼각형 항등식(triangular identity)이 만족됨을 증명하겠습니다. 그 다음 이 수반으로 생성된 모나드가 원래의 모나드 stem:[T]임을 확인하겠습니다.

수반의 단위는 다음과 같은 자연 변환입니다.

[source,haskell]
----
η :: I -> UT ∘ FT
----

이 자연 변환의 stem:[a] 성분을 계산해봅시다. 항등 함자 stem:[I]는 stem:[a]를 주고, 자유 함자 stem:[F^T]는 자유 대수 stem:[(T a, \mu_a)]를 생성하며, 망각 함자 stem:[U^T]는 이를 다시 stem:[T a]로 되돌립니다. 결과적으로 stem:[a]에서 stem:[T a]로의 매핑이 생기는데, 우리는 단순히 모나드 stem:[T]의 단위를 이 수반의 단위로 사용할 것입니다.

이제 코단위를 살펴봅시다.

[source,haskell]
----
ε :: FT ∘ UT -> I
----

어떤 stem:[T]-대수 stem:[(a, f)]에서의 성분을 계산해봅시다. 망각 함자는 stem:[f]를 버리고 stem:[a]만 남기며, 자유 함자는 이로부터 쌍 stem:[(T a, \mu_a)]를 생성합니다. 따라서 stem:[(a, f)]에서의 코단위 stem:[\varepsilon]의 성분을 정의하려면, 아일렌베르크-무어 카테고리의 적절한 모피즘, 즉 stem:[T]-대수의 준동형 모피즘이 필요합니다.

[source,haskell]
----
(T a, μa) -> (a, f)
----

이 준동형 모피즘은 운반자 stem:[T a]를 stem:[a]로 매핑해야 합니다. 아까 잊어버렸던 평가 함수 stem:[f]를 다시 불러와 봅시다. 이번에는 stem:[f]를 stem:[T]-대수의 준동형 모피즘으로 사용하겠습니다. 실제로 stem:[f]가 stem:[T]-대수임을 보이는 가환 다이어그램을 다시 해석하면, 그것이 곧 stem:[T]-대수의 준동형 모피즘임을 보이는 다이어그램이 됩니다.

이렇게 하여 stem:[T]-대수 stem:[(a, f)]에서의 코단위 자연 변환 stem:[\varepsilon]의 성분을 stem:[f]로 정의했습니다.

수반을 완성하려면 단위와 코단위가 삼각형 항등식을 만족함을 보여야 합니다.

첫 번째 항등식은 모나드 stem:[T]의 단위 법칙 덕분에 성립합니다. 두 번째는 단순히 stem:[T]-대수 stem:[(a, f)]의 정의 그 자체입니다.

이제 두 함자가 다음 수반 관계를 형성함을 확립했습니다.

[source,haskell]
----
FT ⊣ UT
----

모든 수반은 모나드를 생성합니다. 다음과 같은 왕복 모피즘

[source,haskell]
----
UT ∘ FT
----

은 해당 모나드를 구성하는 stem:[C] 상의 엔도함자입니다. 객체 stem:[a]에 어떻게 작용하는지 볼까요? stem:[F^T]가 생성한 자유 대수는 stem:[(T a, \mu_a)]이고, 망각 함자 stem:[U^T]는 평가 함수를 떼어내고 운반자 stem:[T a]만 남깁니다. 따라서 예상대로 다음이 성립합니다.

[source,haskell]
----
UT ∘ FT = T
----

마찬가지로 수반의 단위는 모나드 stem:[T]의 단위가 됩니다.

수반의 코단위가 다음 공식을 통해 모나드 곱셈을 생성한다는 점을 기억하실 것입니다.

[source,haskell]
----
μ = R ∘ ε ∘ L
----

이는 세 자연 변환의 수평 합성입니다. 그중 둘은 각각 stem:[L]을 stem:[L]로, stem:[R]을 stem:[R]로 매핑하는 항등 자연 변환입니다. 가운데 있는 것이 코단위 stem:[\varepsilon]인데, 이는 대수 stem:[(a, f)]에서 성분 stem:[f]를 갖는 자연 변환입니다.

성분 stem:[\mu_a]를 계산해봅시다. 먼저 stem:[F^T] 뒤에 stem:[\varepsilon]를 수평 합성하면, stem:[F^T a]에서의 stem:[\varepsilon] 성분이 나옵니다. stem:[F^T]는 stem:[a]를 대수 stem:[(T a, \mu_a)]로 보내고, stem:[\varepsilon]는 평가 함수를 선택하므로 결국 stem:[\mu_a]를 얻습니다. 왼쪽에서 stem:[U^T]를 수평 합성해도 아무것도 바뀌지 않는데, 모피즘에 대한 stem:[U^T]의 작용이 자명하기 때문입니다. 따라서 수반에서 얻은 stem:[\mu]는 원래 모나드 stem:[T]의 stem:[\mu]와 정확히 같습니다.

*클라이슬리 카테고리*는 이미 본 적이 있습니다. 이는 카테고리 stem:[C]와 모나드 stem:[T]로부터 구성되는 카테고리로, stem:[C_T]라고 표기하겠습니다. 클라이슬리 카테고리 stem:[C_T]의 객체는 stem:[C]의 객체와 동일하지만, 모피즘은 다릅니다. stem:[C_T]에서 stem:[a]에서 stem:[b]로 가는 모피즘 stem:[f_K]는, 원래 카테고리 stem:[C]에서 stem:[a]에서 stem:[T b]로 가는 모피즘 stem:[f]에 대응합니다. 이 모피즘 stem:[f]를 stem:[a]에서 stem:[b]로 가는 *클라이슬리 화살표*라고 부릅니다.

클라이슬리 카테고리에서의 모피즘 합성은 클라이슬리 화살표의 모나드 합성을 통해 정의됩니다. 예를 들어 stem:[f_K]와 stem:[g_K]를 합성해봅시다. 클라이슬리 카테고리에서는 다음과 같이 나타납니다.

[source,haskell]
----
fK :: a -> b
gK :: b -> c
----

이는 카테고리 stem:[C]에서 다음과 같은 화살표들에 대응합니다.

[source,haskell]
----
f :: a -> T b
g :: b -> T c
----

이들의 합성 stem:[h_K = g_K \circ f_K]는 stem:[C]에서의 다음과 같은 클라이슬리 화살표 stem:[h]로 정의됩니다.

[source,haskell]
----
h :: a -> T c
h = μ ∘ (T g) ∘ f
----

하스켈에서는 이 합성을 다음과 같이 쓸 수 있습니다.

[source,haskell]
----
h = join . fmap g . f
----

stem:[C]에서 stem:[C_T]로 가는 함자 stem:[F]가 있습니다. 이 함자는 객체에 대해서는 자명하게 작용합니다. 모피즘에 대해서는 stem:[C]의 stem:[f]를 stem:[C_T]의 모피즘으로 매핑하는데, stem:[f]의 반환 값을 장식하는 클라이슬리 화살표를 생성합니다. 즉, 모피즘 stem:[f \:: a \to b]가 주어지면 다음 클라이슬리 화살표에 대응하는 stem:[C_T]의 모피즘을 만듭니다.

[source,haskell]
----
η ∘ f
----

하스켈로는 ``return . f``라고 쓸 수 있습니다.

stem:[C_T]에서 stem:[C]로 돌아가는 함자 stem:[G]도 정의할 수 있습니다. 이는 클라이슬리 카테고리의 객체 stem:[a]를 stem:[C]의 객체 stem:[T a]로 매핑합니다. 클라이슬리 화살표에 대응하는 모피즘 stem:[f_K]에 대해서는 다음과 같은 stem:[C]의 모피즘을 생성합니다.

[source,haskell]
----
T a -> T b
----

이 모피즘은 먼저 stem:[f]를 리프팅한 다음 stem:[\mu]를 적용하여 얻습니다.

[source,haskell]
----
μb ∘ T f
----

하스켈 표기법으로는 다음과 같습니다.

[source,haskell]
----
G fT = join . fmap f
----

익숙한 분들이라면 이것이 바로 ``join``을 이용한 *모나드 바인드(bind)*의 정의임을 알아채셨을 것입니다.

이 두 함자 stem:[F, G] 역시 다음과 같은 수반 관계를 형성함을 쉽게 알 수 있습니다.

[source,haskell]
----
F ⊣ G
----

그리고 이들의 합성 stem:[G \circ F]는 다시 원래의 모나드 stem:[T]를 만들어냅니다.

따라서 이것이 동일한 모나드를 생성하는 두 번째 수반입니다. 사실 stem:[C] 위에서 동일한 모나드 stem:[T]를 만들어내는 수반들의 전체 카테고리 stem:[Adj(C, T)]가 존재합니다. 우리가 방금 본 클라이슬리 수반은 이 카테고리의 *초기 객체*이고, 아일렌베르크-무어 수반은 *종단 객체*입니다.

모든 코모나드 stem:[W]에 대해서도 유사한 구성이 가능합니다. 코모나드와 호환되는 *코대수(coalgebra)*들의 카테고리를 정의할 수 있으며, 이들은 다음 다이어그램을 가환하게 만듭니다.

여기서 ``coa``는 운반자가 stem:[a]인 코대수의 *코평가 모피즘(coevaluation morphism)*입니다.

[source,haskell]
----
coa :: a -> W a
----

그리고 stem:[\varepsilon]와 stem:[\delta]는 코모나드를 정의하는 두 자연 변환입니다(하스켈에서는 이들의 성분을 각각 ``extract``와 ``duplicate``라고 부릅니다).

이러한 코대수들의 카테고리에서 stem:[C]로 가는 자명한 망각 함자 stem:[U^W]가 존재합니다. 이 함자는 코평가 모피즘을 잊어버립니다. 이 함자의 우수반 stem:[F^W]를 생각해봅시다.

[source,haskell]
----
UW ⊣ FW
----

망각 함자의 우수반을 *코자유 함자*라고 부릅니다. stem:[F^W]는 코자유 코대수를 생성합니다. stem:[C]의 객체 stem:[a]에 코대수 stem:[(W a, \delta_a)]를 할당하는 것이죠. 이 수반은 합성 stem:[U^W \circ F^W]를 통해 원래의 코모나드를 재생성합니다.

마찬가지로 코-클라이슬리 화살표를 이용해 *코-클라이슬리 카테고리(co-Kleisli category)*를 구성할 수 있으며, 해당 수반으로부터 코모나드를 다시 유도할 수 있습니다.

== 렌즈 (Lenses)

렌즈에 대한 논의로 다시 돌아가 봅시다. 렌즈는 ``Store s`` 함자에 대한 코대수로 표현될 수 있습니다.

[source,haskell]
----
coalgs :: a -> Store s a
----

여기서 ``Store s`` 함자는 다음과 같이 정의됩니다.

[source,haskell]
----
data Store s a = Store (s -> a) s
----

이 코대수는 두 함수의 쌍으로도 표현할 수 있습니다.

[source,haskell]
----
set :: a -> s -> a
get :: a -> s
----

(stem:[a]를 "전체(all)"로, stem:[s]를 그중 "작은 부분(small part)"으로 생각하면 됩니다.) 이 쌍으로 표현하면 다음과 같습니다.

[source,haskell]
----
coalgs a = Store (set a) (get a)
----

여기서 ``a``는 타입 ``a``인 어떤 값입니다. 부분 적용된 ``set a``는 ``s -> a`` 타입의 함수가 된다는 점에 주목하세요.

우리는 또한 ``Store s``가 코모나드라는 사실을 알고 있습니다.

[source,haskell]
----
instance Comonad (Store s) where
  extract (Store f s) = f s
  duplicate (Store f s) = Store (Store f) s
----

그렇다면 질문은 이것입니다. "어떤 조건에서 렌즈가 이 코모나드에 대한 코대수가 될 수 있을까?" 첫 번째 코히어런스 조건은 다음과 같습니다.

[source,haskell]
----
εa ∘ coalg = ida
----

이를 렌즈의 용어로 번역하면 다음과 같습니다.

[source,haskell]
----
set a (get a) = a
----

이는 구조체 ``a``의 필드를 원래 들어있던 값으로 다시 설정하면 아무런 변화도 일어나지 않아야 한다는 렌즈 법칙을 나타냅니다.

두 번째 조건은 조금 더 따져볼 게 많습니다.

[source,haskell]
----
fmap coalg ∘ coalg = δa ∘ coalg
----

먼저 ``Store`` 함자에 대한 ``fmap`` 정의를 떠올려봅시다.

[source,haskell]
----
fmap g (Store f s) = Store (g . f) s
----

``coalg``의 결과에 ``fmap coalg``를 적용하면 다음과 같은 결과를 얻습니다.

[source,haskell]
----
Store (coalg . set a) (get a)
----

반면 ``coalg``의 결과에 ``duplicate``를 적용하면 다음과 같습니다.

[source,haskell]
----
Store (Store (set a)) (get a)
----

이 두 식이 서로 같으려면 ``Store`` 내부의 두 함수가 임의의 ``s``에 대해 같은 값을 내놓아야 합니다.

[source,haskell]
----
coalg (set a s) = Store (set a) s
----

여기서 좌변의 ``coalg``를 다시 풀어 쓰면 다음과 같습니다.

[source,haskell]
----
Store (set (set a s)) (get (set a s)) = Store (set a) s
----

이 식은 나머지 두 렌즈 법칙과 동등합니다. 첫 번째 법칙은 다음과 같습니다.

[source,haskell]
----
set (set a s) = set a
----

필드의 값을 두 번 연속으로 설정하는 것은 한 번 설정하는 것과 같다는 법칙입니다. 두 번째 법칙은 다음과 같습니다.

[source,haskell]
----
get (set a s) = s
----

어떤 필드를 ``s``로 설정한 뒤 그 값을 다시 가져오면 당연히 ``s``가 나와야 한다는 법칙입니다.

결론적으로, 제대로 정의된(well-behaved) 렌즈는 사실 ``Store`` 함자에 대한 코모나드 코대수와 정확히 같은 개념입니다.
