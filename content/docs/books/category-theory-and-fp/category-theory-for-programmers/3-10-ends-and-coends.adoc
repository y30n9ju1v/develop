'''
카테고리에서 모피즘(morphism)에 대해 여러 직관을 가질 수 있지만, 객체 ``a``에서 객체 ``b``로 가는 모피즘이 존재한다면 두 객체가 어떤 방식으로든 "관련"되어 있다는 점에는 모두 동의할 것입니다. 어떤 면에서 모피즘은 이러한 관계에 대한 증거라고 볼 수 있습니다. 이는 모피즘이 곧 관계인 포셋(poset) 카테고리에서 극명하게 드러납니다. 일반적으로 두 객체 사이의 동일한 관계에 대해 여러 "증거"가 존재할 수 있는데, 이러한 증거들이 모여 우리가 *홈 집합(hom-set)*이라 부르는 집합을 형성합니다. 객체를 변화시키면 객체 쌍을 "증거" 집합으로 매핑하는 관계를 얻게 됩니다. 이 매핑은 함자적(functorial)이며, 첫 번째 인자에 대해서는 반변(contravariant)이고 두 번째 인자에 대해서는 공변(covariant)입니다. 이는 카테고리 내 객체들 사이의 전역적인 관계를 설정하는 것으로 볼 수 있으며, 이 관계는 *홈 함자(hom-functor)*로 설명됩니다.

[source,haskell]
----
C(-, =) :: Cop × C -> Set
----

일반적으로 이와 같은 모든 함자는 카테고리 객체들 사이의 관계를 설정하는 것으로 해석할 수 있습니다. 또한 이 관계는 서로 다른 두 카테고리 ``C``와 ``D``를 포함할 수도 있습니다. 이러한 관계를 설명하는 함자는 다음과 같은 시그니처를 가지며 *프로함자(profunctor)*라고 불립니다.

[source,haskell]
----
p :: Dop × C -> Set
----

수학자들은 이를 ``C``에서 ``D``로의 프로함자라고 부르며(순서가 반전됨에 유의하세요), 슬래시가 있는 화살표 기호를 사용합니다.

[source,haskell]
----
C ↛ D
----

프로함자는 ``C``의 객체와 ``D``의 객체 사이의 증거 관련 관계(proof-relevant relation)로 생각할 수 있습니다. 여기서 집합의 원소는 해당 관계의 증거를 상징합니다. ``p a b``가 공집합이라면 ``a``와 ``b`` 사이에는 관계가 없는 것입니다. 관계가 반드시 대칭적일 필요는 없다는 점을 기억하세요.

또 다른 유용한 직관은 엔도함자(endofunctor)가 '컨테이너'라는 아이디어를 일반화하는 것입니다. ``p a b`` 타입의 프로함자 값은 ``a`` 타입의 원소를 키로 사용하는 ``b``들의 컨테이너로 간주할 수 있습니다. 특히 홈 프로함자의 원소는 ``a``에서 ``b``로 가는 함수입니다.

하스켈에서 프로함자는 ``dimap``이라는 메서드를 가진 인자가 두 개인 타입 생성자 ``p``로 정의됩니다. 이 메서드는 두 함수 쌍을 리프트(lift)하는데, 첫 번째 함수는 "반대" 방향으로 진행됩니다.

[source,haskell]
----
class Profunctor p where
    dimap :: (c -> a) -> (b -> d) -> p a b -> p c d
----

프로함자의 함자성은 우리가 ``a``가 ``b``와 관련되어 있다는 증거를 가지고 있을 때, ``c``에서 ``a``로 가는 모피즘과 ``b``에서 ``d``로 가는 모피즘이 있다면 ``c``가 ``d``와 관련되어 있다는 증거 또한 얻을 수 있음을 알려줍니다. 또는 첫 번째 함수는 새로운 키를 이전 키로 변환하고, 두 번째 함수는 컨테이너의 내용을 수정하는 것으로 생각할 수도 있습니다.

단일 카테고리 내에서 작동하는 프로함자의 경우, 대각선 원소들인 ``p a a`` 타입에서 매우 풍부한 정보를 추출할 수 있습니다. ``b -> a``와 ``a -> c``라는 모피즘 쌍이 있다면 ``b``가 ``c``와 관련되어 있음을 증명할 수 있습니다. 더 나아가 단일 모피즘만으로도 비대각선(off-diagonal) 값에 도달할 수 있습니다. 예를 들어 모피즘 ``f \:: a -> b``가 있다면, 쌍 ``<f, id_b>``를 리프트하여 ``p b b``에서 ``p a b``로 이동할 수 있습니다.

[source,haskell]
----
dimap f id pbb :: p a b
----

또는 쌍 ``<id_a, f>``를 리프트하여 ``p a a``에서 ``p a b``로 이동할 수도 있습니다.

[source,haskell]
----
dimap id f paa :: p a b
----

== 동자연 변환 (Dinatural Transformations)

프로함자 역시 함자이므로 표준적인 방식으로 그들 사이의 자연 변환을 정의할 수 있습니다. 하지만 많은 경우 두 프로함자의 대각선 원소들 사이의 매핑을 정의하는 것만으로도 충분합니다. 이러한 변환을 *동자연 변환(dinatural transformation)*이라고 부르는데, 이는 대각선 원소를 비대각선 원소와 연결하는 두 가지 경로가 일치해야 한다는 가환 조건을 만족해야 합니다. 함자 카테고리 ``[C^op × C, Set]``에 속하는 두 프로함자 ``p``와 ``q`` 사이의 동자연 변환은 다음과 같은 모피즘족입니다.

[source,haskell]
----
α_a :: p a a -> q a a
----

이 모피즘족은 임의의 ``f \:: a -> b``에 대해 다음 다이어그램이 가환해야 합니다.

image::https://bartoszmilewski.files.wordpress.com/2017/03/dinatural.png[Dinatural Transformation]

이 조건은 자연성(naturality) 조건보다 훨씬 약하다는 점에 주목하세요. 만약 ``α``가 ``[C^op × C, Set]``에서의 자연 변환이었다면, 위 다이어그램은 두 개의 자연성 사각형과 하나의 함자성 조건(프로함자 ``q``가 합성을 보존함)으로부터 유도되었을 것입니다.

또한 ``[C^op × C, Set]``에서의 자연 변환 ``α``의 성분은 객체 쌍 ``α_a_b``로 인덱싱되는 반면, 동자연 변환은 각 프로함자의 대각 원소들만 매핑하므로 하나의 객체로 인덱싱된다는 점도 차이점입니다.

== 엔드 (Ends)

이제 "대수(algebra)"를 넘어 카테고리 이론의 "해석학(calculus)"이라 할 수 있는 영역으로 나아갈 준비가 되었습니다. 엔드(end)와 코엔드(coend)의 해석학은 전통적인 미적분학의 아이디어와 표기법을 차용합니다. 특히 코엔드는 무한 합 또는 적분으로, 엔드는 무한 곱으로 이해할 수 있습니다. 심지어 디랙 델타(Dirac delta) 함수와 유사한 개념도 존재합니다.

엔드는 함자를 프로함자로 대체한 극한(limit)의 일반화입니다. 원뿔(cone) 대신 *쐐기(wedge)*가 등장합니다. 쐐기의 밑변(base)은 프로함자 ``p``의 대각 원소들로 구성됩니다. 쐐기의 꼭짓점(apex)은 객체(여기서는 ``Set`` 값을 갖는 프로함자를 다루므로 집합)이고, 옆면(side)은 꼭짓점에서 밑변의 집합들로 가는 함수족입니다. 이 가족을 반환 타입에 대해 다형적인 하나의 다형 함수로 생각할 수 있습니다.

[source,haskell]
----
α :: forall a . apex -> p a a
----

원뿔과 달리 쐐기 내부에는 밑변을 형성하는 정점들을 직접 연결하는 함수가 없습니다. 하지만 앞에서 보았듯이 ``C``의 임의의 모피즘 ``f \:: a -> b``가 주어지면 ``p a a``와 ``p b b``를 공통 집합인 ``p a b``로 연결할 수 있습니다. 따라서 우리는 다음과 같은 다이어그램이 가환할 것을 요구합니다.

image::https://bartoszmilewski.files.wordpress.com/2017/03/wedge.png[Wedge Condition]

이를 *쐐기 조건(wedge condition)*이라 부릅니다. 수식으로는 다음과 같이 쓸 수 있습니다.

[source,haskell]
----
p id_a f ∘ α_a = p f id_b ∘ α_b
----

하스켈 표기법으로는 다음과 같습니다.

[source,haskell]
----
dimap id f . alpha = dimap f id . alpha
----

[source,text]
----
  [ 쐐기 조건 (Wedge Condition) 과 엔드 (End) 보편 다이어그램 ]

  1. 쐐기 (Wedge) 가환 조건:
                     apex
                    /    \
               α_a /      \ α_b
                  v        v
                p a a    p b b
                  │        │
      p id_a f    │        │ p f id_b
      (dimap id f)│        │ (dimap f id)
                  v        v
                    p a b
      * 가환 조건: dimap id f ∘ α_a = dimap f id ∘ α_b

  2. 보편 엔드 (Universal End, ∫_c p c c):
                     apex
                    / │  \
               α_a /  │   \ α_b
                  /   │h   \
                 v    v     v
               p a a <─ ∫_c p c c ─> p b b
                       (π_a, π_b)

  3. 닌자 요네다 보조정리 (Ninja Yoneda Lemma):
       • End 형태:   F a ≅ ∫_c (Set(a, c) -> F c)   (Haskell: forall c. (a -> c) -> F c ≅ F a)
       • Coend 형태: F a ≅ ∫^c (Set(c, a) × F c)    (Haskell: exists c. (c -> a, F c) ≅ F a)
----

이제 보편적 구성(universal construction)을 통해 ``p``의 *엔드*를 보편적인 쐐기로 정의할 수 있습니다. 즉, 어떤 집합 ``e``와 함수족 ``π``가 존재하여, 임의의 다른 쐐기(꼭짓점 ``a``, 함수족 ``α``)에 대해 모든 삼각형을 가환하게 만드는 유일한 함수 ``h \:: a -> e``가 존재하는 경우입니다.

[source,haskell]
----
π_a ∘ h = α_a
----

엔드의 기호는 적분 기호를 사용하며, "적분 변수"를 아래 첨자에 둡니다.

[source,haskell]
----
∫_c p c c
----

``π``의 성분들을 해당 엔드에 대한 *투영 맵(projection maps)*이라고 부릅니다.

[source,haskell]
----
π_a :: ∫_c p c c -> p a a
----

만약 ``C``가 이산 카테고리(항등 모피즘 외에 모피즘이 없음)라면, 엔드는 단순히 카테고리 ``C`` 전체에 걸친 ``p``의 모든 대각 성분들의 전역 곱(global product)이 됩니다. 더 일반적인 경우에도 등화자(equalizer)를 통해 엔드와 이 곱 사이의 관계를 설명할 수 있음을 곧 보여드리겠습니다.

하스켈에서 엔드 공식은 보편 한정자(universal quantifier)로 직접 번역됩니다.

[source,haskell]
----
forall a. p a a
----

엄밀히 말하면 이는 ``p``의 모든 대각 원소들의 곱일 뿐이지만, 쐐기 조건은 매개변수성(parametricity) 덕분에 자동으로 만족됩니다(이에 대해서는 별도의 글에서 설명하겠습니다). 임의의 함수 ``f \:: a -> b``에 대해 쐐기 조건은 다음과 같습니다.

[source,haskell]
----
dimap f id . pi = dimap id f . pi
----

타입 주석을 포함하면 다음과 같습니다.

[source,haskell]
----
dimap f id_b . pi_b = dimap id_a f . pi_a
----

여기서 방정식의 양변은 모두 다음 타입을 가집니다.

[source,haskell]
----
Profunctor p => (forall c. p c c) -> p a b
----

그리고 ``pi``는 다형 투영입니다.

[source,haskell]
----
pi :: Profunctor p => forall c. (forall a. p a a) -> p c c
pi e = e
----

여기서 타입 추론은 ``e``의 올바른 성분을 자동으로 선택해 줍니다.

원뿔에 대한 모든 가환 조건을 하나의 자연 변환으로 표현할 수 있었던 것처럼, 모든 쐐기 조건을 하나의 동자연 변환으로 묶을 수 있습니다. 이를 위해 상수 함자 ``Δ_c``를 상수 프로함자로 일반화해야 합니다. 이 상수 프로함자는 모든 객체 쌍을 단일 객체 ``c``로 매핑하고, 모든 모피즘 쌍을 해당 객체의 항등 모피즘으로 매핑합니다. 쐐기는 이 함자에서 프로함자 ``p``로의 동자연 변환입니다. 실제로 ``Δ_c``가 모든 모피즘을 단일 항등 함수로 리프트한다는 점을 생각하면, 동자연 육각형은 쐐기 다이아몬드로 축소됩니다.

엔드는 ``Set`` 이외의 대상 카테고리에 대해서도 정의될 수 있지만, 여기서는 ``Set`` 값을 갖는 프로함자와 그 엔드만 고려하겠습니다.

== 등화자로서의 엔드 (Ends as Equalizers)

엔드 정의의 가환 조건은 등화자를 사용하여 작성할 수 있습니다. 먼저 두 함수를 정의해 보겠습니다(수학적 표기법보다 하스켈 표기법이 더 이해하기 쉬우므로 이를 사용합니다). 이 함수들은 쐐기 조건의 두 수렴하는 경로에 대응합니다.

[source,haskell]
----
lambda :: Profunctor p => p a a -> (a -> b) -> p a b
lambda paa f = dimap id f paa

rho :: Profunctor p => p b b -> (a -> b) -> p a b
rho pbb f = dimap f id pbb
----

두 함수는 프로함자 ``p``의 대각 원소들을 다음과 같은 타입의 다형 함수들로 매핑합니다.

[source,haskell]
----
type ProdP p = forall a b. (a -> b) -> p a b
----

``lambda``와 ``rho``는 서로 다른 타입을 가지지만, 모든 대각 성분들을 모아 하나의 거대한 곱 타입을 만들면 타입을 통일할 수 있습니다.

[source,haskell]
----
newtype DiaProd p = DiaProd (forall a. p a a)
----

이제 ``lambda``와 ``rho``는 이 곱 타입으로부터의 두 매핑을 유도합니다.

[source,haskell]
----
lambdaP :: Profunctor p => DiaProd p -> ProdP p
lambdaP (DiaProd paa) = lambda paa

rhoP :: Profunctor p => DiaProd p -> ProdP p
rhoP (DiaProd paa) = rho paa
----

``p``의 엔드는 이 두 함수의 *등화자(equalizer)*입니다. 등화자는 두 함수가 일치하는 가장 큰 부분집합을 선택한다는 점을 기억하세요. 이 경우 쐐기 다이어그램이 가환하는 모든 대각 원소들의 곱 중 부분집합을 선택하게 됩니다.

== 엔드로서의 자연 변환 (Natural Transformations as Ends)

엔드의 가장 중요한 예시는 자연 변환의 집합입니다. 두 함자 ``F``와 ``G`` 사이의 자연 변환은 ``C(F a, G a)`` 형태의 홈 집합들에서 선택된 모피즘족입니다. 만약 자연성 조건이 없었다면 자연 변환의 집합은 단순히 이러한 홈 집합들의 곱이었을 것입니다. 실제로 하스켈에서는 다음과 같습니다.

[source,haskell]
----
forall a. f a -> g a
----

하스켈에서 이것이 가능한 이유는 자연성이 매개변수성으로부터 보장되기 때문입니다. 하지만 하스켈 밖에서는 이러한 홈 집합들을 가로지르는 모든 대각 단면(diagonal section)이 자연 변환이 되는 것은 아닙니다. 여기서 다음과 같은 매핑을 생각해 봅시다.

[source,haskell]
----
<a, b> -> C(F a, G b)
----

이 매핑은 프로함자이므로 이것의 엔드를 연구하는 것은 타당합니다. 이때 쐐기 조건은 다음과 같습니다.

image::https://bartoszmilewski.files.wordpress.com/2017/03/ntwedge.png[Natural Transformation Wedge]

집합 ``∫_c C(F c, G c)``에서 원소 하나를 골라 봅시다. 두 투영은 이 원소를 특정 변환의 두 성분으로 매핑할 것입니다. 이를 각각 다음과 같이 부릅시다.

[source,haskell]
----
τ_a :: F a -> G a
τ_b :: F b -> G b
----

왼쪽 경로에서는 홈 함자를 사용하여 모피즘 쌍 ``<id_a, G f>``를 리프트합니다. 이러한 리프팅은 전-합성(pre-composition)과 후-합성(post-composition)을 동시에 수행하는 것으로 구현됨을 기억하실 것입니다. ``τ_a``에 작용하면 리프트된 쌍은 다음을 제공합니다.

[source,haskell]
----
G f ∘ τ_a ∘ id_a
----

다이어그램의 다른 경로는 다음을 제공합니다.

[source,haskell]
----
id_b ∘ τ_b ∘ F f
----

쐐기 조건에 의해 요구되는 이 두 식의 등치성은 곧 ``τ``에 대한 자연성 조건과 정확히 일치합니다.

== 코엔드 (Coends)

예상하셨겠지만, 엔드의 쌍대(dual)는 *코엔드(coend)*라고 부릅니다. 이는 쐐기의 쌍대인 *코쐐기(cowedge)*로부터 구성됩니다.

image::https://bartoszmilewski.files.wordpress.com/2017/03/cowedge.png[Cowedge]

엣지 있는 소(An edgy cow)? (역주: cowedge의 발음이 '카우 에지'가 아니라 '코 웨지'라는 언어유희입니다.)

코엔드의 기호는 "적분 변수"가 위 첨자에 있는 적분 기호를 사용합니다.

[source,haskell]
----
∫^c p c c
----

엔드가 곱과 관련이 있듯이, 코엔드는 쌍대곱(coproduct) 또는 합(sum)과 관련이 있습니다. 이러한 면에서 코엔드는 합의 극한인 적분과 유사합니다. 코엔드에는 투영 대신 프로함자의 대각 원소들에서 코엔드로 향하는 *단사 모피즘(injection)*이 존재합니다. 만약 코쐐기 조건이 없다면 ``p``의 코엔드는 ``p a a``, ``p b b``, ``p c c`` 중 하나라고 말할 수 있을 것입니다. 또는 어떤 객체 ``a``가 존재하여 코엔드가 곧 집합 ``p a a``가 된다고 할 수도 있겠죠. 엔드 정의에서 사용한 보편 한정자는 코엔드에서 *존재 한정자(existential quantifier)*로 바뀝니다.

이것이 의사-하스켈(pseudo-Haskell)에서 코엔드를 다음과 같이 정의하는 이유입니다.

[source,haskell]
----
exists a. p a a
----

하스켈에서 존재 한정자를 인코딩하는 표준적인 방법은 보편적으로 한정된(universally quantified) 데이터 생성자를 사용하는 것입니다.

[source,haskell]
----
data Coend p = forall a. Coend (p a a)
----

이 정의 이면의 논리는 우리가 어떤 ``a``를 선택하더라도 타입군 ``p a a`` 중 하나의 값을 사용하여 코엔드를 구성할 수 있어야 한다는 것입니다.

엔드가 등화자를 통해 정의될 수 있듯이, 코엔드는 *공등화자(coequalizer)*를 통해 설명될 수 있습니다. 모든 코쐐기 조건은 가능한 모든 함수 ``b -> a``에 대해 ``p a b``의 거대한 쌍대곱을 취함으로써 요약될 수 있습니다. 하스켈에서 이는 다음과 같은 존재 타입으로 표현됩니다.

[source,haskell]
----
data SumP p = forall a b. SumP (b -> a) (p a b)
----

``dimap``을 사용하여 함수를 리프트하고 이를 프로함자 ``p``에 적용함으로써 이 합 타입을 평가하는 두 가지 방법이 있습니다.

[source,haskell]
----
lambda, rho :: Profunctor p => SumP p -> DiagSum p
lambda (SumP f pab) = DiagSum (dimap f id pab)
rho    (SumP f pab) = DiagSum (dimap id f pab)
----

여기서 ``DiagSum``은 ``p``의 대각 성분들의 합입니다.

[source,haskell]
----
data DiagSum p = forall a. DiagSum (p a a)
----

이 두 함수의 공등화자가 바로 코엔드입니다. 공등화자는 ``DiagSum p``에서, 동일한 인자에 대해 ``lambda``나 ``rho``를 적용하여 얻은 값들을 동일시(identification)함으로써 얻어집니다. 여기서 인수는 함수 ``b -> a``와 ``p a b`` 원소의 쌍입니다. ``lambda``와 ``rho``를 적용하면 ``DiagSum p`` 타입의 잠재적으로 서로 다른 두 값이 생성되는데, 코엔드에서는 이 두 값을 동일시하여 코쐐기 조건이 자동으로 만족되도록 합니다.

집합에서 관련 성분들을 동일시하는 과정은 공식적으로 *몫(quotient)*을 취한다고 합니다. 몫을 정의하려면 반사성, 대칭성, 전이성을 만족하는 동치 관계(equivalence relation) ``~``가 필요합니다.

[source,haskell]
----
a ~ a
a ~ b 이면 b ~ a
a ~ b 이고 b ~ c 이면 a ~ c
----

이러한 관계는 집합을 *동치류(equivalence class)*로 나눕니다. 각 클래스는 서로 관련된 원소들로 구성됩니다. 각 클래스에서 원소 하나를 대표로 선택하여 몫 집합을 형성합니다. 전형적인 예로 정수 쌍을 다음과 같은 동치 관계로 정의하여 유리수를 만드는 예가 있습니다.

[source,haskell]
----
(a, b) ~ (c, d) iff a * d = b * c
----

이것이 동치 관계임을 확인하는 것은 간단합니다. 쌍 ``(a, b)``를 분수 ``a/b``로 해석하고, 분자와 분모에 공약수가 있는 분수들을 동일시하는 것입니다. 유리수는 이러한 분수들의 동치류입니다.

이전의 극한과 쌍대극한에 대한 논의에서 홈 함자가 연속적임(즉, 극한을 보존함)을 기억하실 것입니다. 쌍대적으로 반변 홈 함자는 쌍대극한을 극한으로 바꿉니다. 이러한 속성은 각각 극한과 쌍대극한의 일반화인 엔드와 코엔드로도 확장됩니다. 특히 코엔드를 엔드로 변환하는 매우 유용한 항등식을 얻을 수 있습니다.

[source,haskell]
----
Set(∫^x p x x, c) ≅ ∫_x Set(p x x, c)
----

이를 의사-하스켈로 살펴보면 다음과 같습니다.

[source,haskell]
----
(exists x. p x x) -> c ≅ forall x. p x x -> c
----

이는 존재 타입을 인자로 받는 함수가 다형 함수와 동등함을 알려줍니다. 이는 매우 타당한데, 그러한 함수는 존재 타입 안에 인코딩될 수 있는 그 어떤 타입이라도 처리할 준비가 되어 있어야 하기 때문입니다. 이는 합 타입(sum type)을 받는 함수가 합 타입에 포함된 각 타입에 대응하는 핸들러 튜플을 가진 ``case`` 문으로 구현되어야 한다는 원칙과 같습니다. 여기서 합 타입은 코엔드로 대체되었고, 핸들러 가족은 엔드 또는 다형 함수가 되었습니다.

== 닌자 요네다 보조정리 (Ninja Yoneda Lemma)

요네다 보조정리에 등장하는 자연 변환 집합을 엔드를 사용하여 표현하면 다음과 같은 공식을 얻습니다.

[source,haskell]
----
∫_z Set(C(a, z), F z) ≅ F a
----

또한 다음과 같은 쌍대 공식도 존재합니다.

[source,haskell]
----
∫^z C(z, a) × F z ≅ F a
----

이 항등식은 ``a = z``에서 무한한 피크를 갖는 디랙 델타 함수(또는 분포) ``δ(a - z)``의 공식을 강력하게 연상시킵니다. 여기서는 홈 함자가 델타 함수의 역할을 수행합니다.

이 두 항등식을 합쳐서 종종 *닌자 요네다 보조정리(Ninja Yoneda lemma)*라고 부릅니다.

두 번째 공식을 증명하기 위해, 두 객체가 동형(isomorphic)인 것과 그들의 홈 함자가 동형인 것이 동치라는 요네다 임베딩의 결과를 사용하겠습니다. 즉, ``a ≅ b``는 다음 타입의 자연 변환이 동형 모피즘인 것과 동치입니다.

[source,haskell]
----
[C, Set](C(a, -), C(b, =))
----

증명하려는 항등식의 좌변을 임의의 객체 ``c``로 향하는 홈 함자 안에 넣어봅시다.

[source,haskell]
----
Set(∫^z C(z, a) × F z, c)
----

연속성 논증을 통해 코엔드를 엔드로 바꿀 수 있습니다.

[source,haskell]
----
∫_z Set(C(z, a) × F z, c)
----

이제 곱(product)과 지수(exponential) 사이의 수반(adjunction)을 활용합니다.

[source,haskell]
----
∫_z Set(C(z, a), c^(F z))
----

요네다 보조정리를 사용하여 "적분을 수행"하면 다음을 얻습니다.

[source,haskell]
----
c^(F a)
----

(``c^(F z)``가 ``z``에 대해 반변이므로 요네다 보조정리의 반변 버전을 사용했음에 유의하세요.)

이 지수 객체는 다음 홈 집합과 동형입니다.

[source,haskell]
----
Set(F a, c)
----

마지막으로 요네다 임베딩을 다시 활용하여 다음과 같은 동형에 도달합니다.

[source,haskell]
----
∫^z C(z, a) × F z ≅ F a
----

== 프로함자 합성 (Profunctor Composition)

프로함자가 관계를 설명한다는 아이디어를 더 깊이 탐구해 봅시다. 더 정확하게는 증거 관련 관계(proof-relevant relation)로서, 집합 ``p a b``는 ``a``가 ``b``와 관련되어 있다는 증거들의 집합을 나타냅니다. 두 관계 ``p``와 ``q``가 있다면 이들을 합성할 수 있습니다. ``q`` 다음에 ``p``가 오는 합성을 통해 ``a``가 ``b``와 관련되어 있다는 것은, ``q b c``와 ``p c a``가 모두 비어 있지 않게 만드는 중간 객체 ``c``가 존재함을 의미합니다. 이 새로운 관계의 증거는 개별 관계 증거들의 쌍입니다. 존재 한정자가 코엔드에 대응하고 두 집합의 데카르트 곱이 "증거 쌍"에 대응한다는 이해를 바탕으로, 프로함자 합성을 다음 공식으로 정의할 수 있습니다.

[source,haskell]
----
(q ∘ p) a b = ∫^c p c a × q b c
----

다음은 일부 이름을 변경한 ``Data.Profunctor.Composition``의 하스켈 정의입니다.

[source,haskell]
----
data Procompose q p a b where
  Procompose :: q a c -> p c b -> Procompose q p a b
----

이는 GADT(Generalized Algebraic Data Type) 구문을 사용하며, 여기서 자유 타입 변수 ``c``는 자동으로 존재 한정(existentially quantified)됩니다. 따라서 (비커리화된) 데이터 생성자 ``Procompose``는 다음과 동등합니다.

[source,haskell]
----
exists c. (q a c, p c b)
----

이렇게 정의된 합성의 단위원(unit)은 홈 함자입니다. 이는 닌자 요네다 보조정리에서 바로 도출됩니다. 따라서 프로함자가 모피즘 역할을 하는 카테고리가 존재하는지 묻는 것은 자연스럽습니다. 답은 긍정적입니다. 다만 프로함자 합성의 결합 법칙과 항등 법칙은 자연 동형(natural isomorphism) 하에서만 성립한다는 점을 주의해야 합니다. 법칙이 동형 모피즘 하에서만 유효한 이러한 카테고리를 *바이카테고리(bicategory)*라고 부릅니다. 이는 2-카테고리보다 더 일반적인 개념입니다. 그리하여 우리는 객체가 카테고리이고 모피즘이 프로함자이며, 모피즘 사이의 모피즘(2-셀)이 자연 변환인 바이카테고리 ``Prof``를 얻게 됩니다. 더 나아가 프로함자 외에도 일반 함자 또한 카테고리 사이의 모피즘으로 존재합니다. 두 종류의 모피즘을 가진 카테고리를 *이중 카테고리(double category)*라고 부릅니다.

프로함자는 하스켈의 ``lens`` 라이브러리와 ``arrow`` 라이브러리에서 매우 중요한 역할을 수행합니다.
