== 로그의 합성 (Composition of Logs)

타입과 순수 함수를 카테고리로 모델링하는 방법은 이미 봤습니다. 또한 카테고리 이론에서 부수 효과(side effect)를 가진 비순수 함수(non-pure function)를 모델링할 방법이 있다는 점도 언급했었죠. 그 예시 중 하나로, 실행 과정을 기록하거나 추적(trace)하는 함수를 살펴봅시다. 명령형 언어에서는 아마 다음처럼 전역 상태를 변경하는 방식으로 구현했을 겁니다.

[source,cpp]
----
string logger;

bool negate(bool b) {
     logger += "Not so! ";
     return !b;
}
----

이 함수는 순수 함수가 아닙니다. 메모이제이션(memoization)을 적용하면 로그가 남지 않기 때문입니다. 이 함수는 부수 효과를 가지고 있습니다.

현대 프로그래밍에서는 전역 가변 상태(global mutable state)를 최대한 피하려 합니다. 동시성(concurrency) 문제로 인한 복잡성 때문입니다. 또한 이런 코드를 라이브러리에 넣는 것도 절대 권장되지 않습니다.

다행히 이 함수를 순수하게 만들 수 있습니다. 로그를 입력과 출력에 명시적으로 전달하면 됩니다. 문자열 인자를 추가하고, 반환값으로 결과값과 업데이트된 로그를 묶은 쌍(pair)을 반환하도록 만듭니다.

[source,cpp]
----
pair<bool, string> negate(bool b, string logger) {
     return make_pair(!b, logger + "Not so! ");
}
----

이제 이 함수는 순수합니다. 부수 효과가 없고, 동일한 인자로 호출하면 항상 같은 쌍을 반환하므로 필요하면 메모이제이션도 적용할 수 있습니다. 하지만 로그가 누적되는 특성상, 특정 호출에 이르기까지의 모든 가능한 이력(history)을 메모화해야 한다는 문제가 있습니다. 다음 호출들에 대해 각각 별도의 메모 항목이 필요합니다.

[source,cpp]
----
negate(true, "It was the best of times. ");
----

그리고

[source,cpp]
----
negate(true, "It was the worst of times. ");
----

이런 식으로 말이죠.

라이브러리 함수 인터페이스로서도 그리 좋지 않습니다. 호출하는 쪽에서 반환된 문자열을 무시할 수는 있으니 큰 부담은 아니지만, 입력으로 매번 문자열을 전달해야 한다는 점은 번거롭습니다.

같은 작업을 더 깔끔하게, 관심사(concern)를 분리해서 처리할 수는 없을까요? 이 간단한 예제에서 ``negate`` 함수의 주요 목적은 불리언 값을 다른 값으로 바꾸는 것입니다. 로깅은 부차적입니다. 물론 로그 메시지 자체는 함수마다 다르지만, 메시지들을 하나의 연속된 로그로 취합하는 작업은 별개의 관심사입니다. 함수가 메시지 문자열은 계속 생성하되, 로그 전체를 관리하는 부담은 덜어주고 싶습니다. 절충안은 다음과 같습니다.

[source,cpp]
----
pair<bool, string> negate(bool b) {
     return make_pair(!b, "Not so! ");
}
----

핵심 아이디어는 로그를 함수 호출 사이에서 외부에서 취합한다는 것입니다.

이게 실제로 어떻게 작동하는지 보기 위해, 좀 더 현실적인 예제로 넘어가 봅시다. 문자열을 대문자로 변환하는 ``string``에서 ``string``으로 가는 함수가 있습니다.

[source,cpp]
----
string toUpper(string s) {
    string result;
    int (*toupperp)(int) = &toupper; // toupper는 오버로딩되어 있습니다
    transform(begin(s), end(s), back_inserter(result), toupperp);
    return result;
}
----

그리고 문자열을 공백 기준으로 나누어 문자열 벡터로 분리하는 또 다른 함수가 있습니다.

[source,cpp]
----
vector<string> toWords(string s) {
    return words(s);
}
----

실제 작업은 보조 함수 ``words``에서 수행됩니다.

[source,cpp]
----
vector<string> words(string s) {
    vector<string> result{""};
    for (auto i = begin(s); i != end(s); ++i)
    {
        if (isspace(*i))
            result.push_back("");
        else
            result.back() += *i;
    }
    return result;
}
----

``toUpper``와 ``toWords``가 일반적인 반환값과 함께 메시지 문자열을 함께 반환하도록 수정하고자 합니다.

이 함수들의 반환값을 "장식(embellish)"하겠습니다. 임의의 타입 ``A``와 문자열을 쌍으로 묶어주는 ``Writer`` 템플릿을 정의해서 일반적인 방식으로 처리해 봅시다.

[source,cpp]
----
template<class A>
using Writer = pair<A, string>;
----

장식된 함수들은 이제 다음과 같은 모습이 됩니다.

[source,cpp]
----
Writer<string> toUpper(string s) {
    string result;
    int (*toupperp)(int) = &toupper;
    transform(begin(s), end(s), back_inserter(result), toupperp);
    return make_pair(result, "toUpper ");
}

Writer<vector<string>> toWords(string s) {
    return make_pair(words(s), "toWords ");
}
----

목표는 이 두 함수를 합성해서, 문자열을 대문자로 바꾸고 단어로 분리하면서 그 과정의 로그를 생성하는 하나의 장식된 함수를 만드는 것입니다. 다음처럼 구현할 수 있습니다.

[source,cpp]
----
Writer<vector<string>> process(string s) {
    auto p1 = toUpper(s);
    auto p2 = toWords(p1.first);
    return make_pair(p2.first, p1.second + p2.second);
}
----

목표를 달성했습니다. 로그 취합은 이제 개별 함수가 관여할 일이 아닙니다. 함수들은 각자의 메시지만 생성하고, 로그 연결은 외부에서 처리됩니다.

그런데 이런 스타일로 프로그램 전체를 작성한다고 상상해 보세요. 반복적이고 오류가 발생하기 쉬운 코드의 악몽이 펼쳐질 겁니다. 하지만 우리는 프로그래머입니다. 반복되는 코드를 다루는 방법을 압니다. 추상화하면 됩니다! 다만 여기서 필요한 것은 평범한 추상화가 아닙니다. 함수 합성 자체를 추상화해야 합니다. 합성은 카테고리 이론의 본질이므로, 더 많은 코드를 쓰기 전에 카테고리 이론 관점에서 문제를 분석해 봅시다.

== Writer 카테고리
(The Writer Category)

부가 기능을 위해 함수의 반환 타입을 장식한다는 아이디어는 매우 유용합니다. 앞으로도 많은 예시를 보게 될 것입니다. 시작점은 평범한 타입과 함수의 카테고리입니다. 타입은 대상(object)으로 그대로 두고, 모피즘(morphism)을 장식된 함수로 재정의합니다.

예를 들어, ``int``에서 ``bool``로 가는 함수 ``isEven``을 장식한다고 해 봅시다. 이 함수를 장식된 함수로 나타내는 모피즘으로 변환합니다. 중요한 점은, 장식된 함수가 실제로는 쌍(pair)을 반환하지만, 이 모피즘은 여전히 ``int``와 ``bool`` 두 대상 사이의 화살표로 간주된다는 것입니다.

[source,cpp]
----
pair<bool, string> isEven(int n) {
     return make_pair(n % 2 == 0, "isEven ");
}
----

카테고리의 법칙에 따르면, 이 모피즘을 대상 ``bool``에서 시작하는 다른 모피즘과 합성할 수 있어야 합니다. 특히 앞서 만든 ``negate``와 합성할 수 있어야 합니다.

[source,cpp]
----
pair<bool, string> negate(bool b) {
     return make_pair(!b, "Not so! ");
}
----

입출력 타입이 정확히 맞지 않기 때문에 일반 함수처럼 직접 합성할 수는 없습니다. 대신 합성은 다음처럼 이루어져야 합니다.

[source,cpp]
----
pair<bool, string> isOdd(int n) {
    pair<bool, string> p1 = isEven(n);
    pair<bool, string> p2 = negate(p1.first);
    return make_pair(p2.first, p1.second + p2.second);
}
----

이것이 우리가 새로 만드는 카테고리에서 두 모피즘을 합성하는 레시피입니다.

- 첫 번째 모피즘에 해당하는 장식된 함수를 실행합니다.
- 결과 쌍의 첫 번째 요소를 추출해서 두 번째 모피즘에 해당하는 장식된 함수로 전달합니다.
- 첫 번째 결과의 두 번째 요소(문자열)와 두 번째 결과의 두 번째 요소(문자열)를 연결합니다.
- 최종 결과의 첫 번째 요소와 연결된 문자열을 결합해 새로운 쌍을 반환합니다.

이 합성을 C++에서 고차 함수(higher-order function)로 추상화하려면, 카테고리의 세 대상에 해당하는 세 타입을 매개변수로 받는 템플릿을 사용해야 합니다. 이 템플릿은 우리의 규칙에 따라 합성 가능한 두 장식된 함수를 받아서, 합성된 세 번째 장식된 함수를 반환합니다.

[source,cpp]
----
template<class A, class B, class C>
function<Writer<C>(A)> compose(function<Writer<B>(A)> m1, 
                               function<Writer<C>(B)> m2)
{
    return [m1, m2](A x) {
        auto p1 = m1(x);
        auto p2 = m2(p1.first);
        return make_pair(p2.first, p1.second + p2.second);
    };
}
----

이제 이 새로운 템플릿을 사용해 앞선 예제의 ``toUpper``와 ``toWords``를 합성할 수 있습니다.

[source,cpp]
----
Writer<vector<string>> process(string s) {
   return compose<string, string, vector<string>>(toUpper, toWords)(s);
}
----

``compose`` 템플릿에 타입을 전달하는 부분이 여전히 번잡합니다. 하지만 일반화된 람다 함수와 반환 타입 추론을 지원하는 C++14 호환 컴파일러가 있다면(이 코드는 Eric Niebler 덕분입니다) 훨씬 깔끔하게 처리할 수 있습니다.

[source,cpp]
----
auto const compose = [](auto m1, auto m2) {
    return [m1, m2](auto x) {
        auto p1 = m1(x);
        auto p2 = m2(p1.first);
        return make_pair(p2.first, p1.second + p2.second);
    };
};
----

이 새로운 정의를 사용하면 ``process`` 구현이 다음과 같이 단순해집니다.

[source,cpp]
----
Writer<vector<string>> process(string s){
   return compose(toUpper, toWords)(s);
}
----

아직 끝나지 않았습니다. 합성을 정의했으니, 이제 항등 모피즘(identity morphism)이 무엇인지 정해야 합니다. 이것들은 일반적인 항등 함수가 아닙니다! 타입 ``A``에서 타입 ``A``로 돌아가는 모피즘이어야 하므로, 다음 형태의 장식된 함수여야 합니다.

[source,cpp]
----
Writer<A> identity(A);
----

이들은 합성에 대한 단위원(unit)으로 작동해야 합니다. 합성 정의를 보면, 항등 모피즘은 인자를 변경 없이 전달하고 로그에는 빈 문자열만 기여해야 함을 알 수 있습니다.

[source,cpp]
----
template<class A>
Writer<A> identity(A x) {
    return make_pair(x, "");
}
----

방금 정의한 카테고리가 실제로 정당한 카테고리임을 쉽게 확인할 수 있습니다. 특히 우리의 합성은 자명하게 결합법칙을 만족합니다. 각 쌍의 첫 번째 요소에서 일어나는 일을 따라가 보면, 그것은 결합법칙을 만족하는 일반적인 함수 합성입니다. 두 번째 요소들은 연결되는데, 연결도 결합법칙을 만족합니다.

눈치 빠른 독자라면 이 구조를 문자열 모노이드뿐만 아니라 임의의 모노이드(monoid)로 쉽게 일반화할 수 있다는 점을 알아챘을 것입니다. ``compose`` 안에서 ``mappend``를, ``identity`` 안에서 ``mempty``를 사용하면 됩니다(``+``와 ``""``대신에). 문자열만 로깅할 이유가 전혀 없습니다. 훌륭한 라이브러리 작성자라면 라이브러리가 작동하기 위한 최소한의 제약을 찾아낼 줄 알아야 합니다. 여기서 로깅 라이브러리의 유일한 요구사항은 로그가 모노이드 속성을 가져야 한다는 것입니다.

== 하스켈에서의 Writer
(Writer in Haskell)

하스켈에서 같은 것을 구현하면 훨씬 간결하고, 컴파일러의 도움도 훨씬 많이 받을 수 있습니다. ``Writer`` 타입 정의부터 시작합시다.

[source,haskell]
----
type Writer a = (a, String)
----

C++의 ``typedef``(또는 ``using``)에 해당하는 타입 별칭(type alias)을 정의한 것입니다. ``Writer`` 타입은 타입 변수 ``a``로 매개변수화되며, ``a``와 ``String``의 쌍과 동일합니다. 쌍 문법은 최소한입니다. 괄호 안에 쉼표로 구분된 두 항목만 있으면 됩니다.

우리 모피즘들은 임의의 타입에서 어떤 ``Writer`` 타입으로 가는 함수입니다.

[source,haskell]
----
a -> Writer b
----

합성을 재미있는 중위 연산자로 선언하겠습니다. 때때로 "물고기(fish)"라고 불립니다.

[source,haskell]
----
(>=>) :: (a -> Writer b) -> (b -> Writer c) -> (a -> Writer c)
----

두 인자를 받는 함수인데, 각 인자도 그 자체로 함수이고, 결과로 함수를 반환합니다. 첫 번째 인자는 ``(a -> Writer b)`` 타입이고, 두 번째는 ``(b -> Writer c)`` 타입이며, 결과는 ``(a -> Writer c)`` 타입입니다.

다음은 이 중위 연산자의 정의입니다. 물고기 기호 양쪽에 두 인자 ``m1``과 ``m2``가 나타납니다.

[source,haskell]
----
m1 >=> m2 = \x -> 
    let (y, s1) = m1 x
        (z, s2) = m2 y
    in (z, s1 ++ s2)
----

결과는 인자 ``x`` 하나를 받는 람다 함수입니다. 람다는 백슬래시로 표현됩니다. 다리 하나가 잘린 그리스 문자 λ라고 생각하면 됩니다.

``let`` 표현식으로 보조 변수를 선언할 수 있습니다. 여기서 ``m1``을 호출한 결과는 변수 쌍 ``(y, s1)``에 패턴 매칭되고, ``m2``를 ``y``를 인자로 호출한 결과는 ``(z, s2)``에 매칭됩니다.

하스켈에서는 C++에서처럼 접근자를 사용하기보다 쌍을 패턴 매칭하는 것이 일반적입니다. 그 외에는 두 구현 사이에 꽤 직접적인 대응이 있습니다.

``let`` 표현식의 전체 값은 ``in`` 절에 명시됩니다. 여기서는 첫 번째 요소가 ``z``이고 두 번째 요소가 두 문자열을 연결한 ``s1++s2``인 쌍입니다.

우리 카테고리의 항등 모피즘도 정의하겠습니다. 하지만 나중에 분명해질 이유로, 이것을 ``return``이라고 부르겠습니다.

[source,haskell]
----
return :: a -> Writer a
return x = (x, "")
----

완성도를 위해 장식된 함수 ``upCase``와 ``toWords``의 하스켈 버전도 보겠습니다.

[source,haskell]
----
upCase :: String -> Writer String
upCase s = (map toUpper s, "upCase ")

toWords :: String -> Writer [String]
toWords s = (words s, "toWords ")
----

``map`` 함수는 C++의 ``transform``에 대응됩니다. 문자 함수 ``toUpper``를 문자열 ``s``에 적용합니다. 보조 함수 ``words``는 표준 ``Prelude`` 라이브러리에 정의되어 있습니다.

마지막으로 두 함수의 합성은 물고기 연산자의 도움으로 완성됩니다.

[source,haskell]
----
process :: String -> Writer [String]
process = upCase >=> toWords
----

== 클라이슬리 카테고리 (Kleisli Categories)

짐작하셨겠지만, 제가 즉석에서 이 카테고리를 발명한 것은 아닙니다. 이것은 소위 클라이슬리 카테고리(Kleisli category)의 예시입니다. 모나드(monad)를 기반으로 하는 카테고리죠. 아직 모나드를 논의할 준비가 되지 않았지만, 모나드가 무엇을 할 수 있는지 맛보기를 보여드리고 싶었습니다.

우리의 제한된 목적을 위해, 클라이슬리 카테고리는 대상(object)으로 기반 프로그래밍 언어의 타입들을 가집니다. 타입 ``A``에서 타입 ``B``로의 모피즘은 ``A``에서 특정 장식(embellishment)을 사용해 ``B``에서 파생된 타입으로 가는 함수입니다. 각 클라이슬리 카테고리는 이러한 모피즘들을 합성하는 자체적인 방법과, 그 합성에 대한 항등 모피즘을 정의합니다. (나중에 부정확한 용어인 "장식"이 카테고리에서 자기함자(endofunctor)의 개념에 대응된다는 것을 보게 될 것입니다.)

이 포스트에서 카테고리의 기반으로 사용한 특정 모나드는 writer 모나드라고 불리며, 함수의 실행을 로깅하거나 추적하는 데 사용됩니다. 이것은 또한 순수 계산에 효과를 내장하는 더 일반적인 메커니즘의 예이기도 합니다. 이전에 우리는 프로그래밍 언어 타입과 함수를 집합의 카테고리로 모델링할 수 있다는 것을 봤습니다(평소처럼 바텀(bottom)은 무시하고). 여기서는 이 모델을 약간 다른 카테고리로 확장했습니다. 모피즘이 장식된 함수로 표현되고, 합성이 한 함수의 출력을 다른 함수의 입력으로 전달하는 것 이상의 일을 하는 카테고리입니다. 우리에게 하나 더 많은 자유도가 생긴 것입니다. 바로 합성 자체입니다. 이것이 바로 명령형 언어에서 전통적으로 부수 효과를 사용해 구현되던 프로그램에 단순한 지시적 의미론(denotational semantics)을 부여할 수 있게 만드는 자유도입니다.

== 도전 과제
(Challenge)

인자로 가능한 모든 값에 대해 정의되지 않은 함수를 부분 함수(partial function)라고 합니다. 수학적 의미에서 진정한 함수가 아니므로, 표준적인 카테고리 틀에 맞지 않습니다. 하지만 장식된 타입 ``optional``을 반환하는 함수로 표현할 수 있습니다.

[source,cpp]
----
template<class A> class optional {
    bool _isValid;
    A    _value;
public:
    optional()    : _isValid(false) {}
    optional(A v) : _isValid(true), _value(v) {}
    bool isValid() const { return _isValid; }
    A value() const { return _value; }
};
----

예를 들어, 다음은 장식된 함수 ``safe_root``의 구현입니다.

[source,cpp]
----
optional<double> safe_root(double x) {
    if (x >= 0) return optional<double>{sqrt(x)};
    else return optional<double>{};
}
----

도전 과제는 다음과 같습니다.

1.  부분 함수를 위한 클라이슬리 카테고리를 구축하세요(합성과 항등 모피즘을 정의).
2.  인자가 0과 다를 때 유효한 역수를 반환하는 장식된 함수 ``safe_reciprocal``을 구현하세요.
3.  ``safe_root``와 ``safe_reciprocal``을 합성해서, 가능할 때마다 ``sqrt(1/x)``를 계산하는 ``safe_root_reciprocal``을 구현하세요.
