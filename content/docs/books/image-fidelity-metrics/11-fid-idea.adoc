10장에서 두 이미지 집합의 특징 벡터의 **분산**을 비교해 모드 붕괴를 잡아냈습니다. 그런데 분산만으로는 부족한 경우가 있습니다 — 두 집합의 분산은 비슷한데 평균이 완전히 다르다면? 또는 평균은 비슷한데 분산의 "모양"(어느 방향으로 퍼져 있는가)이 다르다면? **FID(Fréchet Inception Distance)**는 평균과 공분산(분산의 모양까지 포함)을 한꺼번에 고려해서, 두 집합의 "닮음"을 숫자 하나로 요약합니다.

== 두 집합을 하나의 다변량 정규분포로 근사하기

FID의 핵심 아이디어는, 각 이미지 집합의 특징 벡터들이 **다변량 정규분포(multivariate Gaussian)**를 따른다고 가정하는 것입니다. 정규분포는 평균(`μ`, 벡터)과 공분산(`Σ`, 행렬 — 각 특징이 서로 얼마나 함께 움직이는지까지 포함한 "퍼짐의 모양")이라는 두 통계량으로 완전히 결정됩니다.

[source,python]
----
import numpy as np

def fit_gaussian(features):
    mu = features.mean(axis=0)
    sigma = np.cov(features, rowvar=False)
    return mu, sigma
----

== 두 정규분포 사이의 거리: 프레셰 거리

두 정규분포 `N(μ_a, Σ_a)`와 `N(μ_b, Σ_b)` 사이의 "거리"를 재는 표준적인 공식이 있습니다.

[stem]
++++
\text{FID} = \|\mu_a - \mu_b\|^2 + \text{Tr}\left(\Sigma_a + \Sigma_b - 2(\Sigma_a \Sigma_b)^{1/2}\right)
++++

[source,python]
----
from scipy.linalg import sqrtm

def fid(feats_a, feats_b, eps=1e-6):
    mu_a, mu_b = feats_a.mean(axis=0), feats_b.mean(axis=0)
    cov_a = np.cov(feats_a, rowvar=False) + eps * np.eye(feats_a.shape[1])
    cov_b = np.cov(feats_b, rowvar=False) + eps * np.eye(feats_b.shape[1])

    mean_diff = mu_a - mu_b
    covmean = sqrtm(cov_a @ cov_b)
    if np.iscomplexobj(covmean):     # 수치 오차로 아주 작은 허수부가 생길 수 있어 실수부만 취한다
        covmean = covmean.real

    return mean_diff @ mean_diff + np.trace(cov_a + cov_b - 2 * covmean)
----

식이 복잡해 보이지만 두 부분으로 나눠보면 이해할 만합니다. `‖μ_a - μ_b‖²`는 "두 집합의 평균적인 특징이 얼마나 다른가"(10장에서 다루지 않았던 부분)이고, `Tr(Σ_a + Σ_b - 2(Σ_aΣ_b)^(1/2))`는 "두 집합의 퍼짐(분산)의 모양이 얼마나 다른가"(10장의 분산 비교를 공분산 행렬 전체로 정교하게 확장한 버전)입니다. `eps * np.eye(...)`를 더하는 건 공분산 행렬이 수치적으로 불안정해지는 걸 막는 안전장치입니다(2장·5장에서 봤던 것과 같은 종류의 안전장치입니다). `sqrtm`(행렬의 제곱근)은 일반적인 제곱근과 달리 행렬에 대해 정의되는 특별한 연산으로, `scipy.linalg`가 제공합니다.

== 10장의 세 집합에 FID 적용하기

10장에서 만든 실제 사각형 집합(`real_set`), 모드 붕괴된 집합(`collapsed_set`), 그리고 비교 기준을 위해 실제 집합과 같은 방식으로 만들었지만 다른 무작위 시드로 뽑은 또 다른 "실제와 같은 분포의" 집합(`real_set2`)에 FID를 적용합니다.

[source,python]
----
print("FID(실제, 실제와 같은 분포에서 다시 뽑은 집합):", fid(real_feats, real_feats2))
print("FID(실제, 모드 붕괴된 집합):", fid(real_feats, collapsed_feats))

같은 분포에서 다시 뽑은 두 집합끼리는 FID가 `0.17`로 작습니다(정확히 `0`이 아닌 건, 유한한 개수인 `30`장씩만 뽑았기 때문에 생기는 자연스러운 표본 오차입니다 — "완벽하게 같은 분포"라도 표본이 유한하면 통계량이 조금씩 다르게 추정됩니다). 모드 붕괴된 집합과는 FID가 `0.88`로, 기준선의 `5`배가 넘습니다 — 10장의 분산 비교가 보여줬던 "다양성 부족"이 FID에도 명확하게 반영됐습니다.

== FID는 모드 붕괴가 아닌 다른 종류의 차이도 잡아낸다

이번엔 모드 붕괴가 아니라, 사각형이 전체적으로 더 큰(하지만 여전히 다양한 크기를 갖는) 집합을 만들어 비교합니다.

----
rng4 = np.random.default_rng(11)

== FID의 실전적 의미: "한 장"이 아니라 "이 정도 규모의 집합이 이 정도로 다르다"

FID는 개별 이미지 쌍을 비교하지 않으므로, 1~9장의 지표들과는 근본적으로 다른 질문에 답합니다 — "이 이미지가 저 이미지와 닮았는가"가 아니라 "이 이미지 뭉치 전체가 저 이미지 뭉치 전체와 통계적으로 얼마나 다른가"를 묻습니다. 그래서 FID는 짝지어진 정답이 없는 상황(순수 생성 모델의 결과물 평가)에서 특히 유용하지만, 대가도 있습니다 — 최소 수십~수백 장 이상의 이미지가 있어야 평균·공분산 추정이 안정적입니다(방금 `30`장으로도 완벽히 `0`이 아닌 기준선 오차가 남았던 걸 기억하세요). 실제 FID 논문에서는 보통 수천~수만 장 단위의 이미지로 계산합니다.

== 직접 해보기

* 표본 크기(각 집합의 이미지 개수)를 `30`장에서 `10`장으로 줄이면, "실제 vs 실제(다른 표본)"의 기준선 FID가 어떻게 변하는지 확인해보세요. 표본이 적을수록 이 기준선이 커진다면, 그게 왜 문제가 되는지도 생각해보세요.

def sample_real_set(rng, n):
    s = []
    for _ in range(n):
        cx, cy = rng.integers(15, 33), rng.integers(15, 33)
        size = rng.integers(10, 20)
        s.append(make_square_image(N, cx, cy, size))

rng_a, rng_b = np.random.default_rng(20), np.random.default_rng(21)
feats_10a, feats_10b = sample_real_set(rng_a, 10), sample_real_set(rng_b, 10)
print("표본 10장 기준선 FID:", fid(feats_10a, feats_10b))
----

[source]
----
표본 10장 기준선 FID: 0.8005
----

`30`장일 때 기준선(`0.17`)보다 `10`장일 때 기준선(`0.80`)이 훨씬 큽니다 — 표본이 적을수록 평균·공분산 추정이 부정확해져서, "완전히 같은 분포"에서 뽑은 두 집합조차 우연히 크게 달라 보일 수 있다는 뜻입니다. 이게 왜 문제가 되냐면, 만약 표본이 `10`장뿐인 상황에서 어떤 렌더링 방법의 FID가 `1.0`이 나왔다면, 이게 "진짜로 나쁜 렌더링"인지 아니면 "그냥 표본이 적어서 생기는 우연한 오차"인지 이 숫자 하나만으로는 구별할 수 없습니다. 실전에서 FID를 신뢰하려면 충분히 큰 표본이 필요하다는 걸 반드시 기억해야 합니다.

== 요약

* FID는 두 이미지 집합의 특징 벡터를 다변량 정규분포로 근사하고, 그 평균 차이와 공분산 차이를 프레셰 거리 공식 하나로 합쳐 요약합니다.
* 모드 붕괴(10장)와 분포의 평균 이동(이 장에서 새로 확인)을 모두 잡아낼 수 있어, 분산만 보는 것보다 폭넓은 종류의 분포 차이에 반응합니다.
* 같은 분포에서 뽑은 두 표본이라도 FID가 정확히 `0`이 되지는 않으며, 표본 크기가 작을수록 이 기준선 오차가 커져 실제 차이와 우연한 오차를 구별하기 어려워집니다.
* 이것으로 1~11장의 개별 지표(픽셀, 구조, 지각, 분포)를 모두 다뤘습니다 — 마지막 두 장에서는 이 모든 지표를 3D Gaussian Splatting 렌더링 품질 검증이라는 실전 문제에 적용합니다.
