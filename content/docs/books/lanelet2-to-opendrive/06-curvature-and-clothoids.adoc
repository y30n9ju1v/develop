'''

5장까지 오면서 위치 잔차는 충분히 작아졌습니다(대칭 잔차 mean 몇 cm대). 그런데 4장 끝에서 미뤄둔 질문이 하나 남아 있습니다 — **세그먼트 사이 곡률이 갑자기 튀는 문제**입니다. 이 장은 그 문제가 왜 위치 잔차만 봐서는 안 보이는지, 그리고 어떻게 고치는지 다룹니다.

== 곡률 오차부터 정의한다

먼저 "곡률이 얼마나 정확한가"를 재는 지표부터 만들어야 합니다. 원본 점들의 실측 곡률(이산 곡률, 3점으로 근사)과 피팅된 곡선의 이론 곡률을 비교하면 됩니다.

[source,python]
----
def discrete_curvature(points):
    """3점 유한차분(메넬라우스 공식)으로 이산 곡률 κ(s)를 추정한다."""
    curv = np.zeros(len(points))
    for i in range(1, len(points)-1):
        p0, p1, p2 = points[i-1], points[i], points[i+1]
        a, b, c = np.linalg.norm(p1-p0), np.linalg.norm(p2-p1), np.linalg.norm(p2-p0)
        area2 = abs((p1[0]-p0[0])*(p2[1]-p0[1]) - (p2[0]-p0[0])*(p1[1]-p0[1]))
        curv[i] = 0 if a*b*c == 0 else 2*area2/(a*b*c)
    return curv
----

여기서 첫 번째 함정을 만납니다 — 스무딩 없이 이 값을 그대로 쓰면, "오차"의 대부분이 사실은 피팅 오차가 아니라 **이산 곡률 추정 자체의 노이즈**입니다. 원본 점들을 살짝 스무딩한 뒤와 안 한 뒤의 이산 곡률 차이가, 스무딩 없이 잰 "오차"와 같은 자릿수로 나옵니다. 측정 기준(스무딩 여부·강도)을 지표 이름에 명시해야 다른 결과와 비교할 수 있다는 뜻입니다.

== 곡률 계단을 물리량으로 바꾼다

4장에서 세그먼트 이음새의 헤딩 꺾임을 쟀는데, 곡률도 마찬가지로 이음새에서 계단처럼 튑니다(직선 κ=0에서 원호 κ=const로 넘어가는 지점이 대표적입니다). 문제는 "곡률 계단 0.1 [1/m]"이라는 숫자만 봐서는 이게 심각한지 감이 안 온다는 겁니다.

물리로 바꿔봅니다. 곡률이 `Δκ`만큼 순간적으로 튀는 지점을 속도 `v`로 지나가면, 횡가속도가 **`Δa = v² · Δκ`** 만큼 즉각 점프합니다. 조향 컨트롤러 입장에서는 스텝 입력이나 마찬가지입니다.

이걸로 재보면 결과가 심각합니다. 도심 속도(18km/h)에서도 이음새의 24.2%가 편안한 승차감 한계(약 2 m/s²)를, 12.1%가 급조향 수준(4 m/s²)을 넘습니다. 시속 50km로 올라가면 각각 55.6%, 43.7%로 뛰어 절반 넘는 이음새가 문제가 됩니다. **위치 잔차만 보고 "이 정도면 충분하다"고 판단한 게 틀렸다는 뜻입니다.** 위치와 곡률은 다른 이야기입니다.

[IMPORTANT]
====
이 장의 핵심 교훈은 여기 있습니다 — **추상적인 단위([1/m])의 오차 지표는, 실제로 그 오차가 만드는 물리적 효과로 환산해봐야 "이게 큰가 작은가"를 판단할 수 있습니다.** 숫자 자체보다, 그 숫자를 무엇으로 번역하느냐가 판단을 바꿉니다.
====

== 클로소이드: 곡률을 매끄럽게 잇는 세그먼트

2장에서 잠깐 언급한 `<spiral>`(클로소이드)이 정확히 이 문제를 위한 겁니다 — 곡률이 시작값에서 끝값까지 **선형으로** 변하는 세그먼트를 직선과 원호 사이에 끼우면, 곡률 계단이 완만한 램프로 바뀝니다.

첫 시도는 전환 길이를 그냥 고정값(3m)으로 두고 끼워 넣는 것이었습니다. 결과는 실패였습니다 — 곡률이 크게 튀는 구간(거의 직선에서 반경 1m 미만 커브로)을 3m 안에 욱여넣으니, 경로 자체가 원래 경계에서 크게(1m 이상) 벗어나 버렸습니다.

두 번째 시도는 전환 길이를 자유 변수로 두고, 경계 대칭 잔차를 최소화하는 길이를 최적화로 찾는 것이었습니다. 잔차는 확실히 잡혔지만, 최적 길이가 지나치게 짧게 나왔고, 이걸 다시 jerk(횡가속도 변화율, `da/dt ≈ v³·Δκ/L`)로 환산해보니 표본 15개 lanelet 기준 jerk가 평균 450 m/s³, 최악 988 m/s³까지 나왔고 **편안한 한계 안에 든 표본이 0.0%였습니다.** 원인은 명확합니다 — "경계에 딱 맞는 최단 경로를 찾는 것"과 "곡률을 부드럽게 바꾸는 것"은 서로 경쟁하는 목적함수였던 겁니다. 잔차만 최소화하면 항상 가장 짧은(=가장 급한) 전환을 고릅니다.

== 세 번째 시도: jerk를 목적함수에 직접 넣는다

사후에 이음새만 패치하는 방식으로는 한계가 있다는 게 두 번의 실패로 확인됐습니다. 대신 4~5장의 전역 최적화 **자체**에 곡률 변화율 페널티를 추가합니다.

모든 세그먼트를 `(κ_start, κ_end, L)` 세 값으로 표현하는 "일반화된 클로소이드"로 통일합니다 — 기존 직선(κ=0 상수)과 원호(κ=const)는 이 표현의 특수한 경우(κ_start=κ_end)일 뿐이라 표현력을 잃지 않습니다.

[source,python]
----
def fit_reference_line_jerk_penalized(left, right, jerk_weight=0.0, joint_weight=1.0):
    x0_base, n_segs, _ = fit_reference_line_boundary_symmetric(left, right)  # 5장 결과가 초기값
    kappas = x0_base[3:3+n_segs]
    lengths = x0_base[3+n_segs:3+2*n_segs]
    x0 = np.concatenate([x0_base[:3], kappas, kappas, lengths])  # κ_start=κ_end로 시작

    def residual(params):
        poly = chain_sample_general_fixed(params, n_segs)   # (κ_start,κ_end,L) 지원 샘플러
        sym = point_to_polyline_dist(poly, left) - point_to_polyline_dist(poly, right)
        k_starts = params[3:3+n_segs]
        k_ends = params[3+n_segs:3+2*n_segs]
        lens = params[3+2*n_segs:3+3*n_segs]
        joint_gap = joint_weight * (k_ends[:-1] - k_starts[1:])          # 세그먼트 사이 곡률 연속
        jerk_rate = jerk_weight * (k_ends - k_starts) / np.maximum(lens, 0.1)  # 세그먼트 내부 곡률 변화율
        reg = 0.02 * (params - x0)
        return np.concatenate([sym, joint_gap, jerk_rate, reg])

    return least_squares(residual, x0, bounds=(...)).x
----

`jerk_weight`를 0에서 점점 키워가며 실측해보면, 잔차와 jerk가 정확히 트레이드오프합니다 — 표본 10개 lanelet 기준, 가중치를 0에서 0.05로 올리면 잔차는 평균 1.25cm → 1.37cm로 약 10% 늘어나는 대신, jerk는 평균 204 → 102 m/s³로 절반이 됩니다.

다만 가장 극단적인 경우(반경이 극단적으로 작은 급코너)는 가중치를 아무리 올려도 편안한 한계를 못 맞췄습니다. 필요한 전환 길이를 역산해보면(`L = v³Δκ/jerk_max`) 해당 lanelet 길이보다 훨씬 길게 나옵니다 — **이건 피팅 알고리즘의 한계가 아니라, 그 지점 자체가 애초에 저속 구간(진입로·주차장 모서리)이라는 뜻입니다.** 클로소이드가 못 고치는 게 아니라, 고칠 필요가 없는 지점이라는 걸 숫자로 확인한 겁니다.

== 이 장에서 남은 질문

`jerk_weight`를 얼마로 둘지는 이 장의 코드만으로는 정할 수 없습니다 — "잔차를 몇 % 희생해서 jerk를 몇 m/s³까지 낮출 것인가"는 시뮬레이션의 정합 오차 허용 범위와 회귀 테스트가 감내할 승차감 기준이 있어야 정해지는 값입니다. 이건 알고리즘이 아니라 **도메인 판단**이 필요한 질문이고, 10장에서 다시 다룹니다.

여기까지가 참조선(2부) 전체의 결론입니다: 처음엔 위치 잔차 하나만 봤지만, 그걸로 부족하다는 게 이음새 헤딩(4장) → 중심선 정의(5장) → 곡률 연속성(6장)을 거치며 계속 드러났습니다. 다음 장부터는 3부 — 낱개의 차선을 도로로 묶고 교차로를 만드는 작업입니다.
