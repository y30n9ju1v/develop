'''

4장에서는 "중심선"이라는 점렬이 이미 주어져 있다고 가정하고 그걸 곡선으로 피팅했습니다. 이 장에서는 그 가정 자체를 파고듭니다 — **중심선을 어떻게 계산했는가?**

== 가장 쉬운 방법: 좌우 경계를 평균한다

Lanelet2 lanelet은 왼쪽 경계선과 오른쪽 경계선, 두 폴리라인만 갖고 있습니다. 중심선을 만드는 가장 쉬운 방법은 두 경계를 각각 호길이 비율로 재샘플링해서 점 개수를 맞추고, 같은 인덱스의 점끼리 평균 내는 겁니다.

[source,python]
----
def resample_to_common_length(a, b, n=30):
    def resample(pts, n):
        s = np.concatenate([[0], np.cumsum(np.linalg.norm(np.diff(pts, axis=0), axis=1))])
        query = np.linspace(0, s[-1], n)
        return np.stack([np.interp(query, s, pts[:, 0]), np.interp(query, s, pts[:, 1])], axis=1)
    return resample(a, n), resample(b, n)

left_r, right_r = resample_to_common_length(left, right, n=30)
centerline = (left_r + right_r) / 2
----

간단하고 직관적입니다. 문제는 이게 **"두 경계의 길이가 비슷할 때만" 타당한 암묵적 가정**을 깔고 있다는 겁니다.

== 편향을 실측한다

이 가정이 깨지면 어떤 일이 벌어지는지 직접 재봤습니다. 평균 방식 중심선을 초기 추정으로 두고, 각 점에서 로컬 접선의 법선을 세워 좌/우 경계와의 교점을 구해 그 중점으로 다시 계산한 "법선 투영 중심선"과 비교합니다 — 이게 진짜 "좌우 경계에서 등거리인 지점"의 정의에 더 가깝습니다.

[cols="1,1,1,1"]
|===
| | mean | p95 | max

| Karlsruhe(노이즈 있는 맵)
| 15.8cm
| 63.2cm
| **147cm**

| Autoware 샘플맵(깨끗한 맵)
| 2.0cm
| 3.6cm
| 32cm
|===

**최악 1.47m 벗어납니다.** 원인을 추적해보니 좌우 경계 길이 자체가 크게 다른(쐐기형) lanelet일수록 편향이 컸습니다 — Karlsruhe 맵의 최악 케이스는 왼쪽 경계 24.4m, 오른쪽 경계 126.6m로 5배 넘게 차이 났습니다. 인덱스로 짝지어 평균 내는 순간, 애초에 서로 대응하지 않는 점끼리 평균 내는 셈입니다.

이 발견의 무게는 짚어야 합니다 — **4장에서 잰 모든 잔차 수치는 이 편향된 중심선을 "정답"으로 놓고 잰 값**입니다. 잔차 5cm짜리 피팅이 실제 도로 중심에서는 1m 넘게 벗어나 있을 수 있다는 뜻입니다.

== 첫 수정 시도: 실패

가장 자연스러운 수정은 앞서 계산한 "법선 투영 중심선"을 그대로 파이프라인에 넣는 것입니다. 실제로 해보니 **두 가지 문제**가 나왔습니다.

첫째, 견고성 결함입니다. 법선을 세워 경계와의 교점을 찾는 코드에 거리 상한이 없어서, 쐐기형 lanelet의 끝부분에서 법선이 가까운 경계가 아니라 폴리라인 반대편의 먼 지점과 잘못 교차하는 버그가 있었습니다 — 이 때문에 중심선이 순간적으로 14.6m 튀는 사고가 났습니다. 로컬 폭의 3배를 넘는 교점은 버리고 평균 방식으로 폴백하도록 고쳤습니다.

둘째, 더 근본적인 문제입니다. 버그를 고친 뒤에도 노이즈가 있는 Karlsruhe 맵에서는 4장의 전역 최적화 잔차가 **오히려 나빠졌습니다**(평균 +4cm, 곡률 오차는 약 3배). 30개 점을 하나씩 독립적으로 투영하다 보니 인접 점 사이에 고주파 잡음이 생기고, 그 잡음이 그대로 참조선 피팅에 들어간 겁니다. 편향은 없앴지만 그 대가로 노이즈를 얻은 셈입니다 — 순수하게 목표에 더 가까워지지 않았습니다.

**"중심선을 미리 보정하고 그 위에 참조선을 피팅한다"는 2단계 구조 자체가 틀린 접근**이었다는 게 여기서 나온 결론입니다.

== 성공한 방법: 중심선을 만들지 말고, 경계에 직접 대칭 피팅한다

발상을 바꿉니다 — 중심선이라는 중간 산출물을 아예 만들지 않고, 4장에서 만든 전역 파라메트릭 곡선을 **좌/우 경계 폴리라인까지의 거리가 같아지도록** 직접 최적화합니다.

[source,python]
----
def fit_reference_line_boundary_symmetric(left, right, epsilon=0.15, reg_weight=0.05):
    centerline = (left + right) / 2
    x0, n_segs, _ = fit_reference_line_global(centerline, epsilon=epsilon)  # 4장 결과를 초기값으로

    def residual(params):
        poly = chain_sample_fixed(params, n_segs)          # 4장의 체인 샘플러 (고정 개수 버전)
        d_left = point_to_polyline_dist(poly, left)
        d_right = point_to_polyline_dist(poly, right)
        sym = d_left - d_right                              # 0이면 완전 대칭(도로 중심)
        reg = reg_weight * (params - x0)                     # 초기해 근방 유지
        return np.concatenate([sym, reg])

    sol = least_squares(residual, x0, bounds=(...))
    return sol.x, n_segs
----

핵심은 매끄러움이 **파라메트릭 표현 자체에서 공짜로 나온다**는 겁니다 — 30개 점을 따로따로 계산하는 단계가 아예 없으니, 앞서 겪은 고주파 잡음이 애초에 생길 자리가 없습니다.

결과를 "곡선이 좌우 경계로부터 실제로 등거리인가"로 재보면(이게 진짜 품질 지표입니다):

[cols="1,1,1"]
|===
| | 평균 방식 중심선 자체의 비대칭 | 경계 대칭 피팅 후

| Karlsruhe
| mean 30cm / max 132cm
| **mean 6.6cm / max 40cm**

| Autoware
| mean 1.4cm / max 6.9cm
| mean 1.5cm / max 8.4cm(퇴보 없음)
|===

노이즈가 있는 맵일수록 개선 폭이 컸고, 이미 깨끗했던 맵에서는 퇴보가 없습니다. 첫 시도(법선 투영)와 정반대 결과입니다 — 잡음을 심는 대신, 파라메트릭 곡선 자체가 이미 갖고 있는 매끄러움을 그대로 유지하면서 편향만 없앴기 때문입니다.

**이번 장의 교훈은 이 문제 하나에 국한되지 않습니다.** "먼저 좋은 타깃을 계산하고 그 타깃에 피팅한다"는 2단계 구조는 직관적이지만, 타깃 계산 과정에서 매끄러움을 잃으면 그 대가를 최종 피팅이 고스란히 떠안습니다. 목표를 미리 정제하려 하지 말고, **목표 자체를 최적화 문제의 일부로 넣는 것**이 더 안정적인 경우가 있다는 걸 이 장이 보여줍니다. 다음 장에서 이 원칙을 곡률에도 그대로 적용합니다.
