2장에서 봤듯, 교차로는 `Road`가 아니라 `Junction` — 여러 도로를 잇는 짧은 connecting road들의 묶음입니다. 이 장에서는 7장의 그룹핑 결과 위에 이걸 실제로 만들어봅니다. 지금까지 다룬 것 중 가장 큰 새 서브시스템이라, 이 장은 "전체 맵을 완벽하게" 처리하는 대신 **파이프라인이 끝에서 끝까지 작동하는 것**을 목표로 잡습니다.

== 교차로 후보 찾기

7장의 클러스터 그래프에서, 성공적으로 나가는 연결(`successors`)이 2개 이상이거나 들어오는 연결(`predecessors`)이 2개 이상인 클러스터가 분기점·합류점 — 즉 교차로 후보입니다.

[source,python]
----
junctions = []
for idx in range(len(clusters)):
    if len(successors[idx]) >= 2 or len(predecessors[idx]) >= 2:
        incoming = [...]  # predecessors 클러스터의 subtype=road lanelet들, 끝점 pose와 함께
        outgoing = [...]  # successors 클러스터의 subtype=road lanelet들, 시작점 pose와 함께
        junctions.append({"incoming": incoming, "outgoing": outgoing})
----

Karlsruhe 맵에서 이렇게 찾은 교차로 후보는 37개였고, 그중 가장 복잡한 건 진입 6개·진출 4개짜리였습니다. 이걸 대표 사례로 골라 나머지 과정을 먼저 검증하고, 뒤에서 37개 전체로 확장합니다.

== connecting road: 최적화 대신 닫힌 형태 곡선

4~6장에서 참조선을 피팅할 때는 항상 "맞춰야 할 기존 경계"가 있었습니다 — 반복 최적화가 그 경계에 조금씩 다가가는 방식이었죠. 그런데 connecting road는 **완전히 새로 만드는 도로**라서 맞출 대상이 없습니다. 대신 있는 건 "시작 pose(진입 도로 끝점)"와 "끝 pose(진출 도로 시작점)"뿐입니다 — 이건 최적화 문제가 아니라 **두 점 경계값 문제**입니다.

이럴 때는 3차 Hermite 곡선이 잘 맞습니다 — 시작/끝 위치와 방향을 항상 정확히 만족하는 **닫힌 형태 해**라서, 수렴 실패 위험이 아예 없습니다.

[source,python]
----
def hermite_connecting_road(p0, h0, p1, h1, n_samples=50):
    p0, p1 = np.array(p0), np.array(p1)
    scale = max(np.linalg.norm(p1 - p0) / 3.0, 0.5)
    t0 = np.array([math.cos(h0), math.sin(h0)]) * scale
    t1 = np.array([math.cos(h1), math.sin(h1)]) * scale

    t = np.linspace(0, 1, n_samples)
    h00, h10 = 2*t**3-3*t**2+1, t**3-2*t**2+t
    h01, h11 = -2*t**3+3*t**2, t**3-t**2
    return h00[:,None]*p0 + h10[:,None]*t0 + h01[:,None]*p1 + h11[:,None]*t1
----

탄젠트 크기(`scale`)는 표준 관례대로 두 점 사이 직선 거리의 1/3로 잡습니다. 이 곡선을 OpenDRIVE의 `<paramPoly3>`로 내보내려면 한 가지를 조심해야 합니다 — `paramPoly3`의 `(u, v)` 좌표는 **로컬 프레임**(그 `<geometry>`의 시작점을 원점, 시작 헤딩을 u축으로 삼는 회전된 좌표계) 기준입니다. world 좌표로 계산한 Hermite 계수를 그대로 XML에 써넣으면 안 되고, 시작 pose로 회전·이동시킨 로컬 좌표계로 변환해야 합니다.

[source,python]
----
c, s = math.cos(-h0), math.sin(-h0)
R = np.array([[c, -s], [s, c]])
p1_local = R @ (p1 - p0)
t0_local, t1_local = R @ t0, R @ t1
# 이 로컬 값들로 3차 다항식 계수 (aU,bU,cU,dU)/(aV,bV,cV,dV)를 계산
----

이 변환이 맞는지는 **왕복 검증**으로 확인합니다 — 로컬 계수로 곡선을 다시 그려서 world 프레임으로 되돌린 뒤, 원래 곡선과 겹치는지 봅니다. 오차가 수치 정밀도(1e-6m) 이내면 통과입니다. 이 습관은 이 책 전체에서 좌표계를 바꿀 때마다 반복해서 쓰는 검증 패턴입니다.

== laneLink: 어느 진입이 어느 진출로 이어지는가

connecting road를 만들려면 진입 lanelet 하나마다 어느 진출 lanelet과 짝지을지 정해야 합니다(`laneLink`). 1장에서 언급한 `turn_direction`(straight/left/right) 태그가 있으면 이걸로 정하면 되는데, **이 책이 쓰는 Karlsruhe 맵에는 이 태그가 아예 없습니다** — 태그 관례가 맵마다 다르다는 걸 여기서 처음 체감합니다.

태그가 없을 때의 대안은 "이었을 때 나오는 연결 곡선이 가장 매끄러운(최대 곡률이 가장 작은) 진출 lanelet"을 고르는 지오메트리 휴리스틱입니다 — 급하게 꺾어야 하는 연결보다 부드럽게 이어지는 연결이 실제 도로 연결일 가능성이 높다는 가정입니다.

[source,python]
----
def curvature_along(pts):
    curv = np.zeros(len(pts))
    for i in range(1, len(pts)-1):
        p0, p1, p2 = pts[i-1], pts[i], pts[i+1]
        a, b, c = np.linalg.norm(p1-p0), np.linalg.norm(p2-p1), np.linalg.norm(p2-p0)
        area2 = abs((p1[0]-p0[0])*(p2[1]-p0[1]) - (p2[0]-p0[0])*(p1[1]-p0[1]))
        curv[i] = 0 if a*b*c == 0 else 2*area2/(a*b*c)
    return curv

def best_match(p0, h0, outgoing_candidates):
    scored = []
    for out in outgoing_candidates:
        pts = hermite_connecting_road(p0, h0, out["pos"], out["heading"])
        scored.append((np.max(np.abs(curvature_along(pts)[1:-1])), out))
    return min(scored, key=lambda x: x[0])[1]   # 최대곡률이 가장 작은 후보
----

대표 교차로(진입 6/진출 4)에 이걸 돌려보면, 최근접 위치로 짝짓는 것보다 회전반경이 개선됩니다(0.4m → 0.9m). 하지만 승용차 최소 회전반경(5~6m)에는 여전히 못 미칩니다 — 태그 없이 순수 지오메트리만으로는 완전히 신뢰할 만한 짝짓기를 보장 못 한다는 뜻입니다.

== 37개 전체로 확장하니 드러난 버그

대표 교차로 하나에서는 괜찮아 보였던 것이, 37개(connecting road 96개) 전체로 확장하니 **99%가 회전반경 5m 미만**으로 나왔습니다. 원인을 조사해보니 심각한 버그였습니다 — 어떤 진입 lanelet의 끝점과 진출 lanelet의 시작점이 **좌표가 완전히 같은데** 추정된 헤딩만 159도나 차이 났습니다. 두 lanelet은 원래 정상적으로 이어진 구간인데, 짧은 lanelet의 헤딩을 끝쪽 2~3개 점만으로 추정하다 보니 노이즈에 크게 흔들린 것이었습니다.

수정은 끝쪽 최대 6개 점을 주축(SVD/공분산행렬) 방향으로 직선 피팅해서 헤딩을 추정하는 것이었습니다 — 노이즈에 훨씬 덜 민감합니다.

[source,python]
----
def lanelet_end_pose(center_points, is_start, n_fit_points=6):
    k = min(n_fit_points, len(center_points))
    chunk = center_points[:k] if is_start else center_points[-k:]
    cx, cy = np.mean(chunk, axis=0)
    sxx = np.sum((chunk[:,0]-cx)**2); syy = np.sum((chunk[:,1]-cy)**2)
    sxy = np.sum((chunk[:,0]-cx)*(chunk[:,1]-cy))
    theta = 0.5 * math.atan2(2*sxy, sxx - syy)          # 주축 각도
    direction = np.array([math.cos(theta), math.sin(theta)])
    chord = chunk[-1] - chunk[0]
    if direction @ chord < 0:                            # 진행 방향 부호 정렬
        direction = -direction
    return math.atan2(direction[1], direction[0])
----

이걸로 다시 돌리면 회전반경 중앙값이 0.56m → 1.65m로 3배 개선됩니다. 그런데도 78%가 여전히 5m 임계치 아래였습니다. 최악 케이스를 다시 보니 이번엔 패턴이 달랐습니다 — 대부분 **진출 후보가 1개뿐**(휴리스틱이 고를 여지 자체가 없었던 것)이었고, 그중 몇 개는 헤딩을 6점 피팅으로 고쳐도 여전히 130도가량 어긋나 있었습니다. 이건 7장에서 이미 만났던 **그룹핑 자체의 스퓨리어스 매치**로 보입니다.

== 완벽 대신 topology_warnings

이 지점에서 이 책이 택하는 태도는 7장과 같습니다 — 모든 케이스를 알고리즘으로 완벽하게 걸러내려 하지 않고, 회전반경이 임계치(예: 5m) 아래인 connection을 3장에서 만든 `topology_warnings`에 담아 사람이나 LLM 검토로 넘깁니다.

[source,python]
----
for c in connections:
    c["topology_warning"] = c["min_radius_m"] < 5.0
----

임계치 5m라는 값 자체도 사실 최종 확정은 아닙니다 — 6장 끝에서 미룬 것과 같은 문제입니다. "이 회전반경이 회귀 테스트에 실제로 문제가 되는가"는 결국 시뮬레이션의 정합 오차 허용 범위가 있어야 확정할 수 있습니다.

이 장까지 오면서 3부(그룹핑+교차로)의 결론은 명확합니다 — **낱개 lanelet을 도로망 구조로 재구성하는 작업은, 참조선 피팅(2부)만큼 혹은 그 이상으로 태그 관례·데이터 노이즈에 취약합니다.** 다음 장에서는 참조선 외에 아직 안 다룬 나머지 요소 — 고도, 횡단 경사, 신호등, 차선 마킹 — 을 정리합니다.
