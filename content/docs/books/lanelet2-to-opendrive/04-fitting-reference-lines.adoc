이 장부터 6장까지가 이 책의 핵심입니다. Lanelet2의 좌표점 나열을 OpenDRIVE의 참조선 수식으로 바꾸는 문제 하나를 세 장에 걸쳐 점점 정교하게 풀어나갑니다.

== 1단계: 구간을 나누고 각 구간을 Line/Arc로 근사한다

가장 직관적인 접근은 이렇습니다 — 점 나열을 곡률이 바뀌는 지점마다 잘라서 여러 구간으로 나누고, 각 구간을 직선(Line) 또는 원호(Arc) 중 더 잘 맞는 쪽으로 피팅합니다.

구간을 나누는 데는 **Ramer-Douglas-Peucker(RDP)** 알고리즘을 씁니다 — 원본 폴리라인에서 직선으로 근사해도 되는 부분은 점을 솎아내고, 실제로 꺾이는 지점(곡률이 바뀌는 지점)만 남깁니다.

[source,python]
----
def simplify_polyline(points, epsilon):
    """RDP: 직선으로 근사 가능한 점을 솎아내고, 곡률이 바뀌는 후보 지점만 남긴다."""
    def rdp(idxs):
        if len(idxs) < 3:
            return idxs
        start, end = points[idxs[0]], points[idxs[-1]]
        line_vec = end - start
        line_len = np.linalg.norm(line_vec)
        normal = np.array([-line_vec[1], line_vec[0]]) / line_len
        dists = np.abs((points[idxs[1:-1]] - start) @ normal)
        max_i = np.argmax(dists)
        if dists[max_i] > epsilon:
            split = idxs[1:-1][max_i]
            left = rdp(idxs[: idxs.index(split) + 1])
            right = rdp(idxs[idxs.index(split):])
            return left[:-1] + right
        return [idxs[0], idxs[-1]]
    return np.array(sorted(set(rdp(list(range(len(points)))))))
----

각 구간에는 직선 피팅(SVD로 최소자승 직선)과 원호 피팅(Kasa 방식 최소자승 원)을 둘 다 시도해서, 잔차가 더 작은 쪽을 채택합니다.

[source,python]
----
def fit_line(points):
    centroid = points.mean(axis=0)
    _, _, vt = np.linalg.svd(points - centroid)
    direction = vt[0]                          # 주성분 = 직선 방향
    normal = np.array([-direction[1], direction[0]])
    residuals = (points - centroid) @ normal    # 직선에서 각 점까지 수직 거리
    return direction, float(np.sqrt(np.mean(residuals**2)))

def fit_arc(points):
    x, y = points[:, 0], points[:, 1]
    def residual(params):
        cx, cy, r = params
        return np.sqrt((x-cx)**2 + (y-cy)**2) - r
    cx, cy, r = least_squares(residual, [x.mean(), y.mean(), np.ptp(x)/2]).x
    res = residual([cx, cy, r])
    return (cx, cy, r), float(np.sqrt(np.mean(res**2)))
----

이 정도만으로도 실제 맵에 돌려보면 결과가 꽤 정확합니다. 이 책의 예제 맵(`lanelet2_map.osm`, Autoware planning-simulator 샘플)의 lanelet 163개에 이 방식을 돌려보면, lanelet당 위치 잔차(최대)가 평균 1.06cm, p50 0.83cm, p95 2.82cm, 최악 케이스 8.54cm 수준으로 나옵니다. "이 정도면 다 됐다"고 생각하기 쉽습니다 — 하지만 여기서 잰 숫자가 놓치고 있는 게 있습니다.

== 이 방식이 놓치는 것: 이음새

각 구간을 **독립적으로** 피팅했다는 게 문제입니다. 구간 A를 피팅한 직선/원호와 구간 B를 피팅한 직선/원호는 서로의 존재를 모릅니다. 그러니 구간 A의 끝점과 구간 B의 시작점이 정확히 일치할 이유가 없고, 두 세그먼트의 방향(헤딩)이 매끄럽게 이어질 이유는 더더욱 없습니다.

이게 왜 문제인지는 2장에서 이미 짚었습니다 — OpenDRIVE의 `<geometry>` 체인은 "이전 세그먼트가 끝난 지점·방향에서 다음 세그먼트가 시작한다"는 걸 전제로 합니다. 독립 피팅으로 만든 세그먼트를 그대로 이어 붙이면, 이 전제가 깨집니다.

실측을 해보면 이 불연속이 상상보다 훨씬 큽니다. 163개 lanelet 중 세그먼트가 2개 이상인 89개에서 나오는 이음새 421개를 재보면:

위치 갭은 대부분 밀리미터~센티미터급이라 넘어갈 만하지만, **헤딩 꺾임이 평균 2.2도, 최대 44도**입니다. 참조선을 그대로 그려보면, 세그먼트 경계마다 도로가 눈에 띄게 꺾여 보입니다. "위치 잔차 2~3cm"라는 숫자가 무색해지는 지점입니다 — 위치는 맞는데 방향이 갑자기 꺾이니, 이 참조선을 따라 조향하는 차량은 그 지점마다 급격한 조향 명령을 받게 됩니다.

== 2단계(실패): 앞 세그먼트에 이어 붙이며 순서대로 피팅

직관적인 수정안은 이렇습니다 — 첫 세그먼트만 자유롭게 피팅하고, 이후 세그먼트는 이전 세그먼트의 끝점·끝헤딩에서 시작하도록 강제로 고정한 뒤 피팅합니다("탐욕적/greedy" 방식).

이 방식은 실패합니다. 앞 세그먼트의 피팅 오차가 뒤 세그먼트로 그대로 전파되기 때문입니다 — 뒤 세그먼트는 시작점·시작헤딩이 이미 고정돼 있어서 앞의 오차를 만회할 자유도가 없습니다. 실측해보면 독립 피팅 잔차(최대)가 평균 1.06cm였던 게, 탐욕적 방식에서는 평균 14.14cm, 최악 케이스는 1.14m까지 뛰어버립니다. RMS 잔차도 평균 0.33cm에서 4.92cm로 15배 가까이 뜁니다. 이음새는 완벽히 없앴지만 훨씬 나쁜 곡선이 나온 겁니다.

== 3단계: 전역 최적화 — 체인 전체를 한 번에 피팅한다

문제의 본질은 "구간별로 순서대로 피팅"한다는 접근 자체에 있습니다. 대신 참조선 체인 전체를 **OpenDRIVE가 실제로 쓰는 파라미터** — 시작 pose `(x₀, y₀, h₀)` + 세그먼트별 `(곡률 κᵢ, 길이 Lᵢ)` — 로 한꺼번에 표현하고, 이 전체 파라미터 벡터를 원본 점들과의 거리가 최소가 되도록 **한 번에** 최적화합니다.

이 표현에서는 이음새가 "제약"이 아니라 **파라미터화 자체의 성질**입니다 — 체인을 앞에서부터 순서대로 이어 그리는 함수를 쓰는 한, 세그먼트 사이 위치·헤딩은 항상 정확히 일치합니다. 애초에 어긋날 수가 없는 구조입니다.

[source,python]
----
def chain_sample(params, n_segs, ds=0.25):
    """params = [x0, y0, h0, κ_1..κ_n, L_1..L_n]인 체인을 ds 간격으로 샘플링한다."""
    x, y, h = params[0], params[1], params[2]
    kappas = params[3:3+n_segs]
    lengths = params[3+n_segs:]
    pts = [np.array([x, y])]
    for k, L in zip(kappas, lengths):
        n = max(int(np.ceil(L / ds)), 2)
        s = np.linspace(0, L, n+1)[1:]
        if abs(k) < 1e-9:                                   # 직선
            xs, ys = x + s*np.cos(h), y + s*np.sin(h)
        else:                                                # 원호
            xs = x + (np.sin(h + k*s) - np.sin(h)) / k
            ys = y - (np.cos(h + k*s) - np.cos(h)) / k
            h = h + k * L
        x, y = xs[-1], ys[-1]
        pts.append(np.stack([xs, ys], axis=1))
    return np.concatenate(pts, axis=0)


def fit_reference_line_global(centerline, epsilon=0.15):
    """독립 피팅 결과를 초기값으로 잡고, 체인 전체를 재최적화한다."""
    segs, _ = fit_reference_line_independent(centerline, epsilon)  # 1단계 결과를 초기값으로
    x0 = np.concatenate([segs[0]["start_pt"], [segs[0]["h_start"]],
                          [s["curvature"] for s in segs],
                          [max(s["length"], 0.2) for s in segs]])
    n_segs = len(segs)

    def residual(params):
        poly = chain_sample(params, n_segs)
        d = point_to_polyline_dist(centerline, poly)   # 원본 각 점 -> 체인까지 최단거리
        end_anchor = np.linalg.norm(poly[-1] - centerline[-1])  # 체인이 원본보다 심하게
        start_anchor = np.linalg.norm(poly[0] - centerline[0])  # 짧거나 길어지는 것 방지
        return np.concatenate([d, [end_anchor, start_anchor]])

    sol = least_squares(residual, x0, bounds=(...))  # κ, L에 적절한 범위를 준다
    return sol.x, n_segs
----

이 최적화를 163개 lanelet 전체에 돌려보면, 이음새는 정확히 0이 되고 위치 잔차(최대)는 평균 1.25cm(독립 피팅 1.06cm 대비 +0.19cm)로 거의 늘지 않습니다. RMS 잔차도 평균 0.33cm→0.50cm 수준입니다. **완전한 연속성을 아주 적은 비용으로 삽니다.** 다만 세그먼트가 2개 이상인 lanelet만 보면 곡률 계단(G2 불연속)이 평균 0.115 [1/m], 최악 0.615 [1/m]까지 남아있습니다 — 위치·헤딩은 완전히 이어 붙였어도 곡률이 매끄럽게 이어진다는 보장은 없다는 뜻이고, 세그먼트 개수를 늘려도(더 촘촘히 잘라도) 이 한계는 크게 안 없어집니다 — 이건 "조각별 상수 곡률" 모델 자체의 한계라는 뜻이고, 6장에서 이 문제를 다시 다룹니다.

여기까지가 이 장의 결론입니다: **참조선 피팅은 구간별로 따로 풀 문제가 아니라, 체인 전체를 하나의 최적화 문제로 풀어야 한다**는 것. 5장에서는 "애초에 무엇에 맞춰 피팅해야 하는가" — 즉 중심선 자체를 어떻게 정의할지 — 라는, 지금까지 당연하게 여겨온 질문을 다시 들여다봅니다.
