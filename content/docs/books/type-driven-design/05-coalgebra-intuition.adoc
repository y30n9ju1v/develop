== 4장의 transition에 출력을 더하기

4장의 `transition : State → Event → State`는 "다음 상태가 뭔지"만 알려줬습니다. 실전 FSM은 보통 상태 전이와 함께 **뭔가를 내놓기도** 합니다 — 카운터라면 "지금 몇인지", 자판기라면 "거스름돈이 얼마인지" 같은 출력입니다. 이걸 반영하면 함수의 모양이 이렇게 바뀝니다.

[source,lean]
----
inductive CounterEvent where
  | increment
  | reset

def counterCoalgebra (state : Nat) : CounterEvent → (Nat × Nat)
  | .increment => (state, state + 1)   -- 출력: 증가 전 값, 다음 상태: 증가된 값
  | .reset => (state, 0)

#eval counterCoalgebra 5 .increment  -- (5, 6)
#eval counterCoalgebra 5 .reset      -- (5, 0)
----

`State → Event → (Output × State)`가 이 장에서 다룰 일반형입니다. `increment` 이벤트를 받으면 "증가하기 *전* 값"을 출력하고 상태는 하나 늘립니다 — "지금 상태를 내놓으면서, 동시에 다음 상태로 넘어간다"는 게 이 모양의 핵심입니다.

== 왜 coalgebra라고 부르는가: algebra와 정반대 방향

`List.foldl`처럼 여러 값을 하나로 **모으는** 함수를 생각해봅시다 — `(Acc, Elem) → Acc`라는 모양으로, "여러 조각을 안으로 접어 들어가 하나의 결과를 만든다"는 방향입니다. 이런 "여러 개를 하나로 모으는" 구조를 범주론에서 **algebra**라고 부릅니다.

방금 만든 `counterCoalgebra`는 정확히 **반대 방향**입니다 — `State → (Output × State)`라는 모양은 "하나의 상태에서 시작해서, 관찰 가능한 조각(출력)을 하나씩 밖으로 꺼내며 다음 상태로 나아간다"는 뜻입니다. 안으로 접어 들어가는 게 아니라 **밖으로 펼쳐나가는** 방향이라, algebra의 반대라는 뜻에서 **coalgebra**라고 부릅니다("co-"라는 접두사가 범주론에서 흔히 "화살표 방향을 뒤집는다"는 뜻으로 쓰입니다). 정리하면 이렇습니다.

[cols="1,2,2"]
|===
|구분 |algebra |coalgebra

|방향
|여러 조각 → 하나로 모음
|하나의 상태 → 조각을 하나씩 꺼냄(밖으로 펼침)

|전형적인 모양
|`(Acc, Elem) → Acc` (예: `List.foldl`)
|`State → (Output × State)` (예: 상태 기계의 한 스텝)

|대표 예시
|리스트를 접어 합계를 구하기
|상태 기계를 한 스텝씩 실행하며 출력을 관찰하기
|===

== coalgebra를 값으로: MealyMachine 구조체

이 "carrier 타입에서 관찰 가능한 것을 꺼내는 함수"라는 패턴 자체를 값으로 만들어봅시다.

[source,lean]
----
structure MealyMachine (State Event Output : Type) where
  step : State → Event → (Output × State)

def counterMachine : MealyMachine Nat CounterEvent Nat :=
  { step := counterCoalgebra }
----

`MealyMachine`(입력 이벤트에 따라 출력이 달라지는 이런 종류의 기계를 전통적으로 Mealy 기계라고 부릅니다)은 "상태 타입, 이벤트 타입, 출력 타입, 그리고 그 셋을 잇는 `step` 함수"를 하나로 묶은 구조체입니다. 4장에서 이미 `transition`을 "값"으로 다뤘는데, 이 장에서는 그 값에 "구조체"라는 이름표를 붙이고 출력까지 일반화했을 뿐입니다.

== 기계를 구동하기: 이벤트 목록을 접어 출력 목록으로

[source,lean]
----
def MealyMachine.run (m : MealyMachine State Event Output)
    (init : State) : List Event → List Output × State
  | [] => ([], init)
  | e :: es =>
    let (o, s') := m.step init e
    let (os, sFinal) := m.run s' es
    (o :: os, sFinal)

#eval counterMachine.run 0 [.increment, .increment, .increment, .reset, .increment]
-- 출력: ([0, 1, 2, 3, 0], 1)

example : (counterMachine.run 0 [.increment, .increment, .increment]).2 = 3 := by native_decide
----

`run`은 이벤트 목록을 하나씩 소비하며 `step`을 반복 호출하는 **구동기(driver)**입니다. 흥미로운 지점은 `run` 자체가 이 장의 처음에 정의한 "algebra"(여러 이벤트를 접어 하나의 결과로 모으는 `List.foldl`류의 구조)라는 것입니다 — **coalgebra로 정의한 기계 하나를 반복 실행하는 일 자체는 algebra**입니다. 이 두 방향이 나란히 맞물려야 상태 기계가 "정의된 것"에서 "실제로 돌아가는 것"이 됩니다.

== 실전에서 이 관점이 주는 것

"coalgebra"라는 용어 자체를 실무 코드에 쓸 일은 거의 없습니다. 이 관점이 주는 실질적인 가치는 두 가지입니다.

* *상태 기계를 다른 것과 구분해서 볼 수 있게 해줍니다* — "지금 갖고 있는 게 여러 값을 하나로 모으는 문제(algebra)인지, 하나의 상태에서 관찰 가능한 것들을 계속 꺼내는 문제(coalgebra)인지"를 구분하면, 왜 어떤 로직은 `foldl` 하나로 깔끔히 끝나는데 어떤 로직은 자꾸 상태를 들고 다녀야 하는지가 분명해집니다.
* *합성의 실마리를 줍니다* — `MealyMachine`이 `State`, `Event`, `Output`이라는 세 타입 매개변수를 가진 구조체라는 걸 명확히 하면, "두 기계를 어떻게 합칠까"라는 질문이 "두 `State`를 어떻게 합칠까"(product나 sum으로, 1장에서 배운 바로 그 도구로)라는 훨씬 구체적인 질문으로 바뀝니다 — 다음 장의 주제입니다.

== 직접 해보기

* `MealyMachine Nat Unit Bool`(이벤트가 없고 `Unit`만 받는, 매번 "지금 짝수인지"를 출력하며 1씩 증가하는 기계)을 만들어보세요.
* `[(), (), ()]` 세 번을 `run`에 먹여, 초기 상태 0에서 출력이 `[true, false, true]`(0은 짝수, 1은 홀수, 2는 짝수)가 되는지 확인해보세요.

.해답 보기
[%collapsible]
====
[source,lean]
----
def isEvenCoalgebra (state : Nat) : Unit → (Bool × Nat)
  | () => (state % 2 = 0, state + 1)

def isEvenMachine : MealyMachine Nat Unit Bool :=
  { step := isEvenCoalgebra }

example : (isEvenMachine.run 0 [(), (), ()]).1 = [true, false, true] := by native_decide
----
====

== 요약

* algebra가 "여러 조각을 하나로 접어 모으는" 구조(`(Acc, Elem) → Acc`)라면, coalgebra는 그 반대로 "하나의 상태에서 관찰 가능한 조각을 계속 꺼내며 펼쳐나가는" 구조(`State → (Output × State)`)입니다.
* 상태 기계의 한 스텝(`step`)이 coalgebra이고, 그 기계를 여러 이벤트에 대해 반복 실행하는 `run`은 다시 algebra입니다 — 두 방향이 맞물려 실제로 동작하는 기계가 됩니다.
* 이 구분의 실전 가치는 "지금 다루는 게 모으는 문제인지 펼치는 문제인지"를 분명히 하고, 상태 기계를 `State`·`Event`·`Output` 세 타입으로 파라미터화된 값(`MealyMachine`)으로 다룰 수 있게 해준다는 데 있습니다.

다음 장에서는 이렇게 값이 된 상태 기계 두 개를 어떻게 합쳐 더 큰 상태 기계를 만드는지 다룹니다.
