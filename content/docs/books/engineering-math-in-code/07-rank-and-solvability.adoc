'''

6장의 회로는 운 좋게 유일한 답을 가졌습니다. 하지만 항상 그런 건 아닙니다 — 방정식 세 개를 세웠는데 사실 그중 하나가 나머지 둘의 조합에 지나지 않는다면(중복된 정보), 또는 서로 모순되는 조건을 담고 있다면 어떻게 될까요.

== 방정식이 중복되면: 해가 무한히 많다

이런 연립방정식을 봅시다 — 셋째 식이 사실 첫째 식과 둘째 식을 더한 것과 같습니다(`2x+0y+z=8`이 `(x+y+z=6)+(x-y=2)`와 같은 정보를 담고 있습니다).

[source,python]
----
import numpy as np

A1 = np.array([[1., 1., 1.],
               [1., -1., 0.],
               [2., 0., 1.]])   # 3행 = 1행 + 2행
b1 = np.array([6., 2., 8.])     # 8 = 6 + 2, 값도 앞뒤가 맞음

try:
    x = np.linalg.solve(A1, b1)
    print(x)
except np.linalg.LinAlgError as e:
    print("solve failed:", e)
----

[source]
----
solve failed: Singular matrix
----

`np.linalg.solve`가 **"특이행렬(singular matrix)이라 못 풀겠다"** 고 거부합니다 — 셋째 식이 새로운 정보를 하나도 안 주니, 실질적으로는 미지수 3개에 대한 조건이 2개뿐인 셈이고, 그러면 하나는 자유롭게 고를 수 있어서 답이 무한히 많아집니다.

== 랭크로 미리 알아채기

이 상황을 실행해보기 전에 미리 짚어낼 수 있는 도구가 **랭크(rank)** 입니다 — 행렬이 실제로 몇 개의 "독립적인" 조건을 담고 있는지를 나타내는 숫자입니다.

[source,python]
----
print("rank(A1):", np.linalg.matrix_rank(A1))
print("rank([A1|b1]):", np.linalg.matrix_rank(np.column_stack([A1,b1])))
----

[source]
----
rank(A1): 2
rank([A1|b1]): 2
----

미지수는 3개인데 `A1`의 랭크가 `2`뿐입니다 — 3개의 방정식이 실은 2개 분량의 독립적인 정보만 담고 있다는 뜻입니다. `A1`에 `b1`을 붙인 확장행렬의 랭크도 똑같이 `2`라는 건, 그 부족한 정보가 서로 모순되지는 않는다는(적어도 하나의 답은 존재한다는) 뜻입니다 — 종합하면 **"답은 존재하지만 유일하지 않다(무한히 많다)"** 는 결론이 나옵니다.

== `lstsq`로 무한히 많은 해 중 하나를 구하기

`np.linalg.solve`는 유일해만 다루므로, 해가 무한히 많은 경우엔 `np.linalg.lstsq`(least squares, 최소제곱법)를 대신 씁니다.

[source,python]
----
x_lstsq, res, rank, sv = np.linalg.lstsq(A1, b1, rcond=None)
print("lstsq solution:", x_lstsq)
print("check A1@x == b1:", A1@x_lstsq, "vs", b1)
----

[source]
----
lstsq solution: [3. 1. 2.]
check A1@x == b1: [6. 2. 8.] vs [6. 2. 8.]
----

`A1 @ x`가 `b1`과 **정확히** 일치합니다 — `lstsq`가 무한히 많은 답 중 하나(구체적으로는 크기가 가장 작은 답)를 골라 돌려줬고, 그게 원래 방정식을 실제로 만족한다는 걸 검산으로 확인했습니다.

== 방정식이 서로 모순되면: 해가 아예 없다

이번엔 셋째 식의 우변만 바꿔서, `100`이 `6+2`와 안 맞게 만들어봅니다.

[source,python]
----
A2 = A1.copy()
b2 = np.array([6., 2., 100.])   # 100 != 6+2 -> 모순

print("rank(A2):", np.linalg.matrix_rank(A2))
print("rank([A2|b2]):", np.linalg.matrix_rank(np.column_stack([A2,b2])))
----

[source]
----
rank(A2): 2
rank([A2|b2]): 3
----

이번엔 `A2`의 랭크(`2`)와 확장행렬의 랭크(`3`)가 **다릅니다** — `b2`를 붙이는 순간 새로운 독립 정보가 하나 더 생겼다는 뜻이고, 이건 그 정보가 `A2`의 기존 두 행과 모순된다는 신호입니다. `A`의 랭크와 `[A|b]`의 랭크를 비교하는 것만으로, 실제로 풀어보지 않고도 "이 시스템에 답이 있는지"를 미리 압니다.

[source,python]
----
x2, res2, rank2, sv2 = np.linalg.lstsq(A2, b2, rcond=None)
print("lstsq 'best fit' x:", x2)
print("residual A2@x - b2:", A2@x2 - b2)
----

[source]
----
lstsq 'best fit' x: [28.55555556 -4.11111111 12.22222222]
residual A2@x - b2: [ 30.66666667  30.66666667 -30.66666667]
----

이번엔 `lstsq`가 답을 주긴 하지만, `A2@x - b2`가 `[0,0,0]`이 **아닙니다** — 이건 진짜 해가 아니라 "가장 비슷하게 맞아떨어지는" 근사값(오차를 최소화하는 값)입니다. 6장의 답, 이번 장 첫 예제의 답, 이번 예제의 답을 비교하면 세 종류의 "풀림"이 전부 다르다는 게 뚜렷해집니다 — **유일한 정확한 해**(6장), **무한히 많은 정확한 해 중 하나**(이 장 첫 예제), **정확한 해는 없고 가장 가까운 근사값뿐**(이 장 둘째 예제).

== 직접 해보기

* 아래 시스템의 `rank(A)`와 `rank([A|b])`를 계산해서 해가 유일한지, 무한히 많은지, 없는지 먼저 예측한 다음, `np.linalg.solve` 또는 `np.linalg.lstsq`로 실제로 풀어서 예측이 맞는지 확인해보세요.

[source,python]
----
A3 = np.array([[1., 2., 3.],
               [2., 4., 6.],
               [1., 0., 1.]])
b3 = np.array([6., 12., 2.])
----

.해답 보기

====
[source,python]
----
print("rank(A3):", np.linalg.matrix_rank(A3))
print("rank([A3|b3]):", np.linalg.matrix_rank(np.column_stack([A3,b3])))
----

`rank(A3)`는 `2`입니다(2행이 1행의 정확히 2배라서 새 정보가 없습니다). `rank([A3|b3])`도 `2`입니다(`b3`의 둘째 원소 `12`도 첫째 원소 `6`의 정확히 2배라서, 이 중복도 서로 모순되지 않습니다). 랭크가 같으면서 미지수 개수(3)보다 작으므로 **해가 무한히 많은** 경우입니다 — `np.linalg.solve`는 특이행렬 오류를 낼 것이고, `np.linalg.lstsq`로 풀면 `A3@x`가 `b3`와 정확히 일치하는 답이 나옵니다.
====

== 요약

* 방정식이 중복된(다른 식들의 조합인) 연립방정식은 `np.linalg.solve`가 "특이행렬"이라며 풀기를 거부한다는 걸 실제로 확인했습니다.
* `rank(A)`와 `rank([A|b])`를 비교하면 실제로 풀어보지 않고도 해가 유일한지, 무한히 많은지, 아예 없는지 미리 알 수 있다는 걸 세 가지 예제로 확인했습니다.
* `lstsq`가 해가 무한히 많을 땐 정확히 원래 식을 만족하는 답을(검산 오차 0), 해가 아예 없을 땐 오차를 최소화하는 근사값을(검산 오차가 0이 아님) 준다는 차이도 직접 계산해서 구분했습니다.
