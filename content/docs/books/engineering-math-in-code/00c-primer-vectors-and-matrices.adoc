벡터를 "화살표"나 "좌표평면의 점"으로 배웠다면, 이 책의 3부(선형연립방정식)나 4부(고유값)에서 벡터가 화살표 같지 않은 맥락(연립방정식의 미지수들, 진동하는 질량들의 변위)에 계속 쓰이는 게 낯설 수 있습니다. 이 장은 화살표 이야기를 아예 빼고, **벡터를 "숫자 여러 개를 한 줄로 묶어놓은 것"** 이라는 훨씬 단순한 그림으로 다시 시작합니다.

== 벡터: 관련된 숫자 여러 개를 한 줄로

장을 보러 가서 사과, 우유, 빵을 삽니다. 각각의 가격(원)을 순서대로 적으면:

[source,python]
----
import numpy as np

prices = np.array([1000, 2000, 1500])   # [사과, 우유, 빵]
----

이게 벡터입니다 — 화살표도 아니고 좌표평면의 점도 아니고, **그냥 관련된 숫자 3개를 정해진 순서로 묶어놓은 것**입니다. "사과값이 1000원"이라는 사실과 "우유값이 2000원"이라는 사실을 따로 변수 두 개(`apple_price`, `milk_price`)로 관리하는 대신, `prices[0]`, `prices[1]`처럼 인덱스로 접근할 수 있는 묶음 하나로 관리하는 게 벡터의 실용적인 가치입니다.

같은 날 각각 몇 개씩 샀는지도 벡터로 적을 수 있습니다.

[source,python]
----
quantities = np.array([3, 2, 1])   # 사과 3개, 우유 2개, 빵 1개
----

== 벡터의 내적: "짝지어 곱하고 다 더하기"

오늘 장본 총액은 얼마일까요 — "각 물건의 가격과 개수를 짝지어 곱한 다음, 전부 더한다"입니다.

[source,python]
----
total = sum(p * q for p, q in zip(prices, quantities))
print("총액:", total)
----

[source]
----
총액: 8500
----

이 "짝지어 곱하고 다 더하기" 연산에는 이름이 있습니다 — **내적(dot product)** 입니다. NumPy는 이걸 함수 하나로 제공합니다.

[source,python]
----
total_np = np.dot(prices, quantities)
print("np.dot 결과:", total_np)
----

[source]
----
np.dot 결과: 8500
----

직접 짠 반복문과 `np.dot`이 정확히 같은 값을 냅니다 — `np.dot`은 "짝지어 곱하고 더한다"는 이 단순한 절차를 벡터 크기가 얼마든 한 줄로 처리해주는 함수일 뿐입니다.

== 행렬: 벡터를 여러 줄 쌓은 표

월요일과 화요일에 각각 다른 수량을 샀다면, 두 줄짜리 표로 적을 수 있습니다.

[source,python]
----
Q = np.array([
    [3, 2, 1],   # 월요일: 사과 3, 우유 2, 빵 1
    [1, 0, 4],   # 화요일: 사과 1, 우유 0, 빵 4
])
----

이게 **행렬**입니다 — 벡터(한 줄)를 여러 개 쌓아놓은 **표**입니다. 각 요일의 총액을 한 번에 구하려면, 각 줄(각 요일의 구매 수량 벡터)에 대해 `prices`와 내적을 하면 됩니다 — NumPy에서는 `@` 연산자(또는 `np.matmul`)가 "행렬의 각 행마다 벡터와 내적을 해서, 그 결과들을 새 벡터로 모아준다"는 일을 합니다.

[source,python]
----
totals = Q @ prices
print("월,화 총액:", totals)
----

[source]
----
월,화 총액: [8500 7000]
----

손으로 검산해봅니다 — 월요일은 `3×1000 + 2×2000 + 1×1500 = 8500`, 화요일은 `1×1000 + 0×2000 + 4×1500 = 7000`. 정확히 일치합니다.

== 이 책에서 행렬-벡터 곱을 볼 때마다

이 책 6장부터는 "행렬 `A`와 벡터 `x`를 곱해서 `b`를 얻는다"(`Ax=b`)는 표현이 반복해서 나옵니다. 지금 확인한 장보기 예제로 옮기면 — `A`는 "여러 시나리오(요일)에서 각 항목을 얼마나 샀는가"를 담은 표이고, `x`는 "항목별 단가"이고, 곱한 결과 `b`는 "시나리오별 총액"입니다. 6장부터는 이 "항목"과 "시나리오"가 회로의 미지 전류나 진동하는 질량의 변위처럼 훨씬 추상적인 것으로 바뀌지만, **연산 자체("각 행마다 짝지어 곱하고 더하기")는 이 장에서 확인한 것과 완전히 동일합니다.**

== 직접 해보기

물건이 4종류(사과, 우유, 빵, 계란)이고 사흘치 구매 기록이 있다고 합시다. 가격 벡터와 3×4 수량 행렬을 직접 만들어 하루치 총액 벡터를 계산해보세요.

.해답 보기
[%collapsible]
====
[source,python]
----
prices2 = np.array([1000, 2000, 1500, 300])  # 사과, 우유, 빵, 계란
Q2 = np.array([
    [3, 2, 1, 6],   # 월요일
    [1, 0, 4, 0],   # 화요일
    [0, 1, 2, 12],  # 수요일
])
totals2 = Q2 @ prices2
print("월,화,수 총액:", totals2)
----

[source]
----
월,화,수 총액: [10300  7000  8600]
----

행렬이 3×4(3개 시나리오 × 4개 항목)이고 벡터가 길이 4(항목 4개)라서, 곱하면 길이 3짜리 결과(시나리오 3개의 총액)가 나옵니다 — "행렬의 열 개수"와 "벡터의 길이"가 맞아야 곱셈이 성립한다는 규칙도, 이 예제에서는 "항목 종류 수가 서로 맞아야 짝지어 곱할 수 있다"는 당연한 요구사항으로 자연스럽게 이해됩니다.
