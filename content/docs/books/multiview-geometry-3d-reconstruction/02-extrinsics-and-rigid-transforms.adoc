1장에서는 카메라 좌표계 안의 점을 픽셀로 투영하는 법을 다뤘습니다. 그런데 실제로 다루는 3D 점은 대개 **세계 좌표계**(장면 전체에 고정된, 카메라와 무관한 좌표계)로 주어집니다 — 이 장에서는 세계 좌표계와 카메라 좌표계를 잇는 다리, **외부 파라미터(extrinsics)**를 다룹니다.

== 카메라도 세계 안의 물체다

카메라는 세계 좌표계 안 어딘가에 특정 위치와 방향으로 놓여 있습니다. 이 "위치와 방향"을 **강체 변환(rigid transformation)** — 회전 `R`(3×3 회전행렬)과 이동 `t`(3차원 벡터) — 으로 표현합니다. 세계 좌표계의 점 `X_world`를 카메라 좌표계로 옮기는 공식은 다음과 같습니다.

[source,python]
----
import numpy as np

def rotation_z(theta):
    c, s = np.cos(theta), np.sin(theta)
    return np.array([
        [c, -s, 0],
        [s,  c, 0],
        [0,  0, 1],
    ])

def world_to_camera(R, t, X_world):
    """세계 좌표계의 점을 카메라 좌표계로 옮긴다: X_cam = R @ X_world + t"""
    return R @ X_world + t
----

`rotation_z`는 z축을 기준으로 각도 `theta`만큼 회전하는 행렬을 만듭니다(카메라가 정확히 어느 방향을 보는지를 나타내는 세 축 회전 중 하나입니다). `world_to_camera`가 바로 외부 파라미터의 핵심 공식 `X_cam = R·X_world + t`입니다 — `R`은 세계 좌표축과 카메라 좌표축 사이의 방향 차이를, `t`는 원점의 위치 차이를 흡수합니다.

== 카메라 중심으로부터 t를 구성하기

`t`를 직접 다루기보다, "카메라가 세계 좌표계의 어느 점 `C`에 있는가"로 생각하는 게 더 직관적입니다. 카메라 중심 `C`가 카메라 좌표계에서는 항상 원점이어야 하므로, `R·C + t = 0`이 성립해야 하고, 여기서 `t = -R·C`가 나옵니다.

[source,python]
----
theta = np.pi / 2
R = rotation_z(theta)
C = np.array([2.0, 0.0, 0.0])   # 카메라 중심의 세계 좌표
t = -R @ C                       # 표준 형식: X_cam = R(X_world - C) = R X_world - R C
----

카메라가 세계 좌표 `(2, 0, 0)`에 위치하고, z축 기준으로 90도 회전해 있는 상황입니다.

== 세계 좌표를 카메라 좌표로 옮겨 확인하기

[source,python]
----
X_world = np.array([2.0, 1.0, 0.0])  # 카메라 중심에서 세계좌표 (0,1,0)만큼 떨어진 점
X_cam = world_to_camera(R, t, X_world)
print("X_cam:", X_cam)  # [-1.  0.  0.]
assert np.allclose(X_cam, [-1.0, 0.0, 0.0], atol=1e-10)
----

카메라 중심에서 이 점까지의 세계좌표 변위는 `(0, 1, 0)`입니다. 여기에 90도 회전을 적용하면(`rotation_z(90°)`는 `x`축을 `y`축으로, `y`축을 `-x`축으로 보냅니다), 변위가 카메라 좌표계에서는 `(-1, 0, 0)`이 됩니다 — 코드의 결과와 정확히 일치합니다. 회전이 세계 좌표계의 변위 벡터를 카메라가 "느끼는" 방향으로 다시 표현해준다는 게 핵심입니다.

== 검증: 카메라 중심은 항상 원점으로 간다

[source,python]
----
C_in_cam = world_to_camera(R, t, C)
print("C_in_cam:", C_in_cam)  # [0. 0. 0.]
assert np.allclose(C_in_cam, [0.0, 0.0, 0.0], atol=1e-10)
----

`t = -R·C`를 이렇게 구성한 이유가 정확히 이것입니다 — 카메라 자기 자신의 위치를 카메라 좌표계로 옮기면 항상 원점이어야 하고, 실제로 그렇게 나옵니다. 외부 파라미터를 다룰 때 흔히 하는 실수가 `t`를 "카메라의 위치"라고 착각하는 것인데, 실제로는 `t = -R·C`라는 관계로 카메라 중심 `C`와 연결되어 있을 뿐 `t` 자체가 위치는 아닙니다.

== 회전행렬의 필수 조건

[source,python]
----
assert np.allclose(R.T @ R, np.eye(3), atol=1e-10)
assert np.isclose(np.linalg.det(R), 1.0)
----

아무 3×3 행렬이나 회전을 나타낼 수 있는 건 아닙니다 — 진짜 회전행렬은 **직교(orthogonal)**해야 합니다(`RᵀR = I`, 즉 행렬을 곱한 자기 자신의 전치가 항등행렬이 되어야 합니다 — 길이와 각도를 보존한다는 뜻입니다), 그리고 행렬식이 `+1`이어야 합니다(행렬식이 `-1`이면 반사가 섞여 들어간 것이라 순수한 회전이 아닙니다). 이 두 조건을 만족하는 행렬들의 모임을 `SO(3)`(3차원 특수직교군)이라고 부릅니다 — 카메라의 방향은 항상 이 `SO(3)`의 원소로 표현됩니다.

== 직접 해보기

* 카메라가 세계 좌표 `(0, 0, -3)`에 위치하고 회전이 없다고(`R = I`) 할 때, 세계 좌표 `(1, 1, 0)`인 점의 카메라 좌표를 계산해보세요.

.해답 보기
[%collapsible]
====
[source,python]
----
R_id = np.eye(3)
C2 = np.array([0.0, 0.0, -3.0])
t2 = -R_id @ C2

X_world2 = np.array([1.0, 1.0, 0.0])
X_cam2 = world_to_camera(R_id, t2, X_world2)
print(X_cam2)  # [1. 1. 3.]
assert np.allclose(X_cam2, [1.0, 1.0, 3.0])
----

회전이 없으므로 카메라 좌표는 그냥 세계 좌표에서 카메라 중심을 뺀 것과 같습니다 — `(1,1,0) - (0,0,-3) = (1,1,3)`. `Z=3`이 양수라는 것도 확인할 만합니다 — 카메라가 정면(양의 Z 방향)으로 보고 있는 곳에 점이 있다는 뜻입니다.
====

== 요약

* 외부 파라미터(`R`, `t`)는 세계 좌표계와 카메라 좌표계를 잇는 강체 변환이고, `X_cam = R·X_world + t`로 계산합니다.
* `t = -R·C`라는 관계로, 카메라 중심 `C`의 위치와 `t`가 연결됩니다 — `t` 자체는 카메라의 위치가 아닙니다.
* 회전행렬은 직교(`RᵀR=I`)하고 행렬식이 `+1`이어야 하며, 이런 행렬들의 모임을 `SO(3)`이라고 부릅니다.
