4장에서는 두 카메라의 자세(`R`, `t`)를 **이미 알고 있다는 전제**로 본질행렬 `E`를 만들었습니다. 실전은 거꾸로입니다 — 여러 대응점 쌍으로부터 먼저 `E`를 추정하고, 그 `E`에서 `R`과 `t`를 **역으로 복원**해야 합니다. 이 장에서는 그 복원 과정을 다룹니다.

== 본질행렬을 SVD로 분해하기

`E = [t]_× R`이라는 구성 방식을 거꾸로 풀면, `E`의 특이값분해(SVD)로부터 `R`과 `t`의 후보를 뽑아낼 수 있습니다.

[source,python]
----
import numpy as np

def decompose_essential(E):
    U, S, Vt = np.linalg.svd(E)
    # 본질행렬은 특이값이 (s,s,0) 형태여야 한다; 부호 문제를 피하기 위해 det(U), det(Vt)를 +1로 정규화
    if np.linalg.det(U) < 0:
        U = -U
    if np.linalg.det(Vt) < 0:
        Vt = -Vt
    W = np.array([[0, -1, 0], [1, 0, 0], [0, 0, 1]])
    R_a = U @ W @ Vt
    R_b = U @ W.T @ Vt
    t_unit = U[:, 2]
    return [(R_a, t_unit), (R_a, -t_unit), (R_b, t_unit), (R_b, -t_unit)]
----

`W`라는 고정된 90도 회전 행렬을 매개로, `U`와 `Vt`를 조합하면 두 가지 회전 후보(`R_a`, `R_b`)가 나오고, 이동 방향은 `U`의 세 번째 열(`t_unit`)이거나 그 반대 부호(`-t_unit`)일 수 있습니다 — 회전 2가지 × 이동 부호 2가지로 **총 4가지 후보**가 나옵니다. 이 대수적 사실 자체는 이 책에서 유도하지 않지만(선형대수 교재의 SVD 성질에서 나옵니다), 실제로 후보들의 행렬식이 전부 `+1`(진짜 회전행렬)이 되는지는 코드로 바로 확인할 수 있습니다.

[source,python]
----
for i, (Rc, tc) in enumerate(candidates):
    print(i, "det(R)=", np.linalg.det(Rc))  # 네 후보 모두 1.0
----

== 진짜 해는 하나뿐: 카이랄리티 조건

네 후보 중 딱 하나만 물리적으로 말이 됩니다 — **삼각측량한 3D 점이 두 카메라 모두의 앞쪽(양의 깊이)에 있어야** 합니다. 카메라 뒤에서 물체가 보일 수는 없으니까요. 이 조건을 **카이랄리티(cheirality)**라고 부릅니다.

[source,python]
----
def triangulate_point(K, R1, t1, R2, t2, x1, x2):
    def proj_matrix(R, t):
        return K @ np.hstack([R, t.reshape(3, 1)])
    P1, P2 = proj_matrix(R1, t1), proj_matrix(R2, t2)
    A = np.array([
        x1[0] * P1[2] - P1[0],
        x1[1] * P1[2] - P1[1],
        x2[0] * P2[2] - P2[0],
        x2[1] * P2[2] - P2[1],
    ])
    _, _, Vt = np.linalg.svd(A)
    X_h = Vt[-1]
    return X_h[:3] / X_h[3]
----

이 삼각측량 함수(선형 방법, DLT)는 6장에서 자세히 다룹니다 — 여기서는 "두 카메라의 투영 방정식을 동시에 만족하는 3D 점을 SVD로 찾는다"는 결과만 재사용합니다.

== 네 후보를 실제로 걸러보기

[source,python]
----
def cheirality_score(R1, t1, Rc, tc, x1, x2):
    X = triangulate_point(K, R1, t1, Rc, tc, x1, x2)
    depth1 = (R1 @ X + t1)[2]
    depth2 = (Rc @ X + tc)[2]
    return depth1, depth2

for i, (Rc, tc) in enumerate(candidates):
    d1, d2 = cheirality_score(R1, t1, Rc, tc, x1, x2)
    print(f"candidate {i}: depth1={d1:.3f} depth2={d2:.3f}")
----

4장과 같은 설정(카메라1은 원점, 카메라2는 오른쪽 `0.5m` 이동 + `10°` 회전)에서 실제로 계산해보면 이렇게 나옵니다.

[source]
----
candidate 0: depth1=30.000  depth2=-29.892
candidate 1: depth1=-30.000 depth2=29.892
candidate 2: depth1=6.000   depth2=5.978
candidate 3: depth1=-6.000  depth2=-5.978
----

후보 0과 1은 둘 중 한 카메라에서 깊이가 음수입니다(물체가 카메라 뒤에 있다는 뜻이라 불가능). 후보 3은 **둘 다** 음수입니다. **오직 후보 2만 두 깊이가 모두 양수**입니다 — 이게 유일하게 물리적으로 타당한 해입니다.

[source,python]
----
best_idx, best_R, best_t = None, None, None
for i, (Rc, tc) in enumerate(candidates):
    d1, d2 = cheirality_score(R1, t1, Rc, tc, x1, x2)
    if d1 > 0 and d2 > 0:
        best_idx, best_R, best_t = i, Rc, tc

assert best_idx == 2
assert np.allclose(best_R, R2, atol=1e-8)
----

골라낸 회전 `best_R`이 4장에서 우리가 직접 정의했던 진짜 회전 `R2`와 소수점 8자리까지 정확히 일치합니다 — 대응점 **딱 한 쌍**만으로도 네 후보 중 진짜 해를 가려낼 수 있다는 걸 확인했습니다(실전에서는 잡음에 강해지도록 여러 점으로 다수결을 냅니다).

== 이동은 방향까지만 복원된다

[source,python]
----
t2_unit = t2 / np.linalg.norm(t2)
assert np.allclose(best_t, t2_unit, atol=1e-8) or np.allclose(best_t, -t2_unit, atol=1e-8)
print("recovered t (unit):", best_t)  # [-0.985  0.     0.174]
print("true t (unit):", t2_unit)       # [-0.985  0.     0.174]
----

복원된 이동 벡터는 **단위벡터(길이 1)로 정규화된 방향**만 정확히 맞습니다 — 실제 이동 거리(`0.5m`)라는 절대적인 크기는 두 사진만으로는 알 수 없습니다. 이건 우연한 한계가 아니라 근본적인 성질입니다 — 카메라 사이 거리를 2배로 늘리면서 장면 전체 크기도 2배로 늘리면, 두 사진에 찍히는 픽셀은 완전히 똑같습니다("멀리 있는 큰 것"과 "가까이 있는 작은 것"을 구별 못 한다는 1장의 관찰이 여기서 스케일 전체로 확장된 것입니다). 그래서 단안(monocular) 카메라만으로 재구성하면 항상 "실제 크기를 모르는" 재구성이 나오고, 절대 크기를 알려면 스테레오 카메라의 기준선 길이나 GPS 같은 외부 정보가 필요합니다.

== 요약

* 본질행렬 `E`를 SVD로 분해하면 회전 2가지 × 이동 부호 2가지, 총 4가지 `(R, t)` 후보가 나옵니다.
* 삼각측량한 점이 두 카메라 모두의 앞쪽(양의 깊이)에 있어야 한다는 카이랄리티 조건으로, 네 후보 중 물리적으로 타당한 해를 정확히 하나로 좁힐 수 있습니다.
* 복원되는 이동은 방향만 정확하고 절대 크기(스케일)는 알 수 없습니다 — 단안 카메라 재구성의 근본적인 한계입니다.
