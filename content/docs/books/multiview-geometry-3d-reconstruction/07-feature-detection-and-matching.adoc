4~6장에서는 대응점 쌍 `(x1, x2)`가 이미 주어졌다고 가정했습니다. 실전에서는 이 대응점부터 직접 찾아야 합니다 — 이 장에서 그 과정을 처음부터 구현합니다.

== 어떤 점이 "특징점"이 될 자격이 있는가

사진 두 장에서 같은 3D 점을 다시 찾아내려면, 그 점이 주변과 뚜렷이 구별되는 지점이어야 합니다. 매끈한 벽 한가운데의 한 점은 옆으로 몇 픽셀 옮겨도 똑같아 보여서 다시 찾을 수 없습니다 — 반면 **모서리(코너)**는 어느 방향으로 조금만 움직여도 밝기가 확 달라지기 때문에 위치를 특정하기 좋습니다. 이 장에서는 이 직관을 정확한 수식으로 표현하는 **해리스 코너 검출기(Harris corner detector)**를 구현합니다.

== 해리스 코너 응답

한 지점 주변의 작은 창(window)을 아주 조금 이동시켰을 때, 밝기가 얼마나 달라지는지를 2×2 행렬(구조 텐서, structure tensor) `M`으로 요약할 수 있습니다. 평평한 영역에서는 `M`이 거의 영행렬이고, 한 방향의 경계(edge)에서는 한 방향으로만 크고, 코너에서는 **모든 방향**으로 큽니다. 이 차이를 하나의 숫자로 압축한 게 해리스 응답입니다.

[source,python]
----
import numpy as np
from scipy.ndimage import uniform_filter, shift as ndi_shift

def harris_response(img, k=0.04, window=3):
    """해리스 코너 응답을 계산한다: R = det(M) - k*trace(M)^2"""
    Iy, Ix = np.gradient(img)
    Ixx, Iyy, Ixy = Ix * Ix, Iy * Iy, Ix * Iy
    Sxx = uniform_filter(Ixx, size=window)
    Syy = uniform_filter(Iyy, size=window)
    Sxy = uniform_filter(Ixy, size=window)
    det = Sxx * Syy - Sxy * Sxy
    trace = Sxx + Syy
    return det - k * trace ** 2
----

`Ix`, `Iy`는 가로·세로 방향의 밝기 변화율(그라디언트)이고, `Sxx, Syy, Sxy`는 그 변화율들을 작은 창 안에서 평균 낸 것입니다(`uniform_filter`가 이 창 평균을 구합니다) — 이게 구조 텐서 `M`의 세 성분입니다. `det(M) = Sxx·Syy - Sxy²`는 두 방향 모두로 변화가 커야 커지고, `trace(M) = Sxx+Syy`로 큰 값에 페널티를 줘서(`k·trace²`), 단순히 밝기 변화가 큰 경계(edge)와 진짜 코너를 구별합니다.

== 코너 검출: 임계값과 비최대 억제

[source,python]
----
def detect_corners(img, thresh_ratio=0.3, min_dist=5):
    R = harris_response(img)
    thresh = thresh_ratio * R.max()
    candidates = np.argwhere(R > thresh)
    # 비최대 억제(non-max suppression): 가까운 후보 중 응답이 가장 큰 것만 남긴다
    candidates = sorted(candidates.tolist(), key=lambda rc: -R[rc[0], rc[1]])
    kept = []
    for (r, c) in candidates:
        if all((r - kr) ** 2 + (c - kc) ** 2 > min_dist ** 2 for kr, kc in kept):
            kept.append((r, c))
    return np.array(kept)
----

응답이 충분히 큰 지점을 후보로 뽑은 뒤(`thresh_ratio`), 서로 너무 가까운 후보들은 응답이 가장 큰 것 하나만 남깁니다(**비최대 억제**) — 코너 하나 주변에서 응답이 뭉텅이로 커지는 경향이 있어서, 이 과정 없이는 같은 코너가 여러 번 검출됩니다.

== 합성 이미지로 검출 확인하기

[source,python]
----
def make_synthetic_image(size=60, squares=((15, 15), (40, 20), (25, 45)),
                          intensities=(1.0, 0.7, 0.4)):
    """어두운 배경에 밝기가 다른 정사각형 몇 개를 그려 넣은 합성 이미지. 각 정사각형의 모서리가 코너다."""
    img = np.zeros((size, size), dtype=np.float64)
    for (r, c), val in zip(squares, intensities):
        img[r:r+6, c:c+6] = val
    return img

img1 = make_synthetic_image()
corners1 = detect_corners(img1)
print(corners1)
# [[15 15] [20 20] [15 21] [20 14]]
----

가짜 이미지에 밝기가 서로 다른 정사각형 세 개를 심어뒀습니다(각 정사각형의 네 모서리가 진짜 코너입니다). 검출된 코너 4개가 전부 가장 밝은(대비가 가장 큰) 정사각형의 네 모서리와 정확히 일치합니다 — 나머지 두 정사각형은 배경과의 대비가 약해서 이 임계값을 넘지 못했습니다. 밝기 대비가 클수록 그라디언트가 크고, 그라디언트가 클수록 해리스 응답이 커진다는 게 실제 숫자로 확인됩니다.

== 두 번째 사진과 대응점 매칭

이제 카메라가 이동해서 찍은 "두 번째 사진"을 시뮬레이션합니다 — 여기서는 단순화를 위해 첫 번째 이미지를 그대로 몇 픽셀 이동시킵니다.

[source,python]
----
dy, dx = -2.0, 4.0
img2 = ndi_shift(img1, shift=(dy, dx), order=1, mode="constant", cval=0.0)
corners2 = detect_corners(img2)
----

이제 `img1`의 코너 하나하나에 대해, `img2`의 코너들 중 **주변 픽셀 패치가 가장 비슷한 것**을 찾습니다.

[source,python]
----
def extract_patch(img, rc, half=4):
    r, c = rc
    return img[r-half:r+half+1, c-half:c+half+1]

def match_by_ssd(corners_a, corners_b, img_a, img_b, half=4):
    matches = []
    for ca in corners_a:
        patch_a = extract_patch(img_a, ca, half)
        best_j, best_score = None, np.inf
        for j, cb in enumerate(corners_b):
            patch_b = extract_patch(img_b, cb, half)
            score = np.sum((patch_a - patch_b) ** 2)  # SSD: 제곱오차합
            if score < best_score:
                best_score, best_j = score, j
        matches.append((tuple(ca), tuple(corners_b[best_j]), best_score))
    return matches
----

**SSD(Sum of Squared Differences)**는 두 패치를 픽셀 단위로 뺀 뒤 제곱해서 더한 값입니다 — 두 패치가 똑같으면 `0`이고, 다를수록 커집니다. `img1`의 코너마다 `img2`의 모든 코너와 SSD를 계산해서 가장 작은(가장 닮은) 쪽을 대응점으로 고릅니다.

== 매칭 결과가 실제 이동량과 일치하는지 검증

[source,python]
----
matches = match_by_ssd(corners1, corners2, img1, img2)
for ca, cb, score in matches:
    predicted = (ca[0] + dy, ca[1] + dx)
    err = abs(predicted[0] - cb[0]) + abs(predicted[1] - cb[1])
    print(ca, "->", cb, "score=", score, "err=", err)
    assert err <= 1.0
----

네 쌍 모두 SSD 점수가 정확히 `0`(패치가 완전히 일치)이고, 매칭된 위치가 "원래 좌표 + 실제 이동량(`dy, dx`)"과 오차 `1픽셀` 이내로 맞아떨어집니다 — 우리가 만든 코너 검출기와 매칭기가, 카메라 이동을 전혀 모르는 상태에서도 순전히 이미지의 밝기 패턴만 보고 올바른 대응점을 정확히 찾아냈다는 뜻입니다.

== 실전에서는 왜 이보다 훨씬 정교한 방법을 쓰는가

이 장의 SSD 패치 매칭은 원리를 보여주기 위한 가장 단순한 형태입니다. 실전(그리고 3DGS 파이프라인이 실제로 쓰는 COLMAP 같은 도구)에서는 SIFT나 ORB 같은, 회전·크기·조명 변화에 강건한(invariant) 특징 기술자(descriptor)를 씁니다 — 이 장의 정사각형 예제처럼 카메라가 딱 평행이동만 하는 경우는 실전에 거의 없고, 회전하거나 가까워지거나 멀어지면 패치 자체의 모양이 바뀌기 때문입니다. 다만 "특징점을 찾고, 패치나 기술자를 비교해서 가장 비슷한 것끼리 짝짓는다"는 이 장의 큰 흐름 자체는 어떤 특징점 검출기·기술자를 쓰든 동일합니다.

== 직접 해보기

* 세 번째 정사각형(중간 밝기, `intensities[1]=0.7`)이 검출되도록 `thresh_ratio`를 낮춰보고(`0.3` 대신 `0.05` 시도), 검출되는 코너 개수가 몇 개로 늘어나는지 확인해보세요.

== 요약

* 해리스 코너 검출기는 밝기 변화가 모든 방향으로 큰 지점(구조 텐서의 행렬식이 크고 대각합에 비해 균형 잡힌 지점)을 코너로 판정합니다.
* 비최대 억제로 같은 코너가 중복 검출되는 걸 막습니다.
* SSD 같은 패치 비교로 서로 다른 두 이미지의 코너들을 짝짓고, 짝지어진 결과가 실제 카메라 이동량과 일치하는지 확인했습니다.
* 실전에서는 회전·크기 변화에 강건한 SIFT/ORB 같은 기술자를 쓰지만, "검출 → 비교 → 매칭"이라는 큰 흐름은 동일합니다.
