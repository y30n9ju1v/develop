'''

3부까지는 이미 다 찍어둔 사진 뭉치를 통째로 받아 오프라인으로 재구성했습니다. 자율주행차는 다릅니다 — 사진이 실시간으로 한 장씩 들어오고, 그때그때 "지금 내가 어디에 있는가"를 바로 알아야 합니다. 이 장에서는 이 문제, **SLAM(Simultaneous Localization and Mapping)**을 SfM과 비교하며 소개합니다.

== SfM과 SLAM, 무엇이 다른가

SfM(3부)과 SLAM은 풀고 있는 수학 문제 자체는 거의 같습니다 — 카메라 자세와 3D 점을 동시에 복원한다는 목표는 동일합니다. 차이는 **조건**에 있습니다.

* **SfM**: 사진이 전부 미리 주어져 있고, 순서도 상관없습니다(8장에서 "세 번째 카메라를 추가한다"고 했을 때, 사실 어떤 순서로 추가해도 됩니다). 시간제한 없이 충분히 오래 계산해서 최선의 답(9장의 번들 조정)을 낼 수 있습니다.
* **SLAM**: 사진(또는 라이다 스캔)이 센서에서 실시간으로 하나씩 들어오고, **그 순간 즉시** "지금 위치가 어디인지" 답을 내놓아야 합니다. 나중에 들어올 정보를 기다릴 수 없고, 계산 시간도 한정되어 있습니다(자율주행차는 매 프레임 수십 밀리초 안에 답해야 합니다).

이 "실시간"이라는 제약 때문에, SLAM은 9장의 번들 조정처럼 모든 걸 한꺼번에 다시 최적화할 여유가 없습니다 — 대신 "지금까지의 추정"에 "새로 들어온 정보"를 빠르게 얹어가는 방식을 씁니다. 이 장에서는 그 가장 단순한 형태, **오도메트리 체이닝(odometry chaining)**을 구현하고, 그 결과 어떤 문제가 생기는지 직접 확인합니다.

== 상대 자세를 이어붙이기

연속된 두 프레임 사이의 상대적인 움직임(4~6장에서 다룬 두 카메라 사이의 상대 자세)을 알면, 그걸 계속 이어붙여서 전체 궤적을 재구성할 수 있습니다.

[source,python]
----
import numpy as np

def se3_compose(R_a, t_a, R_b, t_b):
    """두 강체 변환을 이어붙인다: 먼저 b, 그다음 a를 적용한 것과 같은 하나의 변환."""
    return R_a @ R_b, R_a @ t_b + t_a

def chain_odometry(relatives, start_pose):
    poses = [start_pose]
    R_cur, t_cur = start_pose
    for R_rel, t_rel in relatives:
        R_cur, t_cur = se3_compose(R_cur, t_cur, R_rel, t_rel)
        poses.append((R_cur, t_cur))
    return poses
----

`se3_compose`는 2장에서 배운 강체 변환 두 개를 하나로 합치는 함수입니다(2장의 `world_to_camera`와 본질적으로 같은 연산을 반복 적용하는 것뿐입니다). `chain_odometry`가 SLAM 프론트엔드의 가장 단순한 형태입니다 — 매 프레임 "직전 프레임 대비 얼마나 움직였는가"(상대 자세)만 알면, 그걸 누적해서 "지금 세계 좌표계에서 어디에 있는가"(절대 자세)를 실시간으로 계속 갱신할 수 있습니다.

== 원을 그리며 도는 차량 시뮬레이션

[source,python]
----
n_steps = 20
radius = 5.0
true_poses = []
for i in range(n_steps + 1):
    angle = 2 * np.pi * i / n_steps
    R = rotation_z(angle + np.pi / 2)
    t = np.array([radius * np.cos(angle), radius * np.sin(angle), 0.0])
    true_poses.append((R, t))
----

반지름 `5m`인 원을 `20`스텝으로 한 바퀴 도는 차량을 시뮬레이션합니다 — 스텝 `0`과 스텝 `20`은 **정확히 같은 위치**여야 합니다(원을 한 바퀴 돌아 제자리로 왔으니까요). 이 성질을 뒤에서 검증에 씁니다.

== 상대 자세 추정의 잡음

[source,python]
----
def add_noise(R_rel, t_rel, rot_sigma=0.01, trans_sigma=0.01):
    axis_noise = rng.normal(scale=rot_sigma, size=3)
    # ... (축-각 잡음을 회전행렬로 변환해 R_rel에 곱함, 9장의 rodrigues와 같은 방식)
    return R_rel @ R_noise, t_rel + rng.normal(scale=trans_sigma, size=3)

noisy_relatives = [add_noise(R, t) for (R, t) in true_relatives]
estimated_poses = chain_odometry(noisy_relatives, true_poses[0])
----

진짜 상대 자세(`true_relatives`, 실제로는 4~6장의 방법으로 매 프레임 추정해야 하는 값입니다)에 작은 잡음을 섞습니다 — 7장에서 본 특징점 매칭이나 4~5장의 자세 복원이 완벽하지 않다는 걸 반영한 것입니다.

== 드리프트: 오차가 시간이 지날수록 쌓인다

[source,python]
----
position_errors = [np.linalg.norm(est[1] - true[1]) for est, true in zip(estimated_poses, true_poses)]
print(position_errors[0], position_errors[5], position_errors[10], position_errors[20])
# 0.0  0.068  0.365  0.626
assert position_errors[20] > position_errors[5]
----

스텝 `0`에서는 오차가 정확히 `0`(시작점은 정확히 아니까요)이지만, 스텝이 진행될수록 오차가 꾸준히 커져서 스텝 `20`에서는 `0.626m`까지 벌어집니다. 이게 **드리프트(drift)**입니다 — 매 스텝의 잡음은 아주 작아도(`rot_sigma=0.01`, `trans_sigma=0.01`, 둘 다 작은 값입니다), 그 작은 오차들이 다음 스텝, 그다음 스텝으로 **계속 곱해지고 더해지며 누적**됩니다. 9장의 번들 조정이 "이미 가진 모든 관측을 동시에 봐서" 오차를 억누를 수 있었던 것과 달리, 오도메트리 체이닝은 각 스텝을 딱 한 번만 보고 넘어가기 때문에 이 누적을 막을 방법이 없습니다.

== 원 위의 폐루프인데 폐루프가 아니다

[source,python]
----
loop_gap = np.linalg.norm(estimated_poses[20][1] - estimated_poses[0][1])
print(loop_gap)  # 0.626
assert loop_gap > 0.05
----

가장 극적인 증상이 이겁니다 — 차량은 실제로 원을 한 바퀴 돌아 **정확히 출발점으로 돌아왔는데도**, 오도메트리만으로 추정한 궤적은 시작점과 끝점이 `0.626m`이나 떨어져 있습니다. 실제로는 닫혀 있어야 할 원이, 추정된 궤적에서는 나선처럼 어긋난 채로 열려 있는 것입니다. 자율주행차가 같은 교차로를 두 번 지나가는데 지도에는 그 교차로가 두 개의 다른 위치로 기록되는 것과 같은 문제입니다.

== 다음 장으로 이어지는 질문

드리프트 자체는 피할 수 없습니다 — 잡음이 있는 이상, 그걸 계속 이어붙이면 오차도 계속 쌓입니다. 하지만 만약 "지금 이 위치가 예전에 지나간 적 있는 곳과 같다"는 걸 알아챌 수 있다면 어떨까요? 그 정보를 추가로 활용해서, 지금까지 쌓인 궤적 전체를 다시 조율할 수 있지 않을까요? 이게 11~12장에서 다룰 **포즈 그래프 최적화**와 **루프 클로저**의 핵심 아이디어입니다 — 9장의 번들 조정이 "모든 관측을 동시에 본다"는 사치를 실시간 SLAM에서도 부분적으로 되찾아오는 방법입니다.

noisy_relatives_big = [add_noise(R, t, rot_sigma=0.03, trans_sigma=0.03) for (R, t) in true_relatives]

====

== 요약

* SLAM은 SfM과 같은 문제를 풀지만, 정보가 실시간으로 순서대로 들어오고 즉시 답해야 한다는 제약이 추가됩니다.
* 오도메트리 체이닝은 연속된 프레임의 상대 자세를 누적해서 전체 궤적을 추정하는 가장 단순한 SLAM 방식입니다.
* 매 스텝의 작은 잡음도 계속 이어붙이면 시간이 지날수록 누적되는 드리프트가 되고, 실제로는 닫혀 있어야 할 루프가 추정 궤적에서는 열린 채로 어긋납니다.
* 이 드리프트를 바로잡으려면 "같은 곳을 다시 지나갔다"는 정보를 활용해야 하고, 이게 다음 장들의 주제입니다.
