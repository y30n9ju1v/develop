== 이 책이 하려는 것

"안전한 병렬 처리를 위한 이론"이라고 하면 보통 학계 논문이나 형식 증명 도구(Coq, Lean4, Iris 같은) 위에서 정리와 증명으로 다뤄집니다. 하지만 실무에서 매일 쓰는 언어에서는 이 이론들이 어떤 모습으로 나타날까요?

이 책은 그 질문에 **C{pp}23**으로 답합니다. C{pp}는 (Rust와 달리) 선형 타입도, 세션 타입도, 범주론적 인터페이스도 언어 코어에 내장하지 않습니다 — 하지만 이런 이론은 기존 타입 시스템 **안에 인코딩**할 수 있습니다. 이 책은 정확히 그 인코딩을 C{pp}23으로 직접 짜고, 컴파일하고, 실행하고, 일부러 틀리게 짜서 컴파일이 정말로 실패하는지 확인합니다.

* **세션 타입(session type)** — "채널 하나로 다음에 뭘 주고받아야 하는가"라는 통신 프로토콜을 타입으로 명세하는 이론입니다. **타입 상태 패턴(typestate pattern)** 으로 흉내냅니다 — "다음에 뭘 호출해야 하는가"를 객체의 **타입**으로 표현해서, 프로토콜을 어기는 호출 순서를 컴파일 에러로 만듭니다.
* **선형 타입(linear type)** — 값을 정확히 한 번만 쓸 수 있게 강제해서 자원의 이중 사용·누수를 막는 이론입니다. **이동 전용 타입(move-only type)과 RAII** 로 흉내냅니다 — 자원을 두 번 쓰면 컴파일이 안 되게 만듭니다.
* **범주론(category theory)** — Functor·Monad로 "효과가 있는 계산"의 합성을 다스리는 이론입니다. **concepts** 로 그 인터페이스를 표현하고, 병렬 파이프라인을 안전하게 합성합니다.
* **동시성 분리 논리(Concurrent Separation Logic)** — 두 스레드가 겹치지 않는 메모리 영역만 건드리면 동기화 없이도 안전하다는 걸 증명하는 이론입니다. **`std::span` 분할** 로 흉내냅니다 — 겹치지 않는 메모리 영역만 각자 건드리게 만들어, 락 없이도 데이터 경쟁을 원천 봉쇄합니다.
* **CRDT(Conflict-free Replicated Data Type)** — 동시 접근을 막는 대신, merge 연산이 대수 법칙만 지키면 동기화 없이 갱신해도 항상 같은 값에 수렴한다는 이론입니다. **join-semilattice concept** 으로 짜서 대수적으로 확인합니다.

이 책의 모든 코드는 이 세션 환경에 실제로 설치된 Apple Clang 21(`-std=c{pp}23`)로 컴파일하고 실행해서 검증했습니다 — 컴파일이 안 되는 걸 "노린" 예제는 실제로 컴파일러가 내는 에러 메시지를 그대로 인용합니다. 데이터 경쟁을 다루는 1장에서는 ThreadSanitizer(`-fsanitize=thread`)로 실제 경쟁을 검출한 리포트도 그대로 보여줍니다.

== 하나의 시스템을 처음부터 끝까지: TaskGrid

이 책의 각 장은 개별적인 장난감 예제를 따로 보여주지 않습니다. 대신 1장부터 14장까지 **하나의 작은 프로세스 내 작업 분배 시스템, TaskGrid**를 한 조각씩 같이 만들어 나갑니다 — 코디네이터(coordinator)가 작업 배치를 여러 워커(worker)에게 나눠주고, 워커가 그 배치를 처리해 결과를 돌려주는, 실전에서 아주 흔한 형태의 병렬 시스템입니다. 장을 넘어갈 때마다 지금까지 쌓아온 TaskGrid 코드에 그 장이 다루는 이론을 새로 얹습니다.

* *1부* 는 아무 보호 장치도 없는 TaskGrid — 코디네이터가 공유 `int progress` 하나를 여러 워커가 동시에 증가시키는 버전 — 로 시작해, 이게 왜 위험한지 실제로 보여줍니다.
* *2부* 는 코디네이터가 워커에게 배치를 건네는 통로인 ``WorkerConnection``을 타입 상태 패턴으로 다시 짜서, "연결 안 된 워커에게 배치를 보내는" 실수를 컴파일 타임에 막습니다.
* *3부* 는 워커가 배치를 처리하는 동안 붙들고 있는 자원 — 이동 전용 핸들 `DataSegmentHandle` — 을 만들고, ``WorkerConnection``과 합쳐 ``WorkerSession``을 완성한 뒤, 코디네이터가 바쁜 워커에서 한가한 워커로 배치를 재분배할 때 두 워커의 락을 동시에 잡다가 실제로 교착 상태에 빠지는 것과 ``std::scoped_lock``으로 고치는 것까지 다룹니다.
* *4부* 는 워커가 처리를 마친 결과를 Functor/Monad 스타일 인터페이스(``std::expected``의 `.transform()`/`.and_then()`)로 감싸고, 그 인터페이스로 여러 ``WorkerSession``을 ``std::async``를 통해 진짜 병렬로 돌리며, 같은 시퀀싱을 손수 짠 코루틴 ``Task<T>``로도 표현해봅니다.
* *5부* 는 코디네이터가 공유 입력 버퍼를 ``std::span``으로 쪼개 워커마다 겹치지 않는 조각을 나눠주는 방식을 다룹니다.
* *6부* 는 각 워커가 자기 몫의 진행률을 `GCounter`(CRDT)로 독립적으로 세고, 코디네이터가 그걸 동기화 없이 병합합니다 — 1장의 그 위험했던 ``int progress``가 마침내 안전하게 고쳐지는 지점입니다.

맺음말에서는 이렇게 14개 장에 걸쳐 조립된 TaskGrid 전체를 한자리에 모아, 코디네이터·`WorkerConnection`·`WorkerSession`·`DataSegmentHandle`·결과 채널·span 분할·`GCounter` 진행률이 함께 동작하는 완성된 모습을 보여줍니다.

== 왜 "각 장에 C{pp}17 대체법"인가

이 책이 쓰는 기능 상당수 — concepts, ``std::jthread``와 `std::stop_token`, ``std::atomic``의 `wait`/`notify`, 3-way 비교(`<=>`), `if consteval` — 는 C{pp}20에서야 들어왔고, 몇몇(`std::generator`, `std::expected`, `std::mdspan`, `std::flat_map`)은 C{pp}23에서야 들어왔습니다. 실무에서는 여전히 C{pp}17(또는 그 이전) 컴파일러를 벗어날 수 없는 프로젝트가 많습니다 — 임베디드 툴체인, 오래된 빌드 시스템, 회사 정책 등 이유는 다양합니다. 그래서 이 책의 **각 장 끝에는 "C{pp}17 환경이라면" 팁 박스**를 둡니다 — 그 장의 핵심 기법을 C{pp}17만으로 어떻게 근사하는지(대개는 `enable_if`/SFINAE, 수동 스레드 관리, 컴파일러 매크로 기반 정적 단언 등으로), 그리고 그 근사가 정확히 무엇을 잃는지를 씁니다. C{pp}23 코드와 마찬가지로, C{pp}17 코드도 전부 실제로 컴파일해서 검증했습니다.

== 누구를 위한 책인가

이 책은 **독립적으로 완결된 책**입니다 — C{pp}을 어느 정도 다뤄봤다면(포인터, 클래스, 템플릿의 기본을 안다면) 별도의 사전 지식 없이 따라올 수 있습니다. 각 장은 그 장에서 다루는 이론을 코드로 들어가기 전에 필요한 만큼 직접 설명합니다.

== 읽는 순서

이 책은 6부 14개 장과 맺음말로 나뉩니다.

*1부(1~2장)* 는 동기를 다집니다 — 데이터 경쟁을 실제로 일으켜 ThreadSanitizer로 검출하고, C{pp}의 보통 타입 시스템이 이런 버그를 왜 못 잡는지 확인합니다.

*2부(3~5장)* 는 타입 상태 패턴으로 세션 타입을 흉내냅니다 — 기초 패턴부터, 컴파일 타임 프로토콜 검사, 뮤텍스/채널에 실제로 적용하는 것까지 다룹니다.

*3부(6~9장)* 는 이동 전용 타입으로 선형 타입을 흉내냅니다 — ``unique_ptr``과 RAII부터, 커스텀 이동 전용 핸들, 실전 자원 관리(락, 파일, 커넥션)를 거쳐, ``WorkerSession``이 완성된 뒤에야 나올 수 있는 실전 문제 — 여러 락을 동시에 잡을 때 생기는 교착 상태와 ``std::scoped_lock``으로 고치는 것 — 까지 다룹니다.

*4부(10~12장)* 는 concepts로 범주론적 인터페이스를 짜고, 그걸로 병렬 파이프라인을 합성하고, 같은 시퀀싱을 손수 짠 코루틴 ``Task<T>``로도 표현해봅니다.

*5부(13장)* 는 동시성 분리 논리를 `std::span` 분할로 인코딩해, 겹치지 않는 메모리만 각자 건드리면 동기화 없이도 안전하다는 걸 확인합니다.

*6부(14장)* 는 CRDT로 지금까지와 정반대 전략(막는 대신, 동기화 없이 갱신하고 나중에 합쳐도 대수적으로 항상 수렴하게 만드는 것)을 다룹니다.

*맺음말(15장)* 은 이 다섯 이론을 하나의 표로 정리하고, Rust가 그중 무엇을 언어 코어로 채용했는지, 이 책이 다루지 않은 것(C{pp}26의 `std::execution`, 실전 락프리 자료구조 등)과 다음으로 어디를 볼지 안내합니다.

각 장은 이전 장의 코드를 당연하게 재사용합니다 — 이번 개정판부터는 단순한 "재사용" 이상으로, 모든 장이 TaskGrid라는 하나의 프로젝트를 조금씩 완성해 나가므로 순서대로 읽는 걸 강하게 권합니다.
