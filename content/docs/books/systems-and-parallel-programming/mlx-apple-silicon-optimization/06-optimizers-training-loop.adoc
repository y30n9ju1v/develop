5장에서 만든 ``MLP``는 아직 무작위 초기화 상태입니다. 이 장은 나선형 데이터를 만들고, 손실 함수와 Adam 옵티마이저로 실제로 학습시켜서 3개의 뒤섞인 팔을 구분할 수 있게 만듭니다.

== 나선형 데이터 만들기

[source,python]
----
def make_spiral(n_per_class=200, n_classes=3):
    X = np.zeros((n_per_class * n_classes, 2), dtype=np.float32)
    y = np.zeros(n_per_class * n_classes, dtype=np.int32)
    for c in range(n_classes):
        ix = range(n_per_class * c, n_per_class * (c + 1))
        r = np.linspace(0.0, 1, n_per_class)
        t = np.linspace(c * 4, (c + 1) * 4, n_per_class) + np.random.randn(n_per_class) * 0.2
        X[ix] = np.c_[r * np.sin(t), r * np.cos(t)]
        y[ix] = c
    return X, y

X, y = make_spiral()
Xm, ym = mx.array(X), mx.array(y)
----

각 클래스가 중심에서 바깥으로 나선을 그리며 서로 감고 도는 배치입니다 — 클래스 경계가 직선이 아니라서, 5장의 은닉층 두 개(ReLU 비선형)가 실제로 필요합니다.

== 손실 함수와 ``value_and_grad``

[source,python]
----
import mlx.optimizers as optim

def loss_fn(model, x, y):
    logits = model(x)
    return nn.losses.cross_entropy(logits, y).mean()

loss_and_grad = nn.value_and_grad(model, loss_fn)
opt = optim.Adam(learning_rate=1e-2)
----

``nn.value_and_grad(model, loss_fn)``은 3장의 ``mx.grad``를 신경망에 맞게 감싼 버전입니다 — ``loss_fn``을 호출하면서 **손실 값과 그래디언트를 한 번에** 돌려줍니다(둘 다 필요한 경우가 대부분이라, 따로따로 계산하면 순전파를 두 번 하는 낭비가 생깁니다). ``optim.Adam``은 그래디언트를 받아서 파라미터를 어떻게 갱신할지 정하는 규칙입니다 — 5장에서 확인한 파라미터 트리 구조를 그대로 순회하며 각 리프를 갱신합니다.

== 학습 루프

[source,python]
----
def accuracy(model, x, y):
    preds = mx.argmax(model(x), axis=1)
    return (preds == y).mean()

for epoch in range(200):
    loss, grads = loss_and_grad(model, Xm, ym)
    opt.update(model, grads)
    mx.eval(model.parameters(), loss)   # 2장: 파라미터 갱신을 실제로 실행
    if epoch % 40 == 0 or epoch == 199:
        acc = accuracy(model, Xm, ym)
        mx.eval(acc)
        print(f"epoch {epoch:3d}  loss={float(loss):.4f}  acc={float(acc):.3f}")
----

200 에폭 만에 정확도 **99.7%**에 도달합니다. ``opt.update(model, grads)``가 파라미터 트리를 직접 수정하고, 그 뒤에 부르는 ``mx.eval(model.parameters(), loss)``이 2장에서 확인한 것과 정확히 같은 역할을 합니다 — 그래디언트 계산과 파라미터 갱신 전체가 하나의 그래프로 쌓여 있다가, 이 지점에서 실제로 실행됩니다. ``epoch % 40 == 0``마다만 정확도를 찍는 것도 우연이 아닙니다 — 매 에폭마다 ``accuracy``까지 계산하고 ``eval``하면, 불필요하게 자주 그래프를 끊어 2장이 확인한 융합 이득을 깎아 먹습니다.

== 요약

* ``nn.value_and_grad``로 손실과 그래디언트를 한 번에 얻고, ``optim.Adam``으로 5장의 파라미터 트리를 순회하며 갱신하는 학습 루프를 완성했습니다.
* 나선형 3클래스 데이터에 이 루프를 200 에폭 돌려 정확도 99.7%까지 실제로 도달하는 걸 확인했습니다.
* 매 에폭 파라미터 갱신 뒤에만 ``mx.eval``을 부르고, 정확도 로깅처럼 자주 필요 없는 연산은 드물게만 실체화하는 것이 2장의 융합 이득을 지키는 법이라는 것도 짚었습니다.
