이 장은 새 기법을 도입하지 않습니다 — 1~8장에서 만든 조각을 **재구성 없이 그대로** 이어 붙여, 나선형 분류기를 처음부터 끝까지 학습시키고 압축까지 마칩니다.

== 조립: 각 조각이 어느 장에서 왔는가

[source,python]
----
model = MLP(2, 64, 3)                          # 5장
mx.eval(model.parameters())
opt = optim.Adam(learning_rate=1e-2)            # 6장

loss_and_grad = nn.value_and_grad(model, loss_fn)   # 3장의 mx.grad를 감싼 버전(6장)
state = [model.state, opt.state]

def step(x, y):
    loss, grads = loss_and_grad(model, x, y)
    opt.update(model, grads)
    return loss

step = mx.compile(step, inputs=state, outputs=state)   # 4장

for epoch in range(200):
    loss = step(Xm, ym)                          # 1장: CPU/GPU 구분 없이 통합 메모리 위에서
    mx.eval(state, loss)                          # 2장: 그래프를 여기서 실제로 실행
----

``Xm``/``ym``은 6장의 나선형 데이터(1장에서 확인한 것처럼 만드는 순간 이미 GPU에서 쓸 준비가 끝난 ``mx.array``)이고, ``step``은 6장의 학습 스텝을 4장의 ``mx.compile``로 감싼 것입니다.

== 실행: 컴파일된 학습 루프

[source]
----
$ python3 mlx_full_pipeline.py
final acc before quantize=0.997
----

6장에서 컴파일 없이 돌렸을 때(``132.8ms`` → 컴파일 후 ``99.3ms``, 4장)와 같은 200 에폭을 이번엔 실제 나선형 데이터 학습 루프 전체에 적용하면 ``173.2ms``가 걸립니다(4장의 단순 벤치마크보다 절대 시간이 더 걸리는 건, 매 에폭 ``accuracy``를 확인하지 않고도 여기서는 손실 계산과 그래디언트, 옵티마이저 갱신이 실제 나선형 데이터 크기로 매번 돌기 때문입니다). 정확도는 6장과 동일하게 **99.7%**로 수렴합니다 — 컴파일이 학습 결과 자체를 바꾸지 않는다는 것도 이걸로 확인됩니다.

== 양자화까지 이어 붙이기

8장은 양자화를 학습되지 않은 무작위 모델에만 적용했습니다 — 이 장에서 실제로 학습된 모델에 적용해 정확도가 어떻게 되는지 마무리합니다. 8장의 큰 모델과 달리 이 책의 ``MLP(2, 64, 3)``은 첫 레이어의 입력 차원이 ``2``라서, ``group_size``(32/64/128 중 하나만 지원)로 나눠떨어지지 않습니다 — ``class_predicate``로 그 레이어만 양자화에서 제외합니다.

[source,python]
----
def predicate(path, module):
    return path != "l1"   # 입력 차원(2)이 group_size로 안 나눠떨어져서 l1은 제외

nn.quantize(model, bits=4, group_size=32, class_predicate=predicate)
mx.eval(model.parameters())

acc_after = accuracy(model, Xm, ym)
mx.eval(acc_after)
----

[source]
----
quantized (l2,l3 only, 4bit) acc=0.997
----

``l2``, ``l3``(전체 파라미터의 대부분을 차지하는 두 레이어)를 4비트로 압축해도 **정확도가 그대로 0.997입니다.** 8장이 남겨둔 질문 — "학습된 모델을 양자화하면 정확도가 얼마나 떨어지는가" — 에 대한 이 나선형 문제 하나에서의 답은 "떨어지지 않았다"입니다. 이 문제가 결정 경계를 표현하는 데 필요한 정밀도가 4비트로도 충분할 만큼 단순하기 때문입니다 — 8장에서 짚었듯 이건 일반적인 보장이 아니라 이 모델·이 데이터에서 실측한 결과이고, 더 복잡한 문제라면 정확도 손실이 실제로 나타날 수 있습니다.

== 이 장이 보여준 것

1장의 통합 메모리, 2장의 지연 평가, 3장의 자동 미분, 4장의 컴파일이 서로 다른 층위의 최적화인데도 한 파이프라인 안에서 상쇄되지 않고 그대로 합쳐진다는 걸 이 장이 보여줬습니다 — link:../../cpp23-performance-engineering/[『안전을 넘어 성능으로』] 10장이 PerfGrid로 확인한 것과 같은 종류의 확인을, MLX의 도구들로 다시 한 셈입니다.

== 요약

* 1~8장의 조각을 재구성 없이 이어 붙인 학습 루프가 실제로 200 에폭 만에 99.7% 정확도에 도달한다는 걸 확인했습니다.
* 학습된 모델에 4비트 양자화를 적용해도(입력 차원이 그룹 크기와 안 맞는 첫 레이어만 제외하고) 정확도가 그대로 유지된다는 걸 실측으로 확인해, 8장이 남겨둔 질문에 이 문제 한정으로 답했습니다.
* 서로 다른 장에서 검증한 최적화들이 한 파이프라인에서 함께 작동한다는 것도 짚었습니다.
