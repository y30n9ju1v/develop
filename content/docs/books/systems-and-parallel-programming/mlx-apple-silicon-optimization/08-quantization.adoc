'''

7장은 계산량(배치 크기)을 다뤘습니다. 이 장은 다른 축 — **파라미터가 차지하는 메모리 크기** — 를 줄입니다. 6장의 나선형 분류기는 파라미터가 4547개뿐이라 양자화 효과를 실측하기엔 너무 작으므로, 이 장은 더 현실적인 크기의 다층 퍼셉트론(은닉층 6개, 각 1024차원, 파라미터 약 630만 개)으로 압축률과 속도를 함께 잽니다.

== ``nn.quantize``로 파라미터 압축하기

[source,python]
----
model = MLP(512, 1024, 512, n_layers=6)
mx.eval(model.parameters())

orig_bytes = total_bytes(model.parameters())    # fp32 기준

nn.quantize(model, bits=4, group_size=64)
mx.eval(model.parameters())

q_bytes = total_bytes(model.parameters())
----

``nn.quantize(model, bits=4, group_size=64)``는 모델의 ``nn.Linear`` 레이어를 제자리에서 양자화된 버전으로 바꿉니다 — 각 가중치를 32비트 부동소수점 대신 4비트 정수로 저장하고, ``group_size``(여기서는 64)개 원소마다 스케일 하나를 따로 둬서 그 그룹 안에서의 상대적 정밀도를 지킵니다(모든 가중치에 스케일 하나만 쓰면 오차가 너무 커지므로, 그룹을 잘게 나눠 정밀도 손실을 억제하는 절충입니다).

== 실측: 메모리와 속도

[source]
----
$ python3 mlx_quantize_bench.py
fp32 params: 25.19 MB   4bit quantized: 3.96 MB   compression: 6.36x
fp32 inference: 3.837 ms   quantized inference: 2.260 ms   speedup: 1.70x
----

메모리는 **6.36배** 줄었습니다 — 이론상 32비트를 4비트로 바꾸면 8배가 나와야 하는데, 6.36배에 그친 이유는 ``group_size=64``마다 스케일/오프셋 값을 따로 저장하는 부가 비용 때문입니다(순수 4비트 압축률에서 그룹 메타데이터만큼을 뺀 실제 수치입니다). 속도는 **1.70배** 빨라졌습니다 — 이건 "연산이 줄어서"가 아니라 "메모리에서 읽어와야 할 바이트 수가 줄어서"입니다. 이런 완전연결 레이어의 행렬곱은 7장에서 확인했듯 계산량 자체보다 가중치를 메모리에서 읽어오는 대역폭이 병목인 경우가 많은데, 4비트로 압축된 가중치는 같은 대역폭으로 더 많은 파라미터를 실어 나를 수 있습니다.

== 트레이드오프: 공짜가 아니다

link:../../cpp23-performance-engineering/[『안전을 넘어 성능으로』] 4장이 조회 테이블로 ``std::sin``을 근사했을 때 정밀도를 속도와 맞바꿨던 것과 같은 종류의 거래입니다 — 4비트 정수는 32비트 부동소수점보다 표현할 수 있는 값의 가짓수가 훨씬 적으므로, 양자화된 모델의 출력은 원본과 정확히 같지 않습니다. 이 장은 무작위로 초기화된 모델의 순전파 속도만 쟀을 뿐, 실제로 학습된 모델을 양자화했을 때 정확도가 얼마나 떨어지는지는 확인하지 않았습니다 — 그 확인은 9~10장에서 이 책의 나선형 분류기로 직접 해봅니다.

== 요약

* ``nn.quantize``로 모델의 선형 레이어를 4비트로 압축해, 메모리 6.36배 절감을 실측으로 확인했습니다 — 이론상 8배에 못 미치는 이유(그룹별 스케일 저장 비용)도 짚었습니다.
* 같은 양자화가 추론 속도도 1.70배 높인다는 걸 확인했고, 그 이유가 계산량 감소가 아니라 메모리 대역폭 절감이라는 것도 짚었습니다.
* 이 이득이 정밀도와 맞바꾼 것이라는 점, 그리고 이 장은 아직 정확도에 미치는 영향을 확인하지 않았다는 것도 정직하게 남겨뒀습니다.

다음 장에서는 1~8장에서 만든 조각 — 통합 메모리, 지연 평가, 자동 미분, 컴파일, ``nn.Module``, 학습 루프 — 을 재구성 없이 그대로 이어 붙여 나선형 분류기 파이프라인 전체를 완성합니다.
