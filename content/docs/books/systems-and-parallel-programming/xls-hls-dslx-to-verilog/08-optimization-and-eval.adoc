`ir_converter_main`이 뽑은 IR은 소스를 곧이곧대로 옮긴 것이라 군더더기가 많습니다. `opt_main`이 이 IR에 최적화 패스를 연달아 돌려, 의미는 같지만 훨씬 작고 얕은 그래프로 바꿉니다. 스케줄링과 합성은 이 최적화된 IR을 입력으로 받습니다.

== 돌리기

[source,bash]
----
opt_main add.ir > add.opt.ir
----

`add`처럼 단순한 함수는 별로 안 바뀌지만, 캐스팅·상수·루프가 섞이면 차이가 큽니다.

== 주요 패스가 하는 일

[cols="1,3", options="header"]
|===
| 패스 계열 | 하는 일

| **상수 전파 / 폴딩**
| `add(literal:2, literal:3)` → `literal:5`. 컴파일 타임에 계산 가능한 부분을 미리 계산.

| **비트 좁히기 (narrowing)**
| 어떤 노드의 상위 비트가 항상 0/부호비트임을 증명하면, 그 노드와 하류를 더 좁은 폭으로 다시 씁니다. 회로 면적이 줄어듭니다.

| **죽은 코드 제거 (DCE)**
| 반환값에 영향을 주지 않는 노드를 지웁니다.

| **루프 언롤**
| `counted_for`를 `trip_count`번 펼쳐 조합 그래프로. 이후 다른 패스가 펼쳐진 몸통을 가로질러 최적화합니다.

| **표현 재작성 / 정규화**
| `x * 2` → `x << 1`, 중첩 `select`/`one_hot_sel` 병합, 항등원 제거(`x + 0`, `x & all-ones`).

| **BDD 기반 단순화**
| 이진 결정 다이어그램으로 논리적으로 동치인 더 단순한 형태를 찾습니다. 특히 비트 단위 로직에 강합니다.

| **공통 부분식 제거 (CSE)**
| 같은 연산·같은 피연산자 노드를 하나로 합칩니다.
|===

패스 목록과 순서는 XLS 버전에 따라 바뀝니다. `opt_main --help`와 저장소의 패스 문서에서 현재 파이프라인을 확인하세요. `--passes=...`로 특정 패스만 골라 돌려 개별 효과를 관찰할 수도 있습니다.

== 전후 비교: 상수가 접힌다

[source,dslx]
----
fn scale(x: u16) -> u32 {
    let k = u32:100;
    (x as u32) * (k / u32:4)     // k/4 = 25 는 상수
}
----

변환 직후 IR에는 `udiv(literal:100, literal:4)` 노드가 남습니다. `opt_main` 후에는 그 자리에 `literal:25`가 들어가고, 곱셈은 상수 곱으로 재작성됩니다.

[source,bash]
----
ir_converter_main --top=scale scale.x | grep -E 'udiv|umul|literal'
echo '--- 최적화 후 ---'
ir_converter_main --top=scale scale.x | opt_main - | grep -E 'udiv|umul|literal'
----

`udiv`가 사라지면 성공입니다.

== 전후 비교: 루프가 펼쳐진다

6장 `popcount(u8:...)`의 IR에는 `counted_for(trip_count=8, ...)`가 있습니다. `opt_main` 후에는 대개 `counted_for`가 사라지고, 8개의 비트 추출과 덧셈 트리가 직접 남습니다. 스케줄러가 다루기 쉬운 형태입니다.

== 평가 1: IR 인터프리터

최적화가 의미를 바꾸지 않았는지 확인하려면 같은 입력을 전후 IR에 넣어 봅니다.

[source,bash]
----
# 최적화 전
eval_ir_main --input='bits[16]:8' scale.ir
# 최적화 후
eval_ir_main --input='bits[16]:8' scale.opt.ir
# 둘 다 bits[32]:200 이어야 한다 (8 * 25)
----

`eval_ir_main`(도구에 따라 `interpreter_main`)은 IR을 소프트웨어로 한 노드씩 계산합니다. 느리지만 정확한 기준입니다.

== 평가 2: LLVM JIT

`eval_ir_main --use_llvm_jit`(또는 전용 JIT 진입점)은 IR을 LLVM IR로 낮추고 네이티브 코드로 컴파일해 실행합니다. 인터프리터보다 수십~수백 배 빠릅니다. 대량 랜덤 벡터로 회귀 테스트를 돌릴 때 이 속도가 필요합니다.

[source,bash]
----
eval_ir_main --use_llvm_jit --input_file=vectors.txt scale.opt.ir > jit_out.txt
eval_ir_main                --input_file=vectors.txt scale.opt.ir > interp_out.txt
diff jit_out.txt interp_out.txt    # 비어 있어야 한다
----

JIT와 인터프리터가 같은 결과를 내는 것은 XLS 자체의 자기 점검이기도 합니다.

== 이 장에서 만든 안전망

이제 한 설계에 대해 세 개의 일치하는 참조가 생겼습니다.

. DSLX `#[test]` (`dslx_interpreter_main`)
. 최적화 전/후 IR 평가 (`eval_ir_main`)
. LLVM JIT 평가

11장에서 여기에 **Verilog 시뮬레이션 결과**가 하나 더 붙고, 14장에서 **형식 등가 증명**이 붙습니다. 같은 입력이 이 모든 층에서 같은 출력을 내는 것이 XLS 워크플로의 신뢰 기반입니다.

== 직접 확인하기

[source,bash]
----
opt_main scale.ir | tee scale.opt.ir
eval_ir_main --input='bits[16]:8' scale.ir
eval_ir_main --input='bits[16]:8' scale.opt.ir

# popcount IR을 최적화 전후로 grep 해 counted_for 가 사라지는지 확인
opt_main popcount.ir | grep counted_for || echo "언롤됨"

# benchmark_main 이 있으면 최적화 전후의 추정 지연/노드 수를 비교
----
