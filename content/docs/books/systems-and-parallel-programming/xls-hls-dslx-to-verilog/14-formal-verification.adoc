8장에서 최적화 전후 IR을 같은 벡터로 평가해 결과가 같음을 봤습니다. 그건 그 벡터에 대해서만 참입니다. 형식 검증은 **모든 입력에 대해** 두 IR이 같은 함수임을 증명합니다.

== 발상: IR을 논리식으로

XLS IR은 순수 데이터플로 그래프이고, 각 노드는 비트 벡터에 대한 잘 정의된 연산(`add`, `umul`, `sel`, `zero_ext`, …)입니다. 이걸 그대로 **비트벡터 SMT 식**으로 옮길 수 있습니다.

* `add.7 = add(a, b)` → SMT: `add7 = bvadd(a, b)`
* `sel.9 = sel(c, [x, y])` → SMT: `sel9 = ite(c == 0, x, y)`
* 함수 전체 → 입력 심볼에서 출력 심볼까지의 큰 식

두 함수 `f`, `g`가 등가인지 묻는 것은 SMT 솔버(XLS는 **Z3**를 씁니다)에게 이렇게 묻는 것입니다.

[source,text]
----
∃ 입력.  f(입력) ≠ g(입력)  ?
----

솔버가 "unsat"(그런 입력 없음)이라고 하면 `f`와 `g`는 **모든 입력에서 같습니다** — 증명 완료. "sat"이면 솔버가 반례(구체적인 입력)를 줍니다.

== 최적화 전후 등가 증명

[source,bash]
----
ir_converter_main --top=scale scale.x > scale.ir
opt_main scale.ir > scale.opt.ir

check_ir_equivalence_main scale.ir scale.opt.ir
# 기대: "Verified equivalent" (또는 반례)
----

이게 통과하면, 8장에서 본 `udiv` 폴딩·상수 전파·비트 좁히기가 **함수의 의미를 한 톨도 바꾸지 않았음**이 증명됩니다. 특정 테스트 벡터가 아니라 2^입력폭^개 전부에 대해서요.

무거운 연산(넓은 곱, 긴 `counted_for`에서 나온 큰 그래프)은 솔버가 오래 걸리거나 시간 초과할 수 있습니다. 그럴 때는 함수를 조각내 부분별로 증명하거나, 폭을 줄인 파라메트릭 인스턴스로 증명한 뒤 파라메트릭 추론으로 일반화합니다.

== translation validation

XLS의 접근은 "컴파일러가 옳다고 믿어라"가 아니라 **"이번 컴파일 결과가 옳음을 매번 증명하라"**입니다. 이것을 translation validation이라 부릅니다. 최적화 파이프라인이 복잡하고 계속 바뀌어도, 각 실행의 입력 IR과 출력 IR을 등가 검사하면 그 실행은 신뢰할 수 있습니다. 컴파일러 전체를 한 번에 검증하는 것보다 훨씬 현실적입니다.

== IR ↔ 넷리스트 등가 (LEC)

한 걸음 더 내려갈 수 있습니다. `codegen_main`이 뽑은 Verilog를 `yosys` 같은 도구로 게이트 넷리스트까지 합성한 뒤, 그 넷리스트를 다시 논리식으로 옮겨 원래 IR과 등가 검사(Logical Equivalence Check)합니다. XLS에는 넷리스트를 읽어 SMT로 바꾸는 경로가 있습니다.

이게 통과하면 신뢰 사슬이 이렇게 완성됩니다.

[source,text]
----
DSLX  ─(ir_converter)─►  IR  ─(opt)─►  최적화 IR  ─(codegen)─►  Verilog  ─(yosys)─►  넷리스트
        #[test]              eval_ir      check_ir_        sim         LEC
                             (JIT)        equivalence               (IR↔넷리스트)
----

각 화살표가 별도로 검사됩니다. 어느 단계가 의미를 깨뜨리면 그 지점에서 반례가 나옵니다.

== 형식 검증 ≠ 테스트

[cols="1,1", options="header"]
|===
| 테스트 (`#[test]`, 시뮬레이션) | 형식 등가 (`check_ir_equivalence_main`)

| 고른 입력 몇 개에서 동작 확인 | 모든 입력에서 두 구현이 같음을 증명
| 명세가 맞는지도 검사 가능 | "두 IR이 서로 같은가"만 검사 (명세 자체의 옳음은 아님)
| 빠르고 항상 끝남 | 클 때 느리거나 시간 초과
| 회귀·통합에 필수 | 최적화·합성이 안전한지 확인에 필수
|===

둘은 대체재가 아니라 보완재입니다. `#[test]`로 "명세대로 계산하는가"를 잡고, 등가 검사로 "도구가 그 명세를 망가뜨리지 않았는가"를 잡습니다.

== 직접 확인하기

[source,bash]
----
check_ir_equivalence_main scale.ir scale.opt.ir

# 일부러 opt IR 을 손으로 한 노드 바꿔(예: add → sub) 반례가 나오는지 본다

# 작은 파라메트릭 인스턴스(u4 폭)로 등가 검사해 솔버 시간이 어떻게 늘어나는지 관찰
----

다음 장에서 배운 것을 전부 이어 FIR 필터를 처음부터 끝까지 만듭니다.
