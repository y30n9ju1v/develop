'''

가장 단순한 출력부터 봅니다. 클럭도 레지스터도 없이, 입력이 바뀌면 조합 논리를 타고 출력이 따라 바뀌는 회로입니다.

== 방출하기

`mac4.x`를 IR로 만들고 최적화한 `mac4.opt.ir`이 있다고 합시다.

[source,bash]
----
codegen_main --generator=combinational --top=mac4 mac4.opt.ir > mac4_comb.v
----

`mac4_comb.v`는 대략 이런 모양입니다(형식·이름은 버전에 따라 다릅니다).

[source,verilog]
----
module mac4(
  input wire [127:0] a,      // s32[4] 가 128비트 버스로 평탄화됨
  input wire [127:0] b,
  output wire [31:0] out
);
  wire [31:0] a0 = a[31:0];
  wire [31:0] b0 = b[31:0];
  // ... a1..a3, b1..b3 슬라이스 ...
  wire [31:0] p0 = a0 * b0;
  wire [31:0] p1 = a1 * b1;
  wire [31:0] p2 = a2 * b2;
  wire [31:0] p3 = a3 * b3;
  wire [31:0] s01 = p0 + p1;
  wire [31:0] s23 = p2 + p3;
  assign out = s01 + s23;
endmodule
----

핵심 관찰:

* **클럭·리셋 포트가 없습니다.** 순수 조합.
* DSLX의 `s32[4]` 배열 인자가 Verilog에서는 **평탄화된 128비트 버스**가 됩니다. 상위/하위 비트가 배열 인덱스에 대응합니다.
* 모든 게 `wire` + `assign`. `always` 블록이 없습니다.
* 소스의 연산 구조(`(p0+p1)+(p2+p3)`)가 대체로 보존되지만, 최적화가 트리를 재배치했을 수 있습니다.

== 포트 이름과 구조 제어

[cols="1,3", options="header"]
|===
| 옵션 | 효과

| `--module_name=NAME`
| Verilog `module` 이름을 바꿉니다.

| `--use_system_verilog`
| `.v` 대신 SystemVerilog 관용(`logic`, 압축 배열 등)으로 방출.

| `--top=FN`
| IR 패키지에서 최상위로 삼을 함수.

| `--generator=combinational`
| 이 장의 모드. 스케줄링을 하지 않습니다.
|===

배열·튜플·구조체 인자를 "평탄화된 하나의 버스"가 아니라 "필드별 개별 포트"로 내보내는 옵션(예: `--flop_inputs` 계열, 포트 분리 플래그)도 버전에 따라 있습니다. `codegen_main --help`로 현재 지원을 확인하세요.

== 타입이 포트로 내려오는 규칙

* `uN`/`sN` → `[N-1:0]` 버스. 부호는 포트에 표시되지 않습니다(2의 보수 비트 그대로).
* 튜플/구조체 → 필드를 이어 붙인 하나의 버스(또는 옵션에 따라 분리 포트).
* 배열 → 원소를 이어 붙인 버스. `T[K]`는 `K * bits(T)` 폭.
* `()` (유닛) → 포트 없음.

즉 Verilog 경계에서는 모든 것이 그냥 비트 벡터입니다. 어느 비트가 어느 필드인지는 XLS가 정한 레이아웃을 따릅니다.

== 조합 출력의 쓰임

* **빠른 iverilog 시뮬레이션**의 기준. 클럭 관리가 없어서 테스트벤치가 짧습니다(11장에서 파이프라인 버전과 대조).
* **작은 조합 IP** — 우선순위 인코더, 작은 ALU, 포맷 변환기.
* **타이밍 감**을 잡는 용도. `yosys`로 이 Verilog를 합성해 임계경로를 보면, 9장에서 왜 파이프라인이 필요한지 숫자로 납득됩니다.

다만 조합 깊이가 크면(예: 32비트 곱 여러 개 직렬) 실제 클럭이 매우 느려집니다. 그때가 파이프라인(11장)으로 갈 때입니다.

== DSLX 테스트와 잇기

조합 Verilog는 "입력 → (지연 후) 출력"이므로, 8장에서 모은 입력/기대출력 벡터를 그대로 테스트벤치로 옮길 수 있습니다.

[source,verilog]
----
// tb_mac4_comb.v (발췌)
initial begin
  a = {32'd4, 32'd3, 32'd2, 32'd1};   // a = [1,2,3,4]
  b = {32'd6, 32'd5, 32'd4, 32'd3};   // b = [3,4,5,6]
  #1;
  if (out !== 32'd 56) $fatal(1, "mismatch: %0d", out);  // 3+8+15+24 ... (기대값은 직접 계산/DSLX로 확인)
  $display("ok");
end
----

기대값 `56`은 예시로 적은 것입니다. 실제로는 `dslx_interpreter_main`이나 `eval_ir_main`이 뽑은 값을 그대로 넣으세요 — 이 책은 이 값을 실행 검증하지 않았습니다.

== 직접 확인하기

[source,bash]
----
codegen_main --generator=combinational --top=mac4 mac4.opt.ir | tee mac4_comb.v

# 포트 목록과 always 블록 유무 확인
grep -E 'input|output|always' mac4_comb.v

# SystemVerilog 로도 뽑아 차이를 본다
codegen_main --generator=combinational --use_system_verilog --top=mac4 mac4.opt.ir | head -30

# iverilog 가 있으면 위 테스트벤치와 함께 시뮬레이션 (기대값은 eval_ir_main 으로 확정)
iverilog -o sim mac4_comb.v tb_mac4_comb.v && vvp sim
----

다음 장에서 같은 IR을 파이프라인으로 뽑고, 클럭을 돌려 시뮬레이션합니다.
