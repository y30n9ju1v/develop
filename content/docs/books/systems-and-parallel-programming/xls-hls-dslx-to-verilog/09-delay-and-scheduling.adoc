최적화된 IR은 아직 시간이 없는 순수 데이터플로 그래프입니다. 이 장에서 그래프에 **파이프라인 단계 경계**가 그어집니다. 그것을 정하는 것이 스케줄러이고, 스케줄러가 판단 근거로 삼는 것이 지연 모델입니다.

== 지연 모델

지연 모델은 "이 연산은 이 폭에서 대략 몇 피코초 걸린다"를 알려주는 표입니다.

* `unit` — 모든 연산을 1로 세는 장난감 모델. 배우고 실험할 때 씁니다.
* 공정 기반 모델 — `asap7`, `sky130` 등. 특정 표준셀 라이브러리를 특성화한 회귀식으로, `umul[32]`가 `add[32]`보다 훨씬 비싸다는 걸 압니다.

`codegen_main`/스케줄러에 `--delay_model=unit` 또는 `--delay_model=asap7`처럼 넘깁니다. 모델이 정확할수록 스케줄이 실제 합성 타이밍에 가깝습니다.

== 두 가지 질문 방식

스케줄러에게는 목표를 둘 중 하나로 줍니다.

[cols="1,3", options="header"]
|===
| 주는 것 | 스케줄러가 푸는 문제

| `--clock_period_ps=P`
| "한 사이클이 P ps다. 어떤 단계도 P를 넘지 않게, **가장 적은 단계 수**로 잘라라."

| `--pipeline_stages=K`
| "정확히 K단으로 나눠라. 각 단계 지연이 최대한 고르고 낮아지게(→ 달성 가능한 클럭이 빨라지게) 배치하라."
|===

둘 다 줄 수도 있습니다("K단 이하이면서 P ps 이하"). 소스 DSLX는 한 글자도 바뀌지 않습니다 — 같은 `mac4`에서 `--pipeline_stages=2`와 `--pipeline_stages=5`가 서로 다른 회로를 뽑습니다.

== 스케줄링이 실제로 하는 일

데이터플로 그래프의 각 노드에 "몇 번째 단계에서 계산되는가"를 뜻하는 정수 `stage(n)`을 배정하는 문제입니다. 제약은:

* **의존성:** `n`이 `m`을 입력으로 쓰면 `stage(n) >= stage(m)`.
* **주기:** 같은 단계 안에서 조합으로 이어지는 경로의 지연 합이 클럭 주기를 넘으면 안 됨.
* **목표:** 단계 수 최소화, 또는 단계 간 지연 균형.

두 노드가 다른 단계에 배정되면, 그 사이 데이터플로 에지마다 **레지스터(플립플롭)**가 삽입됩니다. 이것이 "파이프라인을 만든다"의 실제 내용입니다.

== SDC 스케줄링

XLS의 기본 스케줄러는 **SDC(System of Difference Constraints)** 방식입니다. 위 제약들을 `stage(n) - stage(m) <= c` 꼴의 차분 부등식으로 적으면, 전체가 선형 계획(LP) 문제가 되고, 그 LP의 제약 행렬이 전유니모듈러라서 LP 최적해가 자동으로 정수해가 됩니다. 덕분에 "주기 제약을 지키며 레지스터(면적)를 최소화"하는 스케줄을 빠르고 최적에 가깝게 얻습니다.

세부는 XLS의 스케줄링 문서에 있지만, 실무에서 알아야 할 것은:

* 스케줄러는 **재타이밍**을 합니다 — 여러분이 어디에 레지스터를 두라고 안 해도, 조합 논리를 단계 경계 너머로 밀고 당겨 균형을 맞춥니다.
* 곱셈처럼 무거운 연산은 그 자체가 한 단계를 다 먹거나 여러 단계에 걸칠 수 있습니다(연산 분할을 지원하는 경우).
* 스케줄이 불가능하면(예: 단일 연산 지연 > 클럭 주기) 도구가 실패를 보고합니다. 클럭 주기를 늘리거나 단계 수를 풀어 줍니다.

== 처리율과 지연

파이프라인 `fn`은 기본적으로 **처리율 1**입니다 — 매 사이클 새 입력을 받고, `K`단이면 `K` 사이클 뒤 결과가 나옵니다. 이 "매 사이클 하나"가 안 되는 경우(예: 자원을 재사용하려고 II>1로 접기)는 `fn` 파이프라인이 아니라 proc의 영역입니다(12장).

== 스케줄만 따로 뽑기

`codegen_main`이 스케줄링과 Verilog 생성을 한 번에 하지만, 스케줄을 파일로 먼저 뽑아 검토할 수도 있습니다.

[source,bash]
----
# 도구/버전에 따라 이름이 다를 수 있음: 스케줄 정보를 텍스트/프로토로 출력
codegen_main --generator=pipeline --delay_model=unit \
             --pipeline_stages=3 --top=mac4 \
             --output_schedule_path=mac4.schedule.txt \
             mac4.opt.ir > /dev/null
cat mac4.schedule.txt
----

각 IR 노드가 몇 단계에 배정됐는지, 단계별 추정 지연이 얼마인지 볼 수 있습니다.

== 직접 확인하기

[source,bash]
----
# mac4 를 단계 수를 바꿔 가며 합성해, 나오는 Verilog 의 always 블록/레지스터 수가 달라지는지 본다
for K in 1 2 3 4; do
  codegen_main --generator=pipeline --delay_model=unit --pipeline_stages=$K \
               --top=mac4 mac4.opt.ir > mac4_$K.v
  echo "K=$K:"; grep -c 'always' mac4_$K.v
done

# clock_period_ps 를 아주 작게 줘서 스케줄 불가 오류를 유도해 본다
----

다음 장은 가장 단순한 출력 — 시간이 전혀 없는 조합 회로 Verilog — 부터입니다.
