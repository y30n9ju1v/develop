DSLX에는 `while`도, 재귀도 없습니다. 반복 수단은 `for` 하나뿐이고, 그마저도 우리가 아는 "카운터를 돌리는 문"이 아니라 **누적자를 접는 표현식**입니다.

== for의 모양

[source,dslx]
----
fn sum_to(n: u32) -> u32 {
    for (i, acc): (u32, u32) in u32:0..n {
        acc + i
    }(u32:0)
}

#[test]
fn sum_test() {
    assert_eq(sum_to(u32:5), u32:10);   // 0+1+2+3+4
}
----

조각별로:

* `for (i, acc): (u32, u32) in u32:0..n { ... }(u32:0)`
* `(i, acc)` — 루프 변수. `i`는 반복 인덱스, `acc`는 **누적자**입니다.
* `: (u32, u32)` — `(i, acc)`의 타입 표기.
* `in u32:0..n` — 반복 범위. `i`가 `0`부터 `n-1`까지.
* `{ acc + i }` — 본문. 이 표현식의 값이 **다음 반복의 `acc`**가 됩니다.
* `(u32:0)` — 마지막 괄호는 **`acc`의 초깃값**입니다.
* `for ... ( init )` 전체가 하나의 표현식이고, 그 값은 **마지막 반복의 본문 값**입니다.

즉 `for`는 `fold`입니다. 초깃값에서 시작해 매 반복 본문으로 `acc`를 갱신하고, 최종 `acc`를 돌려줍니다.

== 반복 범위는 상수여야 한다

위 `sum_to(n)`에서 `n`이 런타임 파라미터인데 `u32:0..n`을 썼습니다. 이건 XLS가 받아들이되, **`n`의 상한이 타입 폭으로 정해진다**는 점을 알아야 합니다. 실무에서는 범위를 컴파일 타임 상수나 파라메트릭 값으로 두는 쪽이 안전합니다.

[source,dslx]
----
fn popcount<N: u32>(x: uN[N]) -> u32 {
    for (i, acc): (u32, u32) in u32:0..N {
        acc + (x[i +: u1] as u32)     // i 번째 비트를 뽑아 더한다
    }(u32:0)
}

#[test]
fn popcount_test() {
    assert_eq(popcount(u8:0b1011_0100), u32:4);
}
----

`N`은 파라메트릭 상수이므로 XLS는 루프를 정확히 `N`번 펼칩니다. `x[i +: u1]`은 "`i`에서 시작해 1비트" 슬라이스입니다(`+:`는 폭 지정 슬라이스).

== 루프는 회로로 어떻게 펼쳐지나

`popcount(u8:...)`는 루프가 8번 펼쳐진 **조합 회로**가 됩니다. 8개의 1비트 추출과 8단 덧셈 트리(도구가 재배치하면 로그 깊이)로요. 시간축은 전혀 들어가지 않습니다 — 한 사이클에 다 계산됩니다.

만약 이 8단 덧셈이 목표 클럭 주기를 넘는다면? 그때 파이프라인 스케줄러(9장)가 이 조합 그래프를 잘라 레지스터를 끼웁니다. 다시 강조하지만, **루프를 몇 사이클에 나눠 처리할지는 `for`에 적혀 있지 않습니다.** 나눠 처리(초기화 간격 > 0)가 정말 필요하면 그건 `for`가 아니라 proc의 일입니다.

== 예제: CRC32 한 바이트

CRC는 대표적인 "비트를 하나씩 훑으며 누적"하는 계산이라 `for`와 잘 맞습니다. XLS 튜토리얼 "For Expressions (CRC32)"가 다루는 형태를 옮기면 대략 이렇습니다.

[source,dslx]
----
// 반사(reflected) CRC32, 다항식 0xEDB88320. 한 바이트를 기존 crc 에 반영.
fn crc32_byte(crc: u32, byte: u8) -> u32 {
    let crc = crc ^ (byte as u32);
    for (_, crc): (u32, u32) in u32:0..u32:8 {
        let lsb = crc & u32:1;
        let shifted = crc >> u32:1;
        if lsb == u32:1 { shifted ^ u32:0xEDB8_8320 } else { shifted }
    }(crc)
}

#[test]
fn crc32_test() {
    // "a" (0x61) 한 바이트의 CRC32 초기 상태 처리 결과
    let crc0 = u32:0xFFFF_FFFF;
    let crc1 = crc32_byte(crc0, u8:0x61);
    // 최종 CRC 는 보통 ~crc 로 마무리한다
    assert_eq(!crc1, u32:0xE8B7_BE43);
}
----

바깥에서 각 바이트마다 `crc32_byte`를 호출하면 전체 메시지의 CRC가 됩니다. 8회 루프는 조합 회로로 펼쳐지고, 메시지 길이만큼의 호출을 접는 것은 상위 `for`나(길이가 상수면) proc가(스트리밍이면) 맡습니다.

[NOTE]
====
위 `assert_eq`의 기대값은 표준 CRC32("a" → `0xE8B7BE43`)를 근거로 적었지만, 이 책은 실행 검증을 하지 못했습니다. `dslx_interpreter_main`으로 돌려 값을 맞춰 보세요. 어긋나면 초기값/최종 반전/바이트 반사 관례를 점검합니다.
====

== 정리

* `for`는 `fold`다: `for (i, acc) in 범위 { 새 acc }(초기 acc)`.
* 범위는 컴파일 타임에 정해져야 도구가 펼친다.
* 펼쳐진 루프는 조합 회로다. 시간에 나누는 건 스케줄러(9장) 또는 proc(12장)의 몫이다.
