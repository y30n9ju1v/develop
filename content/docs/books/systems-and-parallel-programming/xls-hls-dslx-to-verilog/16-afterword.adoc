이 책은 DSLX 하나를 프런트엔드로 삼아 IR → 최적화 → 스케줄링 → Verilog → proc → 형식 검증을 한 번씩 지났습니다. XLS에는 이 경로 바깥에 더 있습니다.

== XLS[cc]: C++ 프런트엔드

`XLS[cc]`는 {cpp}의 부분집합을 XLS IR로 낮춥니다. 기존 {cpp} 알고리즘 코드가 있고 그걸 하드웨어로 옮기려는 팀을 위한 경로입니다. 정수 폭(`ac_int` 계열), 채널, 메모리, 상태, 파이프라인 루프를 지원합니다. IR 아래로는 이 책에서 배운 것과 완전히 같은 파이프라인을 씁니다 — `opt_main`, 스케줄러, `codegen_main`이 그대로 적용됩니다. 즉 **IR이 진짜 인터페이스**이고, DSLX와 {cpp}는 그 위의 두 표면입니다.

DSLX와 {cpp} 중 무엇을 고를까: 새로 설계한다면 하드웨어를 위해 만들어진 DSLX가 함정이 적습니다(임의 폭, 파라메트릭 폭 산술, 재귀 금지). 이식할 {cpp} 자산이 크면 XLS[cc]가 지름길입니다.

== Network-on-Chip 생성

XLS에는 NoC(칩 내부 상호연결) 토폴로지를 기술하고 라우터·링크를 생성하는 실험적 경로가 있습니다. 여러 가속기 블록을 한 다이에 얹고 그 사이 트래픽을 다뤄야 할 때의 도구입니다. 이 책 범위 밖이지만, "proc 네트워크를 크게 키우면 결국 상호연결 설계 문제가 된다"는 흐름의 연장선입니다.

== 주변 도구

* **언어 서버 (LSP)** — 에디터에서 DSLX 타입 오류·정의 이동. 개발 왕복을 줄여 줍니다.
* **퍼저** — 무작위 DSLX 프로그램을 생성해 인터프리터 vs JIT vs 합성 결과를 대조하는 XLS 자체의 회귀 방어.
* **`benchmark_main`** — IR의 추정 지연·노드 수·임계경로를 빠르게 봅니다. 스케줄 목표를 정하기 전 감을 잡는 용도.
* **표준 라이브러리** — `std`, `float32`, `apfloat`, `bfloat16` 등. 전부 순수 DSLX라 읽어서 배울 수 있습니다.

== HLS는 RTL을 대체하지 않는다

정직하게 짚을 것:

* **잘 맞는 곳** — 데이터패스가 무겁고 제어가 규칙적인 것. DSP 필터, 암호 프리미티브, 부동소수점 유닛, 텐서 연산, 프로토콜 인코더/디코더. 알고리즘이 자주 바뀌고 파이프라인 깊이를 실험해야 하는 것.
* **덜 맞는 곳** — 사이클 단위로 손 튜닝한 타이밍이 필요한 것, 비표준 클럭·전력 도메인이 얽힌 것, 아날로그 인접 블록. 이런 곳은 여전히 RTL을 직접 씁니다.
* **현실적 위치** — XLS가 만든 Verilog는 하류 합성 도구(OpenROAD, 상용)의 입력입니다. 면적·전력·타이밍 마감은 그쪽에서 하고, XLS는 그 앞단에서 "알고리즘 ↔ 마이크로아키텍처" 반복을 빠르게 만듭니다.

== 이 사이트의 다른 책들과

* **nand2npu 시리즈** — MLIR/CIRCT로 하드웨어를 방출. XLS와 목적지가 같고(합성 가능한 RTL), 경로가 다릅니다. 두 툴체인의 IR·스케줄링 철학을 비교해 보면 좋습니다.
* **언어를 처음부터 끝까지 (MLIR로 짓는 작은 함수형 언어)** — 같은 "프런트엔드 → IR → 낮추기 → 실행" 골격을 소프트웨어 쪽으로. XLS IR과 MLIR을 나란히 두면 "IR이란 무엇을 위한 것인가"가 또렷해집니다.
* **Lean4 시리즈의 귀납** — 12장 proc의 `next`를 "상태에 대한 귀납"으로 읽은 관점은 그 책들의 귀납적 정의와 같은 뼈대입니다.

== 더 읽을거리

* XLS 공식 문서 — DSLX 레퍼런스와 표준 라이브러리, 튜토리얼(Hello XLS, Float-to-int, For/CRC32, Parametrics, Procs), codegen 옵션, IR 시맨틱, 스케줄링, 형식 검증.
* XLS 저장소의 `xls/examples/` — `dot_product`, `crc32`, 각종 부동소수점 유닛 등 완결된 설계.
* SDC 스케줄링, translation validation을 다룬 XLS 설계 문서들.

이 책의 도구 사슬(`dslx_interpreter_main` → `ir_converter_main` → `opt_main` → `check_ir_equivalence_main` → `codegen_main` → iverilog)을 한 번 손으로 관통해 보면, "소프트웨어처럼 짜서 합성 가능한 하드웨어로"가 구호가 아니라 실제 명령어 몇 줄이라는 걸 알게 됩니다.
