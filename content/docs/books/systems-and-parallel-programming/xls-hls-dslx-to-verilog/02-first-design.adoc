== 파일 하나로 시작

DSLX 소스의 확장자는 관례적으로 `.x`입니다. `hello.x`를 만듭니다.

[source,dslx]
----
// hello.x

// 두 개의 32비트 무부호 정수를 더한다.
fn add(x: u32, y: u32) -> u32 {
    x + y
}

#[test]
fn add_test() {
    assert_eq(add(u32:2, u32:3), u32:5);
    assert_eq(add(u32:0, u32:0), u32:0);
}
----

읽는 법:

* `fn add(x: u32, y: u32) -> u32` — 파라미터마다 타입이 필수이고, 반환 타입도 `->` 뒤에 필수입니다. 추론에 기대지 않습니다.
* 함수 본문의 **마지막 표현식이 반환값**입니다. `return` 키워드도 있지만, 표현식 언어답게 값을 그냥 두는 쪽이 관용적입니다. 마지막 표현식 뒤에는 세미콜론을 붙이지 않습니다.
* `u32:2` — 리터럴에 타입이 붙어 있습니다. 그냥 `2`가 아닙니다. DSLX에는 "기본 정수 타입"이 없어서, 모든 리터럴이 자기 폭을 밝혀야 합니다.
* `#[test]` — 이 어트리뷰트가 붙은 함수는 인터프리터가 테스트로 실행합니다. 합성에는 포함되지 않습니다.
* `assert_eq(a, b)` — 두 값이 다르면 테스트 실패. 세미콜론으로 끝나는 문(statement) 형태입니다.

== 실행

[source,bash]
----
dslx_interpreter_main hello.x
----

`hello.x`의 모든 `#[test]`를 돌리고 통과/실패를 보고합니다. 이것이 DSLX 개발의 가장 짧은 왕복입니다 — 파일을 저장하고, 이 명령을 돌리고, 결과를 본다.

== 왜 리터럴에 타입을 붙이나

`add(u32:2, u32:3)`에서 `u32:`를 빼고 `add(2, 3)`이라고 쓰면 타입 오류입니다. 번거로워 보이지만 이유가 있습니다. 하드웨어에서 `2`는 몇 비트입니까? 2비트? 32비트? 폭이 곧 회로 넓이이므로, DSLX는 폭을 추측하지 않습니다. 리터럴 하나하나가 자기 폭을 선언해야 합니다.

덕분에 이런 실수가 컴파일 타임에 잡힙니다.

[source,dslx]
----
fn narrow(x: u8) -> u8 { x + u8:1 }

#[test]
fn bad() {
    // 오류: u32 리터럴을 u8 파라미터에 넘길 수 없다. 폭이 다르다.
    // assert_eq(narrow(u32:255), u8:0);

    // 맞는 표현: u8:255 + u8:1 은 u8 안에서 0으로 랩어라운드
    assert_eq(narrow(u8:255), u8:0);
}
----

`u8:255 + u8:1 == u8:0` — 무부호 8비트 덧셈은 256에서 자연스럽게 0으로 돌아옵니다. 하드웨어 가산기가 캐리를 버리는 그대로입니다. 이 랩어라운드 규칙은 3장에서 부호 있는 경우까지 정리합니다.

== 기본 스칼라 타입

[cols="1,2,2", options="header"]
|===
| 타입 | 뜻 | 리터럴 예

| `bool`
| 1비트 (`u1`의 별칭). 조건식의 타입.
| `true`, `false`

| `u1`, `u2`, … `u64` …
| N비트 무부호 정수. 폭 제한이 사실상 없습니다.
| `u8:0xff`, `u12:100`

| `s1`, `s2`, … `s64` …
| N비트 2의 보수 부호 정수.
| `s8:-1`, `s16:1000`

| `bits[N]`
| `uN[N]`과 같은 저수준 표기. `u8` == `bits[8]`.
| `bits[8]:0b1010_1010`

| `()`
| 유닛(빈 튜플). 값이 없음을 뜻합니다.
| `()`
|===

숫자 리터럴에는 `_` 자릿수 구분자, `0x`(16진), `0b`(2진)을 쓸 수 있습니다. `u16:0b0001_0000_0000_0000`처럼요.

== 이름 묶기: let은 덮어쓰기가 아니다

[source,dslx]
----
fn poly(x: u32) -> u32 {
    let a = x * x;        // a 를 새로 묶는다
    let b = a + x;        // b 를 새로 묶는다
    let a = b * u32:2;    // "a" 라는 이름을 다시 묶는다 — 앞의 a 를 바꾸는 게 아니라 가린다(shadow)
    a
}
----

`let a = ...`가 두 번 나와도 이것은 재대입이 아니라 **섀도잉**입니다. 첫 `a`가 담긴 배선은 그대로 있고, 두 번째 `let a`는 그 이름을 새 배선에 다시 붙입니다. 회로로 보면 배선 세 가닥(`a₁`, `b`, `a₂`)이 있고 마지막에 `a₂`를 반환하는 것입니다.

== 명세를 코드 옆에 둔다

DSLX에서 `#[test]`는 곁다리가 아니라 워크플로의 중심입니다. 함수를 적을 때마다 그 기대 동작을 `assert_eq`로 몇 줄 남겨 두면, 이후 최적화(8장)나 파이프라인 합성(11장)을 거친 뒤에도 같은 입력이 같은 출력을 내는지 IR·시뮬레이션 수준에서 다시 확인할 수 있습니다. XLS는 "DSLX 테스트 → IR 평가 → Verilog 시뮬레이션"을 같은 벡터로 관통시키는 것을 전제로 설계돼 있습니다.
