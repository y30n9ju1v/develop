== 이 책이 하려는 것

`riir-json-parser` 책에서 C의 `cJSON`을 기준 삼아 Rust로 JSON 파서를 짓고, 마지막엔 C·C++23보다도 빠르게 만들었습니다. 그런데 그 파서는 Rust 프로그램 안에서만 쓸 수 있었습니다 — 실제로 이 도구가 쓸모 있으려면, 파이썬처럼 다른 언어에서도 불러다 쓸 수 있어야 합니다. 이 책은 그 파서를 **PyO3**(Rust ↔ 파이썬 바인딩 라이브러리)와 **`maturin`**(Rust 확장 모듈을 파이썬 패키지로 빌드하는 도구)으로 감싸서, 파이썬에서 `import riirjson; riirjson.parse_json(text)`처럼 그냥 함수 하나를 부르는 것처럼 쓸 수 있게 만듭니다.

== 미리 밝혀둘 반전

이 책도 앞선 책처럼 벤치마크를 실제로 재고, 결과가 예상과 다르면 그대로 싣습니다. 미리 하나 밝혀두면 — **파이썬 확장 모듈로 감싼 Rust 파서가, 파이썬 표준 `json` 모듈보다 오히려 느리게 나왔습니다.** Rust 파서 자체는 여전히 빠른데도 그렇습니다. 이 책의 5~7장이 그 이유를 실제로 추적합니다 — 답은 "파싱"이 아니라 "파이썬 객체를 만드는 비용"에 있었습니다. 이게 이 책에서 가장 중요한 교훈이기도 합니다 — **언어 경계를 넘나드는 순간, 그 경계를 넘는 비용 자체가 새로운 병목이 될 수 있습니다.**

== 이 책의 구조

*1부(1~2장)* 는 PyO3와 `maturin`을 셋업하고, Rust 파서의 결과(`Value` enum)를 파이썬 `dict`/`list`/`str`로 변환합니다.

*2부(3~4장)* 는 Rust의 `Result`를 파이썬 예외로 매핑하고, 파이썬 표준 `json`과 결과가 정확히 일치하는지 검증합니다.

*3부(5~7장)* 는 이 책의 핵심입니다 — 첫 벤치마크에서 파이썬 표준 `json`이 더 빨랐던 결과를 그대로 싣고, 파싱과 파이썬 객체 변환을 단계별로 쪼개 진짜 병목을 찾아낸 뒤, GIL(Global Interpreter Lock)을 실제로 풀어 병렬성을 검증합니다.

*4부(8~10장)* 는 이 확장 모듈을 실제로 `pip install` 가능한 wheel로 패키징합니다 — 만든 컴퓨터가 아닌 완전히 새로운 가상환경에 설치해서, 정말 독립적으로 동작하는지까지 확인합니다.

== 실측 원칙

이 책의 모든 코드는 `cargo`/`maturin`으로 실제 빌드하고, 파이썬에서 실제로 `import`해서 호출했습니다. 벤치마크는 `timeit`으로 실측했고, 좋은 결과든 나쁜 결과든 그대로 싣습니다.

== 사전 지식

`riir-json-parser` 책(또는 그에 준하는 Rust 기초)과 파이썬 기본 문법이면 충분합니다. PyO3나 `maturin`을 한 번도 안 써봤어도, 이 책 안에서 필요한 만큼 설명합니다.
