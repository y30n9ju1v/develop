3장의 ``TransformWorker::transform``은 ``x * 2.0``이라는 자리표시자였습니다. PerfGrid가 실제로 하는 일은 대개 신호 변환처럼 좀 더 무거운 수학 함수입니다 — 이 장에서는 그 계산이 유한한 입력 범위에서 반복된다면, **컴파일 타임에 미리 계산해서 바이너리에 굽고, 실행 중에는 조회만** 하도록 바꿉니다.

== `consteval`: 반드시 컴파일 타임에만 실행되는 함수

[source,cpp]
----
consteval double make_value(double x) { return x * 2.0; }

int main() {
  double runtime_val = 3.0;
  double r = make_value(runtime_val);  // 에러!
}
----

[source]
----
$ clang++ -std=c++23 -O0 consteval_enforce.cpp -o /tmp/y
consteval_enforce.cpp:8:14: error: call to consteval function 'make_value' is not a constant expression
    8 |   double r = make_value(runtime_val);
      |              ^
consteval_enforce.cpp:8:25: note: read of non-constexpr variable 'runtime_val' is not allowed in a constant expression
----

`constexpr`(C{pp}11)는 "컴파일 타임에도, 런타임에도 실행될 수 있다"는 뜻이지만, `consteval`(C{pp}20)은 "**반드시** 컴파일 타임에만 실행될 수 있다"는 더 강한 보장입니다. 조회 테이블에는 이 보장이 딱 맞습니다 — "이 테이블이 혹시라도 런타임에 다시 계산되는" 실수를 원천적으로 막고 싶기 때문입니다.

== ``TransformWorker::transform``을 조회 테이블로 바꾸기

[source,cpp]
----
constexpr std::size_t kLutSize = 4096;
consteval std::array<double, kLutSize> make_sin_table() {
  std::array<double, kLutSize> table{};
  for (std::size_t i = 0; i < kLutSize; i++) {
    double x = (static_cast<double>(i) / kLutSize) * 2.0 * 3.14159265358979323846;
    // std::sin은 이 libc++에서 아직 constexpr이 아니라서 -- 직접 테일러 급수로 근사한다
    double term = x, sum = x, x2 = x * x;
    for (int k = 1; k <= 8; k++) {
      term *= -x2 / ((2 * k) * (2 * k + 1));
      sum += term;
    }
    table[i] = sum;
  }
  return table;
}
constexpr std::array<double, kLutSize> kSinTable = make_sin_table();
double fast_sin(double x) {
  std::size_t idx = static_cast<std::size_t>((x / (2.0 * 3.14159265358979323846)) * kLutSize) % kLutSize;
  return kSinTable[idx];
}

struct TransformWorker {
  void process(this auto&& self, std::mdspan<double, std::dextents<std::size_t, 2>, std::layout_stride> tile) {
    for (std::size_t s = 0; s < tile.extent(0); s++)
      for (std::size_t e = 0; e < tile.extent(1); e++)
        tile[s, e] = self.transform(tile[s, e]);
  }
  double transform(double x) { return fast_sin(x); }  // 3장의 x * 2.0에서 교체
};
----

``kSinTable``은 `constexpr` 전역 변수로 선언했고 초기값이 `consteval` 함수 호출이므로, ``4096``칸 전부가 **컴파일이 끝나는 시점에 이미 계산되어 실행 파일 안에 상수 데이터로 박혀** 있습니다. ``TransformWorker::process``의 나머지 부분은 3장과 완전히 동일합니다 — ``transform``의 몸통만 바뀌었습니다.

조회 버전이 **6배 가까이** 빠릅니다(반복 측정 시 5~9배 사이로 편차가 있었습니다) — 배열 인덱싱 하나가 부동소수점 삼각함수 계산 전체보다 훨씬 쌉니다. 다만 이건 정밀도와 맞바꾼 속도입니다 — ``4096``칸 테이블은 ``2π``를 그만큼만 나눈 것이므로 ``std::sin``과 완전히 같지는 않은 양자화 오차를 갖습니다.

== 요약

* ``consteval``은 함수가 반드시 컴파일 타임에만 평가되도록 강제하고, 런타임 값을 넘기면 컴파일이 실패한다는 걸 확인했습니다.
* ``TransformWorker::transform``의 몸통을 자리표시자에서 `consteval` 조회 테이블 기반 ``fast_sin``으로 교체했습니다 — ``process``를 비롯한 나머지 구조는 3장과 그대로입니다.
* 이 속도는 테이블 해상도만큼의 정밀도와 맞바꾼 것이라, 오차를 허용할 수 있는 자리에서만 쓸 만한 트레이드오프라는 것도 짚었습니다.

다음 장에서는 ``TransformWorker``를 실제로 여러 스레드에 분배하는 ``Coordinator``를 만들고, ``std::atomic_ref``로 각 워커의 진행률을 락 없이 추적합니다.

== 팁 박스: C{pp}17 환경이라면

``consteval``은 **C{pp}20**부터입니다. C{pp}17에는 "이 함수는 반드시 컴파일 타임에만 평가되어야 한다"를 강제하는 언어 기능이 없고, `constexpr`(C{pp}11부터)만 있습니다 — `constexpr` 함수는 컴파일 타임 평가를 **허용**할 뿐, 런타임 문맥에서 부르면 그냥 런타임에 돕니다. 실무에서 쓰는 대체법은 `constexpr` 함수를 짜되, 반드시 `constexpr` 변수를 초기화하는 자리에서만 호출해서 사실상 컴파일 타임 평가를 강제하는 것입니다.

[source,cpp]
----
constexpr std::array<double, 8> build_table() {
    std::array<double, 8> table{};
    for (int i = 0; i < 8; ++i) {
        double x = i * 0.1;
        table[i] = x - (x * x * x) / 6.0;  // sin(x) 근사(예시)
    }
    return table;
}

// 이 초기화 자체가 constexpr 컨텍스트이므로 build_table()은 컴파일 타임에 평가됩니다.
constexpr std::array<double, 8> kTable = build_table();
----

``-std=c{pp}17 -Wall -Wextra``로 경고 없이 컴파일되고, ``kTable``은 컴파일 타임에 채워집니다.

잃는 건 컴파일러가 보증해주는 계약입니다. `consteval` 함수는 런타임 값(예: 사용자 입력)을 넘기면 그 자리에서 컴파일이 실패합니다 — "이 함수는 절대 런타임에 실행되지 않는다"는 게 타입 시스템 수준의 보장입니다. ``constexpr``로 흉내 낸 위 코드는 ``build_table()``을 런타임 변수에 대입하는 식으로도 아무 경고 없이 호출할 수 있습니다 — "컴파일 타임에만 써야 한다"는 규칙이 코드 관례로만 지켜질 뿐, 실수로 런타임에 부르는 걸 컴파일러가 막아주지 않습니다.
