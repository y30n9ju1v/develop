'''

TaskGrid 워커가 배치를 처리하며 같은 수학 함수(예: 삼각함수 기반 신호 변환)를 수백만 번 호출해야 한다면, 그 함수의 입력이 유한하고 미리 알 수 있는 범위라면 굳이 매번 다시 계산할 필요가 없습니다 — **컴파일 타임에 미리 계산해서 바이너리에 구워 넣고, 실행 중에는 조회만 하면** 됩니다. C++23은 `constexpr`가 허용되는 범위를 크게 넓혔고, `consteval`로 "이 계산은 반드시 컴파일 타임에 끝나야 한다"는 걸 강제할 수 있습니다.

== `consteval`: 반드시 컴파일 타임에만 실행되는 함수

[source,cpp]
----
consteval double make_value(double x) {
  return x * 2.0;
}

int main() {
  double runtime_val = 3.0;
  double r = make_value(runtime_val);  // 에러!
}
----

[source]
----
$ clang++ -std=c++23 -O0 consteval_enforce.cpp -o /tmp/y
consteval_enforce.cpp:8:14: error: call to consteval function 'make_value' is not a constant expression
    8 |   double r = make_value(runtime_val);
      |              ^
consteval_enforce.cpp:8:25: note: read of non-constexpr variable 'runtime_val' is not allowed in a constant expression
----

`constexpr`(C++11)는 "컴파일 타임에도, 런타임에도 실행될 수 있다"는 뜻이지만, `consteval`(C++20)은 "**반드시** 컴파일 타임에만 실행될 수 있다"는 더 강한 보장입니다 — 런타임 값(`runtime_val`)을 `consteval` 함수에 넘기려 하면 컴파일 자체가 실패합니다. 이 장의 조회 테이블에는 이 보장이 딱 맞습니다 — "이 테이블이 혹시라도 런타임에 다시 계산되는" 실수를 원천적으로 막고 싶기 때문입니다.

== 사인 근사 조회 테이블을 컴파일 타임에 굽기

[source,cpp]
----
constexpr std::size_t N = 4096;

consteval std::array<double, N> make_sin_table() {
  std::array<double, N> table{};
  for (std::size_t i = 0; i < N; i++) {
    double x = (static_cast<double>(i) / N) * 2.0 * 3.14159265358979323846;
    // std::sin은 이 libc++에서 아직 constexpr이 아니라서 -- 직접 테일러 급수로 근사한다
    double term = x, sum = x, x2 = x * x;
    for (int k = 1; k <= 8; k++) {
      term *= -x2 / ((2 * k) * (2 * k + 1));
      sum += term;
    }
    table[i] = sum;
  }
  return table;
}

constexpr std::array<double, N> kSinTable = make_sin_table();

double fast_sin(double x) {
  std::size_t idx = static_cast<std::size_t>((x / (2.0 * 3.14159265358979323846)) * N) % N;
  return kSinTable[idx];
}
----

`make_sin_table`은 8차 테일러 급수로 `sin`을 근사해 `[0, 2π)` 구간을 `4096`칸으로 나눈 표를 만듭니다(`std::sin` 자체는 이 세션의 `libc++`에서 아직 `constexpr`로 표시되어 있지 않아서, 표를 채우는 계산에는 직접 짠 테일러 급수를 씁니다 — 표준 라이브러리 함수가 `constexpr` 지원 범위에 들어왔는지는 구현마다 다르다는 걸 여기서도 확인할 수 있습니다). `kSinTable`은 `constexpr` 전역 변수로 선언했고 초기값이 `consteval` 함수 호출이므로, 이 배열 `4096`칸 전부가 **컴파일이 끝나는 시점에 이미 계산되어 실행 파일 안에 상수 데이터로 박혀** 있습니다 — `main`이 실행되는 순간에는 이미 다 채워진 테이블만 남아 있습니다.

== 벤치마크: 조회 vs 매번 계산

[source,cpp]
----
constexpr int iters = 2'000'000;

double s1 = 0;
for (int i = 0; i < iters; i++) s1 += kSinTable[(idx + i) % N];      // 조회

double s2 = 0;
for (int i = 0; i < iters; i++) {
  double x = (static_cast<double>((idx + i) % N) / N) * 2.0 * 3.14159265358979323846;
  s2 += std::sin(x);                                                  // 매번 계산
}
----

[source]
----
$ clang++ -std=c++23 -O2 consteval_lut.cpp -o consteval_lut && ./consteval_lut
LUT lookup:      1.89 ms (sum=1772.1543)
std::sin() call: 11.55 ms (sum=668.1940)
table[0]=0.000000 (should be ~0)
table[N/4]=1.000000 (should be ~1)
----

`table[0]`이 `0`에, `table[N/4]`(`π/2` 근처)가 `1`에 가깝다는 것으로 테이블 값 자체가 맞다는 것도 확인했습니다. 조회 버전이 `std::sin()`을 직접 부르는 버전보다 6배 가까이 빠릅니다 — 배열 인덱싱(캐시에 올라간 작은 테이블 안에서의 조회) 하나가, 부동소수점 삼각함수 계산 전체보다 훨씬 쌉니다. 다만 이건 정밀도와 맞바꾼 속도입니다 — `4096`칸 테이블은 `2π`를 그 칸 수만큼만 나눈 것이므로, `fast_sin`의 결과는 `std::sin`과 완전히 같지 않고 양자화 오차(테이블 칸 사이의 간격만큼)를 갖습니다. 신호 처리처럼 약간의 오차를 허용할 수 있는 자리에서는 남는 장사지만, 정밀도가 중요한 계산에는 맞지 않습니다.

== TaskGrid에 적용한다면

TaskGrid 워커가 배치마다 같은 변환 함수(코덱, 정규화, 스케일링 등)를 반복 적용한다면, 그 함수의 입력 범위가 유한하고 미리 알 수 있는 만큼은 `consteval`로 조회 테이블을 만들어 두는 게 이득입니다 — 특히 이 함수가 배치 처리의 핫 패스(가장 자주 실행되는 경로)에 있다면, 테이블 하나로 대체하는 것만으로 전체 처리량이 눈에 띄게 늘어날 수 있습니다. `consteval`을 쓰면 "이 테이블이 실수로 런타임에 재계산되게 리팩터링되는" 회귀도 컴파일 에러로 막아줍니다.

== 요약

* `consteval`은 `constexpr`보다 강한 보장입니다 — 함수가 반드시 컴파일 타임에만 평가되도록 강제하고, 런타임 값을 넘기려 하면 컴파일이 실패한다는 걸 직접 확인했습니다.
* `consteval` 함수로 초기화한 `constexpr` 배열은 컴파일이 끝나는 시점에 이미 다 채워진 상수 데이터로 바이너리에 박히고, 조회 한 번이 부동소수점 함수 호출 전체보다 훨씬 빠르다는 걸 실측(약 6배)으로 확인했습니다.
* 이 속도는 테이블 해상도만큼의 정밀도와 맞바꾼 것이라, 오차를 허용할 수 있는 자리에서만 쓸 만한 트레이드오프라는 것도 함께 짚었습니다.

다음 장에서는 계산이 아니라 메모리 할당 쪽 — `allocate_at_least`로 벡터가 실제로 확보한 용량을 정확히 알아내 재할당 낭비를 줄이는 법을 다룹니다.
