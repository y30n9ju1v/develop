'''

1장에서는 순회 순서와 저장 순서가 맞아떨어지면 빠르고, 어긋나면 느려진다는 걸 봤습니다. 그런데 실전에서는 항상 "맞는 방향"으로만 순회할 수 있는 게 아닙니다 — TaskGrid가 "세그먼트 우선"으로 저장한 버퍼를, 어떤 워커는 "모든 세그먼트의 특정 구간만" 훑어야 할 수도 있습니다. 이 장에서는 **캐시를 최대한 재사용하는 순서로 접근 자체를 재구성**하는 타일링(블록화) 기법과, 그 타일 하나를 가리키는 뷰를 복사 없이 만드는 `layout_stride`를 다룹니다.

== 최악의 경우: 전치 방향 순회

버퍼가 `[row][col]`(`layout_right`, 행 우선) 순서로 저장되어 있는데, 어떤 이유로든 열을 바깥, 행을 안쪽에 두고 순회해야 한다고 합시다 — 1장의 `sum_col_major`와 같은 모양입니다.

[source,cpp]
----
constexpr std::size_t rows = 6000, cols = 6000;
std::mdspan<double, std::dextents<std::size_t, 2>> m(buf.data(), rows, cols);

auto naive_transpose_sum = [&] {
  double s = 0;
  for (std::size_t j = 0; j < cols; j++)
    for (std::size_t i = 0; i < rows; i++)
      s += m[i, j];
  return s;
};
----

[source]
----
$ clang++ -std=c++23 -O2 mdspan_stride.cpp -o mdspan_stride && ./mdspan_stride
naive column-outer sum: 82.22 ms (sum=36000000)
----

6000×6000 규모에서는 1장의 4000×4000보다 훨씬 크게 느려집니다 — 안쪽 루프 한 번마다 `6000 * 8바이트`(약 47KB)씩 건너뛰는데, 이건 대부분의 CPU L1 캐시(보통 32~48KB) 크기를 넘어섭니다. 그러니 안쪽 루프가 한 바퀴 돌 때마다 방금 캐시에 올린 데이터가 이미 밀려나 있을 수 있습니다.

== 타일링: 작은 블록 단위로 순회 순서를 재구성하기

이 문제의 표준 해법은 **타일링(블록화, tiling/blocking)**입니다 — 전체를 한 방향으로 쭉 훑는 대신, `tile × tile` 크기의 작은 정사각형 블록으로 잘라서, 블록 하나를 통째로 다 쓴 다음에야 다음 블록으로 넘어갑니다. 블록 하나가 캐시에 통째로 들어갈 만큼 작으면, 그 블록 안에서는 어느 순서로 접근해도 캐시 밖으로 안 밀려납니다.

[source,cpp]
----
constexpr std::size_t tile = 64;
auto tiled_transpose_sum = [&] {
  double s = 0;
  for (std::size_t jj = 0; jj < cols; jj += tile)
    for (std::size_t ii = 0; ii < rows; ii += tile)
      for (std::size_t j = jj; j < std::min(jj + tile, cols); j++)
        for (std::size_t i = ii; i < std::min(ii + tile, rows); i++)
          s += m[i, j];
  return s;
};
----

[source]
----
$ clang++ -std=c++23 -O2 mdspan_stride.cpp -o mdspan_stride && ./mdspan_stride
naive column-outer sum: 82.22 ms (sum=36000000)
tiled (blocked) sum:    26.19 ms (sum=36000000)
----

바깥의 두 루프(`jj`, `ii`)가 "어느 타일 차례인가"를 정하고, 안쪽 두 루프(`j`, `i`)가 그 타일 **안에서만** 열-우선으로 순회합니다. `tile = 64`짜리 정사각형 블록은 `64 * 64 * 8바이트`(32KB) — 대부분의 L1 캐시에 통째로 들어가는 크기입니다. 그 결과 똑같은 접근 순서(열 우선)를 쓰면서도, 타일 하나에 머무는 동안은 캐시를 최대한 재사용해서 전체 실행 시간이 3배 넘게 줄었습니다 — 순회 알고리즘의 **논리는 그대로**(모든 `(i,j)`를 정확히 한 번씩 방문), 방문 **순서만** 캐시에 맞게 재배열한 것입니다.

== `layout_stride`로 타일 하나를 뷰로 뽑아내기

타일링을 인덱스 계산으로 직접 하는 대신, "이 타일은 그 자체로 독립된 작은 `mdspan`이다"라고 표현하고 싶을 수 있습니다 — 워커 함수가 "타일 하나를 받아서 처리한다"는 인터페이스를 갖게 하려는 것입니다. C++23 표준에는 아직 `std::submdspan`(부분 뷰를 자동으로 뽑아주는 함수, C++26에 예정)이 없어서, 이 세션의 `libc++`에서 실제로 컴파일해보면 이렇게 실패합니다.

[source]
----
$ clang++ -std=c++23 -O2 submdspan_test.cpp -o /tmp/x
submdspan_test.cpp:7:20: error: no member named 'submdspan' in namespace 'std'; did you mean 'mdspan'?
    7 |   auto tile = std::submdspan(m, std::pair{2,5}, std::pair{2,5});
      |                    ^~~~~~~~~
1 error generated.
----

`std::submdspan`이 없어도, 부분 뷰가 **정확히 무엇을 뜻하는지**는 표준 `std::layout_stride`로 손수 조립할 수 있습니다 — 원본과 같은 스트라이드(각 차원으로 한 칸 이동할 때 메모리에서 몇 칸을 건너뛰는지)를 그대로 물려받되, 시작 위치와 크기만 바꾼 새 `mdspan`을 만드는 것입니다.

[source,cpp]
----
std::size_t tile_row0 = 2, tile_col0 = 2, tile_rows = 3, tile_cols = 3;
double* tile_ptr = &full[tile_row0, tile_col0];             // 타일의 시작 주소
std::array<std::size_t, 2> tile_strides{full.stride(0), full.stride(1)};  // 원본과 같은 스트라이드

std::mdspan<double, std::dextents<std::size_t, 2>, std::layout_stride> tile(
    tile_ptr,
    std::layout_stride::mapping{std::dextents<std::size_t, 2>{tile_rows, tile_cols}, tile_strides});
----

[source]
----
$ clang++ -std=c++23 -O2 mdspan_manual_stride.cpp -o mdspan_manual_stride && ./mdspan_manual_stride
  202   203   204
  302   303   304
  402   403   404
----

원본 버퍼는 `buf[i * 10 + j] = i * 100 + j`로 채워져 있고, `(2,2)`에서 시작하는 `3×3` 타일을 뽑으면 정확히 `(202,203,204)/(302,303,304)/(402,403,404)`(2~4행, 2~4열)가 나옵니다 — `tile_ptr`가 가리키는 메모리는 `buf`와 **완전히 같은 메모리**이고(복사가 전혀 없었습니다), `tile[i, j]`에 접근하면 `layout_stride`가 `tile_strides`(원본의 스트라이드)를 써서 올바른 오프셋으로 변환합니다. 이렇게 만든 `tile`은 어떤 `mdspan` 알고리즘에도 그대로 넘길 수 있는 독립된 값입니다 — 호출하는 쪽은 이게 큰 버퍼의 일부라는 걸 몰라도 됩니다.

== 요약

* 순회 순서가 저장 순서와 완전히 어긋나는 최악의 경우(전치 방향 순회)는, 안쪽 루프 한 바퀴가 캐시 크기보다 큰 보폭으로 건너뛰기 때문에 데이터 규모가 커질수록 더 크게 느려집니다.
* 타일링(블록화)으로 접근 순서를 "타일 하나를 다 쓰고 나서 다음 타일로" 재구성하면, 논리적으로 같은 순회를 하면서도 캐시 재사용률이 올라가 실측 3배 넘는 속도 차이가 났습니다.
* `std::submdspan`은 아직 이 툴체인에 없지만, `std::layout_stride`로 원본과 같은 스트라이드를 물려받는 부분 뷰를 손으로 조립하면 복사 없이 타일 하나를 독립된 `mdspan` 값으로 다룰 수 있습니다.

다음 장에서는 메모리 레이아웃을 떠나, C++23의 `deducing this`로 오래된 CRTP 패턴을 단순화하는 법을 다룹니다.
