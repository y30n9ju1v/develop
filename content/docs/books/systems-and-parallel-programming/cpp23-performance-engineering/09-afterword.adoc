== 이 책에서 다룬 것

`std::mdspan`으로 평평한 버퍼를 다차원 뷰로 감싸 순회 순서와 저장 순서를 맞추는 것부터 시작해(1장), `layout_stride`로 그 버퍼의 일부만 복사 없이 가리키는 타일 뷰를 만들고(2장), `deducing this`로 CRTP의 보일러플레이트를 없애고(3장), `consteval`로 런타임 계산을 컴파일 타임 조회 테이블로 옮기고(4장), `allocate_at_least`로 이미 지불한 메모리 여유분을 낭비 없이 쓰고(5장), PMR 스레드 로컬 아레나로 워커 간 할당 경합을 없애고(6장), `views::zip`으로 중간 컨테이너 없이 여러 배열을 짝지어 순회하는 것(7장)까지 다뤘습니다. 마지막 장(8장)에서는 그중 세 가지를 한 파이프라인에 모아 "고치기 전/후"를 나란히 벤치마크했습니다.

전작과 마찬가지로 이 책의 모든 벤치마크는 이 세션의 Apple Clang 21(`-std=c++23`, `-O2`)로 실제로 컴파일하고 실행한 실측치입니다. 이 책이 처음부터 강조했듯, 벤치마크 숫자는 전작의 컴파일 성공/실패나 TSan 리포트처럼 재현 가능한 참/거짓이 아니라 **이 머신, 이 순간의 상대적 차이**입니다 — 그래서 매 장마다 반복 실행으로 대세가 일관됨을 확인한 뒤에야 대표 실행 결과를 실었습니다.

== 안전과 성능은 같은 코드베이스에서 만난다

전작이 TaskGrid를 안전하게 만드는 데 집중했다면, 이 책은 같은 TaskGrid를 빠르게 만드는 데 집중했습니다 — 그런데 이 둘은 서로 다른 코드베이스가 아닙니다. 전작 8장의 `WorkerSession`(타입 상태 + 이동 전용 핸들의 합성)은 이 책이 성능을 최적화한 배치 처리 로직을 감싸는 그릇으로 그대로 재사용할 수 있고, 전작 9장의 락 순서 규칙은 이 책 6장의 PMR 아레나처럼 "애초에 공유 자원을 안 만든다"는 전략과 상충하지 않습니다(오히려 공유 자원 자체를 없애면 락 순서를 신경 쓸 필요도 함께 줄어듭니다). `std::expected`의 `.transform()`/`.and_then()`(전작 10장)으로 감싼 파이프라인 단계 하나하나에, 이 책의 `mdspan`/PMR/`consteval` 최적화를 그대로 끼워 넣을 수 있습니다 — **정확성을 인코딩하는 타입과 성능을 결정하는 메모리 접근 패턴은 서로 다른 층위의 관심사**이기 때문입니다.

== 이 책이 다루지 않은 것

* **SIMD 명시적 벡터화** — `std::experimental::simd`나 컴파일러 내장 함수(intrinsics)로 명시적으로 벡터 레지스터를 쓰는 것은 다루지 않았습니다. `std::mdspan`의 레이아웃 정책은 벡터화하기 좋은 메모리 배치를 만들어주지만, 컴파일러가 실제로 자동 벡터화했는지는 이 책에서 확인하지 않았습니다.
* **GPU 오프로딩** — TaskGrid 워커의 배치 처리를 GPU로 옮기는 것(CUDA, SYCL, 또는 `std::execution`의 GPU 실행기)은 다루지 않았습니다.
* **`std::submdspan`, `views::chunk`/`slide`/`stride`** — C++23/26 표준에는 있지만 이 세션의 `libc++`에는 아직 구현되지 않은 기능들을 2장과 7장에서 실제 컴파일 에러로 확인하고 넘어갔습니다. 구현이 따라잡으면 다시 살펴볼 만합니다.
* **다른 컴파일러/플랫폼과의 비교** — 이 책의 모든 숫자는 Apple Clang 21, Darwin, `libc++` 조합 하나에서만 나왔습니다. GCC/libstdc++나 MSVC, 리눅스 환경에서는 같은 코드가 다른 절대 수치(그리고 어쩌면 다른 상대적 순위)를 낼 수 있습니다 — 이식성 있는 결론을 원한다면 각 플랫폼에서 직접 재현해봐야 합니다.
* **프로파일러 기반 분석** — 이 책은 `std::chrono`로 전체 실행 시간만 쟀습니다. `perf`, Instruments, VTune 같은 프로파일러로 캐시 미스 횟수나 분기 예측 실패율을 직접 측정하는 것은 다루지 않았습니다 — 1장과 6장에서 "캐시 미스 때문일 것"이라고 설명한 부분은 실행 시간 차이로부터의 합리적 추론이지, 프로파일러로 캐시 미스 카운터를 직접 읽은 것은 아닙니다.

== 다음 단계

전작과 이 책을 함께 읽었다면, TaskGrid는 이제 컴파일 타임에 프로토콜을 강제하고, 자원을 안전하게 이동하고, 실패를 자동으로 전파하고, 메모리 레이아웃이 접근 패턴과 맞고, 워커끼리 할당 경합 없이, 반복 계산을 조회 테이블로 대신하는 시스템이 됐습니다. 다음으로 볼 만한 자리는 정확히 이 책이 다루지 않은 것들 — 명시적 벡터화, 프로파일러로 확인하는 실제 캐시 동작, 그리고 두 책 모두 계속 미뤄온 C++26의 `std::execution`(전작 맺음말에서 다룬 스케치를 실제 구현으로 확인하는 것)입니다.
