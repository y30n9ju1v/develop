TaskGrid의 워커는 배치를 처리할 때 대개 평평한 `std::vector<double>` 버퍼 하나를 받습니다. 그 버퍼가 논리적으로는 "세그먼트 여러 개, 세그먼트마다 원소 여러 개"인 2차원 구조라도, C++은 그걸 표현할 표준 방법이 오랫동안 없었습니다 — `buf[i * cols + j]`처럼 인덱스 계산을 직접 손으로 짜거나, 포인터 산술을 감싼 커스텀 클래스를 만들어야 했습니다. C++23의 **`std::mdspan`**이 이 자리를 표준으로 채웁니다.

== `std::mdspan`: 소유하지 않는 다차원 뷰

[source,cpp]
----
#include <mdspan>
#include <vector>

std::vector<double> buf(rows * cols, 1.0);
std::mdspan<double, std::dextents<std::size_t, 2>> m(buf.data(), rows, cols);

double x = m[3, 5];  // C++23의 다중 첨자 연산자(operator[])
----

`std::mdspan`은 포인터 하나와 각 차원의 크기(`extents`)만 들고 있는 **비소유(non-owning) 뷰**입니다 — `buf`의 메모리를 복사하지 않고, 그 위에 "이건 사실 `rows`행 `cols`열짜리 2차원 배열이다"라는 해석만 얹습니다. `m[3, 5]`처럼 콤마로 구분한 여러 첨자를 한 번에 쓰는 문법(다중 첨자 `operator[]`)도 C++23에서 새로 들어온 것입니다 — 이전에는 `operator[]`가 인자를 하나만 받을 수 있어서 `m(3, 5)`처럼 함수 호출 문법을 흉내 내야 했습니다.

== 순회 순서가 메모리 레이아웃과 어긋나면

`std::mdspan`의 기본 레이아웃(`layout_right`)은 마지막 차원이 메모리에서 연속입니다 — 수학의 행 우선(row-major) 저장과 같습니다. 순회 순서가 이 레이아웃과 맞는지 어긋나는지에 따라 캐시 적중률이 크게 달라집니다.

[source,cpp]
----
constexpr std::size_t rows = 4000, cols = 4000;
std::vector<double> buf(rows * cols, 1.0);
std::mdspan<double, std::dextents<std::size_t, 2>> m(buf.data(), rows, cols);

auto sum_row_major = [&] {
  double s = 0;
  for (std::size_t i = 0; i < rows; i++)
    for (std::size_t j = 0; j < cols; j++)
      s += m[i, j];  // 안쪽 루프가 j -- 메모리 연속 방향과 일치
  return s;
};
auto sum_col_major = [&] {
  double s = 0;
  for (std::size_t j = 0; j < cols; j++)
    for (std::size_t i = 0; i < rows; i++)
      s += m[i, j];  // 안쪽 루프가 i -- 매번 4000개(32KB) 건너뛰며 접근
  return s;
};
----

[source]
----
$ clang++ -std=c++23 -O2 mdspan_bench.cpp -o mdspan_bench && ./mdspan_bench
row-major traversal: 20.99 ms (sum=16000000)
col-major traversal: 35.39 ms (sum=16000000)
----

똑같은 합계(`16000000`)를 내지만, 안쪽 루프가 메모리 연속 방향(`j`)과 일치하는 `sum_row_major`가 그렇지 않은 `sum_col_major`보다 눈에 띄게 빠릅니다 — `sum_col_major`는 안쪽 루프 한 번 돌 때마다 `cols * sizeof(double)`(약 32KB)씩 건너뛰며 접근하므로, CPU 캐시 라인(보통 64바이트)을 한 번 가져올 때마다 double 하나만 쓰고 버리는 셈입니다. 반면 `sum_row_major`는 캐시 라인 하나에 들어간 8개의 double을 전부 다 씁니다.

== 진짜 힘: 알고리즘은 그대로 두고 레이아웃 정책만 바꾸기

`std::mdspan`이 단순히 "인덱스 계산을 대신 해주는" 것 이상인 이유는, **레이아웃이 타입 파라미터**라는 점입니다. 똑같은 순회 코드를 템플릿 함수로 한 번만 짜두면, `layout_right`(행 우선 저장)과 `layout_left`(열 우선 저장) 중 어느 쪽을 넘기느냐에 따라 물리적인 메모리 접근 패턴이 완전히 달라집니다 — 알고리즘 코드는 단 한 글자도 바뀌지 않습니다.

[source,cpp]
----
template <typename Layout>
double sum_all(std::mdspan<double, std::dextents<std::size_t, 2>, Layout> m) {
  double s = 0;
  for (std::size_t i = 0; i < m.extent(0); i++)
    for (std::size_t j = 0; j < m.extent(1); j++)
      s += m[i, j];  // i-then-j 순회는 고정
  return s;
}

std::mdspan<double, std::dextents<std::size_t, 2>, std::layout_right> right_view(buf.data(), rows, cols);
std::mdspan<double, std::dextents<std::size_t, 2>, std::layout_left> left_view(buf.data(), rows, cols);
----

[source]
----
$ clang++ -std=c++23 -O2 mdspan_layout.cpp -o mdspan_layout && ./mdspan_layout
layout_right (row-major storage), i-then-j loop: 15.95 ms
layout_left  (col-major storage), i-then-j loop: 35.94 ms
sums equal: 1
----

`sum_all` 함수는 `layout_right`를 넘겼을 때와 `layout_left`를 넘겼을 때 **완전히 똑같은 소스 코드**로 컴파일됩니다 — 바뀌는 건 `m[i, j]`가 내부적으로 계산하는 실제 메모리 오프셋 공식뿐입니다(`layout_right`는 `i * cols + j`, `layout_left`는 `i + j * rows`). 같은 `i`-바깥/`j`-안쪽 순회를 두 레이아웃에 적용했더니, `layout_left`(열 우선 저장인데 행을 안쪽에서 순회) 쪽이 앞서 본 것과 똑같은 이유로 두 배 넘게 느려졌습니다. 이게 C++23이 말하는 **제로 오버헤드 추상화**의 실전 예시입니다 — `std::mdspan`이라는 뷰 타입 자체가 실행 시점에 어떤 부가 비용도 안 만들고, 컴파일 타임에 레이아웃 정책만 바꿔서 알고리즘과 메모리 배치를 독립적으로 조율할 수 있게 해줍니다.

== TaskGrid에 적용한다면

TaskGrid의 워커가 "세그먼트 하나를 통째로 처리"하는 패턴(각 세그먼트의 원소들을 순서대로 훑는 것)이 흔하다면, 버퍼를 `[세그먼트][원소]` 순서(세그먼트가 바깥, 원소가 안쪽 — `layout_right`와 자연스럽게 맞음)로 저장해야 합니다. 반대로 "모든 세그먼트의 n번째 원소들을 한 번에 훑는"(SIMD로 여러 세그먼트를 동시에 처리하는) 패턴이 흔하다면 `[원소][세그먼트]` 순서가 더 유리할 수 있습니다 — 어느 쪽이든 `std::mdspan`의 레이아웃 정책 하나만 바꾸면 되고, 그 위에서 도는 처리 알고리즘 코드는 그대로 재사용됩니다.

== 요약

* `std::mdspan`은 포인터와 크기만으로 다차원 배열처럼 접근할 수 있게 해주는 비소유 뷰이고, C++23의 다중 첨자 `operator[]`(`m[i, j]`)와 함께 씁니다.
* 순회 순서가 메모리의 실제 저장 순서(연속 방향)와 어긋나면, 캐시 라인 하나를 가져와서 값 하나만 쓰고 버리는 낭비가 생겨 실행 시간이 두 배 넘게 늘어난다는 걸 실측으로 확인했습니다.
* 레이아웃 정책(`layout_right`/`layout_left`)이 `std::mdspan`의 타입 파라미터이므로, 순회 알고리즘 코드를 한 글자도 바꾸지 않고도 레이아웃만 바꿔 성능을 조절할 수 있습니다 — 제로 오버헤드 추상화가 실제 실행 시간 차이로 나타나는 걸 직접 확인했습니다.

다음 장에서는 전체 버퍼가 아니라 그 안의 한 조각(타일)만 가리키는 뷰를, 복사 없이 `layout_stride`로 만드는 법을 다룹니다.
