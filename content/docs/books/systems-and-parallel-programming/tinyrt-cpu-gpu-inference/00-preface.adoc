== 이 책이 하려는 것

이 시리즈는 지금까지 세 갈래로 따로 자랐습니다.

* link:../../safe-parallel-cpp23/[『이론을 C{pp}23으로 옮기다』]는 타입 상태·이동 전용 타입으로 "잘못된 순서로 자원을 쓰는" 실수를 컴파일 타임에 막는 법을 다뤘습니다.
* link:../../cpp23-performance-engineering/[『안전을 넘어 성능으로』]는 `mdspan`·PMR 아레나·`atomic_ref`·``flat_map``으로 그 안전한 코드를 실제로 빠르게 만드는 법을 다뤘습니다.
* link:../../heterogeneous-computing-opencl/[『OpenCL로 배우는 헤테로지니어스 컴퓨팅』]은 CPU 한 개로 안 되는 계산을 GPU로 오프로드하는 법을 다뤘습니다.

이 책은 이 세 갈래를 한 자리에 모읍니다. 딥러닝 모델(작은 CNN)을 CPU와 GPU를 오가며 추론하는 작은 런타임 **TinyRT**를 처음부터 끝까지 같이 만듭니다 — 모델이 로드되지 않았는데 추론을 시도하는 실수는 타입 상태로 컴파일 타임에 막고(1장), 텐서는 ``mdspan``으로 표현하고(2장), 무거운 레이어는 OpenCL로 GPU에 올리되 그 GPU 자원은 이동 전용 RAII 핸들로 안전하게 관리하고(4장), 어떤 레이어를 CPU에 두고 어떤 레이어를 GPU로 보낼지는 ``flat_map`` 레지스트리와 실측 벤치마크로 결정하며(7장), 그 추론 요청 여러 개가 동시에 몰려도 ``std::scoped_lock``과 스레드별 자원 분리로 정답과 처리량을 함께 지키며(11장), 마지막으로 CoreML로 Apple Neural Engine이라는 세 번째 실행 장치까지 열어봅니다(12장).

== 정직하게 미리 말해둘 것: GPU가 항상 이기지 않습니다

이 책의 핵심 발견 하나를 미리 밝혀둡니다 — 작은 모델에서는 **CPU가 GPU보다 빠릅니다.** GPU에 커널을 올리고 결과를 받아오는 데는 컨텍스트 전환·버퍼 전송·커널 디스패치 같은 고정 비용이 붙는데, 계산량이 그 비용을 넘어설 만큼 크지 않으면 GPU로 보내는 것 자체가 손해입니다. 이 책은 이 결과를 감추지 않고 정면으로 다룹니다 — 7장에서 정확히 이 현상을 실측하고, "그러면 언제부터 GPU가 이기는가"를 같은 방식으로 실측해서, 런타임이 **크기에 따라 동적으로 CPU/GPU를 고르게** 만드는 것으로 이어갑니다. "GPU로 돌리면 무조건 빠르다"는 흔한 통념을, 이 시리즈의 다른 책들이 그래왔듯 실제로 재고 확인합니다.

== 이 책의 검증 원칙

전작들과 같은 원칙을 지킵니다 — **이 책의 모든 코드는 이 세션 환경에 실제로 설치된 Apple Clang 21(`-std=c{pp}23`)로 컴파일하고, 이 환경의 실제 GPU(Apple, OpenCL "Apple" 플랫폼)에서 실제로 실행해서 검증한 결과**입니다. CPU 기준 구현과 GPU 커널의 출력이 정확히 일치하는지(오차 0)까지 매번 실제로 비교합니다. 벤치마크 숫자는 이 머신, 이 순간의 실측치이고, 여러 번 반복 실행해 대세가 일관됨을 확인한 뒤에만 대표값을 싣습니다.

== 누구를 위한 책인가

이 책은 앞선 세 권의 기법을 실전 하나로 합치는 캡스톤이라, 세 권을 모두 읽었다면 가장 매끄럽게 읽힙니다. 다만 완전히 독립적으로 읽을 수 있도록 각 장에서 재사용하는 개념(타입 상태, `mdspan`, OpenCL 호스트-디바이스 모델)을 그때그때 필요한 만큼 다시 설명합니다 — C{pp}을 어느 정도 다뤄봤고 "안전하면서도 빠른 시스템을 실제로 조립해보고 싶다"는 독자를 위한 책입니다.
