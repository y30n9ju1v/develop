== 이 책에서 조립한 것: TinyRT

``Unloaded``가 ``load_weights()``로 ``Loaded``가 되고, ``compile()``로 GPU 프로그램까지 빌드된 ``Ready``가 되어야만 ``infer()``를 부를 수 있다는 생명주기(1장) 위에, ``mdspan``으로 감싼 ``Tensor2D``(2장)가 CPU 컨볼루션(3장)과 GPU 컨볼루션(4~5장)에서 같은 메모리 레이아웃으로 오가고, 완전연결 레이어는 산술 강도가 높아 로컬 메모리 타일링이 실제로 통한다는 걸 확인한 뒤(6장), ``flat_map`` 레지스트리가 레이어별로 CPU와 GPU 중 실측으로 더 빠른 쪽을 고르고(7장), 그 위에서 GPU 자원은 예외가 나도 스택 되감기로 안전하게 정리되며 CPU 쪽 임시 버퍼는 PMR 아레나로 재사용됩니다(8장). 9장에서 이 전체가 재구성 없이 하나의 순전파로 합쳐져, CPU 전용 기준 구현과 정확히 같은 소프트맥스 출력을 냈습니다. 10장에서는 흑백 이미지를 넘어 다채널 텐서로 확장해, MobileNet의 depthwise separable convolution이 표준 컨볼루션보다 FLOP을 7배 줄인다는 것과, 그 두 단계(depthwise/pointwise)가 정확히 6~7장의 CPU/GPU 배치 기준과 맞아떨어진다는 것도 확인했습니다. 11장은 이 파이프라인을 요청 하나가 아니라 여러 개가 동시에 몰리는 상황으로 확장해, 공유된 GPU 커널 오브젝트에 락 없이 접근하면 API 에러 하나 없이 결과만 조용히 틀어진다는 걸 재현하고, ``std::scoped_lock``으로 고치되 임계 구역을 최소로 좁혀야(스레드별 커맨드 큐) 정답과 처리량을 동시에 얻는다는 걸 확인했습니다. 12장은 CPU/GPU 이분법에 세 번째 선택지 — CoreML로 여는 Apple Neural Engine — 을 더해, 이 책의 작은 CNN에서는 ANE 위임이 OpenCL GPU 디스패치보다 143배 빠르고, 심지어 CoreML의 CPU 전용 경로조차 이 책이 손으로 짠 CPU 삼중 루프보다 빠르다는 것까지 확인했습니다.

이 책도 전작들과 같은 원칙을 지켰습니다 — 모든 코드는 이 세션의 Apple Clang 21로 컴파일하고, 이 세션의 실제 GPU에서 실행해서 검증했습니다. 특히 이 책의 핵심 결과("작은 모델에서는 CPU가 GPU보다 80배 빠르다")는 흔한 통념과 반대되는 결과였는데도 감추지 않았습니다 — 오히려 그 반대 사례(완전연결 레이어를 키우면 GPU가 130배 빠르다)까지 나란히 재서, "GPU가 항상 이기지는 않지만 항상 지지도 않는다, 크기가 관건이다"라는 더 정확한 결론으로 이어갔습니다.

== 세 전작이 한 시스템 안에서 겹치는 지점

* **link:../../safe-parallel-cpp23/[『이론을 C{pp}23으로 옮기다』]** — 1장의 타입 상태 생명주기, 4장의 이동 전용 `GpuContext`/`DeviceBuffer`, 8장의 예외 안전성(스택 되감기), 그리고 9장의 `std::scoped_lock`이 11장에서 공유 커널 오브젝트를 지키는 데 그대로 재사용됐습니다.
* **link:../../cpp23-performance-engineering/[『안전을 넘어 성능으로』]** — 2장의 `mdspan` 텐서, 7장의 `flat_map` 레지스트리와 `atomic_ref` 보정 기록, 8장의 PMR 아레나가 CPU 쪽 성능을 책임졌습니다.
* **link:../../heterogeneous-computing-opencl/[『OpenCL로 배우는 헤테로지니어스 컴퓨팅』]** — 5장의 워크그룹/SIMT 실행 모델과 6장의 로컬 메모리 타일링이 GPU 쪽 계산을 맡았습니다.

세 책이 따로 검증했던 것들이 실제로 충돌 없이 겹쳤다는 게, 이 책 9장의 진짜 결론입니다 — 타입으로 강제하는 안전성과 메모리 레이아웃으로 얻는 성능, 그리고 GPU로의 오프로드는 서로 다른 계층의 관심사라서 한 시스템 안에서 자연스럽게 공존합니다.

== 이 책이 다루지 않은 것

* **진짜 학습된 가중치** — 이 책의 컨볼루션 커널과 완전연결 가중치는 전부 무작위값입니다. 실제로 학습된 모델(ONNX 같은 포맷에서 읽어온 가중치)을 돌리는 것은 다루지 않았습니다.
* **진짜 배치 처리와 여러 층 쌓기** — 11장이 다룬 건 이미지 여러 장을 **동시에, 각각 따로** 처리하는 것(요청 병렬화)이지, 여러 장을 **한 번의 GPU 커널 호출**로 묶어 처리하는 배치 처리(진짜 배치 행렬곱)는 아닙니다. 10장에서 다채널 depthwise separable convolution 한 블록까지는 다뤘지만, 이 블록을 여러 겹 쌓아 진짜 MobileNet 깊이를 흉내 내는 것도 이 책의 범위 밖입니다.
* **파라미터를 갱신하면서 동시에 추론하기** — 11장은 파라미터가 고정된 추론 전용 상황만 검증했습니다. 온라인 학습처럼 파라미터를 실제로 갱신하면서 동시에 추론 요청도 처리해야 하는 상황은 11장의 결론이 그대로 적용되지 않습니다.
* **``kGpuBreakEvenFlops``의 정밀한 보정** — 7장의 계산량 기준값은 두 극단(작은 모델 vs 512³ 행렬곱) 사이에 실용적으로 그은 경계선이지, 그 사이 여러 크기에서 촘촘히 측정해 정확한 교차점을 찾은 것은 아닙니다.
* **다른 GPU/플랫폼과의 비교** — 이 책의 모든 숫자는 Apple Silicon의 통합 메모리 GPU 하나에서만 나왔습니다. discrete GPU(별도 VRAM을 가진, PCIe로 연결된 GPU)에서는 호스트↔디바이스 전송 비용이 더 크므로, GPU가 유리해지는 크기의 경계선이 이 책보다 더 클 가능성이 높습니다.
* **커널 융합의 한계** — 3장에서 컨볼루션과 ReLU를 하나의 커널로 융합했지만, 풀링이나 완전연결까지 더 크게 융합하는 것은 다루지 않았습니다.
* **NPU 경로의 동시성 검증** — 12장은 CoreML의 `MLModel`이 문서상 스레드 안전하다고만 밝혔을 뿐, 11장이 OpenCL 커널 오브젝트에 했던 것 같은 실제 스트레스 테스트로 재확인하지는 않았습니다. NPU 경로를 11장의 동시 요청 스케줄러에 실제로 통합하는 것도 다루지 않았습니다.
