10장의 최적화 버전은 이스케이프 문자열 처리를 아예 생략했습니다(공정한 C++23 비교를 위한 축소였습니다). 파이썬 사용자에게 내놓을 라이브러리는 실전 JSON을 그대로 받아야 하므로, 여기서는 정직하게 이스케이프까지 처리합니다 — 다만 이스케이프가 **없는** 대다수의 문자열은 여전히 복사 없이 빌려오고 싶습니다.

== `Cow<str>`: 빌릴지 소유할지 그때그때 정하기

[source,rust]
----
use std::borrow::Cow;

#[derive(Debug, Clone, PartialEq)]
pub enum Value<'a> {
    Null,
    Bool(bool),
    Number(f64),
    Str(Cow<'a, str>),                          // &str 대신 Cow<str>
    Array(Vec<Value<'a>>),
    Object(Vec<(Cow<'a, str>, Value<'a>)>),
}
----

[source,rust]
----
fn parse_string_cow(&mut self) -> PResult<Cow<'a, str>> {
    self.expect(b'"')?;
    let start = self.pos;
    let mut has_escape = false;
    loop {
        let c = self.peek()?;
        if c == b'"' { break; }
        if c == b'\\' { has_escape = true; self.pos += 2; continue; }
        self.pos += 1;
    }
    let raw = &self.input[start..self.pos];
    self.pos += 1;
    if !has_escape {
        return Ok(Cow::Borrowed(raw));   // 이스케이프 없으면 원본을 그대로 빌린다 -- 복사 없음
    }
    Ok(Cow::Owned(unescape(raw)))         // 있으면 그때만 새로 할당한다
}
----

`Cow<'a, str>`(Clone-on-Write)는 "빌린 참조일 수도, 직접 소유한 값일 수도 있는" 타입입니다 — 대부분의 JSON 문자열(이스케이프가 없는 이름, 값)은 `Cow::Borrowed`로 원본을 그대로 가리키고, `\n`이나 `\"` 같은 이스케이프가 있는 드문 경우에만 `Cow::Owned`로 새 `String`을 만듭니다. 3장에서 본 라이프타임과 4장에서 본 `Result` 패턴이, 여기서는 "대부분은 빠른 길, 가끔만 느린 길"이라는 하나의 타입으로 합쳐집니다.

== 재귀 변환기

[source,rust]
----
use pyo3::prelude::*;
use pyo3::types::{PyDict, PyList};

fn value_to_py(py: Python<'_>, v: &Value) -> PyResult<Py<PyAny>> {
    Ok(match v {
        Value::Null => py.None(),
        Value::Bool(b) => b.into_pyobject(py)?.to_owned().into_any().unbind(),
        Value::Number(n) => n.into_pyobject(py)?.into_any().unbind(),
        Value::Str(s) => s.as_ref().into_pyobject(py)?.into_any().unbind(),
        Value::Array(items) => {
            let list = PyList::empty(py);
            for item in items {
                list.append(value_to_py(py, item)?)?;
            }
            list.into_any().unbind()
        }
        Value::Object(fields) => {
            let dict = PyDict::new(py);
            for (k, v) in fields {
                dict.set_item(k.as_ref(), value_to_py(py, v)?)?;
            }
            dict.into_any().unbind()
        }
    })
}

#[pyfunction]
fn parse_json(py: Python<'_>, text: &str) -> PyResult<Py<PyAny>> {
    match parser::parse(text) {
        Ok(v) => value_to_py(py, &v),
        Err(e) => Err(pyo3::exceptions::PyValueError::new_err(format!(
            "위치 {}: {}", e.pos, e.message
        ))),
    }
}
----

`Value::Array`/`Object` 분기가 `value_to_py`를 재귀 호출합니다 — 6장에서 `Display` 트레잇을 재귀로 구현했던 것과 같은 모양입니다. `Python<'_>` 토큰(`py`)은 PyO3에서 "지금 GIL(파이썬 전역 락)을 쥐고 있다"는 증거로 쓰이는 값입니다 — 파이썬 객체를 만들거나 건드리는 모든 연산은 이 토큰을 요구합니다. 이 GIL 이야기는 21장에서 정면으로 다룹니다.

== 실행 확인

[source]
----
$ python -c "
import riirjson
print(riirjson.parse_json('[1, 2, {\"a\": true, \"b\": null, \"c\": \"hello\\\\nworld\"}]'))
"
[1.0, 2.0, {'a': True, 'b': None, 'c': 'hello\nworld'}]
----

배열이 파이썬 `list`로, 객체가 `dict`로, `true`/`null`이 `True`/`None`으로, 그리고 **이스케이프가 있던 문자열(`\n`)까지 실제 개행 문자로 정확히 풀려서** 나왔습니다 — `Cow::Owned` 경로가 실제로 동작한다는 증거입니다.

== 요약

* `&str` 대신 `Cow<'a, str>`를 써서, 이스케이프 없는 문자열은 복사 없이 빌리고 이스케이프가 있을 때만 새로 할당하는 파서로 다시 짰습니다.
* `Value` 트리를 재귀적으로 순회하며 파이썬 `dict`/`list`/`bool`/`None`/`str`로 변환하는 `value_to_py`를 짰고, 실제로 중첩된 JSON을 파싱해 정확한 파이썬 객체가 나오는 걸 확인했습니다.
* `Python<'_>` 토큰이 GIL을 쥐고 있다는 증거로 쓰인다는 것도 짚었습니다 — 21장에서 이 GIL을 실제로 다룹니다.
