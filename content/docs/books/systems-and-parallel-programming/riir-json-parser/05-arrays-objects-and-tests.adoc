배열과 객체는 재귀 하강 파서에서 자연스러운 자리를 찾습니다 — 배열/객체 안의 각 원소가 다시 `parse_value`를 호출하면 됩니다.

== 배열

[source,rust]
----
fn parse_array(&mut self) -> PResult<Value> {
    self.expect(b'[')?;
    let mut items = Vec::new();
    self.skip_whitespace();
    if self.peek()? == b']' {
        self.pos += 1;
        return Ok(Value::Array(items));
    }
    loop {
        let item = self.parse_value()?; // 재귀
        items.push(item);
        self.skip_whitespace();
        match self.advance()? {
            b',' => continue,
            b']' => break,
            c => return Err(self.err(&format!("','나 ']'를 기대했지만 '{}'를 만났습니다", c as char))),
        }
    }
    Ok(Value::Array(items))
}
----

객체도 같은 구조에 키를 파싱하는 단계만 추가됩니다(전체 코드는 저장소를 참고하세요).

== `cargo test`로 검증하기

Rust는 별도의 테스트 프레임워크 없이, `#[cfg(test)]`로 감싼 모듈 안에 `#[test]`가 붙은 함수를 두면 그게 곧 테스트입니다.

[source,rust]
----
#[cfg(test)]
mod tests {
    use super::*;

    #[test]
    fn parses_primitives() {
        assert_eq!(parse("null").unwrap(), Value::Null);
        assert_eq!(parse("true").unwrap(), Value::Bool(true));
        assert_eq!(parse("42").unwrap(), Value::Number(42.0));
        assert_eq!(parse("-3.5").unwrap(), Value::Number(-3.5));
        assert_eq!(parse("\"hi\"").unwrap(), Value::String("hi".to_string()));
    }

    #[test]
    fn parses_array() {
        let v = parse("[1, 2, 3]").unwrap();
        assert_eq!(v, Value::Array(vec![Value::Number(1.0), Value::Number(2.0), Value::Number(3.0)]));
    }

    #[test]
    fn parses_object() {
        let v = parse(r#"{"a": 1, "b": true}"#).unwrap();
        match v {
            Value::Object(map) => {
                assert_eq!(map.get("a"), Some(&Value::Number(1.0)));
                assert_eq!(map.get("b"), Some(&Value::Bool(true)));
            }
            _ => panic!("object가 아님"),
        }
    }

    #[test]
    fn rejects_trailing_garbage() {
        let err = parse("42 garbage").unwrap_err();
        assert!(err.message.contains("여분"));
    }

    #[test]
    fn rejects_truncated_input() {
        let err = parse("nul").unwrap_err();
        assert!(err.message.contains("일찍 끝"));
    }
}
----

`assert_eq!(parse("[1, 2, 3]").unwrap(), Value::Array(...))`이 그냥 동작하는 건 1장에서 파생한 `PartialEq` 덕분입니다 — 중첩된 `Vec<Value>`까지 재귀적으로 비교해줍니다.

== 실행 확인

[source]
----
$ cargo test

test parser::tests::parses_array ... ok
test parser::tests::parses_primitives ... ok
test parser::tests::rejects_trailing_garbage ... ok
test parser::tests::parses_object ... ok
test parser::tests::rejects_truncated_input ... ok

test result: ok. 5 passed; 0 failed; 0 ignored; 0 measured; 0 filtered out; finished in 0.00s
----

다섯 테스트 모두 통과했습니다 — 정상 입력(원시값, 배열, 객체)뿐 아니라, **실패해야 하는 입력이 실제로 실패하는지**(`rejects_trailing_garbage`, `rejects_truncated_input`)도 함께 검증했습니다. 파서 테스트에서는 "잘 파싱되는 것"만큼 "잘못된 입력을 확실히 거부하는 것"도 중요합니다.

== 요약

* 재귀 하강으로 배열·객체 파싱을 완성했습니다 — `parse_value`가 자기 자신을 재귀 호출하는 구조입니다.
* `cargo test` + `#[test]`로 별도 도구 설치 없이 테스트를 짰고, 1장의 `PartialEq` 파생 덕분에 중첩 구조체 비교가 `assert_eq!` 한 줄로 끝난다는 걸 확인했습니다.
* 정상 케이스뿐 아니라 "실패해야 하는 입력이 실제로 실패하는가"까지 테스트로 검증했고, 5개 테스트 전부 통과했습니다.
