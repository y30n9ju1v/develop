== RIIR, 그리고 이 책이 바로잡고 싶은 것

"Rewrite It In Rust"(RIIR)는 오래된 C 도구나 라이브러리를 Rust로 다시 짜는 프로젝트들을 가리키는 농담 섞인 별명입니다 — `ripgrep`(grep), `bat`(cat), `fd`(find), `uutils/coreutils` 같은 실제 프로젝트들이 이 흐름 위에 있습니다. 이 유행의 배경에는 "Rust가 더 빠르다"는 인식이 있는데, 여기서 흔한 오해 하나를 먼저 바로잡고 시작합니다 — Rust가 빠른 근본 이유는 "컴파일 타임에 병렬처리를 안전하게 체크해서"가 아니라, **가비지 컬렉터 없이 메모리 안전을 보장**하기 때문에 애초에 C만큼 빠른 것이 기본값이라는 데 있습니다. "Fearless Concurrency"(데이터 경쟁을 컴파일 타임에 막아주는 것)는 그 위에 얹힌 **별도의 추가 이점**입니다 — 이 책 뒷부분(12~13장)에서 정확히 이 지점을 실제 컴파일 에러로 확인합니다.

== 이 책이 하려는 것

C의 대표적인 JSON 라이브러리 `cJSON`을 기준 삼아, 같은 기능을 하는 JSON 파서를 Rust로 처음부터 짓습니다. 파싱 로직 자체는 아주 작지만, 이 작은 프로젝트 하나로 Rust 언어의 핵심 영역 — 소유권, 라이프타임, 트레잇, 제네릭, 이터레이터와 클로저, 스마트 포인터, 안전한 병렬처리 — 을 전부 실제 코드로 지나갑니다. 그리고 C와 나란히 놓고 실제로 벤치마크합니다 — "Rust가 당연히 더 빠르다"고 전제하지 않고, 실측한 숫자를 그대로 싣습니다(9장에서 미리 밝히면, 첫 결과는 Rust의 손을 들어주지 않습니다 — 다만 10장에서 그 원인을 실제로 고쳐서 다시 잽니다).

== 이 책의 구조

*1부(1~2장)* 는 JSON 값을 `enum`으로 모델링하고, 가장 단순한(안전하지 않은) 파서부터 짭니다.

*2부(3~5장)* 는 이 책의 핵심입니다 — 라이프타임을 정면으로 다루고, `Result`로 에러를 안전하게 전파하고, 배열·객체까지 완성해 테스트를 짭니다.

*3부(6~7장)* 는 반대 방향(직렬화)과 함수형 스타일을 다룹니다 — `Display` 트레잇, 그리고 이터레이터·클로저로 JSON 트리를 변환하는 법입니다.

*4부(8~11장)* 는 C의 `cJSON`과 정면으로 대조합니다 — 같은 입력에 대해 같은 결과가 나오는지, 실제로 얼마나 빠른지(`hyperfine`), 그 결과를 어떻게 개선할 수 있는지(이 시리즈의 `cpp23-performance-engineering` 책 기법을 빌려), 그리고 빌림 체커가 실제로 잡아준 버그가 무엇인지.

*5부(12~13장)* 는 병렬처리로 확장합니다 — `rayon`과 `Arc`로 안전하게 병렬 파싱하고, 데이터 경쟁을 일으키는 코드가 실제로 컴파일이 안 된다는 걸 확인합니다.

== 실측 원칙

이 책의 모든 Rust 코드는 `rustc`/`cargo`로 실제 컴파일·실행·테스트했고, C 코드는 `clang`으로 실제 컴파일했습니다. 컴파일 에러 메시지, 벤치마크 숫자, 테스트 결과 전부 이 세션에서 실제로 재현한 것을 그대로 싣습니다 — Rust가 이겼을 때도, 지지 않았을 때도 감추지 않습니다.

== 사전 지식

C나 다른 정적 타입 언어(Java, C++, TypeScript 등)를 다뤄본 경험이면 충분합니다. Rust를 한 번도 안 써봤어도, 이 책 안에서 필요한 만큼 개념을 함께 설명합니다.
