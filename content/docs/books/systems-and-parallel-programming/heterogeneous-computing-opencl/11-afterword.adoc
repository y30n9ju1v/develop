== 이 책이 실측한 다섯 가지 병목

10개 장에 걸쳐 "GPU가 빠르다"는 한 문장을 다섯 번 다른 각도로 쪼갰습니다. 표로 모으면:

[cols="1,3,2"]
|===
|장 |병목의 얼굴 |이 책에서 실측한 수치

|1장 |계산 강도가 낮으면 GPU의 병렬성이 발휘될 자리가 없다 |삼각함수 커널 14.2배 개선 vs 단순 덧셈은 개선 없음
|2장 |전송/디스패치 고정 비용이 작은 작업에서는 GPU가 CPU보다 손해다 |원소 100개에서 GPU가 626배 느림, 100만 개부터 역전
|3장 |같은 락스텝 그룹 안에서 분기가 갈리면(발산) 두 갈래를 다 실행한 것과 비슷한 비용이 든다 |체커보드 발산 패턴이 블록 패턴보다 1.88배 느림
|4장 |워크그룹 안의 협력에는 명시적 동기화(`barrier`)가 필요하고, 빠뜨려도 조용히 틀린 값을 낸다 |배리어 없는 리덕션이 461872(정답 523776)를 돌려줌
|5~6장 |같은 데이터를 스레드마다 중복해서 전역 메모리에서 읽으면 대역폭이 병목이 된다 |타일링으로 전역 메모리 접근 16배 감소, 실측 속도 3.4배 개선
|===

이 다섯 가지는 서로 다른 문제가 아니라 **"GPU 하드웨어가 CPU와 다르게 설계된 이유"** 를 다른 각도에서 본 것입니다 — 단순한 연산 유닛을 대량으로 굴리는 대신(1장), 개별 스레드의 지연시간을 줄이는 데는 신경을 덜 쓰고(2장의 디스패치 오버헤드), 락스텝으로 명령어 페치 비용을 아끼는 대신(3장), 그 락스텝을 넘나드는 협력에는 프로그래머가 직접 대가를 치러야 하고(4장), 좁고 빠른 로컬 메모리와 넓고 느린 전역 메모리를 분리해서(5~6장) 대역폭을 아낍니다.

== "병목은 다시 재야 한다"는 방법론

9~10장에서 확인한 대조가 이 책의 마지막 교훈을 가장 잘 보여줍니다 — 9장에서는 동기화 횟수를 줄이는 게 6.3배 이득이었는데, 10장에서 무거운 커널(래스터라이제이션)을 뒤에 붙이자 그 이득이 사실상 사라졌습니다(0.95배). 같은 최적화가 어떤 워크로드에서는 결정적이고 다른 워크로드에서는 무의미합니다 — 그러니 이 책에서 배운 다섯 가지 병목의 이름을 외우는 것보다 중요한 건, **매번 실측해서 무엇이 시간을 먹는지 확인하는 습관**입니다. `time.perf_counter()`와 `q.finish()` 몇 줄이면 충분합니다.

== OpenCL 밖에서도 통하는 것

이 책은 OpenCL로 개념을 익혔지만, 다른 이름의 같은 개념이 CUDA와 Metal에도 그대로 있습니다.

[cols="1,1,1,1"]
|===
|개념 |OpenCL |CUDA |Metal

|디바이스 실행 함수 |kernel |`__global__` 함수 |compute function
|워크그룹 |work-group |thread block |threadgroup
|락스텝 실행 단위 |(구현별, 보통 32) |warp(32) |SIMD-group
|워크그룹 공유 메모리 |`__local` |`__shared__` |threadgroup memory
|동기화 |`barrier()` |`__syncthreads()` |`threadgroup_barrier()`
|===

이 책에서 4장의 배리어, 3장의 분기 발산, 5~6장의 타일링을 실제로 GPU에서 돌려보며 익혔다면, 나중에 NVIDIA GPU가 있는 환경에서 CUDA로 옮기더라도 `__syncthreads()`가 왜 필요한지, `__shared__` 배열을 왜 쓰는지 헤매지 않을 겁니다 — 서문에서 약속한 대로, OpenCL이라는 문법 뒤에 있는 모델 자체를 익히는 게 이 책의 목표였습니다.

== 다음 단계: 진짜 3D로

이 책의 4부는 3DGS의 핵심(점을 화면에 뿌리는 래스터라이제이션)을 다뤘지만, 몇 가지는 의도적으로 생략했습니다.

* **3D → 2D 투영**: 이 책은 이미 2D로 투영된 점을 다뤘습니다. 실제 3DGS는 카메라 파라미터로 3D 가우시안(위치, 3D 공분산)을 2D 타원으로 투영하는 단계가 앞에 붙습니다.
* **깊이 순서와 알파 블렌딩**: 이 책의 래스터라이제이션은 겹치는 점들을 단순히 더했습니다(가산 블렌딩). 실제 3DGS는 카메라에서 가까운 순서대로 정렬해서 알파 블렌딩(뒤에 있는 점이 앞에 있는 점에 가려지는 정도를 반영)합니다 — 이건 8장의 타일 목록을 깊이 순으로 정렬하는 것으로 확장할 수 있습니다.
* **역전파(학습)**: 3DGS는 렌더링한 이미지와 실제 사진의 차이로 가우시안 파라미터를 학습합니다 — 이 책의 커널들을 미분 가능하게 만들어야 합니다(각 연산의 그래디언트를 계산하는 커널을 추가로 짜는 것).

이 책이 다진 기반(워크그룹, 메모리 계층, 실측 습관) 위에 이 세 가지를 하나씩 얹으면, 이 시리즈의 `differentiable-rendering-3dgs`류 작업이나 실제 3DGS 논문 구현으로 자연스럽게 이어집니다. 디지털 트윈 쪽도 마찬가지입니다 — 9~10장의 입자 시뮬레이션 루프에 강체 충돌, 유체, 혹은 실측 센서 데이터를 얹으면 더 정교한 실시간 시뮬레이션이 됩니다. 어느 방향으로 가든, 이 책에서 반복해서 강조한 한 가지는 유효합니다 — **추측하지 말고, `time.perf_counter()`로 재고, 그다음에 최적화하십시오.**
