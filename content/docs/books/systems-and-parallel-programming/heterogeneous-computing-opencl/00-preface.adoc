== 이 책이 하려는 것

3D Gaussian Splatting(3DGS)이나 디지털 트윈 같은 작업을 붙잡고 있으면 어느 순간 똑같은 벽에 부딪힙니다 — 알고리즘 자체는 NumPy로 다 짤 수 있는데, 점 수십만 개를 매 프레임 처리하려면 CPU 한 개로는 속도가 안 나옵니다. "GPU로 돌리면 빨라진다"는 건 누구나 압니다. 이 책이 다루는 건 그 한 문장 뒤에 있는 실제 질문들입니다 — GPU는 정확히 *왜* 빠른가, 그 힘을 쓰려면 코드를 어떻게 바꿔야 하는가, 그리고 아무렇게나 바꾼다고 빨라지는 게 아니라 왜 어떤 코드는 GPU에 올려도 오히려 느려지는가.

이 책은 **OpenCL**로 이 질문들에 답합니다. CUDA는 NVIDIA GPU가 있어야 하고, Metal은 Apple 플랫폼에 갇힙니다 — OpenCL은 느리더라도 어떤 GPU에서나 동작하는 개방 표준이고, 이 시리즈의 다른 책들처럼 "이 세션 환경에서 실제로 컴파일하고 실행해서 검증한다"는 원칙을 지킬 수 있는 유일한 선택지이기도 합니다. 호스트 코드는 ``pyopencl``로 짜서 NumPy와 나란히 비교하기 쉽게 하고, 커널(GPU에서 실제로 도는 코드)은 OpenCL C로 직접 씁니다.

== 이 책이 다루는 다섯 기둥

* **호스트-디바이스 분리** — CPU(호스트)와 GPU(디바이스)가 왜 별개의 메모리를 가진 별개의 컴퓨터처럼 동작하는지, 그리고 그 사이의 데이터 전송이 왜 진짜 병목인지.
* **커널과 실행 모델** — GPU가 코드 한 줄을 수천 개 스레드가 동시에 실행하는 SIMT 모델, 그리고 그 스레드들을 묶는 워크그룹과 동기화.
* **메모리 계층구조** — 전역 메모리, 로컬(공유) 메모리, 그리고 타일링이라는 기법으로 메모리 대역폭 병목을 우회하는 법.
* **3DGS 가속** — 점군을 화면에 뿌리는 래스터라이제이션 커널을 직접 짜고, NumPy 구현과 실측으로 속도를 비교.
* **실시간 시뮬레이션** — 매 프레임 GPU 커널을 반복 실행하는 루프, 그리고 여러 커널을 파이프라인으로 엮는 법.

== 이 책의 방식: 실제 GPU에서 실제로 돌려서 확인한다

이 책의 모든 커널은 이 세션 환경에 실제로 있는 GPU(Apple M4, OpenCL로 "Apple" 플랫폼의 디바이스로 잡힙니다 — compute unit 10개, 워크그룹 최대 크기 256, 전역 메모리 약 19GB)에서 실제로 컴파일되고 실행됩니다. 속도 비교는 추측이나 이론적 계산이 아니라 ``time.perf_counter()``로 실측한 숫자입니다. 커널이 틀린 결과를 낼 만한 지점(경쟁 조건, 잘못된 동기화)은 일부러 틀리게 짜서 실제로 틀린 출력을 보여준 다음 고칩니다.

CUDA나 Metal 전용 문법은 다루지 않습니다 — 다만 OpenCL의 개념(워크그룹, 로컬 메모리, 배리어)은 그 두 API에도 이름만 다르게 그대로 있습니다. OpenCL로 이 모델을 한번 제대로 이해하면, 나중에 CUDA를 쓰게 되더라도 ``{us}{us}global{us}{us}``이 무엇에 대응하는지 헤매지 않습니다.

== 읽는 순서

1부부터 5부까지 순서대로 읽는 걸 권합니다 — 뒤로 갈수록 앞 부의 개념을 그대로 씁니다. 이미 GPU 프로그래밍 경험이 있다면 1~2부는 훑고 3부(메모리 계층구조)부터 시작해도 좋습니다 — 실전에서 성능을 좌우하는 건 대부분 메모리 접근 패턴이기 때문입니다.
