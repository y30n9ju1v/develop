== 하나의 macro로는 부족할 때

10장의 ``twice``는 문법 하나를 다른 문법 하나로 바꿔치기하는 가장 단순한 macro였습니다. 그런데 실전에서 새 문법을 만들다 보면 "모양이 여러 가지인 입력을 각각 다르게 처리하고 싶다"는 경우가 흔합니다 — 이럴 때 ``macro``를 여러 번 쓰는 대신 ``macro_rules``로 한 문법에 여러 패턴을 묶습니다.

== macro_rules: 재귀적으로 패턴 쌓기

숫자를 대괄호 안에 나열하면 전부 더해주는 `sum[1, 2, 3]` 같은 문법을 만들어봅시다. 이건 "원소가 없거나(0), 하나거나(그 값 자체), 첫 원소와 나머지로 나뉘거나(첫 원소 + 나머지의 합)"라는 세 가지 모양을 가지므로, 패턴이 하나로는 안 됩니다.

[source,lean]
----
syntax "sum[" term,* "]" : term

macro_rules
  | `(sum[]) => `(0)
  | `(sum[$x]) => `($x)
  | `(sum[$x, $xs,*]) => `($x + sum[$xs,*])

#eval sum[1, 2, 3, 4]  -- 10
#eval sum[]            -- 0
#eval sum[7]           -- 7
----

``syntax "sum[" term,* "]" : term``은 "쉼표로 구분된 term 여러 개를 대괄호로 감싼 모양의 새 문법을 term 자리에 허용한다"는 선언입니다. ``macro_rules``는 그 문법이 실제로 어떤 모양으로 들어왔는지에 따라 세 가지 확장 규칙을 답니다 — 이게 2장에서 배운 패턴 매칭과 정확히 같은 발상입니다. 다만 여기서 매칭되는 건 "값"이 아니라 "문법 조각"입니다. 마지막 규칙 ``sum[$x, $xs,*]``이 자기 자신(`sum[$xs,*]`)을 다시 참조하는 것도 눈여겨보세요 — 2장의 재귀 함수와 똑같이, 매크로도 재귀적으로 자신을 확장할 수 있습니다.

== notation과 infixl: 연산자 기호 직접 만들기

새 "문법 모양"을 선언하는 대신, 기존 함수에 그냥 연산자 기호를 붙이고 싶을 때가 더 흔합니다. ``infixl``은 그럴 때 쓰는 지름길입니다.

[source,lean]
----
structure Vec2 where
  x : Float
  y : Float
deriving Repr

def addVec2 (a b : Vec2) : Vec2 := { x := a.x + b.x, y := a.y + b.y }

infixl:65 " ⊞ " => addVec2

#eval (Vec2.mk 1.0 2.0) ⊞ (Vec2.mk 3.0 4.0)  -- { x := 4.000000, y := 6.000000 }
----

``infixl:65 " ⊞ " => addVec2``는 "``⊞``를 왼쪽 결합(infixl) 이항 연산자로 등록하고, ``a ⊞ b``가 나오면 ``addVec2 a b``로 취급하라"는 뜻입니다. ``65``는 우선순위입니다 — 숫자가 클수록 먼저 묶입니다(``+``나 ``*``와 섞어 쓸 때 어느 게 먼저 계산될지 결정하는 값입니다). `infixl` 내부에서 실제로 일어나는 일도 결국 ``macro``와 같습니다 — ``a ⊞ b``라는 문법을 ``addVec2 a b``라는 이미 아는 문법으로 바꿔치기하는 것뿐입니다.

== 이 장이 왜 중요한가

`syntax` + ``macro_rules``로 재귀적인 새 문법을 정의하고, ``infixl``로 익숙한 연산자 기호를 붙이는 법까지 봤습니다. 10~11장에서 배운 macro(문법 치환), elab(정교화 개입), tactic(목표 조작)에 이 장의 표기법 도구를 더하면, 3부에서 배운 재료로 여러분만의 작은 표기 체계를 일관되게 쌓아 올릴 수 있습니다 — 이 책의 범위를 넘어서면 여기서 한 걸음 더 나아가 완전히 새로운 문법 카테고리(`declare_syntax_cat`)를 선언해 진짜 도메인 특화 언어(DSL)를 만드는 데까지 이어집니다.

이걸로 3부를 마칩니다 — 1부(함수형 프로그래밍)에서 시작해 2부(증명)를 거쳐, Lean4가 스스로를 확장하는 원리까지 왔습니다.

TIP: 더 깊이 들어가려면 — ``macro_rules``와 재귀적 문법 확장은 link:../../../programming/lean/metaprogramming-in-lean4/06-macros/[Metaprogramming in Lean 4의 6장: 매크로], 새 문법 카테고리로 완전한 DSL을 만드는 법은 link:../../../programming/lean/metaprogramming-in-lean4/08-dsls/[같은 책 8장]에서 다룹니다.

== 직접 해보기

* ``sum[...]``을 참고해, 모든 원소를 곱하는 ``prod[...]``을 ``macro_rules``로 만들어보세요. ``#eval prod[1, 2, 3, 4]``는 24가 나와야 합니다.
* ``Vec2``에 뺄셈 함수 ``subVec2``를 만들고, `⊟` 기호로 쓸 수 있게 ``infixl``을 등록해보세요.

.해답 보기
[%collapsible]
====
[source,lean]
----
syntax "prod[" term,* "]" : term

macro_rules
  | `(prod[]) => `(1)
  | `(prod[$x]) => `($x)
  | `(prod[$x, $xs,*]) => `($x * prod[$xs,*])

#eval prod[1, 2, 3, 4]  -- 24
#eval prod[]            -- 1

def subVec2 (a b : Vec2) : Vec2 := { x := a.x - b.x, y := a.y - b.y }

infixl:65 " ⊟ " => subVec2

#eval (Vec2.mk 5.0 5.0) ⊟ (Vec2.mk 1.0 2.0)  -- { x := 4.000000, y := 3.000000 }
----
====

== 요약

* ``macro_rules``는 한 문법 이름에 여러 패턴(모양)을 등록한다 — 2장의 패턴 매칭이 값 대신 문법 조각에 적용된 것이다.
* `syntax` 규칙과 ``macro_rules``는 재귀적으로 자기 자신을 참조하며 확장될 수 있다.
* ``infixl:우선순위 " 기호 " => 함수``는 기존 함수를 익숙한 연산자 기호로 감싸는 지름길이며, 내부적으로는 macro와 같은 문법 치환이다.
