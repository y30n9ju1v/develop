== 왜 계산기부터 시작하는가

증명이니 타입 이론이니 하는 말을 듣고 나면 Lean4가 뭔가 대단히 특별한 도구처럼 느껴집니다. 그런데 시작은 아주 소박합니다 — Lean4는 우선 식(expression)을 평가하는 계산기입니다. `#eval` 명령 하나에 식을 적으면 그 값을 계산해서 보여줍니다.

[source,lean]
----
#eval 1 + 2 * 3        -- 7
#eval "hello" ++ " " ++ "world"  -- "hello world"
#eval (2 : Float) ^ 10  -- 1024.000000
----

이게 전부입니다. 이 장 전체가 결국 "식과 값이 무엇이고, 그 값들이 어떤 타입을 갖는지"를 설명하는 게 다입니다.

== 모든 식은 타입을 갖는다

Lean4에서는 모든 값이 정확히 하나의 타입을 갖습니다. `#check`로 어떤 식의 타입을 물어볼 수 있습니다.

[source,lean]
----
#check 1 + 2          -- Nat
#check "hello"        -- String
#check 1.5            -- Float
#check (1, "one")     -- Nat × String
----

`Nat`은 0 이상의 자연수, `String`은 문자열입니다. 흥미로운 건 `(1, "one")`처럼 서로 다른 두 값을 묶으면 타입도 `Nat × String`처럼 묶여서 나온다는 점입니다 — 타입이 값의 모양을 그대로 반영합니다.

여기서 다른 언어와 다른 점이 하나 있습니다. Python이나 JavaScript는 실행하는 동안 타입을 확인합니다(동적 타입). Lean4는 `#eval`을 누르기 전, 식을 적는 순간 이미 타입을 계산해둡니다(정적 타입). 타입이 안 맞는 식은 애초에 컴파일이 안 됩니다.

[source,lean]
----
#eval 1 + "hello"  -- 에러: Nat과 String을 더할 수 없다
----

당장은 이게 불편한 제약처럼 보일 수 있지만, 2부에서 증명을 다룰 때 이 정적 타입 검사가 그대로 "증명이 논리적으로 맞는지 확인하는 절차"로 재활용됩니다. 지금은 "실행하기 전에 실수를 잡아준다" 정도로 기억해두면 충분합니다.

== 이름 붙이기: def

같은 식을 여러 번 쓰려면 이름을 붙입니다. `def`로 정의합니다.

[source,lean]
----
def greeting : String := "Hello, Lean!"
def double (n : Nat) : Nat := n * 2

#eval greeting     -- "Hello, Lean!"
#eval double 21    -- 42
----

`def 이름 : 타입 := 식` 형태입니다. `double`처럼 인자를 받으면 `def 이름 (인자 : 타입) : 반환타입 := 식`이 됩니다. 타입은 대부분 생략해도 Lean4가 식을 보고 스스로 추론합니다 — 하지만 함수의 인자 타입만큼은 명시하는 게 관례입니다. 인자가 여러 개면 Lean4는 어떤 순서로 적용됐는지 알아야 하는데, 타입을 적어두면 그 실수를 미리 잡아줄 수 있기 때문입니다.

== 상수가 아니라 정의다

`def`로 만든 이름은 변수가 아니라 정의입니다. 한 번 정의하면 그 값이나 계산 방식이 고정되고, 다시 대입해서 바꿀 수 없습니다. 이건 사소한 문법 차이가 아니라 함수형 프로그래밍의 근본 태도입니다 — Lean4에는 "변수의 값을 나중에 바꾼다"는 개념 자체가 (기본적으로는) 없습니다. 대신 새 이름에 새 값을 정의합니다.

[source,lean]
----
def x : Nat := 5
-- x := 6  -- 이런 문법은 없다. x는 영원히 5다.

def y : Nat := x + 1  -- 새 이름 y를 x로부터 정의
#eval y  -- 6
----

왜 이렇게 만들었을까요? "이 이름은 한 번 정해지면 절대 안 바뀐다"는 보장이 있으면, 코드 어디에서 그 이름을 보든 항상 같은 뜻이라고 믿을 수 있습니다. 이 성질(참조 투명성)이 나중에 증명을 쓸 때 결정적으로 중요해집니다 — "`double 21`은 항상 42다"라고 증명하려면, `double`이 호출될 때마다 다른 값을 낼 수도 있다는 가능성 자체가 없어야 하기 때문입니다.

== 조건 분기: if와 값

Lean4의 `if`는 문장이 아니라 식입니다 — 즉 `if`도 값을 냅니다.

[source,lean]
----
def abs (n : Int) : Int :=
  if n < 0 then -n else n

#eval abs (-7)  -- 7
#eval abs 3     -- 3
----

C나 Java의 `if`는 "이 조건이면 이 문장을 실행"하는 제어 흐름이지만, Lean4의 `if ... then ... else ...`는 자기 자신이 하나의 식이라서 `then`과 `else` 양쪽이 같은 타입의 값을 내야 합니다. 이것도 "모든 식은 타입을 갖는다"는 원칙의 자연스러운 결과입니다 — `if`도 예외가 아닙니다.
