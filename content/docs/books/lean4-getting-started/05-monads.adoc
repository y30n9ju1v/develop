== 실패할 수 있는 계산을 이어붙이기

3장에서 "값이 없을 수도 있다"를 표현하는 `Option`을 봤습니다. 이런 계산을 여러 번 잇는 경우가 흔합니다 — 나눗셈을 두 번 연달아 하는데, 둘 중 하나라도 0으로 나누면 전체가 실패해야 합니다.

[source,lean]
----
def safeDiv (a b : Nat) : Option Nat :=
  if b == 0 then none else some (a / b)

def twoSteps (a b c : Nat) : Option Nat :=
  match safeDiv a b with
  | none => none
  | some r1 =>
    match safeDiv r1 c with
    | none => none
    | some r2 => some r2

#eval twoSteps 100 5 4  -- some 5
#eval twoSteps 100 0 4  -- none
----

계산이 세 단계, 네 단계로 늘어나면 `match`가 계속 겹겹이 쌓입니다. 그런데 이 겹겹이 쌓이는 패턴을 자세히 보면 항상 똑같습니다 — "실패면 즉시 실패로 끝내고, 성공이면 그 값을 다음 단계에 넘긴다." 이 반복되는 뼈대를 함수 하나로 뽑아낼 수 있습니다.

[source,lean]
----
def andThen : Option α → (α → Option β) → Option β
  | none,   _ => none
  | some a, f => f a

def twoSteps' (a b c : Nat) : Option Nat :=
  andThen (safeDiv a b) fun r1 =>
  andThen (safeDiv r1 c) fun r2 =>
  some r2
----

`andThen`이 하는 일은 "이 계산이 실패하지 않았으면, 그 결과를 다음 계산에 넘겨서 이어간다"는 딱 한 가지입니다.

== 완전히 다른 상황인데 같은 패턴이 또 나온다

이제 전혀 다른 문제를 봅시다 — 화면에 출력하고 입력을 받는 `IO` 계산입니다.

[source,lean]
----
def greet : IO Unit := do
  IO.println "이름을 입력하세요:"
  let stdin ← IO.getStdin
  let name ← stdin.getLine
  IO.println s!"안녕, {name}!"
----

(`do`와 `←` 문법은 이 장 뒤에서 설명합니다 — 지금은 위에서 아래로 한 줄씩 실행되는 것처럼 읽으면 됩니다.)

`Option`과 `IO`는 표현하는 게 완전히 다릅니다 — 하나는 "실패할 수도 있는 값", 다른 하나는 "부수효과가 있는 실행 순서"입니다. 그런데 둘 다 똑같은 구조를 갖습니다: "이 계산을 하고, 그 결과를 받아서 다음 계산에 넘긴다." `Option`에서는 그게 `andThen`이었고, `IO`에서는 그게 각 줄을 순서대로 실행하고 결과를 다음 줄에 넘기는 것입니다. 리스트의 모든 조합을 만드는 계산, 상태를 들고 다니는 계산 등 겉보기엔 무관해 보이는 여러 상황이 전부 같은 뼈대를 공유합니다.

Lean4는 이 공통 뼈대를 `Monad`라는 타입 클래스로 뽑아냈습니다 — 4장에서 본 "타입마다 다르지만 이름은 같은 연산"과 정확히 같은 발상입니다. 핵심 연산은 두 개뿐입니다: 평범한 값을 계산으로 감싸는 `pure`, 그리고 방금 만든 `andThen`과 같은 역할을 하는 `bind`(기호로는 `>>=`). 두 타입에서 `bind`의 모양을 나란히 놓으면 같은 뼈대가 한눈에 보입니다.

----
Option에서의 bind : Option α → (α → Option β) → Option β
IO에서의 bind     : IO α → (α → IO β) → IO β
----

== do 표기법: 겹겹이 쌓인 bind를 순서대로 읽히게

`bind`(`>>=`)를 직접 계속 이어 쓰면 코드가 오른쪽으로 계속 밀려납니다. `do` 표기법은 그걸 마치 명령형 언어의 순차 실행처럼 보이게 풀어씁니다.

[source,lean]
----
def twoSteps'' (a b c : Nat) : Option Nat := do
  let r1 ← safeDiv a b
  let r2 ← safeDiv r1 c
  pure r2

#eval twoSteps'' 100 5 4  -- some 5
#eval twoSteps'' 100 0 4  -- none
----

`let r1 ← safeDiv a b`는 "`safeDiv a b`를 계산하고, 실패하지 않았다면 그 결과를 `r1`이라는 이름에 담아 다음 줄로 넘어간다"는 뜻입니다. 겉모습은 완전히 명령형처럼 보이지만, 실제로는 이 `do` 블록 전체가 앞서 손으로 쓴 `andThen` 연쇄로 그대로 풀립니다. `greet` 함수도 마찬가지입니다 — `IO` 계산을 순서대로 나열한 것처럼 보이지만, 사실은 `Monad IO` 인스턴스의 `bind`를 반복 적용한 것입니다.

`do` 블록 안에서는 `←`와 `:=`를 구분하는 게 중요합니다. `←`는 `Option` 같은 포장을 벗겨 값을 꺼내는 것(그래서 실패가 전파될 수 있는 것)이고, `:=`는 1장부터 써온 평범한 값 정의입니다 — 실패할 게 없는 순수 계산에는 `←`가 필요 없습니다.

[source,lean]
----
def twoStepsSum (a b c : Nat) : Option Nat := do
  let r1 ← safeDiv a b   -- Option에서 값을 꺼낸다 (none이면 여기서 전체 중단)
  let r2 ← safeDiv r1 c
  let total := r1 + r2   -- 평범한 계산에는 :=
  pure total

#eval twoStepsSum 100 5 4  -- some 25
----

== 1부를 마치며

1부에서는 Lean4를 증명이나 메타프로그래밍 이야기 없이 하나의 함수형 언어로만 다뤘습니다 — 값과 타입, 재귀와 패턴 매칭, 나만의 자료구조, 다형성과 타입 클래스, 그리고 그 타입 클래스의 대표적인 응용인 모나드까지 왔습니다. 이 다섯 개념(특히 "모든 식은 타입을 갖는다"와 "타입이 여러 모양 중 하나로 정의된다")이 2부의 출발점이 됩니다 — 다음 장에서 그 두 가지가 어떻게 "증명"이라는 완전히 새로운 영역으로 그대로 이어지는지 보게 됩니다.

def threeSteps (a b c d : Nat) : Option Nat := do
  let r1 ← safeDiv a b
  let r2 ← safeDiv r1 c
  let r3 ← safeDiv r2 d
  pure r3

#eval threeSteps 100 5 2 2  -- some 5
#eval threeSteps 100 5 0 2  -- none

def safeSub (a b : Nat) : Option Nat :=
  if b > a then none else some (a - b)

def subThenDiv (a b c : Nat) : Option Nat := do
  let d ← safeSub a b
  safeDiv d c

#eval subThenDiv 10 4 2  -- some 3
#eval subThenDiv 4 10 2  -- none

-- getLine 결과에는 줄바꿈 문자가 붙어 있어 출력 모양이 조금 어색할 수
-- 있지만, 계산을 순서대로 잇는 연습으로는 충분합니다.
def greet2 : IO Unit := do
  IO.println "이름을 입력하세요:"
  let stdin ← IO.getStdin
  let name ← stdin.getLine
  IO.println "사는 곳을 입력하세요:"
  let city ← stdin.getLine
  IO.println s!"{city}에 사는 {name}님, 반갑습니다!"
