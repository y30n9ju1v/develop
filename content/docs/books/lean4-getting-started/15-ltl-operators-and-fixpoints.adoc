NOTE: 14~16장 보너스 3부작의 2부입니다. 14장에서 ``LTL``, ``Trace``, ``sat``을 만들었다는 걸 전제로 이어집니다.

== until 하나로는 부족한 두 가지

14장에서는 ``until``(``.until``)로부터 ``eventually``(``◇``)와 ``always``(``□``)를 파생시켰습니다. 그런데 표준 LTL에는 이 둘 말고도 실무에서 자주 등장하는 연산자가 두 개 더 있습니다.

* **weak until** (``φ W ψ``): "``ψ``가 될 때까지 ``φ``가 계속된다"는 뜻은 ``until``과 같지만, ``ψ``가 **끝내 오지 않아도** ``φ``가 영원히 계속되기만 하면 참으로 칩니다. "``ψ``가 온다"는 약속이 없다는 뜻에서 "약한(weak)" until입니다.
* **release** (``φ R ψ``): "``ψ``는 ``φ``가 참이 되는 순간까지(그 순간 포함) 계속 참이어야 하고, ``φ``가 끝내 오지 않으면 ``ψ``가 영원히 참이어야 한다". `until`의 **쌍대(dual)** 연산자입니다 — ``¬(¬φ U ¬ψ)``로 정의됩니다.

두 연산자 모두 14장에서 이미 가진 조각(``until``, `not`, `and`)만으로 조립할 수 있습니다. 새 `inductive` 생성자가 필요 없다는 게 핵심입니다 — 6장에서 명제를 타입으로 다뤘던 것처럼, 논리 연산자도 "이미 있는 것들의 조합"으로 계속 늘려갈 수 있습니다.

== or부터: 그동안 없었던 논리합

14장의 ``LTL``에는 `and`와 `not`만 있고 `or`가 없었습니다. 드모르간 법칙(``p ∨ q ↔ ¬(¬p ∧ ¬q)``)을 그대로 가져오면 새 생성자 없이 만들 수 있습니다.

[source,lean]
----
def LTL.or {Atom} (φ ψ : LTL Atom) : LTL Atom := .not (.and (.not φ) (.not ψ))
----

== weak until과 release 정의하기

[source,lean]
----
def LTL.weakUntil {Atom} (φ ψ : LTL Atom) : LTL Atom :=
  LTL.or (.until φ ψ) (LTL.always φ)

def LTL.release {Atom} (φ ψ : LTL Atom) : LTL Atom :=
  .not (.until (.not φ) (.not ψ))

infixl:35 " U " => LTL.until
infixl:35 " W " => LTL.weakUntil
infixl:35 " R " => LTL.release
----

``φ W ψ``는 정확히 앞서 말한 정의 그대로입니다 — "``φ U ψ``가 성립하거나(``ψ``가 결국 온다), ``□φ``가 성립한다(``φ``가 영원히 계속된다)"의 논리합입니다. ``φ R ψ``는 9장에서 배운 ``¬p``가 ``p → False``였던 것과 같은 태도로, "``¬φ U ¬ψ``가 거짓이다"라는 이중부정으로 정의됩니다 — until을 뒤집으면 release가 나온다는 뜻입니다.

== 신호등으로 weak until 확인하기

14장의 신호등 trace(2번째 스텝까지 빨강, 그 이후 계속 초록)를 그대로 씁니다.

[source,lean]
----
example : sat trace 0 (isRed U isGreen) := by
  refine ⟨2, by omega, ?_, ?_⟩
  · show trace 2 .green = true
    simp [trace, lightAtom]
  · intro k _ hk
    show trace k .red = true
    simp [trace, lightAtom]
    omega

example : sat trace 0 (isRed W isGreen) := by
  unfold LTL.weakUntil LTL.or sat
  intro ⟨hn1, _⟩
  apply hn1
  refine ⟨2, by omega, ?_, ?_⟩
  · show trace 2 .green = true
    simp [trace, lightAtom]
  · intro k _ hk
    show trace k .red = true
    simp [trace, lightAtom]
    omega
----

두 증명이 사실상 똑같아 보이는 게 당연합니다 — ``isRed U isGreen``이 이미 참이니 ``isRed W isGreen``도 그 왼쪽 선택지(`or`의 첫 번째 항)를 고르기만 하면 참이 됩니다. `weak`이라는 이름값은 ``ψ``가 끝내 오지 않는 trace에서만 드러납니다 — 예를 들어 영원히 빨간불인 trace 위에서는 ``isRed U isGreen``은 거짓이지만 ``isRed W isGreen``은 참(``□isRed`` 덕분에)입니다.

== always는 사실 "모든 미래 스텝"과 같은 말이다

14장에서 ``□φ``는 ``¬◇(¬φ)``로, 다시 그건 ``¬(until top (not φ))``로 정의됐습니다. 정의만 보면 "``φ``가 아닌 순간이 존재한다는 게 거짓"이라는 이중부정처럼 보이는데, 직관적으로 우리가 기대하는 뜻은 훨씬 단순합니다 — "**모든** 미래 스텝에서 ``φ``가 참이다". 이 두 표현이 실제로 같은 뜻임을 증명해봅시다.

[source,lean]
----
theorem always_iff_forall {Atom} (σ : Trace Atom) (φ : LTL Atom) (i : Nat) :
    sat σ i (□φ) ↔ ∀ n, sat σ (i + n) φ := by
  unfold LTL.always LTL.eventually
  show (¬ ∃ j, j ≥ i ∧ sat σ j (.not φ) ∧ ∀ k, i ≤ k → k < j → sat σ k .top)
      ↔ ∀ n, sat σ (i + n) φ
  constructor
  · intro h n
    exact Classical.byContradiction fun hφ =>
      h ⟨i + n, by omega, hφ, fun k _ hk2 => trivial⟩
  · intro h ⟨j, hj1, hj2, _⟩
    exact hj2 (by have := h (j - i); rwa [show i + (j - i) = j by omega] at this)
----

``→`` 방향은 "``i+n``에서 ``φ``가 거짓이라고 가정하면, 그 ``j = i+n``이 바로 ``□φ`` 정의 안의 ``¬∃j...``를 무너뜨리는 증인이 된다"는 걸 ``Classical.byContradiction``으로 보입니다. ``←`` 방향은 반대로, ``□φ``를 무너뜨리는 증인 ``j``가 있다고 가정했을 때 그 ``j``를 ``i + (j - i)`` 꼴로 다시 쓰고 가정 ``h``를 그 자리에 대입해 모순을 끌어냅니다.

이 정리가 왜 중요할까요 — ``□``의 원래 정의는 "``until``을 뒤집은 이중부정"이라 한눈에 뜻이 안 들어오지만, 이 정리 덕분에 이제부터는 ``□φ``를 볼 때마다 "``i``, ``i+1``, ``i+2``, ... 모든 스텝에서 ``φ``가 참"이라는 훨씬 익숙한 그림으로 바꿔 생각할 수 있습니다. 모델체킹 이론에서 ``□``를 "최대 고정점(greatest fixpoint)"으로 정의하는 이유가 바로 이겁니다 — "한 스텝 더 파고들어도 계속 성립"을 무한히 반복한 게 정확히 "모든 스텝에서 성립"과 같다는 뜻이고, 방금 그 동치를 직접 증명한 셈입니다.

== 직접 해보기

* ``LTL.release``의 정의를 참고해, "``φ R ψ``이면 ``ψ``도 참이다"(``sat σ i (φ R ψ) → sat σ i ψ``)를 증명해보세요. 14장 마지막 연습문제의 ``always_implies``와 구조가 거의 같습니다.
* ``always_iff_forall``을 이용해서, "``□φ``이면 다음 스텝에서도 ``□φ``다"(``sat σ i (□φ) → sat σ (i+1) (□φ)``)를 ``unfold`` 없이 ``.mp``/``.mpr``만으로 증명해보세요.

.해답 보기
[%collapsible]
====
[source,lean]
----
theorem release_implies {Atom} (σ : Trace Atom) (φ ψ : LTL Atom) (i : Nat) :
    sat σ i (φ R ψ) → sat σ i ψ := by
  intro h
  unfold LTL.release sat at h
  exact Classical.byContradiction fun hψ =>
    h ⟨i, by omega, hψ, fun k _ hk2 => absurd hk2 (by omega)⟩

theorem always_next {Atom} (σ : Trace Atom) (φ : LTL Atom) (i : Nat) :
    sat σ i (□φ) → sat σ (i+1) (□φ) := by
  intro h
  apply (always_iff_forall σ φ (i+1)).mpr
  intro n
  have := (always_iff_forall σ φ i).mp h (n + 1)
  rwa [show i + (n + 1) = i + 1 + n by omega] at this
----
====

== 이 장이 왜 중요한가

새 생성자를 하나도 추가하지 않고 `or`, `weak until`, `release`를 전부 기존 조각의 조합으로 채웠습니다 — 6장부터 반복해서 확인한 태도, "새 논리 연산자도 결국 이미 아는 것들의 재조합"이 여기서도 통했습니다. 그리고 ``always_iff_forall``은 이 장에서 가장 중요한 결과입니다 — ``□``의 재귀적(이중부정) 정의와 "모든 스텝에서 참"이라는 직관적 정의가 동치라는 걸 직접 증명함으로써, 다음 장에서 "경로 전체에 걸친 성질"을 다룰 때 필요한 감각을 미리 확보했습니다.

다음 장에서는 지금까지 하나의 무한 실행 흐름(단일 `Trace`)만 다뤘던 걸 벗어나, "다음 상태가 여러 갈래로 갈라질 수 있는" 시스템 위에서 "모든 경로에서"와 "어떤 경로가 존재해서"를 구분하는 분기 시제논리(CTL)를 다룹니다.

== 요약

* ``or``, ``weak until``, ``release``는 모두 14장의 `until`/`not`/`and`만으로 새 생성자 없이 정의된다 — `release`는 `until`의 쌍대(``¬(¬φ U ¬ψ)``)다.
* ``φ W ψ``는 ``φ U ψ ∨ □φ``다 — ``ψ``가 끝내 오지 않아도 ``φ``가 영원히 계속되면 참이 된다는 점에서 `until`보다 "약하다".
* ``□φ``(항상 φ)는 정의상 이중부정이지만, ``always_iff_forall`` 정리로 "모든 미래 스텝 ``i``, ``i+1``, ``i+2``, ...에서 ``φ``가 참"과 정확히 같은 뜻임이 증명된다 — 이게 ``□``의 최대 고정점 성격이다.
