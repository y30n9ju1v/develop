== 모든 자연수를 어떻게 증명할까

"모든 자연수 ``n``에 대해 ..." 같은 명제는 무한히 많은 경우를 담고 있습니다. ``n``에 0, 1, 2, ...를 하나씩 대입해서 확인할 수는 없습니다. 그런데 2장에서 ``Nat``을 재귀로 다룰 때 이미 이 문제의 답을 봤습니다 — ``sumTo``를 정의할 때 "0인 경우"와 "``n+1``인 경우(단, ``sumTo n``은 이미 계산됐다고 가정)" 두 가지만 다뤄서 모든 자연수를 커버했습니다. 귀납 증명은 정확히 같은 구조를 씁니다.

실습을 위해, 2장에서 했던 것처럼 우리만의 덧셈 함수를 하나 정의합시다. 첫째 인자에 대해 재귀합니다.

[source,lean]
----
def myAdd : Nat → Nat → Nat
  | 0,     m => m
  | n + 1, m => myAdd n m + 1

#eval myAdd 3 4  -- 7
----

정의상 ``myAdd 0 m = m``은 계산만으로 바로 참입니다. 그런데 반대쪽인 ``myAdd n 0 = n``은 어떨까요? 정의 어디에도 "둘째 인자가 0이면"이라는 규칙은 없으므로, 계산만으로는 끝나지 않습니다 — 모든 ``n``에 대한 증명이 필요합니다.

[source,lean]
----
theorem myAdd_zero (n : Nat) : myAdd n 0 = n := by
  induction n with
  | zero => rfl
  | succ k ih =>
    -- ih : myAdd k 0 = k  (귀납 가정)
    -- 목표 : myAdd (k + 1) 0 = k + 1
    simp [myAdd, ih]
----

``induction n with``은 목표를 두 하위 목표로 쪼갭니다. `zero` 갈래는 ``n``이 0인 경우로, ``myAdd 0 0 = 0``이 계산만으로(`rfl`) 바로 참입니다. `succ k ih` 갈래는 ``n``이 어떤 ``k``의 다음 수(`k+1`)인 경우인데, 여기서 `ih`(induction hypothesis, 귀납 가정)로 "``k``에 대해서는 이미 명제가 참이라고 가정해도 된다"는 걸 공짜로 받습니다.

`succ k ih` 갈래로 들어간 직후, VS Code의 InfoView(커서를 그 줄에 두면 보이는 목표 상태 창)는 이렇게 보입니다.

----
k : Nat
ih : myAdd k 0 = k
⊢ myAdd (k + 1) 0 = k + 1
----

``ih``가 가정 목록에 새로 추가된 걸 눈여겨보세요 — 이게 바로 "``k``에 대해서는 이미 증명됐다고 치자"는 귀납 가정입니다. ``simp [myAdd, ih]``를 실행하면 ``simp``이 ``myAdd``의 정의를 한 겹 펼쳐 목표를 ``myAdd k 0 + 1 = k + 1``로 만들고, ``ih``를 재작성 규칙으로 써서 ``myAdd k 0``을 ``k``로 바꾸면 ``k + 1 = k + 1``이 되어 닫힙니다.

시험 삼아 ``ih``를 빼고 ``simp [myAdd]``만 써보세요 — InfoView에 이렇게 남은 채 멈춥니다.

----
k : Nat
ih : myAdd k 0 = k
⊢ myAdd k 0 = k
----

목표가 귀납 가정과 글자까지 똑같은 모양으로 줄어들었는데도, ``ih``를 쓰라고 알려주지 않으면 닫히지 않습니다. 귀납 가정 없이는 딱 거기까지입니다.

이게 왜 정당한 걸까요? 도미노를 생각하면 됩니다 — 첫 도미노(`zero`)가 넘어지고, "``k``번째가 넘어지면 ``k+1``번째도 넘어진다"(`succ`)는 것만 보이면, 모든 도미노가 넘어진다고 결론 낼 수 있습니다. 무한히 많은 경우를 두 단계로 압축하는 게 귀납법의 핵심입니다.

NOTE: 왜 표준 덧셈이 아니라 ``myAdd``로 연습할까요? 표준 라이브러리의 덧셈은 둘째 인자에 대해 재귀하도록 정의돼 있어서 ``n + 0 = n``이 계산만으로(`rfl` 한 줄) 끝나 버리고, 그렇지 않은 명제도 대부분 이미 증명돼 있어서 ``simp``이 기존 정리를 그냥 가져다 씁니다. 귀납이 실제로 일하는 모습을 보려면 아직 아무 정리도 증명돼 있지 않은 우리만의 함수가 필요합니다.

== 재귀 정의와 귀납 증명은 사실 하나다

2장에서 재귀 함수를 정의할 때 컴파일러가 "종료성"을 검사한다고 했습니다. 사실 그 검사와 지금 본 귀납 증명은 같은 원리를 반대 방향으로 쓴 것입니다.

* 재귀 정의: "``n``에 대한 답을 내려면, 더 작은 값(``n``보다 작은 수)에 대한 답을 이미 안다고 가정하고 그걸로 조립한다."
* 귀납 증명: "``n``에 대한 명제를 증명하려면, 더 작은 값(`k = n-1`)에 대한 명제를 이미 참이라고 가정하고 그걸로 조립한다."

``inductive``로 정의된 타입(3장)은 전부 이런 식으로 "자기 자신을 증명하거나 계산하는 규칙"을 공짜로 딸려 옵니다. ``Shape``처럼 재귀적이지 않은 타입도, ``List``나 ``Nat``처럼 재귀적인 타입도 전부 `induction` 전술을 쓸 수 있습니다 — 예를 들어 ``List``는 ``nil``과 `cons` 두 갈래로 귀납합니다. 2장의 ``listLen``으로 확인해봅시다.

[source,lean]
----
def listLen : List Nat → Nat
  | []      => 0
  | _ :: xs => 1 + listLen xs

theorem listLen_append (as bs : List Nat) :
    listLen (as ++ bs) = listLen as + listLen bs := by
  induction as with
  | nil => simp [listLen]
  | cons a as' ih =>
    simp [listLen, ih]
    omega
----

`cons a as' ih` 갈래에서 ``ih : listLen (as' ++ bs) = listLen as' + listLen bs``를 이미 참이라고 가정할 수 있습니다. ``simp [listLen, ih]``가 정의를 펼치고 귀납 가정을 적용하고 나면 ``1 + (listLen as' + listLen bs) = 1 + listLen as' + listLen bs``라는 순수 산술 목표만 남는데, 이런 괄호 재배열 마무리는 7장에서 본 ``omega``에게 맡기면 됩니다.

== 귀납 가정을 어떻게 쓰는지가 핵심이다

귀납 증명에서 실수하기 가장 쉬운 지점은 "귀납 가정(`ih`)을 어디에 어떻게 꽂아 넣어야 목표가 풀리는가"입니다. 앞의 두 예제 모두 ``simp [..., ih]``처럼 ``ih``를 명시적으로 넘겨서 단순화 도구가 그 등식을 재작성 규칙으로 쓰게 했습니다. ``ih``를 빼면 ``simp``은 정의를 펼치는 데까지만 가고 멈춥니다 — ``myAdd_zero``에서 직접 확인했듯이요. 증명이 막혔을 때 가장 먼저 확인할 것은 "지금 가진 귀납 가정을 목표에 실제로 활용했는가"입니다.

== 이 장이 왜 중요한가

6장에서 명제가 타입이고 증명이 값이라는 관점을 세우고, 7장에서 그 값을 손으로 조립하는 대신 전술로 만드는 법을 봤습니다. 이 장의 귀납법으로 무한히 많은 경우를 유한한 단계로 압축하는 도구까지 갖췄습니다 — 여기까지가 "참인 명제를 증명하는 법"의 핵심입니다.

다음 장에서는 반대 방향을 다룹니다 — "아니다"와 모순을 증명하는 법입니다. 참을 증명하는 도구만큼이나, 거짓을 다루는 도구도 2부를 완성하는 데 필요합니다.

TIP: 더 깊이 들어가려면 — 귀납적 타입의 이론적 토대는 link:../../../programming/lean/theorem-proving-in-lean4/07-inductive-types/[Theorem Proving in Lean 4의 7장: 귀납적 타입], 더 복잡한 귀납·재귀 패턴은 link:../../../programming/lean/theorem-proving-in-lean4/08-induction-and-recursion/[같은 책 8장: 귀납과 재귀]를 보세요.

== 직접 해보기

* ``myAdd n (m + 1) = myAdd n m + 1``을 ``n``에 대한 귀납으로 증명해보세요. 본문의 ``myAdd_zero``와 거의 같은 뼈대로 됩니다.
* 방금 증명한 ``listLen_append``를 이용해 — 새 귀납 없이 ``rw``와 ``omega``만으로 — ``listLen (as ++ as) = 2 * listLen as``를 증명해보세요. 한 번 증명한 정리는 이렇게 재료로 다시 쓸 수 있습니다.

.해답 보기
[%collapsible]
====
[source,lean]
----
theorem myAdd_succ (n m : Nat) : myAdd n (m + 1) = myAdd n m + 1 := by
  induction n with
  | zero => rfl
  | succ k ih => simp [myAdd, ih]

theorem listLen_double (as : List Nat) :
    listLen (as ++ as) = 2 * listLen as := by
  rw [listLen_append]
  omega
----
====

== 요약

* 무한히 많은 경우를 담은 명제("모든 자연수에 대해...")는 대입으로 다 확인할 수 없어 귀납법이 필요하다.
* ``induction n with | zero => ... | succ k ih => ...``는 기저 사례(0)와 귀납 단계(k → k+1)로 목표를 쪼갠다.
* `succ` 갈래에서 얻는 `ih`(귀납 가정)는 "k에 대해서는 이미 참"이라는 공짜 가정이고, 이걸 실제로 활용해야 목표가 닫힌다.
* 재귀 정의(더 작은 입력의 답을 가정하고 조립)와 귀납 증명(더 작은 값의 명제를 가정하고 조립)은 같은 원리를 반대 방향으로 쓴 것이다.
