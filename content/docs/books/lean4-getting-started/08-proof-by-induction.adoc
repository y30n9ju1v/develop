== 모든 자연수를 어떻게 증명할까

"모든 자연수 `n`에 대해 `n + 0 = n`이다" 같은 명제는 무한히 많은 경우를 담고 있습니다. `n`을 0, 1, 2, ...로 하나씩 대입해서 확인할 수는 없습니다. 그런데 2장에서 `Nat`을 재귀로 다룰 때 이미 이 문제의 답을 봤습니다 — `sumTo`를 정의할 때 "0인 경우"와 "`n+1`인 경우(단, `sumTo n`은 이미 계산됐다고 가정)" 두 가지만 다뤄서 모든 자연수를 커버했습니다.

귀납 증명은 정확히 같은 구조를 씁니다.

[source,lean]
----
theorem add_zero' (n : Nat) : n + 0 = n := by
  induction n with
  | zero => rfl
  | succ k ih =>
    -- ih : k + 0 = k  (귀납 가정)
    -- 목표 : k + 1 + 0 = k + 1
    simp [ih]
----

`induction n with`은 목표를 두 하위 목표로 쪼갭니다. `zero` 갈래는 `n`이 0인 경우고, 여기서는 `0 + 0 = 0`이 계산만으로(`rfl`) 바로 참입니다. `succ k ih` 갈래는 `n`이 어떤 `k`의 다음 수(`k+1`)인 경우인데, 여기서 `ih`(induction hypothesis, 귀납 가정)로 "`k`에 대해서는 이미 명제가 참이라고 가정해도 된다"는 걸 공짜로 받습니다.

`succ k ih` 갈래로 들어간 직후, VS Code의 InfoView(커서를 그 줄에 두면 보이는 목표 상태 창)는 이렇게 보입니다.

----
k : Nat
ih : k + 0 = k
⊢ k + 1 + 0 = k + 1
----

`ih`가 가정 목록에 새로 추가된 걸 눈여겨보세요 — 이게 바로 "`k`에 대해서는 이미 증명됐다고 치자"는 귀납 가정입니다. 목표(`⊢` 아래)는 `k`가 아니라 `k + 1`에 대한 것으로 바뀌어 있습니다. 이 상태에서 `simp [ih]`를 실행하면, `simp`이 `ih`를 재작성 규칙으로 써서 목표 안의 `k + 0`을 `k`로 바꾸고, 남은 `k + 1 = k + 1`을 자동으로 닫습니다.

이게 왜 정당한 걸까요? 도미노를 생각하면 됩니다 — 첫 도미노(`zero`)가 넘어지고, "`k`번째가 넘어지면 `k+1`번째도 넘어진다"(`succ`)는 것만 보이면, 모든 도미노가 넘어진다고 결론 낼 수 있습니다. 무한히 많은 경우를 두 단계로 압축하는 게 귀납법의 핵심입니다.

== 재귀 정의와 귀납 증명은 사실 하나다

2장에서 재귀 함수를 정의할 때 컴파일러가 "종료성"을 검사한다고 했습니다. 사실 그 검사와 지금 본 귀납 증명은 같은 원리를 반대 방향으로 쓴 것입니다.

* 재귀 정의: "`n`에 대한 답을 내려면, 더 작은 값(`n`보다 작은 수)에 대한 답을 이미 안다고 가정하고 그걸로 조립한다."
* 귀납 증명: "`n`에 대한 명제를 증명하려면, 더 작은 값(`k = n-1`)에 대한 명제를 이미 참이라고 가정하고 그걸로 조립한다."

`inductive`로 정의된 타입(3장)은 전부 이런 식으로 "자기 자신을 증명하거나 계산하는 규칙"을 공짜로 딸려 옵니다. `Shape`처럼 재귀적이지 않은 타입도, `List`나 `Nat`처럼 재귀적인 타입도 전부 `induction` 전술을 쓸 수 있습니다 — 예를 들어 `List`는 `nil`과 `cons` 두 갈래로 귀납합니다.

[source,lean]
----
theorem len_append (as bs : List Nat) :
    (as ++ bs).length = as.length + bs.length := by
  induction as with
  | nil => simp
  | cons a as' ih =>
    simp [ih]
    omega
----

`cons a as' ih` 갈래에서 `ih : (as' ++ bs).length = as'.length + bs.length`를 이미 참이라고 가정할 수 있고, 그걸 이용해 리스트 앞에 원소 하나(`a`)가 더 붙은 경우까지 증명을 확장합니다.

== 귀납 가정을 어떻게 쓰는지가 핵심이다

귀납 증명에서 실수하기 가장 쉬운 지점은 "귀납 가정(`ih`)을 어디에 어떻게 꽂아 넣어야 목표가 풀리는가"입니다. 앞의 두 예제 모두 `simp [ih]`처럼 `ih`를 명시적으로 넘겨서 단순화 도구가 그 등식을 재작성 규칙으로 쓰게 했습니다. 만약 `ih`를 빼고 `simp`만 쓰면, `simp`은 재귀적으로 정의된 `length`나 `+`를 더 풀어내지 못하고 막히는 경우가 많습니다. 증명이 막혔을 때 가장 먼저 확인할 것은 "지금 가진 귀납 가정을 목표에 실제로 활용했는가"입니다.

== 2부를 마치며

2부에서는 명제가 타입이고 증명이 값이라는 관점(6장)에서 출발해, 그 값을 손으로 조립하는 대신 전술로 반자동으로 만드는 법(7장), 그리고 무한히 많은 경우를 유한한 단계로 압축하는 귀납법(8장)까지 왔습니다. 여기까지가 "Lean4를 증명 도구로 쓰는 법"의 핵심입니다.

3부에서는 시선을 한 단계 더 올립니다 — `induction`, `simp`, `omega` 같은 전술들이 대체 어떻게 동작하는지, 그리고 여러분이 직접 그런 전술을 만들 수 있는지를 봅니다.
