== 왜 "지금 참"만으로는 부족한가

지금까지 증명한 명제는 전부 어떤 한 순간의 사실이었습니다 — "``1 + 1 = 2``", "``n < 3``". 그런데 신호등, 네트워크 프로토콜, 동시성 프로그램처럼 **시간에 따라 상태가 바뀌는 시스템**을 다룰 때는 "지금 참이다"만으로는 표현이 안 되는 성질이 있습니다.

* "신호등은 **언젠가는** 초록으로 바뀐다" — 지금 당장은 아니어도 상관없다.
* "빨간불인 동안에는 **계속** 차가 멈춰 있다" — 매 순간 성립해야 한다.
* "요청을 보내면 **다음 순간** 응답을 기다리는 상태가 된다" — 바로 한 스텝 뒤의 이야기다.

이런 "언젠가는(eventually)", "항상(always)", "다음에(next)" 같은 시간 관계를 다루는 논리를 **시제논리(temporal logic)**라고 부르고, 그중 하나의 무한한 실행 흐름을 대상으로 하는 버전을 **선형 시제논리(Linear Temporal Logic, LTL)**라고 합니다. 이 장에서는 LTL을 Lean4 위에 처음부터 직접 만들어봅니다.

== 무한 실행 흐름을 함수로 표현하기

시제논리가 다루는 대상은 "시간이 지나며 상태가 바뀌는 무한한 흐름"입니다. 2장에서 자연수를 재귀적으로 다뤘던 것처럼, 여기서도 시간을 자연수 ``Nat``으로, 그 시간에 어떤 원자명제가 참인지를 함수로 표현하면 됩니다.

[source,lean]
----
def Trace (Atom : Type) := Nat → Atom → Bool
----

``Trace Atom``은 "시간 ``i``에 원자명제 ``a``가 참인가"를 답해주는 함수입니다. 별도의 무한 리스트 자료구조를 만들 필요가 없습니다 — 함수 자체가 이미 "각 시간마다 값 하나"라는 무한 수열을 표현하기 때문입니다.

== LTL 논리식을 inductive 타입으로

3장에서 ``Shape``를 생성자들로 빚었듯이, LTL 논리식도 "이 문법으로 만들 수 있는 것들"을 나열한 `inductive` 타입입니다.

[source,lean]
----
inductive LTL (Atom : Type) where
  | top                          -- 항상 참
  | atom (a : Atom)              -- 원자명제
  | not (φ : LTL Atom)           -- ¬φ
  | and (φ ψ : LTL Atom)         -- φ ∧ ψ
  | next (φ : LTL Atom)          -- ○φ : 다음 순간에 φ
  | until (φ ψ : LTL Atom)       -- φ U ψ : ψ가 참이 될 때까지 φ
  deriving Repr
----

핵심은 ``next``와 ``until`` 두 생성자입니다. ``next φ``는 "바로 다음 시점에 ``φ``"라는 뜻이고, ``until φ ψ``는 "``ψ``가 참이 될 때까지 ``φ``가 계속 참이다가, 결국 어느 시점에 ``ψ``가 참이 된다"는 뜻입니다. 이 두 개만 있으면 "언젠가는"과 "항상"을 **파생시켜** 만들 수 있습니다 — 새 생성자를 더 추가할 필요가 없습니다.

[source,lean]
----
def LTL.eventually {Atom} (φ : LTL Atom) : LTL Atom := .until .top φ
def LTL.always {Atom} (φ : LTL Atom) : LTL Atom := .not (LTL.eventually (.not φ))

notation "◇" φ => LTL.eventually φ   -- ◇φ : 언젠가는 φ
notation "□" φ => LTL.always φ       -- □φ : 항상 φ
----

``◇φ``(언젠가는 φ)는 "아무 조건 없이(``top``) φ를 향해 나아가다가 φ에 도달한다"는 뜻이고, ``□φ``(항상 φ)는 "φ가 아닌 순간이 언젠가는 온다는 게 거짓이다" — 즉 6~9장에서 배운 ``¬(¬p) ↔ p`` 발상 그대로, "결코 어긋나지 않는다"를 이중부정으로 표현한 것입니다.

== 만족 관계: 논리식이 언제 참인가

`inductive` 타입은 형태만 정의할 뿐, 그게 실제로 "참"이 되는 조건은 따로 정의해야 합니다. 6장에서 명제를 타입으로 다뤘던 것과 마찬가지로, 여기서는 "trace ``σ``의 시간 ``i``에서 논리식 ``φ``가 참이다"를 재귀 함수로 정의합니다.

[source,lean]
----
def sat {Atom : Type} (σ : Trace Atom) (i : Nat) : LTL Atom → Prop
  | .top => True
  | .atom a => σ i a = true
  | .not φ => ¬ sat σ i φ
  | .and φ ψ => sat σ i φ ∧ sat σ i ψ
  | .next φ => sat σ (i + 1) φ
  | .until φ ψ => ∃ j, j ≥ i ∧ sat σ j ψ ∧ ∀ k, i ≤ k → k < j → sat σ k φ
----

``next``는 인덱스를 ``i + 1``로 옮겨서 재귀 호출하는 것뿐이고, ``until``은 "미래의 어느 시점 ``j``에 ``ψ``가 참이고, 그 전까지(``i``부터 ``j`` 직전까지)는 계속 ``φ``가 참"이라는 정의를 그대로 ``∃``와 ``∀``로 옮긴 것입니다. 2장에서 재귀 함수로 "몇 번 반복할지"를 표현했다면, 여기서는 그 반복이 "언제 끝날지"를 증명 대상으로 다루는 셈입니다.

== 신호등 예제로 확인해보기

신호등이 두 스텝 동안 빨강이었다가 그 뒤로 계속 초록인 trace를 만들어 봅시다.

[source,lean]
----
inductive Light where
  | red | yellow | green
  deriving DecidableEq, Repr

def isRed : LTL Light := .atom .red
def isGreen : LTL Light := .atom .green

def lightAtom : Light → Light → Bool := fun s a => s == a
def trace : Trace Light := fun i => lightAtom (if i < 2 then .red else .green)

-- 시간 0에서 "언젠가는 초록이 켜진다"가 성립함을 증명
example : sat trace 0 (◇isGreen) := by
  unfold LTL.eventually sat
  refine ⟨2, by omega, ?_, ?_⟩
  · show trace 2 .green = true
    simp [trace, lightAtom]
  · intro k _ hk
    trivial
----

증명의 뼈대는 익숙합니다 — ``refine ⟨2, ...⟩``으로 "시간 2에 도달한다"는 증인을 직접 제시하고, 나머지는 정의를 펼쳐(`unfold`) 계산으로 확인합니다. 8장에서 존재 증명에 증인을 직접 제시했던 패턴이 여기서도 그대로 통합니다.

== eventually의 한 스텝 이동을 증명하기

"``i+1``번째 시점에서 언젠가는 φ가 참이면, ``i``번째 시점에서도 언젠가는 φ가 참이다" — 미래의 어느 시점에 도달할 약속은 한 스텝 앞에서 봐도 여전히 유효하다는 뜻입니다. 8장의 귀납 증명과 마찬가지로, `until`의 정의 안에 있는 ``∃``와 ``∀``를 직접 다뤄야 합니다.

[source,lean]
----
theorem eventually_of_next {Atom} (σ : Trace Atom) (φ : LTL Atom) (i : Nat) :
    sat σ (i+1) (◇φ) → sat σ i (◇φ) := by
  intro h
  unfold LTL.eventually sat at h ⊢
  obtain ⟨j, hj1, hj2, hj3⟩ := h
  refine ⟨j, by omega, hj2, ?_⟩
  intro k hk1 hk2
  rcases Nat.lt_or_ge k (i+1) with hk | hk
  · trivial
  · exact hj3 k hk hk2
----

가정 `h`를 ``obtain``으로 뜯어보면 "미래의 어느 시점 ``j``에서 ``φ``가 참이고, ``i+1``부터 ``j`` 이전까지는 조건이 없다(``top``이므로 자동으로 참)"는 증거가 들어있습니다. 목표도 똑같은 ``j``로 증명하면 되는데, 유일하게 다른 건 범위가 ``i``부터로 한 칸 넓어졌다는 것뿐입니다. ``i``에서 ``i+1`` 사이의 구간(``k < i+1``)은 ``top``이라 `trivial`로 넘어가고, 나머지는 원래 가정 `hj3`를 그대로 재사용합니다.

이 증명이 보여주는 건 결국 8장에서 배운 태도와 같습니다 — 새 시제논리 연산자처럼 보여도 그 증명은 결국 ``∃``와 ``∀``를 다루는 익숙한 전술 조합일 뿐입니다.

== 직접 해보기

* ``trace`` 위에서 ``sat trace 2 (□isGreen)``(시간 2부터는 항상 초록)이 성립함을 증명해보세요. ``LTL.always``와 ``LTL.eventually``를 `unfold`한 뒤, 모순을 이끌어내는 방식(9장의 ``exfalso`` 스타일)으로 접근하면 됩니다.
* ``LTL.always``의 정의를 참고해, "``□φ``이면 ``φ``도 참이다"(``sat σ i (□φ) → sat σ i φ``)를 증명해보세요. `until`의 정의에서 ``j = i``인 경우를 어떻게 배제(또는 활용)할지가 핵심입니다. (참고: ``sat``은 임의의 ``Prop``이라 결정 가능성이 보장되지 않으므로, 9장까지와 달리 ``Classical.byContradiction``으로 배중률을 명시적으로 빌려와야 합니다.)

.해답 보기
[%collapsible]
====
[source,lean]
----
example : sat trace 2 (□isGreen) := by
  unfold LTL.always LTL.eventually sat
  intro hex
  obtain ⟨j, hj1, hj2, hj3⟩ := hex
  apply hj2
  show trace j Light.green = true
  simp [trace, lightAtom]
  omega

theorem always_implies {Atom} (σ : Trace Atom) (φ : LTL Atom) (i : Nat) :
    sat σ i (□φ) → sat σ i φ := by
  intro h
  unfold LTL.always LTL.eventually sat at h
  exact Classical.byContradiction fun hφ =>
    h ⟨i, by omega, hφ, fun k _ hk2 => absurd hk2 (by omega)⟩
----
====

== 이 장이 왜 중요한가

이 장에서 새로 만든 건 사실 하나도 없습니다 — `inductive`로 문법을 정의하고(3장), 그 문법에 뜻을 부여하는 재귀 함수를 짜고(2장), ``∃``·``∀``가 섞인 명제를 전술로 풀어냈을(7~9장) 뿐입니다. 다만 이번엔 그 재료로 "시간이 흐르는 시스템의 성질"이라는, 전혀 다른 분야의 논리 체계 하나를 통째로 빚어냈습니다. Lean4에서 새 논리를 만드는 일이 언어 밖 특별한 기능이 아니라, 지금까지 배운 타입과 증명 도구의 재조합이라는 걸 다시 한번 확인한 셈입니다.

실제 소프트웨어 검증에서는 이런 LTL/CTL 스타일의 시제논리가 모델 체커(model checker)의 이론적 기반으로 쓰입니다. 이 장에서는 `next`와 `until` 두 연산자만 다뤘는데, 15장에서는 나머지 표준 연산자(`release`, `weak until`)를 마저 채우고 ``□``가 사실 "모든 미래 스텝에서 참"과 정확히 같은 뜻임을 증명해봅니다. 16장에서는 여기서 한 걸음 더 나가 "경로가 여러 갈래로 갈라질 수 있는" 분기 시제논리(CTL)를 맛봅니다.

== 요약

* 무한히 이어지는 실행 흐름은 별도 자료구조 없이 함수 ``Nat → Atom → Bool``(``Trace``)로 표현할 수 있다.
* LTL 논리식은 3장의 `inductive` 타입 그대로 정의된다 — 핵심 생성자는 `next`(다음 순간)와 `until`(~할 때까지)뿐이고, "언젠가는"(``◇``)과 "항상"(``□``)은 그로부터 파생된다.
* 논리식이 "참"이 되는 조건(``sat``)은 6장의 명제=타입 발상처럼 별도의 재귀 함수로 정의하며, ``until``의 정의는 ``∃``와 ``∀``의 조합일 뿐이다.
* 시제논리에 대한 증명도 8~9장에서 배운 귀납·모순 증명 패턴을 그대로 재사용해서 풀 수 있다.
