== 손으로 조립하기 vs 전술로 좁혀가기

6장 마지막에서 `And'`(그리고)를 증명하려면 양쪽 증명을 담은 값을 직접 만들면 된다고 했습니다.

[source,lean]
----
theorem and_comm' (p q : Prop) (h : p ∧ q) : q ∧ p :=
  ⟨h.right, h.left⟩
----

`⟨h.right, h.left⟩`은 `And`(구조체) 값을 직접 조립한 것입니다. 명제가 단순할 땐 이렇게 손으로 조립하는 게 빠릅니다. 하지만 증명이 복잡해지면 "어떤 값을 조립해야 하는지"를 미리 통째로 그려내기가 점점 어려워집니다. 대신 **전술(tactic)**을 쓰면 "지금 증명해야 할 목표"를 한 걸음씩 더 쉬운 목표로 바꿔가면서, 마지막엔 Lean4가 자동으로 그 값을 조립하게 시킬 수 있습니다.

[source,lean]
----
theorem and_comm'' (p q : Prop) (h : p ∧ q) : q ∧ p := by
  constructor
  · exact h.right
  · exact h.left
----

`by`로 시작하면 전술 모드에 들어갑니다. `constructor`는 "목표가 `And`(그리고) 모양이니, 두 개의 하위 목표(`q`, `p`)로 쪼개라"는 뜻입니다. 각 하위 목표를 `exact`로 채우면 끝입니다. 결과물은 `and_comm'`과 똑같은 증명 값이지만, 쓰는 과정이 "이 목표를 어떻게 좁힐까"를 반복하는 대화형 작업이 됩니다.

== 자주 쓰는 전술 몇 가지

*intro* — 목표가 `p → q`(함의) 모양이면, `p`의 증명을 가정으로 받아들이고 목표를 `q`로 줄입니다.

[source,lean]
----
theorem imp_example (p q : Prop) : p → (q → p) := by
  intro hp
  intro _hq
  exact hp
----

*apply* — 이미 가진 정리나 가정을 목표에 "역방향으로" 적용합니다. 목표가 `B`이고 `h : A → B`가 있으면, `apply h`로 목표를 `A`로 바꿉니다.

[source,lean]
----
theorem apply_example (n : Nat) (h : n > 0 → n ≠ 0) (hn : n > 0) : n ≠ 0 := by
  apply h
  exact hn
----

*rw* (rewrite) — 등식을 이용해 목표 안의 식을 다른 식으로 바꿔 씁니다.

[source,lean]
----
theorem rw_example (a b : Nat) (h : a = b) : a + 1 = b + 1 := by
  rw [h]
----

`h : a = b`를 이용해 목표 `a + 1 = b + 1`에서 `a`를 `b`로 바꾸면 `b + 1 = b + 1`이 되고, 이건 `rfl`로 바로 끝납니다. `rw`는 마지막에 남는 `rfl`을 자동으로 처리해줍니다.

*simp* — 등록된 "당연한" 등식과 정리들을 최대한 자동으로 적용해서 목표를 단순화합니다.

[source,lean]
----
theorem simp_example (n : Nat) : n + 0 = n := by
  simp
----

`simp`은 편리하지만 "왜 증명됐는지"를 감춥니다. 어떤 정리 하나로 충분한 증명이라면 `rw`나 `exact`로 명시하는 게 나중에 코드를 읽을 사람(미래의 여러분 포함)에게 더 친절합니다.

== 목표 상태 읽는 법

전술을 쓰는 동안 Lean4는 항상 "현재 증명해야 할 목표"를 보여줍니다. VS Code에서 커서를 전술 사이에 두면 이렇게 보입니다.

----
p q : Prop
h : p ∧ q
⊢ q ∧ p
----

`⊢` 위는 지금까지 얻은 가정들, `⊢` 아래는 지금 증명해야 할 목표입니다. 전술을 한 줄씩 적용할 때마다 이 화면이 바뀌는 걸 지켜보는 게 전술 증명을 익히는 가장 빠른 방법입니다 — 눈으로 읽기보다 직접 VS Code에서 한 줄씩 눌러보길 권합니다.

== 왜 손으로 조립하는 대신 전술을 쓰는가

전술의 진짜 힘은 "반복되는 증명 패턴을 자동화할 수 있다"는 데 있습니다. `omega`(6장에서 잠깐 봤던)는 선형 산술 문제를, `simp`은 단순화를, 뒤에서 볼 `induction`은 귀납 증명의 뼈대를 대신 짜줍니다. 이런 전술들 하나하나가 사실 Lean4로 짜인 평범한 프로그램입니다 — 3부에서 그 전술을 직접 만들어보면서 이 사실을 확인합니다.

다음 장에서는 "모든 자연수에 대해" 같은, 경우의 수가 무한한 명제를 어떻게 유한한 단계로 증명하는지 — 귀납법을 다룹니다.
