== 손으로 조립하기 vs 전술로 좁혀가기

6장 마지막에서 `And'`(그리고)를 증명하려면 양쪽 증명을 담은 값을 직접 만들면 된다고 했습니다.

[source,lean]
----
theorem and_comm' (p q : Prop) (h : p ∧ q) : q ∧ p :=
  ⟨h.right, h.left⟩
----

`⟨h.right, h.left⟩`은 `And`(구조체) 값을 직접 조립한 것입니다 — `⟨...⟩`는 익명 생성자 문법으로, 지금 만들어야 할 타입이 무엇인지 Lean4가 이미 알고 있을 때 생성자 이름을 생략하고 재료만 나열해 값을 조립합니다.

명제가 단순할 땐 이렇게 손으로 조립하는 게 가장 빠릅니다. 하지만 질문이 생깁니다. *"왜 굳이 전술(Tactic)을 또 배워야 할까요?"* 두 가지 이유 때문입니다:

1. **사람 머리의 한계**: 식이나 명제가 조금만 복잡해져도 완성된 증명 값의 모양을 머릿속으로 통째로 그려내어 한 방에 적는 것이 불가능해집니다.
2. **대화형 작성과 자동화**: 전술을 쓰면 완성품을 던지는 대신, 오른쪽 InfoView 화면을 보며 Lean4와 대화하듯이 목표를 한 단계씩 더 쉬운 하위 목표로 좁혀갈 수 있습니다. 게다가 산술 계산처럼 복잡한 과정은 `omega` 같은 전술이 내부에서 대신 증명 값을 뚝딱 만들어 줍니다.

[source,lean]
----
theorem and_comm'' (p q : Prop) (h : p ∧ q) : q ∧ p := by
  constructor
  · exact h.right
  · exact h.left
----

`by`로 시작하면 전술 모드에 들어갑니다. `constructor`는 "목표가 `And`(그리고) 모양이니, 두 개의 하위 목표(`q`, `p`)로 쪼개라"는 뜻입니다. 각 하위 목표를 `exact`로 채우면 끝입니다. 결과물은 `and_comm'`과 똑같은 증명 값이지만, 쓰는 과정이 "이 목표를 어떻게 좁힐까"를 반복하는 대화형 작업이 됩니다.

== 자주 쓰는 전술 몇 가지

전술을 쓸 때 가장 중요한 요령은 **"전술 한 줄을 실행할 때마다 InfoView의 목표 창이 어떻게 바뀌는가"**를 지켜보는 것입니다. 가장 자주 쓰는 5가지 기본 전술을 봅시다.

=== 1. intro: 조건 받아오기

목표가 `p → q`("p이면 q이다") 모양일 때, `→` 왼쪽의 ``p``를 **가정 목록으로 들여오면서** 목표를 ``q``로 줄입니다.

[source,lean]
----
theorem imp_example (p q : Prop) : p → (q → p) := by
  intro hp   -- (hp : p) 가 가정 목록에 추가되고, 목표는 ⊢ q → p 로 줄어듦
  intro _hq  -- (_hq : q) 가 가정 목록에 추가되고, 목표는 ⊢ p 로 줄어듦
  exact hp   -- 가정에 있는 hp(p의 증명)로 목표 ⊢ p를 완료함
----

=== 2. apply: 역방향으로 목표 바꾸기

가정 ``h : A → B``가 있을 때 "목표 ``B``를 증명하려면, **대신 A만 증명하면 되겠네!**" 하고 목표를 ``A``로 바꿔 칩니다.

[source,lean]
----
theorem apply_example (n : Nat) (h : n > 0 → n ≠ 0) (hn : n > 0) : n ≠ 0 := by
  apply h   -- 목표인 ⊢ n ≠ 0 이 ⊢ n > 0 으로 바뀜
  exact hn  -- 이미 가진 가정 hn(n > 0)으로 목표를 바로 완료함
----

=== 3. rw (rewrite): 글자 바꿔치기

등식 가정(`h : a = b`)을 이용해 목표 안의 모든 ``a``를 ``b``로 **싹 바꿔치기**합니다.

[source,lean]
----
theorem rw_example (a b : Nat) (h : a = b) : a + 1 = b + 1 := by
  rw [h]   -- 목표 ⊢ a + 1 = b + 1 이 ⊢ b + 1 = b + 1 로 바뀌고 바로 증명 완료
----

``rw``는 대입 후 양변이 같아지면(`b + 1 = b + 1`) 증명을 자동으로 마쳐줍니다.

=== 4. simp: 당연한 식 자동 단순화

``n + 0 = n``처럼 당연히 성립하는 규칙들을 가져와 목표를 자동으로 단순하게 정리해 줍니다.

[source,lean]
----
theorem simp_example (n : Nat) : n + 0 = n := by
  simp     -- ⊢ n + 0 = n 식을 단순화하여 바로 증명 완료
----

=== 5. omega: 산술 문제 자동 해결 (치트키)

자연수와 정수의 덧셈, 뺄셈, 방정식(예: ``a + 2 * b = 7``이고 ``b = 2``이면 `a = 3`) 문제를 사람이 일일이 풀 필요 없이 **한 줄로 끝내주는 치트키**입니다.

[source,lean]
----
theorem omega_example (a b : Nat) (h1 : a + 2 * b = 7) (h2 : b = 2) : a = 3 := by
  omega    -- 복잡한 산술 추론을 한 줄로 자동 해결
----

다음 장의 귀납 증명에서도 마지막에 남는 산술 정리를 ``omega``에게 맡기게 됩니다.

=== 💡 한눈에 보는 종합 예제

위에서 배운 전술들이 실제 증명 하나에서 어떻게 유기적으로 연결되는지 종합 예제로 확인해 봅시다.

첫 번째는 `rw`(바꿔치기)를 연달아 쓰는 예제입니다. "가정 ``h1 : a = b``와 ``h2 : b = c``가 있을 때, ``a + 1 = c + 1``을 증명하라"는 문제입니다.

[source,lean]
----
theorem combined_demo (a b c : Nat) (h1 : a = b) (h2 : b = c) : a + 1 = c + 1 := by
  rw [h1]  -- 1단계: a를 b로 바꿔치기 (목표: ⊢ b + 1 = c + 1)
  rw [h2]  -- 2단계: b를 c로 바꿔치기 (목표: ⊢ c + 1 = c + 1 -> 자동으로 완료!)
----

두 번째는 ``intro``와 ``apply``가 함께 쓰이는 추론 예제입니다. +
*"비가 오면(`Rain`) 땅이 젖고(`Wet`), 땅이 젖으면 수풀이 자란다(`Grass`). 비가 오면 수풀이 자라는가?"*

[source,lean]
----
theorem rain_example (Rain Wet Grass : Prop)
    (h1 : Rain → Wet) (h2 : Wet → Grass) : Rain → Grass := by
  intro hRain   -- 1단계: "비가 온다"(hRain : Rain)를 가정으로 받아들임 (목표: ⊢ Grass)
  apply h2      -- 2단계: "Grass를 보이기 위해 대신 Wet을 증명하겠다" (목표: ⊢ Wet)
  apply h1      -- 3단계: "Wet을 보이기 위해 대신 Rain을 증명하겠다" (목표: ⊢ Rain)
  exact hRain   -- 4단계: 이미 가진 가정 hRain(비가 온다)으로 완결!
----

== 목표 상태 읽는 법

전술을 쓰는 동안 Lean4는 항상 "현재 증명해야 할 목표"를 보여줍니다. VS Code에서 커서를 전술 사이에 두면 이렇게 보입니다.

----
p q : Prop
h : p ∧ q
⊢ q ∧ p
----

`⊢` 위는 지금까지 얻은 가정들, `⊢` 아래는 지금 증명해야 할 목표입니다.

이 화면이 전술 한 줄에 어떻게 바뀌는지가 핵심입니다. 위 상태에서 `constructor`를 실행한 직후, InfoView는 이렇게 바뀝니다.

----
case left
p q : Prop
h : p ∧ q
⊢ q

case right
p q : Prop
h : p ∧ q
⊢ p
----

목표 하나(`q ∧ p`)가 두 개(`q`와 `p`)로 쪼개졌고 각각 `case left`/`case right`라는 이름이 붙었습니다 — `·`(불릿)이 하나씩 맡아 처리하는 게 바로 이 목표들입니다. 이렇게 전술 실행 전/후의 InfoView를 대조하며 지켜보는 게 전술 증명을 익히는 가장 빠른 방법입니다 — 눈으로 읽기보다 직접 VS Code에서 한 줄씩 눌러보길 권합니다.

그리고 목표를 다 닫지 못한 채 증명을 끝내면 이런 에러를 만납니다.

----
error: unsolved goals
case right
p q : Prop
h : p ∧ q
⊢ p
----

무섭게 생겼지만 내용은 InfoView 화면과 똑같습니다 — "아직 `case right`(`⊢ p`)가 안 닫혔다"는 안내일 뿐입니다. 남은 목표를 마저 증명하면 사라집니다.

== 이 장이 왜 중요한가

전술의 진짜 힘은 "반복되는 증명 패턴을 자동화할 수 있다"는 데 있습니다. `omega`는 선형 산술 문제를, `simp`은 단순화를, 뒤에서 볼 `induction`은 귀납 증명의 뼈대를 대신 짜줍니다. 이런 전술들 하나하나가 사실 Lean4로 짜인 평범한 프로그램입니다 — 3부에서 그 전술을 직접 만들어보면서 이 사실을 확인합니다.

다음 장에서는 "모든 자연수에 대해" 같은, 경우의 수가 무한한 명제를 어떻게 유한한 단계로 증명하는지 — 귀납법을 다룹니다.

TIP: 더 깊이 들어가려면 — 전술의 전체 목록과 조합 방법은 link:../../../programming/lean/theorem-proving-in-lean4/05-tactics/[Theorem Proving in Lean 4의 5장: 전술]에서 다룹니다.

== 직접 해보기

* `p → q → p ∧ q`를 전술로 증명해보세요. (`intro` 두 번 → `constructor` → 각 목표를 `exact`로.)
* `(h1 : a = b)`와 `(h2 : b = c)`가 가정으로 있을 때 `a = c`를 `rw`로 증명해보세요.
* `(h : 2 * n + 1 = 9)`에서 `n = 4`를 `omega`로 증명해보고, `omega`를 지우면 InfoView에 어떤 목표가 남는지도 확인해보세요.

.해답 보기
[%collapsible]
====
[source,lean]
----
theorem ex1 (p q : Prop) : p → q → p ∧ q := by
  intro hp
  intro hq
  constructor
  · exact hp
  · exact hq

theorem ex2 (a b c : Nat) (h1 : a = b) (h2 : b = c) : a = c := by
  rw [h1, h2]

theorem ex3 (n : Nat) (h : 2 * n + 1 = 9) : n = 4 := by
  omega
-- omega를 지우면 남는 목표:  h : 2 * n + 1 = 9  ⊢ n = 4
----
====

== 요약

* 전술(`by`로 시작)은 증명 값을 한 방에 조립하는 대신, 목표를 한 걸음씩 더 쉬운 목표로 좁혀가는 방식이다.
* `intro`(가정 받기), `apply`(정리를 역방향 적용), `rw`(등식으로 재작성), `simp`(자동 단순화), `omega`(선형 산술 자동 증명)가 자주 쓰는 전술이다.
* InfoView는 `⊢` 위에 가정을, 아래에 지금 증명해야 할 목표를 보여주며, 전술 한 줄마다 이 화면이 바뀐다.
* `unsolved goals` 에러는 InfoView에 남은 목표와 같은 내용을 알려주는 것뿐이다.
