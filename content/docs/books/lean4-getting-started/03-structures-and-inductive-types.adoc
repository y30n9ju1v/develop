== 여러 값을 하나로: structure

여러 값을 한 덩어리로 묶고 싶을 때가 있습니다. 점 하나는 x좌표와 y좌표 두 값으로 이뤄집니다.

[source,lean]
----
structure Point where
  x : Float
  y : Float

def origin : Point := { x := 0.0, y := 0.0 }
def p1 : Point := { x := 3.0, y := 4.0 }

#eval p1.x  -- 3.000000

def dist (a b : Point) : Float :=
  Float.sqrt ((a.x - b.x)^2 + (a.y - b.y)^2)

#eval dist origin p1  -- 5.000000
----

`structure`는 다른 언어의 튜플이나 레코드와 비슷합니다. 필드 이름으로 값을 꺼내 쓸 수 있다는 점이 튜플보다 편합니다(`p1.1` 대신 `p1.x`). 이 정도는 여러분이 이미 아는 언어에도 있을 개념입니다.

== 값이 여러 "모양" 중 하나일 때: inductive

`structure`는 필드를 전부 가진 값 하나만 표현합니다. 그런데 "이 값은 A이거나, 아니면 B다"처럼 서로 다른 모양 중 하나를 표현하고 싶을 때가 있습니다. 예를 들어 "빈 도형이거나, 반지름이 있는 원이거나, 밑변과 높이가 있는 직사각형"을 표현하려면 `structure`만으로는 부족합니다. 이럴 때 쓰는 게 `inductive`입니다.

[source,lean]
----
inductive Shape where
  | empty : Shape
  | circle (radius : Float) : Shape
  | rect (w h : Float) : Shape

def area : Shape → Float
  | .empty => 0.0
  | .circle r => 3.14159 * r * r
  | .rect w h => w * h

#eval area (.circle 2.0)  -- 12.566360
#eval area (.rect 3.0 4.0)  -- 12.000000
----

`Shape`의 값을 만드는 방법이 셋(`empty`, `circle`, `rect`)이라고 선언하면, Lean4는 "`Shape` 타입의 값은 반드시 이 세 가지 중 하나로 만들어졌다"는 걸 압니다. 그래서 2장에서 본 패턴 매칭이 `Shape`에도 그대로 적용됩니다 — 그리고 세 경우 중 하나라도 빠뜨리면 컴파일 에러가 납니다. 이건 사소한 편의 기능이 아닙니다 — "모든 경우를 빠짐없이 처리했다"는 걸 컴파일러가 대신 확인해준다는 뜻입니다.

== List와 Option도 사실 이렇게 만들어졌다

2장에서 `List`를 "빈 리스트거나 head::tail"이라고 설명했는데, 실제로 Lean4 표준 라이브러리의 `List` 정의도 여러분이 방금 만든 `Shape`와 똑같은 방식입니다(대략 이런 모양입니다).

[source,lean]
----
inductive MyList (α : Type) where
  | nil : MyList α
  | cons (head : α) (tail : MyList α) : MyList α
----

``nil``과 `cons`는 리스트를 만드는 두 가지 전통적인 생성자 이름입니다. `nil`은 빈 리스트(`[]`)를 뜻하고, `cons`(construct의 줄임말)는 기존 리스트 앞에 원소 하나를 덧붙이는 역할을 합니다 — 2장에서 본 `head :: tail` 표기법에서 `::` 연산자가 바로 이 `cons` 생성자를 보기 편하게 쓴 기호 표기입니다. 예를 들어 ``[1, 2]``는 실제 내부에서 ``MyList.cons 1 (MyList.cons 2 MyList.nil)``로 빚어진 값입니다.

`MyList α`처럼 타입 자체가 인자(`α`)를 받을 수 있다는 점도 새롭습니다 — `MyList Nat`, `MyList String`처럼 원소 타입이 다른 리스트를 전부 이 정의 하나로 만들어냅니다. 이런 "타입을 인자로 받는 타입"을 다음 장에서 다형성이라는 이름으로 정식으로 다룹니다.

값이 없을 수도 있다는 걸 표현하는 `Option`도 마찬가지입니다.

[source,lean]
----
inductive MyOption (α : Type) where
  | none : MyOption α
  | some (val : α) : MyOption α

def safeDiv (a b : Nat) : MyOption Nat :=
  if b == 0 then .none else .some (a / b)

#eval safeDiv 10 2  -- MyOption.some 5
#eval safeDiv 10 0  -- MyOption.none
----

``none``은 "비어있는 상자(실패/값 없음)", ``some val``은 "알맹이 값(`val`)이 담긴 상자(성공)"를 뜻합니다.

다른 언어의 ``null``이나 예외 대신 "값이 있을 수도, 없을 수도 있다"는 상황을 안전한 상자(타입) 그 자체로 표현한 것입니다. 이 값을 쓰는 쪽은 패턴 매칭으로 ``.none``과 ``.some`` 두 경우를 반드시 다 다뤄 상자를 열어봐야 하므로, "혹시 값이 없으면 어떡하지"를 깜빡하여 일어나는 버그(`null` 관련 오류)를 원천 차단해 줍니다.

== 이 장이 왜 중요한가

`Nat`, `List`, `Option`, `Bool` — Lean4의 거의 모든 기본 타입은 여러분이 이번 장에서 배운 `inductive` 하나로 정의되어 있습니다. 특별 취급을 받는 "내장 타입"이 따로 있는 게 아니라, 표준 라이브러리 제작자가 쓴 것과 똑같은 도구를 여러분도 그대로 씁니다. 그리고 2부에서 볼 "증명"이라는 것도 사실 이 `inductive` 타입의 값을 만들어내는 것과 다르지 않습니다 — 명제 하나가 `Shape`처럼 몇 가지 방식으로만 증명될 수 있는 타입이 되고, 증명을 쓴다는 건 그 타입의 값을 하나 만들어내는 일이 됩니다. 지금 당장 그 말이 다 이해될 필요는 없습니다 — 6장에서 이 연결고리를 정면으로 다룹니다.

다음 장에서는 `Shape`나 `MyList`처럼 서로 다른 타입에 공통된 동작(더하기, 비교하기, 출력하기)을 붙이는 법 — 다형성과 타입 클래스를 다룹니다.

TIP: 더 깊이 들어가려면 — 구조체·귀납적 타입·패턴 매칭의 더 풍부한 예제는 link:../../../programming/lean/functional-programming-in-lean/ch01/[Functional Programming in Lean Ch.1]을 보세요.

== 직접 해보기

* `Shape`에 밑변과 높이를 받는 `triangle` 생성자를 추가해보세요 — 단, `area`를 고치기 전에 먼저 컴파일해서, 빠뜨린 경우를 컴파일러가 어떻게 알려주는지 확인해보세요.
* 제목(`String`)과 쪽수(`Nat`)를 갖는 `structure Book`을 정의하고, 값을 하나 만들어 필드를 `#eval`로 꺼내보세요.
* `MyOption Nat` 값에서 값이 있으면 그 값을, 없으면 기본값을 돌려주는 `getOrElse : MyOption Nat → Nat → Nat`을 패턴 매칭으로 정의해보세요.

.해답 보기
[%collapsible]
====
[source,lean]
----
-- 1. triangle을 추가하고 area를 그대로 두면, 패턴 매칭에서 빠진 경우를
--    알려주는 컴파일 에러(missing cases)가 난다.
inductive Shape where
  | empty : Shape
  | circle (radius : Float) : Shape
  | rect (w h : Float) : Shape
  | triangle (base height : Float) : Shape

def area : Shape → Float
  | .empty => 0.0
  | .circle r => 3.14159 * r * r
  | .rect w h => w * h
  | .triangle b h => 0.5 * b * h

#eval area (.triangle 6.0 4.0)  -- 12.000000

structure Book where
  title : String
  pages : Nat

def myBook : Book := { title := "Lean4 입문", pages := 300 }
#eval myBook.pages  -- 300

def getOrElse : MyOption Nat → Nat → Nat
  | .none,   d => d
  | .some v, _ => v

#eval getOrElse (safeDiv 10 0) 99  -- 99
----
====

== 요약

* `structure`는 여러 값을 한 덩어리로 묶는다(모든 필드를 가진 값 하나).
* `inductive`는 값이 여러 "모양" 중 하나임을 표현한다 — 모든 경우를 패턴 매칭으로 빠짐없이 다뤄야 컴파일된다.
* `Nat`, `List`, `Option`, `Bool` 같은 Lean4의 기본 타입도 특별 취급 없이 전부 `inductive`로 정의되어 있다.
* 타입은 `MyList α`처럼 다른 타입을 인자로 받을 수 있다 — 다음 장의 다형성으로 이어지는 지점이다.
