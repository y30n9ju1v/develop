== 이 책이 하려는 것

이 사이트에는 이제 "안전한 병렬 처리를 위한 이론"이 여러 갈래로 흩어져 있습니다 — `category-theory-for-programmers`/`category-theory-made-simple`의 범주론, `linear-and-session-types`의 선형 타입과 세션 타입, `nand2npu-gpu`의 하드웨어 수준 조작적 의미론까지. 하지만 이 이론들은 전부 Lean4나 손으로 쓴 작은 언어 위에서 증명됐습니다 — 실무에서 매일 쓰는 언어에서는 이 이론들이 어떤 모습으로 나타날까요?

이 책은 그 질문에 **C++23**으로 답합니다. C++는 (Rust와 달리) 선형 타입도, 세션 타입도, 범주론적 인터페이스도 언어 코어에 내장하지 않습니다 — 하지만 `linear-and-session-types` 8장에서 이미 확인했듯, 이런 이론은 기존 타입 시스템 **안에 인코딩**할 수 있습니다. 이 책은 정확히 그 인코딩을 C++23으로 직접 짜고, 컴파일하고, 실행하고, 일부러 틀리게 짜서 컴파일이 정말로 실패하는지 확인합니다.

* **타입 상태 패턴(typestate pattern)** 으로 `linear-and-session-types` 5~7장의 세션 타입을 흉내냅니다 — "다음에 뭘 호출해야 하는가"를 객체의 **타입**으로 표현해서, 프로토콜을 어기는 호출 순서를 컴파일 에러로 만듭니다.
* **이동 전용 타입(move-only type)과 RAII** 로 2~4장의 선형 타입을 흉내냅니다 — 자원을 두 번 쓰면 컴파일이 안 되게 만듭니다.
* **concepts** 로 범주론적 인터페이스(Functor, Monad)를 표현하고, 그 인터페이스로 병렬 파이프라인을 안전하게 합성합니다.
* **`std::span` 분할** 로 동시성 분리 논리(Concurrent Separation Logic)를 흉내냅니다 — 겹치지 않는 메모리 영역만 각자 건드리게 만들어, 락 없이도 데이터 경쟁을 원천 봉쇄합니다.
* **join-semilattice concept** 으로 CRDT를 짜서, 지금까지와 정반대 전략(막는 대신 동기화 없이 갱신하고 나중에 합쳐도 항상 같은 값에 수렴하는 것)까지 대수적으로 확인합니다.

이 책의 모든 코드는 이 세션 환경에 실제로 설치된 Apple Clang 21(`-std=c++23`)로 컴파일하고 실행해서 검증했습니다 — 컴파일이 안 되는 걸 "노린" 예제는 실제로 컴파일러가 내는 에러 메시지를 그대로 인용합니다. 데이터 경쟁을 다루는 1장에서는 ThreadSanitizer(`-fsanitize=thread`)로 실제 경쟁을 검출한 리포트도 그대로 보여줍니다.

== 왜 "각 장에 C++17 대체법"인가

이 책이 쓰는 기능 상당수 — concepts, `std::jthread`와 `std::stop_token`, `std::atomic`의 `wait`/`notify`, 3-way 비교(`<=>`), `if consteval` — 는 C++20에서야 들어왔고, 몇몇(`std::generator`, `std::expected`, `std::mdspan`, `std::flat_map`)은 C++23에서야 들어왔습니다. 실무에서는 여전히 C++17(또는 그 이전) 컴파일러를 벗어날 수 없는 프로젝트가 많습니다 — 임베디드 툴체인, 오래된 빌드 시스템, 회사 정책 등 이유는 다양합니다. 그래서 이 책의 **각 장 끝에는 "C++17 환경이라면" 팁 박스**를 둡니다 — 그 장의 핵심 기법을 C++17만으로 어떻게 근사하는지(대개는 `enable_if`/SFINAE, 수동 스레드 관리, 컴파일러 매크로 기반 정적 단언 등으로), 그리고 그 근사가 정확히 무엇을 잃는지를 씁니다. C++23 코드와 마찬가지로, C++17 코드도 전부 실제로 컴파일해서 검증했습니다.

== 누구를 위한 책인가

이 책은 **독립적으로 완결된 책**입니다 — C++을 어느 정도 다뤄봤다면(포인터, 클래스, 템플릿의 기본을 안다면) `linear-and-session-types`나 범주론 책들을 먼저 안 읽어도 따라올 수 있습니다. 다만 각 장에서 "이 C++ 코드가 흉내 내는 이론"을 아주 짧게 요약만 하고 곧바로 C++ 코드로 넘어가므로, 그 이론의 배경이 더 궁금하다면 해당 장에서 링크하는 원전 책을 함께 보는 걸 권합니다.

== 읽는 순서

이 책은 6부 12개 장과 맺음말로 나뉩니다.

*1부(1~2장)* 는 동기를 다집니다 — 데이터 경쟁을 실제로 일으켜 ThreadSanitizer로 검출하고, C++의 보통 타입 시스템이 이런 버그를 왜 못 잡는지 확인합니다.

*2부(3~5장)* 는 타입 상태 패턴으로 세션 타입을 흉내냅니다 — 기초 패턴부터, 컴파일 타임 프로토콜 검사, 뮤텍스/채널에 실제로 적용하는 것까지 다룹니다.

*3부(6~8장)* 는 이동 전용 타입으로 선형 타입을 흉내냅니다 — `unique_ptr`과 RAII부터, 커스텀 이동 전용 핸들, 실전 자원 관리(락, 파일, 커넥션)까지 다룹니다.

*4부(9~10장)* 는 concepts로 범주론적 인터페이스를 짜고, 그걸로 병렬 파이프라인을 합성합니다.

*5부(11장)* 는 동시성 분리 논리를 `std::span` 분할로 인코딩해, 겹치지 않는 메모리만 각자 건드리면 동기화 없이도 안전하다는 걸 확인합니다.

*6부(12장)* 는 CRDT로 지금까지와 정반대 전략(막는 대신, 동기화 없이 갱신하고 나중에 합쳐도 대수적으로 항상 수렴하게 만드는 것)을 다룹니다.

*맺음말(13장)* 은 이 다섯 이론을 하나의 표로 정리하고, Rust가 그중 무엇을 언어 코어로 채용했는지, 이 책이 다루지 않은 것(C++26의 `std::execution`, 실전 락프리 자료구조 등)과 다음으로 어디를 볼지 안내합니다.

각 장은 이전 장의 코드를 당연하게 재사용합니다 — 순서대로 읽는 걸 권합니다.
