1~4부는 "값 하나"(3부) 또는 "채널 하나의 순서"(2부)를 안전하게 다뤘습니다. 이 장은 다른 종류의 안전성을 다룹니다 — **메모리 영역 하나를 여러 스레드에 나눠줄 때, 어떻게 하면 겹치지 않는다는 걸 보장할 수 있는가**입니다. 이건 맺음말에서 예고했던, 이 책이 원래 안 다루기로 했던 락프리 자료구조의 사촌 문제이지만, 락 없이 안전한 병렬 처리를 가능케 하는 훨씬 간단하고 흔한 패턴이라 여기서 짧게 다룹니다.

== 이론: 동시성 분리 논리의 핵심 발상

**동시성 분리 논리(Concurrent Separation Logic, CSL)** 는 "두 스레드가 각자 **겹치지 않는** 자원만 갖고 있다면, 그 둘을 동시에 실행해도 안전하다"는 걸 증명하는 형식 체계입니다(O'Hearn 2007). 핵심 연산자는 분리 논리곱(separating conjunction, `P * Q`) — "`P`와 `Q`가 각각 서로 다른(겹치지 않는) 메모리 영역에 대해 성립한다"는 뜻입니다. 스레드 하나가 `P`가 성립하는 영역만 건드리고 다른 스레드가 `Q`가 성립하는 영역만 건드린다면, 그 둘 사이엔 애초에 경쟁이 있을 수 없습니다 — 물리적으로 같은 바이트를 만질 방법이 없기 때문입니다.

이건 사실 `linear-and-session-types` 2장의 `Disjoint`를 그대로 다시 만난 것입니다. 그 책에서 `Disjoint (dom Γ1) (dom Γ2)`는 "함수 `f`와 인자 `a`가 서로 다른 **변수**만 쓴다"를 강제했습니다. CSL은 정확히 같은 발상을 "서로 다른 **스레드**가 서로 다른 **메모리 주소**만 건드린다"에 적용합니다 — 쪼개는 대상이 변수 컨텍스트에서 메모리 영역으로 바뀌었을 뿐, "겹치지 않으면 안전하다"는 원리는 동일합니다.

== `std::span`으로 겹치지 않게 쪼개기

[source,cpp]
----
template <typename T>
std::pair<std::span<T>, std::span<T>> split_at(std::span<T> s, std::size_t mid) {
  return {s.first(mid), s.subspan(mid)};
}
----

`s.first(mid)`는 `[0, mid)`, `s.subspan(mid)`는 `[mid, size)`를 가리키는 `span`을 돌려줍니다 — 이 둘은 **구조적으로** 겹칠 수 없습니다. `mid`가 무슨 값이든, 앞쪽은 항상 인덱스 `mid` 미만만, 뒤쪽은 항상 `mid` 이상만 가리키기 때문입니다.

[source,cpp]
----
void double_each(std::span<int> region) {
  for (int& x : region) x *= 2;
}

int main() {
  std::vector<int> data(1'000'000);
  for (int i = 0; i < (int)data.size(); i++) data[i] = i;

  auto [left, right] = split_at(std::span<int>(data), data.size() / 2);

  std::thread t1(double_each, left);
  std::thread t2(double_each, right);
  t1.join();
  t2.join();

  bool ok = true;
  for (int i = 0; i < (int)data.size(); i++) if (data[i] != i * 2) ok = false;
  std::cout << (ok ? "all correct, no race" : "WRONG RESULT") << "\n";
}
----

[source]
----
$ clang++ -std=c++23 -O0 -pthread -fsanitize=thread split_span.cpp -o split_span_tsan
$ ./split_span_tsan
all correct, no race
----

100만 개짜리 배열을 반으로 쪼개 두 스레드가 각자 자기 절반을 두 배로 만들었습니다 — ThreadSanitizer를 켜도 **아무 경고가 없습니다.** `left`와 `right`가 물리적으로 겹치지 않는 메모리를 가리키므로, 두 스레드는 동기화(뮤텍스, 원자 연산) 없이도 안전합니다 — CSL이 말하는 "겹치지 않으면 안전하다"를 도구로 직접 확인한 것입니다.

== 반증: `split_at`을 거치지 않고 손으로 겹치게 만들면

`split_at`이 주는 보장은 **그 함수를 통해서 쪼갤 때만** 유효합니다 — 아무도 강제하지 않으니, 손으로 겹치는 `span` 두 개를 만드는 것도 얼마든지 가능합니다.

[source,cpp]
----
void bump(std::span<int> region) {
  for (int rep = 0; rep < 200000; rep++)
    for (int& x : region) x++;
}

int main() {
  std::vector<int> shared(10, 0);
  std::span<int> left(shared.data(), 6);        // [0,6)
  std::span<int> right(shared.data() + 4, 6);   // [4,10) -- [4,6) 구간이 겹친다!

  std::thread t1(bump, left);
  std::thread t2(bump, right);
  t1.join();
  t2.join();
  std::cout << "done\n";
}
----

[source]
----
$ clang++ -std=c++23 -O0 -pthread -fsanitize=thread split_span_bad3.cpp -o split_span_bad3_tsan
$ ./split_span_bad3_tsan
==================
WARNING: ThreadSanitizer: data race (pid=39450)
  Write of size 4 at 0x00010b500880 by thread T2:
    #0 bump(std::__1::span<int, ...>) ...
  Previous write of size 4 at 0x00010b500880 by thread T1:
    #0 bump(std::__1::span<int, ...>) ...
  Location is heap block of size 40 at 0x00010b500870 allocated by main thread: ...
----

`[4,6)` 구간을 두 스레드가 동시에 20만 번씩 두들기니, TSan이 정확히 그 구간에서 경쟁을 잡아냅니다. (흥미로운 실전 팁 하나 — 처음엔 100만 개 배열에서 딱 한 번씩만 겹치는 2000개 원소를 건드리는 버전으로 시도했는데, 스레드가 워낙 빨리 지나가서 TSan이 실제 겹치는 순간을 못 잡은 적이 있었습니다. 결과값은 확실히 틀렸는데도(겹친 원소들이 두 번 곱해져서) 말이죠 — TSan은 **정적** 증명이 아니라 **그 실행에서 실제로 일어난** 접근만 잡는 동적 도구라서, 아주 짧게 스쳐 지나가는 겹침은 운 나쁘게 놓칠 수 있습니다. 그래서 이 예제는 같은 구간을 20만 번 반복해서 두들기도록 바꿔, 겹침이 반드시 실제로 동시에 일어나도록 만들었습니다 — 도구의 한계까지 정직하게 검증 과정에서 확인한 셈입니다.)

== 이게 정확히 무엇을 증명하고, 무엇을 증명 안 하는가

`split_at`은 CSL이 하는 일의 아주 작은 부분만 흉내 냅니다 — CSL은 임의로 복잡한 프로그램에 대해 "분리 논리곱으로 쪼갠 자원만 쓰면 항상 안전하다"는 걸 **증명 규칙**으로 제공하지만, 이 장의 `split_at`은 딱 "인덱스 하나로 앞뒤를 가르면 안 겹친다"는 **한 가지 패턴**만 구조적으로 보장합니다. 여러 조각으로 나누거나(3개 이상), 조건에 따라 다르게 나누거나, 겹치지 않는지 런타임에 계산해야 하는 경우(예: 인덱스가 아니라 조건으로 나누는 경우)까지 일반화하려면 훨씬 정교한 타입(또는 런타임 검사)이 필요합니다 — 이 책의 다른 모든 장이 그랬듯, 이것도 이론 전체가 아니라 그 이론이 실전에서 가장 자주 쓰이는 한 조각만 인코딩한 것입니다.

== 요약

* 동시성 분리 논리의 핵심 발상 — "겹치지 않는 메모리만 각자 건드리면 안전하다" — 이 `linear-and-session-types` 2장의 `Disjoint`(변수 컨텍스트를 쪼개는 것)와 근본적으로 같은 아이디어라는 걸 확인했습니다.
* `std::span`을 인덱스로 쪼개는 `split_at`으로 두 스레드에 겹치지 않는 절반씩 나눠주면 ThreadSanitizer가 아무 경고도 안 낸다는 것과, `split_at`을 거치지 않고 손으로 겹치는 `span`을 만들면 같은 도구가 실제 데이터 경쟁을 잡아낸다는 걸 실제로 확인했습니다.
* TSan이 "실제로 일어난 접근"만 잡는 동적 도구라 아주 짧게 스쳐 가는 겹침은 놓칠 수 있다는 것도, 처음 예제가 실제로 그렇게 실패하면서 배운 정직한 교훈으로 남겼습니다.
* `split_at`이 CSL 전체가 아니라 "인덱스로 앞뒤를 가른다"는 한 가지 패턴만 인코딩한다는 것도 짚었습니다.

다음 장에서는 지금까지와 정반대의 전략 — 동시 접근을 막는 대신, 동기화 없이 각자 갱신하게 두고 나중에 합칠 때 항상 같은 값에 수렴한다는 걸 대수로 보장하는 CRDT — 를 다룹니다.
