== 이 책이 하려는 것

react.dev(공식 React 문서)와 TypeScript Handbook은 둘 다 훌륭합니다 — 정확하고, 최신이고, 무료입니다. 그런데 둘 다 **레퍼런스**로 설계됐습니다. "이 기능이 어떻게 동작하는가"에는 잘 답하지만, "왜 이 기능이 이렇게 생겨야만 했는가"는 각 페이지 사이사이에 흩어져 있거나 아예 생략되어 있습니다. `useEffect`의 의존성 배열이 왜 그런 규칙을 갖는지, 왜 리스트에 `key`가 필요한지, 왜 인터페이스와 타입 별칭이 둘 다 존재하는지 — 이런 질문들은 두 문서를 각각 처음부터 끝까지 읽어도 자연스럽게 이어지지 않습니다.

이 책은 그 둘을 하나의 재료로 삼아, **"왜"라는 질문을 축으로 처음부터 다시 엮은 입문서**입니다. TypeScript부터(1부) React로(2부), 그리고 그 둘을 실제로 합치는 데까지(3부) 순서대로 쌓아 올립니다.

이 책의 코드 예제는 전부 이 책을 위해 새로 짠 것이며, 원본 문서의 예제를 그대로 옮기지 않습니다. 모든 예제는 실제로 TypeScript 컴파일러로 타입 검사를 통과한 것만 싣습니다.

== 누구를 위한 책인가

프로그래밍을 조금이라도 해본 적이 있다면(어떤 언어든 상관없습니다) 충분합니다. JavaScript를 반드시 먼저 알아야 하는 건 아닙니다 — 다만 변수, 함수, 조건문, 반복문 같은 가장 기본적인 개념은 안다고 전제합니다. 화살표 함수나 구조 분해 할당처럼 JavaScript 고유의 문법은 바로 아래 절("시작하기 전에")에서 따로 짚어주니, 몰라도 괜찮습니다. React나 타입 시스템을 처음 접해도 상관없습니다 — 오히려 이 책의 목적이 그 배경지식 없이도 "이게 왜 필요한지"부터 이해시키는 것입니다.

== 시작하기 전에: 이 책이 당연하게 쓰는 JavaScript 문법

이 책은 변수·함수·조건문·반복문 이상의 JavaScript 문법을 설명 없이 바로 씁니다. 아래 여섯 가지는 1부부터 계속 등장하는데, 처음 보는 것이어도 걱정할 필요는 없습니다 — 각각 한 줄씩만 기억해두면 충분합니다. (반대로 이미 익숙하다면 이 절은 건너뛰어도 됩니다.)

[source,js]
----
// 1. 화살표 함수 — function(x) { return x * 2; } 를 짧게 쓰는 방법
const double = (x) => x * 2;

// 2. 구조 분해 할당 — 객체/배열에서 값을 꺼내 바로 변수로 만들기
const user = { name: "Ada", age: 30 };
const { name, age } = user; // name = "Ada", age = 30

// 3. spread 연산자(...) — 객체/배열을 "펼쳐서" 복사하거나 합치기
const updated = { ...user, age: 31 }; // user는 그대로, age만 바뀐 새 객체

// 4. 배열 메서드 map — 배열의 각 원소를 변환해 새 배열 만들기(반복문 대신)
const doubled = [1, 2, 3].map((n) => n * 2); // [2, 4, 6]

// 5. Promise와 async/await — 시간이 걸리는 작업(네트워크 요청 등)을 다루는 방법
async function loadData() {
  const response = await fetch("/api/data"); // 응답이 올 때까지 여기서 기다림
  return response.json();
}

// 6. 모듈 import/export — 파일 간에 코드를 나눠 쓰고 불러오기
export function greet() { /* ... */ }
// 다른 파일에서: import { greet } from "./greet";
----

`{ name, age }`처럼 중괄호로 감싸 꺼내는 게 구조 분해, `{ ...user, age: 31 }`처럼 점 세 개로 펼치는 게 spread입니다 — 이 두 문법은 특히 7장(Props)과 14장(폼)에서 계속 등장하므로, 낯설다면 이 예제로 돌아와 확인하길 권합니다.

== 시작하기: 5분이면 충분합니다

[source,bash]
----
mkdir my-ts-react-app && cd my-ts-react-app
npm create vite@latest . -- --template react-ts
npm install
npm run dev
----

`npm create vite@latest`가 TypeScript + React가 이미 연결된 최소 프로젝트를 만들어줍니다 — 이 책 전체에서 별도 언급 없이 이 환경을 전제합니다. `vite@latest`는 빌드 도구 Vite를 스캐폴딩하는 `create-vite` 패키지의 최신 버전을 뜻하고, `-- --template react-ts`는 그 패키지에게 "React + TypeScript 템플릿을 쓰라"고 전달하는 옵션입니다.

=== React가 뭔가요

**React**는 Meta(옛 Facebook)가 만들고 지금은 커뮤니티가 함께 관리하는, **사용자 인터페이스(UI)를 만들기 위한 JavaScript 라이브러리**입니다. "프레임워크"가 아니라 "라이브러리"라고 부르는 이유는, React가 라우팅·서버 통신·상태 관리 같은 걸 전부 강제하지 않고 딱 "화면을 어떻게 그릴 것인가"에만 집중하기 때문입니다(나머지는 필요할 때 다른 라이브러리를 골라 붙입니다).

React 이전의 전통적인 방식은 "무엇이 바뀌었을 때 어떤 DOM 노드를 어떻게 조작할지"를 직접 명령형으로 적는 것이었습니다(`document.getElementById(...)`로 노드를 찾아 `.textContent`를 바꾸는 식). React는 이 방식 대신 **"지금 데이터가 이렇다면 화면은 이런 모양이어야 한다"를 선언**하게 하고, "그 모양을 실제로 어떻게 만들지"는 React 내부(9장에서 다룰 재조정)에 맡깁니다 — 이런 방식을 **선언형(declarative)** UI라고 부르고, 이 책 2부 전체가 이 선언형 모델이 왜 이렇게 설계됐는지를 다룹니다. React는 웹(react-dom)뿐 아니라 모바일(React Native) 등 다른 렌더링 대상에도 같은 컴포넌트 모델을 적용할 수 있게 설계돼 있습니다 — 이 책은 그중 웹 브라우저 대상만 다룹니다.

=== Vite가 뭔가요

**Vite**(프랑스어로 "빠르다"는 뜻, 발음은 "비트"에 가깝습니다)는 프론트엔드 프로젝트를 위한 **빌드 도구**입니다. 우리가 짜는 TSX/JSX 코드는 브라우저가 원래 이해하는 문법이 아니고(6장에서 직접 확인합니다), 여러 파일로 나뉜 소스도 배포할 땐 최적화된 형태로 묶여야 합니다 — 이런 "코드를 브라우저가 실행 가능한 형태로 바꿔주는 일" 전반을 빌드 도구가 담당합니다. Vite는 구체적으로 세 가지 역할을 합니다.

* *개발 서버*: `npm run dev`로 실행하면, 코드를 저장할 때마다 페이지 전체를 새로고침하지 않고 바뀐 부분만 거의 즉시 브라우저에 반영합니다(이걸 HMR, Hot Module Replacement라고 부릅니다) — 브라우저가 요청하는 모듈만 그때그때 변환해서 내려주는 방식이라 프로젝트가 커져도 개발 서버 시작이 느려지지 않습니다.
* *번들러*: 배포할 때(`npm run build`)는 여러 파일로 흩어진 소스를 최적화된 소수의 파일로 묶어 압축합니다.
* *변환기*: 06장에서 확인할 것처럼, TSX/JSX 문법을 브라우저가 이해하는 평범한 JS 함수 호출로 변환하는 역할(내부적으로 esbuild를 씀)도 Vite가 담당합니다.

예전에는 Create React App(CRA)이 이 역할을 하는 표준 도구였는데, 개발 서버 시작 속도가 느리고 유지보수가 사실상 멈추면서, 지금은 React 프로젝트를 새로 시작할 때 가장 널리 쓰이는 도구가 Vite입니다. Vite 자체는 React 전용이 아니라 Vue·Svelte 등 다른 프레임워크에서도 똑같이 쓰입니다 — "React를 어떻게 화면에 그릴지"는 React의 역할이고, "그 코드를 어떻게 실행 가능한 형태로 만들지"는 Vite의 역할이라고 나눠 생각하면 됩니다.

=== 나머지 도구들

1부(TypeScript)의 예제는 `.ts` 파일 하나만 있어도 되고, `npx tsc --noEmit 파일명.ts`로 타입 검사만 해볼 수도 있습니다. `tsc`는 TypeScript 컴파일러 CLI이고, `npx`는 전역 설치 없이 그 자리에서 실행해주는 npm의 실행기입니다 — `--noEmit`은 "결과 JS 파일은 만들지 말고 타입 오류만 검사하라"는 옵션입니다. 이 책의 모든 코드는 TypeScript 컴파일러로 실제 검사를 거쳤습니다.

== 읽는 순서

이 책은 3부 14개 장과 맺음말로 나뉩니다.

*1부(1~5장)* 는 React 이야기를 전혀 하지 않습니다. TypeScript를 순수하게 "JavaScript 위에 얹는 타입 시스템"으로만 놓고, 값과 타입, 타입 추론, 인터페이스, 제네릭, 유니온까지 다룹니다. 이 부분을 제대로 소화해야 2부에서 "Props 타입은 왜 이렇게 쓰는가" 같은 질문이 자연스럽게 풀립니다.

*2부(6~12장)* 에서 React의 핵심 — 컴포넌트, Props, State, 렌더링, `useEffect`, 리스트와 key, 커스텀 훅 — 을 다룹니다. 이 부는 아직 TypeScript를 적극적으로 쓰지 않고, React 자체의 동작 원리에 집중합니다.

*3부(13~14장)* 는 1부와 2부를 실제로 합칩니다 — 컴포넌트에 타입을 제대로 입히고, API 호출과 폼을 다루는 실전 패턴을 씁니다.

*맺음말(15장)* 은 여기서 더 나아가고 싶을 때 어디로 가면 되는지, 그리고 이 책 다음이 실제 프로젝트(Refine.dev 기반 어드민 대시보드)로 어떻게 이어지는지 안내합니다.

각 장은 되도록 독립적으로 읽을 수 있게 썼지만, 순서대로 읽는 걸 권합니다 — 이 책의 각 장은 앞 장에서 이미 등장한 개념을 당연하게 재사용합니다.
