== 원칙: 값이 있으면 추론되고, 없으면 추론 못 한다

1장에서 `let count = 5`만 써도 `count`가 `number`로 추론된다는 걸 봤습니다. 이게 되는 이유는 단순합니다 — **오른쪽에 이미 구체적인 값(`5`)이 있기 때문**입니다. TypeScript는 그 값을 보고 타입을 거꾸로 알아냅니다. 그럼 오른쪽에 아무 값이 없는 경우는 어떨까요.

[source,ts]
----
function greet(name) {
  return "Hello, " + name;
}
----

`name`에는 대입된 값이 없습니다 — 함수가 호출될 때마다 다른 값이 들어올 자리이기 때문입니다. TypeScript 입장에서는 이 매개변수가 문자열인지 숫자인지 추측할 근거가 전혀 없습니다. 그래서 `strict` 모드에서는 이 코드가 에러가 됩니다(`암시적으로 any 형식을 가집니다`) — **함수 매개변수는 추론할 값이 없으므로 항상 명시적으로 타입을 적어야 한다**는 게 이 장의 첫 번째 규칙입니다.

[source,ts]
----
function greet(name: string) {
  return "Hello, " + name;
}

console.log(greet("Ada"));
----

== 반환 타입은 대부분 생략해도 된다

매개변수와 달리, 함수의 반환 타입은 대부분 추론에 맡겨도 됩니다 — 함수 본문이 이미 있으니, TypeScript가 그 본문을 실행해보지 않고도(정적으로) "이 함수가 결국 무엇을 반환하는지" 계산할 수 있기 때문입니다.

[source,ts]
----
function greet(name: string) {   // 반환 타입 생략 — string으로 자동 추론됨
  return "Hello, " + name;
}

const message: string = greet("Ada"); // greet의 반환값이 string으로 추론되므로 문제 없음
console.log(message);
----

그런데도 반환 타입을 일부러 적어두는 경우가 있습니다 — **본문을 고치다가 실수로 반환값의 종류가 바뀌는 걸 막고 싶을 때**입니다.

[source,ts]
----
function getUserId(): number {
  return "42"; // 컴파일 에러: string 형식은 number 형식에 할당할 수 없습니다.
}
----

반환 타입을 명시해뒀기 때문에, 본문에서 실수로 문자열을 반환하면 그 실수가 함수를 호출하는 쪽이 아니라 **함수를 정의하는 바로 그 자리**에서 잡힙니다. 함수가 여러 곳에서 호출되는 라이브러리성 코드일수록, 이렇게 정의 지점에서 에러를 잡는 게 값어치가 커집니다.

== 빈 배열과 빈 객체: 추론이 힘을 못 쓰는 지점

[source,ts]
----
let scores = []; // 이 시점엔 무엇이 들어갈지 전혀 알 수 없음
scores.push(90);
scores.push("A"); // strict 모드에서도 이건 통과됨 — scores가 any[]로 추론됐기 때문
----

`let scores = []`처럼 빈 배열로 시작하면, TypeScript는 "이 배열에 나중에 뭐가 들어올지" 알 방법이 없어 잠정적으로 `any[]`(아무거나 담을 수 있는 배열)로 취급합니다. 이건 1장에서 봤던 "타입을 안 적으면 에러"와는 다른, **더 조용한 위험**입니다 — 에러가 안 나니 놓치기 쉽습니다. 해결책은 애초에 무엇이 들어갈 배열인지 명시하는 것입니다.

[source,ts]
----
let scores: number[] = [];
scores.push(90);
scores.push("A"); // 컴파일 에러: string 형식의 인수는 number 형식의 매개변수에 할당될 수 없습니다.
----

== 맥락적 타이핑: 추론이 "주변 맥락"까지 본다

지금까지는 "오른쪽 값 하나만 보고 추론한다"고 했는데, TypeScript는 종종 그보다 더 똑똑합니다 — 콜백 함수의 매개변수는 그 콜백이 어디에 쓰이는지(맥락)를 보고 타입을 추론해줍니다.

[source,ts]
----
const numbers: number[] = [1, 2, 3];

const doubled = numbers.map(function (n) {
  return n * 2; // n에 타입을 안 적었는데도 에러가 안 남 — n이 number로 자동 추론됨
});

console.log(doubled);
----

`n`에 타입을 안 적었지만 에러가 나지 않습니다 — `numbers`가 `number[]`라는 걸 이미 알고 있으므로, `.map()`에 넘기는 콜백의 매개변수도 당연히 `number`일 수밖에 없다는 걸 TypeScript가 그 맥락에서 알아냅니다. 이걸 **맥락적 타이핑(contextual typing)**이라고 부릅니다 — 앞서 "매개변수는 항상 명시해야 한다"고 했던 규칙의 예외처럼 보이지만, 사실은 "추론할 근거가 있으면 생략 가능하다"는 원래 원칙이 콜백에도 똑같이 적용된 것뿐입니다.

== 정리: 언제 적고 언제 생략하는가

[cols="1,2"]
|===
|상황 |명시 여부

|함수 매개변수
|**항상 명시** — 추론할 값이 없음

|함수 반환 타입
|생략 가능(추론됨), 다만 정의 지점에서 실수를 잡고 싶으면 명시

|`let`/`const`로 즉시 값을 대입하는 변수
|생략 가능 — 오른쪽 값에서 추론됨

|빈 배열/빈 객체로 시작하는 변수
|**명시 권장** — 나중에야 채워질 내용까지 추론할 근거가 없음

|콜백 함수의 매개변수
|생략 가능 — 맥락(예: 배열의 원소 타입)에서 추론됨
|===

== 직접 해보기

* 매개변수 타입을 생략한 함수 `square(x)`를 작성하고, `strict` 모드에서 어떤 에러가 나는지 확인해보세요.
* `let ids = []`로 시작해 숫자 여러 개를 `push`한 뒤, 실수로 문자열도 하나 `push`해보고 에러가 안 나는지 확인해보세요. 그다음 `let ids: number[] = []`로 고쳐서 같은 실수가 이번엔 에러로 잡히는지 확인해보세요.

.해답 보기
[%collapsible]
====
[source,ts]
----
function square(x: number) { // x를 생략하면 TS7006: 암시적으로 any 형식을 가집니다
  return x * x;
}

let untypedIds = [];
untypedIds.push(1);
untypedIds.push("2"); // any[]라 에러 없이 통과됨

let typedIds: number[] = [];
typedIds.push(1);
// typedIds.push("2"); // 이제는 컴파일 에러

console.log(square(3), untypedIds, typedIds);
----
====

== 요약

* TypeScript는 오른쪽에 구체적인 값이 있을 때만 타입을 추론할 수 있습니다 — 함수 매개변수처럼 추론할 값이 없는 자리는 항상 명시해야 합니다.
* 함수의 반환 타입은 대부분 생략해도 되지만, 정의 지점에서 실수를 잡고 싶을 때는 명시하는 게 값어치가 있습니다.
* 빈 배열/빈 객체로 시작하는 변수는 `any`로 추론될 위험이 있어, 명시적으로 타입을 적어두는 걸 권장합니다.
* 콜백 함수의 매개변수처럼, 값이 아니라 "맥락"에서 타입을 추론하는 경우(맥락적 타이핑)도 있습니다.

다음 장에서는 이렇게 명시한 타입을 여러 곳에서 재사용할 수 있게 이름 붙이는 두 가지 방법 — 인터페이스와 타입 별칭 — 을 다룹니다.
