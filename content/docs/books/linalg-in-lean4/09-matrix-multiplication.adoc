8장에서 행렬을 "벡터를 옮기는 함수"로 봤다면, 자연스러운 다음 질문은 "그런 함수 두 개를 이어붙이면 어떻게 되는가"입니다. 이 장에서 정의하는 행렬 곱셈이 그 답이고, 여기서 완전히 증명하는 결합법칙 `(AB)C = A(BC)`는 이 책에서 가장 실용적으로 재사용되는 정리 중 하나입니다 — 11장의 "왼쪽 역 = 오른쪽 역" 증명이 새로운 계산 없이 이 결합법칙 하나만으로 끝나고, 14장의 대각화(`Aᵏ = PDᵏP⁻¹`)와 15장의 QR 알고리즘(`Aₖ₊₁ = RₖQₖ = Qₖᵀ Aₖ Qₖ`)에서도 여러 행렬을 한 줄에 늘어놓고 괄호를 자유롭게 묶고 푸는 계산의 근거가 됩니다. 반대로 교환법칙이 성립하지 않는다는 것도 단순한 주의사항이 아니라, 15장에서 닮음변환 `B = P⁻¹AP`를 다룰 때 `P⁻¹`과 `P`의 순서를 함부로 바꿀 수 없다는 실질적 제약으로 이어집니다. 교환법칙이 성립하지 않는다는 걸 구체적 반례로 확인해두는 것도, 뒤에서 무심코 `AB`와 `BA`를 같다고 착각해 잘못된 계산으로 넘어가는 실수를 막기 위해서입니다.

== 행렬 곱셈: 선형함수를 이어붙이기

8장에서 행렬을 "벡터를 다른 벡터로 옮기는 규칙(선형함수)"으로 봤습니다. 두 선형함수를 이어붙이면 어떻게 될까요 — `m×n` 행렬 `A`와 `n×p` 행렬 `B`가 있을 때, `B`로 `p`차원 벡터를 `n`차원으로 옮기고 그 결과에 `A`를 적용해 `m`차원으로 옮기는 것을 하나의 연산으로 표현하고 싶습니다. 이게 행렬 곱셈 `AB`입니다 — 결과는 `m×p` 행렬이고, `(AB)`의 `(i, k)` 성분은 `A`의 `i`번째 행과 `B`의 `k`번째 열의 내적입니다.

[source,lean]
----
-- Matrices/Multiplication.lean
import Matrices.MatVecProduct

namespace LinAlg

def Mat.mul {m n p : ℕ} (A : Mat m n) (B : Mat n p) : Mat m p :=
  fun i k => ∑ j, A i j * B j k

instance {m n p : ℕ} : HMul (Mat m n) (Mat n p) (Mat m p) := ⟨Mat.mul⟩

end LinAlg
----

로봇 예제를 다시 확장하면, `A`가 "구간별 예상 시간(분/km)"이고 `B`가 "여러 경로 후보 각각의 구간별 거리"를 담은 행렬이라면, `A * B`는 각 경로 후보의 예상 총 소요 시간을 한 번에 계산하는 행렬이 됩니다 — 8장의 행렬-벡터 곱을 "벡터 하나"가 아니라 "여러 벡터(경로 후보들)를 열로 모은 행렬"에 한꺼번에 적용한 것과 같습니다.

== 결합법칙: 이 장의 핵심 정리

행렬 곱셈에서 가장 중요하게 확인해야 할 성질은 결합법칙입니다 — `(AB)C = A(BC)`. 이게 성립해야 "여러 선형함수를 순서대로 이어붙인다"는 것이 괄호 위치와 무관하게 잘 정의된 하나의 개념이 됩니다.

=== 완전히 증명하는 것: 행렬 곱셈의 결합법칙

[source,lean]
----
namespace LinAlg

theorem Mat.mul_assoc {m n p q : ℕ} (A : Mat m n) (B : Mat n p) (C : Mat p q) :
    (A * B) * C = A * (B * C) := by
  funext i l
  show ∑ k, (∑ j, A i j * B j k) * C k l = ∑ j, A i j * (∑ k, B j k * C k l)
  simp only [Finset.sum_mul, Finset.mul_sum]
  rw [Finset.sum_comm]
  congr 1
  funext j
  congr 1
  funext k
  ring

end LinAlg
----

이 증명이 지금까지 이 책에서 나온 것 중 가장 흥미로운 지점은, 좌변과 우변이 **이중 합**이라는 것입니다. 좌변(`(AB)C`)은 "먼저 `j`에 대해 합해서 `AB`를 만들고, 그 결과를 `k`에 대해 합한다"는 순서이고, 우변(`A(BC)`)은 "먼저 `k`에 대해 합해서 `BC`를 만들고, 그 결과를 `j`에 대해 합한다"는 순서입니다. `Finset.sum_mul`/`Finset.mul_sum`으로 두 이중 합을 각각 "$\sum_j \sum_k$" 형태로 풀어헤치면, 남는 문제는 **합의 순서를 바꿔도 결과가 같다**는 것뿐입니다(`Finset.sum_comm`) — 각 항 `A i j * B j k * C k l`이 어느 순서로 더해지든 결국 실수의 곱셈 결합·교환법칙(`ring`)으로 같은 값이 나오기 때문입니다.

이 증명이 보여주는 건, "행렬 곱셈의 결합법칙"이라는 다소 무거워 보이는 정리가 실제로는 **"유한한 이중 합에서는 더하는 순서를 바꿔도 결과가 같다"는 훨씬 단순한 사실 하나**로 환원된다는 것입니다. 이게 이 책 전체에서 반복해서 확인하는 패턴 — 선형대수의 정리가 결국 실수(또는 합)의 기본 성질로 환원된다는 것 — 의 가장 인상적인 사례입니다.

== 왜 교환법칙은 성립하지 않는가

`AB = BA`는 일반적으로 성립하지 않습니다. 가장 근본적인 이유는 **차원이 안 맞을 수도 있다**는 것입니다 — `A`가 `2×3` 행렬이고 `B`가 `3×4` 행렬이면 `AB`는 계산되지만(`2×4` 결과), `BA`는 애초에 정의되지 않습니다(`B`의 열 개수 4가 `A`의 행 개수 2와 다르므로). 하지만 차원이 맞는 정사각행렬끼리도 교환법칙은 여전히 성립하지 않습니다 — 이건 증명할 정리가 아니라, 반례 하나로 "일반적으로는 성립하지 않는다"는 것만 보이면 충분합니다.

[source,lean]
----
namespace LinAlg

def exampleA : Mat 2 2 := fun i j =>
  match i, j with
  | 0, 0 => 1 | 0, 1 => 1
  | 1, 0 => 0 | 1, 1 => 1

def exampleB : Mat 2 2 := fun i j =>
  match i, j with
  | 0, 0 => 1 | 0, 1 => 0
  | 1, 0 => 1 | 1, 1 => 1

example : exampleA * exampleB ≠ exampleB * exampleA := by
  intro h
  have h00 := congrFun (congrFun h 0) 0
  have lhs : (exampleA * exampleB) 0 0 = 2 := by
    show ∑ j, exampleA 0 j * exampleB j 0 = 2
    simp [exampleA, exampleB, Fin.sum_univ_two]
    norm_num
  have rhs : (exampleB * exampleA) 0 0 = 1 := by
    show ∑ j, exampleB 0 j * exampleA j 0 = 1
    simp [exampleA, exampleB, Fin.sum_univ_two]
  rw [lhs, rhs] at h00
  norm_num at h00

end LinAlg
----

이 반례가 왜 교환법칙 실패를 "증명"하는지 짚어볼 만합니다 — `exampleA * exampleB`와 `exampleB * exampleA`의 `(0,0)` 성분을 직접 계산하면 서로 다른 값이 나옵니다(전자는 `1*1+1*1=2`, 후자는 `1*1+0*0=1`). `congrFun`을 두 번 적용해 "두 행렬이 같다면 모든 성분이 같아야 한다"는 것에서 `(0,0)` 성분이 같다는 명제를 끌어낸 뒤, `simp`로 양쪽을 실제 숫자로 계산해서 모순을 보입니다. 결합법칙이 "모든 `m,n,p,q`와 모든 행렬에 대해" 성립하는 보편 정리였다면, 교환법칙의 실패는 "성립하지 않는 구체적인 경우가 존재한다"는, 정반대 형태의 명제라는 것도 짚어둘 만합니다 — 보편 명제를 반박하려면 반례 하나로 충분하지만, 증명하려면 모든 경우를 다 봐야 합니다.

== 이 장에서 확정한 것

* 행렬 곱셈을 "행과 열의 내적"으로 정의하고, 이게 선형함수를 이어붙이는 연산에 대응한다는 것을 확인했습니다.
* 결합법칙을 완전히 증명했고, 그 증명이 본질적으로 "이중 합의 순서를 바꿀 수 있다"는 사실 하나로 환원된다는 것을 확인했습니다.
* 교환법칙은 일반적으로 성립하지 않는다는 것을, 2×2 구체적인 반례로 확인했습니다 — 보편 명제의 증명과 반박이 서로 다른 형태의 작업이라는 것도 짚었습니다.
