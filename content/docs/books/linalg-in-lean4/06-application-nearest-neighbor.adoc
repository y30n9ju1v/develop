1부 전체(1~5장)에서 벡터, 내적, 노름, 코시-슈바르츠, 직교성, 선형독립을 쌓았습니다. 이 마지막 장은 그 도구들을 실제 문제에 적용합니다 — 여러 개의 "후보" 벡터 중, 주어진 "질의" 벡터와 가장 가까운 것을 찾는 최근접 이웃 탐색입니다.

== 문제 설정: 여러 후보 중 가장 가까운 것

로봇이 여러 개의 landmark(기준점) 위치를 벡터로 갖고 있고, 자신의 현재 위치도 벡터로 알고 있다고 합시다. "지금 가장 가까운 landmark가 무엇인가"라는 질문은 정확히 최근접 이웃 탐색입니다 — landmark 벡터들 중, 현재 위치 벡터와의 거리(노름)가 최소인 것을 찾는 문제입니다.

거리는 두 벡터의 차의 노름으로 정의합니다 — `dist(u, v) = ‖u - v‖`.

[source,lean]
----
-- Vectors/NearestNeighbor.lean
import Vectors.Independence

namespace LinAlg.Vec

def dist {n : ℕ} (u v : Vec n) : ℝ := ‖u - v‖

end LinAlg.Vec
----

== 최근접 이웃 찾기: k개 후보 중 최솟값

`k`개의 후보 벡터(`candidates : Fin k → Vec n`)와 질의 벡터(`query`)가 주어졌을 때, 거리가 가장 작은 후보의 인덱스를 찾습니다. `k`가 0보다 클 때만 의미가 있으므로(후보가 하나도 없으면 "가장 가까운 것"이 정의되지 않습니다), `k = m + 1` 형태로 표현해 최소 하나의 후보가 있음을 타입에서 보장합니다.

[source,lean]
----
namespace LinAlg.Vec

/-- Fin (m+1) 위에서 f의 값이 최소가 되는 인덱스. m+1개 후보 중 첫 번째부터
    순회하며 지금까지의 최솟값을 갱신하는 방식으로 구현합니다. -/
def argmin {m : ℕ} (f : Fin (m + 1) → ℝ) : Fin (m + 1) :=
  (List.finRange (m + 1)).tail.foldl
    (fun best i => if f i < f best then i else best)
    ⟨0, Nat.zero_lt_succ m⟩

def nearestNeighbor {n m : ℕ} (candidates : Fin (m + 1) → Vec n) (query : Vec n) : Fin (m + 1) :=
  argmin (fun i => dist (candidates i) query)

end LinAlg.Vec
----

`argmin`은 인덱스 0을 "지금까지의 최선"으로 시작해, 나머지 인덱스를 하나씩 훑으며 더 작은 값을 발견할 때마다 갱신하는 표준적인 방식입니다.

== 정확성 증명: argmin이 실제로 최솟값을 찾는다는 것

`argmin`을 구현했다고 해서 그게 "진짜로 최솟값을 찾는다"는 게 자동으로 보장되지는 않습니다 — 구현이 틀렸다면(예를 들어 부등호 방향을 반대로 짰다면) 최댓값을 찾는 함수가 되어버릴 수도 있습니다. 이 장의 핵심 정리는 `argmin`이 반환한 인덱스의 함수값이, 다른 모든 인덱스의 함수값보다 크지 않다는 것을 증명하는 것입니다.

=== 증명을 세 조각으로 나누기

`argmin`의 정확성을 한 번에 증명하려고 하면 막막합니다. 먼저 이 증명이 실제로 어떤 사실들의 조합인지 말로 풀어보면 세 조각으로 나뉩니다.

1. **`foldl`은 최종 결과가 시작값보다 나쁠 수 없다.** `foldl`은 `best`(지금까지의 최선)를 들고 리스트를 순회하면서, 새 원소가 더 작을 때만 `best`를 갱신합니다 — 즉 `best`의 값은 순회하는 동안 절대 커지지 않습니다. 그러니 순회가 끝난 최종 결과는 시작값보다 작거나 같습니다. 이건 리스트가 비어있든 아니든 항상 성립하는, 가장 기초적인 사실입니다.
2. **`foldl`은 순회한 원소들 중 어떤 것보다도 나쁠 수 없다.** 리스트의 각 원소 `j`에 대해, `foldl`이 `j`를 지나칠 때 `f j < f best`이면 `best`가 `j`로 갱신되고, 그렇지 않으면 이미 `best ≤ j`인 상태가 유지됩니다. 두 경우 모두 그 시점 이후로 `best`는 `f j` 이하로 유지됩니다(1번 사실 덕분에). 그러니 순회가 끝난 최종 결과는 리스트 안의 모든 원소보다 작거나 같습니다.
3. **`argmin`은 이 두 조각을 조합한 특수한 경우다.** `argmin`은 시작값을 인덱스 0으로 두고 나머지 인덱스(`List.finRange (m+1)`의 꼬리 부분)를 순회합니다. 어떤 인덱스 `j`에 대해서든 — `j`가 0이면 1번 사실로, `j`가 0이 아니면 2번 사실로 — `f (argmin f) ≤ f j`를 얻습니다.

이 세 조각을 각각 독립적인 보조정리로 만들면, 최종 증명은 그 세 보조정리를 상황에 맞게 갖다 붙이는 것으로 끝납니다.

[source,lean]
----
namespace LinAlg.Vec

/-- 조각 1: foldl의 결과는 시작값보다 나쁠 수 없다. -/
theorem foldl_le_start {m : ℕ} (f : Fin (m+1) → ℝ) (l : List (Fin (m+1))) (start : Fin (m+1)) :
    f (l.foldl (fun best i => if f i < f best then i else best) start) ≤ f start := by
  sorry
  -- 힌트: l에 대한 귀납(induction l with | nil | cons hd tl ih).
  -- nil: foldl [] start = start이므로 f start ≤ f start (le_refl).
  -- cons hd tl: List.foldl_cons로 (hd::tl).foldl _ start = tl.foldl _ (if f hd < f start then hd else start)를
  --   먼저 전개한 뒤, by_cases hlt : f hd < f start로 두 경우를 나눕니다.
  --   두 경우 모두 "새 시작값의 f값 ≤ f start"라는 것을 먼저 확인하고(hlt인 경우는 le_of_lt hlt,
  --   아닌 경우는 not_lt.mp hlt), 그 다음 ih를 새 시작값에 적용한 뒤 le_trans로 이어붙입니다.

/-- 조각 2: foldl의 결과는 순회한 모든 원소보다 나쁠 수 없다. -/
theorem foldl_le_mem {m : ℕ} (f : Fin (m+1) → ℝ) (l : List (Fin (m+1))) (start : Fin (m+1)) :
    ∀ j ∈ l, f (l.foldl (fun best i => if f i < f best then i else best) start) ≤ f j := by
  induction l with
  | nil => intro j hj; simp at hj
  | cons hd tl ih =>
      intro j hj
      simp only [List.foldl_cons]
      rcases List.mem_cons.mp hj with h | h
      · subst h
        by_cases hlt : f hd < f start
        · -- hd로 갱신된 경우: 이제부터 시작값이 hd이므로, foldl_le_start를 그 새 시작값에 적용
          calc f (tl.foldl (fun best i => if f i < f best then i else best) hd) ≤ f hd :=
                 foldl_le_start f tl hd
        · -- 갱신되지 않은 경우: 새 시작값이 여전히 start이고, f start ≤ f hd(hlt가 거짓이므로)를 거쳐야 함
          have hge : f start ≤ f hd := not_lt.mp hlt
          calc f (tl.foldl (fun best i => if f i < f best then i else best) start) ≤ f start :=
                 foldl_le_start f tl start
            _ ≤ f hd := hge
      · -- j가 tl 안에 있는 경우: 새 시작값(hd로 갱신되었든 아니든)에서 시작해 ih를 적용
        by_cases hlt : f hd < f start
        · exact ih hd hd (List.mem_cons_self hd tl) |>.trans (le_refl _) |>.trans (foldl_le_start f tl hd)
              -- 위 한 줄이 어색하다면, 아래처럼 두 단계로 나눠 써도 됩니다:
              -- have := ih hd j h  -- tl.foldl _ hd에 대한 부등식 (j ∈ tl)
              -- exact this
        · exact ih start j h

end LinAlg.Vec
----

`foldl_le_mem`의 `cons` 경우 중 "j가 tl 안에 있는 경우" 갈래는 일부러 두 가지 표현을 나란히 남겨뒀습니다 — `calc`/`trans` 체이닝이 익숙하지 않다면 주석 처리된 두 줄짜리 버전(`ih hd j h`를 직접 쓰는 것)이 더 읽기 쉬울 수 있습니다. 어느 쪽이든 핵심은 같습니다 — **`ih`(귀납 가설)는 "tl을 어떤 시작값으로 `foldl`하든 그 결과가 tl의 원소들보다 작거나 같다"는 것을 이미 알고 있으므로, 지금 시작값이 뭐로 바뀌었는지만 파악해서 `ih`에 넣어주면 됩니다.**

=== 세 조각을 조합해 최종 정리 완성하기

[source,lean]
----
namespace LinAlg.Vec

theorem argmin_is_min {m : ℕ} (f : Fin (m + 1) → ℝ) :
    ∀ j, f (argmin f) ≤ f j := by
  intro j
  unfold argmin
  by_cases hj : j = ⟨0, Nat.zero_lt_succ m⟩
  · subst hj
    exact foldl_le_start f (List.finRange (m+1)).tail ⟨0, Nat.zero_lt_succ m⟩
  · have hmem : j ∈ (List.finRange (m+1)).tail := by
      sorry -- 힌트: List.finRange (m+1) = 0 :: (List.finRange (m+1)).tail임을 보인 뒤
             -- (List.finRange의 정의 또는 List.finRange_succ 계열 정리),
             -- j ∈ List.finRange (m+1)은 항상 참(List.mem_finRange)이고 j ≠ 0이므로
             -- List.mem_cons에서 tail 쪽 경우만 남는다는 것을 씁니다.
    exact foldl_le_mem f (List.finRange (m+1)).tail ⟨0, Nat.zero_lt_succ m⟩ j hmem

end LinAlg.Vec
----

이제 최종 정리는 `by_cases`로 "`j`가 시작 인덱스 0인가, 아닌가"만 나누고, 각 경우에 위에서 만든 `foldl_le_start`(0인 경우) 또는 `foldl_le_mem`(0이 아닌 경우)을 그대로 호출하는 것으로 끝납니다. 남은 `sorry` 하나(`hmem`)는 "0이 아닌 인덱스는 전체 범위 리스트의 꼬리 부분에 있다"는, 리스트 자체의 구조에 대한 사실이라 선형대수와는 무관한 순수 리스트 조작입니다.

전체 증명이 `sorry`가 세 곳(`foldl_le_start`, `foldl_le_mem`의 한 갈래, `hmem`)으로 줄었고, 그 세 곳 각각에 어떤 전술 조합을 시도해야 하는지 구체적으로 적어뒀습니다 — 이전보다 훨씬 좁혀진 목표들입니다.

이 정리는 이 책 1부에서 유일하게 "완전히 증명"과 "연습 문제"의 경계가 흐릿한 사례입니다 — 정리의 전체 구조(리스트 귀납으로 "지금까지 본 원소 중 최소"라는 불변식을 유지한다는 것을 보인다)는 확정했지만, 세부 단계 중 상당수를 `sorry`로 남겼습니다. `foldl`에 대한 귀납은 원리적으로 새로운 게 없지만, 리스트 인덱스와 `Fin` 타입 사이의 변환(`List.mem_finRange`, `List.tail_cons`)이 지루하게 반복되어 지면에 전부 담기엔 부담이 큽니다. 힌트에 적어둔 대로 `List.foldl`에 대한 표준적인 불변식 증명 패턴을 따라가면 채울 수 있습니다.

== 이 정리가 왜 이 책의 마무리로 적절한가

`argmin_is_min`이 증명하는 것은 사실 선형대수 고유의 정리가 아닙니다 — "리스트를 순회하며 최솟값을 갱신하는 알고리즘이 실제로 최솟값을 찾는다"는 것은 순수하게 알고리즘에 대한 명제입니다. 이 장이 보여주고 싶었던 건 정확히 이 지점입니다 — **1~5장에서 쌓은 선형대수 정리(노름, 코시-슈바르츠, 삼각부등식)는 `dist` 함수를 정의하는 데만 쓰였고, 그 `dist`가 일단 정의되고 나면 "최솟값을 찾는다"는 문제는 평범한 알고리즘 정확성 문제로 넘어갑니다.**

이건 이 책의 2부·3부(행렬, 최소자승법)에서도 반복될 구조입니다 — 선형대수가 제공하는 건 "거리", "각도", "독립성" 같은 개념과 그 개념들이 만족하는 성질이고, 그 위에서 실제 알고리즘(최근접 이웃, 최소자승 적합, 분류)을 짜고 정확성을 증명하는 일은 또 다른 층위의 작업입니다.

== 1부에서 확정한 것

* 벡터를 `Fin n → ℝ`로 정의하고 덧셈·스칼라곱·벡터공간 공리를 세웠습니다(1장).
* 선형결합과 표준 기저 전개 정리를 증명했습니다(2장).
* 내적과 노름을 정의하고, 노름이 음이 아니며 영벡터에서만 0이 된다는 것을 증명했습니다(3장).
* 코시-슈바르츠 부등식을 판별식 트릭으로 완전히 증명하고, 삼각부등식·직교성·피타고라스 정리로 확장했습니다(4장).
* 직교하는 0이 아닌 벡터가 항상 선형독립이라는 것을 증명하고, 표준 기저가 실제로 기저의 조건을 만족함을 확인했습니다(5장).
* 이 모든 도구를 실제 알고리즘(최근접 이웃 탐색)에 적용하고, 선형대수 정리와 알고리즘 정확성 증명이 서로 다른 층위의 작업이라는 것을 확인했습니다(6장).
