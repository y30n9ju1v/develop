'''

1부 4장에서 "직교하는 벡터들은 항상 선형독립"이라는 정리를 증명했습니다. 이 마지막 장은 그 반대 방향에 가까운 질문을 다룹니다 — **선형독립인 벡터들이 주어졌을 때, 이들을 직교하는 벡터들로 바꿀 수 있는가?** 답은 그렇다이고, 그 절차가 그람-슈미트 직교화(Gram-Schmidt orthogonalization)입니다. 이 과정을 행렬로 정리한 것이 QR 분해입니다. 이 절차가 왜 필요한지는 15장에서 분명해집니다 — 일반적인 정사각행렬의 고유값을 정확히 계산하는 표준적인 방법(특성방정식)은 행렬식이 필요해 이 책의 범위 밖인데, `A`를 `QR`로 분해한 뒤 곱셈 순서를 뒤집어(`RQ`) 반복하는 QR 알고리즘은 행렬식 없이도 고유값에 점점 가까워지는 근사를 얻습니다. 즉 이 장은 계산 편의를 위한 곁가지가 아니라, 3부에서 고유값을 실제로 "찾는" 방법 그 자체를 준비하는 장입니다.

== 두 벡터로 시작하기: 사영을 빼서 직교화하기

핵심 아이디어를 가장 단순한 경우(벡터 두 개)로 먼저 봅니다. `v₁`, `v₂`가 있을 때, `q₁ = v₁`로 두고, `v₂`에서 "`q₁` 방향 성분"을 빼내면 남는 것이 `q₁`과 직교하게 됩니다. `v₂`의 `q₁` 방향 성분(사영, projection)은 `((v₂⬝q₁)/(q₁⬝q₁)) • q₁`입니다 — 이건 `v₂`를 `q₁` 방향으로 "그림자 드리운" 만큼입니다.

그림으로 보면 이렇습니다 — `v₂`를 `q₁` 방향 성분과 `q₁`에 수직인 성분으로 쪼갠 뒤, `q₁` 방향 성분만 잘라내는 것입니다.

[source,text]
----
   v₂
   ^\
   | \
   |  \   q₂ = v₂ - proj_{q1}(v₂)  (잘라내고 남은, q1에 수직인 부분)
   |   \
   |    \
   +-----+--------> q₁ (= v₁)
   proj_{q1}(v₂)
   (= ((v₂⬝q₁)/(q₁⬝q₁)) • q₁, v₂의 그림자)
----

`proj_{q1}(v₂)`(그림의 가로 화살표)가 `v₂`의 "`q₁`과 같은 방향으로 겹치는 부분"이고, 이걸 `v₂`에서 빼고 남는 `q₂`(그림의 세로에 가까운 화살표)는 정의상 `q₁`과 겹치는 부분이 하나도 없습니다 — 그래서 `q₁`과 직교합니다. 4장에서 코시-슈바르츠를 판별식 트릭으로 증명할 때 "`u`에서 `v` 방향 성분을 뺀 나머지"를 다뤘던 것과 정확히 같은 그림이, 여기서는 "직교하는 벡터를 실제로 만들어내는" 데 쓰이는 것입니다.

[source,lean]
----
-- Vectors/GramSchmidt.lean
import Vectors.CauchySchwarz

namespace LinAlg.Vec

def gramSchmidt2 {n : ℕ} (v1 v2 : Vec n) : Vec n × Vec n :=
  let q1 := v1
  let q2 := v2 - ((v2 ⬝ q1) / (q1 ⬝ q1)) • q1
  (q1, q2)

end LinAlg.Vec
----

== 완전히 증명하는 것: q1과 q2는 실제로 직교한다

[source,lean]
----
namespace LinAlg.Vec

theorem gramSchmidt2_orthogonal {n : ℕ} (v1 v2 : Vec n) (h1 : v1 ≠ 0) :
    let (q1, q2) := gramSchmidt2 v1 v2
    q1 ⬝ q2 = 0 := by
  show v1 ⬝ (v2 - ((v2 ⬝ v1) / (v1 ⬝ v1)) • v1) = 0
  have hv1v1_ne : v1 ⬝ v1 ≠ 0 := by
    intro heq
    apply h1
    exact (norm_eq_zero_iff v1).mp (by show Real.sqrt (v1 ⬝ v1) = 0; rw [heq]; simp)
  have expand : v1 ⬝ (v2 - ((v2 ⬝ v1) / (v1 ⬝ v1)) • v1) =
      v1 ⬝ v2 - ((v2 ⬝ v1) / (v1 ⬝ v1)) * (v1 ⬝ v1) := by
    show (∑ i, v1 i * (v2 i - ((v2 ⬝ v1) / (v1 ⬝ v1)) * v1 i)) =
      (∑ i, v1 i * v2 i) - ((v2 ⬝ v1) / (v1 ⬝ v1)) * (∑ i, v1 i * v1 i)
    rw [Finset.mul_sum]
    rw [← Finset.sum_sub_distrib]
    congr 1
    funext i
    ring
  rw [expand]
  have inner_comm : v2 ⬝ v1 = v1 ⬝ v2 := by
    show (∑ i, v2 i * v1 i) = ∑ i, v1 i * v2 i
    congr 1; funext i; ring
  rw [inner_comm]
  field_simp

end LinAlg.Vec
----

이 증명은 지금까지 이 책에서 쌓은 세 가지 도구를 한 번에 조합합니다 — 3장의 `norm_eq_zero_iff`(영벡터가 아니면 자기 자신과의 내적이 0이 아니라는 것, 여기서는 나눗셈이 안전하다는 근거로 씁니다), 내적의 정의를 펼치는 합 연산(1~3장에서 반복한 패턴), 그리고 마지막에 분수를 정리하는 `field_simp`입니다. 계산의 핵심은 `expand`에서 사영을 뺀 결과를 내적 안에서 분배법칙으로 펼치는 것이고, 그렇게 펼친 뒤 `v2⬝v1`을 `v1⬝v2`로 바꿔치기(내적의 대칭성)하면 분자와 분모가 정확히 상쇄되어 0이 남습니다.

== 일반적인 k개 벡터로 확장하기

`v₃`가 하나 더 있다면, `q₃`는 `v₃`에서 `q₁` 방향 성분과 `q₂` 방향 성분을 모두 빼서 만듭니다 — `q₃ = v₃ - proj_{q1}(v₃) - proj_{q2}(v₃)`. 일반적으로 `k`번째 벡터는 그 앞의 모든 `q`들 방향 성분을 순서대로 빼는 방식으로 만들어집니다.

=== 정의부터 제대로 세우기: 누적 리스트를 명시적으로 들고 다니기

앞선 스케치의 문제는 "재귀 호출이 뒤쪽 벡터들을 먼저 처리한 결과"를 만들어서, 정작 필요한 "이미 처리된 **앞쪽** q들"을 손에 쥐고 있지 않다는 데 있었습니다. 6장에서 `argmin`을 만들 때 "지금까지의 최선"을 누적 인자로 들고 다녔던 것과 같은 해법을 여기서도 씁니다 — 처리된 q들의 리스트를 별도의 누적 인자(`done`)로 명시적으로 받는 보조 함수를 둡니다.

먼저 "한 벡터에서 주어진 q들 방향 성분을 전부 빼는" 헬퍼 함수를 분리합니다 — 이게 `gramSchmidt2`의 사영 빼기 한 단계를, q가 여러 개인 경우로 일반화한 것입니다.

[source,lean]
----
namespace LinAlg.Vec

/-- v에서 qs에 있는 각 벡터 방향 성분을 순서대로 빼냅니다.
    qs = [q1, q2]라면 결과는 v - proj_{q1}(v) - proj_{q2}(v)입니다. -/
def subtractProjections {n : ℕ} (v : Vec n) (qs : List (Vec n)) : Vec n :=
  qs.foldl (fun acc q => acc - ((acc ⬝ q) / (q ⬝ q)) • q) v

/-- done: 이미 만든 q들 (서로 직교). remaining: 아직 처리 안 한 원본 벡터들. -/
def gramSchmidtAux {n : ℕ} : List (Vec n) → List (Vec n) → List (Vec n)
  | done, [] => done
  | done, v :: rest => gramSchmidtAux (done ++ [subtractProjections v done]) rest

def gramSchmidt {n : ℕ} (vs : List (Vec n)) : List (Vec n) := gramSchmidtAux [] vs

end LinAlg.Vec
----

이 정의는 `sorry`가 없습니다 — 6장의 `argmin`처럼 리스트를 순회하며 누적하는 완전한(total) 재귀 함수입니다. `gramSchmidtAux`가 벡터를 하나씩 꺼내(`v :: rest`) `subtractProjections`로 처리한 뒤, 그 결과를 누적 리스트 뒤에 붙이고(`done ++ [...]`) 나머지(`rest`)로 재귀하는 구조가, 앞서 말로 설명한 "그 앞의 모든 q들 방향 성분을 순서대로 뺀다"는 절차를 그대로 코드로 옮긴 것입니다.

=== 연습 문제로 남기는 것: 쌍마다 직교한다는 증명

정의는 완성했지만, "이렇게 만든 q들이 실제로 서로 직교하는가"는 여전히 증명해야 합니다.

[source,lean]
----
namespace LinAlg.Vec

/-- 불변식: done 안의 벡터들은 이미 서로 직교합니다. -/
def PairwiseOrthogonal {n : ℕ} (l : List (Vec n)) : Prop :=
  ∀ q1 ∈ l, ∀ q2 ∈ l, q1 ≠ q2 → q1 ⬝ q2 = 0

/-- 핵심 보조정리: subtractProjections로 만든 새 벡터는, PairwiseOrthogonal한 qs의
    각 원소와 직교합니다. gramSchmidt2_orthogonal을 q 한 개에서 여러 개로 일반화한 것입니다. -/
theorem subtractProjections_orthogonal_to_all {n : ℕ} (v : Vec n) (qs : List (Vec n))
    (hqs : PairwiseOrthogonal qs) (hqne : ∀ q ∈ qs, q ≠ 0) :
    ∀ q ∈ qs, (subtractProjections v qs) ⬝ q = 0 := by
  sorry
  -- 힌트: qs에 대한 귀납. subtractProjections의 foldl을 한 겹씩 벗겨내면서,
  -- "이미 뺀 q들과는 이미 직교하고, 방금 뺀 q와도 gramSchmidt2_orthogonal과
  -- 같은 계산으로 직교해진다"는 것을 보입니다. 까다로운 지점은, q_k를 뺄 때
  -- 이미 직교시켜둔 q_1, ..., q_{k-1}과의 직교성이 "계속 유지되는가"인데,
  -- hqs(qs 자체가 서로 직교)를 이용하면 q_k 방향 성분을 빼는 것이
  -- q_1, ..., q_{k-1}과의 내적을 바꾸지 않는다는 것을 보일 수 있습니다
  -- ((a - c•q_k) ⬝ q_i = a⬝q_i - c*(q_k⬝q_i)이고 k≠i면 q_k⬝q_i=0이므로).

theorem gramSchmidtAux_pairwise_orthogonal {n : ℕ} (done remaining : List (Vec n))
    (hdone : PairwiseOrthogonal done) :
    PairwiseOrthogonal (gramSchmidtAux done remaining) := by
  sorry
  -- 힌트: remaining에 대한 귀납. base case(remaining = [])는 hdone 자체가 결론.
  -- 귀납 스텝(v :: rest)에서는 subtractProjections_orthogonal_to_all로
  -- 새로 만든 벡터가 done의 모든 원소와 직교함을 얻고, 그로부터
  -- done ++ [새 벡터]가 PairwiseOrthogonal임을 보인 뒤, 귀납 가설을 remaining = rest,
  -- done = done ++ [새 벡터]에 적용합니다.

theorem gramSchmidt_pairwise_orthogonal {n : ℕ} (vs : List (Vec n)) :
    PairwiseOrthogonal (gramSchmidt vs) :=
  gramSchmidtAux_pairwise_orthogonal [] vs (by intro q1 hq1; simp at hq1)

end LinAlg.Vec
----

`gramSchmidt_pairwise_orthogonal`(맨 아래)은 이제 새로운 증명이 필요 없습니다 — `gramSchmidtAux_pairwise_orthogonal`을 빈 리스트(`done = []`, 공집합은 자명하게 `PairwiseOrthogonal`)에서 시작하는 특수한 경우로 호출하는 것뿐입니다. 실제로 채워야 할 두 개의 `sorry`(`subtractProjections_orthogonal_to_all`, `gramSchmidtAux_pairwise_orthogonal`)는 각각 "한 단계"와 "리스트 전체"를 다루는 역할로 명확히 나뉘어 있습니다 — 전자를 먼저 완성하면, 후자는 6장의 `foldl_le_mem`을 증명할 때 썼던 것과 같은 "리스트 귀납 + 한 단계 보조정리 호출" 패턴으로 상대적으로 기계적으로 채워집니다.

== QR 분해: 그람-슈미트를 행렬로 정리하기

그람-슈미트 과정으로 만든 직교 벡터들을 각자의 노름으로 나눠 **정규직교(orthonormal)**(노름이 1이고 서로 직교)로 만들고, 그 벡터들을 열로 모은 행렬을 `Q`라 부릅니다. 원래 벡터 `v₁, ..., vₖ`는 이 `Q`의 열들의 선형결합으로 표현되는데, 그 계수들을 모은 위삼각행렬(대각선 아래가 전부 0인 행렬)을 `R`이라 부르면 원래 벡터들을 열로 모은 행렬 `A`에 대해 `A = QR`이 성립합니다 — 이게 **QR 분해**입니다.

이 책에서는 QR 분해를 Lean4로 완전히 구현하지 않습니다 — `Q`의 열이 정규직교라는 것(노름이 1이라는 조건까지 포함)과 `R`이 위삼각이라는 것을 동시에 만족하는 분해가 존재한다는 정리는, 지금까지 다룬 어떤 정리보다도 많은 세부 단계(귀납, 나눗셈의 안전성, 행렬 성분의 위치 조건)를 요구합니다. 대신 이 절의 역할은 **왜 이 분해가 유용한지**를 짚는 것입니다 — `Q`의 열이 정규직교이면 `QᵀQ = I`가 성립하고(10장에서 다룬 대칭행렬·전치 도구와 5장의 직교성이 여기서 합쳐집니다), 이 성질은 3부에서 다룰 QR 알고리즘(고유값을 반복으로 근사하는 방법)의 핵심 재료입니다. QR 분해를 완전히 구현하는 것은 이 책의 3부(15장)로 미루는 것이 적절한 이유입니다.

== 2부에서 확정한 것

* m×n 행렬을 `Fin m → Fin n → ℝ`로 정의하고, 1부의 벡터 증명 패턴이 인덱스만 늘려 그대로 확장된다는 것을 확인했습니다(7장).
* 행렬-벡터 곱을 정의하고 선형성(덧셈 보존)을 증명했으며, 항등행렬이 2장의 표준 기저 전개 정리를 재사용해 항등함수로 작동함을 확인했습니다(8장).
* 행렬 곱셈의 결합법칙을 완전히 증명하고, 그 증명이 "이중 합의 순서 교환"이라는 단순한 사실로 환원된다는 것과, 교환법칙은 구체적인 반례로 실패함을 확인했습니다(9장).
* 전치를 정의하고 `(AB)ᵀ = BᵀAᵀ`를 증명했으며, `AᵀA`가 항상 대칭이라는 것을 앞선 두 정리의 조합만으로 얻었습니다(10장).
* 역행렬의 왼쪽/오른쪽 정의를 나누고, 결합법칙 하나로 둘의 동일성(유일성)을 증명했습니다(11장).
* 그람-슈미트 직교화를 두 벡터에 대해 완전히 증명하고, 일반적인 k개로의 확장과 QR 분해를 3부의 QR 알고리즘으로 가는 다리로 남겼습니다(12장).

이것으로 벡터(1부)와 행렬(2부)을 마칩니다. 3부에서는 고유값과 고유벡터 — 행렬을 곱해도 방향이 바뀌지 않는 특별한 벡터 — 를 정의하고, 이 QR 분해를 반복 적용해 고유값을 근사하는 방법과, 데이터의 주축을 찾는 응용(PCA)을 이 책 전체에서 쌓은 도구로 증명하며 다룹니다.
