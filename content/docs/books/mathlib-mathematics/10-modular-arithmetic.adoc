== 나머지 연산의 기본 성질

[source,lean]
----
example (a : ℕ) : a % 7 < 7 ∨ a = 0 := by omega

example (a b : ℕ) (h : a % 5 = b % 5) : (a + 3) % 5 = (b + 3) % 5 := by omega
----

`%`(나머지)의 기본적인 성질(항상 나누는 수보다 작다, 나머지가 같으면 같은 수를 더해도 나머지가 같다)은 `omega`(선형 정수 산술 자동 증명 전술)로 대부분 즉시 처리됩니다 — 나머지 연산은 본질적으로 선형 산술의 한 형태라, 3장에서 배운 도구가 그대로 통합니다.

== 합동: 두 수가 같은 나머지를 갖는다는 관계

[source,lean]
----
example (a b : ℤ) (n : ℕ) (h : a ≡ b [ZMOD n]) : a + 1 ≡ b + 1 [ZMOD n] :=
  Int.ModEq.add_right 1 h
----

`a ≡ b [ZMOD n]`("`a`와 `b`가 법 `n`에 대해 합동")은 "`a`와 `b`를 `n`으로 나눈 나머지가 같다"는 관계입니다(4장에서 배운 "관계"가 다시 등장합니다). 이 관계는 양쪽에 같은 수를 더해도 유지됩니다 — `Int.ModEq.add_right`가 그 사실을 이미 증명해뒀습니다.

== ZMod n: 나머지 세계 자체를 타입으로

[source,lean]
----
example : (17 : ZMod 5) = 2 := by decide

example : (3 : ZMod 7) + 5 = 1 := by decide
example : (4 : ZMod 7) * 5 = 6 := by decide
----

`ZMod n`은 접근이 다릅니다 — "`n`으로 나눈 나머지가 같은 수들은 아예 같은 값으로 취급하는 새로운 타입"입니다. `(17 : ZMod 5) = 2`는 "17을 5로 나눈 나머지가 2다"라는 사실이 아니라, **`ZMod 5`라는 세계 안에서는 17과 2가 정말로 같은 값**이라는 뜻입니다. 그래서 `ZMod 7`에서 `3 + 5`를 계산하면 보통의 정수 세계라면 `8`이지만, `ZMod 7`에서는 `8`과 `1`이 같은 값이라 결과가 `1`로 나옵니다 — 덧셈·곱셈 자체가 "계산하고 나머지를 취하는" 방식으로 다시 정의된 것입니다.

`Int.ModEq`(관계)와 `ZMod n`(타입)은 같은 개념을 다루는 두 가지 방식입니다 — "두 정수가 합동이라는 사실을 명제로 다루고 싶다면" 앞쪽을, "나머지 세계에서 직접 계산하고 싶다면" 뒤쪽을 씁니다. 5장에서 본 "같은 사실을 명제로도, 계산 가능한 값으로도 표현할 수 있다"는 감각이 여기서도 반복됩니다.

== 페르마의 소정리 맛보기

[source,lean]
----
example (a : ZMod 5) : a ^ 5 = a := by
  haveI : Fact (Nat.Prime 5) := ⟨by decide⟩
  exact ZMod.pow_card a

example : (2 : ZMod 5) ^ 5 = 2 := by decide
example : (3 : ZMod 7) ^ 7 = 3 := by decide
----

**페르마의 소정리**는 "`p`가 소수면, 어떤 정수 `a`에 대해서도 `a^p`를 `p`로 나눈 나머지는 `a`를 `p`로 나눈 나머지와 같다"는 정리입니다. `ZMod p`의 언어로는 그냥 `a^p = a`로 깔끔하게 쓸 수 있습니다. `haveI : Fact (Nat.Prime 5) := ⟨by decide⟩`가 낯설 수 있는데, `ZMod.pow_card`라는 정리 자체가 **"법이 소수다"라는 사실을 배경 정보로 요구**합니다(`Fact` 타입클래스로 표현됩니다) — 매번 명시적으로 인자를 넘기는 대신, "지금 이 문맥에서는 5가 소수라는 사실을 써도 된다"고 미리 등록해두는 방식입니다. 구체적인 사례(`2^5 = 2 (mod 5)`, `3^7 = 3 (mod 7)`)는 `decide`로 즉시 확인됩니다.

== 왜 이 두 표현 방식을 둘 다 익혀야 하는가

`Int.ModEq`는 "합동"이라는 **관계**를 다루기 편하고(4장의 관계 다루는 기술이 그대로 적용됩니다), `ZMod n`은 "나머지 세계에서의 계산" 자체를 다루기 편합니다(보통의 정수 계산처럼 `+`, `*`, `^`를 그냥 쓰면 됩니다). 실전에서 암호학(RSA 같은)이나 정수론 문제를 다룰 때 이 두 표현을 오가며 쓰는 경우가 많아서, 이 장에서 미리 둘 다 확인해뒀습니다.

== 왜 이게 4부의 기반인가

`ZMod n`은 사실 단순한 타입이 아니라 **군(group)이자 환(ring)**입니다 — 덧셈에 대해서도, 곱셈에 대해서도 구조를 갖춘 대수적 대상입니다. 다음 장부터 다룰 "군"이라는 추상적인 개념이, 사실 이 장에서 이미 구체적인 예시(`ZMod n`의 덧셈)로 눈앞에 있었다는 걸 4부에서 다시 확인하게 됩니다.

== 요약

* 나머지 연산의 기본 성질은 대부분 `omega`로 처리됩니다.
* `Int.ModEq`(합동)는 "두 정수가 같은 나머지를 갖는다"는 관계이고, `ZMod n`은 그 나머지 세계 자체를 타입으로 만들어 직접 계산할 수 있게 해줍니다.
* 페르마의 소정리는 `ZMod p`의 언어로 `a^p = a`라는 간결한 형태로 표현되고, `Fact (Nat.Prime p)`라는 배경 정보를 문맥에 등록해서 씁니다.

3부가 여기서 끝났습니다. 4부에서는 군·부분군·준동형사상 같은 대수 구조를 다룹니다 — `ZMod n`이 이미 그 구체적인 사례였다는 걸 다시 만나게 됩니다.
